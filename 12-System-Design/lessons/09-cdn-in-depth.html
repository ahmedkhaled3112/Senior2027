Why this matters · ليه ده مهم

English

A CDN is usually the cheapest capacity you can buy and the easiest to get wrong. One marketing link can drop your hit ratio from 80% to 23%. One Cache-Control: public on the wrong route shows one customer's email to the next customer. One "purge everything" during a sale sends 100 times the normal load to your origin. And at a 95% hit ratio your origin is quietly sized for 5% of real traffic, so a CDN outage means 20× load. In system design interviews "put a CDN in front" is the easy sentence; this lesson is about the questions that follow it. We measure all of it on a Node stand-in you can read and run, and we mark clearly what a real CDN does differently.

بالعامية

Part 1 — Static vs dynamic 🟡 Intermediateالجزء 1 — المحتوى الـ static والـ dynamic

English

A CDN is a fleet of reverse-proxy caches (PoPs) close to users. In the usual pull model a PoP that misses fetches from your origin, stores the response according to the response's own headers, and serves later requests itself. The basics are in section 03, Load balancers & CDNs, part 5, and the HTTP caching rules in section 03, HTTP, part 5. Here we measure them.

The stand-in below applies the shared-cache rules: s-maxage beats max-age, no-store and private are not stored, and a response without explicit freshness is not stored. That last rule is a simplification: real CDNs have their own defaults, such as caching by file extension, so read your vendor's default behaviour.

The run sends 10,000 Zipf-distributed requests for 2,000 products at 50 requests per second, with an injected origin latency of 120 to 180 ms and a 20 ms round trip to the edge. Going from no-store to a 60 s TTL cuts origin hits by 76%. A 300 s TTL gets to 85.2%, and an hour gives exactly the same number, because the run lasts only 200 s. The remaining 1,476 calls are the first request for each distinct product. No TTL fixes a cold miss, and that is why the p99 stays near 196 ms while the p50 falls to 20 ms: the misses decide your tail.

Dynamic content can't be cached, but the CDN still helps. TCP and TLS terminate near the user, and the edge reuses warm keep-alive connections to the origin. On a new connection that is 540 ms versus 240 ms in the calculator. On a connection that is already open, the gain is zero (200 ms both ways), so the win is concentrated in the first request of each visit.

  user ──20ms──▶ PoP ──HIT──▶ answer in ~20ms
                  │
                  └──MISS──150ms──▶ origin (stores per Cache-Control)

  dynamic:  TLS + TCP end at the PoP ──warm keep-alive──▶ origin
اليوزر بيوصل لأقرب PoP في 20ms. لو الـ object موجود (HIT) بيرجع فورًا. لو مش موجود (MISS) الـ PoP بيروح للـ origin ويخزّن الرد حسب الـ Cache-Control. في السطر التاني: حتى الـ dynamic اللي مش بيتخزن، الـ TCP والـ TLS بيخلصوا عند الـ PoP، والـ PoP بيكلم الـ origin على connection جاهز keep-alive.

export type Hdrs = Record<string, string>;
export interface Req { url: string; method?: string; headers?: Hdrs }
export interface Res { status: number; headers: Hdrs; body: string }
export type Origin = (req: Req) => Promise<Res>;
export interface Clock { now(): number; sleep(ms: number): Promise<void> }

export const realClock: Clock = {
  now: () => performance.now(),
  sleep: (ms) => new Promise((r) => setTimeout(r, ms)),
};

// الوقت هنا افتراضي: نفس الـ seed يطلّع نفس الأرقام بالظبط في كل run
export class VirtualClock implements Clock {
  private t = 0;
  private seq = 0;
  private q: { at: number; seq: number; wake: () => void }[] = [];
  now() { return this.t; }
  sleep(ms: number) {
    return new Promise<void>((wake) => this.q.push({ at: this.t + ms, seq: this.seq++, wake }));
  }
  async run() {
    for (;;) {
      // استنى كل الـ microtasks تخلص قبل ما تحرّك الساعة
      await new Promise<void>((r) => setImmediate(r));
      if (this.q.length === 0) return;
      let m = 0;
      for (let i = 1; i < this.q.length; i++) {
        const a = this.q[i]!, b = this.q[m]!;
        if (a.at < b.at || (a.at === b.at && a.seq < b.seq)) m = i;
      }
      const [e] = this.q.splice(m, 1);
      this.t = e!.at;
      e!.wake();
    }
  }
}

export function mulberry32(seed: number) {
  return () => {
    seed = (seed + 0x6d2b79f5) | 0;
    let t = Math.imul(seed ^ (seed >>> 15), 1 | seed);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

// توزيع Zipf: قلة من المنتجات بتاخد معظم الطلبات، زي الترافيك الحقيقي
export function zipfSampler(n: number, s: number, rand: () => number) {
  const cdf: number[] = [];
  let sum = 0;
  for (let i = 1; i <= n; i++) { sum += 1 / i ** s; cdf.push(sum); }
  return () => {
    const x = rand() * sum;
    let lo = 0, hi = n - 1;
    while (lo < hi) { const mid = (lo + hi) >> 1; if (cdf[mid]! < x) lo = mid + 1; else hi = mid; }
    return lo;
  };
}

export function pct(values: number[], p: number) {
  const s = [...values].sort((a, b) => a - b);
  return s[Math.min(s.length - 1, Math.ceil((p / 100) * s.length) - 1)] ?? 0;
}

// بيبعت طلب كل gapMs في الوقت الافتراضي ويستنى الكل يخلص
export async function drive(clock: VirtualClock, n: number, gapMs: number, fn: (i: number) => Promise<void>) {
  const pending: Promise<void>[] = [];
  const arrivals = (async () => {
    for (let i = 0; i < n; i++) { pending.push(fn(i)); await clock.sleep(gapMs); }
  })();
  await clock.run();
  await arrivals;
  await Promise.all(pending);
}

function directives(cc = "") {
  const m = new Map<string, number | true>();
  for (const part of cc.split(",")) {
    const [k, v] = part.trim().toLowerCase().split("=");
    if (k) m.set(k, v === undefined ? true : Number(v));
  }
  return m;
}

// قواعد الـ shared cache من RFC 9111 و RFC 5861
function policyOf(req: Req, res: Res) {
  if (res.status !== 200 || res.headers.vary === "*") return null;
  const cc = directives(res.headers["cache-control"]);
  if (cc.has("no-store") || cc.has("private")) return null;
  // قاعدة الـ Authorization: متتخزنش إلا لو الـ response سمح صراحة
  const explicit = cc.has("public") || cc.has("s-maxage") || cc.has("must-revalidate");
  if (req.headers?.authorization && !explicit) return null;
  // الـ s-maxage بيكسب الـ max-age في الـ shared cache
  const ttl = cc.get("s-maxage") ?? cc.get("max-age");
  if (typeof ttl !== "number") return null;
  const num = (k: string) => { const v = cc.get(k); return typeof v === "number" ? v * 1000 : 0; };
  return {
    freshMs: cc.has("no-cache") ? 0 : ttl * 1000,
    swrMs: num("stale-while-revalidate"),
    sieMs: num("stale-if-error"),
  };
}

export type CacheStatus = "HIT" | "MISS" | "EXPIRED" | "STALE" | "COLLAPSED" | "PASS";
export interface Served { res: Res; cache: CacheStatus }
interface Entry { res: Res; storedAt: number; freshMs: number; swrMs: number; sieMs: number; tags: string[] }

export interface EdgeOptions {
  keyOf?: (req: Req) => string;
  collapse?: boolean;
  normalizeVary?: (name: string, value: string) => string;
}

export class Edge {
  readonly stats = { requests: 0, originCalls: 0, revalidated: 0, staleOnError: 0, HIT: 0, MISS: 0, EXPIRED: 0, STALE: 0, COLLAPSED: 0, PASS: 0 };
  readonly store = new Map<string, Entry>();
  private varyOf = new Map<string, string[]>();
  private inflight = new Map<string, Promise<Res>>();
  private passUntil = new Map<string, number>();
  private opts: { keyOf: (req: Req) => string; collapse: boolean; normalizeVary: (n: string, v: string) => string };
  private origin: Origin;
  private clock: Clock;

  constructor(origin: Origin, clock: Clock, opts: EdgeOptions = {}) {
    this.origin = origin;
    this.clock = clock;
    this.opts = {
      keyOf: opts.keyOf ?? ((r) => r.url),
      collapse: opts.collapse ?? true,
      normalizeVary: opts.normalizeVary ?? ((_n, v) => v),
    };
  }

  handle(req: Req): Promise<Served> {
    this.stats.requests++;
    return this.lookup(req, false);
  }

  private async lookup(req: Req, waited: boolean): Promise<Served> {
    const now = this.clock.now();
    const base = this.opts.keyOf(req);
    if ((req.method ?? "GET") !== "GET" || (this.passUntil.get(base) ?? 0) > now) {
      this.stats.originCalls++;
      const passed = await this.origin(req).catch((): Res => ({ status: 502, headers: {}, body: "bad gateway" }));
      return this.mark("PASS", passed);
    }
    const key = this.variantKey(base, req);
    const entry = this.store.get(key);
    if (entry) {
      const age = now - entry.storedAt;
      if (age < entry.freshMs) return this.mark(waited ? "COLLAPSED" : "HIT", entry.res);
      if (age < entry.freshMs + entry.swrMs) {
        // رجّع القديم فورًا وجدّد في الخلفية، واليوزر مبيستناش
        void this.fill(key, base, req, entry);
        return this.mark("STALE", entry.res);
      }
    }
    const running = this.opts.collapse ? this.inflight.get(key) : undefined;
    if (running) {
      // الـ followers بيستنوا الـ leader، وبعدها يدوّروا تاني عشان يتأكدوا إن النتيجة بتاعتهم
      await running;
      return this.lookup(req, true);
    }
    const res = await this.fill(key, base, req, entry);
    return this.mark(entry ? "EXPIRED" : "MISS", res);
  }

  private fill(key: string, base: string, req: Req, prev?: Entry): Promise<Res> {
    const running = this.inflight.get(key);
    if (this.opts.collapse && running) return running;
    const p = this.fetchOrigin(base, req, prev).finally(() => this.inflight.delete(key));
    if (this.opts.collapse) this.inflight.set(key, p);
    return p;
  }

  private async fetchOrigin(base: string, req: Req, prev?: Entry): Promise<Res> {
    this.stats.originCalls++;
    const headers: Hdrs = { ...req.headers };
    if (prev?.res.headers.etag) headers["if-none-match"] = prev.res.headers.etag;
    let res: Res;
    try { res = await this.origin({ ...req, headers }); }
    catch { res = { status: 502, headers: {}, body: "bad gateway" }; }
    const now = this.clock.now();
    if (res.status === 304 && prev) { prev.storedAt = now; this.stats.revalidated++; return prev.res; }
    if (res.status >= 500 && prev && now - prev.storedAt < prev.freshMs + prev.sieMs) {
      this.stats.staleOnError++;
      return prev.res;
    }
    const p = policyOf(req, res);
    if (!p) {
      // ده hit-for-pass: افتكر إن الـ URL ده مش بيتخزن عشان الطلبات متقفش في طابور
      if (res.status === 200 && !req.headers?.authorization) this.passUntil.set(base, now + 30_000);
      return res;
    }
    const vary = (res.headers.vary ?? "").toLowerCase().split(",").map((s) => s.trim()).filter(Boolean);
    this.varyOf.set(base, vary);
    const tags = (res.headers["surrogate-key"] ?? "").split(" ").filter(Boolean);
    this.store.set(this.variantKey(base, req), { res, storedAt: now, tags, ...p });
    return res;
  }

  private variantKey(base: string, req: Req) {
    const names = this.varyOf.get(base) ?? [];
    return names.reduce((k, n) => `${k}|${n}=${this.opts.normalizeVary(n, req.headers?.[n] ?? "")}`, base);
  }

  private mark(cache: CacheStatus, res: Res): Served { this.stats[cache]++; return { res, cache }; }

  // الـ soft purge بيعلّم الـ entry إنه stale بدل ما يمسحه، فالـ SWR يفضل شغال
  private expire(key: string, e: Entry, soft: boolean) {
    if (soft) { e.freshMs = 0; e.storedAt = this.clock.now(); } else this.store.delete(key);
  }
  purgeTag(tag: string, soft = false) {
    for (const [k, e] of this.store) if (e.tags.includes(tag)) this.expire(k, e, soft);
  }
  purgeAll(soft = false) { for (const [k, e] of this.store) this.expire(k, e, soft); }
}

async function run(cacheControl: string) {
  const clock = new VirtualClock();
  // خلّي الطلبات والـ jitter من PRNG منفصلين، فكل الـ policies تشوف نفس الطلبات
  const pickProduct = zipfSampler(2_000, 1.0, mulberry32(42));
  const jitter = mulberry32(7);
  const origin = async (_req: Req) => {
    await clock.sleep(120 + jitter() * 60);
    return { status: 200, headers: { "cache-control": cacheControl }, body: "{}" };
  };
  const edge = new Edge(origin, clock);
  const latencies: number[] = [];
  const edgeRtt = 20;
  // عشرة آلاف طلب، 50 طلب في الثانية يعني 200 ثانية افتراضية
  await drive(clock, 10_000, 20, async () => {
    const t0 = clock.now();
    await edge.handle({ url: `https://shop.example/products/${pickProduct()}` });
    latencies.push(clock.now() - t0 + edgeRtt);
  });
  const { originCalls, requests } = edge.stats;
  const hitRatio = ((1 - originCalls / requests) * 100).toFixed(1);
  const mean = latencies.reduce((a, b) => a + b, 0) / latencies.length;
  console.log(
    cacheControl.padEnd(32),
    `origin=${String(originCalls).padStart(5)}  hit=${hitRatio.padStart(5)}%`,
    `mean=${mean.toFixed(0).padStart(4)}ms  p50=${pct(latencies, 50).toFixed(0).padStart(4)}ms  p99=${pct(latencies, 99).toFixed(0)}ms`,
  );
}

Part 2 — Cache keys 🟡 Intermediateالجزء 2 — الـ cache keys

English

The cache key decides what counts as "the same request". A typical default is host + path + query string, taken literally. That means ?color=red&size=m and ?size=m&color=red are two objects, and every utm_campaign or gclid creates a new one. In the run below, 10,000 requests for 500 products produce 7,689 distinct keys and a 23.1% hit ratio. Dropping tracking parameters and sorting the rest gives 2,007 keys and 79.9%, with no change to the origin.

Vary adds request headers to the key. Vary: Accept-Encoding is fine once the value is normalized to br, gzip or identity; raw browser strings split each object into several variants, and many CDNs normalize this header for you. Accept-Language has the same problem and more values: normalize it to the languages you actually ship. Vary: Cookie gives every session its own copy: 3.3% hit ratio here, which means the cache is doing nothing but costing memory.

The dangerous case is the opposite one. A personalized response marked public, or cached by a rule that ignores the cookie, is served to the next user. The run shows Bob receiving Alice's email. The fix is private, no-store on personalized responses. Don't fix it with Vary: Cookie: it hides the bug only while your key includes cookies. Also watch for Web Cache Deception, where a rule like "cache everything ending in .css" gets tricked into storing /account/x.css.

Part 3 — TTL & invalidation 🟡 Intermediateالجزء 3 — الـ TTL والـ invalidation

English

You have three ways to stop serving old content, and they suit different data. A TTL is simple and self-healing, but the data stays stale until it expires. A purge is immediate but adds a system you must operate. Versioned file names (app.3f2a1c.js with max-age=31536000, immutable) never need either, because a new version is a new URL.

Purges should be surgical. With a Surrogate-Key (Fastly) or tags (Cloudflare's Tag purge) the origin labels each response, for example product-7 brand-7, and one API call removes all objects with that label. For tag design see section 08, revalidation and tags. In the run below a purge of one product barely registers, a brand purge adds a few origin calls, and a purge of everything takes the origin from about 1 call per second to 111 in the following second. A soft purge marks entries stale instead of deleting them: origin calls are identical (390 in 5 s), but users who waited on the origin drop from 458 to 4, because SWR keeps serving the old copy while the refresh happens.

Purges don't land everywhere at once. Cloudflare's docs call their purge "instant" and also warn that an HTTP 200 only means the request was received, so verify by checking the cache status header. In the simulation, a purge that reaches five PoPs over 800 ms leaves 34 of 300 later requests on the old price, and over 3 s it leaves 131. Hashed assets avoid this entirely, which is the trade-off to remember: purges propagate over time, hashed assets never need one.

Part 4 — Caching API responses 🟡 Intermediateالجزء 4 — تخزين الـ API responses

English

A public product catalog can use Cache-Control: public, s-maxage=60, stale-while-revalidate=300, stale-if-error=600. The first number is freshness, the second allows serving stale while refreshing in the background, and the third allows stale when the origin is failing (RFC 5861). Add an ETag and the refresh becomes cheap: the origin answers 304 with no body.

The experiment below is real HTTP: a Node origin, the edge stand-in over real sockets, and autocannon with 20 connections for 5 s against 10 URLs. TTLs are scaled from 60 s to 1 s so the run fits in seconds. With no-store the origin takes everything (about 300 requests/s). With TTL only, the origin drops to about 10/s: 10 URLs refreshed once a second. Adding SWR leaves origin load the same, about 10/s, and the p99 falls from about 56 ms to about 1 ms. That's the key point: SWR doesn't reduce origin load, it removes the users who wait for it. With stale-if-error, a 500 from the origin still produced a 200 for the user.

Requests with Authorization need care. RFC 9111 section 3.5 says a shared cache must not reuse a response to such a request unless the response explicitly allows it, and names public, s-maxage and must-revalidate. The last block confirms the rule on the stand-in. Note the flip side: adding public to an authenticated route shares it with every other caller.

What never to cache in a shared cache: per-user data (orders, carts, balances), responses that carry Set-Cookie, payment and auth endpoints, anything that must be exact at decision time such as final price or stock during checkout, and POST responses. Hit ratio on per-user data would be low anyway.

Part 5 — Origin shield 🟡 Intermediateالجزء 5 — الـ origin shield

English

Each PoP has its own cache. With 50 PoPs, a cold object produces up to 50 origin requests, one per PoP. An origin shield adds one more cache layer between the PoPs and the origin: every PoP asks the shield, the shield asks the origin once. In the run: 50 origin calls without a shield, 1 with it.

Request collapsing is the same idea inside one PoP. When 1,000 requests for the same cold key arrive inside 100 ms, a cache without collapsing sends all 1,000 to the origin. With collapsing one request goes and the other 999 wait for it. The stand-in re-checks after waiting, because a follower must not receive a response that was private or belongs to another variant: real CDNs handle this with "hit-for-pass".

The shield isn't free. It adds a hop on a shield miss: in the model a leader takes 190 ms against 180 ms direct, though shield hits are faster, so the mean is 166 ms. It costs extra per request on most vendors. And it's a shared dependency. If it fails with no fallback, every miss in every PoP fails: 50 of 50 users got errors in the run. With fallback to the origin nobody errors, but all 50 calls hit the origin, so the protection vanishes exactly when you're in trouble. AWS documents that Origin Shield routes to a secondary location if the primary is unavailable, and it says the feature fits badly with dynamic or infrequently requested content.

  without shield                 with shield

  PoP2 ─┼──▶ origin (50 calls)   PoP2 ─┼──▶ shield ──▶ origin (1 call)
  PoP50 ┘                        PoP50 ┘

English

Edge functions run your code inside the PoP, in a fetch(request) handler built on Web APIs. They fit decisions made from the request alone: geo redirects, token verification, A/B assignment, header rewrites. The handler below runs in Node by calling it directly with real Request objects. It was not run on Cloudflare. Runtimes and platform status are covered in section 06, edge runtimes; here we focus on the design consequences.

Two details matter. The token check rejects bad requests before they reach your origin. And the A/B variant must become part of the cache key, otherwise the cached page for variant A is served to users in variant B.

Limits shape what fits. Per Cloudflare's docs as read in November 2026: CPU time per request is 10 ms on Free and up to 5 minutes on Paid (30 s by default), memory is 128 MB per isolate, subrequests per request are 50 on Free and 10,000 on Paid, Worker size is capped at 64 MiB uncompressed, and a request can hold 6 simultaneous outgoing connections. Check the current numbers before you design around them.

The main trap is data gravity. An edge function is close to the user but far from your database, so every query pays the full edge-to-DB round trip. With a user 20 ms from the edge and 70 ms from the region, and a database 60 ms from the edge and 1 ms from a regional function, one query already loses: 80 ms at the edge, 71 ms in the region. At 5 queries it's 320 ms against 75 ms. The crossover here is below one query, so run edge functions that use data only with a cache, a read replica, or regional placement.

// الـ handler ده Workers-style: Web APIs بس، ومن غير أي import من Node
interface Env { JWT_SECRET: string; ORIGIN: (req: Request) => Promise<Response> }

const enc = new TextEncoder();
const b64url = (s: string) => Uint8Array.from(atob(s.replace(/-/g, "+").replace(/_/g, "/")), (c) => c.charCodeAt(0));

async function verifyJwt(token: string, secret: string): Promise<{ sub: string } | null> {
  const [h, p, s] = token.split(".");
  if (!h || !p || !s) return null;
  const key = await crypto.subtle.importKey("raw", enc.encode(secret), { name: "HMAC", hash: "SHA-256" }, false, ["verify"]);
  const ok = await crypto.subtle.verify("HMAC", key, b64url(s), enc.encode(`${h}.${p}`));
  if (!ok) return null;
  const claims = JSON.parse(new TextDecoder().decode(b64url(p)));
  return claims.exp * 1000 > Date.now() ? claims : null;
}

// اختيار ثابت لنفس اليوزر: نفس الـ IP يطلّع نفس الـ bucket
function bucketOf(seed: string): "a" | "b" {
  let h = 0;
  for (const ch of seed) h = (h * 31 + ch.charCodeAt(0)) | 0;
  return h % 2 === 0 ? "a" : "b";
}

  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);

    // (1) تحويل حسب البلد قبل ما الطلب يوصل الـ origin
    if (url.pathname === "/") {
      const country = request.headers.get("cf-ipcountry") ?? "XX";
      return Response.redirect(new URL(country === "EG" ? "/ar" : "/en", url), 302);
    }

    // (2) فحص الـ token على الـ edge: الطلبات الغلط متوصلش الـ origin أصلًا
    if (url.pathname.startsWith("/api/")) {
      const token = request.headers.get("authorization")?.replace("Bearer ", "") ?? "";
      const user = await verifyJwt(token, env.JWT_SECRET);
      if (!user) return new Response("unauthorized", { status: 401 });
      const forwarded = new Request(request, { headers: { ...Object.fromEntries(request.headers), "x-user-id": user.sub } });
      return env.ORIGIN(forwarded);
    }

    // (3) توزيع A/B: الـ variant لازم يدخل في الـ cache key
    const cookie = request.headers.get("cookie") ?? "";
    const assigned = /ab=(a|b)/.exec(cookie)?.[1] as "a" | "b" | undefined;
    const variant = assigned ?? bucketOf(request.headers.get("cf-connecting-ip") ?? "0");
    const upstream = new Request(request, { headers: { ...Object.fromEntries(request.headers), "x-variant": variant } });
    const res = await env.ORIGIN(upstream);
    const out = new Response(res.body, res);
    if (!assigned) out.headers.append("set-cookie", `ab=${variant}; Path=/; Max-Age=2592000`);
    return out;
  },

}

Part 7 — Push vs pull & CDN failure 🟡 Intermediateالجزء 7 — الـ push مقابل الـ pull ولما الـ CDN يقع

English

Pull is the default: you do nothing and objects fill on first request. Push means uploading content to the CDN's storage or pre-warming it before demand. It fits large, known files that will all be requested at once, such as a game patch or a video premiere. The calculator shows a 4 GB launch file across 50 PoPs: pull without a shield makes the origin send 200 GB, with a shield 4 GB, and only push gets to 4 GB with no user waiting.

On cost, per-gigabyte CDN egress is often only slightly cheaper than origin egress. The prices below are inputs from third-party sources read in November 2026, so confirm them on the vendor's page before you quote them: about $0.09/GB from S3 after 100 GB free, and CloudFront tiers starting around $0.085/GB after 1 TB free, with S3-to-CloudFront transfer reported as free. AWS's own page also lists flat-rate CloudFront plans now. At 50 TB/month the difference is about $500, roughly 12%. The real savings are the origin servers you don't run and the latency you don't serve.

Then the question interviewers like: what if the CDN fails? A 95% hit ratio means the origin sees 5% of traffic, so bypassing the CDN multiplies its load by 20. For 10,000 peak QPS that means 500 QPS today and 10,000 tomorrow, or 21 instances against the 2 you run. Real CDNs have failed: the Cloudflare outage of 18 November 2025 began at about 11:20 UTC, core traffic largely recovered by 14:30, and everything was normal by 17:06. Its cause was a database permissions change that doubled a generated file past a software limit. It wasn't an attack, and nothing you did could have prevented it.

So you need a plan, not hope. First, decide per route what survives: serve a static or read-only site from object storage instead of the full origin. Second, make bypass possible: a short DNS TTL on the CDN record, an origin TLS certificate for the public hostname, and an origin firewall that can admit direct traffic, since most origins only allow the CDN's IP ranges. Third, shed load at the origin with rate limits and 429s so it stays up for the routes that matter. Fourth, consider a second CDN only if the business justifies the cost. Fifth, rehearse it, because an untested failover plan usually fails on the firewall rule.

type Tier = { upToGb: number; perGb: number };

function tieredCost(gb: number, freeGb: number, tiers: Tier[]) {
  let left = Math.max(0, gb - freeGb);
  let cost = 0, prev = 0;
  for (const t of tiers) {
    const inTier = Math.min(left, t.upToGb - prev);
    cost += inTier * t.perGb;
    left -= inTier;
    prev = t.upToGb;
  }
  return cost;
}

export async function serve(edge: Edge, req: Req): Promise<Served> {
  const served = await edge.handle(req);
  const inm = req.headers?.["if-none-match"];
  if (inm && served.res.status === 200 && served.res.headers.etag === inm) {
    return { cache: served.cache, res: { status: 304, headers: { etag: inm }, body: "" } };
  }
  return served;
}

3. An allow-list key 🟡 medium Write catalogKey(url) that keeps only page, sort and color, sorted. Prove two URLs with different junk give the same key.

Solution · الحل 
// تمرين 3: allow-list للـ query params بدل block-list
const ALLOWED = new Set(["page", "sort", "color"]);
export function catalogKey(rawUrl: string) {
  const u = new URL(rawUrl);
  const kept = [...u.searchParams].filter(([k]) => ALLOWED.has(k)).sort(([a], [b]) => a.localeCompare(b));
  return `${u.host}${u.pathname}?${new URLSearchParams(kept)}`;
}
const a = catalogKey("https://shop.example/products?utm_source=fb&sort=price&page=2&sessionid=abc");
const b = catalogKey("https://shop.example/products?page=2&sort=price");
assert.equal(a, b);
console.log(a);

Cheat sheet · الخلاصة

  • Hit ratio is the metric; the misses that remain after a long TTL are cold keys, and they set your p99.
  • Dynamic content still gains on new connections (540 → 240 ms in the calculator), and gains nothing on open ones.
  • Normalize the key: drop tracking params, sort the rest. 23.1% → 79.9% in the run.
  • Normalize Vary values. Vary: Cookie means no cache (3.3%).
  • Personal data: private, no-store. Authorization requests aren't reused unless public, s-maxage or must-revalidate allows it (RFC 9111 §3.5).
  • Tag purge or hashed assets instead of purge-all; soft purge hides the spike from users, not from the origin.
  • Purges take time to reach every PoP; keep a TTL as the backstop.
  • s-maxage + SWR + stale-if-error + ETag: same origin load, p99 gone, survives origin failure.
  • Shield: 50 calls → 1. Collapsing: 1,000 → 1. A shield is a shared dependency, so plan its failure.
  • Edge functions: fine for request-only logic, wrong for routes with many DB round trips.
  • Pull by default; push for large known files.
  • CDN down means origin × 1/(1 − hit ratio). Have a rehearsed plan.
بالعامية
  • الـ hit ratio هو المقياس، والـ misses اللي بتفضل بعد TTL طويل هي cold keys، وهي اللي بتحدد الـ p99.
  • الـ dynamic بيكسب على الـ connections الجديدة (540 لـ 240ms في الحاسبة) ومبيكسبش حاجة على المفتوحة.
  • ظبّط الـ key: شيل الـ tracking params ورتّب الباقي. من 23.1% لـ 79.9% في التجربة.
  • ظبّط قيم الـ Vary. وVary: Cookie معناها مفيش cache (3.3%).
  • الـ data الشخصية: private, no-store. والطلبات اللي فيها Authorization مبتتعادش إلا لو public أو s-maxage أو must-revalidate سمحوا (RFC 9111 قسم 3.5).
  • Tag purge أو hashed assets بدل purge-all، والـ soft purge بيخبي الـ spike عن اليوزرز مش عن الـ origin.
  • الـ purge بياخد وقت عشان يوصل كل PoP، فخلّي TTL كخط دفاع.
  • s-maxage + SWR + stale-if-error + ETag: نفس حمل الـ origin، والـ p99 بيروح، وبتستحمل وقوع الـ origin.
  • الـ shield: 50 نداء لـ 1، والـ collapsing: 1000 لـ 1. والـ shield shared dependency، فخطط لفشله.
  • الـ edge functions كويسة للـ logic اللي من الطلب بس، وغلط للـ routes اللي فيها DB round trips كتير.
  • الـ pull هو الـ default، والـ push للملفات الكبيرة المعروفة.
  • الـ CDN لو وقع يبقى حمل الـ origin مضروب في 1/(1 − hit ratio). لازم خطة مجربة.
