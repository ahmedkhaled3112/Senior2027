Why this matters · ليه ده مهم

English

Every system design answer is built from about a dozen boxes. If you can't say what goes into a box, what comes out and when you would add it, you end up drawing boxes because other diagrams have them. This lesson is the shallow tour: one small run per block, so each name maps to behaviour you have seen. Limits and failure modes come later, in lesson 42.

أي إجابة system design مبنية من حوالي 12 box. لو مش عارف إيه اللي بيدخل الـ box، وإيه اللي بيطلع منه، وإمتى تضيفه، هتلاقي نفسك بترسم boxes عشان شفتها في diagrams تانية. الدرس ده جولة سريعة: تشغيلة صغيرة لكل block، عشان كل اسم يرتبط في دماغك بسلوك شفته بعينك. الحدود والـ failure modes هنتكلم عنها بعدين في درس 42.

Part 1 — Traffic blocks 🟢 Basicالجزء 1 — الـ blocks اللي بتوجّه الـ traffic

English

Four blocks sit between the user and your code. They are roles, not products: one nginx can be a reverse proxy and a load balancer at once, and Cloudflare can be a CDN and a gateway. What matters is the job each one does on the path.

  • A CDN answers from a location near the user when it has a fresh copy, and goes to your origin when it doesn't.
  • An API gateway is the front door for API callers: authentication, per-client rate limits, routing to services.
  • A load balancer picks one healthy instance out of several. It knows nothing about your business.
  • A reverse proxy speaks to clients on behalf of your app: TLS, compression, buffering slow clients.

The run below chains stand-ins for these (the reverse proxy role is folded into the edge and LB) and prints the route each request took. Watch two things: a cache hit never reaches anything behind the edge, and that includes the gateway's API key check. For the mechanics of balancing and proxying, see CS Fundamentals 16; this part is only about what each block is for.

type Upstream = { status: number; cacheControl: string; path: string; body: string };
type Handler = (req: http.IncomingMessage, res: http.ServerResponse) => void | Promise<void>;

function listen(handler: Handler): Promise<{ url: string; stop(): void }> {
  const server = http.createServer((req, res) => void handler(req, res));
  return new Promise((resolve) =>
    server.listen(0, "127.0.0.1", () => {
      const { port } = server.address() as AddressInfo;
      resolve({
        url: `http://127.0.0.1:${port}`,
        stop: () => { server.closeAllConnections(); server.close(); },
      });
    }),
  );
}

// كل hop بيكلّم اللي بعده وبيرجّع الـ path اللي الـ request مشي فيه
async function forward(baseUrl: string, req: http.IncomingMessage): Promise<Upstream> {
  const key = req.headers["x-api-key"];
  const r = await fetch(baseUrl + req.url, {
    headers: typeof key === "string" ? { "x-api-key": key } : {},
  });
  return {
    status: r.status,
    cacheControl: r.headers.get("cache-control") ?? "",
    path: r.headers.get("x-path") ?? "",
    body: await r.text(),
  };
}

function reply(res: http.ServerResponse, up: Upstream, path: string): void {
  res.writeHead(up.status, {
    "content-type": "application/json",
    "cache-control": up.cacheControl,
    "x-path": path,
  });
  res.end(up.body);
}

// (1) الـ API instances: الكتالوج public، والطلبات private
const apiInstance = (name: string): Handler => (req, res) => {
  const isCatalog = req.url!.startsWith("/products/");
  reply(res, {
    status: 200,
    cacheControl: isCatalog ? "public, max-age=60" : "private, no-store",
    path: "",
    body: JSON.stringify({ url: req.url, servedBy: name }),
  }, name);
};

const apiA = await listen(apiInstance("api-a"));
const apiB = await listen(apiInstance("api-b"));

// (2) الـ load balancer: بياخد request ويختار instance، ومش فاهم الـ business خالص
const instances = [apiA.url, apiB.url];
let next = 0;
const lb = await listen(async (req, res) => {
  const target = instances[next++ % instances.length]!;
  const up = await forward(target, req);
  reply(res, up, `lb > ${up.path}`);
});

// (3) الـ API gateway: بيرفض أي request من غير API key قبل ما يوصل للـ services
const gateway = await listen(async (req, res) => {
  if (req.headers["x-api-key"] !== "shop-key") {
    reply(res, { status: 401, cacheControl: "no-store", path: "", body: '{"error":"bad key"}' }, "gateway(401)");
    return;
  }
  const up = await forward(lb.url, req);
  reply(res, up, `gateway > ${up.path}`);
});

// (4) الـ edge: كاش مؤقت. لو الرد public بيتخزن، والـ HIT بيرجع من غير ما يكمل السكة
const cache = new Map<string, Upstream>();
const edge = await listen(async (req, res) => {
  const hit = cache.get(req.url!);
  if (hit) { reply(res, hit, "edge(HIT)"); return; }
  const up = await forward(gateway.url, req);
  if (up.cacheControl.startsWith("public")) cache.set(req.url!, up);
  reply(res, up, `edge(MISS) > ${up.path}`);
});

async function median(path: string, n: number): Promise<number> {
  const samples: number[] = [];
  for (let i = 0; i < n; i++) {
    const t0 = performance.now();
    const r = await fetch(edge.url + path, { headers: { "x-api-key": "shop-key" } });
    await r.text();
    samples.push(performance.now() - t0);
  }
  return samples.sort((a, b) => a - b)[Math.floor(n / 2)]!;
}

الـ CDN: بيدخله GET قريب من الـ user، وبيطلع منه bytes متخزنة أو fetch من الـ origin، وتضيفه لو المحتوى public وبيتقري أكتر بكتير ما بيتغير والـ users بعيد. الـ API gateway: بيدخله API call ومعاه credentials، وبيطلع منه call متأكد منه ومتوجّه لـ service، وتضيفه لما clients أو services كتير محتاجين باب واحد. الـ load balancer: بيدخله connection أو request، وبيطلع نفس الحاجة لـ instance سليمة، وتضيفه من أول اتنين instances ورا عنوان واحد. الـ reverse proxy: بيدخله HTTP من الـ client (TLS، بطيء، مضغوط)، وبيطلع HTTP نضيف للـ app، ومفيد دايمًا قدام Node process على الإنترنت.
بالعامية

بص، الأربع blocks دول بيقفوا بين الـ user والكود بتاعك، وهم أدوار مش منتجات: nginx واحد ممكن يبقى reverse proxy و load balancer في نفس الوقت، و Cloudflare ممكن يبقى CDN و gateway. المهم الشغلانة اللي كل واحد بيعملها على السكة.

  • الـ CDN بيرد من مكان قريب من الـ user لو عنده نسخة صالحة، ولو مفيش بيروح للـ origin بتاعك.
  • الـ API gateway هو الباب بتاع اللي بيكلم الـ API: authentication، و rate limits لكل client، و routing للـ services.
  • الـ load balancer بيختار instance سليمة من وسط كذا واحدة، ومش فاهم أي حاجة عن الـ business.
  • الـ reverse proxy بيكلّم الـ clients بدل الـ app: TLS، وضغط، وبيستحمل الـ clients البطيئة.

التشغيلة فوق بتوصّل stand-ins للأدوار دي (دور الـ reverse proxy مدموج في الـ edge والـ LB) وبتطبع السكة اللي كل request مشي فيها. ركّز في حاجتين: الـ cache hit مبيوصلش لأي حاجة ورا الـ edge، ومن ضمنها فحص الـ API key في الـ gateway. تفاصيل الـ balancing والـ proxying في درس CS 16، هنا بنسأل بس كل block بيعمل إيه.

فين هستخدمه في شغلي؟ لما تحط Cloudflare قدام Express API: رد GET /products/:id بـ Cache-Control: public, max-age=60 عشان الكتالوج يتخدم من الـ edge. لكن /orders و /me لازم يطلعوا private, no-store. وفي الـ code review، أي route جديد عليه auth ومعاه public وقّفه فورًا، لأن رد user ممكن يروح لـ user تاني.

Interview question "What's the difference between a reverse proxy, a load balancer and an API gateway?" → A reverse proxy fronts your app (TLS, buffering). A load balancer spreads requests over instances. A gateway applies API policy per caller (auth, quotas, routing). The roles overlap in one product, so name the job you need, not the tool.
"إيه الفرق بين reverse proxy و load balancer و API gateway؟" ← الـ reverse proxy واقف قدام الـ app (TLS و buffering). الـ load balancer بيوزّع الـ requests على instances. الـ gateway بيطبّق سياسات الـ API لكل caller (auth و quotas و routing). الأدوار بتتداخل في منتج واحد، فقول الشغلانة اللي محتاجها، مش اسم الأداة.

Part 2 — Stores 🟢 Basicالجزء 2 — أماكن تخزين الـ data

English

Here is one product stored in three real engines: Postgres 18 (relational), MongoDB 8 (document), and Redis 8 used as a key-value store and cache. What differs is the question each one can answer cheaply.

  • By key, all three are close at this scale. Don't quote "Redis is 100× faster": on loopback with one connection and data fully in memory, the gap was fractions of a millisecond. A cache earns its place by taking load off the database, and by what it saves over a real network path.
  • An ad hoc filter is one line in SQL or Mongo. Plain Redis has no WHERE, so the application read all 20,000 values to find 5.
  • A join is a hash join in Postgres, about 4 ms with no index on the join column. Mongo's $lookup without an index on the foreign field ran a full collection scan per order item: 60 million documents examined and about 16 seconds. With the index it took about 95 ms.

On Redis filters, be exact: Redis Search (FT.*) exists and redis.io lists it for Redis Open Source, but you declare an index first. The Windows build used here doesn't include it, as the last line of the output shows. SQL basics are in CS Fundamentals 17, and Mongo modeling and $lookup are in Databases 31 and 32.

// حماية: السكريبت ده بيمسح data، فممنوع يشتغل على الـ services الحقيقية بتاعتك
export function requirePort(name: string): number {
  const raw = process.env[name] ?? "";
  const n = Number(raw);
  if (!/^\d+$/.test(raw) || n < 1024 || n > 65535 || [27017, 5432, 6379].includes(n)) {
    throw new Error(`refusing ${name}="${raw}": give me the port of a throwaway instance`);
  }
  return n;
}

Part 3 — Queue & object storage 🟢 Basicالجزء 3 — الـ queue والـ object storage

English

A message queue takes a small message and hands it to a worker later, so the request doesn't wait for the slow part. In the run, enqueueing an order confirmation took about 3 ms, while the simulated SMTP call took 300 ms in the background. The full BullMQ story, including retries and scheduling, is in Node.js 22.

Object storage takes a key and bytes and returns those bytes later, durably. It has no SQL and no partial update of a file. You store the file there and keep only its key in the database. The run uses s3rver as a local stand-in with the real AWS SDK. It is a test double: it has no lifecycle rules and it even accepted a tampered signature in our checks, so don't learn S3's security from it.

The classic mistake is putting a large payload inside the message. Five 50 MiB PDFs as base64 added about 400 MB to Redis memory, and a queue backlog of PDFs would be an out-of-memory incident. Five messages that carry only the object key added about 0.005 MB. That is the claim check pattern: the message holds a reference and the blob lives in object storage. The numbers are from one run on a loaded Windows machine, so read them as ratios.

Part 4 — DNS as a block 🟢 Basicالجزء 4 — الـ DNS كـ block

English

DNS takes a name and returns addresses plus a TTL, which is how long that answer may be reused. As a block it is simple, and it sits at the very start of every request's path. The full recursive journey is in CS Fundamentals 14, part 6, so here we only look at the interface.

The stand-in below is a real authoritative-style server on UDP, about 40 lines over node:dgram. A real dns.promises.Resolver queries it through setServers. The answers are { address, ttl } pairs, and an unknown name gives ENOTFOUND (NXDOMAIN on the wire). What TTL values to pick and how DNS routes traffic globally is the next lesson, 06.

import dgram from "node:dgram";
import { promises as dns } from "node:dns";
import type { AddressInfo } from "node:net";

// تنبيه: ده stand-in صغير لـ authoritative server، مش BIND ولا Route 53
console.log("STAND-IN: a tiny authoritative DNS server on node:dgram");

type Zone = Record<string, { addresses: string[]; ttl: number }>;

const zone: Zone = {
  "shop.example.com": { addresses: ["203.0.113.10", "203.0.113.11"], ttl: 300 },
  "img.shop.example.com": { addresses: ["198.51.100.7"], ttl: 60 },
};

function startServer(zone: Zone): Promise<{ port: number; stop(): void }> {
  const socket = dgram.createSocket("udp4");
  socket.on("message", (query, client) => {
    // الـ name بيبدأ عند byte 12 ومكتوب كده: طول، حروف، طول، حروف، ... 0
    const labels: string[] = [];
    let end = 12;
    while (query[end] !== 0) {
      const len = query[end]!;
      labels.push(query.toString("ascii", end + 1, end + 1 + len));
      end += len + 1;
    }
    end += 5;

    const entry = zone[labels.join(".").toLowerCase()];
    const header = Buffer.from(query.subarray(0, 12));
    header[2] = 0x84;
    // كود الرد: 0 يعني تمام و3 يعني ⁦NXDOMAIN (⁩الاسم مش موجود)
    header[3] = entry ? 0x00 : 0x03;
    header.writeUInt16BE(entry?.addresses.length ?? 0, 6);
    header.writeUInt16BE(0, 8);
    header.writeUInt16BE(0, 10);

    const answers = (entry?.addresses ?? []).map((ip) => {
      const rr = Buffer.alloc(16);
      // البداية: pointer للاسم (0xc00c) وبعده type A و class IN
      rr.set([0xc0, 0x0c, 0, 1, 0, 1], 0);
      rr.writeUInt32BE(entry!.ttl, 6);
      rr.writeUInt16BE(4, 10);
      rr.set(ip.split(".").map(Number), 12);
      return rr;
    });
    socket.send(Buffer.concat([header, query.subarray(12, end), ...answers]), client.port, client.address);
  });
  return new Promise((resolve) =>
    socket.bind(0, "127.0.0.1", () =>
      resolve({ port: (socket.address() as AddressInfo).port, stop: () => socket.close() }),
    ),
  );
}

Part 5 — One sentence per block 🟢 Basicالجزء 5 — جملة واحدة لكل block

English

If you can't describe a block in one sentence of input, output and when, you don't know it yet. So we turn that into code: a typed catalog of every block, and a choose(need) function that maps a requirement to blocks. The eight scenario assertions make the catalog concrete, and the discriminated union forces you to state the need before you name a tool.

Then we use it to assemble the shop's high-level design, and every box must justify itself. The last lines of the run put a price on extra boxes: if every hop is 99.95% available, a nine-hop path loses availability and adds latency compared with a four-hop one. The classic mistake is a gateway, a service mesh and three proxies on an app serving 100 QPS: each one adds a hop, a config and a new reason for an outage, and none of them solves a problem you have. Availability math comes from lesson 04. Each hop's real limits and failure modes are in lesson 42.

  "reverse-proxy":   { input: "client HTTP",              output: "backend HTTP",                  when: "TLS, gzip, buffering in front of the app" },
  "api-gateway":     { input: "API call + credentials",   output: "authorized, routed call",       when: "many clients or services need one front door" },
  "relational-db":   { input: "SQL + transaction",        output: "rows, durably",                 when: "relations, constraints, ad hoc queries (the default)" },
  "document-db":     { input: "query on a JSON document", output: "whole documents",               when: "self-contained aggregates read together" },
  "key-value-store": { input: "a key",                    output: "its value, fast",               when: "you always know the key: sessions, counters" },
  "cache":           { input: "a key you can recompute",  output: "a copy, or a miss",             when: "reads repeat and staleness is acceptable" },
  "message-queue":   { input: "a small message",          output: "delivered later to a worker",   when: "work outlives the request, or producers outpace consumers" },
  "object-storage":  { input: "key + bytes (a blob)",     output: "those bytes, durably",          when: "files, backups, anything too big for a DB row" },
};

export type Need =
  | { kind: "slow-side-effect" }
  | { kind: "file"; audience: "worldwide" | "internal" }
  | { kind: "system-of-record"; shape: "relational" | "self-contained" }
  | { kind: "lookup-by-key" }
  | { kind: "repeated-reads"; source: "database" | "public-http" }
  | { kind: "traffic"; instances: number; externalPartners: boolean; needsTls: boolean }
  | { kind: "public-name" };

// (2) القرار: بنبدأ من الاحتياج، مش من اسم الأداة
export function choose(need: Need): BlockName[] {
  switch (need.kind) {
    case "slow-side-effect": return ["message-queue"];
    case "file": return need.audience === "worldwide" ? ["cdn", "object-storage"] : ["object-storage"];
    case "system-of-record": return need.shape === "relational" ? ["relational-db"] : ["document-db"];
    case "lookup-by-key": return ["key-value-store"];
    case "repeated-reads": return need.source === "database" ? ["cache"] : ["cdn"];
    case "public-name": return ["dns"];
    case "traffic": {
      const picked: BlockName[] = [];
      if (need.needsTls) picked.push("reverse-proxy");
      if (need.externalPartners) picked.push("api-gateway");
      if (need.instances > 1) picked.push("load-balancer");
      return picked;
    }
  }
}

Common mistakes · غلطات شائعة

❌ Public cache on a private response 
// الغلط: رد خاص بـ user ومعلم إنه ينفع يتخزن
res.set("Cache-Control", "public, max-age=60");
res.json(await ordersFor(req.user.id));
✅ Private data is never stored at the edge 
// الصح: الـ edge ممنوع يخزن ردود الـ users
res.set("Cache-Control", "private, no-store");
res.json(await ordersFor(req.user.id));
بالعامية

في الـ ❌، الـ edge هيخزن طلبات user ويرجّعها لأول حد يطلب نفس الـ URL، وده تسريب data زي اللي شفناه في الجزء 1 لما الـ no key أخد 200. في الـ ✅، الرد private, no-store فمفيش نسخة بتتخزن، وكل request بيعدّي على الـ gateway وفحص الـ auth.

❌ The blob inside the message 
// الغلط: 50 MiB جوه Redis لكل job
await queue.add("render", {
  orderId,
  pdfBase64: pdf.toString("base64"),
});
✅ Claim check: the message carries a key 
// الصح: الملف في الـ object storage والـ job فيها الـ key
await s3.send(new PutObjectCommand({ Bucket, Key, Body: pdf }));
await queue.add("render", { orderId, invoiceKey: Key });
بالعامية

في الـ ❌، كل job بتاكل حوالي 80 MB من memory بتاعة Redis، فـ backlog صغير يوقّع الـ queue وكل اللي بيستخدم نفس Redis. في الـ ✅، الملف في الـ object storage والـ job كام byte، وقسناها: حوالي 0.005 MB لخمس jobs. ده الـ claim check.

❌ Filtering a store that can't filter 
// الغلط: KEYS بيقف عليه الـ Redis كله، وبعدين فلترة في الـ app
const keys = await redis.keys("product:*");
const all = await redis.mget(...keys);
const shoes = all.map(parse).filter((p) => p.category === "shoes");
✅ Ask the store that can answer it 
// الصح: السؤال ده SQL، و Redis نسخة بالـ key بس
const { rows } = await db.query(
  "SELECT id FROM products WHERE category = $1 LIMIT 20", ["shoes"]);
بالعامية

في الـ ❌، KEYS بيعدّي على كل الـ keys على main thread بتاع Redis، فبيعطل كل الـ clients التانيين. وحتى بـ SCAN، قريت 20000 value عشان 5 نتايج (حوالي 66 ms مقابل حوالي 2 ms في SQL). في الـ ✅، الفلتر راح للـ DB اللي عنده query engine، و Redis فضل للقراية بالـ key.

❌ $lookup with no index on the foreign field 
// الغلط: collection scan لكل document داخل
db.collection("order_items").aggregate([
  { $lookup: { from: "products", localField: "sku", foreignField: "sku", as: "p" } },
]);
✅ Index it, or embed what you read together 
// الصح: index على الـ foreignField الأول
await db.collection("products").createIndex({ sku: 1 });
// أو خزّن اسم المنتج جوه الـ order_item لو دايمًا بيتقرو مع بعض
بالعامية

في الـ ❌، Mongo عمل 3001 collection scan وفحص 60 مليون document في حوالي 16 ثانية. في الـ ✅، الـ index نزّل نفس الـ query لحوالي 95 ms وفحص 3001 document بس. ولو الاتنين بيتقروا دايمًا مع بعض، الـ embedding أحسن من الـ $lookup أصلًا.

Solution · الحل 
import assert from "node:assert/strict";

type Entry = { body: string; expiresAt: number };

// حساب مدة الصلاحية من الـ header، و0 يعني ممنوع يتخزن
export function maxAgeOf(cacheControl: string): number {
  if (!cacheControl.includes("public")) return 0;
  const match = /max-age=(\d+)/.exec(cacheControl);
  return match ? Number(match[1]) : 0;
}

export function createEdgeCache(now: () => number) {
  const entries = new Map<string, Entry>();
  return {
    get(url: string): string | undefined {
      const entry = entries.get(url);
      if (!entry) return undefined;
      // الـ entry اللي انتهى لازم يتشال، عشان الـ memory متكبرش على الفاضي
      if (entry.expiresAt <= now()) { entries.delete(url); return undefined; }
      return entry.body;
    },
    put(url: string, body: string, cacheControl: string): void {
      const seconds = maxAgeOf(cacheControl);
      if (seconds > 0) entries.set(url, { body, expiresAt: now() + seconds * 1000 });
    },
    size: () => entries.size,
  };
}

let clock = 0;
const cache = createEdgeCache(() => clock);
cache.put("/products/42", "red shirt", "public, max-age=60");
cache.put("/orders/7", "secret", "private, no-store");

assert.equal(cache.get("/products/42"), "red shirt");
assert.equal(cache.get("/orders/7"), undefined);
clock = 59_999;
assert.equal(cache.get("/products/42"), "red shirt");
clock = 60_000;
assert.equal(cache.get("/products/42"), undefined);
assert.equal(cache.size(), 0);

import assert from "node:assert/strict";

type BlockName = "relational-db" | "search-engine" | "message-queue";
type Need =
  | { kind: "search"; rows: number; fuzzyRelevance: boolean }
  | { kind: "slow-side-effect" };

// القاعدة: ابدأ بـ Postgres، ومحرك البحث المنفصل بس لما الحجم أو الـ relevance يطلبوه
function choose(need: Need): BlockName[] {
  if (need.kind === "slow-side-effect") return ["message-queue"];
  const outgrowsPostgres = need.rows > 50_000_000 || need.fuzzyRelevance;
  return outgrowsPostgres ? ["relational-db", "search-engine"] : ["relational-db"];
}

Cheat sheet · الخلاصة

  • CDN: GET in, cached bytes out. Use for public, read-heavy content with far-away users.
  • Gateway: API call + credentials in, authorized call out. Use when many clients need one front door.
  • Load balancer: request in, same request to one healthy instance. Use from two instances up.
  • Reverse proxy: raw client HTTP in, clean HTTP out (TLS, gzip, buffering).
  • A cache HIT at the edge skips everything behind it, including auth. Never mark private data public.
  • Relational DB is the default; document DB for self-contained aggregates; key-value when you always know the key; a cache is never the only copy.
  • Plain Redis has no ad hoc filter. $lookup without a foreign-field index scans once per document (60 million examined in our run).
  • Queue: small message in, delivered later. Object storage: key + bytes in, the same bytes out, durably.
  • Blobs never go inside messages: use a claim check (400 MB vs 0.005 MB in our run).
  • DNS: name in, addresses + TTL out.
  • Every box must have one sentence: input, output, and the number or requirement that forces it.
بالعامية
  • الـ CDN: بيدخله GET وبيطلع bytes متخزنة. للمحتوى الـ public اللي بيتقري كتير والـ users بعيد.
  • الـ gateway: بيدخله API call ومعاه credentials وبيطلع call متأكد منه. لما clients كتير يحتاجوا باب واحد.
  • الـ load balancer: request داخل، ونفس الـ request لـ instance سليمة. من أول اتنين instances.
  • الـ reverse proxy: HTTP خام داخل، و HTTP نضيف خارج (TLS و gzip و buffering).
  • الـ HIT في الـ edge بيفوّت كل اللي وراه ومنهم الـ auth. عمرك ما تعلّم data خاصة إنها public.
  • الـ relational هو الـ default، والـ document للـ aggregates المستقلة، والـ key-value لما تبقى دايمًا عارف الـ key، والـ cache عمره ما يبقى النسخة الوحيدة.
  • الـ Redis العادي مفيهوش فلتر ad hoc. والـ $lookup من غير index على الـ foreign field بيعمل scan لكل document (60 مليون في تجربتنا).
  • الـ queue: message صغيرة داخلة وبتتسلّم بعدين. والـ object storage: key وبايتات داخلين ونفس البايتات خارجين، durable.
  • الملفات عمرها ما تدخل جوه messages: استخدم claim check (400 MB مقابل 0.005 MB في تجربتنا).
  • الـ DNS: اسم داخل، وعناوين و TTL خارجين.
  • كل box لازم يبقى ليه جملة: داخل إيه، خارج إيه، وأنهي رقم أو requirement بيفرضه.
