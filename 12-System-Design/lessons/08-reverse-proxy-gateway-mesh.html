Why this matters · ليه ده مهم

English

Reverse proxies, gateways and meshes all sit in the request path, and each one takes work out of your Node processes. Done well, a 1-second cache took an origin from 1400 hits to 3 in the runs below. Done badly, the same layer multiplies a failure: three layers that each retry three times turned 100 requests into 2700 hits on a struggling payments service.

The questions you'll get at work and in interviews are about placement. Where does auth belong? Who owns the timeout? Does this team need a mesh? This lesson builds each piece in Node so you can count what it does. Every proxy, gateway and sidecar here is a Node stand-in, labelled as such. nginx, Envoy and Istio configs are real but marked Not run here.

Part 1 — Reverse proxy jobs 🟡 Intermediateالجزء 1 — شغل الـ reverse proxy

English

Section 03, part 4 builds a basic proxy. This one adds the three jobs that pay for it, and measures them:

  • TLS termination: the proxy holds the certificate. The client negotiated TLS 1.3, and the origin saw plain HTTP plus x-forwarded-proto: https. Your app has no certificates to rotate, and it must trust that header only from the proxy.
  • Compression: 45,121 bytes of order JSON became 3,560 bytes (92.1% saved) in about 0.4 ms. Compress once per cache entry, not once per client. Don't gzip what's already compressed (images, video).
  • Microcaching: a 1-second cache sounds useless and is the best trick here. Under the same load the origin went from 1400 hits with no cache to 60 with a 1 s cache, because of the misses that pile up at each expiry, and to 3 once concurrent misses wait on one upstream request (coalescing, proxy_cache_lock in nginx). Only cache responses that are safe to share: never anything per-user without the user in the key.

Current fact: community ingress-nginx was retired in March 2026, with no further releases or security fixes, and the Kubernetes project points to the Gateway API. That is the Kubernetes controller. nginx itself is not retired.

const pemKey = async (keys: CryptoKeyPair) => {
  const der = await crypto.subtle.exportKey("pkcs8", keys.privateKey);
  return `-----BEGIN PRIVATE KEY-----\n${Buffer.from(der).toString("base64")}\n-----END PRIVATE KEY-----\n`;
};

export async function createCa(name = "Shop Internal CA") {
  const caKeys = await crypto.subtle.generateKey(alg, true, ["sign", "verify"]);
  const ca = await x509.X509CertificateGenerator.createSelfSigned({
    serialNumber: "01", name: `CN=${name}`, notBefore, notAfter, signingAlgorithm: alg, keys: caKeys,
    extensions: [
      new x509.BasicConstraintsExtension(true, 1, true),
      new x509.KeyUsagesExtension(x509.KeyUsageFlags.keyCertSign, true),
    ],
  });
  const issue = async (cn: string, dns = "localhost") => {
    const keys = await crypto.subtle.generateKey(alg, true, ["sign", "verify"]);
    const cert = await x509.X509CertificateGenerator.create({
      serialNumber: String(Math.floor(Math.random() * 1e8) + 2), subject: `CN=${cn}`, issuer: ca.subject,
      notBefore, notAfter, signingAlgorithm: alg, publicKey: keys.publicKey, signingKey: caKeys.privateKey,
      extensions: [new x509.SubjectAlternativeNameExtension([{ type: "dns", value: dns }])],
    });
    return { key: await pemKey(keys), cert: cert.toString("pem") };
  };
  return { ca: ca.toString("pem"), issue };
}

const agent = new http.Agent({ keepAlive: true });
const fetchOrigin = (path: string, proto: string) =>
  new Promise<Buffer>((resolve, reject) => {
    http.get({ port: originPort, host: "127.0.0.1", path, agent, headers: { "x-forwarded-proto": proto } }, (r) => {
      const chunks: Buffer[] = [];
      r.on("data", (c: Buffer) => chunks.push(c));
      r.on("end", () => resolve(Buffer.concat(chunks)));
    }).on("error", reject);
  });

type Entry = { body: Buffer; gz: Buffer; expires: number };

function makeProxy(opts: { ttlMs: number; coalesce: boolean }) {
  const cache = new Map<string, Entry>();
  const inflight = new Map<string, Promise<Entry>>();
  const load = async (key: string, proto: string): Promise<Entry> => {
    const body = await fetchOrigin(key, proto);
    // بنضغط مرة واحدة لكل cache entry، مش مرة لكل client
    const entry = { body, gz: gzipSync(body), expires: Date.now() + opts.ttlMs };
    if (opts.ttlMs > 0) cache.set(key, entry);
    return entry;
  };
  return async (req: http.IncomingMessage, res: http.ServerResponse) => {
    const key = req.url!;
    const proto = "encrypted" in req.socket ? "https" : "http";
    let entry = cache.get(key);
    if (!entry || entry.expires < Date.now()) {
      if (opts.coalesce) {
        // كل الـ misses في نفس اللحظة بيستنوا طلب واحد للـ origin
        let p = inflight.get(key);
        if (!p) {
          p = load(key, proto).finally(() => inflight.delete(key));
          inflight.set(key, p);
        }
        entry = await p;
      } else {
        entry = await load(key, proto);
      }
    }
    res.setHeader("content-type", "application/json");
    if (/\bgzip\b/.test(String(req.headers["accept-encoding"]))) {
      res.setHeader("content-encoding", "gzip");
      res.end(entry.gz);
    } else {
      res.end(entry.body);
    }
  };
}

Section 03 part 4 بيبني proxy بسيط. هنا بنزود التلات شغلات اللي بتستاهل التعب، وبنقيسهم:

  • الـ TLS termination: الـ certificate عند الـ proxy. العميل عمل TLS 1.3، والـ origin شاف HTTP عادي ومعاه x-forwarded-proto: https. الـ app بتاعك مفيهوش certificates تتجدد، وبس لازم يصدق الـ header ده من الـ proxy بس.

  • الـ microcaching: cache لمدة ثانية شكله مالوش لازمة وهو أحسن حيلة هنا. تحت نفس الحمل الـ origin نزل من 1400 hit من غير cache لـ 60 بالـ cache لمدة ثانية، بسبب الـ misses اللي بتتراكم وقت كل expiry، ولـ 3 لما الـ misses المتزامنة بقت تستنى request واحد (coalescing، وده proxy_cache_lock في nginx). خزّن بس الردود اللي ينفع تتشارك، وأي حاجة per-user لازم الـ user يبقى في الـ key.

Part 2 — Buffering & slow clients 🟡 Intermediateالجزء 2 — الـ buffering والـ clients البطيئين

English

Without buffering, a slow client holds a backend connection for its entire download. Five clients each read a 4 MB response at about 1 MB/s through the stand-in proxy. With buffering off, the backend held each request for ≈3.3 s (it finishes before the client does because kernel socket buffers absorb the tail). With buffering on, the proxy read the whole body at full speed, and the backend was free in ≈41 ms, about 79× less. The client took ≈5 s either way, since its speed didn't change. That is the point: a backend worker or a connection slot is expensive, and proxy memory is cheap.

The cost is on the proxy: ≈20 MB held for five clients here, and real proxies spill large responses to disk. And don't buffer streams: Server-Sent Events and long downloads need proxy_buffering off, or the client gets nothing until the buffer fills.

Slowloris abuses the same slowness on the way in, by sending headers one line at a time and never finishing. Node defends with headersTimeout, 60 s by default, checked by a timer every 30 s (connectionsCheckingInterval). In the run, with the limit lowered to 1 s and the check to 200 ms, all 30 attackers were answered with 408 Request Timeout and closed within 3 s. With timeouts disabled all 30 stayed open.

The proxy also enforces body and connection limits before your app spends anything on a bad request. A 2 MB upload against a 1 MB limit got 413, and 5 connections from one IP with a limit of 3 had 3 stay open and 2 closed. One detail from the first run: if you destroy the socket the moment you see too many bytes, the client reports a generic network failure instead of 413, so answer first and close a moment later. Request-rate limiting also lives here, and the algorithms are in lesson 25.

// تجربة: عملاء بطيئين، proxy بيعمل buffering أو لأ، وعداد الـ inflight عند الـ backend.
import http from "node:http";
import net from "node:net";
import { once } from "node:events";
import type { AddressInfo } from "node:net";

const sleep = (ms: number) => new Promise((r) => setTimeout(r, ms));
const CHUNK = Buffer.alloc(64 * 1024, "x");
const BODY_CHUNKS = 64;
const BODY_BYTES = CHUNK.length * BODY_CHUNKS;

const stats = { inflight: 0, peak: 0, heldMs: [] as number[] };
const backend = http.createServer(async (_req, res) => {
  stats.inflight++;
  stats.peak = Math.max(stats.peak, stats.inflight);
  const t0 = performance.now();
  res.setHeader("content-length", BODY_BYTES);
  for (let i = 0; i < BODY_CHUNKS; i++) {
    if (!res.write(CHUNK)) await once(res, "drain");
  }
  res.end();
  await once(res, "finish");
  stats.inflight--;
  stats.heldMs.push(performance.now() - t0);
});
await new Promise<void>((r) => backend.listen(0, "127.0.0.1", r));
const backendPort = (backend.address() as AddressInfo).port;

function startProxy(buffering: boolean) {
  let bufferedNow = 0, bufferedPeak = 0;
  const server = http.createServer((req, res) => {
    const up = http.get({ port: backendPort, host: "127.0.0.1", path: req.url }, async (r) => {
      res.writeHead(r.statusCode ?? 502, { "content-length": r.headers["content-length"] });
      if (!buffering) return void r.pipe(res);
      // الـ proxy بيستلم كل الـ body بسرعة ويحرر الـ backend، وبعدين يبعت للعميل براحته
      const chunks: Buffer[] = [];
      for await (const c of r) { chunks.push(c as Buffer); bufferedNow += (c as Buffer).length; }
      bufferedPeak = Math.max(bufferedPeak, bufferedNow);
      res.end(Buffer.concat(chunks), () => (bufferedNow -= BODY_BYTES));
    });
    up.on("error", () => res.destroy());
  });
  return { server, peak: () => bufferedPeak };
}

function slowClient(port: number, bytesPerSec: number) {
  return new Promise<number>((resolve) => {
    const t0 = performance.now();
    const s = net.connect(port, "127.0.0.1", () => s.write("GET /export.csv HTTP/1.1\r\nHost: shop\r\nConnection: close\r\n\r\n"));
    let got = 0;
    s.on("data", (d) => {
      got += d.length;
      s.pause();
      setTimeout(() => s.resume(), (d.length / bytesPerSec) * 1000);
    });
    s.on("close", () => resolve(Math.round(performance.now() - t0)));
    s.on("error", () => {});
  });
}

async function slowloris(name: string, opts: http.ServerOptions) {
  const server = http.createServer(opts, (_req, res) => res.end("ok"));
  await new Promise<void>((r) => server.listen(0, "127.0.0.1", r));
  const port = (server.address() as AddressInfo).port;
  const socks = Array.from({ length: 30 }, () => {
    const s = net.connect(port, "127.0.0.1", () => s.write("GET /orders HTTP/1.1\r\nHost: shop\r\n"));
    const state = { open: true, first: "" };
    s.on("data", (d) => (state.first ||= d.toString().split("\r\n")[0]!));
    s.on("close", () => (state.open = false));
    s.on("error", () => {});
    const t = setInterval(() => { if (state.open) s.write(`x-a: ${Date.now()}\r\n`); }, 300);
    return { s, state, t };
  });
  await sleep(3000);

Part 3 — A working API gateway 🟡 Intermediateالجزء 3 — API gateway شغال

English

A reverse proxy is about traffic. An API gateway adds API-level concerns: who is calling, how much they may call, and what shape the request should be when it reaches a service. The Fastify stand-in below does exactly five things: routing to orders and users, JWT verification with jose, a per-key limiter, an analytics counter, and one request transformation that renames customer_id to customerId. Services receive x-user-id and never see the token.

Real calls through it: no token and a bad token both got 401, the transformation arrived as {"customerId":42,...}, and six quick calls on the free plan went 200 200 200 200 429 429 (one token was already spent on the POST). The per-key limiter here is per process, so it undercounts when you run several gateways: that's why the real thing needs Redis, as in lesson 25.

Latency cost: the gateway added ≈3 ms at p50 and dropped throughput from ≈29,472 rps to ≈2,994 rps. One ES256 verification took ≈0.18 ms, so the JWT is not the main cost. Most of it is the extra HTTP hop and Fastify, and here the load generator shares the process, so read the ratio, not the numbers.

The rule that matters: no business rules in the gateway. Discounts, order limits and pricing tiers need domain data and need tests next to the code that owns them. A gateway that knows about plans and products becomes a shared bottleneck that every team has to deploy through. For gateway vs BFF see section 11 · 3.3.

function service(name: string) {

type Bucket = { tokens: number; last: number };

const allow = (key: string, rate: number, burst: number) => {
  const now = performance.now();
  const b = buckets.get(key) ?? { tokens: burst, last: now };
  b.tokens = Math.min(burst, b.tokens + ((now - b.last) / 1000) * rate);
  b.last = now;
  buckets.set(key, b);
  if (b.tokens < 1) return false;
  b.tokens -= 1;
  return true;
};

Part 4 — Aggregation 🟡 Intermediateالجزء 4 — الـ aggregation

English

GET /me/dashboard fans out to orders, notifications and recommendations, and one of them hangs for 2 s on 5% of calls. The chance that a dashboard hits the slow path is the chance that any call does, so one flaky dependency sets the tail of the whole page.

With plain Promise.all and no deadline, p99 was ≈2035 ms and throughput was ≈170 rps. With a deadline per call (AbortSignal.timeout) and Promise.allSettled, the response returns what it has with degraded: true and missing: [...]. p99 fell to ≈166 ms, throughput rose to ≈399 rps, and 95 responses were degraded. Decide per call: orders is required (fail the whole response), while notifications and recommendations are optional. Keep the deadlines inside the caller's own budget. Next step: when a dependency keeps failing, stop calling it at all, with a circuit breaker in lesson 24.

// تجربة: ⁦/me/dashboard⁩ بيجمع من 3 خدمات، وواحدة منها أوقات بتعلّق ثانيتين.

function upstream(name: string, delay: () => number) {
  const server = http.createServer((_req, res) => {
    setTimeout(() => { res.setHeader("content-type", "application/json"); res.end(JSON.stringify({ [name]: "data" })); }, delay());
  });
  return new Promise<{ url: string; stop(): void }>((resolve) => server.listen(0, "127.0.0.1", () => resolve({
    url: `http://127.0.0.1:${(server.address() as AddressInfo).port}/`,
    stop() { server.closeAllConnections(); server.close(); },
  })));
}

    { name: "recommendations", url: recommendations.url, ms: 150, required: false },

  const out: Record<string, unknown> = {};

    if (r.status === "fulfilled") Object.assign(out, r.value);
    else if (calls[i]!.required) throw new Error(`${calls[i]!.name} unavailable`);
    else missing.push(calls[i]!.name);
  });
  if (missing.length) degradedCount++;
  return { ...out, degraded: missing.length > 0, missing };
}

Part 5 — Service mesh 🟡 Intermediateالجزء 5 — الـ service mesh

English

A mesh moves mTLS, retries, timeouts and telemetry out of every service's code into a proxy the platform runs. The mini version below is a real one: orders talks plain HTTP to its sidecar on localhost, the sidecars speak mTLS to each other with certificates from @peculiar/x509, and the outbound sidecar retries 503s.

  • Identity: payments learned its caller was orders-service from the client certificate, not from a header anyone could forge.
  • Refusal: without a client certificate the TLS handshake failed with ERR_SSL_TLSV13_ALERT_CERTIFICATE_REQUIRED, before any HTTP.
  • Retries outside the code: 300 calls hit 20% transient failures, payments saw 374 requests, the sidecar retried 74 times, and the application saw 0 failures.
  • Cost: direct was ≈28,029 rps at p50 ≈0 ms, through two sidecars with mTLS ≈6,322 rps at p50 ≈1 ms and p99 ≈4 ms. Each Node sidecar used about 86–150 MB RSS. Istio's published figure for its Envoy sidecar at 1,000 rps (version 1.24) is about 0.20 vCPU and 60 MB per sidecar. Multiply that by every pod in the fleet.

The README says "sidecar per service", but that's one mode. Istio ambient mode has no sidecars: a per-node ztunnel handles L4 mTLS, and optional waypoint proxies handle L7 features for the namespaces that need them. Istio's docs put ztunnel at about 0.06 vCPU and 12 MB at the same 1,000 rps. Linkerd uses small Rust sidecars. Real meshes also need what this demo skips: a control plane that issues and rotates certificates, service discovery and config distribution. That's the operational bill.

import https from "node:https";
import type { TLSSocket } from "node:tls";
import type { AddressInfo } from "node:net";

type Config = { name: string; key: string; cert: string; ca: string; appPort?: number; peerPort?: number; retries: number };
const cfg = JSON.parse(process.env.SIDECAR_CONFIG!) as Config;
const stats = { retries: 0 };

const localAgent = new http.Agent({ keepAlive: true });
const peerAgent = new https.Agent({ keepAlive: true, key: cfg.key, cert: cfg.cert, ca: cfg.ca, servername: "localhost" });

// الـ inbound: لازم شهادة client موقعة من نفس الـ CA، وبنعدّي الهوية للـ app
const inbound = https.createServer(
  { key: cfg.key, cert: cfg.cert, ca: cfg.ca, requestCert: true, rejectUnauthorized: true },
  (req, res) => {
    const peer = (req.socket as TLSSocket).getPeerCertificate().subject?.CN ?? "unknown";
    const up = http.request(
      { port: cfg.appPort!, host: "127.0.0.1", path: req.url, method: req.method, agent: localAgent, headers: { ...req.headers, "x-peer-identity": peer } },
      (r) => { res.writeHead(r.statusCode ?? 502, r.headers); r.pipe(res); },
    );
    up.on("error", () => { res.statusCode = 502; res.end(); });
    req.pipe(up);
  },
);

function callPeer(req: http.IncomingMessage, body: Buffer) {
  return new Promise<{ status: number; headers: http.IncomingHttpHeaders; data: Buffer }>((resolve) => {
    const up = https.request(
      { port: cfg.peerPort!, host: "127.0.0.1", path: req.url, method: req.method, agent: peerAgent, headers: req.headers },
      (r) => {
        const chunks: Buffer[] = [];
        r.on("data", (c: Buffer) => chunks.push(c));
        r.on("end", () => resolve({ status: r.statusCode ?? 502, headers: r.headers, data: Buffer.concat(chunks) }));
      },
    );
    up.on("error", () => resolve({ status: 0, headers: {}, data: Buffer.alloc(0) }));
    up.end(body);
  });
}

// الـ outbound: بيسمع على localhost بس، وبيعمل retry على 503 والأخطاء
const outbound = http.createServer(async (req, res) => {
  const chunks: Buffer[] = [];
  for await (const c of req) chunks.push(c as Buffer);
  const body = Buffer.concat(chunks);
  let r = await callPeer(req, body);
  for (let i = 0; i < cfg.retries && (r.status === 503 || r.status === 0); i++) {
    stats.retries++;
    r = await callPeer(req, body);
  }
  res.writeHead(r.status || 502, r.headers);
  res.end(r.data);
});

await Promise.all([
  new Promise<void>((r) => inbound.listen(0, "127.0.0.1", r)),
  new Promise<void>((r) => outbound.listen(0, "127.0.0.1", r)),
]);
process.send!({
  type: "ready",
  inboundPort: (inbound.address() as AddressInfo).port,
  outboundPort: (outbound.address() as AddressInfo).port,
});

  if (m === "stats") process.send!({ type: "stats", rssMb: Math.round(process.memoryUsage().rss / 1e6), retries: stats.retries });
  if (m === "stop") process.exit(0);
});

Part 6 — Gateway vs mesh 🟡 Intermediateالجزء 6 — الـ gateway ضد الـ mesh

English

Each layer's retries are reasonable alone. Stacked, they multiply. The stand-ins below chain client → gateway → sidecar → payments, each with 3 attempts, and payments returns 503 every time. 100 client requests produced 2700 hits on payments, 27× the original traffic, sent to a service that was already failing. With retries in one layer only it was 300 hits. With that layer on a 20% retry budget (retries are allowed only while they stay under 20% of requests) it was 120. Backoff and storms are covered in lesson 23.

Who owns the timeout? The caller, and every layer below must spend less than what's left. In the second experiment the client waits 300 ms, and the service takes 800 ms. Without propagation, all 20 clients timed out and the service finished all 20 anyway: work done for nobody, possibly a duplicate charge. With the remaining budget passed down (x-deadline-ms), the service refused immediately: 20 fast 504s and no wasted work. gRPC has deadline propagation built in; with HTTP you carry it yourself.

When a mesh isn't worth it: a handful of services, one language, and nobody whose job includes running it. Sidecars, certificates and upgrades are a platform team's work. Pick the simplest thing that gets you mTLS and consistent timeouts.

type Budget = { requests: number; retries: number; ratio: number };

// طبقة بتعمل حتى attempts محاولات، مع budget اختياري
function layer(next: string, attempts: number, budget?: Budget) {
  return http.createServer(async (_req, res) => {
    if (budget) budget.requests++;
    let status = 0;
    for (let a = 1; a <= attempts; a++) {
      if (a > 1 && budget) {
        // الـ retry بيتحسب من الـ budget، ولو خلص بنوقف
        if (budget.retries >= budget.requests * budget.ratio) break;
        budget.retries++;
      }
      status = await fetch(next).then(async (r) => { await r.arrayBuffer(); return r.status; }, () => 0);
      if (status === 200) break;
    }
    res.statusCode = status || 502;
    res.end();
  });
}

async function chain(name: string, sidecarAttempts: number, gatewayAttempts: number, clientAttempts: number, budget?: Budget) {
  paymentHits = 0;
  const sidecar = layer(paymentsUrl, sidecarAttempts, budget);
  const gateway = layer(await listen(sidecar), gatewayAttempts);
  const gwUrl = await listen(gateway);
  const N = 100;
  for (let i = 0; i < N; i++) {
    for (let a = 1; a <= clientAttempts; a++) {
      const s = await fetch(gwUrl).then(async (r) => { await r.arrayBuffer(); return r.status; }, () => 0);
      if (s === 200) break;
    }
  }
  console.log(`${name.padEnd(42)} ${N} client requests -> ${paymentHits} hits on payments (${(paymentHits / N).toFixed(1)}x)`);
  for (const s of [sidecar, gateway]) { s.closeAllConnections(); s.close(); }
}

الجدول سطر بسطر: نوع الـ traffic: الـ gateway north-south من العملاء للخدمات، والـ mesh east-west بين الخدمات. بيخدم مين: الـ gateway مستخدمي الـ API والـ product، والـ mesh أصحاب الخدمات والـ platform. المميزات المعتادة: الـ gateway الـ auth و rate limits لكل key وتجميع الـ APIs والـ transformation والـ analytics، والـ mesh الـ mTLS والـ retries والـ timeouts والـ telemetry و traffic shifting. بيشتغل إزاي: الـ gateway طبقة مشتركة على الـ edge، والـ mesh sidecars أو proxies على الـ nodes جنب الـ workloads. نطاق العطل: الـ gateway بيوقّع الـ API كله، والـ mesh غالبًا per pod أو node، بس غلطة config ممكن تبقى global.
بالعامية

الـ retries بتاعة كل طبقة منطقية لوحدها، بس لما تتكوم بتتضرب في بعض. الـ stand-ins تحت بتربط client → gateway → sidecar → payments، كل واحد 3 محاولات، و payments بيرجع 503 دايمًا. 100 request من العميل بقوا 2700 hit على payments، يعني 27× الـ traffic الأصلي، على خدمة بتقع أصلًا. ولو الـ retries في طبقة واحدة: 300 hit. ولو الطبقة دي معاها retry budget 20% (الـ retries مسموحة طول ما هي أقل من 20% من الـ requests): 120. الـ backoff والـ storms في درس 23.

مين مسؤول عن الـ timeout؟ اللي بينادي، وكل طبقة تحتها لازم تصرف أقل من اللي فاضل. في التجربة التانية العميل بيستنى 300ms والخدمة بتاخد 800ms. من غير propagation كل الـ 20 عميل عملوا timeout والخدمة خلصت الـ 20 برضه: شغل لولا حد، وممكن charge مكرر. ولما مررنا الـ budget الفاضل (x-deadline-ms) الخدمة رفضت فورًا: 20 رد 504 سريع وصفر شغل ضايع. الـ gRPC عنده deadline propagation جاهز، وفي HTTP لازم تعمله بنفسك.

إمتى الـ mesh مش مستاهل: كام خدمة بس، ولغة واحدة، ومفيش حد شغلته يشغّله. الـ sidecars والشهادات والـ upgrades شغل platform team. اختار أبسط حاجة تديك mTLS و timeouts موحدة.

فين هستخدمه في شغلي؟ لما تعمل incident review وتلاقي الـ DB وقعت عشان 50× traffic وقت الـ blip، ابدأ بعدّ الطبقات اللي بتعمل retry: SDK في الـ frontend، و axios-retry في الـ BFF، و retry في الـ gateway. سيب طبقة واحدة، وخليها مع budget و jitter. والغلطة الشائعة: كل فريق يضيف retry عنده عشان "آمن"، ومفيش حد شايف الصورة كلها.

Common mistakes · غلطات شائعة

❌ Business rules in the gateway 
// الخصم ده مكانه خدمة الـ orders
app.addHook("preHandler", async (req) => {
  if (req.plan === "gold" && req.body.total > 1000) {
    req.body.discount = 0.1;
  }
});
✅ Cross-cutting concerns only 
// الـ gateway بيضيف هوية المستخدم بس
app.addHook("preHandler", async (req) => {
  req.headers["x-user-id"] = req.userId;
  req.headers["x-plan"] = req.plan;
});
بالعامية

❌ الخصم في الـ gateway معناه أي تغيير تسعير يبقى deploy لطبقة قدّام كل الخدمات، ومن غير domain tests. ✅ الـ gateway بيبعت الهوية والـ plan، وخدمة الـ orders هي اللي بتقرر الخصم بالـ tests بتاعتها.

❌ Retries at every layer 
// كل طبقة بتعمل 3 محاولات من غير ما تعرف عن التانية
const client = axios.create();
axiosRetry(client, { retries: 3 });
// البوابة كمان بتعمل retry، والـ sidecar كمان
✅ One layer retries, with a budget 
// الـ retry هنا بس، وبيتوقف لو زاد عن 20%
const allowed = budget.retries < budget.requests * 0.2;
if (status === 503 && allowed) {
  budget.retries++;
  return send(req);
}
بالعامية

❌ 3 طبقات × 3 محاولات عملت 27 hit لكل request على خدمة واقعة أصلًا. ✅ طبقة واحدة بس تعمل retry، ومعاها budget عشان وقت العطل تقف لوحدها: نزلت من 2700 لـ 120 hit في التجربة.

❌ Fan-out with no deadlines 
// لو خدمة علّقت، الـ dashboard كله بيعلق
const [orders, recs] = await Promise.all([
  getOrders(userId),
  getRecommendations(userId),
]);
✅ Deadline per call + partial response 
// الجزء الاختياري يتشال لو اتأخر
const [orders, recs] = await Promise.allSettled([
  getOrders(userId, AbortSignal.timeout(300)),
  getRecommendations(userId, AbortSignal.timeout(150)),
]);
بالعامية

❌ Promise.all من غير deadlines خلّى p99 ≈2035ms بسبب خدمة واحدة. ✅ deadline لكل call و Promise.allSettled خلّوا p99 ≈166ms، والرد بيرجع degraded: true بدل ما يعلق.

❌ Trusting identity headers from anywhere 
// أي حد يقدر يبعت الـ header ده لو الخدمة مكشوفة
const userId = req.headers["x-user-id"];
return getOrdersFor(userId);
✅ Trust only the gateway's path 
// الـ header مقبول بس لو الطلب جاي من الـ gateway بـ mTLS
const peer = (req.socket as TLSSocket).getPeerCertificate().subject?.CN;
if (peer !== "api-gateway") throw new ForbiddenError();
const userId = req.headers["x-user-id"];
بالعامية

❌ لو الخدمة وصلها traffic من غير الـ gateway، أي حد يقدر يزور x-user-id ويقرا بيانات أي مستخدم. ✅ اقبل الـ header بس من الـ gateway، بـ mTLS زي Part 5 أو بـ network policy، ورفض أي مصدر تاني.

Try it yourself · جرّب بنفسك

1. Find the coalescing gain 🟢 easy In p1-proxy.ts, raise the origin delay from 15 ms to 200 ms and rerun. Compare originHits with and without coalescing and explain the difference.
في p1-proxy.ts زود الـ origin delay من 15ms لـ 200ms وشغّله تاني. قارن originHits بالـ coalescing ومن غيره، واشرح الفرق.
Hint · تلميح Each expiry opens a window as long as the origin call. With a slower origin, more of the 20 connections miss inside that window.
كل expiry بيفتح شباك طوله قد وقت الـ origin call. لو الـ origin أبطأ، عدد أكبر من الـ 20 connection بيعملوا miss جوه الشباك ده.
2. Add a request id and a timeout budget 🟡 medium In the gateway from p3-gateway.ts, add an x-request-id (generated if the client didn't send one) and an x-deadline-ms header forwarded to the services. Verify both arrive in the echo response.
في الـ gateway بتاع p3-gateway.ts ضيف x-request-id (يتولد لو العميل مابعتوش) و x-deadline-ms يتبعت للخدمات. اتأكد إن الاتنين وصلوا في الـ echo.
Solution · الحل 
import { randomUUID } from "node:crypto";

// الـ gateway بيولّد الـ id لو مش موجود، والـ budget بياخد أقل قيمة
function forwardedHeaders(incoming: Record<string, string | undefined>, defaultBudgetMs: number) {
  const clientBudget = Number(incoming["x-deadline-ms"] ?? defaultBudgetMs);
  return {
    "x-request-id": incoming["x-request-id"] ?? randomUUID(),
    "x-deadline-ms": String(Math.min(clientBudget, defaultBudgetMs)),
  };
}

console.log(forwardedHeaders({ "x-request-id": "abc", "x-deadline-ms": "300" }, 1000));
// → { 'x-request-id': 'abc', 'x-deadline-ms': '300' }
console.log(forwardedHeaders({ "x-deadline-ms": "5000" }, 1000)["x-deadline-ms"]);
// → 1000
العميل مايقدرش يطلب budget أكبر من اللي الـ gateway مسموح بيه: بناخد الأقل بين الاتنين. والـ x-request-id بيتولد لو مش موجود عشان تربط الـ logs ببعضها.
3. Hide a failing sidecar 🔴 hard In sidecar.ts, the outbound side retries immediately. Add exponential backoff with jitter and a per-try timeout. Then make payments stall for 300 ms instead of returning 503, and show the retries now protect the caller's budget.
في sidecar.ts الـ retry فوري. ضيف exponential backoff مع jitter و timeout لكل محاولة. وبعدين خلي payments يعلق 300ms بدل ما يرجع 503، ووريني إن الـ retries بقت بتحمي الـ budget بتاع اللي بينادي.
Hint · تلميح Use AbortSignal.timeout(perTryMs) around each attempt and compute the delay as Math.random() * Math.min(cap, base * 2 ** attempt). Make sure the total stays inside the incoming deadline.
استخدم AbortSignal.timeout(perTryMs) حوالين كل محاولة، واحسب التأخير Math.random() * Math.min(cap, base * 2 ** attempt)، واتأكد إن المجموع جوه الـ deadline اللي جاي.
4. In your project / at work 🔴 project Draw every layer between a user and your database and write next to each: does it retry, what's its timeout, and where is auth checked? Then remove one duplicate retry, and add one deadline that flows from the edge to the database.
ارسم كل طبقة بين المستخدم والـ DB بتاعتك، واكتب جنب كل واحدة: بتعمل retry؟ الـ timeout بتاعها كام؟ والـ auth بيتراجع فين؟ وبعدين شيل retry مكرر، وضيف deadline واحد بيمشي من الـ edge لحد الـ DB.

Cheat sheet · الخلاصة

  • Reverse proxy: TLS termination, gzip, microcache, buffering, limits. A 1 s microcache with coalescing took the origin from 1400 hits to 3.
  • Buffering frees backends from slow clients (≈3.3 s to ≈41 ms held). Never buffer SSE or long streams.
  • Slowloris: keep headersTimeout and requestTimeout on. Node's defaults are 60 s and 300 s, and the check runs every 30 s.
  • Answer 413 before closing the socket, or the client just sees a reset.
  • Community ingress-nginx retired in March 2026; the Kubernetes path is Gateway API. nginx itself continues.
  • Gateway: routing, auth, per-key limits, transformation, analytics. No business rules. Strip the token and forward the identity.
  • Aggregation: deadline per call + allSettled + degraded: true. p99 went from ≈2035 ms to ≈166 ms.
  • Mesh moves mTLS, retries, timeouts out of code. Sidecars are one mode; Istio ambient uses a per-node ztunnel plus optional waypoints.
  • Retries multiply across layers (27× here). Retry in one layer, with a budget.
  • The caller owns the timeout. Propagate the remaining budget so services can refuse work nobody will read.
بالعامية

  • الـ buffering بيحرر الـ backends من العملاء البطيئين (من ≈3.3 ثانية لـ ≈41ms). وأوعى تعمل buffering لـ SSE أو streams طويلة.
  • الـ Slowloris: سيب headersTimeout و requestTimeout شغالين. defaults الـ Node 60 ثانية و 300 ثانية، والفحص كل 30 ثانية.
  • رد بـ 413 قبل ما تقفل الـ socket، وإلا العميل هيشوف reset بس.
  • الـ community ingress-nginx اتقاعد في مارس 2026، والطريق في Kubernetes هو Gateway API. و nginx نفسه مكمل.
  • الـ gateway: routing و auth و limits لكل key و transformation و analytics. مفيش business rules. شيل الـ token وابعت الهوية.
  • الـ aggregation: deadline لكل call مع allSettled مع degraded: true. الـ p99 نزل من ≈2035ms لـ ≈166ms.
  • الـ mesh بينقل الـ mTLS والـ retries والـ timeouts بره الكود. والـ sidecars وضع واحد بس، و Istio ambient بيستخدم ztunnel لكل node مع waypoints اختيارية.

  • اللي بينادي هو صاحب الـ timeout. مرر الـ budget الفاضل عشان الخدمات ترفض شغل محدش هيقراه.
