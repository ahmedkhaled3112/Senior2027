Why this matters · ليه ده مهم

English

The README names seven Hards for the Senior loop. What the round actually tests is less "do you know this problem" and more "can you hold two solutions in your head and say why you'd pick one". So each drill here has a brute force, two real approaches, and measurements. Some of those measurements go against the usual advice: the heap makes more comparisons than divide and conquer, and it still wins for streaming.

These seven also show up in real systems: K-way merges across shards, latency percentiles, LFU eviction in Redis, migration ordering, and deep JSON taking a process down.

Part 1 — Merge K sorted feeds 🔴 Advancedالجزء 1 — دمج K feeds مترتبين

⏱ Timed prompt · 35 minutes (classic: merge k lists) Orders are spread across K database shards. Each shard gives you a cursor of orders sorted by createdAt. Produce one feed sorted by createdAt, oldest first. Orders with equal timestamps must come out in a stable order. Say how your solution behaves when the caller only wants the first 20.
الـ orders موزعة على K shards. كل shard بيديك cursor من orders مترتبة بـ createdAt. طلّع feed واحد مترتب بـ createdAt من الأقدم للأحدث. والـ orders اللي ليها نفس الـ timestamp لازم تطلع بترتيب ثابت. وقول الحل بتاعك بيعمل إيه لو اللي بيطلب عايز أول 20 بس.
English

doubling.ts and min-heap.ts come from lesson 05, Parts 2 and 4.

Brute force. Collect every row and sort: O(N log N), O(N) memory. Approach A, k-way heap. Put the first row of each shard in a min-heap; pop the smallest, then pull the next row from that same shard. O(N log k) time, O(k) memory, and it reads a shard only when it needs the next row. Approach B, pairwise divide and conquer. Merge shards in pairs, then pairs of pairs. Same O(N log k) bound, but it holds O(N) rows in memory.

What to expect before measuring. A heap costs up to two comparisons per level, so about 2·N·log₂k; pairwise costs about N·log₂k. So the heap should lose on comparisons, and it does. Also, V8's sort is Timsort, which detects already-sorted runs, so "collect and sort" on K concatenated shards is much cheaper than N log N; it only reaches that when the rows are shuffled.

Why the heap still wins here. The heap isn't cheaper per row; it is lazy and small. The first 20 rows of a 100-shard feed need about 119 rows read from the shards, against 100,000 for collect-and-sort. Pairwise can be made lazy too, with a tree of generators, but then each row passes through log k generator frames. Use the heap for streams and pagination; use pairwise when everything is already in memory and you want the simplest loop.

import { noop, type Tick } from "./doubling.ts";
import { MinHeap } from "./min-heap.ts";

export interface Order {
  id: string;
  createdAt: number;
}

// كسر التعادل بالـ id عشان الترتيب يبقى ثابت بين shards
export const byTime = (a: Order, b: Order): number =>
  a.createdAt - b.createdAt || (a.id < b.id ? -1 : a.id > b.id ? 1 : 0);

// الـ brute: اجمع كل الصفوف ورتّبها، كله في الـ memory
export function mergeBySort(shards: Iterable<Iterable<Order>>, tick: Tick = noop): Order[] {
  const all: Order[] = [];
  for (const shard of shards) for (const order of shard) all.push(order);
  return all.sort((a, b) => { tick(); return byTime(a, b); });
}

interface Head {
  order: Order;
  cursor: Iterator<Order>;
}

// الحل A: heap فيه أول صف من كل shard، ⁦O(N log k)⁩ و memory قدها k
export function* mergeKHeap(shards: Iterable<Iterable<Order>>, tick: Tick = noop): Generator<Order> {
  const heap = new MinHeap<Head>((a, b) => { tick(); return byTime(a.order, b.order); });
  for (const shard of shards) {
    const cursor = shard[Symbol.iterator]();
    const first = cursor.next();
    if (!first.done) heap.push({ order: first.value, cursor });
  }
  while (heap.size > 0) {
    const head = heap.pop()!;
    yield head.order;
    // هنا بس بنطلب الصف اللي بعده من نفس الـ shard
    const next = head.cursor.next();
    if (!next.done) heap.push({ order: next.value, cursor: head.cursor });
  }
}

function mergeTwo(a: readonly Order[], b: readonly Order[], tick: Tick): Order[] {
  const out: Order[] = [];
  let i = 0;
  let j = 0;
  while (i < a.length && j < b.length) {
    tick();
    out.push(byTime(a[i], b[j]) <= 0 ? a[i++] : b[j++]);
  }
  while (i < a.length) out.push(a[i++]);
  while (j < b.length) out.push(b[j++]);
  return out;
}

// الحل B: ادمج كل اتنين مع بعض لحد ما يفضل واحد، ⁦O(N log k)⁩ و memory قدها N
export function mergePairwise(shards: ReadonlyArray<readonly Order[]>, tick: Tick = noop): Order[] {
  let round = shards.filter((shard) => shard.length > 0);
  if (round.length === 0) return [];
  while (round.length > 1) {
    const next: Array<readonly Order[]> = [];
    for (let i = 0; i < round.length; i += 2) {
      next.push(i + 1 < round.length ? mergeTwo(round[i], round[i + 1], tick) : round[i]);
    }
    round = next;
  }
  return [...round[0]];
}

الـ doubling.ts و min-heap.ts جايين من درس 05، الجزء 2 والجزء 4.

الـ brute force: اجمع كل الصفوف ورتّب، O(N log N) و O(N) memory. الحل A، الـ k-way heap: حط أول صف من كل shard في min-heap، طلّع الأصغر، وبعدين هات الصف اللي بعده من نفس الـ shard. O(N log k) وقت، O(k) memory، ومبيقراش من shard غير لما يحتاج الصف اللي بعده. الحل B، الـ pairwise divide and conquer: ادمج كل shardين، وبعدين كل نتيجتين. نفس O(N log k)، بس بيمسك O(N) صف في الـ memory.

المتوقع قبل القياس: الـ heap بيكلف لحد مقارنتين في كل مستوى، يعني حوالي 2·N·log₂k. والـ pairwise حوالي N·log₂k. فالـ heap المفروض يخسر في المقارنات، وده اللي حصل. وكمان sort بتاع V8 هو Timsort اللي بيكتشف الـ runs المترتبة، فـ "اجمع ورتّب" على K shards متوصلين أرخص بكتير من N log N، ومبيوصلش للرقم ده غير لما الصفوف تتبعتر.

ليه الـ heap برضه بيكسب هنا: مش عشان أرخص لكل صف. هو lazy وصغير. أول 20 صف من feed فيه 100 shard محتاجين 119 صف بس من الـ shards، مقابل 100,000 للـ collect and sort. والـ pairwise ممكن يبقى lazy بـ tree من generators، بس وقتها كل صف بيعدّي على log k مستوى. استخدم الـ heap للـ streams والـ pagination، والـ pairwise لما كل حاجة أصلًا في الـ memory وعايز أبسط loop.

Part 2 — Running median 🔴 Advancedالجزء 2 — الـ median المتحرك

⏱ Timed prompt · 30 minutes (classic: median of a data stream) Checkout latencies arrive one at a time. Build a class with add(ms) and median(), where median() can be asked after every value. An even count returns the average of the two middle values, and an empty stream returns null.
الـ latency بتاع الـ checkout بييجي رقم رقم. ابني class فيها add(ms) و median()، و median() ينفع يتسأل بعد كل قيمة. لو العدد زوجي رجّع متوسط القيمتين في النص، ولو الـ stream فاضي رجّع null.
English

Brute force. Append and re-sort on every value. A naive estimate is O(n log n) per insert; Timsort sees one out-of-place element, so in practice it is closer to n comparisons, and the total is still O(n²). Approach A, sorted array. Binary search for the position, then splice: O(log n) comparisons, O(n) element moves per insert. Approach B, two heaps. A max-heap for the lower half and a min-heap for the upper half: O(log n) per insert, O(1) for the median.

The invariants to say out loud: every value in lower ≤ every value in upper, and lower is either the same size as upper or one bigger. Both invariants hold again after each add with at most one move between the heaps.

Honest numbers. Doubling n shows x4 for A and about x2 for B, but A's moves are a memmove, so the wall-time gap is smaller than the op counts suggest until n is large. What production does instead: exact percentiles need every value kept, so metrics systems keep histograms or sketches, such as t-digest and DDSketch. See the metrics case study, including why you can't average percentiles.

 lower (max-heap)            upper (min-heap)

 median = top(lower)                     when the count is odd
 median = (top(lower) + top(upper)) / 2  when the count is even
الـ lower max-heap فيه النص الصغير، و upper min-heap فيه النص الكبير، وأعلى الـ lower أقل من أو يساوي أعلى الـ upper. الأحجام يا إما متساوية يا إما الـ lower أكبر بواحد. لو العدد فردي الـ median هو أعلى الـ lower، ولو زوجي متوسط الأعليين.
import { noop, type Tick } from "./doubling.ts";
import { MinHeap } from "./min-heap.ts";

const middle = (sorted: readonly number[]): number | null => {
  if (sorted.length === 0) return null;
  const mid = sorted.length >> 1;
  return sorted.length % 2 === 1 ? sorted[mid] : (sorted[mid - 1] + sorted[mid]) / 2;
};

// الـ brute: رتّب كل الأرقام بعد كل قيمة جديدة
export class MedianBySort {
  #values: number[] = [];
  #tick: Tick;
  constructor(tick: Tick = noop) { this.#tick = tick; }
  add(value: number): void {
    this.#values.push(value);
    this.#values.sort((a, b) => { this.#tick(); return a - b; });
  }
  median(): number | null { return middle(this.#values); }
}

// الحل A: binary search على المكان و splice، ⁦O(log n)⁩ مقارنات و ⁦O(n)⁩ نقل
export class MedianSortedArray {
  #values: number[] = [];
  #tick: Tick;
  constructor(tick: Tick = noop) { this.#tick = tick; }
  add(value: number): void {
    let low = 0;
    let high = this.#values.length;
    while (low < high) {
      this.#tick();
      const mid = (low + high) >> 1;
      if (this.#values[mid] <= value) low = mid + 1;
      else high = mid;
    }
    // كل عنصر بعد المكان ده بيتنقل خطوة، وده اللي بنعدّه لما حد بيقيس
    if (this.#tick !== noop) for (let i = low; i < this.#values.length; i++) this.#tick();
    this.#values.splice(low, 0, value);
  }
  median(): number | null { return middle(this.#values); }
}

// الحل B: heap للنص الصغير و heap للنص الكبير، ⁦O(log n)⁩ لكل قيمة
export class RunningMedian {
  // الـ lower ده max-heap، و upper ده min-heap
  #lower: MinHeap<number>;
  #upper: MinHeap<number>;
  constructor(tick: Tick = noop) {
    this.#lower = new MinHeap<number>((a, b) => { tick(); return b - a; });
    this.#upper = new MinHeap<number>((a, b) => { tick(); return a - b; });
  }
  add(value: number): void {
    const top = this.#lower.peek();
    if (top === undefined || value <= top) this.#lower.push(value);
    else this.#upper.push(value);
    // الـ invariant: الـ lower يا إما زي الـ upper يا إما أكبر بواحد
    if (this.#lower.size > this.#upper.size + 1) this.#upper.push(this.#lower.pop()!);
    else if (this.#upper.size > this.#lower.size) this.#lower.push(this.#upper.pop()!);
  }
  median(): number | null {
    const low = this.#lower.peek();
    if (low === undefined) return null;
    return this.#lower.size > this.#upper.size ? low : (low + this.#upper.peek()!) / 2;
  }
}

export class LogHistogram {
  #counts = new Map<number, number>();
  #total = 0;
  #base: number;
  constructor(relativeError = 0.01) { this.#base = (1 + relativeError) / (1 - relativeError); }
  add(value: number): void {
    const bucket = Math.ceil(Math.log(value) / Math.log(this.#base));
    this.#counts.set(bucket, (this.#counts.get(bucket) ?? 0) + 1);
    this.#total++;
  }
  get buckets(): number { return this.#counts.size; }
  quantile(q: number): number {
    const target = q * (this.#total - 1);
    let seen = 0;
    for (const [bucket, count] of [...this.#counts].sort((a, b) => a[0] - b[0])) {
      seen += count;
      if (seen > target) return (2 * this.#base ** bucket) / (this.#base + 1);
    }
    throw new RangeError("empty histogram");
  }
}

Part 3 — Voucher ladder 🔴 Advancedالجزء 3 — سلم الـ vouchers

⏱ Timed prompt · 35 minutes (classic: word ladder) Voucher codes are issued with the same length. Find the shortest chain from one issued code to another, changing one character at a time, where every code in the chain was issued. Return how many codes the chain contains, counting both ends, or 0 if there's no chain.
الـ voucher codes اتصدرت كلها بنفس الطول. لاقي أقصر chain من كود متصدر لكود تاني، بتغيّر حرف واحد في كل خطوة، وكل كود في الـ chain لازم يكون متصدر. رجّع عدد الأكواد في الـ chain بالطرفين، أو 0 لو مفيش chain.
English

Brute force. Compare every pair of codes to build the graph: O(n²·L). Approach A, BFS with pattern buckets. A code like ABC belongs to buckets *BC, A*C, AB*; codes sharing a bucket are one step apart. Building them is O(n·L²), since each of n codes makes L patterns of length L. BFS gives the shortest chain because it explores by distance.

Approach B, bidirectional BFS. Search from both ends and always expand the smaller frontier. If a level grows by a factor b, one search reaches about bd nodes, while two searches that meet in the middle reach about 2·bd/2. Same answer, far fewer nodes visited. Check back.has(neighbour) before seen; otherwise a neighbour the other side already reached looks like one you can skip, and you miss the meeting point.

When B isn't worth it. If the graph is small, or the target isn't known up front, or neighbours can't be computed from the target side, write A. In a 35-minute round, A first; offer B as the improvement.

import { noop, type Tick } from "./doubling.ts";

export interface LadderResult {
  codes: number;
  visited: number;
}

function differsByOne(a: string, b: string, tick: Tick): boolean {
  let differences = 0;
  for (let i = 0; i < a.length && differences < 2; i++) {
    tick();
    if (a[i] !== b[i]) differences++;
  }
  return differences === 1;
}

// الـ brute: قارن كل كودين عشان تبني الـ graph، ⁦O(n²·L)⁩
export function ladderBrute(start: string, target: string, issued: readonly string[], tick: Tick = noop): LadderResult {
  const known = new Set(issued);
  if (!known.has(start) || !known.has(target)) return { codes: 0, visited: 0 };
  const neighbours = new Map<string, string[]>(issued.map((code) => [code, []]));
  for (let i = 0; i < issued.length; i++) {
    for (let j = i + 1; j < issued.length; j++) {
      if (differsByOne(issued[i], issued[j], tick)) {
        neighbours.get(issued[i])!.push(issued[j]);
        neighbours.get(issued[j])!.push(issued[i]);
      }
    }
  }
  const seen = new Set([start]);
  let frontier = [start];
  for (let codes = 1; frontier.length > 0; codes++) {
    if (frontier.includes(target)) return { codes, visited: seen.size };
    const next: string[] = [];
    for (const code of frontier) {
      for (const neighbour of neighbours.get(code)!) {
        if (seen.has(neighbour)) continue;
        seen.add(neighbour);
        next.push(neighbour);
      }
    }
    frontier = next;
  }
  return { codes: 0, visited: seen.size };
}

const patternsOf = (code: string): string[] =>
  Array.from(code, (_, i) => `${code.slice(0, i)}*${code.slice(i + 1)}`);

function bucketsOf(issued: Iterable<string>, tick: Tick = noop): Map<string, string[]> {
  const buckets = new Map<string, string[]>();
  for (const code of issued) {
    for (const pattern of patternsOf(code)) {
      tick();
      const bucket = buckets.get(pattern);
      if (bucket) bucket.push(code);
      else buckets.set(pattern, [code]);
    }
  }
  return buckets;
}

// الحل A: BFS على pattern buckets، ⁦O(n·L²)⁩ للـ buckets والـ BFS
export function ladderBfs(start: string, target: string, issued: Iterable<string>, tick: Tick = noop, clearBuckets = true): LadderResult {
  const known = new Set(issued);
  if (!known.has(start) || !known.has(target)) return { codes: 0, visited: 0 };
  if (start === target) return { codes: 1, visited: 1 };
  const buckets = bucketsOf(known, tick);
  const seen = new Set([start]);
  let frontier = [start];
  for (let codes = 2; frontier.length > 0; codes++) {
    const next: string[] = [];
    for (const code of frontier) {
      for (const pattern of patternsOf(code)) {
        for (const neighbour of buckets.get(pattern) ?? []) {
          tick();
          if (neighbour === target) return { codes, visited: seen.size };
          if (seen.has(neighbour)) continue;
          seen.add(neighbour);
          next.push(neighbour);
        }
        // الـ bucket خلص شغله: أي كود فيه دلوقتي بقى seen
        if (clearBuckets) buckets.delete(pattern);
      }
    }
    frontier = next;
  }
  return { codes: 0, visited: seen.size };
}

// الحل B: BFS من الطرفين، وكل مرة وسّع الـ frontier الأصغر
export function ladderBidirectional(start: string, target: string, issued: Iterable<string>, tick: Tick = noop): LadderResult {
  const known = new Set(issued);
  if (!known.has(start) || !known.has(target)) return { codes: 0, visited: 0 };
  if (start === target) return { codes: 1, visited: 1 };
  const buckets = bucketsOf(known, tick);
  let front = new Set([start]);
  let back = new Set([target]);
  const seen = new Set([start, target]);
  for (let codes = 2; front.size > 0 && back.size > 0; codes++) {
    if (front.size > back.size) [front, back] = [back, front];
    const next = new Set<string>();
    for (const code of front) {
      for (const pattern of patternsOf(code)) {
        for (const neighbour of buckets.get(pattern) ?? []) {
          tick();
          if (back.has(neighbour)) return { codes, visited: seen.size };
          if (seen.has(neighbour)) continue;
          seen.add(neighbour);
          next.add(neighbour);
        }
      }
    }
    front = next;
  }
  return { codes: 0, visited: seen.size };
}

Part 4 — Trapped spare capacity 🔴 Advancedالجزء 4 — الـ capacity المحبوسة

⏱ Timed prompt · 25 minutes (classic: trapping rain water) hours[i] is the committed capacity of the warehouse in hour i, as non-negative integers. For each hour, spare capacity is trapped when both an earlier and a later hour are higher, up to the lower of the two peaks. Return the total trapped.
hours[i] هي الـ capacity المحجوزة في الساعة i، أرقام صحيحة مش سالبة. في كل ساعة، الـ spare بتبقى محبوسة لو فيه ساعة قبلها وساعة بعدها أعلى منها، لحد أوطى قمة من الاتنين. رجّع إجمالي الـ spare المحبوسة.
English

Brute force. For each hour, scan left and right for the highest wall: O(n²). Approach A, prefix and suffix maxima. Pre-compute the highest value to each side in two arrays: O(n) time, O(n) space. Both good approaches are O(n), so the difference is memory: 2n extra numbers against 2. Before you measure, expect about 3n steps for A (three passes) and exactly n for B.

The invariant is what wins this interview. Say this sentence: "If leftMax ≤ rightMax, the left position is decided, because its right wall can only be rightMax or higher, so the water there is limited by leftMax alone." Anyone can recite the code; explaining why it's safe to settle one side without knowing the far side is the point.

import { noop, type Tick } from "./doubling.ts";

// الـ brute: لكل ساعة، دوّر شمال ويمين على أعلى ساعة، ⁦O(n²)⁩
export function spareBrute(hours: readonly number[], tick: Tick = noop): number {
  let total = 0;
  for (let i = 0; i < hours.length; i++) {
    let leftMax = 0;
    let rightMax = 0;
    for (let l = 0; l <= i; l++) { tick(); leftMax = Math.max(leftMax, hours[l]); }
    for (let r = i; r < hours.length; r++) { tick(); rightMax = Math.max(rightMax, hours[r]); }
    total += Math.min(leftMax, rightMax) - hours[i];
  }
  return total;
}

// الحل A: جهّز أعلى قيمة من كل ناحية في array، O(n) time و O(n) space
export function spareWithArrays(hours: readonly number[], tick: Tick = noop): number {
  const n = hours.length;
  const leftMax = new Array<number>(n);
  const rightMax = new Array<number>(n);
  for (let i = 0, top = 0; i < n; i++) { tick(); top = Math.max(top, hours[i]); leftMax[i] = top; }
  for (let i = n - 1, top = 0; i >= 0; i--) { tick(); top = Math.max(top, hours[i]); rightMax[i] = top; }
  let total = 0;
  for (let i = 0; i < n; i++) { tick(); total += Math.min(leftMax[i], rightMax[i]) - hours[i]; }
  return total;
}

// الحل B: مؤشرين وأعلى قيمة من كل ناحية، O(n) time و O(1) space
export function sparePointers(hours: readonly number[], tick: Tick = noop): number {
  let left = 0;
  let right = hours.length - 1;
  let leftMax = 0;
  let rightMax = 0;
  let total = 0;
  while (left <= right) {
    tick();
    leftMax = Math.max(leftMax, hours[left]);
    rightMax = Math.max(rightMax, hours[right]);
    // الـ invariant: الناحية الأوطى حدّها معروف أكيد، فنقفل حسابها
    if (leftMax <= rightMax) {
      total += leftMax - hours[left];
      left++;
    } else {
      total += rightMax - hours[right];
      right--;
    }
  }
  return total;
}

Part 5 — LFU against LRU 🔴 Advancedالجزء 5 — الـ LFU ضد الـ LRU

⏱ Timed prompt · 40 minutes (classic: LFU cache) Build a cache with get and put in O(1). When it is full, evict the least frequently used key; on a tie, evict the least recently used among them. put on an existing key updates the value and counts as a use. Then say which traffic makes LFU worse than LRU.
ابني cache فيها get و put بـ O(1). لما تتملي، ارمي الـ key الأقل استخدامًا، ولو في تعادل ارمي الأقدم استخدامًا منهم. و put على key موجود بيحدّث القيمة وبيتحسب استخدام. وبعدين قول أنهي نوع traffic بيخلي الـ LFU أسوأ من الـ LRU.
English

Brute force. Keep a Map with a use count and scan for the minimum at eviction: O(capacity) per eviction. Approach A, frequency buckets. One Map for key → entry, a Map from use count → a Set of keys, and minUses. A Set iterates in insertion order, so the first key in the lowest bucket is the oldest one on a tie. Every operation is O(1) on average.

The rule that's easy to get wrong. When a key moves up and its bucket empties, and that bucket was minUses, then minUses becomes exactly the next value, because the key just moved there. A brand-new key resets minUses to 1.

Approach B is really a different policy. LRU, from section 03, is the comparison: same interface, simpler, but it remembers recency rather than frequency. The real question is which one fits the traffic, so the measurement below runs both on three traces. LFU wins on a skewed Zipf trace and on hot keys interrupted by one-off scans. LRU wins when the trend changes: yesterday's hot products keep a high count, sit in the cache and block today's. That is why production LFU needs aging. Redis's allkeys-lfu uses an approximate counter with lfu-decay-time.

This is the LFU item in the README's practical-coding/ artifact, so keep your version and its tests.

entries:  Map  key  -> { value, uses }
buckets:  Map  uses -> Set of keys, oldest first

uses = 1:  [ d, e ]    <- minUses = 1, evict d first
uses = 2:  [ b ]
uses = 5:  [ a, c ]

touch b:   b leaves uses=2 (bucket now empty, deleted), joins uses=3
الـ entries بتوصلك لأي key بـ O(1). والـ buckets بتجمّع الـ keys حسب عدد الاستخدام، جوه كل bucket الأقدم الأول. minUses=1، فالـ eviction هياخد d. ولما تلمس b بتطلع من bucket الـ 2 (ولو فضيت بتتمسح) وتدخل bucket الـ 3.
import { noop, type Tick } from "./doubling.ts";

interface Entry<V> {
  value: V;
  uses: number;
}

// الحل: Map للقيم، و bucket لكل عدد استخدامات، و minUses يقول مين الأقل
export class LfuCache<K, V> {
  #capacity: number;
  #tick: Tick;
  #entries = new Map<K, Entry<V>>();
  // الـ Set بيحفظ ترتيب الإضافة: أول key فيه هو الأقدم في نفس الـ bucket
  #buckets = new Map<number, Set<K>>();
  #minUses = 0;

  constructor(capacity: number, tick: Tick = noop) {
    this.#capacity = capacity;
    this.#tick = tick;
  }

  get(key: K): V | undefined {
    const entry = this.#entries.get(key);
    if (entry === undefined) return undefined;
    this.#touch(key, entry);
    return entry.value;
  }

  put(key: K, value: V): void {
    if (this.#capacity <= 0) return;
    const entry = this.#entries.get(key);
    if (entry !== undefined) {
      entry.value = value;
      this.#touch(key, entry);
      return;
    }
    if (this.#entries.size >= this.#capacity) this.#evict();
    this.#entries.set(key, { value, uses: 1 });
    this.#bucket(1).add(key);
    this.#minUses = 1;
  }

  #bucket(uses: number): Set<K> {
    let bucket = this.#buckets.get(uses);
    if (bucket === undefined) {
      bucket = new Set();
      this.#buckets.set(uses, bucket);
    }
    return bucket;
  }

  #touch(key: K, entry: Entry<V>): void {
    this.#tick();
    const bucket = this.#buckets.get(entry.uses)!;
    bucket.delete(key);
    if (bucket.size === 0) {
      this.#buckets.delete(entry.uses);
      // لو ده كان أقل bucket وفضي، الأقل الجديد هو اللي بعده بالظبط
      if (this.#minUses === entry.uses) this.#minUses++;
    }
    entry.uses++;
    this.#bucket(entry.uses).add(key);
  }

  #evict(): void {
    this.#tick();
    const bucket = this.#buckets.get(this.#minUses)!;
    const victim = bucket.values().next().value as K;
    bucket.delete(victim);
    if (bucket.size === 0) this.#buckets.delete(this.#minUses);
    this.#entries.delete(victim);
  }
}

// الـ brute: نفس الفكرة، بس الـ eviction بيلف على كل الـ entries، ⁦O(capacity)⁩
export class LfuScanCache<K, V> {
  #capacity: number;
  #tick: Tick;
  #entries = new Map<K, { value: V; uses: number; lastUsed: number }>();
  #clock = 0;

  constructor(capacity: number, tick: Tick = noop) {
    this.#capacity = capacity;
    this.#tick = tick;
  }

  get(key: K): V | undefined {
    const entry = this.#entries.get(key);
    if (entry === undefined) return undefined;
    entry.uses++;
    entry.lastUsed = ++this.#clock;
    return entry.value;
  }

  put(key: K, value: V): void {
    if (this.#capacity <= 0) return;
    const entry = this.#entries.get(key);
    if (entry !== undefined) {
      entry.value = value;
      entry.uses++;
      entry.lastUsed = ++this.#clock;
      return;
    }
    if (this.#entries.size >= this.#capacity) {
      let victim: K | undefined;
      let worst = { uses: Infinity, lastUsed: Infinity };
      for (const [candidate, e] of this.#entries) {
        this.#tick();
        if (e.uses < worst.uses || (e.uses === worst.uses && e.lastUsed < worst.lastUsed)) {
          victim = candidate;
          worst = e;
        }
      }
      this.#entries.delete(victim as K);
    }
    this.#entries.set(key, { value, uses: 1, lastUsed: ++this.#clock });
  }
}

// الـ LRU بالـ Map: delete ثم set بينقل الـ key لآخر الترتيب
export class LruCache<K, V> {
  #capacity: number;
  #entries = new Map<K, V>();

  constructor(capacity: number) { this.#capacity = capacity; }

  get(key: K): V | undefined {
    if (!this.#entries.has(key)) return undefined;
    const value = this.#entries.get(key) as V;
    this.#entries.delete(key);
    this.#entries.set(key, value);
    return value;
  }

  put(key: K, value: V): void {
    if (this.#capacity <= 0) return;
    this.#entries.delete(key);
    if (this.#entries.size >= this.#capacity) this.#entries.delete(this.#entries.keys().next().value as K);
    this.#entries.set(key, value);
  }
}

English

Any N-ary category tree fits this shape through left-child, right-sibling: left is the first child and right the next sibling.

Brute force. JSON.stringify and JSON.parse, which is the right first thing to say. It repeats field names on every node, and on Node 22.19 it threw RangeError on a chain only 4,000 levels deep. Approach A, preorder with null markers. Write a node, then its left subtree, then its right, with # for empty. Approach B, level order. Write the tree level by level and drop the trailing markers.

Size depends on shape. On a complete tree, A carries one marker for every empty child, n + 1 in all, and B drops almost all of them because they come last, so B is about 26% smaller. On a random shape or a chain they are about equal. Before measuring, say that the difference comes from the trailing nulls alone.

Depth. Both encoders are iterative here. The short recursive decoder overflows on deep input; an iterative one has no such limit because its stack is a heap array. A 100,000-node chain is the test. export interface CategoryNode {
  id: number;
  left: CategoryNode | null;
  right: CategoryNode | null;
}

function parseId(token: string): number {
  if (!/^\d+$/.test(token)) throw new SyntaxError(`bad token "${token}"`);
  return Number(token);
}

// الحل A: preorder مع ⁦"#"⁩ مكان كل ناحية فاضية
export function encodePreorder(root: CategoryNode | null): string {
  const out: string[] = [];
  const stack: Array<CategoryNode | null> = [root];
  while (stack.length > 0) {
    const node = stack.pop()!;
    if (node === null) { out.push("#"); continue; }
    out.push(String(node.id));
    stack.push(node.right, node.left);
  }
  return out.join(",");
}

// النسخة الـ recursive: أقصر، بس عمقها قد عمق الشجرة
export function decodePreorderRecursive(text: string): CategoryNode | null {
  const tokens = text.split(",");
  let index = 0;
  const build = (): CategoryNode | null => {
    const token = tokens[index++];
    if (token === undefined) throw new SyntaxError("input ended early");
    if (token === "#") return null;
    const node: CategoryNode = { id: parseId(token), left: null, right: null };
    node.left = build();
    node.right = build();
    return node;
  };
  const root = build();
  if (index !== tokens.length) throw new SyntaxError("extra tokens after the tree");
  return root;
}

// النسخة الـ iterative: نفس الترتيب، والـ stack في الـ heap مش في الـ call stack
export function decodePreorder(text: string): CategoryNode | null {
  const tokens = text.split(",");
  if (tokens[0] === "#") {
    if (tokens.length !== 1) throw new SyntaxError("extra tokens after the tree");
    return null;
  }
  const root: CategoryNode = { id: parseId(tokens[0]), left: null, right: null };
  const open = [{ node: root, leftDone: false }];
  let index = 1;
  while (open.length > 0) {
    const token = tokens[index++];
    if (token === undefined) throw new SyntaxError("input ended early");
    const child: CategoryNode | null = token === "#" ? null : { id: parseId(token), left: null, right: null };
    const top = open[open.length - 1];
    if (!top.leftDone) {
      top.node.left = child;
      top.leftDone = true;
    } else {
      top.node.right = child;
      open.pop();
    }
    if (child !== null) open.push({ node: child, leftDone: false });
  }
  if (index !== tokens.length) throw new SyntaxError("extra tokens after the tree");
  return root;
}

// الحل B: level order، والـ ⁦"#"⁩ اللي في الآخر بتتشال
export function encodeLevel(root: CategoryNode | null): string {
  const out: string[] = [];
  const queue: Array<CategoryNode | null> = [root];
  for (let head = 0; head < queue.length; head++) {
    const node = queue[head];
    if (node === null) { out.push("#"); continue; }
    out.push(String(node.id));
    queue.push(node.left, node.right);
  }
  while (out.at(-1) === "#") out.pop();
  return out.join(",");
}

export function decodeLevel(text: string): CategoryNode | null {
  if (text === "") return null;
  const tokens = text.split(",");
  const root: CategoryNode = { id: parseId(tokens[0]), left: null, right: null };
  const queue = [root];
  let index = 1;
  for (let head = 0; head < queue.length && index < tokens.length; head++) {
    const node = queue[head];
    for (const side of ["left", "right"] as const) {
      const token = tokens[index++];
      if (token === undefined || token === "#") continue;
      const child: CategoryNode = { id: parseId(token), left: null, right: null };
      node[side] = child;
      queue.push(child);
    }
  }
  if (index < tokens.length) throw new SyntaxError("extra tokens after the tree");
  return root;
}

⏱ Timed prompt · 35 minutes (classic: course schedule II) Migrations have dependencies: [before, after] means before must run first. Return an order that respects every dependency, or null if none exists because of a cycle. Name a second approach and say which you would code.
عندك migrations ليها dependencies: [before, after] معناها إن before لازم يتنفذ الأول. رجّع ترتيب بيحترم كل الـ dependencies، أو null لو مفيش بسبب cycle. وسمّي حل تاني وقول هتكتب أنهي واحد.
English

Brute force. Repeatedly scan for a job whose prerequisites are done: O(V²·E). Approach A, Kahn's BFS. Count unfinished prerequisites; a queue releases jobs at zero. O(V+E). If fewer than V are released, there's a cycle. Approach B, DFS postorder. Visit with three states, unvisited, visiting and done, and push a job after its dependents finish, then reverse. O(V+E). Hitting a job in the visiting state means a cycle.

Which to code. Kahn is iterative, so a long chain can't overflow the stack, and adding a heap to the queue gives a deterministic order. Recursive DFS is shorter and hands you the cycle path easily, but on a 100,000-long chain it throws RangeError, as the run below shows.

Prove it with a property test. A fast-check property encodes the exact requirement: for every edge u → v, u comes first. Adding a back edge must make both approaches report a cycle.

The closing rule. In an interview, name both approaches and the trade-off, then code one. Two full implementations in 45 minutes is a time mistake, not extra credit. import { noop, type Tick } from "./doubling.ts";

export type Dep = readonly [before: string, after: string];

// الـ brute: كل لفة دوّر على job كل اللي قبلها خلص، ⁦O(V²·E)⁩
export function orderByScan(jobs: readonly string[], deps: readonly Dep[], tick: Tick = noop): string[] | null {
  const done = new Set<string>();
  const order: string[] = [];
  while (order.length < jobs.length) {
    const ready = jobs.find((job) => {
      if (done.has(job)) return false;
      return deps.every(([before, after]) => { tick(); return after !== job || done.has(before); });
    });
    if (ready === undefined) return null;
    done.add(ready);
    order.push(ready);
  }
  return order;
}

function graphOf(jobs: readonly string[], deps: readonly Dep[]) {
  const next = new Map<string, string[]>(jobs.map((job) => [job, []]));
  for (const [before, after] of deps) {
    if (!next.has(before) || !next.has(after)) throw new Error(`unknown job in ${before} -> ${after}`);
    next.get(before)!.push(after);
  }
  return next;
}

// الحل A: Kahn، ⁦O(V+E)⁩، وأي job فاضلة معناها فيه cycle
export function orderKahn(jobs: readonly string[], deps: readonly Dep[], tick: Tick = noop): string[] | null {
  const next = graphOf(jobs, deps);
  const waiting = new Map<string, number>(jobs.map((job) => [job, 0]));
  for (const [, after] of deps) waiting.set(after, waiting.get(after)! + 1);
  const order = jobs.filter((job) => waiting.get(job) === 0);
  for (let head = 0; head < order.length; head++) {
    tick();
    for (const after of next.get(order[head])!) {
      tick();
      const left = waiting.get(after)! - 1;
      waiting.set(after, left);
      if (left === 0) order.push(after);
    }
  }
  return order.length === jobs.length ? order : null;
}

// الحل B: DFS postorder بتلات حالات، ⁦O(V+E)⁩
export function orderDfs(jobs: readonly string[], deps: readonly Dep[], tick: Tick = noop): string[] | null {
  const next = graphOf(jobs, deps);
  const state = new Map<string, "visiting" | "done">();
  const postorder: string[] = [];
  const visit = (job: string): boolean => {
    tick();
    if (state.get(job) === "done") return true;
    // لو الـ job لسه visiting يبقى رجعنا لجد من أجدادنا، يعني cycle
    if (state.get(job) === "visiting") return false;
    state.set(job, "visiting");
    for (const after of next.get(job)!) {
      if (!visit(after)) return false;
    }
    state.set(job, "done");
    postorder.push(job);
    return true;
  };
  for (const job of jobs) {
    if (!visit(job)) return null;
  }
  return postorder.reverse();
}

Solution · الحل 
export type Dep = readonly [before: string, after: string];

// بيرجّع الـ cycle نفسها عشان رسالة الـ error تقول للمهندس يصلح إيه
export function findCycle(jobs: readonly string[], deps: readonly Dep[]): string[] | null {
  const next = new Map<string, string[]>(jobs.map((job) => [job, []]));
  for (const [before, after] of deps) next.get(before)?.push(after);
  const state = new Map<string, "visiting" | "done">();
  const path: string[] = [];
  const visit = (job: string): string[] | null => {
    if (state.get(job) === "done") return null;
    if (state.get(job) === "visiting") return [...path.slice(path.indexOf(job)), job];
    state.set(job, "visiting");
    path.push(job);
    for (const after of next.get(job) ?? []) {
      const cycle = visit(after);
      if (cycle) return cycle;
    }
    path.pop();
    state.set(job, "done");
    return null;
  };
  for (const job of jobs) {
    const cycle = visit(job);
    if (cycle) return cycle;
  }
  return null;
}
نفس DFS بتلات حالات + array بتمشي مع الـ recursion. اتجرب على cycle وسط graph، و diamond من غير cycle، و job بتعتمد على نفسها.

Cheat sheet · الخلاصة

  • K-way merge: heap O(N log k), O(k) memory, about 2× the comparisons of pairwise but lazy: 119 rows read against 100,000 for a first page.
  • Timsort makes "collect and sort" cheap on K sorted runs. Shuffling is what brings back N log N.
  • Running median: sorted array is O(n) moves (fast memmove), two heaps O(log n). At scale, histograms or sketches: 243 buckets gave under 1% error here.
  • Voucher ladder: BFS with buckets, then bidirectional (15× fewer nodes in this run). Check the meeting point before seen.
  • Trapped capacity: arrays vs two pointers are 3n vs n steps and 2n vs 2 extra numbers; explain the invariant in one sentence.
  • LFU: entries, buckets by use count, minUses. O(1). Beats LRU on skew; loses when trends change. Production needs aging.
  • Tree serialization: preorder vs level order differ by trailing nulls. Recursive decoders and JSON.stringify overflow on deep input; validate the depth at the boundary.
  • Topological sort: Kahn is iterative; DFS needs three states; property-test "for every edge, u first".
