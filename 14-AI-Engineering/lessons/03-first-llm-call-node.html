Why this matters · ليه ده مهم

English

An LLM call looks like one line of code, and that line is where most production AI bugs start. It costs money per token, it can stop halfway while returning HTTP 200, it fails in ways a normal API doesn't, and it forgets everything between requests. A senior engineer treats it like any other unreliable, metered external dependency: typed responses, a usage log from the first day, one retry policy, and a key that never leaves the server. Interviews ask exactly these things: why did the chat bill explode, what do you do on a 529, how does a stream fail after the 200.

بالعامية

الـ LLM call شكلها سطر كود واحد، والسطر ده هو اللي بتبدأ منه معظم مشاكل الـ AI في production. بتتحاسب بالـ token، وممكن تقف في النص وترجّع HTTP 200 عادي، وبتفشل بطرق الـ API العادي مبيفشلش بيها، وبتنسى كل حاجة بين كل request والتاني. السنيور بيعاملها زي أي external dependency مش مضمونة وبالعداد: responses ليها types، و usage log من أول يوم، و retry policy واحدة، و key عمره ما بيخرج من الـ server. والـ interviews بتسأل في الحاجات دي بالظبط: ليه فاتورة الـ chat ولّعت، بتعمل إيه لو جالك 529، وإزاي الـ stream بيقع بعد الـ 200.

Part 1 — The stand-in and the first call 🟢 Basicالجزء 1 — الـ stand-in وأول call

English

There is no API key on this machine, and you don't need one to learn the plumbing. Every LLM call in this section goes to kit/mock-anthropic.ts, a small local server that speaks the wire format of POST /v1/messages. The SDK you import is the real @anthropic-ai/sdk 1.6.0: the same request building, typed errors, retries, backoff and SSE parser you get in production. Only the model is scripted, and every run prints a [SIMULATED] banner so nobody mistakes its words for a real model's.

That split is what keeps this honest. Anything about your code is measured for real: how many requests a retry policy sends, what a truncated reply does to your parser, how a dollar figure is computed. Anything about a model, such as how good an answer is or how fast it really generates, cannot be learned from a script, so those numbers are labelled or left out. // مُحاكى (SIMULATED): ده stand-in محلي لـ POST /v1/messages، مش Claude ومبيولّدش لغة حقيقية
// شكل الـ wire زي الـ API الحقيقي، فالـ SDK الحقيقي بيكلمه عن طريق baseURL
import { createHash } from "node:crypto";
import { createServer, type IncomingMessage, type ServerResponse } from "node:http";
import type { AddressInfo } from "node:net";

export type Block =
  | { type: "text"; text: string }
  | { type: "tool_use"; id?: string; name: string; input: unknown };
export type Reply = { content: Block[]; stop_reason?: "end_turn" | "tool_use" | "max_tokens" | "stop_sequence" | "refusal" };
export type MockRequest = Record<string, any> & { model: string; messages: any[]; max_tokens: number };
export type Fail = { status: 429 | 500 | 529 | 400; retryAfter?: number; message?: string; midStreamAfterTokens?: number };
export type MockOpts = {
  reply?: (req: MockRequest, n: number) => Reply;
  ttftMs?: number;      // وقت مُحاكى لأول token
  tokenMs?: number;     // تأخير مُحاكى لكل output token
  rpm?: number;         // حد مُحاكى للـ requests في الدقيقة، و0 يعني مقفول
  minCacheTokens?: number;
  quiet?: boolean;      // بيخفي سطر SIMULATED، فلازم الدرس يطبع الـ label بتاعه
};

const REJECT_FORCED = new Set(["claude-opus-5-5", "claude-sonnet-5-5", "claude-fable-5-1"]);
const KNOWN = new Set(["claude-opus-5-5", "claude-sonnet-5-5", "claude-haiku-5-5", "claude-opus-5", "claude-sonnet-5", "claude-haiku-4-5"]);

// عدّ token مُحاكى: تقريب بالطول، مش الـ tokenizer الحقيقي
export const simulatedTokens = (s: string) => Math.max(1, Math.ceil([...s].length / 3.6));
const render = (x: unknown) => (typeof x === "string" ? x : JSON.stringify(x));
const blocksOf = (c: any): any[] => (typeof c === "string" ? [{ type: "text", text: c }] : c);

function flatten(req: MockRequest): any[] {
  const out: any[] = [];
  for (const t of req.tools ?? []) out.push({ ...t, __k: "tool" });
  for (const b of blocksOf(req.system ?? [])) out.push({ ...b, __k: "system" });
  for (const m of req.messages) for (const b of blocksOf(m.content)) out.push({ ...b, __k: m.role });
  return out;
}
const blockText = (b: any) => { const { cache_control, __k, ...rest } = b; return __k + ":" + render(rest); };

export async function startMock(opts: MockOpts = {}) {
  const { ttftMs = 40, tokenMs = 4, rpm = 0, minCacheTokens = 512 } = opts;
  const failQueue: Fail[] = [];
  const cache = new Map<string, number>();
  const log: { model: string; status: number; stream: boolean; headers: Record<string, unknown>; body: MockRequest; aborted?: boolean; sentTokens?: number; plannedTokens?: number }[] = [];
  let window: number[] = [];
  let n = 0;

  const defaultReply = (req: MockRequest): Reply => {
    const last = req.messages.at(-1);
    const text = blocksOf(last.content).filter((b) => b.type === "text").map((b) => b.text).join(" ");
    return { content: [{ type: "text", text: `[simulated reply] received ${text.length} chars.` }] };
  };

  function usageFor(req: MockRequest) {
    const blocks = flatten(req);
    let lastMark = -1;
    blocks.forEach((b, i) => { if (b.cache_control) lastMark = i; });
    if (req.cache_control && lastMark === -1) lastMark = blocks.length - 1;
    const texts = blocks.map(blockText);
    const tok = texts.map(simulatedTokens);
    const total = tok.reduce((a, b) => a + b, 0);
    if (lastMark === -1) return { input_tokens: total, cache_creation_input_tokens: 0, cache_read_input_tokens: 0 };
    const upto = tok.slice(0, lastMark + 1).reduce((a, b) => a + b, 0);
    if (upto < minCacheTokens) return { input_tokens: total, cache_creation_input_tokens: 0, cache_read_input_tokens: 0 };
    const key = req.model + createHash("sha256").update(texts.slice(0, lastMark + 1).join("\u0000")).digest("hex");
    const now = Date.now();
    const hit = (cache.get(key) ?? 0) > now;
    cache.set(key, now + 300_000);
    return hit
      ? { input_tokens: total - upto, cache_creation_input_tokens: 0, cache_read_input_tokens: upto }
      : { input_tokens: total - upto, cache_creation_input_tokens: upto, cache_read_input_tokens: 0 };
  }

  const sendErr = (res: ServerResponse, status: number, type: string, message: string, headers: Record<string, string> = {}) => {
    res.writeHead(status, { "content-type": "application/json", "request-id": `req_mock_${++n}`, ...headers });
    res.end(JSON.stringify({ type: "error", error: { type, message }, request_id: `req_mock_${n}` }));
  };
  const typeFor = (s: number) => (s === 429 ? "rate_limit_error" : s === 529 ? "overloaded_error" : s === 400 ? "invalid_request_error" : "api_error");

  function validate(req: MockRequest): string | null {
    if (!KNOWN.has(req.model)) return "404";
    for (const k of ["temperature", "top_p", "top_k"]) if (k in req) return `${k}: this field is not supported on API version 2026-10-21`;
    if (req.messages.at(-1)?.role === "assistant" && req.model !== "claude-haiku-4-5") return "This model does not support assistant message prefill. The conversation must end with a user message.";
    if (req.tool_choice && ["any", "tool"].includes(req.tool_choice.type) && REJECT_FORCED.has(req.model)) return 'tool_choice: type "tool" and "any" are not supported for this model.';
    if (req.thinking?.type === "disabled" && req.model === "claude-opus-5-5") return '"thinking.type.disabled" is not supported for this model. Use "thinking.type.adaptive" and "output_config.effort" to control thinking behavior.';
    if (req.thinking?.type === "enabled") return '"thinking.type.enabled" is not supported for this model. Use "thinking.type.adaptive" and "output_config.effort" to control thinking behavior.';
    return null;
  }

  const server = createServer(async (rq: IncomingMessage, rs: ServerResponse) => {
    const chunks: Buffer[] = [];
    for await (const c of rq) chunks.push(c as Buffer);
    const req = JSON.parse(Buffer.concat(chunks).toString() || "{}") as MockRequest;
    if (rq.url?.startsWith("/v1/messages/count_tokens")) {
      const u = flatten(req).map(blockText).map(simulatedTokens).reduce((a, b) => a + b, 0);
      rs.writeHead(200, { "content-type": "application/json" });
      return rs.end(JSON.stringify({ input_tokens: u }));
    }
    if (!rq.url?.startsWith("/v1/messages") || rq.method !== "POST") return sendErr(rs, 404, "not_found_error", "unknown path");
    const entry: (typeof log)[number] = { model: req.model, status: 200, stream: !!req.stream, headers: rq.headers as any, body: req };
    log.push(entry);

    const now = Date.now();
    window = window.filter((t) => now - t < 60_000);
    if (rpm && window.length >= rpm) {
      entry.status = 429;
      return sendErr(rs, 429, "rate_limit_error", "This request would exceed your organization's rate limit.", { "retry-after": "1", "anthropic-ratelimit-requests-limit": String(rpm), "anthropic-ratelimit-requests-remaining": "0" });
    }
    window.push(now);
    const v = validate(req);
    if (v === "404") { entry.status = 404; return sendErr(rs, 404, "not_found_error", `model: ${req.model}`); }
    if (v) { entry.status = 400; return sendErr(rs, 400, "invalid_request_error", v); }

    const fail = failQueue[0] && !failQueue[0].midStreamAfterTokens ? failQueue.shift() : undefined;
    if (fail) {
      entry.status = fail.status;
      const h: Record<string, string> = fail.retryAfter !== undefined ? { "retry-after": String(fail.retryAfter) } : {};
      return sendErr(rs, fail.status, typeFor(fail.status), fail.message ?? "simulated failure", h);
    }

    const reply = (opts.reply ?? defaultReply)(req, log.length);
    const usage = usageFor(req);
    const id = `msg_mock_${++n}`;
    let content: any[] = reply.content.map((b, i) => (b.type === "tool_use" ? { ...b, id: b.id ?? `toolu_mock_${n}_${i}` } : b));
    const textOf = (b: any) => (b.type === "text" ? b.text : JSON.stringify(b.input));
    let outTokens = content.map((b) => simulatedTokens(textOf(b))).reduce((a, b) => a + b, 0);
    let stop = reply.stop_reason ?? (content.some((b) => b.type === "tool_use") ? "tool_use" : "end_turn");
    if (outTokens > req.max_tokens) {
      // زي الحقيقي: النص بيتقطع فعلًا، والـ tool input المقطوع مينفعش يتنفّذ
      let left = req.max_tokens;
      const cut: any[] = [];
      for (const b of content) {
        if (left <= 0) break;
        const t = simulatedTokens(textOf(b));
        if (t <= left) { cut.push(b); left -= t; continue; }
        cut.push(b.type === "text" ? { ...b, text: [...b.text].slice(0, Math.floor(left * 3.6)).join("") } : { ...b, input: {} });
        left = 0;
      }
      content = cut;
      outTokens = req.max_tokens;
      stop = "max_tokens";
    }
    entry.plannedTokens = outTokens;
    const headers = { "request-id": `req_mock_${n}`, ...(rpm ? { "anthropic-ratelimit-requests-limit": String(rpm), "anthropic-ratelimit-requests-remaining": String(rpm - window.length) } : {}) };
    const meta = { id, type: "message", role: "assistant", model: req.model, stop_sequence: null, stop_details: null };

    if (!req.stream) {
      await new Promise((r) => setTimeout(r, ttftMs + tokenMs * outTokens));
      rs.writeHead(200, { "content-type": "application/json", ...headers });
      return rs.end(JSON.stringify({ ...meta, content, stop_reason: stop, usage: { ...usage, output_tokens: outTokens } }));
    }

    // الـ streaming: نفس ترتيب الـ events الحقيقي عشان الـ SDK يقدر يجمّعها
    let closed = false; let sent = 0;
    rs.on("close", () => { if (!rs.writableEnded) { closed = true; entry.aborted = true; entry.sentTokens = sent; } });
    rs.writeHead(200, { "content-type": "text/event-stream", "cache-control": "no-cache", ...headers });
    const ev = (type: string, data: object) => rs.write(`event: ${type}\ndata: ${JSON.stringify({ type, ...data })}\n\n`);
    const sleep = (ms: number) => new Promise((r) => setTimeout(r, ms));
    await sleep(ttftMs);
    if (closed) return;
    ev("message_start", { message: { ...meta, content: [], stop_reason: null, usage: { ...usage, output_tokens: 1 } } });
    ev("ping", {});
    const mid = failQueue[0]?.midStreamAfterTokens ? failQueue.shift() : undefined;
    for (let i = 0; i < content.length; i++) {
      const b: any = content[i];
      ev("content_block_start", { index: i, content_block: b.type === "text" ? { type: "text", text: "" } : { type: "tool_use", id: b.id, name: b.name, input: {} } });
      const s = textOf(b);
      // كل delta = token مُحاكى واحد، عشان sentTokens و plannedTokens يبقوا بنفس الوحدة
      const chars = [...s];
      const count = simulatedTokens(s);
      const pieces = Array.from({ length: count }, (_, k) => chars.slice(Math.floor((k * chars.length) / count), Math.floor(((k + 1) * chars.length) / count)).join(""));
      for (const piece of pieces) {
        if (closed) return;
        if (mid && sent >= mid.midStreamAfterTokens!) {
          ev("error", { error: { type: typeFor(mid.status), message: mid.message ?? "simulated mid-stream failure" } });
          entry.sentTokens = sent;
          return rs.end();
        }
        ev("content_block_delta", { index: i, delta: b.type === "text" ? { type: "text_delta", text: piece } : { type: "input_json_delta", partial_json: piece } });
        sent++;
        await sleep(tokenMs);
      }
      ev("content_block_stop", { index: i });
    }
    entry.sentTokens = sent;
    ev("message_delta", { delta: { stop_reason: stop, stop_sequence: null }, usage: { output_tokens: outTokens } });
    ev("message_stop", {});
    rs.end();
  });

  await new Promise<void>((r) => server.listen(0, "127.0.0.1", r));
  const port = (server.address() as AddressInfo).port;
  if (!opts.quiet) console.log(`[SIMULATED] local stand-in on 127.0.0.1:${port}: text, tokens and latency are simulated, not a real model`);
  return {
    url: `http://127.0.0.1:${port}`,
    log,
    failNext: (...f: Fail[]) => failQueue.push(...f),
    close: () => new Promise<void>((r) => { server.closeAllConnections(); server.close(() => r()); }),
  };
}

// الأسعار دي من صفحات الأسعار الرسمية، اتراجعت يوم ⁦2026-11-09 (⁩دولار لكل مليون token)
// المصدر: https://platform.claude.com/docs/en/about-claude/pricing
export const PRICES_CHECKED_ON = "2026-11-09";
export type Price = { input: number; cacheWrite5m: number; cacheWrite1h: number; cacheRead: number; output: number; batchInput: number; batchOutput: number };
export const PRICES: Record<string, Price> = {
  "claude-opus-5-5": { input: 4, cacheWrite5m: 5, cacheWrite1h: 8, cacheRead: 0.2, output: 20, batchInput: 2, batchOutput: 10 },
  "claude-sonnet-5-5": { input: 2, cacheWrite5m: 2.5, cacheWrite1h: 4, cacheRead: 0.1, output: 10, batchInput: 1, batchOutput: 5 },
  // السعر ده لـ Haiku 5.5 لحد 100K token في الـ prompt، وفوق كده بيتضرب في 5
  "claude-haiku-5-5": { input: 0.1, cacheWrite5m: 0.125, cacheWrite1h: 0.2, cacheRead: 0.01, output: 0.5, batchInput: 0.05, batchOutput: 0.25 },
};
export const HAIKU_LONG_CONTEXT: Price = { input: 0.5, cacheWrite5m: 0.625, cacheWrite1h: 1, cacheRead: 0.05, output: 2.5, batchInput: 0.25, batchOutput: 1.25 };

export type Usage = { input_tokens: number; output_tokens: number; cache_creation_input_tokens?: number | null; cache_read_input_tokens?: number | null };

// لاحظ: input_tokens في Claude من غير الـ cached، فالإجمالي لازم يتجمع
export const promptTokens = (u: Usage) => u.input_tokens + (u.cache_creation_input_tokens ?? 0) + (u.cache_read_input_tokens ?? 0);

export function costOf(model: string, u: Usage, opts: { batch?: boolean } = {}): number {
  const base = PRICES[model];
  if (!base) throw new Error(`no price for ${model}`);
  const p = model === "claude-haiku-5-5" && promptTokens(u) > 100_000 ? HAIKU_LONG_CONTEXT : base;
  const input = opts.batch ? p.batchInput : p.input;
  const output = opts.batch ? p.batchOutput : p.output;
  return (u.input_tokens * input + (u.cache_creation_input_tokens ?? 0) * p.cacheWrite5m + (u.cache_read_input_tokens ?? 0) * p.cacheRead + u.output_tokens * output) / 1_000_000;
}
بالعامية

مفيش API key على الجهاز ده، وإنت مش محتاج واحد عشان تتعلم السباكة. كل LLM call في القسم ده بتروح لـ kit/mock-anthropic.ts، server صغير محلي بيتكلم نفس شكل POST /v1/messages. الـ SDK نفسه حقيقي، @anthropic-ai/sdk 1.6.0: نفس بناء الـ request، والـ errors، والـ retries، والـ backoff، ونفس الـ SSE parser اللي هتشتغل بيهم في production. الموديل بس هو اللي متمثّل، وكل تشغيل بيطبع [SIMULATED] عشان محدش يفتكر الكلام ده من موديل حقيقي.

التقسيمة دي هي اللي بتخلي الكلام أمين. أي حاجة عن الكود بتاعك بتتقاس بجد: الـ retry بيبعت كام request، الرد المقطوع بيعمل إيه في الـ parser، الدولارات بتتحسب إزاي. وأي حاجة عن الموديل، زي جودة الإجابة أو سرعته الحقيقية، مينفعش تتعرف من script، فالأرقام دي يا إما مكتوب عليها إنها simulated يا إما مش موجودة. الدروس الجاية هتيجي هنا لما تحتاج الملف ده.

لما تقرا الملف ركز على 4 حاجات: startMock وخياراته، وvalidate() اللي بترفض اللي الـ API الحقيقي بيرفضه، وusageFor() اللي بتحسب الـ cache، وجزء الـ streaming اللي بيبعت الـ events بنفس الترتيب. وprices.ts فيه الأسعار الرسمية اتراجعت يوم 2026-11-09.

فين هستخدمه في شغلي؟ ده نفس الـ pattern اللي هتعمله في أي CI عندك: fake server بنفس الـ wire format، فالـ tests بتجري من غير key ومن غير فلوس ومن غير flakiness، وبتختبر الـ error handling بتاعك بجد. لو عندك service بيكلم Stripe أو provider تاني، نفس الفكرة بالظبط.
English

The first call needs four things: model, max_tokens, messages and, usually, system. messages alternates user and assistant turns and must start with user. system is a separate top-level field, not a message in the list. (Newer models also accept a role: "system" message appended later in the conversation for mid-session operator instructions, never as the first message; that is a caching tool, covered in lesson 06.)

Walk the response field by field. id identifies the message. content is an array of typed blocks (text, tool_use, thinking and others), a discriminated union you must narrow, never a plain string. stop_reason says why generation ended. usage is what you pay for. _request_id is added by the SDK from the response header and is what you quote to support. On the wire, SDK 1.6.0 sends the key as Authorization: Bearer, with no x-api-key header, and pins anthropic-version: 2026-10-21.

import Anthropic from "@anthropic-ai/sdk";
import { startMock } from "./kit/mock-anthropic.ts";

// الرد ده مكتوب بإيدي: الـ stand-in مبيفكرش، بيرجّع اللي قلتله عليه
const mock = await startMock({
  reply: () => ({ content: [{ type: "text", text: "Order ord_1042 left the warehouse on Monday." }] }),
});

// الفرق الوحيد عن production: الـ baseURL والـ key المزيف
const client = new Anthropic({ apiKey: "mock-key-not-real", baseURL: mock.url });

const res = await client.messages.create({

Part 2 — max_tokens, stop reasons and usage from day one 🟢 Basicالجزء 2 — الـ max_tokens وأسباب الوقوف والـ usage من أول يوم

English

HTTP 200 does not mean you got a complete answer. stop_reason tells you what happened, and you check it before reading content. The SDK 1.6.0 type has seven values: end_turn (finished), stop_sequence (hit one of your stop_sequences; stop_sequence in the response holds which one on the real API, while the stand-in always returns null), max_tokens (cut off by your cap), tool_use (the model wants a tool run, lesson 08), pause_turn (a server-tool turn paused and must be continued), refusal (declined; on Opus-class models a safety classifier can return this with HTTP 200, and stop_details carries the category) and model_context_window_exceeded (the prompt plus output hit the context limit).

export function readText(res: Anthropic.Message): TextResult {
  const text = res.content.flatMap((b) => (b.type === "text" ? [b.text] : [])).join("");
  switch (res.stop_reason) {
    case "end_turn":
    case "stop_sequence":
      return text ? { ok: true, text } : { ok: false, reason: "no_text", stopReason: res.stop_reason };
    case "max_tokens":
      return { ok: false, reason: "truncated", stopReason: res.stop_reason };
    case "model_context_window_exceeded":
      return { ok: false, reason: "context_full", stopReason: res.stop_reason };
    case "refusal":
      return { ok: false, reason: "refusal", stopReason: res.stop_reason };
    case "tool_use":
      return { ok: false, reason: "needs_tools", stopReason: res.stop_reason };
    case "pause_turn":
      return { ok: false, reason: "paused", stopReason: res.stop_reason };
    default:
      return { ok: false, reason: "no_text", stopReason: res.stop_reason };

English

Print usage from the first day: tokens and dollars per call. Two traps. First, input_tokens does not include cached tokens, so the real prompt size is input_tokens + cache_creation_input_tokens + cache_read_input_tokens; the first request below reports input=14 for a prompt of 1,423. Second, thinking counts as output. On Opus 5.5 thinking is always on, so a very low max_tokens can run out while thinking and return no text at all.

So don't lowball max_tokens: it is a ceiling, and you pay only for what is generated. A sensible default is about 16,000 for non-streaming calls and about 64,000 for streaming, going lower only for a reason such as classification (about 256) or a hard cost cap. An LLM key is money. Whoever holds it can spend on your account until a limit stops them. It lives in the environment, injected at runtime from a secrets manager (AWS Secrets Manager, Vault, Doppler and the like), and it never reaches the browser. The generic rules are in API security essentials and config and CI; what is specific here is how easily a Next.js project ships the key to everyone.

Part 4 — Errors and retries 🟢 Basicالجزء 4 — الـ errors والـ retries

English

The same rules apply as for any external API, and you already have them from timeouts, retries and circuit breakers and retry, timeout and fallback. What's new is what the SDK does for you. Every HTTP status maps to a typed class: 429 is RateLimitError (its type is rate_limit_error and it has a retry-after header), 529 is OverloadedError (a subclass of InternalServerError, so catch it first), 400 is BadRequestError, and a bad model name is NotFoundError. Catch a chain from most specific to least.

maxRetries defaults to 2, which means up to 3 requests with exponential backoff, and it covers 408, 409, 429, 5xx and connection errors. Timeouts default to 10 minutes, are given in milliseconds in TypeScript, and are retried too, so the worst-case wall clock is about timeout × 3. A 400 is never retried, because nothing about it will change.

English

A long answer can take many seconds to generate. Streaming doesn't make it finish sooner; it shows the first words early, so the wait feels short. English

The API is stateless. There is no session on the other side; the model knows only what is in this request. So a chat means appending to your own array and resending all of it every turn. import type Anthropic from "@anthropic-ai/sdk";

type Msg = Anthropic.MessageParam;

// "exchange" بيبدأ برسالة user حقيقية، مش رسالة شايلة tool_result
const startsExchange = (m: Msg) =>
  m.role === "user" && !(Array.isArray(m.content) && m.content.some((b) => b.type === "tool_result"));

const sizeOf = (m: Msg) => Math.ceil(JSON.stringify(m.content).length / 3.6);

// بنشيل أقدم exchange كامل: كده الـ tool_use عمره ما بيتفصل عن الـ tool_result بتاعه
export function trimHistory(history: Msg[], maxTokens: number): Msg[] {
  const starts = history.flatMap((m, i) => (startsExchange(m) ? [i] : []));
  let from = 0;
  let total = history.reduce((n, m) => n + sizeOf(m), 0);
  for (let s = 1; s < starts.length && total > maxTokens; s++) {
    total -= history.slice(from, starts[s]).reduce((n, m) => n + sizeOf(m), 0);
    from = starts[s];
  }
  return from === 0 ? history : history.slice(from).map(stripThinking);
}

// بعد ما تشيل turns قديمة، بلوكات الـ thinking في اللي فاضل مبقتش صالحة، فبنشيلها
function stripThinking(m: Msg): Msg {
  if (m.role !== "assistant" || typeof m.content === "string") return m;
  return { role: "assistant", content: m.content.filter((b) => b.type !== "thinking" && b.type !== "redacted_thinking") };
}

الـ API مبيفتكرش حاجة. مفيش session في الناحية التانية، والموديل يعرف اللي في الـ request ده بس. فالـ chat معناها إنك بتضيف على array بتاعك وتبعتها كلها كل turn. الـ input بيزيد بخط مستقيم مع عدد الـ turns، ولأنك بتدفع على الـ input ده في كل turn فالإجمالي بيزيد quadratic: لو الـ system فيه S tokens وكل exchange بيضيف h، يبقى n turns بيكلفوا حوالي n·S + h·n(n+1)/2. فوق شات دعم طلبات 20 turn بـ tokens متمثّلة وأسعار Sonnet 5.5 الحقيقية.

ضيف res.content كله، مش النص بس. الـ content ممكن يكون فيه thinking blocks و compaction blocks لازم يترجعوا زي ما هما، ولو خزنت النص بس هيضيعوا من غير ما تحس. وأول رسالة لازم تبقى user.

إدارة الطول فيها 3 حاجات. حط cap بالـ tokens (في الكود الحقيقي عدّها بـ client.messages.countTokens، وtrimHistory هنا بتستخدم نفس تقدير الطول بتاع الـ stand-in). شيل أقدم exchanges كاملة، لأن tool_use من غير tool_result بتاعه بيخلي الـ API يرفض الـ request. وفي المحادثات الطويلة لخّص بدل ما تحذف، وده في درس 21.

على أحدث الموديلات فيه نقطة مهمة. الـ thinking block مربوط بالمحادثة اللي طلّعته، فلو عدّلت أو شيلت turn قديم، كل الـ thinking blocks اللي بعده بتبقى مش صالحة. والحسابات اللي اتعملت من 2026-08-31 على Opus 5.5 و Sonnet 5.5 بيترفضوا بـ 400. فخلي الـ history append-only لما تقدر. ولو لازم تشيل turns، شيل الـ thinking blocks من اللي فاضل (النص والـ tool calls يفضلوا)، أو استخدم الـ compaction بتاعة الـ server. وفيه كمان beta اسمها message-threads-2026-08-12 بتخلي الـ API يحتفظ بنسخة لوقت قصير فالـ requests تصغر، وأنا بذكر اسمها بس عشان تدور عليها. الـ stand-in مبيمثلش الكلام ده، والمصدر هو توثيق claude-api.

import Anthropic from "@anthropic-ai/sdk";
import { costOf, promptTokens } from "./kit/prices.ts";

export type FailKind =
  | "truncated" | "context_full" | "refusal" | "needs_tools" | "paused" | "empty"
  | "rate_limited" | "overloaded" | "server_error" | "timeout" | "network"
  | "bad_request" | "auth" | "not_found" | "stream_failed";

export type LLMResult =
  | { ok: true; text: string; requestId: string | null }
  | { ok: false; kind: FailKind; retryLater: boolean; partial: string; retryAfterSec?: number };

export type Log = (line: Record<string, unknown>) => void;
type Params = Anthropic.MessageCreateParamsNonStreaming;
type Reply = Anthropic.Message & { _request_id?: string | null };

// الترتيب من الأخص للأعم: الـ subclass لازم ييجي قبل الـ parent
export function classify(e: unknown): { kind: FailKind; retryLater: boolean; retryAfterSec?: number } {
  if (e instanceof Anthropic.RateLimitError) {
    const header = e.headers?.get("retry-after");
    return { kind: "rate_limited", retryLater: true, ...(header ? { retryAfterSec: Number(header) } : {}) };
  }
  if (e instanceof Anthropic.OverloadedError) return { kind: "overloaded", retryLater: true };
  if (e instanceof Anthropic.InternalServerError) return { kind: "server_error", retryLater: true };
  if (e instanceof Anthropic.APIConnectionTimeoutError) return { kind: "timeout", retryLater: true };
  if (e instanceof Anthropic.APIConnectionError) return { kind: "network", retryLater: true };
  if (e instanceof Anthropic.AuthenticationError || e instanceof Anthropic.PermissionDeniedError) return { kind: "auth", retryLater: false };
  if (e instanceof Anthropic.NotFoundError) return { kind: "not_found", retryLater: false };
  if (e instanceof Anthropic.BadRequestError) return { kind: "bad_request", retryLater: false };
  // غلطة في نص الـ stream: الـ status بتاعها undefined والـ SDK مبيعملش retry
  if (e instanceof Anthropic.APIError && e.status === undefined) return { kind: "stream_failed", retryLater: true };
  throw e;
}

function fromMessage(res: Reply): LLMResult {
  const text = res.content.flatMap((b) => (b.type === "text" ? [b.text] : [])).join("");
  const fail = (kind: FailKind): LLMResult => ({ ok: false, kind, retryLater: false, partial: text });
  switch (res.stop_reason) {
    case "end_turn":
    case "stop_sequence":
      return text ? { ok: true, text, requestId: res._request_id ?? null } : fail("empty");
    case "max_tokens": return fail("truncated");
    case "model_context_window_exceeded": return fail("context_full");
    case "refusal": return fail("refusal");
    case "tool_use": return fail("needs_tools");
    case "pause_turn": return fail("paused");
    default: return fail("empty");
  }
}

// سطر واحد لكل call: الموديل والـ tokens والدولارات والوقت والنتيجة
function logLine(log: Log, model: string, t0: number, outcome: string, res?: Reply) {
  log({
    event: "llm_call", model, outcome,
    ms: Math.round(performance.now() - t0),
    prompt_tokens: res ? promptTokens(res.usage) : 0,
    output_tokens: res?.usage.output_tokens ?? 0,
    usd: res ? Number(costOf(model, res.usage).toFixed(6)) : 0,
    stop_reason: res?.stop_reason ?? null,
    request_id: res?._request_id ?? null,
  });
}

export async function callLLM(client: Anthropic, params: Params, log: Log): Promise<LLMResult> {
  const t0 = performance.now();
  try {
    const res = await client.messages.create(params);
    const out = fromMessage(res);
    logLine(log, params.model, t0, out.ok ? "ok" : out.kind, res);
    return out;
  } catch (e) {
    const c = classify(e);
    logLine(log, params.model, t0, c.kind);
    return { ok: false, partial: "", ...c };
  }
}

export async function streamLLM(client: Anthropic, params: Params, onText: (d: string) => void, log: Log): Promise<LLMResult> {
  const t0 = performance.now();
  let partial = "";
  const stream = client.messages.stream(params);
  stream.on("text", (d) => { partial += d; onText(d); });
  try {
    const res = await stream.finalMessage();
    const out = fromMessage(res);
    logLine(log, params.model, t0, out.ok ? "ok" : out.kind, res);
    return out;
  } catch (e) {
    const c = classify(e);
    logLine(log, params.model, t0, c.kind);
    return { ok: false, partial, ...c };
  }
}

❌ Reading the first block blindly

❌ A retry loop around the SDK

  try { return await client.messages.create(params); }

    // الصمت هنا بيخبي السبب
  }

const out = await callLLM(client, params, log);

بالعامية

اللوب الخارجية بتضرب في الـ retries بتاعة الـ SDK، وبتعيد على 400 لأن الـ catch مش بيفرّق. الصح تسيب الـ SDK يعمل المحاولات القصيرة، وبعدها تبص على kind: لو مؤقت أجّل الـ job، ولو bug أوقفها.

❌ A "stream" that buffers

res.end(JSON.stringify(final.content));
// نفس الانتظار، وزوّدنا hop كمان
✅ Forward deltas as they arrive

  res.write(`data: ${JSON.stringify({ delta })}\n\n`));
stream.on("end", () => res.end());
بالعامية

الـ finalMessage() ممتازة في الـ jobs، بس لو ناديتها قبل ما تبعت أي حاجة للمستخدم يبقى إنت حافظت على نفس الانتظار، والقياس فوق بيقول إن أول byte جه عند ≈1650 ms بدل ≈220 ms. الصح تكتب كل delta أول ما توصل.

❌ Storing only the text

  role: "assistant",
  content: res.content.map((b) => (b.type === "text" ? b.text : "")).join(""),

// الـ thinking والـ compaction blocks ضاعوا

history.push({ role: "assistant", content: res.content });
// الـ blocks كلها بترجع زي ما اتولدت
بالعامية

لو خزنت النص بس، الـ blocks التانية بتضيع من غير أي error، والمحادثة ممكن تبوظ أو تفقد سياقها. الصح تضيف res.content زي ما رجع.

2. Delay after the SDK gives up 🟡 medium Write nextDelayMs(attempt, retryAfterSec) for a background job. A server-provided retry-after wins; otherwise exponential backoff with full jitter, capped at 60 s.

Solution · الحل 
import assert from "node:assert/strict";

// بعد ما الـ SDK يخلص الـ retries بتاعته، الـ job بتتأجل بالوقت ده
export function nextDelayMs(attempt: number, retryAfterSec?: number, random = Math.random): number {
  // الـ retry-after من السيرفر أهم من أي حساب عندك
  if (retryAfterSec !== undefined) return retryAfterSec * 1_000;
  const ceiling = Math.min(60_000, 1_000 * 2 ** attempt);
  // الـ jitter بيفرّق الـ jobs عشان ميرجعوش كلهم في نفس اللحظة
  return Math.floor(random() * ceiling);
}

assert.equal(nextDelayMs(3, undefined, () => 0.5), 4_000);
assert.equal(nextDelayMs(20, undefined, () => 0.999999), 59_999);
console.log("all assertions passed");

Cheat sheet · الخلاصة

  • messages.create({ model, max_tokens, system, messages }): system is top-level, the first message is user.
  • content is an array of blocks. Check stop_reason first, then narrow.
  • Seven stop reasons in SDK 1.6.0; max_tokens, refusal and model_context_window_exceeded are not success.
  • Real prompt size = input + cache_creation + cache_read. Thinking counts as output. Log tokens and dollars per call.
  • Don't lowball max_tokens: about 16,000 non-streaming, 64,000 streaming, lower only for a reason.
  • Keys: env plus a secrets manager, server only; NEXT_PUBLIC_ means public; a committed key must be rotated.
  • maxRetries defaults to 2 (3 requests). Don't nest loops. Most specific error class first; 529 before 500.
  • Timeout default is 10 min, in ms, retried: wall clock can reach timeout × 3.
  • Streaming improves perceived latency, not total time. Forward deltas; abort when the client leaves.
  • A mid-stream failure arrives after the 200 as APIError with undefined status, and it isn't retried.
  • The API is stateless: input grows linearly, spend quadratically. Append res.content; drop whole exchanges; keep it append-only on models with preserved thinking.
  • Eval the wrapper in CI: one case per stop reason and per error class.

  • messages.create({ model, max_tokens, system, messages }): الـ system لوحده فوق، وأول رسالة user.
  • content مصفوفة blocks. افحص الـ stop_reason الأول، وبعدها اعمل narrow.
  • 7 أسباب للوقوف في الـ SDK 1.6.0، وmax_tokens وrefusal وmodel_context_window_exceeded مش نجاح.
  • الحجم الحقيقي للـ prompt = input + cache_creation + cache_read. الـ thinking بيتحسب output. سجّل الـ tokens والدولارات لكل call.
  • متبخلش في max_tokens: حوالي 16,000 من غير streaming، و64,000 مع streaming، وتنزل لسبب بس.
  • الـ keys: في الـ env مع secrets manager، وعلى الـ server بس. NEXT_PUBLIC_ يعني عام. أي key اتعمله commit لازم يتغير.
  • maxRetries الـ default بتاعها 2 (يعني 3 requests). متحطش لوب فوقها. اكتب الـ errors من الأخص للأعم، والـ 529 قبل الـ 500.
