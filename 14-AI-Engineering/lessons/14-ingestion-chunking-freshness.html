Why this matters · ليه ده مهم

English

Most RAG failures that reach users start here, not in the model: a table cut in half, a stale policy still answering, a deleted customer's document still searchable, a nightly job burning money re-embedding what never changed. Ingestion is ordinary backend work (jobs, idempotency, transactions, retries) applied to a new kind of data, and that is exactly why a strong backend engineer has an edge here. Interviewers probe it with one question: "what happens when a document changes?"

Part 1 — The pipeline as a job 🟡 Intermediateالجزء 1 — الـ pipeline كـ background job

English

Ingestion has five stages: load (PDF, HTML, Markdown, DB rows), clean, chunk, embed, store. It's slow, it calls a rate-limited paid API, and any stage can fail, so it belongs in a background job and never in a request. BullMQ gives you retries, concurrency and visibility on Redis; section 06 lesson 22 covers the basics, so this part focuses on what is specific to RAG.

The defining requirement is idempotency by content hash. Each chunk gets a SHA-256 of its embedded text, and UNIQUE (doc_id, content_hash) makes it a key. A re-run compares hashes, embeds only what is new, deletes what disappeared, and leaves the rest alone. The run below processes four real sources twice: 8 texts embedded the first time, 0 the second. The opposite design, a nightly job that re-embeds everything, costs $80 a night at 10M chunks on the cheapest model: $2,400 a month to learn nothing new.

Each loader removes what would pollute search. In HTML that means dropping nav, footer and scripts before reading main; embedding "Sign in · Orders · Cart" on every page makes every page look alike. PDF text comes from unpdf as a flat string with no headings at all, and repeated headers and footers must be stripped explicitly. The output confirms that "ACME Billing" and "Page 1 of 2" are gone.

// عدّ tokens تقريبي (الحروف على 3.6)، نفس المستخدم في الـ stand-in، ومش tokenizer حقيقي
export const tokens = (s: string) => Math.ceil([...s].length / 3.6);
export const sha = (s: string) => createHash("sha256").update(s).digest("hex").slice(0, 16);

export type Chunk = { text: string; section: string };
export type SourceDoc = { docId: string; tenantId: number; source: string; updatedAt: string; chunks: Chunk[] };

export const EMBEDDING_MODEL = "kit-v1";

export async function openStore() {
  const db = await PGlite.create({ extensions: { vector } });
  await db.exec(`
    CREATE EXTENSION vector;
    CREATE TABLE chunks (
      id bigserial PRIMARY KEY,
      doc_id text NOT NULL,
      tenant_id int NOT NULL,
      source text NOT NULL,
      section text NOT NULL,
      updated_at date NOT NULL,
      content_hash text NOT NULL,
      embedding_model text NOT NULL,
      body text NOT NULL,
      embedding vector(${DIM}) NOT NULL,
      UNIQUE (doc_id, content_hash)
    );
  `);
  return db;
}

// الـ title prefix بيدخل الـ embedding بس، مش الـ body اللي بيروح للـ LLM
export const embedText = (c: Chunk, source: string) => `${source} > ${c.section}\n${c.text}`;

export type EmbedFn = (texts: string[]) => Promise<number[][]>;
export const localEmbed: EmbedFn = async (texts) => texts.map(embed);

// ✅ كل المستند في transaction واحدة، والـ chunks اللي الـ hash بتاعها موجود مبتتعملهاش embed
export async function ingestDocument(db: PGlite, doc: SourceDoc, embedFn: EmbedFn = localEmbed) {
  // نفس النص مرتين في المستند (footer مثلًا) بيتخزن مرة واحدة
  const unique = new Map(doc.chunks.map((c) => [sha(embedText(c, doc.source)), c]));
  const wanted = [...unique].map(([hash, c]) => ({ ...c, hash }));
  const existing = await db.query<{ content_hash: string }>("SELECT content_hash FROM chunks WHERE doc_id = $1", [doc.docId]);
  const have = new Set(existing.rows.map((r) => r.content_hash));
  const toEmbed = wanted.filter((c) => !have.has(c.hash));
  const vectors = toEmbed.length ? await embedFn(toEmbed.map((c) => embedText(c, doc.source))) : [];

  const keep = wanted.map((c) => c.hash);
  await db.transaction(async (tx) => {
    await tx.query("DELETE FROM chunks WHERE doc_id = $1 AND NOT (content_hash = ANY($2))", [doc.docId, keep]);
    for (const [i, c] of toEmbed.entries()) {
      await tx.query(
        `INSERT INTO chunks (doc_id, tenant_id, source, section, updated_at, content_hash, embedding_model, body, embedding)
         VALUES ($1,$2,$3,$4,$5,$6,$7,$8,$9)`,
        [doc.docId, doc.tenantId, doc.source, c.section, doc.updatedAt, c.hash, EMBEDDING_MODEL, c.text, JSON.stringify(vectors[i])],
      );
    }
  });
  return { total: wanted.length, embedded: toEmbed.length, skipped: wanted.length - toEmbed.length };
}

// الـ port لازم يتفحص قبل أي اتصال: port فاضي معناه الـ default بتاع الـ service الحقيقية
export function safePort(raw: string): number {
  const text = String(raw).trim();
  const n = Number(text);
  if (!/^\d+$/.test(text) || n < 1024 || n > 65535 || [27017, 5432, 6379].includes(n)) throw new Error("refusing port " + raw);
  return n;
}
import { JSDOM } from "jsdom";
import { extractText, getDocumentProxy } from "unpdf";

export type Section = { section: string; text: string };

// الـ clean بيشيل زبالة الـ encoding قبل الـ chunking، مش بعده
export function clean(raw: string): string {
  return raw
    .normalize("NFKC")
    .replace(/­/g, "")
    .replace(/[\u0000-\u0008\u000b\u000c\u000e-\u001f�]/g, "")
    .replace(/(\p{L})-\n(\p{L})/gu, "$1$2")
    .replace(/[ \t]+/g, " ")
    .replace(/ ?\n ?/g, "\n")
    .replace(/\n{3,}/g, "\n\n")
    .trim();
}

// الـ Markdown: كل heading بيبدأ section، والـ tables بتفضل زي ما هي
export function loadMarkdown(text: string): Section[] {
  const sections: Section[] = [];
  let current: Section = { section: "(intro)", text: "" };
  for (const line of text.split("\n")) {
    const heading = line.match(/^#{1,3}\s+(.*)$/);
    if (heading) {
      if (current.text.trim()) sections.push(current);
      current = { section: heading[1].trim(), text: "" };
    } else {
      current.text += line + "\n";
    }
  }
  if (current.text.trim()) sections.push(current);
  return sections.map((s) => ({ section: s.section, text: clean(s.text) }));
}

// الـ HTML: الـ nav والـ footer والـ scripts مش معرفة، والـ embedding بتاعهم بيلوّث البحث
export function loadHtml(html: string): Section[] {
  const { document } = new JSDOM(html).window;
  document.querySelectorAll("script, style, nav, header, footer, aside, form, [aria-hidden=true]").forEach((n) => n.remove());
  const root = document.querySelector("main, article") ?? document.body;
  const sections: Section[] = [];
  let current: Section = { section: "(intro)", text: "" };
  for (const node of Array.from(root.children)) {
    if (/^H[1-3]$/.test(node.tagName)) {
      if (current.text.trim()) sections.push(current);
      current = { section: (node.textContent ?? "").trim(), text: "" };
    } else {
      current.text += (node.textContent ?? "") + "\n\n";
    }
  }
  if (current.text.trim()) sections.push(current);
  return sections.map((s) => ({ section: s.section, text: clean(s.text) }));
}

// الـ PDF: الناتج نص بس من غير headings، فالـ header والـ footer المتكرر لازم يتشال يدوي
export async function loadPdf(bytes: Uint8Array, repeatedLines: RegExp[] = []): Promise<Section[]> {
  const pdf = await getDocumentProxy(bytes);
  const { text } = await extractText(pdf, { mergePages: true });
  const merged = Array.isArray(text) ? text.join("\n") : text;
  const body = repeatedLines.reduce((acc, re) => acc.replace(re, " "), merged);
  return [{ section: "(pdf)", text: clean(body) }];
}

  if (job.kind === "md") return loadMarkdown(readFileSync(job.path, "utf8"));
  if (job.kind === "html") return loadHtml(readFileSync(job.path, "utf8"));

// ملف PDF حقيقي صغير مبني بإيدينا: صفحتين عليهم نفس الـ header والـ footer
function buildPdf(pages: string[][]): Buffer {
  const objects: string[] = [];
  const add = (body: string) => objects.push(body) - 1;
  const catalog = add("<< /Type /Catalog /Pages 2 0 R >>");
  add("");
  const font = add("<< /Type /Font /Subtype /Type1 /BaseFont /Helvetica >>");
  const kids: number[] = [];
  for (const lines of pages) {
    const body = ["BT", "/F1 11 Tf", "72 760 Td", "14 TL", ...lines.map((l) => `(${l.replace(/([()\\])/g, "\\$1")}) Tj T*`), "ET"].join("\n");
    const content = add(`<< /Length ${Buffer.byteLength(body)} >>\nstream\n${body}\nendstream`);
    kids.push(add(`<< /Type /Page /Parent 2 0 R /MediaBox [0 0 612 792] /Resources << /Font << /F1 ${font + 1} 0 R >> >> /Contents ${content + 1} 0 R >>`));
  }
  objects[1] = `<< /Type /Pages /Count ${kids.length} /Kids [${kids.map((k) => `${k + 1} 0 R`).join(" ")}] >>`;
  let out = "%PDF-1.4\n";
  const offsets: number[] = [];
  objects.forEach((body, i) => {
    offsets.push(Buffer.byteLength(out));
    out += `${i + 1} 0 obj\n${body}\nendobj\n`;
  });
  const xref = Buffer.byteLength(out);
  out += `xref\n0 ${objects.length + 1}\n0000000000 65535 f \n` + offsets.map((o) => `${String(o).padStart(10, "0")} 00000 n \n`).join("");
  out += `trailer\n<< /Size ${objects.length + 1} /Root ${catalog + 1} 0 R >>\nstartxref\n${xref}\n%%EOF\n`;
  return Buffer.from(out, "latin1");
}

الـ ingestion 5 مراحل: load (PDF و HTML و Markdown و DB rows)، clean، chunk، embed، store. بطيء، وبينادي API مدفوع عليه rate limit، وأي مرحلة ممكن تقع، فمكانه background job ومش جوه request أبدًا. الـ BullMQ بيديك retries و concurrency و visibility على Redis، والدرس 22 من قسم 06 بيغطي الأساسيات، فالجزء ده مركز على اللي خاص بالـ RAG.

الشرط الأساسي هو idempotency بالـ content hash. كل chunk بياخد SHA-256 للنص اللي بيتعمله embed، وUNIQUE (doc_id, content_hash) بيخليه مفتاح. الـ re-run بيقارن الـ hashes، يعمل embed للجديد بس، يمسح اللي اختفى، ويسيب الباقي. الـ run فوق شغّل 4 مصادر حقيقية مرتين: 8 نصوص أول مرة و0 تاني مرة. والتصميم العكسي، job كل ليلة بيعمل re-embed لكل حاجة، بيكلف $80 في الليلة على 10 مليون chunk بأرخص model، يعني $2,400 في الشهر من غير أي فايدة.

كل loader بيشيل اللي بيلوّث البحث. في الـ HTML يعني تشيل nav وfooter والـ scripts قبل ما تقرا main، لأن لو عملت embed لـ "Sign in · Orders · Cart" في كل صفحة، كل الصفحات هتبقى شبه بعض. والـ PDF بييجي من unpdf كنص مسطح من غير أي headings، فالـ headers والـ footers المتكررة لازم تتشال صراحة. والناتج بيأكد إن "ACME Billing" و"Page 1 of 2" اختفوا.

فين هستخدمه في شغلي؟ الـ ops team بيرفع PDFs لسياسات الشركة على الـ admin panel: الـ upload بيحط الملف في S3 ويعمل queue.add بـ path الملف مش محتواه، عشان Redis يفضل خفيف. لو نفس الملف اترفع تاني بتعديل صغير في صفحة واحدة، الـ hash بيخلي الـ embed يحصل للـ chunks اللي اتغيرت بس، والفاتورة تفضل صغيرة.

Part 2 — Chunking strategies 🟡 Intermediateالجزء 2 — استراتيجيات الـ chunking

English

You embed chunks because one vector can't represent a whole document, and because the prompt can't hold it either. There are three families. Fixed size with overlap slides a window over the text: trivial, and blind to meaning. By structure follows headings and paragraphs and treats a table as atomic. Semantic computes the similarity between adjacent sentences and splits where it drops, at the price of embedding every sentence once before chunking.

The numbers are from long documents built by merging the corpus per source, with recall@5 counting a hit only when the entire answer sits inside one chunk. Two styles were tested. On structured Markdown, fixed-size scored 0.73 and structure 0.60, which looks like a defeat until you read the next column. Fixed sent 732 tokens of context per query and structure sent 118: the fixed chunker won by sending six times as much text. Give structure the same budget (k=30, 710 tokens) and it scores 0.83. Compare strategies at equal context budget, or you're measuring how much you paid. On flat text with no headings, as PDFs often arrive, structure has nothing to hold on to and the gap closes to 0.73 against 0.70.

Semantic chunking scored lowest here because it split answers that span two sentences, and that's partly the stand-in: its similarity comes from a synonym table, and the 0.15 threshold is a guess. Treat this as a demonstration of the mechanism and the cost (191 sentence embeds before chunking even starts). Whether semantic chunking helps a real model on your documents is something only your own eval can answer.

import { cosine, embed } from "../../kit/rag-kit.ts";
import { tokens, type Chunk } from "./lib.ts";
import type { Section } from "./loaders.ts";

const CHARS_PER_TOKEN = 3.6;
const sentencesOf = (text: string) =>
  (text.match(/[^.!?\n]+[.!?]*(?=\s|$)/g) ?? []).map((s) => s.trim()).filter(Boolean);

// (1) حجم ثابت ⁦+ overlap⁩: أبسط حاجة، وبيقطع في أي مكان
export function fixedChunks(sections: Section[], maxTokens: number, overlapTokens: number): Chunk[] {
  const size = Math.floor(maxTokens * CHARS_PER_TOKEN);
  const step = size - Math.floor(overlapTokens * CHARS_PER_TOKEN);
  const text = sections.map((s) => s.text).join("\n\n");
  const out: Chunk[] = [];
  for (let i = 0; i < text.length; i += step) {
    out.push({ text: text.slice(i, i + size).trim(), section: "(none)" });
    if (i + size >= text.length) break;
  }
  return out;
}

// الجدول الكبير بيتقسم صفوف، والـ header بيتكرر عشان كل صف يفضل مفهوم لوحده
function splitTable(block: string, maxTokens: number): string[] {
  const [header, divider, ...rows] = block.split("\n");
  const pieces: string[] = [];
  let current: string[] = [];
  const frame = (r: string[]) => [header, divider, ...r].join("\n");
  for (const row of rows) {
    if (current.length && tokens(frame([...current, row])) > maxTokens) {
      pieces.push(frame(current));
      current = [];
    }
    current.push(row);
  }
  if (current.length) pieces.push(frame(current));
  return pieces;
}

// (2) حسب الهيكل: headings ثم paragraphs، والجدول عمره ما يتقطع في نص صف
export function structureChunks(sections: Section[], maxTokens: number): Chunk[] {
  const out: Chunk[] = [];
  for (const s of sections) {
    let current = "";
    const flush = () => {
      if (current) out.push({ text: current, section: s.section });
      current = "";
    };
    for (const block of s.text.split(/\n{2,}/).map((b) => b.trim()).filter(Boolean)) {
      const isTable = block.startsWith("|");
      const pieces = tokens(block) <= maxTokens ? [block] : isTable ? splitTable(block, maxTokens) : sentencesOf(block);
      for (const piece of pieces) {
        if (current && tokens(`${current}\n\n${piece}`) > maxTokens) flush();
        current = current ? `${current}\n\n${piece}` : piece;
      }
    }
    flush();
  }
  return out;
}

// (3) التقسيم الـ semantic: بيقطع لما الـ similarity بين جملتين ورا بعض تقع
export function semanticChunks(sections: Section[], maxTokens: number, threshold: number) {
  const out: Chunk[] = [];
  let sentenceEmbeds = 0;
  for (const s of sections) {
    const sentences = sentencesOf(s.text);
    if (!sentences.length) continue;
    let current = [sentences[0]];
    let previous = embed(sentences[0]);
    sentenceEmbeds++;
    for (const sentence of sentences.slice(1)) {
      const vector = embed(sentence);
      sentenceEmbeds++;
      const tooBig = tokens([...current, sentence].join(" ")) > maxTokens;
      if (cosine(previous, vector) < threshold || tooBig) {
        out.push({ text: current.join(" "), section: s.section });
        current = [];
      }
      current.push(sentence);
      previous = vector;
    }
    out.push({ text: current.join(" "), section: s.section });
  }
  return { chunks: out, sentenceEmbeds };
}

import { ALL_DOCS, GOLDEN, cosine, embed } from "../../kit/rag-kit.ts";
import { tokens, type Chunk } from "./lib.ts";
import type { Section } from "./loaders.ts";

export type LongDoc = { source: string; sections: Section[] };

// ملفات طويلة مبنية من الـ corpus: كل source بقى ملف واحد فيه كل الـ sections بتاعته
export function longDocs(style: "structured" | "flat"): LongDoc[] {
  const bySource = new Map<string, Section[]>();
  for (const d of ALL_DOCS) {
    const list = bySource.get(d.source) ?? [];
    list.push({ section: d.section, text: d.body });
    bySource.set(d.source, list);
  }
  return [...bySource].map(([source, sections]) => ({
    source,
    // الـ flat بيقلّد PDF: نص متصل من غير headings ولا paragraphs
    sections: style === "structured" ? sections : [{ section: "(none)", text: sections.map((s) => s.text).join(" ") }],
  }));
}

export type Located = Chunk & { source: string };
const bodyOf = new Map(ALL_DOCS.map((d) => [d.id, d.body]));

export function evaluate(chunks: Located[], opts: { titlePrefix?: boolean; k?: number } = {}) {
  const k = opts.k ?? 5;
  const indexed = chunks.map((c) => ({
    ...c,
    vector: embed(opts.titlePrefix ? `${c.source} > ${c.section}\n${c.text}` : c.text),
  }));
  let hits = 0;
  let contextTokens = 0;
  let relevantTokens = 0;
  for (const g of GOLDEN) {
    const q = embed(g.q);
    const top = [...indexed].sort((a, b) => cosine(q, b.vector) - cosine(q, a.vector)).slice(0, k);
    const gold = g.relevant.map((id) => bodyOf.get(id)!);
    // الـ hit هنا معناه إن الإجابة كلها جوه chunk واحد، مش مقطوعة بين اتنين
    const hit = top.some((c) => gold.some((body) => c.text.includes(body)));
    if (hit) {
      hits++;
      relevantTokens += tokens(gold[0]);
    }
    contextTokens += top.reduce((s, c) => s + tokens(c.text), 0);
  }
  const avg = chunks.reduce((s, c) => s + tokens(c.text), 0) / chunks.length;
  const max = Math.max(...chunks.map((c) => tokens(c.text)));
  return {
    chunks: chunks.length,
    avgTokens: Math.round(avg),
    maxTokens: max,
    recallAt5: (hits / GOLDEN.length).toFixed(2),
    contextTokensPerQuery: Math.round(contextTokens / GOLDEN.length),
    relevantShare: ((relevantTokens / contextTokens) * 100).toFixed(1) + "%",
  };
}

Part 3 — Chunk size and metadata 🟡 Intermediateالجزء 3 — حجم الـ chunk والـ metadata

English

Chunk size is a trade-off between precision and context. Small chunks embed one idea and match sharply, but can lack the surrounding sentence that makes them meaningful. Big chunks carry that context plus noise, and every retrieved chunk costs prompt tokens. The sweep shows recall@5 climbing from 0.70 to 0.90 as size grows from 200 to 800, and it would be easy to stop reading there. But the share of retrieved tokens that are actually relevant falls from 2.3% to 1.7%, and on this small corpus, 15 chunks of 800 tokens means top-5 returns a third of everything.

The cost table makes it concrete at scale, with 4,000 MTok of text and 15% overlap. Embedding cost barely depends on chunk size ($94 for all three), because you embed the same text either way. What moves is storage (97 GB of vectors at 200 tokens versus 24 GB at 800, at 1024 dims) and the recurring cost of context: $2,000 a month against $8,000 at a million queries on Sonnet 5.5. Chunk size is mostly a query-time bill.

Metadata belongs in columns: source, section, date. Then filtering by date or source is ordinary SQL in the same statement as the vector search. A separate technique is the title prefix: embed source > section with the text, but store and send only the text. On the stand-in, recall went from 0.60 to 0.77 at the same context cost, because a section title like "VAT" adds a concept the body may not repeat. That number belongs to the stand-in. The same idea with real models is Anthropic's Contextual Retrieval, where the published result was a 35% lower top-20 retrieval failure rate.

Part 4 — Embedding at scale 🟡 Intermediateالجزء 4 — الـ embedding على حجم كبير

English

The kit's rpm option serves only /v1/messages and uses a 60-second window, so a small local embeddings server stands in here, with the same shape as a real API and a 429 after 8 requests per second. Embedding APIs enforce both request and token limits; Voyage for instance accepts up to 1,000 texts per request and 120K to 1M tokens per request depending on the model. Batching is the first lever because it multiplies throughput without adding a single request.

The three runs below embed the same 712 texts. Naive (one request per chunk, all at once, no retry) got 8 through: 224 were rate limited and 480 died with socket errors before reaching the server. Batched with backoff (16 per batch, 4 lanes, honoring retry-after with jitter) embedded all 712 in about 6 s with 65 requests and 20 retried 429s. The BullMQ limiter paced the worker itself at 7 per second: all 712, 45 requests, and zero 429s, in the same time. The limiter is better than backoff because the waiting happens in your queue instead of as failed calls against someone's rate limit, and it holds across every worker sharing the queue. Backoff stays as the safety net.

A poison document is one that will never succeed, such as a broken PDF the provider rejects with a 400. Retrying it wastes attempts and delays everything behind it, so throw UnrecoverableError and copy it to a dead-letter queue with the reason. BullMQ has no built-in DLQ; a second queue and the failed event are the pattern. Rate limits, by contrast, are retryable and must never go to the DLQ.

Two failure modes define the job's guarantees. Kill the worker mid-document: in the real run below, a child process was killed with SIGKILL at 16 of 40 chunks. BullMQ's stalled check handed the job to a new worker when the lock expired, and it embedded only the remaining 24, so the document cost 40 embeddings and not 56, because each batch is checkpointed in Redis. Half-indexed documents: writing chunks one at a time leaves 5 of 10 rows after a failure, and a reader gets half a document with no warning. One transaction per document leaves 0 and the retry starts clean.

async function withBackoff<T>(fn: () => Promise<T>, maxAttempts = 8): Promise<T> {
  for (let attempt = 1; ; attempt++) {
    try {
      return await fn();
    } catch (err) {
      if (!(err instanceof RateLimited) || attempt === maxAttempts) throw err;
      // الـ jitter بيمنع كل الـ workers يرجعوا في نفس اللحظة
      await sleep(err.retryAfterMs + Math.random() * 250);
    }
  }
}

import { createServer } from "node:http";
import type { AddressInfo } from "node:net";
import { embed } from "../../kit/rag-kit.ts";

export async function startEmbedServer(opts: { limit: number; windowMs: number; latencyMs?: number }) {
  const stats = { requests: 0, ok: 0, rateLimited: 0, rejected: 0 };
  let hits: number[] = [];
  const server = createServer(async (rq, rs) => {
    const body: Buffer[] = [];
    for await (const c of rq) body.push(c as Buffer);
    const { input } = JSON.parse(Buffer.concat(body).toString()) as { input: string[] };
    stats.requests++;
    const now = Date.now();
    hits = hits.filter((t) => now - t < opts.windowMs);
    if (hits.length >= opts.limit) {
      stats.rateLimited++;
      rs.writeHead(429, { "content-type": "application/json", "retry-after": "1" });
      return rs.end(JSON.stringify({ error: { message: "rate limit exceeded" } }));
    }
    hits.push(now);
    if (input.some((t) => t.includes("POISON"))) {
      stats.rejected++;
      rs.writeHead(400, { "content-type": "application/json" });
      return rs.end(JSON.stringify({ error: { message: "input could not be processed" } }));
    }
    await new Promise((r) => setTimeout(r, opts.latencyMs ?? 20));
    stats.ok++;
    rs.writeHead(200, { "content-type": "application/json" });
    rs.end(JSON.stringify({ data: input.map((t) => ({ embedding: embed(t) })), usage: { total_tokens: input.join("").length } }));
  });
  await new Promise<void>((r) => server.listen(0, "127.0.0.1", r));
  const url = `http://127.0.0.1:${(server.address() as AddressInfo).port}/v1/embeddings`;
  console.log(`[SIMULATED] embedding stand-in: ${opts.limit} requests per ${opts.windowMs} ms, then 429`);
  return { url, stats, close: () => new Promise<void>((r) => { server.closeAllConnections(); server.close(() => r()); }) };
}

export class RateLimited extends Error {
  retryAfterMs: number;
  constructor(retryAfterMs: number) {
    super("429 from embedding API");
    this.retryAfterMs = retryAfterMs;
  }
}

export async function callEmbed(url: string, input: string[]): Promise<number[][]> {
  const res = await fetch(url, { method: "POST", headers: { "content-type": "application/json" }, body: JSON.stringify({ input }) });
  if (res.status === 429) throw new RateLimited(Number(res.headers.get("retry-after") ?? "1") * 1000);
  if (!res.ok) throw new Error(`embedding API ${res.status}: ${await res.text()}`);
  const json = (await res.json()) as { data: { embedding: number[] }[] };
  return json.data.map((d) => d.embedding);
}

export async function embedWithCheckpoint(job: Job, redis: Redis, onEmbedded: (n: number) => void, delayMs: number) {
  const key = ckptKey(DOC_ID);
  const done = new Set(await redis.hkeys(key));
  for (let i = 0; i < TEXTS.length; i += 4) {
    const batch = TEXTS.slice(i, i + 4).filter((t) => !done.has(sha(t)));
    if (batch.length) {
      await new Promise((r) => setTimeout(r, delayMs));
      const fields = batch.flatMap((t) => [sha(t), JSON.stringify(embed(t))]);
      await redis.hset(key, ...fields);
      onEmbedded(batch.length);
    }
    await job.updateProgress(Math.round((Math.min(i + 4, TEXTS.length) / TEXTS.length) * 100));
  }
  const saved = await redis.hgetall(key);
  return TEXTS.map((t) => ({ text: t, vector: JSON.parse(saved[sha(t)]) as number[] }));
}

فيه failure modes اتنين بيحددوا ضمانات الـ job. قتل الـ worker في نص المستند: في الـ run الحقيقي تحت، child process اتقتل بـ SIGKILL عند 16 من 40 chunk. الـ stalled check بتاع BullMQ سلّم الـ job لـ worker جديد لما الـ lock خلص، وعمل embed للـ 24 الباقيين بس، فالمستند اتكلف 40 embedding مش 56، لأن كل batch له checkpoint في Redis. والمستندات النص متخزنة: الكتابة chunk بـ chunk سابت 5 من 10 صفوف بعد الوقوع، والقارئ بياخد نص مستند من غير أي تحذير. أما transaction لكل مستند فبتسيب صفر، والـ retry بيبدأ نضيف.

Interview question: your backfill worker keeps getting 429s. What do you change first? Pace before you retry. Batch to cut the request count, cap the worker with a shared limiter below the provider's limit, and keep backoff with jitter that honors retry-after as the fallback. Then checkpoint progress so a restart doesn't pay twice. Retrying harder only moves the failure around.

Part 5 — Freshness 🟡 Intermediateالجزء 5 — الـ freshness والحذف

English

A vector is a copy of your data, and copies go stale. The reliable way to keep it in step is the outbox: update the row and insert an outbox event in one transaction, so a change can't be saved without its event. A worker consumes the outbox and re-embeds. Section 09 lesson 41 covers relays, ordering and CDC in depth. Debezium reading the WAL is the alternative that needs no application changes; it's not run here because it requires an external service. To avoid paying for every keystroke, BullMQ's deduplication collapses rapid edits: five edits inside the TTL became a single delayed job in a real run.

The stale-answer test below is real, with the answer scripted. Version 1 says 14 days. After the row is updated to 30 days but before the relay runs, the system still answers 14 days: that window is the true cost of asynchronous indexing, and its length is something you can measure and alert on. After the relay it says 30. Running the relay again processes 0 events, so it is safe to repeat.

Deletion is a requirement, not a cleanup task. When a document or a user goes, their chunks must go too, or the bot keeps quoting data you promised to erase. Here a foreign key with ON DELETE CASCADE removes the chunks in the same transaction as the document: 0 left, and the question now gets "I don't know". Soft deletes don't fire a cascade, so they need an outbox event (exercise 3). Backups and retention windows are part of the same promise; see section 09 lesson 21 for GDPR deletion.

  app transaction                      relay / worker
  +------------------------+           +----------------------------------+
  | UPDATE docs SET body   |           | read unprocessed outbox rows     |
  | INSERT INTO outbox ... | --------->| delete old chunks, embed, insert |
  +------------------------+  COMMIT   | mark processed, in one tx        |
                                       +----------------------------------+
  stale window = time between COMMIT and "mark processed"

  deletion:  DELETE docs --(FK cascade, same tx)--> doc_chunks gone

// ✅ تعديل الـ row والـ outbox في transaction واحدة: مفيش تغيير يضيع
async function saveDoc(id: string, ownerUserId: number, body: string) {
  await db.transaction(async (tx) => {
    await tx.query(
      `INSERT INTO docs (id, owner_user_id, body) VALUES ($1, $2, $3)
       ON CONFLICT (id) DO UPDATE SET body = EXCLUDED.body, updated_at = now()`,
      [id, ownerUserId, body],
    );
    await tx.query("INSERT INTO outbox (doc_id, op) VALUES ($1, 'upsert')", [id]);
  });
}

// الـ relay: بيقرا الـ outbox ويعمل re-embed، وتكراره مش بيضر
async function drainOutbox() {
  const pending = await db.query<{ id: string; doc_id: string; op: string }>("SELECT id, doc_id, op FROM outbox WHERE processed_at IS NULL ORDER BY id");
  for (const e of pending.rows) {
    await db.transaction(async (tx) => {
      await tx.query("DELETE FROM doc_chunks WHERE doc_id = $1", [e.doc_id]);
      if (e.op === "upsert") {
        const doc = await tx.query<{ body: string }>("SELECT body FROM docs WHERE id = $1", [e.doc_id]);
        if (doc.rows[0]) {
          await tx.query("INSERT INTO doc_chunks VALUES ($1, $2, $3)", [e.doc_id, doc.rows[0].body, JSON.stringify(embed(doc.rows[0].body))]);
        }
      }
      await tx.query("UPDATE outbox SET processed_at = now() WHERE id = $1", [e.id]);
    });
  }
  return pending.rows.length;
}

Part 6 — Cost, latency, failure, and an eval 🟡 Intermediateالجزء 6 — التكلفة والـ latency والأعطال والـ eval

English

The run ingests 1,000 documents (6,000 chunks) through the real pipeline. Without a provider in the loop, the pipeline itself took about 1.4 s and the HNSW build about 1.2 s, on PGlite on a loaded Windows machine. That's the point: your code is almost never the slow part. With an assumed 200 ms per embedding request and 4 in flight, one chunk per request means about 300 s, batches of 16 about 19 s and batches of 128 about 2.4 s. Cost is simple arithmetic on the 189,192 simulated tokens: $0.0038 per 1,000 documents on text-embedding-3-small, and $0.0227 on voyage-4-large. Embedding this corpus is nearly free. Paying for the same thing every night is what gets expensive.

A pipeline's eval is mostly invariants, because the failures are structural. The script below asserts 15 of them: chunk output is stable across runs, no chunk exceeds the token limit under any chunker, tables are never cut and repeat their header, PDF junk is removed, boilerplate stays out, a re-run embeds 0 chunks, every chunk has metadata, duplicates are stored once, only one embedding model exists, and deleted documents are absent from search. These run in CI with no API key at all, which is exactly why they run on every commit. Retrieval quality is a separate eval (lesson 15).

The remaining failure modes are the silent ones: PDF junk that embeds fine and retrieves badly, a footer repeated on every page and stored once per page, and a mid-run model change that writes a second kind of vector into the column without any error. async function softDelete(id: string) {
  await db.transaction(async (tx) => {
    await tx.query("UPDATE docs SET deleted_at = now() WHERE id = $1", [id]);
    await tx.query("INSERT INTO outbox (doc_id, op) VALUES ($1, 'delete')", [id]);
  });
}

async function drain() {
  const events = await db.query<{ id: string; doc_id: string }>("SELECT id, doc_id FROM outbox WHERE processed_at IS NULL AND op = 'delete' ORDER BY id");

    await db.transaction(async (tx) => {
      await tx.query("DELETE FROM doc_chunks WHERE doc_id = $1", [e.doc_id]);
      await tx.query("UPDATE outbox SET processed_at = now() WHERE id = $1", [e.id]);
    });
  }
}

Cheat sheet · الخلاصة

  • Pipeline: load → clean → chunk → hash → embed → store, in a background job and never in a request.
  • Idempotency: UNIQUE (doc_id, content_hash); a re-run embeds 0 unchanged chunks.
  • Structure-aware chunking first, fixed with overlap for flat text, tables split between rows with the header repeated.
  • Compare chunkers at equal context budget: 0.73 for fixed at 732 tokens beat 0.60 at 118, and lost to 0.83 at 710.
  • Chunk size is a query-time bill: embed cost stayed at $94 while context went from $2,000 to $8,000 a month.
  • Metadata goes in columns so filters are plain SQL. Title prefix goes in the embedded text only.
  • Pace with a shared limiter below the provider limit; backoff with jitter is the safety net.
  • Poison documents: UnrecoverableError plus a DLQ queue. Rate limits are retried and never dead-lettered.
  • Checkpoint each batch, one transaction per document: a kill at 16 of 40 still paid only 40 embeddings.
  • Freshness: row plus outbox event in one transaction; measure the stale window and alert on it.
  • Deletion is a requirement: FK cascade, or an outbox event for soft deletes. Assert it in the eval.
  • Record embedding_model per chunk, and treat more than one value outside a migration as an incident.
بالعامية
  • الـ pipeline هو load ثم clean ثم chunk ثم hash ثم embed ثم store، في background job ومش في request أبدًا.
  • الـ idempotency بـ UNIQUE (doc_id, content_hash)، والـ re-run بيعمل embed لصفر chunks متغيرتش.
  • ابدأ بالـ structure-aware، و fixed مع overlap للنص المسطح، والجداول تتقسم بين الصفوف والـ header يتكرر.
  • قارن الـ chunkers بنفس ميزانية الـ context: الـ fixed بـ 0.73 على 732 token كسب 0.60 على 118، وخسر قدام 0.83 على 710.
  • حجم الـ chunk فاتورة وقت الـ query: الـ embed فضل $94 والـ context طلع من $2,000 لـ $8,000 في الشهر.
  • الـ metadata في columns عشان الـ filters تبقى SQL عادي، والـ title prefix في النص اللي بيتعمله embed بس.
  • نظّم السرعة بـ limiter مشترك أقل من حد الـ provider، والـ backoff مع jitter شبكة أمان.
  • الـ poison documents ليها UnrecoverableError و DLQ، والـ rate limits بتتعمل لها retry ومبتروحش DLQ.
  • checkpoint لكل batch و transaction لكل مستند: القتل عند 16 من 40 دفع 40 embedding بس.
  • الـ freshness: الـ row وحدث الـ outbox في transaction واحدة، وقيس الـ stale window واعمل عليه alert.
  • الحذف شرط أساسي: FK cascade، أو حدث outbox للـ soft delete، وتأكد منه في الـ eval.
  • سجّل embedding_model لكل chunk، وأكتر من قيمة واحدة بره migration معناها incident.
