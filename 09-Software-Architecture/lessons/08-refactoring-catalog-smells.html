Why this matters · ليه ده مهم

English

Lesson 07 fixed smells you can see inside one function. The expensive ones hide between files: a function living next to the wrong data, a pair of arguments repeated across 14 signatures, a payment method that needs 7 files changed, a billing query that breaks when another team renames a column. You find those by counting accesses and reading history, not by reading one file. This lesson names them with Fowler's vocabulary, so you can say "feature envy, Move Function" in a review instead of "this feels wrong", and it finishes with a whole session on a checkout route from the shared orders service.

درس 07 صلّح الـ smells اللي بتشوفها جوه function واحدة. الغالية بجد مستخبية بين الملفات: function قاعدة جنب data مش بتاعتها، زوج arguments متكرر في 14 signature، طريقة دفع جديدة محتاجة تغيير في 7 ملفات، query بتاعة billing بتقع لما فريق تاني يغيّر اسم column. دول بتلاقيهم بإنك تعدّ الـ accesses وتقرا الـ history، مش بإنك تقرا ملف واحد. الدرس ده بيدّيهم أسامي من vocabulary بتاع Fowler، فتقدر تقول في الـ review "feature envy، Move Function" بدل "حاسس إن فيه حاجة غلط"، وبيخلص بـ session كاملة على route الـ checkout من الـ orders service المشترك.

Part 1 — Feature envy → move function and field 🟡 Intermediateالجزء 1 — الـ feature envy: انقل الـ function والـ field

English

Feature envy is a function more interested in another object's data than in its own. calculateInvoiceTotal(order) lives in billing, but it reads six fields of order and nothing of billing. Every new charge on an order now means editing billing, and the rule cannot be reused or tested without it. You do not have to argue about it, because you can count:

import type { Invoice } from "./invoice.ts";
import type { Order } from "./order.ts";

export class BillingService {
  readonly #numberPrefix = "INV";

  calculateInvoiceTotal(order: Order): number {
    const subtotal = order.lines.reduce((sum, l) => sum + l.unitPriceCents * l.qty, 0);
    const discount = Math.round((subtotal * order.discountPercent) / 100);
    const taxable = subtotal - discount;
    const tax = Math.round((taxable * order.vatPercent) / 100);
    const fee = order.isRush ? order.rushFeeCents : 0;
    return taxable + tax + order.shippingCents + fee;

  }

Move Function, Fowler's mechanics, with tests green between steps:

  1. Look at everything the function uses, and decide whether it should move too.
  2. Copy the function to the target and adapt it: order.x becomes this.x.
  3. Run the static checks.
  4. Turn the source into a delegating function that calls the new one. Run the tests.
  5. Consider inlining the delegate: move each caller over, delete it, run the tests.

Move Field. The printed total needs a currency, and the currency sits on Invoice, although the prices it describes belong to Order. The mechanics use the same idea of two places existing for a moment:

  1. Encapsulate the field, so reads go through one accessor.
  2. Add the field to the target.
  3. Make the source accessor read from the target. Run the tests.
  4. Remove the source field. Run the tests.

With real data the field is a column, so the same dance happens in the database, and it is called expand/contract: see section 07 · expand/contract.

بالعامية

الـ feature envy هي function مهتمة بـ data object تاني أكتر من بتاعتها. calculateInvoiceTotal(order) عايشة في billing، بس بتقرا 6 fields من order ومفيش حاجة من billing. فأي رسم جديد على الـ order معناه تعديل في billing، والقاعدة متتجربش ولا تتستخدم من غيره. ومش محتاج تجادل، لأنك تقدر تعدّ.

الـ Move Function، خطوات Fowler، والـ tests خضرا بين كل خطوة:

  1. بص على كل حاجة الـ function بتستخدمها، وقرر هتتنقل معاها ولا لأ.
  2. انسخ الـ function للمكان الجديد وظبّطها: order.x تبقى this.x.
  3. شغّل الـ static checks.
  4. خلّي القديمة delegating function بتنادي الجديدة، وشغّل الـ tests.
  5. فكّر تعمل inline للـ delegate: انقل كل caller، امسحها، وشغّل الـ tests.

الـ Move Field. الإجمالي المطبوع محتاج currency، والـ currency قاعدة على Invoice، مع إن الأسعار اللي بتوصفها بتاعة Order. الخطوات بنفس فكرة إن فيه مكانين لفترة قصيرة:

  1. غلّف الـ field، بحيث كل القراية تعدّي من accessor واحد.
  2. ضيف الـ field في المكان الجديد.
  3. خلّي الـ accessor القديم يقرا من الجديد، وشغّل الـ tests.
  4. امسح الـ field القديم، وشغّل الـ tests.

ومع data حقيقية الـ field هو column، فنفس الرقصة بتحصل في الـ database، واسمها expand/contract: شوف درس expand/contract في القسم 07.

فين هستخدمه في شغلي؟ في الـ code review لما تلاقي utils/orderHelpers.ts كلها functions بتاخد order وتقرا منه 5 حاجات، قول "feature envy" وشغّل العدّ. انقل أكتر واحدة بتتغير لـ Order الأول. الغلطة الشائعة: تسيب الـ delegate القديمة "مؤقتًا" لسنين، فيبقى عندك طريقتين لنفس الحاجة. خطوة الـ inline جزء من الحركة، مش حاجة اختيارية بعدين.
Trade-off: not every envious function should move Moving everything onto Order grows a god object. Strategies are designed to read another object's data, and so are report builders and mappers. Move when the rule belongs to the data and changes with it; leave it when it belongs to a different reason to change, such as PDF layout for an invoice.
لو نقلت كل حاجة على Order هيكبر ويبقى god object. الـ strategies معمولة أصلًا عشان تقرا data object تاني، وكذلك الـ report builders والـ mappers. انقل لما القاعدة تخص الـ data وتتغير معاها؛ وسيبها لما يبقى ليها سبب تغيير تاني، زي شكل الـ PDF بتاع الفاتورة.

Step 2, Replace Primitive with Object. Give the data behaviour. Money from the shared service (after/src/shared/money.ts) holds minor units and a currency, and refuses to mix them. The same line that silently gave 15000 now throws where the mistake happens. The healthy results stay identical, which is what makes this a refactor on valid input.

// ده value object: immutable وبيتساوى بالقيمة، ودايمًا بالـ minor units
export class Money {
  readonly minor: number;
  readonly currency: string;

  private constructor(minor: number, currency: string) {
    this.minor = minor;
    this.currency = currency;
    Object.freeze(this);
  }

  static of(minor: number, currency: string): Money {
    if (!Number.isSafeInteger(minor)) throw new RangeError(`Money needs a safe integer of minor units, got ${minor}`);
    if (!/^[A-Z]{3}$/.test(currency)) throw new RangeError(`bad currency ${currency}`);
    return new Money(minor, currency);
  }

  add(other: Money): Money {
    if (other.currency !== this.currency) throw new TypeError(`cannot add ${other.currency} to ${this.currency}`);
    return new Money(this.minor + other.minor, this.currency);
  }

  times(qty: number): Money {
    return Money.of(this.minor * qty, this.currency);
  }

  // التقريب half-up هنا بس، عشان مفيش caller يخترع تقريب من عنده
  percent(pct: number): Money {
    return Money.of(Math.round((this.minor * pct) / 100), this.currency);
  }

  equals(other: Money): boolean {
    return this.minor === other.minor && this.currency === other.currency;
  }
}

export function invoiceSummaryBefore(lines: readonly Line[], vatPercent: number): string {

  for (const l of lines) subtotal += l.unitPriceCents * l.qty;
  const discount = subtotal > 100_000 ? Math.round(subtotal * 0.05) : 0;
  const taxable = subtotal - discount;
  const tax = Math.round((taxable * vatPercent) / 100);

}

Part 5 — Shotgun surgery vs divergent change 🟡 Intermediateالجزء 5 — الـ shotgun surgery قصاد الـ divergent change

English

These are opposite smells, and neither shows up in a single file:

  • Shotgun surgery: one change touches many files. One idea is smeared across the system. Fix by gathering it into one place.
  • Divergent change: one file changes for many unrelated reasons. Several ideas are stuck together. Fix by splitting along those reasons.

Both leave fingerprints in history, so detect them from there. The script below scripts two temp repos with isomorphic-git (the git executable is not run here), walks each commit against its parent, and prints files per commit for a feature, plus distinct reasons per file, taken from the commit scope in feat(scope):. // (1) كل commit هو رسالة وقايمة ملفات اتغيرت
async function buildRepo(name, commits) {
  const dir = path.join(here, name);
  fs.rmSync(dir, { recursive: true, force: true });
  fs.mkdirSync(dir, { recursive: true });
  await git.init({ fs, dir, defaultBranch: "main" });
  for (const [message, files] of commits) {
    for (const f of files) {
      const p = path.join(dir, f);
      fs.mkdirSync(path.dirname(p), { recursive: true });
      fs.appendFileSync(p, `// ${message}\n`);
      await git.add({ fs, dir, filepath: f });
    }
    clock += 3600;
    await git.commit({ fs, dir, message, author: { name: "Ahmed", email: "ahmed@example.com", timestamp: clock, timezoneOffset: 0 } });
  }
  return dir;
}

// (2) الملفات اللي اتغيرت في commit: قارن الـ tree بتاعه بالـ tree بتاع الأب
async function changedFiles(dir, oid, parent) {
  const trees = [git.TREE({ ref: oid }), ...(parent ? [git.TREE({ ref: parent })] : [])];
  const changed = await git.walk({
    fs, dir, trees,
    map: async (file, [a, b]) => {
      if (file === "." || (await a?.type()) === "tree") return undefined;
      return (await a?.oid()) === (await b?.oid()) ? undefined : file;
    },
  });
  return changed.flat(Infinity).filter(Boolean);
}

// (3) التحليل: الـ scope جوه الأقواس في الـ commit message هو سبب التغيير
async function analyze(dir) {
  const log = (await git.log({ fs, dir })).reverse();
  const perCommit = [];
  const reasons = new Map();
  for (const entry of log) {
    const message = entry.commit.message.trim();
    const scope = /^\w+\(([\w-]+)\)/.exec(message)?.[1] ?? "none";
    const files = await changedFiles(dir, entry.oid, entry.commit.parent[0]);
    perCommit.push({ message, count: files.length });
    for (const f of files) {
      if (!reasons.has(f)) reasons.set(f, new Set());
      reasons.get(f).add(scope);
    }
  }
  return { perCommit, reasons };
}

export function createCheckoutApp(pool: Pool, paymentsUrl: string): Express {
  const app = express();

  app.post("/checkout", async (req, res) => {
    const { userEmail, lines, coupon, rush, country } = req.body;
    if (!userEmail || !String(userEmail).includes("@")) {
      res.status(400).json({ error: "bad email" });
      return;
    }
    if (!Array.isArray(lines) || lines.length === 0) {
      res.status(400).json({ error: "no lines" });
      return;
    }

    let subtotal = 0;
    const priced = [];
    for (const l of lines) {
      const r = await pool.query("select price_cents, stock from products where sku = $1", [l.sku]);
      if (r.rowCount === 0) {
        res.status(404).json({ error: "unknown sku " + l.sku });
        return;
      }
      if (r.rows[0].stock < l.qty) {
        res.status(409).json({ error: "out of stock " + l.sku });
        return;
      }
      subtotal += r.rows[0].price_cents * l.qty;
      priced.push({ sku: l.sku, qty: l.qty, unit: r.rows[0].price_cents });
    }

    let discount = 0;
    if (coupon) {
      const c = await pool.query(
        "select percent, min_subtotal_cents, active, expires_at, country from coupons where code = $1",
        [coupon],
      );
      if (c.rowCount === 0) {
        res.status(422).json({ error: "unknown coupon " + coupon });
        return;
      }
      const row = c.rows[0];
      if (
        row.active &&
        subtotal >= row.min_subtotal_cents &&
        (row.expires_at === null || new Date(row.expires_at).getTime() > Date.now()) &&
        (row.country === null || row.country === country)
      ) {
        discount = Math.round((subtotal * row.percent) / 100);
      }
    }

    const taxable = subtotal - discount;
    const tax = Math.round(taxable * 0.14);

    let shipping = 5000;
    if (taxable > 100000) {
      shipping = 0;
    }
    if (rush) {
      shipping = shipping + 7500;
    }
    if (country !== "EG") {
      shipping = shipping + 20000;
    }
    const total = taxable + tax + shipping;

    const o = await pool.query(

    for (const p of priced) {
      await pool.query("insert into order_lines values ($1,$2,$3,$4)", [id, p.sku, p.qty, p.unit]);
      await pool.query("update products set stock = stock - $1 where sku = $2", [p.qty, p.sku]);
    }

    const pay = await fetch(paymentsUrl + "/charge", {
      method: "POST",
      headers: { "content-type": "application/json" },
      body: JSON.stringify({ orderId: id, amountCents: total }),
    });
    if (!pay.ok) {
      await pool.query("update orders set status = 'payment_failed' where id = $1", [id]);
      res.status(402).json({ error: "payment failed", id });
      return;
    }
    await pool.query("update orders set status = 'paid' where id = $1", [id]);

    await pool.query(

      [invoiceNumber, id, total],
    );

    console.log(`[email] to ${userEmail}: order ${id} confirmed, invoice ${invoiceNumber}, total ${total}`);
    res.status(201).json({
      id,
      status: "paid",
      invoice: invoiceNumber,
      subtotalCents: subtotal,
      discountCents: discount,
      taxCents: tax,
      shippingCents: shipping,
      totalCents: total,
    });

"إزاي تعمل refactor لحاجة مفيهاش tests؟" ← الأول أعمل شبكة أمان عند أبعد seam: characterization tests على HTTP أو CLI، بتسجّل ناتج النهارده بالـ bugs بتاعته. ولو مفيش حاجة ينفع أوصلها، أعمل أصغر تغيير أوتوماتيك يخلق seam، زي Extract Function من الـ editor. وبعدين refactor في commits صغيرة. ومببدأش أبدًا بـ rewrite. الطريقة كاملة في درس 09.
Interview question "Feature envy, divergent change, shotgun surgery: name the fix for each in one line." → Feature envy: Move Function to the data it wants. Divergent change: split by reason to change. Shotgun surgery: gather what changes together. All three are the same principle, cohesion: keep what changes together in one place (lesson 02).
"الـ feature envy والـ divergent change والـ shotgun surgery: قول حل كل واحد في سطر." ← الـ feature envy: انقل الـ function للـ data اللي عايزاها. الـ divergent change: قسّم حسب سبب التغيير. الـ shotgun surgery: جمّع اللي بيتغير مع بعض. والتلاتة نفس المبدأ، الـ cohesion: اللي بيتغير مع بعض يعيش مع بعض (درس 02).

Common mistakes · غلطات شائعة

❌ The delegate stays forever 
// اتساب "مؤقتًا" من 3 سنين، ودلوقتي فيه طريقتين
class BillingService {
  calculateInvoiceTotal(order: Order): number {
    return order.invoiceTotal();
  }
}
✅ Finish the move 
// انقل كل caller وامسح القديمة في نفس الـ PR أو اللي بعده
const label = `${invoice.number}: ${order.invoiceTotal()}`;
بالعامية

❌ الـ delegating function مرحلة مؤقتة في الحركة. لو فضلت، الناس هتستخدم الطريقتين، والجديد هيفتكر إن فيه فرق بينهم. ✅ خلّص الـ Move Function: انقل الـ callers وامسح القديمة. ولو الـ callers كتير، خلّيها @deprecated مع تاريخ مسح.

❌ Value object goes to JSON as {} 
// الـ ⁦#value⁩ مبيتعملوش serialize
res.json({ customer: Email.parse("sara@example.com") });
// {"customer":{}}
✅ Say how it serializes 
// الـ JSON.stringify بينادي toJSON لوحده
class Email {
  // بقية الـ class زي ما هي
  toJSON(): string { return this.#value; }
}
// {"customer":"sara@example.com"}
بالعامية

❌ الـ #private field مش بيظهر في JSON.stringify، فالـ API بيرجّع {} والـ queue بتشيل رسالة فاضية، ومن غير أي error. ✅ ضيف toJSON() بترجّع الـ primitive. والأحسن كمان: حوّل صراحةً لـ DTO عند الحد، زي اللي في درس الـ patterns في TypeScript.

❌ Classes for one switch 
// 4 classes و interface لـ switch بيتقرا في مكان واحد
class PaidLabel implements StatusLabel { text() { return "Paid"; } }
class FailedLabel implements StatusLabel { text() { return "Failed"; } }
const label = LABELS[order.status].text();
✅ One table or one switch 
// الـ Record بيمسك النوع الناقص وقت الـ compile
const LABEL: Record<Status, string> = { paid: "Paid", failed: "Failed" };
const label = LABEL[order.status];
بالعامية

❌ الـ Replace Conditional with Polymorphism علاج للـ switch المتكرر. لو الـ switch واحد ومن غير سلوك، إنت بتضيف classes لحاجة بسيطة، وده speculative generality جديد. ✅ جدول Record بيدّيك نفس الحماية في سطر واحد.

❌ Refactor and new rule together 
// بعد الـ extract اتضاف شرط جديد في نفس الـ commit
const couponApplies = (c: CouponRow, s: Money, country: string) =>
  c.active && s.minor >= c.min_subtotal_cents
    && !isExpired(c) && coversCountry(c, country)
    && !c.first_order_only;
✅ Refactor, then a new commit 
// الـ commit ده نقل بس، والـ pins مش بتتغير
const couponApplies = (c: CouponRow, s: Money, country: string) =>
  c.active && s.minor >= c.min_subtotal_cents
    && !isExpired(c) && coversCountry(c, country);
// والشرط الجديد و test بتاعه في commit لوحده بعده
بالعامية

❌ لما الشرط الجديد يدخل مع الـ extract، الـ reviewer مش هيشوفه جوه النقل، والـ bisect هيقف على commit كبير. ✅ الـ commit الأول نقل بس والـ pins زي ما هي، والتاني فيه القاعدة الجديدة مع الـ test بتاعها. (first_order_only هنا مثال مش في الـ schema اللي شغلنا عليه.)

Cheat sheet · الخلاصة

  • Feature envy → Move Function: copy, delegate, test, inline the delegate. Move Field: encapsulate, add to target, read from target, remove. In a DB that is expand/contract.
  • Data clumps → Introduce Parameter Object cleans the signature only. Primitive obsession → Replace Primitive with Object adds the rules (Money.add throws on EGP + USD).
  • Value object vs branded type: rules and methods vs zero runtime. #private fields serialize to {}; add toJSON.
  • Decompose Conditional: predicates named after the rule. Check with a grid.
  • Replace Conditional with Polymorphism when a switch repeats and types grow. One switch with never, or a Record, is often better. default: on a union hides new cases.
  • Replace Temp with Query only for pure, cheap calculations. A temp holding an await stays a temp.
  • Extract Class when fields change together; Remove Middle Man when more than half the methods only forward. Ask what the class decides.
  • Shotgun surgery: one change, many files → gather. Divergent change: one file, many reasons → split. Both show in history, not in code.
  • Speculative generality: delete it; unchanged tests prove it was safe. Inappropriate intimacy: module API, then a DB role that enforces it.
  • Session order: mechanical and safest first, data-shape changes after, delegates removed at the end. Same pins throughout.
  • Stop when the change is easy, the metrics flatten, or the next step needs a design decision.
  • Editor refactors are safe only where types can see: any, SQL and JSON keys escape.
بالعامية
  • الـ feature envy ← Move Function: انسخ، خلّي القديمة delegate، جرّب، اعمل inline للـ delegate. الـ Move Field: غلّف، ضيف في الجديد، اقرا من الجديد، امسح. وفي الـ DB ده expand/contract.
  • الـ data clumps ← الـ Introduce Parameter Object بينضّف الـ signature بس. الـ primitive obsession ← الـ Replace Primitive with Object بيضيف القواعد (Money.add بيرمي error في EGP + USD).
  • الـ value object قصاد الـ branded type: قواعد و methods قصاد صفر تكلفة runtime. والـ #private بيتحول لـ {} في JSON، فضيف toJSON.
  • الـ Decompose Conditional: predicates باسم القاعدة، واتأكد بـ grid.
  • الـ Replace Conditional with Polymorphism لما الـ switch يتكرر والأنواع تزيد. و switch واحد مع never أو Record غالبًا أحسن. والـ default: على union بيخبّي الحالات الجديدة.
  • الـ Replace Temp with Query للحسابات الـ pure والرخيصة بس. والـ temp اللي شايل await يفضل temp.
  • الـ Extract Class لما الـ fields تتغير مع بعض؛ والـ Remove Middle Man لما أكتر من نص الـ methods تمرّر بس. اسأل الـ class بيقرر إيه.
  • الـ shotgun surgery: تغيير واحد وملفات كتير ← جمّع. الـ divergent change: ملف واحد وأسباب كتير ← قسّم. والاتنين بيبانوا في الـ history، مش في الكود.
  • الـ speculative generality: امسحها، والـ tests اللي متغيرتش بتثبت إنه آمن. الـ inappropriate intimacy: module API، وبعدين DB role بيفرضها.
  • ترتيب الـ session: الميكانيكي والأأمن الأول، وتغييرات شكل الـ data بعده، والـ delegates تتشال في الآخر. ونفس الـ pins طول الوقت.
  • اقف لما التغيير يبقى سهل، أو الأرقام تثبت، أو الخطوة الجاية تحتاج قرار design.
  • الـ refactors بتاعة الـ editor آمنة بس في اللي الـ types شايفاه: الـ any و SQL و JSON keys بيفلتوا.
