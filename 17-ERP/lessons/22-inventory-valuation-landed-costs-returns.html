Why this matters · ليه ده مهم

English

Sell the same six routers for the same price and your gross profit is 1100 or 900, depending on one setting. Inventory valuation is where the warehouse and the accounts meet, and it is also where they disagree. If you build ERP integrations you will be asked why the stock report and the balance sheet differ by 6300. This lesson builds a costing engine in TypeScript, matches it against real Odoo 20, shows what this version really posts (which isn't what most articles say), and ends with the reconciliation script an accountant runs at month end.

Part 1 — Why valuation decides profit 🟡 Intermediateالجزء 1 — ليه الـ valuation بيحدد الربح

English

Stock is an asset. When you sell it, its cost becomes an expense called cost of goods sold (COGS). Lesson 2 covers the accounts. The catch is that identical units are bought at different prices, so you need a rule for which cost leaves first. The rule changes COGS, so it changes reported profit, tax and the value of what remains.

FIFO (first in, first out) keeps layers and consumes the oldest. AVCO (average cost) keeps one running total and divides. Standard uses a fixed cost set in advance. LIFO isn't offered in Odoo and IAS 2 doesn't allow it.

The engine below works in integer minor units, as lesson 4 recommends, and asserts three invariants after every event: no negative units, no negative value, and value out plus value on hand equals value in. AVCO needs care: dividing can leave a fraction, so each delivery rounds and takes its share from the running total, and the last unit takes whatever remains. That keeps the third invariant exact.

  receipts:  5 @ 100   then   5 @ 200          deliver 6

  FIFO   [ 100 100 100 100 100 ][ 200 200 200 200 200 ]
           ^^^^^^^ out 500 ^^^^^  ^out 200   left 4 @ 200 = 800
           COGS = 700

  AVCO   [ 150 150 150 150 150   150 150 150 150 150 ]
           ^^^^^^^^^ out 6 x 150 ^^^^^^^^^   left 4 @ 150 = 600
           COGS = 900
نفس الاستلامين ونفس التسليم. في الـ FIFO بيخرج الأقدم: 5 بـ 100 ووحدة بـ 200، يعني التكلفة 700 والباقي 4 بـ 200 = 800. في الـ AVCO كل وحدة بـ 150: التكلفة 900 والباقي 600. في الحالتين 700 + 800 = 900 + 600 = 1500، وده اللي دخل.
// تشغيل: node src/valuation.ts
// الفلوس هنا integers بالـ ⁦minor unit (⁩قرش)، عشان الجمع يبقى مظبوط من غير float
type Move =
  | { kind: "receipt"; qty: number; unitCost: number }
  | { kind: "delivery"; qty: number };

interface CostMethod {
  readonly units: number;
  readonly value: number;
  receive(qty: number, unitCost: number): void;
  // بترجع تكلفة الكمية اللي خرجت، وبتنقصها من المخزن
  deliver(qty: number): number;
}

class Fifo implements CostMethod {
  private layers: { qty: number; unitCost: number }[] = [];
  get units() { return this.layers.reduce((s, l) => s + l.qty, 0); }
  get value() { return this.layers.reduce((s, l) => s + l.qty * l.unitCost, 0); }
  receive(qty: number, unitCost: number) { this.layers.push({ qty, unitCost }); }
  deliver(qty: number) {
    let left = qty;
    let cost = 0;
    while (left > 0) {
      // أقدم layer هي اللي بتخرج الأول
      const layer = this.layers[0]!;
      const take = Math.min(left, layer.qty);
      cost += take * layer.unitCost;
      layer.qty -= take;
      left -= take;
      if (layer.qty === 0) this.layers.shift();
    }
    return cost;
  }
}

class Avco implements CostMethod {
  units = 0;
  value = 0;
  receive(qty: number, unitCost: number) { this.units += qty; this.value += qty * unitCost; }
  deliver(qty: number) {
    // لو خرج كل اللي في المخزن، خد الـ value كله عشان متفضلش قروش يتيمة من التقريب
    const cost = qty === this.units ? this.value : Math.round((this.value * qty) / this.units);
    this.units -= qty;
    this.value -= cost;
    return cost;
  }
}

function run(method: CostMethod, moves: Move[]) {
  let valueIn = 0;
  let valueOut = 0;
  for (const m of moves) {
    if (m.kind === "receipt") {
      method.receive(m.qty, m.unitCost);
      valueIn += m.qty * m.unitCost;
    } else {
      // القاعدة الأولى: مفيش صرف بكمية مش موجودة
      if (m.qty > method.units) throw new Error(`short stock: need ${m.qty}, have ${method.units}`);
      valueOut += method.deliver(m.qty);
    }
    // القواعد التانية: مفيش سالب، واللي دخل بيساوي اللي خرج زائد اللي فاضل
    if (method.units < 0 || method.value < 0) throw new Error("negative stock");
    if (valueOut + method.value !== valueIn) throw new Error("value leaked");
  }
  return { valueIn, valueOut, units: method.units, onHand: method.value };
}

const moves: Move[] = [
  { kind: "receipt", qty: 5, unitCost: 10_000 },
  { kind: "receipt", qty: 5, unitCost: 20_000 },
  { kind: "delivery", qty: 6 },
];
const egp = (minor: number) => minor / 100;
const revenue = 6 * 30_000;

for (const [name, method] of [["FIFO", new Fifo()], ["AVCO", new Avco()]] as const) {
  const r = run(method, moves);
  console.log(name, {
    cogs: egp(r.valueOut),
    onHand: egp(r.onHand),
    unitsLeft: r.units,
    grossProfit: egp(revenue - r.valueOut),
  });
}

بالعامية

المخزون أصل. لما تبيعه، تكلفته بتبقى مصروف اسمه تكلفة البضاعة المباعة (COGS). الدرس 2 بيغطي الحسابات. المشكلة إن الوحدات الشبه بعض بتتشرى بأسعار مختلفة، فمحتاج قاعدة تقول أنهي تكلفة تخرج الأول. القاعدة دي بتغير الـ COGS، يعني بتغير الربح والضريبة وقيمة اللي فاضل.

FIFO (أول داخل أول خارج) بيحتفظ بـ layers وبيستهلك الأقدم. AVCO (متوسط التكلفة) بيحتفظ بإجمالي واحد وبيقسم. Standard بيستخدم تكلفة ثابتة محددة مسبقًا. الـ LIFO مش موجود في Odoo وIAS 2 مش بيسمح بيه.

الـ engine فوق شغال بـ integers بالـ minor unit زي ما الدرس 4 بيقول، وبيعمل assert على 3 invariants بعد كل حدث: مفيش وحدات سالبة، ومفيش قيمة سالبة، واللي خرج زائد اللي فاضل يساوي اللي دخل. الـ AVCO محتاج انتباه: القسمة ممكن تسيب كسر، فكل تسليم بيقرّب وبياخد نصيبه من الإجمالي، وآخر وحدة بتاخد اللي فاضل. وكده الـ invariant التالت يفضل مظبوط.

فين هستخدمه في شغلي؟ لو بتعمل dashboard لربح كل منتج في متجر Node وPostgres: لو ضربت الكمية في آخر سعر شراء، الربح هيبقى غلط لما الأسعار تتغير، وده طبيعي في مصر مع تغير سعر الصرف. احفظ حركات الاستلام واحسب التكلفة بـ engine زي ده. والغلطة الشائعة: تستخدم float وتلاقي value ضايع بقروش كل شهر.

Part 2 — FIFO and AVCO on real Odoo 🔴 Advancedالجزء 2 — الـ FIFO والـ AVCO على Odoo حقيقي

English

The cost method is property_cost_method on product.category, with the values standard, average and fifo. The script runs the same flow for each: receive 5 at 100, receive 5 at 200, deliver 6 at a selling price of 300. FIFO gives delivery value −700 with 800 left at 200 each. AVCO gives −900 with 600 left at 150 each. Those are exactly the numbers from the TypeScript engine, and the method changes reported profit by 200 on the same sale.

Standard cost values every unit at a fixed price, here 150, whatever the vendor charged. Manufacturers use it because a bill of materials needs a stable planning cost, and differences from it are information: they show purchasing or production drifting from plan. Those differences have to go somewhere. Odoo posts them to a price difference account, but the source only does so when anglo_saxon_accounting is on. The Egyptian company has it off, so a bill at 100 debits stock 500 while the stock report says 750. With the flag on, an extra debit of 250 to stock and credit of 250 to the difference account line them up.

طريقة التكلفة هي property_cost_method على product.category، وقيمها standard وaverage وfifo. السكريبت بيشغّل نفس الدورة لكل واحدة: استلام 5 بـ 100، واستلام 5 بـ 200، وتسليم 6 بسعر بيع 300. الـ FIFO بيدي قيمة تسليم −700 و800 باقيين بـ 200 للوحدة. الـ AVCO بيدي −900 و600 باقيين بـ 150 للوحدة. دي نفس أرقام الـ engine بالظبط، والـ method بيغير الربح 200 على نفس البيعة.

فين هستخدمه في شغلي؟ في مشروع Odoo لشركة استيراد: الـ FIFO أو الـ AVCO قرار لازم يتاخد مع المحاسب في أول يوم، لأن تغييره بعدين بيعيد حساب القيم. وفي تقرير الربح اقرا move.value الفعلي. والغلطة الشائعة: تشغّل Standard لتاجر والفروق تتراكم في حساب محدش بيبص عليه.
Trade-off: FIFO or AVCO? In a period of rising prices FIFO reports lower cost and higher profit, and leaves stock valued near current prices. AVCO smooths the swings and needs one number per product instead of layers. FIFO shows more detail and depends on the order of events, so correcting a receipt cost re-costs deliveries already made, as Part 5 shows.
لما الأسعار بتزيد، الـ FIFO بيطلّع تكلفة أقل وربح أعلى، وبيسيب المخزون قريب من الأسعار الحالية. الـ AVCO بيهدّي التقلبات ومحتاج رقم واحد للمنتج بدل layers. الـ FIFO تفاصيله أكتر وبيعتمد على ترتيب الأحداث، فتصحيح تكلفة استلام بيعيد تكلفة تسليمات حصلت خلاص، زي ما الجزء 5 هيوريك.

Part 3 — What changed in Odoo 20 🔴 Advancedالجزء 3 — إيه اللي اتغير في Odoo 20

English

stock.valuation.layer is gone. Any older tutorial, report or SQL that reads stock_valuation_layer is wrong here. Value now lives directly on the move: stock.move has a stored value and computed remaining_qty and remaining_value. product.total_value and avg_cost are computed by replaying moves through _run_fifo, _run_avco or _run_standard, and they respect a to_date context for historic values.

product.value (stock_account/models/product_value.py) is a smaller thing than the old layers. Its docstring says it is "the history of manual update of a value": a changed standard price, a changed lot price or an edited move value. A normal FIFO flow creates zero rows.

Because total_value isn't stored, reading it across thousands of products is a computation, not a column read. Run such reports in a job rather than a page load. Valuation by lot is a per-product flag, lot_valuated: each lot then carries its own cost, so shipping the expensive lot takes its real cost and not the product's average.

Part 6 — Returns and scrap 🔴 Advancedالجزء 6 — المرتجعات والهالك

English

Odoo 20 has neither the stock.return.picking wizard nor the stock.scrap model. A return goes through picking._create_return(): it gives a draft transfer with zero demand, you set product_uom_qty, confirm and validate. A scrap is a stock.move with is_scrap=True and quantity set, finished with _action_scrap().

In perpetual mode the physical return posts nothing, as in Part 4, and comes back at its original cost of 100. The stock report rises and the books don't: a gap of 100. The credit note is the accounting event: it reverses income, VAT and COGS, debiting stock 100, and the gap closes. On a product with invoice_policy='delivery', qty_to_invoice goes to −1 and _create_invoices(final=True) builds the refund. With the default ordered-quantity policy it stays 0 and the call raises "No items are available to invoice".

Scrap has the same shape with a sharper edge. The value is −100, the quantity drops by 1, and no account.move is created, because the scrap location has no valuation_account_id. Nothing later will post it, so the stock account stays overstated until someone does. Set an account on the location and each later scrap posts debit expense, credit stock.

Part 7 — Reconcile stock to the books 🔴 Advancedالجزء 7 — مطابقة المخزون مع الدفاتر

English

Month end is one question: does the stock report equal the balance of the stock account? The script compares product.total_value with the sum of posted lines on the stock account, per product. account.move.line carries product_id, so the books can be split the same way as the stock.

A difference isn't automatically an error. Each row below has a different cause and a different response:

  • Clean Router, 0: bought with a bill, sold with an invoice.
  • Received Not Billed, +400: a timing difference. It clears when the bill arrives. Report it, don't correct it.
  • Switched Midstream, +6000: the category moved from periodic to perpetual after the bill had debited expense. The stock account never received the 6000. This is a real error, and it needs a reclassification entry.
  • Scrapped, −100: a real gap from Part 6. Post the write-off and configure the location.

After the correcting entry, the Switched row is 0 and the total drops from 6300 to 300, which is the 400 of goods awaiting a bill less the 100 of scrap. The same check is what proves opening stock after a migration: see lesson 29.

// تشغيل: node src/ex-return.ts
type Layer = { qty: number; unitCost: number };
type Shipment = { layers: Layer[] };

class Fifo {
  private layers: Layer[] = [];
  get units() { return this.layers.reduce((s, l) => s + l.qty, 0); }
  get value() { return this.layers.reduce((s, l) => s + l.qty * l.unitCost, 0); }
  receive(qty: number, unitCost: number) { this.layers.push({ qty, unitCost }); }
  deliver(qty: number): Shipment {
    if (qty > this.units) throw new Error("short stock");
    const taken: Layer[] = [];
    let left = qty;
    while (left > 0) {
      const layer = this.layers[0]!;
      const take = Math.min(left, layer.qty);
      taken.push({ qty: take, unitCost: layer.unitCost });
      layer.qty -= take;
      left -= take;
      if (layer.qty === 0) this.layers.shift();
    }
    return { layers: taken };
  }
  // المرتجع بيرجع بتكلفة الشحنة الأصلية، مش بالتكلفة الحالية
  returnFrom(shipment: Shipment, qty: number): number {
    let left = qty;
    let value = 0;
    for (const part of [...shipment.layers].reverse()) {
      if (left === 0) break;
      const back = Math.min(left, part.qty);
      this.layers.unshift({ qty: back, unitCost: part.unitCost });
      part.qty -= back;
      left -= back;
      value += back * part.unitCost;
    }
    if (left > 0) throw new Error("returning more than was shipped");
    return value;
  }
}

Cheat sheet · الخلاصة

  • Same sale: FIFO COGS 700, AVCO COGS 900. The method moves profit.
  • Invariant: value out + value on hand = value in. Use integers.
  • Cost method: property_cost_method is standard, average or fifo.
  • stock.valuation.layer is gone: read stock.move.value and product.total_value, with to_date for history.
  • product.value records manual value changes only.
  • Periodic: bill debits expense, closing adjusts stock. Perpetual: bill debits stock, invoice posts COGS.
  • Receipt and delivery post nothing in either mode unless the location has valuation_account_id.
  • Price differences on standard cost need anglo_saxon_accounting.
  • Landed cost: unsold share enters stock, sold share stays in expense. Check that weights and volumes aren't zero.
  • Returns: _create_return(); scrap: is_scrap + _action_scrap(). Always pair a return with a credit note.
  • Month end: compare per product, and classify each difference as timing, configuration or error.
بالعامية
  • نفس البيعة: الـ FIFO تكلفتها 700 والـ AVCO تكلفتها 900. الطريقة بتحرك الربح.
  • الـ invariant: اللي خرج + اللي فاضل = اللي دخل. واستخدم integers.
  • طريقة التكلفة: property_cost_method قيمها standard أو average أو fifo.
  • stock.valuation.layer اتشال: اقرا stock.move.value وproduct.total_value، وto_date للتاريخ.
  • product.value بيسجل التعديلات اليدوية بس.
  • الـ periodic: الفاتورة مدين مصروف والإقفال بيظبط المخزون. الـ perpetual: الفاتورة مدين مخزون وفاتورة العميل بتقيد COGS.
  • الاستلام والتسليم مبيقيدوش حاجة في الوضعين، إلا لو الـ location عليه valuation_account_id.
  • فروق الأسعار في الـ standard محتاجة anglo_saxon_accounting.
  • الـ landed cost: نصيب اللي ماتباعش بيدخل المخزون، ونصيب المباع بيفضل مصروف. واتأكد إن الأوزان والأحجام مش صفر.
  • المرتجع: _create_return()، والهالك: is_scrap و_action_scrap(). واربط المرتجع بـ credit note دايمًا.
  • آخر الشهر: قارن لكل منتج، وصنّف كل فرق توقيت أو إعدادات أو غلطة.
