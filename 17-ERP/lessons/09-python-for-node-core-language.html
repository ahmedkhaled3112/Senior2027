Why this matters · ليه ده مهم

English

Odoo is written in Python, so every module, override and test you write in the rest of this section is Python. You already know how to program, so this lesson doesn't teach programming: it maps what you know from TypeScript onto Python and spends its time on the places where the same-looking code behaves differently. Those differences are where a Node developer loses hours: an empty list that is falsy, a default argument that survives between calls, a super() that doesn't call the parent you read in the class header.

Everything here was run on Python 3.14.5, the interpreter Odoo 20 uses on this machine. Wherever a Python feature explains something in Odoo, you'll see the real Odoo line or a real run.

بالعامية

Odoo مكتوب بـ Python، فكل module وكل override وكل test هتكتبه في باقي القسم ده هيبقى Python. إنت أصلًا عارف تبرمج، فالدرس مش هيعلّمك برمجة: هو بيوصّل اللي تعرفه من TypeScript بـ Python، وبيركّز على الأماكن اللي الكود فيها شكله واحد وسلوكه مختلف. الفروق دي هي اللي بتضيّع ساعات من مبرمج Node: list فاضية بتطلع falsy، و default argument بيفضل عايش بين الـ calls، و super() مش بينادي الـ parent اللي إنت شايفه في تعريف الـ class.

كل حاجة هنا اتشغلت على Python 3.14.5، وده الـ interpreter اللي Odoo 20 شغال بيه على الجهاز ده. وأي ميزة في Python بتفسّر حاجة في Odoo، هتشوف معاها السطر الحقيقي من Odoo أو تشغيل حقيقي.

Part 1 — Syntax and types 🟢 Basicالجزء 1 — الـ syntax والـ types

English

Python uses indentation instead of braces: the block is whatever is indented under the line ending in :. There are no semicolons. Names are snake_case by convention, booleans are True and False, and "no value" is one single thing, None, instead of JavaScript's two (null and undefined). An f-string is a template literal. A keyword argument is passed by name at the call site, so you don't need an options object, and a bare * in the signature forces everything after it to be passed by name.

Here is the same function in both languages, so you can compare them line by line.

type Line = { product: string; qty: number; unitCents: number };
type Options = { discountPct?: number; currency?: string };

function invoiceTotal(lines: Line[], options: Options = {}): string {
  const { discountPct = 0, currency = "EGP" } = options;
  // الليستة الفاضية truthy في JS، فلازم تبص على length
  if (lines.length === 0) return `empty invoice (${currency})`;

  let totalCents = 0;
  for (const line of lines) {
    totalCents += line.qty * line.unitCents;
  }

  const netCents = Math.floor((totalCents * (100 - discountPct)) / 100);
  return `${(netCents / 100).toFixed(2)} ${currency}`;
}

const lines: Line[] = [{ product: "Router", qty: 2, unitCents: 150_000 }];

console.log(invoiceTotal(lines, { discountPct: 10 }));
// → 2700.00 EGP
console.log(invoiceTotal([], { currency: "USD" }));
// → empty invoice (USD)

# مفيش أقواس ومفيش ; والـ indentation هو اللي بيحدد الـ block
def invoice_total(lines: list[dict], discount_pct: int = 0, currency: str = "EGP") -> str:
    # الليستة الفاضية falsy في Python، فـ "not lines" معناها مفيش سطور
    if not lines:
        return f"empty invoice ({currency})"

    total_cents = 0
    for line in lines:
        total_cents += line["qty"] * line["unit_cents"]

    # العلامة // هنا integer division، مش comment
    net_cents = total_cents * (100 - discount_pct) // 100
    # الـ f-string زي الـ template literal، و :.2f بتحدد رقمين عشريين
    return f"{net_cents / 100:.2f} {currency}"


lines = [{"product": "Router", "qty": 2, "unit_cents": 150_000}]

# الـ keyword argument بيتبعت بالاسم، من غير object زي TypeScript
print(invoice_total(lines, discount_pct=10))
# → 2700.00 EGP
print(invoice_total([], currency="USD"))
# → empty invoice (USD)
English

Truthiness is where the two languages disagree. 0, "" and "no value" are falsy in both. But an empty collection is falsy in Python and truthy in JavaScript: [] and {} are truthy in JS, so if (lines) passes for an empty array, while if lines: in Python doesn't. This is the idiom you'll read everywhere in Odoo, because an empty recordset is falsy too. NaN goes the other way: falsy in JS, truthy in Python. and and or return one of their operands, like && and ||, but Python has no ??, so when 0 is a valid value you must test is not None.

English

Equality. == compares values and is compares identity: "is this the very same object?". Python has no === and needs none, because == doesn't coerce between a string and a number. Use is only for None, True and False. A missing dictionary key raises KeyError rather than giving you undefined, and dict.get is the non-raising form. Python also doesn't coerce in arithmetic: "Total: " + 42 raises TypeError. / always gives a float, // floors (even for negatives), and integers have no size limit.

paid_lines = ["router", "switch"]
draft_lines = ["router", "switch"]

# العلامة == بتقارن المحتوى
print(paid_lines == draft_lines)
# → True
# الكلمة is بتقارن الهوية: نفس الـ object في الـ memory ولا لأ
print(paid_lines is draft_lines)
# → False

first_id = int("1000")
second_id = int("1000")
print(first_id == second_id, first_id is second_id)
# → True False

# مفيش === في Python، والـ == مش بيعمل coercion بين string و int
print(1 == "1", 1 == 1.0, True == 1)
# → False True True

# القاعدة: None بس هو اللي بيتقارن بـ is

# → True

English

The mutable default trap. A default value is evaluated once, when def runs, and stored on the function object. If that value is a list, every call that omits the argument shares the same list. In JavaScript the default expression runs on every call, so this bug has no equivalent there, which is exactly why Node developers walk into it.

# ❌ القيمة الافتراضية بتتحسب مرة واحدة وقت تعريف الـ function
def add(line, lines=[]):
    lines.append(line)
    return lines


first_invoice = add("router")
second_invoice = add("switch")
print(first_invoice)
# → ['router', 'switch']
print(first_invoice is second_invoice)
# → True
print(add.__defaults__)
# → (['router', 'switch'],)


# ✅ الحل: None كعلامة، والليستة الجديدة بتتعمل جوه كل call
def add_fixed(line, lines=None):
    if lines is None:
        lines = []
    lines.append(line)
    return lines


print(add_fixed("router"))
# → ['router']
print(add_fixed("switch"))
# → ['switch']

// في JS الـ default بيتحسب مع كل call، فالمشكلة دي مش موجودة
function add(line: string, lines: string[] = []): string[] {
  lines.push(line);
  return lines;
}

console.log(add("router"));
// → [ 'router' ]
console.log(add("switch"));
// → [ 'switch' ]
بالعامية

Python بيستخدم الـ indentation بدل الأقواس: الـ block هو اللي متزق تحت السطر اللي بينتهي بـ :. مفيش semicolons. الأسماء snake_case بالعُرف، والـ booleans True و False بحرف كبير، و"مفيش قيمة" حاجة واحدة بس اسمها None بدل الاتنين بتوع JS (null و undefined). الـ f-string هو الـ template literal. والـ keyword argument بيتبعت بالاسم وقت الـ call، فمش محتاج options object.

الـ truthiness هو مكان الخلاف. الـ 0 والنص الفاضي و"مفيش قيمة" falsy في الاتنين. بس الـ collection الفاضية falsy في Python و truthy في JS: يعني if (lines) بتعدّي مع array فاضية، و if lines: في Python مش بتعدّي. ده الأسلوب اللي هتقراه في كل حتة في Odoo، لأن الـ recordset الفاضي falsy برضو. والـ NaN بالعكس: falsy في JS و truthy في Python. وخد بالك إن and و or بيرجّعوا القيمة نفسها زي && و ||، وإن Python مفيهاش ??: لو الـ 0 قيمة صحيحة عندك، discount or 15 هتبوّظها، فاسأل بـ is not None.

المساواة. == بتقارن القيم و is بتقارن الهوية: "ده نفس الـ object بالظبط؟". مفيش === ومش محتاجينها، لأن == مش بتعمل coercion بين نص ورقم. استخدم is مع None و True و False بس. الـ key الناقص في dict بيرمي KeyError بدل ما يديك undefined، و dict.get هي النسخة اللي مش بترمي. وكمان مفيش coercion في الحساب: "Total: " + 42 بترمي TypeError، والقسمة / دايمًا float، و // بتقرّب لتحت حتى مع السالب (-7 // 2 بتطلع -4)، والـ int مالوش حد أقصى، مش زي Number اللي بيفقد الدقة بعد 2^53. والنجمة لوحدها في تعريف الـ function معناها إن اللي بعدها لازم يتبعت بالاسم.

فخ الـ mutable default. الـ default بيتحسب مرة واحدة بس، لما سطر def يتنفذ، وبيتخزن على الـ function نفسها. لو القيمة list، كل call بتسيب الـ argument بتشارك نفس الليستة: شوف first_invoice طلعت فيها سطر الفاتورة التانية كمان. في JS الـ default بيتحسب مع كل call، فالـ bug ده ملوش مقابل، وعشان كده مبرمج Node بيقع فيه. الحل: None كعلامة وتعمل الليستة جوه الـ function.

فين هستخدمه في شغلي؟ لما تكتب method في Odoo بتاخد vals=None أو domain=None، مش vals={}: لو حطيت {} كـ default وعدّلت فيه، الـ worker هيفضل شايل قيم request قديم لـ request جديد، وتلاقي عميل بياخد خصم عميل تاني، ودي من أصعب الـ bugs لأنها بتظهر تحت load بس. ولما تراجع كود في PR وتشوف if not records: افهمها "مفيش records"، ومتترجمهاش في دماغك لـ JS.
Interview question "What's wrong with def add(line, lines=[])?" → The default is created once at definition time and lives on the function object, so calls that omit lines share one list. Use lines=None and create the list inside.
"إيه الغلط في def add(line, lines=[])؟" ← الـ default بيتعمل مرة واحدة وقت التعريف وبيعيش على الـ function object، فكل الـ calls اللي مش بتبعت lines بتشارك نفس الليستة. استخدم lines=None واعمل الليستة جوه.

Part 2 — venv and pip versus npm 🟢 Basicالجزء 2 — الـ venv والـ pip مقارنة بـ npm

English

npm install puts packages in a node_modules folder next to your project, and require walks up the folders to find them, so isolation comes for free. Python has no such default. import searches the list in sys.path, and without a virtual environment that list points at one shared site-packages for the whole interpreter. Two projects that need different versions of a library will fight. A venv is the fix: a folder with its own python.exe and its own empty site-packages. Think of it as creating your node_modules by hand, then telling the shell to use it.

"Activating" a venv only prepends its Scripts folder to PATH. You can skip activation completely by calling .venv/Scripts/python.exe directly, which is what scripts and CI should do. Note the Windows path: Scripts, where Linux has bin.

requirements.txt plays the role of package.json and the lockfile at once, and does neither job fully: it's a flat list, and it only pins what you pinned. pip freeze writes the exact installed versions, which is the closest thing to a lockfile in plain pip. pip 26 also has an experimental pip lock command that writes the standard pylock.toml, and tools like uv and Poetry give you real lockfiles (none of those were run here).

بالعامية

npm install بيحط الـ packages في node_modules جنب مشروعك، و require بيطلع في الفولدرات يدوّر، فالعزل ببلاش (شوف درس الـ modules في قسم Node). Python مفيهاش ده by default. الـ import بيدوّر في sys.path، ومن غير virtual environment الليستة دي بتشاور على site-packages واحدة مشتركة للـ interpreter كله، فمشروعين محتاجين نسختين مختلفتين من library هيتخانقوا. الـ venv هو الحل: فولدر فيه python.exe خاص بيه و site-packages فاضية خاصة بيه. اعتبره إنك بتعمل الـ node_modules بإيدك وبتقول للـ shell يستخدمها.

الـ "activate" كل اللي بيعمله إنه بيحط فولدر Scripts في أول الـ PATH. تقدر تستغنى عنه خالص وتنادي .venv/Scripts/python.exe مباشرةً، وده اللي الـ scripts والـ CI المفروض يعملوه. وخد بالك: على Windows اسمه Scripts، وعلى Linux اسمه bin.

requirements.txt بيلعب دور package.json والـ lockfile مع بعض، ومش بيعمل الاتنين كويس: ليستة مسطحة، وبيثبّت اللي إنت ثبّته بس. pip freeze بيكتب النسخ المثبتة بالظبط، ودي أقرب حاجة لـ lockfile في pip العادي. وكمان pip 26 فيه أمر experimental اسمه pip lock بيكتب ملف pylock.toml الـ standard، وأدوات زي uv و Poetry بتديك lockfile حقيقي (ولا واحدة منهم اتشغلت هنا). والجزء اللي بعد ; في ملف Odoo اسمه environment marker: pip بيقيّمه وبيثبّت السطر لو الشرط صح، و npm مفيهوش زيه في package.json غير os و cpu والـ optional dependencies.

فين هستخدمه في شغلي؟ لما تجيلك مشكلة "ModuleNotFoundError وأنا مثبّتها!" في Odoo، غالبًا إنت ثبّتها في Python غلط. أول سؤال: which python أو python -c "import sys; print(sys.executable)". وفي الـ Dockerfile أو الـ deploy script نادي /opt/odoo/venv/bin/python بالـ path الكامل بدل ما تعتمد على activate. والغلطة الشائعة إنك تعمل pip install من غير venv فتوسّخ الـ Python بتاع النظام.
Trade-off Pinning every version (==) makes builds reproducible, but you own the security updates. Odoo pins most lines, and leaves tzdata unpinned on purpose so that timezone rules stay current. Pin what can break your code, and leave out what is pure data.
تثبيت كل نسخة بـ == بيخلّي الـ build ثابت، بس بتبقى إنت مسؤول عن الـ security updates. Odoo بيثبّت أغلب الأسطر، وساب tzdata من غير تثبيت بقصد عشان قواعد الـ timezones تفضل محدّثة. ثبّت اللي ممكن يكسر كودك، وسيب اللي هو data بس.

Part 3 — Collections 🟢 Basicالجزء 3 — الـ collections

English

Python has four built-in collections and you'll use all of them daily. A dict keeps insertion order (guaranteed by the language since 3.7) and is the workhorse: Odoo passes values, contexts and search options around as dicts. A tuple is immutable and hashable if its items are, which makes it usable as a dict key. That gives Python something JavaScript can't do directly: a composite key compared by value. A Map in JS compares array keys by identity. Slices ([start:stop:step]) return new lists, unpacking is destructuring with * for the rest, dict.get gives a default instead of an exception, and sorted(key=...) takes a function that extracts the sort value and returns a new list.

Now a task you'll do constantly: group invoices by customer. There are three common ways. The plain dict is explicit. defaultdict removes the "does the key exist?" step and is the usual choice in Odoo's source (it appears on 13 lines of account_move.py alone). itertools.groupby looks like SQL's GROUP BY but is not: it only groups adjacent items, so unsorted input silently loses data.

from collections import defaultdict

Common mistake: a shallow copy of a nested dict. dict.copy() and list(x) copy one level only. The nested list is still shared, exactly like {...order} in JavaScript, and copy.deepcopy is the equivalent of structuredClone.

Part 4 — Comprehensions 🟢 Basicالجزء 4 — الـ comprehensions

English

A comprehension builds a collection in one expression. Read it as "value for item in source if condition": map is the part before for, filter is the if at the end. Square brackets give a list, curly braces with k: v give a dict, curly braces with one value give a set, and plain parentheses give a generator expression, which builds nothing up front (Part 7). There is no direct reduce: Python prefers sum, min, max, any and all applied to a generator expression.

const orderLines = [

الـ comprehension بيبني collection في expression واحد. اقراه كده: "القيمة لكل عنصر في المصدر لو الشرط". اللي قبل for هو الـ map، و if اللي في الآخر هو الـ filter. الأقواس المربعة بتدي list، والمعقوفة مع k: v بتدي dict، والمعقوفة بقيمة واحدة بتدي set، والأقواس العادية بتدي generator expression مش بيبني حاجة مقدمًا (الجزء 7). ومفيش reduce مباشر: Python بتفضّل sum و min و max و any و all على generator expression. وخد بالك من مكان الـ if: القيمة الشرطية ("tax" if ... else "no-tax") قبل for، وفلترة الصفوف بعد for.

Part 5 — Classes and inheritance 🟢 Basicالجزء 5 — الـ classes والوراثة

English

In Python self is an ordinary first parameter, written explicitly. invoice.get_net() is shorthand for Invoice.get_net(invoice), so there's no this binding problem like the one you know from JS. __init__ is the constructor. An attribute assigned in the class body is a class attribute, shared by all instances; an attribute assigned through self belongs to one instance. If a class attribute is a mutable list, every instance mutates the same list, which is the mutable default trap again in another form. Assigning through an instance creates a private copy that hides the class attribute without changing it.

Three decorators change how a method is called. @property makes it read like a field, @classmethod passes the class instead of the instance (the standard way to write alternative constructors, and it respects subclasses), and @staticmethod passes nothing: it's a plain function that lives in the class namespace.

English

Multiple inheritance and the MRO. TypeScript has single inheritance. Python allows several parents, and resolves "which method wins?" with the Method Resolution Order, a single linear list computed by the C3 algorithm and stored in __mro__. Here's the key sentence: super() doesn't mean "my parent". It means "the next class after me in the MRO of the object's actual type". The same Taxed.post code calls Audited when the object is an Invoice, and Document when it's a plain Taxed.

class Document:
    def post(self) -> list[str]:
        return ["Document"]


class Taxed(Document):
    def post(self) -> list[str]:
        # الـ super هنا مش معناها Document بالضرورة
        return ["Taxed"] + super().post()


class Audited(Document):
    def post(self) -> list[str]:
        return ["Audited"] + super().post()


class Invoice(Taxed, Audited):
    def post(self) -> list[str]:
        return ["Invoice"] + super().post()


# الترتيب الحقيقي بتاع البحث عن أي method
print([cls.__name__ for cls in Invoice.__mro__])
# → ['Invoice', 'Taxed', 'Audited', 'Document', 'object']

print(Invoice().post())
# → ['Invoice', 'Taxed', 'Audited', 'Document']

Part 6 — Dunder methods 🟢 Basicالجزء 6 — الـ dunder methods

English

"Dunder" means double underscore. These methods are how your objects plug into Python's syntax: a + b calls a.__add__(b), len(x) calls x.__len__(), if x: calls x.__bool__() (falling back to __len__), for i in x calls x.__iter__(), and y in x calls x.__contains__(y). TypeScript has no operator overloading, so a Money type there ends up as a.add(b), and [Symbol.iterator] is the only comparable protocol. In Python a domain type can feel like a built-in.

Three rules matter. Return NotImplemented, not False or an exception, when the other operand's type is unknown: Python then tries the other side and raises a proper TypeError if nothing works. __repr__ is what shows up in logs and the debugger, so make it unambiguous. And defining __eq__ without __hash__ sets __hash__ to None, so your objects stop working in sets and as dict keys.

from collections.abc import Iterator
from decimal import Decimal


class Money:
    def __init__(self, amount: str, currency: str = "EGP") -> None:
        self.amount = Decimal(amount)
        self.currency = currency

    # الـ repr هو اللي بيظهر في الـ logs والـ debugger
    def __repr__(self) -> str:
        return f"Money('{self.amount}', '{self.currency}')"

    # لو النوع مختلف بنرجّع NotImplemented، مش False ومش exception
    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Money):
            return NotImplemented
        return (self.amount, self.currency) == (other.amount, other.currency)

    # لو عرّفت __eq__ من غير __hash__ الـ class بيبقى unhashable
    def __hash__(self) -> int:
        return hash((self.amount, self.currency))

    def __add__(self, other: "Money") -> "Money":
        if not isinstance(other, Money):
            return NotImplemented
        if self.currency != other.currency:
            raise ValueError(f"cannot add {self.currency} to {other.currency}")
        return Money(str(self.amount + other.amount), self.currency)

    # الـ bool بتتنادى في if money
    def __bool__(self) -> bool:
        return self.amount != 0


class Lines:
    def __init__(self, items: list[Money] | None = None) -> None:
        self._items = list(items or [])

    def __repr__(self) -> str:
        return f"Lines({self._items!r})"

    def __len__(self) -> int:
        return len(self._items)

    def __iter__(self) -> Iterator[Money]:
        return iter(self._items)

Part 7 — Generators and iterators 🟢 Basicالجزء 7 — الـ generators والـ iterators

English

The protocol is the same idea as in JavaScript, with different names. An iterable has __iter__, which returns an iterator. An iterator has __next__, which returns the next value and raises StopIteration at the end (JS returns { value, done } instead of raising). A function containing yield becomes a generator function: calling it runs none of its body and returns a generator, which then runs up to the next yield each time you ask for a value. yield from yields everything from another iterable.

itertools is the toolbox. islice takes a slice of any iterator, including an endless one. batched (Python 3.12+) yields tuples of a fixed size, with a shorter last batch, and strict=True (3.13+) raises ValueError on an incomplete one.

        return self.current + 1

def write_sample() -> None:
    with CSV_PATH.open("w", newline="", encoding="utf-8") as handle:
        writer = csv.writer(handle)
        writer.writerow(["number", "customer_id", "total_cents"])
        for number in range(1, ROWS + 1):

# الطريقة الأولى: كل الصفوف في list قبل ما نجمع
def total_with_list() -> int:
    with CSV_PATH.open(newline="", encoding="utf-8") as handle:
        rows = list(csv.DictReader(handle))
    return sum(int(row["total_cents"]) for row in rows)


# الطريقة التانية: generator بيطلّع صف صف
def read_rows() -> Iterator[dict[str, str]]:
    with CSV_PATH.open(newline="", encoding="utf-8") as handle:
        yield from csv.DictReader(handle)


def total_with_generator() -> int:
    return sum(int(row["total_cents"]) for row in read_rows())


# الطريقة التالتة: batches، زي لما تعمل insert كل 1000 صف
def total_in_batches() -> tuple[int, int]:
    total = 0
    batch_count = 0
    for batch in batched(read_rows(), 1_000):
        total += sum(int(row["total_cents"]) for row in batch)
        batch_count += 1
    return total, batch_count

    _, peak = tracemalloc.get_traced_memory()
    tracemalloc.stop()
    print(f"{label:<10} result={result} peak={peak / 1_000_000:.2f} MB")

def split_every[T](n: int, iterable: Iterable[T], piece_maker=tuple):
    iterator = iter(iterable)
    piece = piece_maker(islice(iterator, n))
    while piece:
        yield piece
        piece = piece_maker(islice(iterator, n))

Solution · الحل 
from decimal import Decimal
from functools import total_ordering


@total_ordering
class Money:
    def __init__(self, amount: str, currency: str = "EGP") -> None:
        self.amount = Decimal(amount)
        self.currency = currency

    def __repr__(self) -> str:
        return f"Money('{self.amount}', '{self.currency}')"

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Money):
            return NotImplemented
        return (self.amount, self.currency) == (other.amount, other.currency)

    def __hash__(self) -> int:
        return hash((self.amount, self.currency))

    # الدالة دي كفاية، و total_ordering بيكمّل باقي المقارنات
    def __lt__(self, other: "Money") -> bool:
        if self.currency != other.currency:
            raise ValueError("cannot compare different currencies")
        return self.amount < other.amount

    def __sub__(self, other: "Money") -> "Money":
        if self.currency != other.currency:
            raise ValueError("cannot subtract different currencies")
        return Money(str(self.amount - other.amount), self.currency)


prices = [Money("30"), Money("5.50"), Money("12")]
print(sorted(prices))
# → [Money('5.50', 'EGP'), Money('12', 'EGP'), Money('30', 'EGP')]
print(max(prices) - min(prices), Money("1") >= Money("1"))
# → Money('24.50', 'EGP') True

Cheat sheet · الخلاصة

  • Indentation is syntax. None is the only "no value". True/False are capitalized.
  • Empty [] and {} are falsy in Python, truthy in JS. Empty recordsets are falsy.
  • is None, never == None. No ??: x or d loses a valid 0.
  • Never a mutable default: lines=None and create inside. The same goes for class attributes.
  • A venv is your hand-made node_modules. Call .venv/Scripts/python.exe directly in scripts.
  • requirements.txt is a flat list, and pip freeze pins what's installed.
  • dict keeps insertion order. A tuple can be a composite key. .copy() is shallow.
  • groupby groups adjacent items only: sort first, or use defaultdict(list).
  • Comprehension: one for, one if. Beyond that, write a loop.
  • super() follows the MRO of type(self), not the class header. That's what makes _inherit work.
  • Dunders are how |, len(), in, if work, including on recordsets. __eq__ needs __hash__.
  • Generators are lazy and single-use: ≈0.18 MB against ≈331 MB for a million rows. batched and split_every make chunks.
