Why this matters · ليه ده مهم

English

In Egypt an invoice is not just a PDF you email. It is a signed document that a government system has to accept, and every ERP that sells there has to talk to that system. The hard engineering is not the JSON. It is making a hash match byte for byte, keeping a private key on hardware a server cannot reach, and knowing what to do when a request times out after the authority already saved the document.

Everything here runs against real Odoo 20 code and a local stand-in. Nothing in this lesson contacts the real ETA, including its pre-production environment.

بالعامية

في مصر الفاتورة مش PDF بتبعته بالإيميل وخلاص. دي document متوقّع لازم سيستم حكومي يقبله، وأي ERP بيبيع هناك لازم يكلّم السيستم ده. الشغل الصعب مش الـ JSON. الصعب إن الـ hash يطابق byte بـ byte، وإن الـ private key يفضل على hardware السيرفر مش واصله، وإنك تعرف تعمل إيه لما الـ request يعمل timeout بعد ما الـ authority تكون حفظت الـ document فعلًا.

كل حاجة هنا شغالة على كود Odoo 20 الحقيقي وعلى stand-in محلي. مفيش أي حاجة في الدرس ده بتكلّم الـ ETA الحقيقية، حتى الـ pre-production بتاعها.

Part 1 — The system and who is in scope 🔴 Advancedالجزء 1 — المنظومة ومين ملزم بيها

English

The Egyptian Tax Authority (ETA) runs two related systems. The e-invoice system covers business-to-business and business-to-government sales. The e-receipt system covers business-to-consumer sales at a point of sale. They have separate APIs: Odoo's client posts invoices to /api/v1.0/documentsubmissions and receipts to /api/v1/receiptsubmissions.

Who must comply. The ETA announced that all its taxpayers would be obliged to join the e-invoice system by 15 December 2022. A later statement from the head of the ETA, reported in January 2025, says the obligation stages finished on 30 April 2023, so treat December 2022 as the announced date and April 2023 as the reported completion. E-receipt is still rolling out in phases. Secondary sources disagree on its shape: one counts 5 phases, another lists a sixth wave in January 2025, and a 2026 decree (189/2026) is reported to have moved dates. Read the current decision on eta.gov.eg before you quote a date to a client.

What that means for jobs (inference, not a measured fact): since the e-invoice mandate is complete, most Egyptian e-invoice work today is maintaining and fixing existing integrations rather than building new ones.

A consumer can still receive an e-invoice instead of a receipt, and then the receiver type is P. Odoo asks for a national ID above a configurable threshold (l10n_eg_edi_eta.invoicing_threshold, default 150,000 in this checkout).

الـ ETA عندها سيستمين مرتبطين ببعض: e-invoice للبيع من شركة لشركة أو لجهة حكومية، وe-receipt للبيع للمستهلك في نقطة البيع. وكل واحد ليه API لوحده: الـ client بتاع Odoo بيبعت الفواتير على /api/v1.0/documentsubmissions والإيصالات على /api/v1/receiptsubmissions.

Part 2 — Document structure and validation 🔴 Advancedالجزء 2 — هيكل الـ document والـ validation

English

An ETA document is a JSON object with an issuer, a receiver, a documentType (i invoice, c credit note, d debit note), internalID (your own invoice number), invoiceLines, and totals. Each line carries itemType, itemCode, unitValue and taxableItems.

itemType is GS1 for a global barcode or EGS for a code you register with the ETA. Odoo decides with one rule: a code starting with EG is EGS, anything else is GS1. A line without a code cannot be sent.

Amounts are rounded to 5 decimals by _l10n_eg_edi_round, and Odoo blocks a line description longer than 500 characters before sending. The ETA's own validators go much further: structure, core fields, signature, national ID, taxpayer status, reference documents for credit and debit notes, code tables, and the arithmetic at line and document level.

The JSON below is not hand-written. It came from a real invoice posted in the lab's EG Company through _generate_l10n_eg_edi_json. Notice 2.0 and 1000.0: Python floats keep their decimal point, and Part 3 shows why that matters.

Part 3 — Canonicalization, byte for byte 🔴 Advancedالجزء 3 — الـ canonicalization بالـ byte

English

You cannot sign "a JSON object". You sign bytes, so both sides need one agreed way to turn the object into bytes. The ETA's "Document Serialization Approach" says: property names go to culture-invariant uppercase inside double quotes; simple values go inside double quotes exactly as they appear in the input; an array writes its property name once, then repeats it before every element. Whitespace between elements does not count.

The SDK is explicit about numbers: there is no reformatting, so 0.0 must stay 0.0. That is the trap for a JavaScript developer. JSON.parse('1.0') returns the number 1, and String(1) is "1", so the original text is gone before your code runs.

The fix uses the JSON.parse source text access feature: on Node 22 the reviver receives a third argument whose source field holds the raw text of each number. Odoo's serializer is 14 lines of Python, and the port below was checked against it on 100 random documents with Arabic text, quotes, backslashes, newlines and floats: 100 of 100 identical. A naive port using plain JSON.parse matched 0 of 100.

import hashlib
import json


# الدالة الحقيقية من Odoo: دي المرجع اللي بنقارن بيه
def serialize_eta_document(payload):
    if not isinstance(payload, dict):
        return json.dumps(str(payload), ensure_ascii=False)
    canonical_str = []
    for key, value in payload.items():
        if isinstance(value, list):
            canonical_str.append(json.dumps(key, ensure_ascii=False).upper())
            for elem in value:
                canonical_str.append(json.dumps(key, ensure_ascii=False).upper())
                canonical_str.append(serialize_eta_document(elem))
        else:
            canonical_str.append(json.dumps(key, ensure_ascii=False).upper())
            canonical_str.append(serialize_eta_document(value))
    return ''.join(canonical_str)

export function parseKeepingNumbers(json: string): EtaValue {
  return JSON.parse(json, (_key: string, value: unknown, context?: { source?: string }) =>
    typeof value === "number" ? new RawNumber(context!.source!) : value,
  ) as EtaValue;

export function serialize(value: EtaValue): string {
  if (value instanceof RawNumber) return JSON.stringify(value.text);
  if (typeof value === "string") return JSON.stringify(value);
  // بايثون بتكتب True و None، فبنطابقها هنا عشان المقارنة تبقى byte-for-byte
  if (typeof value === "boolean") return JSON.stringify(value ? "True" : "False");
  if (value === null) return JSON.stringify("None");
  if (Array.isArray(value)) throw new Error("array outside an object is not part of an ETA document");

  let out = "";
  for (const [key, child] of Object.entries(value)) {
    const name = JSON.stringify(key).toUpperCase();
    if (Array.isArray(child)) {
      // اسم الـ array بيتكتب مرة قبلها، ومرة قبل كل عنصر
      out += name;
      for (const element of child) out += name + serialize(element);
    } else {
      out += name + serialize(child);
    }
  }
  return out;
}

export const sha256Hex = (text: string): string => createHash("sha256").update(text, "utf8").digest("hex");

function naiveSerialize(value: unknown): string {
  if (typeof value !== "object" || value === null) return JSON.stringify(String(value));
  let out = "";
  for (const [key, child] of Object.entries(value)) {
    const name = JSON.stringify(key).toUpperCase();

      out += name;
      for (const element of child) out += name + naiveSerialize(element);
    } else {
      out += name + naiveSerialize(child);
    }
  }
  return out;
}

Part 4 — Signing: token, HSM, CAdES-BES 🔴 Advancedالجزء 4 — التوقيع: الـ token والـ HSM و CAdES-BES

English

The SDK's signature steps are: serialize the document, take SHA-256 of the UTF-8 bytes, sign that hash with an eSeal certificate as a CAdES-BES signature, Base64-encode it, and add it to the document. CAdES-BES is a CMS SignedData structure. The private key does not sign your document directly. It signs a small set of signed attributes: content type, message digest (your SHA-256), a hash of the signing certificate, and the signing time.

The key lives on a USB token or an HSM, so a server alone cannot sign. Odoo's flow shows the consequence: the server builds the signed attributes, returns a client action to the browser, the browser posts them to a local signing host on the user's machine, that host talks to the token, and the browser sends the signature back through set_signature_data. Someone has to be at a desk with the token plugged in.

There is no real token here. The code below signs with a throwaway RSA key generated at runtime and never saved, labelled stand-in. As a cross-check, a CAdES signature built by Odoo's own _generate_cades_bes_signature was verified in Node, so the two implementations agree on the format.

export async function makeThrowawaySigner() {
  const alg = { name: "RSASSA-PKCS1-v1_5", hash: "SHA-256", publicExponent: new Uint8Array([1, 0, 1]), modulusLength: 2048 };
  const keys = await crypto.subtle.generateKey(alg, false, ["sign", "verify"]);
  const certificate = await x509.X509CertificateGenerator.createSelfSigned({
    serialNumber: "01", name: "CN=STAND-IN eSeal, not a real certificate",
    notBefore: new Date(Date.now() - 86_400_000), notAfter: new Date(Date.now() + 86_400_000),
    signingAlgorithm: alg, keys,
  });
  return { privateKey: keys.privateKey, der: new Uint8Array(certificate.rawData) };
}

      }),
      new pkijs.Attribute({ type: OID.signingTime, values: [new asn1js.UTCTime({ valueDate: new Date() })] }),

  const info = new pkijs.ContentInfo({ contentType: OID.signedData, content: signedData.toSchema(true) });

}

  return { ok, version: signedData.version, eContentType: signedData.encapContentInfo.eContentType, types };
}

Part 5 — OAuth, submit, status, rejection 🔴 Advancedالجزء 5 — الـ OAuth والـ submit والـ status والرفض

English

The protocol has four calls in Odoo's lib/eta_client.py: POST /connect/token (client credentials), POST /api/v1.0/documentsubmissions, GET /api/v1.0/documents/{uuid}/pdf, and PUT /api/v1.0/documents/state/{uuid}/state to cancel. The SDK adds GET /api/v1.0/documentsubmissions/{uuid} for status and GET /api/v1.0/documents/search, which can filter by internalID. The access token lasts 60 minutes by default and should be cached.

The most important fact is the status code. A successful submit returns 202, because validation is not finished. Only a minimal check runs during the call. A partial batch is normal: the response splits documents into acceptedDocuments and rejectedDocuments. "Accepted" here means accepted for processing. A document can still end up invalid, so you poll until overallStatus leaves in progress. The SDK prefers callbacks over polling and gives no polling interval, so the backoff below is our own choice.

Other responses: 422 DuplicateSubmission when an identical payload arrives within 10 minutes (with Retry-After), 429 when you exceed a per-API limit, 503 when the service is overloaded. The SDK warns against resending after any 20x.

A field-name warning: Odoo reads submissionId, while the SDK's field table says submissionUUID. They cannot both be right, and checking would mean calling the authority, so the connector in Part 6 accepts either.

      return send(res, 200, { result });

      if (!row) return send(res, 404, { error: { code: "NotFound" } });
      if (row.status === "invalid" || row.status === "rejected") return send(res, 400, { error: { code: "IncorrectState" } });
      row.status = "cancelled";
      return send(res, 200, {});
    }

    const pdf = url.pathname.match(/^\/api\/v1\.0\/documents\/([^/]+)\/pdf$/);
    if (req.method === "GET" && pdf) return send(res, 200, { note: `${BANNER} no PDF here` });

    return send(res, 404, { error: "not found in stand-in" });
  });

  await new Promise<void>((resolve) => server.listen(0, "127.0.0.1", resolve));
  const { port } = server.address() as AddressInfo;

    url: `http://127.0.0.1:${port}`,
    stats,
    documents,
    injectFault: (fault: Fault) => faults.push(fault),
    acceptedFor: (internalId: string) => documents.filter((d) => d.internalId === internalId && d.status !== "cancelled").length,
    async stop() {
      for (const res of hanging) res.destroy();
      server.closeAllConnections();
      await new Promise<void>((resolve) => server.close(() => resolve()));
    },
  };
}

Part 6 — A connector in Node 🔴 Advancedالجزء 6 — Connector بـ Node

English

A reliable connector needs four things. Idempotency on internalID, enforced by a database primary key rather than by careful code. A state machine: draft, signed, submitted, valid, invalid, cancelled, plus an extra unknown state for when we do not know the result. A retry policy that separates outcomes: a rejection is final, a 429 or 503 means the request did not run, and a timeout or 500 means we do not know. A reconciliation job that asks the authority what happened and settles every unknown.

The dangerous case is a timeout after the authority saved the document. Blind retry looks harmless because the ETA detects duplicates, but its check hashes the request payload. If your retry signs again, the signing time changes, the payload changes, and the duplicate check does not fire. The run below shows exactly that: a naive retry creates 2 accepted documents for one invoice.

The fix has two parts. Sign once and store the exact bytes. On an unknown outcome, search by internalID before resending. This is README artifact 5. The store here is node:sqlite so the file runs alone; in production use Postgres, with the same constraint and an outbox. The state machine idea comes from section 11, and the key pattern from section 12.

  draft --sign once--> signed --202 accepted--> submitted --poll--> valid --> cancelled
                         |  ^                      ^   |
                         |  | not found            |   +--poll--> invalid
             timeout/500 |  |                      |
                         v  |      found           |
                       unknown --------------------+

  signed --rejected in the response--> invalid
الرسمة دي الـ state machine: draft بيتوقّع مرة واحدة ويبقى signed. لو الرد 202 يبقى submitted، وبعد الـ polling يبقى valid أو invalid. لو حصل timeout أو 500 يبقى unknown، والـ reconciliation يسأل: لو لقاه عند الـ authority يبقى submitted، ولو ملقاهوش يرجع signed ويتبعت بنفس الـ bytes. ولو الرد قال مرفوض، يبقى invalid على طول.

import { DatabaseSync } from "node:sqlite";
import { BANNER, startEtaStandIn } from "./eta-standin.ts";

export type State = "draft" | "signed" | "unknown" | "submitted" | "valid" | "invalid" | "cancelled";

const ALLOWED: Record<State, State[]> = {
  draft: ["signed"],
  signed: ["submitted", "unknown", "invalid"],
  unknown: ["submitted", "signed", "invalid"],
  submitted: ["valid", "invalid", "cancelled"],
  valid: ["cancelled"],
  invalid: [],
  cancelled: [],
};

type Row = { internal_id: string; state: State; payload: string | null; uuid: string | null; submission_id: string | null; attempts: number };

export class EtaConnector {
  readonly db = new DatabaseSync(":memory:");
  private token: string | null = null;
  private readonly baseUrl: string;
  private readonly timeoutMs: number;

  constructor(baseUrl: string, timeoutMs = 150) {
    this.baseUrl = baseUrl;
    this.timeoutMs = timeoutMs;
    this.db.exec(`
      CREATE TABLE documents (
        internal_id TEXT PRIMARY KEY, state TEXT NOT NULL, source TEXT NOT NULL, payload TEXT,
        uuid TEXT, submission_id TEXT, attempts INTEGER NOT NULL DEFAULT 0);
      CREATE TABLE events (seq INTEGER PRIMARY KEY AUTOINCREMENT, internal_id TEXT NOT NULL, from_state TEXT, to_state TEXT NOT NULL, note TEXT);
    `);
  }

  // الـ PRIMARY KEY على internal_id هو اللي بيضمن الـ idempotency، مش الكود
  enqueue(internalId: string, source: object): boolean {
    const result = this.db.prepare("INSERT INTO documents (internal_id, state, source) VALUES (?, 'draft', ?) ON CONFLICT (internal_id) DO NOTHING").run(internalId, JSON.stringify(source));
    return result.changes === 1;
  }

  row(internalId: string): Row {
    return this.db.prepare("SELECT internal_id, state, payload, uuid, submission_id, attempts FROM documents WHERE internal_id = ?").get(internalId) as Row;
  }

  private move(internalId: string, to: State, note: string, extra: { uuid?: string; submissionId?: string } = {}) {
    const { state: from } = this.row(internalId);
    if (!ALLOWED[from].includes(to)) throw new Error(`illegal transition ${from} -> ${to} for ${internalId}`);
    this.db.prepare("UPDATE documents SET state = ?, uuid = COALESCE(?, uuid), submission_id = COALESCE(?, submission_id) WHERE internal_id = ?").run(to, extra.uuid ?? null, extra.submissionId ?? null, internalId);
    this.db.prepare("INSERT INTO events (internal_id, from_state, to_state, note) VALUES (?, ?, ?, ?)").run(internalId, from, to, note);
  }

  // التوقيع بيحصل مرة واحدة، والـ bytes بتتخزن عشان أي retry يبعت نفس الحاجة
  sign(internalId: string, signer: (source: Record<string, unknown>) => Record<string, unknown>) {
    const current = this.db.prepare("SELECT state, source FROM documents WHERE internal_id = ?").get(internalId) as { state: State; source: string };
    if (current.state !== "draft") return;
    const payload = JSON.stringify(signer(JSON.parse(current.source)));
    this.db.prepare("UPDATE documents SET payload = ? WHERE internal_id = ?").run(payload, internalId);
    this.move(internalId, "signed", "signed once, bytes stored");
  }

  private async call(path: string, init: RequestInit = {}): Promise<Response> {
    if (!this.token) {
      const response = await fetch(`${this.baseUrl}/connect/token`, {
        method: "POST",
        headers: { "content-type": "application/x-www-form-urlencoded" },
        body: new URLSearchParams({ grant_type: "client_credentials", client_id: "fake-client-id", client_secret: "fake-client-secret" }),
        signal: AbortSignal.timeout(this.timeoutMs),
      });
      this.token = ((await response.json()) as { access_token: string }).access_token;
    }
    return fetch(`${this.baseUrl}${path}`, {
      ...init,
      headers: { "content-type": "application/json", authorization: `Bearer ${this.token}` },
      signal: AbortSignal.timeout(this.timeoutMs),
    });
  }

  // بنفرّق بين 3 نتايج: اترفض، اتقبل، أو مش عارفين
  async send(internalId: string) {
    const row = this.row(internalId);
    if (row.state !== "signed") return;
    this.db.prepare("UPDATE documents SET attempts = attempts + 1 WHERE internal_id = ?").run(internalId);
    let response: Response;
    try {
      response = await this.call("/api/v1.0/documentsubmissions", { method: "POST", body: `{"documents":[${row.payload}]}` });
    } catch (error) {
      return this.move(internalId, "unknown", `no response: ${(error as Error).name}`);
    }
    if (response.status === 202) {
      const body = (await response.json()) as {
        submissionId?: string; submissionUUID?: string;
        acceptedDocuments: { uuid: string; internalId: string }[];
        rejectedDocuments: { internalId: string; error: { code: string } }[];
      };
      const submissionId = body.submissionUUID ?? body.submissionId;
      const accepted = body.acceptedDocuments.find((d) => d.internalId === internalId);
      if (accepted) return this.move(internalId, "submitted", "accepted for validation", { uuid: accepted.uuid, ...(submissionId ? { submissionId } : {}) });
      const rejected = body.rejectedDocuments.find((d) => d.internalId === internalId);
      if (rejected) return this.move(internalId, "invalid", `rejected: ${rejected.error.code}`);
      return this.move(internalId, "unknown", "document missing from the response");
    }
    await response.body?.cancel();
    // الـ 429 والـ 503 معناهم الطلب متنفذش، فنفضل signed ونعيد بعدين
    if (response.status === 429 || response.status === 503) return;
    // الـ 422 Duplicate والـ 500 ملهومش إجابة أكيدة، فلازم نسأل قبل ما نعيد
    return this.move(internalId, "unknown", `HTTP ${response.status}`);
  }

  // الـ reconciliation هو اللي بيحسم الـ unknown، مش الـ retry الأعمى
  async reconcile() {
    const unknown = this.db.prepare("SELECT internal_id FROM documents WHERE state = 'unknown'").all() as { internal_id: string }[];
    for (const { internal_id: internalId } of unknown) {
      const response = await this.call(`/api/v1.0/documents/search?internalID=${encodeURIComponent(internalId)}`);
      const { result } = (await response.json()) as { result: { uuid: string; submissionId: string }[] };
      const found = result[0];
      if (found) this.move(internalId, "submitted", "found at the authority", { uuid: found.uuid, submissionId: found.submissionId });
      else this.move(internalId, "signed", "not found, safe to resend the same bytes");
    }
    const open = this.db.prepare("SELECT internal_id, submission_id FROM documents WHERE state = 'submitted'").all() as { internal_id: string; submission_id: string }[];
    for (const { internal_id: internalId, submission_id: submissionId } of open) {
      const response = await this.call(`/api/v1.0/documentsubmissions/${submissionId}?pageNo=1&pageSize=100`);
      const { documentSummary } = (await response.json()) as { documentSummary: { internalId: string; status: string }[] };
      const status = documentSummary.find((d) => d.internalId === internalId)?.status;
      if (status === "valid" || status === "invalid") this.move(internalId, status, "final status from polling");
    }
  }

  async drain(ids: string[], rounds = 8) {
    for (let round = 0; round < rounds; round++) {
      for (const internalId of ids) await this.send(internalId);
      await this.reconcile();
      if (ids.every((i) => ["valid", "invalid", "cancelled"].includes(this.row(i).state))) return round + 1;
      // انتظار بـ backoff متزايد مع jitter بين كل جولة والتانية
      await new Promise((resolve) => setTimeout(resolve, Math.random() * 10 * 2 ** round));
    }
    return rounds;
  }

Cheat sheet · الخلاصة

  • E-invoice is B2B and B2G; e-receipt is B2C at a point of sale. Separate APIs.
  • Mandate: announced for 15 December 2022, reported complete on 30 April 2023. E-receipt is still phased.
  • itemType is EGS when the code starts with EG, otherwise GS1. Amounts to 5 decimals.
  • Canonical form: uppercase quoted names, values as written, arrays repeat the name.
  • 1.0 and 1 hash differently. Use context.source in the JSON.parse reviver.
  • Signature: SHA-256 of UTF-8 bytes, then CAdES-BES over signed attributes, then Base64.
  • Token: cheap, needs a person. HSM: costs more, can run unattended. The PIN is a secret.
  • 202 means accepted for validation. Poll or use callbacks for valid or invalid.
  • Duplicate check: identical payload within 10 minutes gives 422. Re-signing defeats it.
  • Timeout or 500 means unknown. Search by internalID, then resend the same bytes.
  • Wrong and accepted: cancel in the window, or issue a credit note after it. Never edit quietly.
  • Odoo gives you connectivity. Reconciliation, failure handling and signing operations are yours.
بالعامية
  • الـ e-invoice لـ B2B و B2G، والـ e-receipt لـ B2C في نقطة البيع، وكل واحد ليه API.
  • الإلزام: اتعلن لـ 15 ديسمبر 2022، واتقال إنه اكتمل 30 أبريل 2023. والـ e-receipt لسه على مراحل.
  • itemType بيبقى EGS لو الكود بيبدأ بـ EG، غير كده GS1. والمبالغ 5 أرقام عشرية.
  • الـ canonical form: الأسماء uppercase بين علامات تنصيص، والقيم زي ما هي، والـ array بتكرر الاسم.
  • 1.0 و1 ليهم hash مختلف. استخدم context.source في الـ reviver بتاع JSON.parse.
  • التوقيع: SHA-256 للـ UTF-8 bytes، وبعدين CAdES-BES على الـ signed attributes، وبعدين Base64.
  • الـ token رخيص ومحتاج شخص. الـ HSM أغلى ويشتغل لوحده. والـ PIN ده secret.
  • الـ 202 معناها اتقبل للـ validation. استخدم polling أو callbacks عشان تعرف valid ولا invalid.
  • كشف التكرار: نفس الـ payload خلال 10 دقايق بيرجع 422. والتوقيع من جديد بيبوّظ الكشف ده.
  • الـ timeout أو الـ 500 معناهم unknown. دوّر بـ internalID، وبعدين ابعت نفس الـ bytes.
  • لو اتقبلت وطلعت غلط: إلغاء خلال الفترة، أو credit note بعدها. وعمرك ما تعدّل في السر.
  • Odoo بيديك الاتصال. والـ reconciliation و failure handling وتشغيل التوقيع شغلك إنت.
