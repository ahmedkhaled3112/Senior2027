Why this matters · ليه ده مهم

English

When XML views run out, you write JavaScript: a dashboard, a custom field, a confirmation before a risky save, a public page for customers. Your React experience transfers, with one warning. Odoo 20 ships OWL 3 (3.0.0-alpha.50), and nearly every tutorial online still shows OWL 2. Code copied from those fails, and two of the failures are quiet: the screen goes back to the list, or a field renders empty with no error at all.

This lesson reads the API from the owl.js that Odoo actually loads and proves each piece in real headless Chrome.

بالعامية

لما الـ XML views متكفيش، بتكتب JavaScript: dashboard، أو field مخصوص، أو تأكيد قبل save خطر، أو صفحة عامة للعملاء. خبرتك في React هتنفعك، بس فيه تحذير. Odoo 20 جاي بـ OWL 3 (3.0.0-alpha.50)، وتقريبًا كل الـ tutorials على النت لسه بتشرح OWL 2. الكود المنقول منها بيقع، واتنين من الأعطال دي هاديين: الشاشة بترجع للـ list، أو الـ field بيطلع فاضي من غير أي error.

الدرس ده بيقرا الـ API من owl.js اللي Odoo بيحمّله فعلًا، وبيثبت كل حتة في Chrome headless حقيقي.

Part 1 — OWL against React 🟡 Intermediateالجزء 1 — OWL قصاد React

English

OWL components are classes. A component has a static template, optional class fields, and a setup() that runs once, where hooks are called. Templates are XML, compiled to JavaScript in the browser, and use directives: t-if, t-foreach with t-as and t-key, t-out, t-on-click.

Reactivity moved to signals in version 3. proxy(obj) tracks deep mutations, signal(value) is one cell you read by calling it and write with .set(), computed(fn) derives a value, and useEffect(fn) runs when anything it read changes, with no dependency array. useState no longer exists in owl.js. Here is the same cart in both libraries.

const { Component, computed, mount, proxy, signal, useEffect, xml } = owl;

class OrderCart extends Component {
  static template = xml`
    <section class="cart">
      <button class="add" t-on-click="this.addItem">Add item</button>
      <button class="discount" t-on-click="this.applyDiscount">Apply 50 off</button>
      <span class="count" t-out="this.count()"/>
      <span class="total" t-out="this.total()"/>
      <ul>
        <li t-foreach="this.cart.items" t-as="item" t-key="item.sku" t-out="item.sku"/>
      </ul>
      <p class="free" t-if="this.total() >= 300">Free delivery</p>
    </section>`;

  // الـ proxy بيتابع أي تعديل جوه الـ object، حتى push على array
  cart = proxy({ items: [] });
  // الـ signal خلية واحدة: بتقراها بالنداء وبتكتبها بـ set
  discount = signal(0);
  // الـ computed بيتعاد حسابه لما حاجة قراها تتغير بس
  count = computed(() => this.cart.items.length);
  total = computed(() => this.cart.items.reduce((sum, item) => sum + item.price, 0) - this.discount());

  setup() {
    // الـ effect بيعرف الـ dependencies لوحده، مفيش array زي React
    useEffect(() => {
      document.title = `Cart (${this.count()})`;
    });
  }

  addItem() {
    this.cart.items.push({ sku: `SKU-${this.cart.items.length + 1}`, price: 100 });
  }

  applyDiscount() {
    this.discount.set(50);
  }
}
import { useEffect, useMemo, useState } from 'react';
import { createRoot } from 'react-dom/client';

type Item = { sku: string; price: number };

function OrderCart() {
  // الـ state لازم يتبدّل بـ array جديد: push مش هيعمل re-render
  const [items, setItems] = useState<Item[]>([]);
  const [discount, setDiscount] = useState(0);
  const total = useMemo(() => items.reduce((sum, item) => sum + item.price, 0) - discount, [items, discount]);

  // الـ dependency array إنت اللي بتكتبها بإيدك
  useEffect(() => {
    document.title = `Cart (${items.length})`;
  }, [items.length]);

  return (
    <section className="cart">
      <button className="add" onClick={() => setItems((old) => [...old, { sku: `SKU-${old.length + 1}`, price: 100 }])}>Add item</button>
      <button className="discount" onClick={() => setDiscount(50)}>Apply 50 off</button>
      <button className="mutate" onClick={() => { items.push({ sku: 'SKU-X', price: 100 }); setItems(items); }}>Mutate</button>
      <span className="count">{items.length}</span>
      <span className="total">{total}</span>
      <ul>{items.map((item) => <li key={item.sku}>{item.sku}</li>)}</ul>
      {total >= 300 && <p className="free">Free delivery</p>}
    </section>
  );
}

بالعامية

الـ OWL components عبارة عن classes. الـ component ليه static template، و class fields لو حبيت، وsetup() بتشتغل مرة واحدة وفيها الـ hooks. الـ templates بـ XML بتتحول JavaScript في المتصفح، وفيها directives: t-if، وt-foreach مع t-as وt-key، وt-out، وt-on-click.

الـ reactivity اتنقلت لـ signals في version 3. proxy(obj) بيتابع التعديلات لحد جوه، signal(value) خلية واحدة بتقراها بالنداء وتكتبها بـ .set()، computed(fn) بيطلّع قيمة مشتقة، وuseEffect(fn) بيشتغل لما أي حاجة قراها تتغير، من غير dependency array. وuseState مبقتش موجودة في owl.js أصلًا.

شغّلنا الصفحتين في Chrome headless: OWL من owl.js بتاع Odoo نفسه، و React 19.3 معمول له bundle بـ esbuild. سكريبت داس على الزراير وقرا الـ DOM. و OWL بيعمل الـ render على requestAnimationFrame، فأي test أوتوماتيك لازم يستنى frame قبل ما يقرا الـ DOM.

وخد بالك إن الإصدار alpha، فالنسخة المثبّتة جوه web/static/lib/owl هي المرجع مش الـ docs العامة. وweb/static/src/owl2/owl3_compatibility_layer.js بيغطي جزء من الـ API القديم، وodoo/upgrade_code/owl3-migration.py بيعمل التحويلات الميكانيكية اللي في الجدول التاني.

فين هستخدمه في شغلي؟ لو جالك ticket "اعمل dashboard في Odoo" هتلاقي نفسك بتدوّر على Google وتنقل useState من blog قديم. الصح: افتح أي field قريب في addons/web/static/src/views/fields وانسخ شكله. ولو بتعمل code review لزميل جاي من React، دوّر على حاجتين: متغيرات في الـ template من غير this.، و array بيتعمل له copy من غير داعي، لأن proxy بيتابع الـ mutation عادي.
Interview question "How does OWL 3 reactivity differ from React's model?" → React re-runs the component function and compares references, so you replace state and list dependencies yourself. OWL 3 runs setup() once and tracks what each computation reads through proxies and signals, so you mutate directly and dependencies are automatic.
"الـ reactivity في OWL 3 بتختلف إزاي عن React؟" ← React بيعيد تشغيل الـ function ويقارن references، فإنت بتبدّل الـ state وبتكتب الـ dependencies بإيدك. OWL 3 بيشغّل setup() مرة واحدة وبيتابع كل computation قرت إيه عن طريق proxies و signals، فبتعدّل مباشرة والـ dependencies أوتوماتيك.

Part 2 — Assets and client actions 🟡 Intermediateالجزء 2 — الـ assets والـ client actions

English

There is no webpack step. The manifest's assets key adds your files to named bundles, and the server concatenates, transpiles and caches them. The bundles you will touch are web.assets_backend (the app; included by web.assets_web), web.assets_frontend (the public website), web.assets_tests (tours) and web.assets_unit_tests (Hoot). A plain string appends; tuples give other directives: prepend, after, before, remove, replace, include.

Files under static/src are ES modules. The server transpiles them to odoo.define and names them from their path, so erp_lab_web/static/src/lab_badge.js becomes @erp_lab_web/lab_badge, importable like @web/core/registry or @odoo/owl. A client action is a full screen you draw yourself: register a component in registry.category("actions"), then create an ir.actions.client whose tag matches the key.

To debug, add ?debug=assets to the URL and you get unminified code. In this lab, editing a JS or OWL XML file needed only a server restart and a page reload, no -u, and the hash in the bundle URL changed by itself.

import { registry } from "@web/core/registry";

import { standardActionServiceProps } from "@web/webclient/actions/action_plugin";
import { RefundStatsPlugin } from "./refund_stats_plugin";

export class RefundDashboard extends Component {
    static template = "erp_lab_web.RefundDashboard";
    props = useProps(standardActionServiceProps);

    setup() {
        this.stats = useService("erp_lab_refund_stats");
        this.statsPlugin = usePlugin(RefundStatsPlugin);
        this.action = useService("action");
        this.notification = useService("notification");
        this.data = proxy({ groups: [], drafts: 0 });
        // الـ onWillStart بيأخّر أول render لحد ما الـ data تيجي

        this.data.groups = await this.stats.byState();
        this.data.drafts = await this.statsPlugin.draftCount();
    }

    openDrafts() {
        this.notification.add(`${this.data.drafts} drafts waiting`, { type: "info" });
        return this.action.doAction("erp_lab.refund_action");
    }
}

Part 3 — Services and registries 🟡 Intermediateالجزء 3 — الـ services والـ registries

English

The web client is a plugin system built on one idea: a registry is a named map that modules add to at load time. registry.category("fields") holds field widgets, "views" holds view types, "actions" client actions, and "services" long-lived singletons. Nothing imports your widget directly; the view asks the registry for a name.

A service is a singleton with declared dependencies, the same shape as the DI composition root: dependencies: ["orm"] is constructor injection, and the framework starts services in dependency order. Components get one with useService("orm"); the common ones are orm, notification, action and dialog.

Odoo is partway through a migration here. In 20.0 orm, notification, dialog and action are implemented as OWL Plugin classes with a thin service wrapper marked @todo owl3 migration in the source, and owl3-migration.py rewrites 22 services to usePlugin(...). Core code such as FormController still calls useService, so both work today. Both are shown below and both ran.

import { registry } from "@web/core/registry";

Part 6 — Website and QWeb 🟡 Intermediateالجزء 6 — الـ website والـ QWeb

English

Public pages are server-rendered. An http.Controller method with @http.route handles the URL, and request.render runs a QWeb template in Python. website=True adds the website layer: the layout, the language and the theme. auth='public' means anonymous visitors reach it, so they run as the public user with almost no rights, which is why the code uses sudo() and why the check right after it matters.

Don't mix up the two QWebs. Backend OWL templates run in the browser and need this.. Website QWeb runs on the server, and variables come from the dict passed to render, with no this. In both, t-out escapes plain strings and renders Markup as-is.

The page below shows a customer their order status. An integer in a public URL can be guessed, so the route also requires the order's access_token, compared in constant time, and answers 404 for both a missing order and a wrong token, so a visitor can't tell which orders exist. The template receives four chosen values, not the record, so a later template edit can't leak an internal field. Lesson 19 goes deeper on sudo in public routes.

from markupsafe import Markup

from odoo import http
from odoo.http import request
from odoo.tools import consteq


class OrderStatus(http.Controller):

    @http.route('/orders/<int:order_id>', type='http', auth='public', website=True, methods=['GET'], sitemap=False)

        return request.render('erp_lab_web.order_status_page', {

            'status': labels[order.state],
            'customer_note': order.client_order_ref or '',
            'trusted_html': Markup('<em>Thank you</em>'),
        })

import { chromium } from 'playwright-core';

const url = process.env.ODOO_URL;
const refundId = process.env.REFUND_ID;
const browser = await chromium.launch({
  headless: true,
  executablePath: 'C:/Program Files/Google/Chrome/Application/chrome.exe',
});
const errors = [];
try {
  const page = await browser.newPage();
  // الـ console error والـ uncaught بييجوا من مكانين مختلفين
  page.on('pageerror', (error) => errors.push(error.message));
  page.on('console', (message) => message.type() === 'error' && errors.push(message.text()));

  await page.goto(`${url}/web/login`, { timeout: 120_000 });
  await page.fill('form.oe_login_form input[name=login]', 'admin');
  await page.fill('form.oe_login_form input[name=password]', 'admin');
  await page.click('form.oe_login_form button[type=submit]');
  await page.waitForURL(/\/odoo/, { timeout: 240_000 });

  await page.goto(`${url}/odoo/refunds/${refundId}`, { timeout: 240_000 });
  await page.waitForSelector('.o_lab_badge', { timeout: 240_000 });
  const text = await page.textContent('.o_lab_badge');
  console.log('badge', text, 'page errors', errors.length);
  // لازم نشيّك النص نفسه: span فاضي بيعدّي الـ selector
  if (text !== '42' || errors.length) process.exitCode = 1;
} finally {
  await Promise.race([browser.close(), new Promise((done) => setTimeout(done, 6000))]);
}
process.exit(process.exitCode ?? 0);

Common mistakes · غلطات شائعة

❌ OWL 2 state from a blog 
import { useState } from "@odoo/owl";
// الـ import ده undefined في OWL 3
this.state = useState({ total: 0 });
✅ OWL 3 
import { proxy } from "@odoo/owl";
// نفس الاستخدام بعد كده: this.state.total = 5
this.state = proxy({ total: 0 });
بالعامية

❌ useState مش موجودة في owl.js بتاع Odoo 20. ✅ proxy هو البديل المباشر، وطريقة التعديل نفسها.

❌ Bare name in an OWL template 
<span t-out="value"/>
✅ Explicit this 
<span t-out="this.value"/>
بالعامية

❌ الاسم لوحده بيرندر نص فاضي من غير error، وجرّبناها: BADGE "" وصفر errors. ✅ اكتب this. دايمًا في templates الـ OWL. أما QWeb بتاع الموقع فمن غير this.

❌ A business rule that lives in patch

patch(FormController.prototype, {
    async saveButtonClicked(params) { return this.askThenSave(params); },
});
✅ Rule in Python, patch for comfort 
@api.constrains('total', 'reason')
def _check_large_refund(self):
    # ده بيقف قدام كل المسارات
    for refund in self:
        if refund.total > 1000 and not refund.reason:
            raise ValidationError('Large refunds need a reason.')
بالعامية

❌ الـ patch بيشتغل على زرار واحد بس، وأثبتنا إن الخروج من الصفحة حفظ 2,500 من غير تأكيد. ✅ حط القاعدة في @api.constrains عشان كل المسارات تقف عندها، وسيب الـ patch للـ UX.

Cheat sheet · الخلاصة

  • Odoo 20 ships OWL 3.0.0-alpha.50: read owl.js and core fields, not OWL 2 tutorials.
  • State: proxy, signal, computed, useEffect(fn). useState is gone.
  • Props: props = useProps(schema). static props throws in Odoo.
  • OWL templates need this.; a bare name renders empty with no error. Server QWeb has no this.
  • assets in the manifest; files in static/src become @module/path; ?debug=assets for readable code.
  • Client action: registry.category("actions").add(tag, Component) + ir.actions.client.
  • Registries are the plugin system. useService works today and Odoo is moving to usePlugin.
  • patch(Class.prototype, {...}) + super: for UX only, coupled to internals, and other code paths bypass it.
  • Widget: registry.category("fields").add(name, { component, supportedTypes }) + widget=.
  • Public route: auth='public', sudo only behind a token check, 404 for all failures, send chosen values.
  • t-out escapes strings; Markup disables that, so never wrap user input.
  • Tours need websocket-client; a skip is not a pass, so assert on text in your e2e.
بالعامية
  • Odoo 20 جاي بـ OWL 3.0.0-alpha.50: اقرا owl.js والـ fields الأساسية، مش tutorials الـ OWL 2.
  • الـ state: proxy وsignal وcomputed وuseEffect(fn). وuseState راحت.
  • الـ props: props = useProps(schema). وstatic props بترمي error في Odoo.
  • templates الـ OWL محتاجة this.، والاسم لوحده بيطلع فاضي من غير error. و QWeb بتاع الـ server من غير this.
  • assets في الـ manifest؛ ملفات static/src بتبقى @module/path؛ و?debug=assets للكود المقروء.
  • الـ client action: registry.category("actions").add(tag, Component) مع ir.actions.client.
  • الـ registries هي الـ plugin system. useService شغالة النهارده و Odoo رايح ناحية usePlugin.
  • patch(Class.prototype, {...}) مع super: للـ UX بس، مربوط بـ internals، ومسارات تانية بتعدّيه.
  • الـ widget: registry.category("fields").add(name, { component, supportedTypes }) مع widget=.
  • الـ public route: auth='public'، وsudo ورا token check بس، و 404 لكل الفشل، وابعت قيم مختارة.
  • t-out بيعمل escape للـ strings؛ Markup بيلغيه، فأوعى تلف بيه input من المستخدم.
  • الـ tours محتاجة websocket-client؛ والـ skip مش نجاح، فشيّك النص في الـ e2e بتاعك.
