Why this matters · ليه ده مهم

English

Odoo isn't the only ERP you'll meet. Integrations land you against SAP or NetSuite whether you chose them or not, and clients ask "why not ERPNext?" in the first meeting. You don't need to master these systems. You need a working map: how each is extended, what its limits are, what its license allows, and how much of what you've learned carries over. One of them, SAP CAP, runs on Node, so this lesson runs it for real. The others need accounts or runtimes that aren't available here, so their code is labelled "not run here".

بالعامية

Odoo مش الـ ERP الوحيد اللي هتقابله. الـ integrations هتحطك قصاد SAP أو NetSuite سواء اخترتهم أو لأ، والعملاء بيسألوا "ليه مش ERPNext؟" من أول اجتماع. إنت مش محتاج تتقن الأنظمة دي. محتاج خريطة شغالة: كل واحد بيتعمله extension إزاي، حدوده إيه، رخصته بتسمح بإيه، وقد إيه من اللي اتعلمته بينتقل معاك. واحد منهم، SAP CAP، شغال على Node، فالدرس ده بيشغّله فعلًا. الباقيين محتاجين حسابات أو runtimes مش متاحة هنا، فكودهم مكتوب عليه "not run here" يعني متشغّلش هنا.

Part 1 — SAP 🔴 Advancedالجزء 1 — SAP

English

S/4HANA is SAP's current ERP, running only on the HANA database. ECC is the older generation that most long-term customers still have. ABAP is SAP's own language, and RAP (the ABAP RESTful Application Programming Model) is the current standard for building services in it. Lesson 37 introduced clean core; SAP's mechanism for it is ABAP Cloud, restricted to released objects and public APIs. The alternative is a side-by-side extension on BTP (Business Technology Platform): a separate application that talks to S/4HANA through APIs. For a Node developer that's the way in, and Part 2 runs it.

The ECC deadline. Secondary sources report mainstream maintenance ending at the end of 2027 and paid extended maintenance to the end of 2030, for enhancement packages 6 to 8. I didn't find SAP's own primary statement, so confirm it on SAP's roadmap before you quote it to anyone. The premium for the extension is also disputed. The RAP behavior definition below is not run here: it needs an ABAP system.

How much migration is left. Gartner's last public figure, via The Register, says about 39% of about 35,000 ECC customers had bought or subscribed to S/4HANA licences by the end of 2024. That measures licensing, not go-live, so real migrations are behind that number. It had moved from 34% to 37% across the year to Q2 2024. A straight line at that pace leaves around 18,000 customers unlicensed at the 2027 deadline. My inference, not a forecast: migration work looks more like a long slope than a cliff, so an "SAP gold rush in 2027" is a weak thing to plan a career around.

// الأرقام: Gartner عن طريق The Register، والـ projection تحت استنتاج مني
const eccCustomers = 35_000;
const licensedShare = { q2_2023: 34, q2_2024: 37, q4_2024: 39 };

// المعدل: الفرق بين آخر قراءتين سنويتين
const pointsPerYear = licensedShare.q2_2024 - licensedShare.q2_2023;

function licensedAt(yearEnd: number): number {
  return Math.min(100, licensedShare.q4_2024 + (yearEnd - 2024) * pointsPerYear);
}

console.log(`rate: ${pointsPerYear} points a year`);
for (const year of [2024, 2027, 2030]) {
  const share = licensedAt(year);
  const remaining = Math.round(eccCustomers * (1 - share / 100));
  console.log(`end ${year}: licensed ${share}%  not licensed ${remaining}`);
}

بالعامية

S/4HANA هو الـ ERP الحالي بتاع SAP وبيشتغل على database الـ HANA بس. ECC الجيل الأقدم اللي معظم العملاء القدام لسه عليه. ABAP لغة SAP الخاصة، وRAP (الـ ABAP RESTful Application Programming Model) الطريقة الحالية لبناء services بيها. الدرس 37 عرّف الـ clean core، وآلية SAP ليه هي ABAP Cloud اللي مسموح فيها بالـ released objects والـ public APIs بس. البديل side-by-side extension على BTP (Business Technology Platform): تطبيق منفصل بيكلم S/4HANA عن طريق APIs. ولمبرمج Node ده مدخلك، والجزء 2 بيشغّله.

ميعاد ECC. مصادر ثانوية بتقول الـ mainstream maintenance بتخلص آخر 2027، والـ extended المدفوع لآخر 2030، لـ enhancement packages من 6 لـ 8. ملقتش تصريح SAP الأصلي، فاتأكد من الـ roadmap بتاعهم قبل ما تقولها لحد. وكمان نسبة الزيادة بتاعة الـ extension عليها خلاف. والـ RAP behavior definition اللي تحت not run here لأنه محتاج نظام ABAP.

فاضل قد إيه migration. آخر رقم عام من Gartner، عن طريق The Register: حوالي 39% من حوالي 35,000 عميل ECC اشتروا أو اشتركوا في S/4HANA licenses بنهاية 2024. ده بيقيس الـ licensing مش الـ go-live، فالـ migrations الفعلية وراه. وكان اتحرك من 34% لـ 37% في السنة اللي خلصت Q2 2024. خط مستقيم بنفس المعدل بيسيب حوالي 18,000 عميل من غير license عند ميعاد 2027. ده استنتاج مني مش توقع: شغل الـ migration شكله منحدر طويل أكتر منه هاوية، فـ"موجة SAP في 2027" حاجة ضعيفة تبني عليها career.

فين هستخدمه في شغلي؟ عميل عنده SAP وعايز الموقع بتاعك يبعتله orders. إنت مش هتكتب ABAP: هتكلم OData API من Node service، وتحط idempotency زي الدرس 28. واسأله أول حاجة: "إنتوا على ECC ولا S/4؟"، لأن الـ APIs المتاحة مختلفة. الغلطة الشائعة إنك تفهم رقم الـ 39% إنه 39% خلصوا migration.

Part 2 — SAP CAP on Node 🔴 Advancedالجزء 2 — SAP CAP على Node

English

CAP (Cloud Application Programming Model) is SAP's framework for those side-by-side apps, with a Node runtime. This ran for real: @sap/cds 10.2.2 with @cap-js/sqlite 3.1.2, which uses node:sqlite, so npm i --ignore-scripts needs no native download. No SAP service was touched. You describe entities in CDS, project them through a service, and the framework gives you the database schema and an OData API. Business logic goes in a .js file named after the service, which CAP finds by itself.

Three things in the output deserve attention. The decimal came back as the string '1140.50', which protects precision and means total + 10 concatenates: see money in code. $filter and $select worked with no code from me. And the log says kind: 'mocked': that's a development-only auth strategy, so real authentication is on you before anything ships.

Licence. @sap/cds isn't open source; its package.json says SEE LICENSE IN LICENSE, and that file is the SAP Developer License Agreement. It permits "testing and only non-productive use" or "productive use deployed and operated exclusively on" SAP BTP or another platform licensed from SAP, and using the software counts as accepting it. It also bars applications that "permit mass data extraction from an SAP product to a non-SAP product" beyond interoperability, and bars using the tools for AI training. Read it before putting CAP in a product. A practical note on running it: calling cds.exec('serve', ...) from a script didn't mount the service when this was tested, while cds.serve('all').from(csn).in(app) did.

Interview question "When would you pick CAP over Express plus an ORM?" → When the app is a side-by-side extension of SAP: you get OData, Fiori annotations and SAP integration for free, and it's the supported route that keeps the core clean. Outside SAP, the licence ties productive use to SAP's platforms and you'd be paying for features you don't use.
"إمتى تختار CAP بدل Express مع ORM؟" ← لما التطبيق side-by-side extension لـ SAP: بتاخد OData و Fiori annotations و integration مع SAP ببلاش، وده الطريق المدعوم اللي بيحافظ على الـ core نضيف. برّه SAP، الرخصة بتربط الاستخدام الإنتاجي بـ platforms بتاعة SAP وهتدفع تمن features مش محتاجها.

Part 3 — NetSuite and SuiteScript 🔴 Advancedالجزء 3 — NetSuite و SuiteScript

English

NetSuite is Oracle's cloud ERP, and SuiteScript 2.1 is its JavaScript. It looks familiar, but modules load through AMD define, there's no npm install at runtime and no Node built-ins such as fs, and the runtime charges you for every API call. These are governance units, and the figures below come from Oracle's documentation:

  • record.load costs 10 units on a transaction record, Record.save costs 20.
  • User Event scripts (run on record save) get 1,000 units. Scheduled scripts get 10,000.
  • Map/Reduce has no limit on the whole deployment. Each invocation has its own: getInputData 10,000, map 1,000, reduce 5,000, summarize 10,000.
  • Going over throws SSS_USAGE_LIMIT_EXCEEDED and ends the invocation, even if it wasn't finished.

The real sample needs a NetSuite account, so it's not run here. The Node stand-in below fakes N/record and the budget using Oracle's published numbers, to show what changes: a loop over 500 invoices is trivial in Node, stops at 333 in a Scheduled script, stops at 33 in a User Event, and finishes under Map/Reduce because each invoice gets its own invocation. Map/Reduce is the design answer, in the same way that queue workers handle bulk work in Node.

Tim Dietrich, who has built on NetSuite since 2017, puts it well: "SuiteScript is JavaScript, but it's a curated subset running inside a controlled environment. It's more like learning a dialect than a new language."

/**
 * @NApiVersion 2.1
 * @NScriptType ScheduledScript
 */
// مش متشغّل هنا: محتاج حساب NetSuite حقيقي
define(['N/record', 'N/runtime', 'N/log'], (record, runtime, log) => {
  const execute = () => {
    const invoiceIds = [101, 102, 103];
    for (const id of invoiceIds) {
      // التكلفة: load بـ 10 و save بـ 20 على الـ transaction record
      const invoice = record.load({ type: record.Type.INVOICE, id });
      invoice.setValue({ fieldId: 'memo', value: 'reviewed' });
      invoice.save();
      log.debug('remaining', runtime.getCurrentScript().getRemainingUsage());
    }
  };
  return { execute };
});

// بديل محلي: مش NetSuite، بيقلّد الـ governance بأرقام Oracle المنشورة بس
const COST = { load: 10, save: 20 };
const LIMIT = { scheduled: 10_000, userEvent: 1_000, mapInvocation: 1_000 };

class UsageLimitExceeded extends Error {
  code = "SSS_USAGE_LIMIT_EXCEEDED";
}

class Governor {
  used = 0;
  limit: number;
  constructor(limit: number) { this.limit = limit; }
  charge(units: number) {
    if (this.used + units > this.limit) throw new UsageLimitExceeded(`used ${this.used}/${this.limit}`);
    this.used += units;
  }
  remaining() { return this.limit - this.used; }
}

// التقليد: N/record بيخصم من الميزانية مع كل نداء
function fakeRecordModule(gov: Governor) {
  return {
    load(id: number) { gov.charge(COST.load); return { id, memo: "" }; },
    save(_rec: { id: number; memo: string }) { gov.charge(COST.save); },
  };
}

const invoiceIds = Array.from({ length: 500 }, (_, i) => i + 1);

// الحالة 1: نفس الـ loop في Node عادي مفيش حد بيعد عليه
let nodeDone = 0;
for (const _id of invoiceIds) nodeDone++;
console.log(`plain node loop: ${nodeDone}/500`);

function runLoop(limit: number, label: string) {
  const gov = new Governor(limit);
  const record = fakeRecordModule(gov);
  let done = 0;
  try {
    for (const id of invoiceIds) {
      const inv = record.load(id);
      inv.memo = "reviewed";
      record.save(inv);
      done++;
    }
    console.log(`${label}: ${done}/500 finished, used ${gov.used}`);
  } catch (e) {
    console.log(`${label}: stopped at ${done}/500, ${(e as UsageLimitExceeded).code}, remaining ${gov.remaining()}`);
  }
}

// الحالة 2 و 3: نفس الكود جوه scheduled و user event
runLoop(LIMIT.scheduled, "scheduled (10,000)");
runLoop(LIMIT.userEvent, "user event (1,000)");

// الحالة 4: map/reduce، كل invoice في invocation ليها ميزانيتها
let mapped = 0;
let totalUnits = 0;
for (const id of invoiceIds) {
  const gov = new Governor(LIMIT.mapInvocation);
  const record = fakeRecordModule(gov);
  const inv = record.load(id);
  record.save(inv);
  mapped++;
  totalUnits += gov.used;
}
console.log(`map/reduce: ${mapped}/500 finished, ${totalUnits} units across invocations`);

Part 4 — Dynamics 365 🔴 Advancedالجزء 4 — Dynamics 365

English

Microsoft has two ERPs under one brand, each with its own language. Business Central (smaller companies) uses AL, written in VS Code with the AL Language extension and published as extensions. You don't edit base objects: you write a tableextension and subscribe to events. Finance and Supply Chain Management (larger companies) uses X++, a C#-like language in Visual Studio.

X++ carries a useful history. Customization used to happen through overlayering: a higher layer holds a replaced copy of the element, which is the fork from lesson 37 with vendor support. Microsoft moved to extensions and states the reason directly: "Unlike overlayering, extensions reduce the cost of upgrading to a new version, as this approach eliminates costly code and metadata conflicts." The modern tool is Chain of Command: an extension class wraps a method and must call next, and "The wrapper method must have the same signature as the base method."

That's the same design as Odoo's _inherit and super(). The real Odoo run from lesson 37 shows both owners of _line_cost in the MRO. The AL and X++ below are not run here. The small simulation shows why the industry moved: when the vendor adds tax in v2, the overlay silently keeps the old behaviour and the wrapper picks up the change.

Part 5 — ERPNext and Frappe 🔴 Advancedالجزء 5 — ERPNext و Frappe

English

ERPNext is the closest open-source rival to Odoo, built on the Frappe framework. The core difference is where a model lives. Odoo's is a Python class; the database follows. Frappe is metadata-first: a DocType is a JSON document describing fields, permissions and form behaviour, with an optional Python controller. As Frappe's docs say, "A DocType is also a DocType. This means that we store meta-data as the part of the data." Tables get a tab prefix (tabRefund), against Odoo's lab_refund. REST comes out of the box at /api/resource/:doctype, authenticated with an API key and secret.

Licences: ERPNext is GPL-3.0, against Odoo Community's LGPL-3. Note that Frappe itself is MIT, so an app on Frappe alone has more freedom than one that builds on ERPNext. (Engineering orientation, not legal advice.)

Language is a weak reason to choose. NetSuite is JavaScript, but as Part 3 showed its environment isn't Node's, and the larger investment is the data model. What actually transfers between ERPs is the domain: accounting, business processes, and integration reliability. You've spent this section building exactly those, and they don't expire when you change vendors.

So split the question. The domain is paid for once. Each platform is paid for separately. The model below makes that visible. The week counts are placeholders, your own inputs, not market data, so change them. Also weigh what the model leaves out: the research behind this section found Egyptian hiring evidence only for Odoo and ERPNext, and local demand should matter more than language fit. The actual decision, using numbers you collect yourself, is lesson 41.

بالعامية

اللغة سبب ضعيف للاختيار. NetSuite هو JavaScript، بس زي ما شفنا في الجزء 3 البيئة مش بتاعة Node، والاستثمار الأكبر في الـ data model. اللي بينتقل فعلًا بين الـ ERPs هو الـ domain: المحاسبة، والـ business processes، والـ integration reliability. وإنت قضيت القسم ده بتبني دول بالظبط، ومش بينتهوا لما تغير الـ vendor.

فقسّم السؤال. الـ domain بيتدفع مرة واحدة. وكل platform بيتدفع لوحده. الـ model بيوضح ده. عدد الأسابيع placeholders، مدخلات بتاعتك إنت مش بيانات سوق، فغيّرها. وكمان فكر في اللي الـ model سايبه: البحث ورا القسم ده لقى أدلة توظيف مصرية لـ Odoo و ERPNext بس، والطلب المحلي لازم يهم أكتر من توافق اللغة. والقرار الفعلي بأرقام تجمعها بنفسك في الدرس 41.

فين هستخدمه في شغلي؟ لما recruiter يكلمك عن وظيفة NetSuite عشان "إنت بتعرف JavaScript"، اسأل نفسك: الوظيفة هتعلمني domain ولا platform بس؟ الـ fintech أو الـ startup اللي بتبني ledger بـ TypeScript ممكن تدّيك الـ domain من غير vendor lock. الغلطة الشائعة إنك تختار بالاسم الأعلى مرتب في مقالة، من غير ما تشوف فيه طلب في السوق بتاعك ولا لأ.
Trade-off Generalist or specialist isn't a binary. Deep platform skill commands a premium while that platform is in demand, and it's stranded if demand moves. Domain skill is portable but harder to show on a CV. A workable shape is one platform deep, chosen by local demand, on top of the domain, with enough of the others to integrate against them.
عام ولا متخصص مش اختيار من اتنين. المهارة العميقة في platform ليها سعر أعلى طول ما عليها طلب، وبتقف لو الطلب اتحرك. ومهارة الـ domain بتتنقل بس أصعب تبينها في الـ CV. الشكل العملي: platform واحدة بعمق تختارها حسب الطلب المحلي، فوق الـ domain، ومعاك من الباقيين اللي يكفي تعمل معاهم integration.

Solution · الحل 
const cds = require('@sap/cds');

module.exports = class BillingService extends cds.ApplicationService {
  init() {
    const { Invoices } = this.entities;
    // الحماية: الفاتورة اللي اترحّلت مبتتعدلش
    this.before('UPDATE', Invoices, async (req) => {
      const current = await SELECT.one.from(Invoices).where({ ID: req.data.ID });
      if (current?.status === 'posted') req.reject(409, 'posted invoices are immutable');
    });
    return super.init();
  }
};

Solution · الحل 
// الحل: بنقف قبل الميزانية ما تخلص ونكمّل في run جديد من آخر checkpoint
const COST_PER_INVOICE = 30;
const LIMIT = 10_000;
const invoiceIds = Array.from({ length: 500 }, (_, i) => i + 1);

function scheduledRun(startIndex: number): number {
  let remaining = LIMIT;
  let index = startIndex;
  while (index < invoiceIds.length && remaining >= COST_PER_INVOICE) {
    remaining -= COST_PER_INVOICE;
    index++;
  }
  console.log(`run from ${startIndex}: processed ${index - startIndex}, remaining ${remaining}`);
  return index;
}

let checkpoint = 0;
let runs = 0;
while (checkpoint < invoiceIds.length) {
  checkpoint = scheduledRun(checkpoint);
  runs++;
}
console.log(`done in ${runs} runs`);

run from 0: processed 333, remaining 10
run from 333: processed 167, remaining 4990
done in 2 runs
Real output: two runs, 333 then 167. On real NetSuite you'd store the checkpoint in a record and use getRemainingUsage(), but Map/Reduce is still the better design (not run here).
الناتج الحقيقي: run-ين، 333 وبعدين 167. على NetSuite الحقيقي هتخزن الـ checkpoint في record وتستخدم getRemainingUsage()، بس Map/Reduce لسه التصميم الأحسن (not run here).

Cheat sheet · الخلاصة

  • SAP: S/4HANA is current, ECC older. ABAP plus RAP on-stack, CAP on BTP side-by-side. Clean core: released APIs only.
  • ECC: mainstream to end 2027, paid extended to end 2030 for EHP 6–8 (secondary sources; confirm with SAP).
  • 39% of about 35,000 is licensing, not go-live. A slope, not a cliff (inference).
  • CAP: CDS model, service projection, handlers in a same-named .js, OData for free. Decimals arrive as strings.
  • @sap/cds is under an SAP developer licence: productive use only on SAP's platforms.
  • SuiteScript 2.1: AMD, no Node built-ins, metered. Load 10, save 20. User Event 1,000, Scheduled 10,000. Map/Reduce per invocation.
  • Dynamics: AL with events (Business Central), X++ with Chain of Command (Finance and SCM). Overlayering is the abandoned fork.
  • Frappe: DocType metadata first, REST built in. ERPNext GPL-3.0, Frappe MIT, Odoo Community LGPL-3.
  • GitHub's "Latest" means most recently published, not newest line.
  • 80 people in Cairo: Odoo on base weights. Always state what flips it.
  • Language is a weak reason. Domain is paid once, platforms per vendor. Weigh local demand.
