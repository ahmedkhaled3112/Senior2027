Why this matters · ليه ده مهم

English

Frameworks shape your application, while libraries shape your data and your failures: React's rules, Query's cache keys, Zod's bundle cost, BullMQ's guarantees. Each of these looks like magic until you find the twenty lines that explain it. "Hooks can't be called conditionally" is really a statement about a linked list. "Two components share one fetch" is a Map keyed by a hash. Knowing the mechanism lets you predict behaviour, debug it, and answer the interview question "what does this do under the hood" from something you actually read. This lesson applies the method from lesson 33 to four libraries.

بالعامية

الـ frameworks بتشكّل الـ application، والـ libraries بتشكّل الـ data والأعطال بتاعتك: قواعد React، والـ cache keys في Query، وتكلفة الـ bundle في Zod، والضمانات بتاعة BullMQ. كل واحدة فيهم شكلها سحر لحد ما تلاقي العشرين سطر اللي بيشرحوها. "اتنين components بيشاركوا fetch واحد" هي Map متخزن فيها بالـ hash. لما تعرف الميكانيزم بتقدر تتوقع السلوك، وتعمله debug، وتجاوب سؤال الـ interview "دي بتشتغل إزاي من جوه" من حاجة إنت قريتها فعلًا. الدرس ده بيطبّق الطريقة بتاعة درس 33 على 4 libraries.

Part 1 — React: hooks as a linked list 🔴 Advancedالجزء 1 — React: الـ hooks كـ linked list

English

Read react-dom/cjs/react-dom-client.development.js at 19.3.1, the built file that actually runs. The source lives in packages/react-reconciler/src/ReactFiberHooks.js on GitHub, but line numbers differ, so this lesson cites the built file. At line 8192 mountWorkInProgressHook creates a plain object with a next field and appends it: workInProgressHook = workInProgressHook.next = hook. So a component's hooks are a singly linked list hanging off fiber.memoizedState. renderWithHooks at :7990 sets up the render, updateWorkInProgressHook at :8205 walks the same list on re-render, mountState at :8670 is one concrete hook, and dispatchSetState at :9506 is the setter.

This single structure is why the rules of hooks exist. The list has no names and no keys: position is identity. On re-render React moves one node forward for each hook call, so a conditional hook shifts every later hook onto the wrong node (the rules are taught in the hooks lesson). The run below proves the structure in real Chrome: it reads the private __reactFiber$… key from a DOM node, walks up to the component fiber, and follows memoizedState.next (the same trick as reading the real fiber tree). Notice that each kind of hook stores something different in the same slot: useState keeps the value, useRef the object, useMemo a [value, deps] pair, and useEffect an effect record.

Part 2 — React: reconciler, context, Suspense 🔴 Advancedالجزء 2 — React: الـ reconciler والـ context والـ Suspense

English

Reconciler. A component tree is a Composite: leaves and containers share one interface, and reconcileChildrenArray at :6979 and reconcileChildFibersImpl at :7205 diff children uniformly. The interesting part is how React walks that tree: performUnitOfWork at :19172 runs beginWork (:12052) for one fiber, then line 19199 either moves to the child or calls completeUnitOfWork, which follows sibling and return pointers and runs completeWork (:12883). There is no recursion: it is a loop over child, sibling and return, and that is what makes rendering interruptible. The run proves it: at depths 5 to 0 of a nested component tree, the JS stack depth is the same, 19, every time.

Context. pushProvider at :5760 pushes the old value onto a stack and writes the new one straight onto the context object (:5762). So reading is O(1): readContextForConsumer at :5962 reads _currentValue, with no walk up the tree. The value is scoped by push and pop, which the run shows as a=acme, b=globex, c=acme, and none afterwards. When a value changes, propagateContextChanges at :5800 finds the consumers.

Suspense. The README says "throw promise", and that is half true today. throwException at :9899 still checks typeof value.then === "function" at :9911, so throwing a thenable does suspend, and the run confirms it with no warning printed. But use() does something different: it throws a sentinel, SuspenseException (created at :28683, thrown at :6356), an ordinary Error whose message tells you not to catch it. The real promise is stored by trackUsedThenable (:6262) and fetched again by getSuspendedThenable (:6372) inside handleThrow (:18848, check at :18854). Why a sentinel? The real thenable stays out of user code, and a value React can recognise by identity lets it detect misuse: checkIfUseWrappedInAsyncCatch at :6382 tests for exactly that object. The run caught the sentinel and copied its message.

الـ Reconciler. شجرة الـ components هي Composite: الـ leaves والـ containers ليهم نفس الـ interface، وreconcileChildrenArray في :6979 وreconcileChildFibersImpl في :7205 بيعملوا diff للأولاد بنفس الطريقة. الجزء الحلو هو إزاي React بيمشي على الشجرة: performUnitOfWork في :19172 بيشغّل beginWork (:12052) لـ fiber واحد، وبعدها سطر 19199 يا إما بينزل للـ child يا إما بينادي completeUnitOfWork، اللي بيتبع pointers الـ sibling والـ return وبيشغّل completeWork (:12883). مفيش recursion: ده loop على child وsibling وreturn، وده اللي بيخلي الـ render ينفع يتقطع. والتشغيل بيثبت ده: عند المستويات من 5 لـ 0 في شجرة components متداخلة، عمق الـ JS stack ثابت 19 كل مرة.

Interview question "Why did React move from a recursive reconciler to Fiber?" A recursive walk keeps its position on the JS call stack, so it can't pause. Fiber stores position in child, sibling and return pointers, turning the walk into a loop that can stop and resume. In a real run the stack depth stayed at 19 frames at every depth of the tree.
"ليه React اتنقل من reconciler recursive لـ Fiber؟" الـ recursion بتحفظ مكانها في الـ JS call stack، فمتقدرش تقف. الـ Fiber بيحفظ المكان في pointers child وsibling وreturn، فالمشي بقى loop ينفع يقف ويكمّل. وفي تشغيل حقيقي، عمق الـ stack فضل 19 frame عند كل مستوى في الشجرة.

Interview question "Why does BullMQ use Lua scripts instead of a sequence of Redis commands?" Moving a job means several changes that must look like one: RPOPLPUSH, setting the lock, writing an event, updating the hash. In a Lua script no other client's command runs in between, so a job can never be seen in active without a lock. It is isolation, not rollback: if a script fails halfway, its earlier writes stay. A sequence of commands from Node would allow a crash or another worker to land between steps.
"ليه BullMQ بيستخدم Lua scripts بدل أوامر Redis ورا بعض؟" نقل الـ job فيه كذا تغيير لازم يبانوا كأنهم واحد: RPOPLPUSH، والـ lock، والـ event، وتحديث الـ hash. في Lua مفيش أمر من client تاني بيدخل في النص، فعمر الـ job ما هيتشاف في active من غير lock. ده isolation مش rollback: الـ script لو وقع في النص الـ writes اللي قبله بتفضل. أما أوامر ورا بعض من Node ممكن تسيب crash أو worker تاني يدخل بين الخطوات.

// الـ Subject: مجموعة listeners وsubscribe بيرجّع unsubscribe
class Subscribable<L extends Function> {
  protected listeners = new Set<L>();
  subscribe(listener: L): () => void {
    this.listeners.add(listener);
    return () => this.listeners.delete(listener);
  }
}

type Listener<T> = (state: { status: "pending" | "success"; data?: T }) => void;

// الـ Query: كيان واحد لكل key، فيه fetch واحد شغال بس
class Query<T> extends Subscribable<Listener<T>> {
  private state: Parameters<Listener<T>>[0] = { status: "pending" };
  private inflight?: Promise<void>;

  private readonly fn: () => Promise<T>;

  constructor(fn: () => Promise<T>) {
    super();
    this.fn = fn;
  }

  fetch(): Promise<void> {
    // لو فيه fetch شغال، رجّع نفس الـ promise بدل ما تعمل واحد جديد
    return (this.inflight ??= this.fn().then((data) => {
      this.state = { status: "success", data };
      this.inflight = undefined;
      for (const l of this.listeners) l(this.state);
    }));
  }
}

// الـ cache: Identity Map بالـ hash، زي build في queryCache.ts
class Cache {
  private queries = new Map<string, Query<unknown>>();
  build<T>(key: unknown[], fn: () => Promise<T>): Query<T> {
    const hash = JSON.stringify(key);
    let q = this.queries.get(hash) as Query<T> | undefined;
    if (!q) {
      q = new Query(fn);
      this.queries.set(hash, q as Query<unknown>);
    }
    return q;
  }
}

let fetches = 0;
const loadOrder = async () => {
  fetches++;

};

Cheat sheet · الخلاصة

  • React hooks are a singly linked list on fiber.memoizedState; position is identity, which is why order matters.
  • Fiber walks the tree with a loop over child, sibling and return, so the JS stack does not grow with tree depth; it stayed at 19 frames.
  • Context writes the value onto the context object and keeps a stack of old values, so a read is O(1).
  • Suspense: throwing a thenable still works at :9911, but use() throws the sentinel SuspenseException. Never swallow it.
  • Query: one Query per hash (Identity Map in build), observers on top, a tracking Proxy to limit re-renders.
  • Zod: check() returns a clone (immutable builder), brand() returns this, traits replace inheritance, and _zod.input/_zod.output are phantom.
  • With esbuild: import { z } 443.4 KB (64 locales), import * as z 75.9 KB, zod/mini 14.0 KB for the same schema. Rollup and Webpack can shake the named form, per Zod's source: measure yours.
  • BullMQ: a job is a serialisable Command; one job cost 4 Lua calls and 47 Redis commands. Lua gives isolation, not rollback.
  • Reading rule: 2–3 patterns per library, each as where / pattern / why / alternative, citations checked, because blog posts go stale.
