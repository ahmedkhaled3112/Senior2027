Why this matters · ليه ده مهم

English

These six libraries are where a "small ticket" becomes a production incident: an Arabic screen that says "11 invoices" in English because a translator skipped one plural form, a due date that shows the previous day for every customer in the US, a dashboard that takes 386 MB of heap, a backend that sends 2026-11-03T22:00:00.000Z for a date that was 4 November in the database.

A senior isn't expected to know every API here by heart. They are expected to pick the dependency, know what it costs in kilobytes and milliseconds, and know how it fails. Each part below gives the current version, a real run, and that trade-off. This ecosystem also moved: Temporal is native in Chrome and Firefox, <ViewTransition> is stable in React 19.3, and framer-motion is now motion.

بالعامية

الـ 6 مواضيع دول هما المكان اللي "ticket صغيرة" بتتحول فيه لـ production incident: شاشة عربي مكتوب فيها "11 invoices" بالإنجليزي عشان المترجم نسي شكل جمع واحد، تاريخ استحقاق بيبان يوم قبله لكل عميل في أمريكا، dashboard واكلة 386 MB من الـ heap، و backend بيبعت 2026-11-03T22:00:00.000Z لتاريخ كان 4 نوفمبر في الـ database.

محدش مستني من السنيور يحفظ كل الـ APIs دي. المطلوب منه يختار الـ dependency، ويعرف تكلفتها بالـ KB والـ ms، ويعرف بتقع إزاي. كل part تحت فيه الـ version الحالية، وتشغيل حقيقي، والـ trade-off ده. وكمان الدنيا اتغيرت: الـ Temporal بقى native في Chrome و Firefox، و <ViewTransition> بقى stable في React 19.3، و framer-motion بقى اسمه motion.

Part 1 — i18n: Arabic plurals, namespaces, RTL 🔴 Advancedالجزء 1 — الـ i18n: الجمع العربي، الـ namespaces، والـ RTL

English

Plurals are data, not an if. count === 1 ? a : b encodes English grammar. Arabic has six CLDR categories: zero, one, two, few, many, other. i18next 26 asks Intl.PluralRules for the category (the API itself is in the Intl lesson), then looks up key_category. The rules work on the last two digits: 3 to 10 is few, 11 to 99 is many, so 100 is other while 103 is few and 111 is many. You will not get that right by hand. English only has one and other, so a _zero key in English is never read.

Digits are a product decision. {{count}} prints the number as is. {{count, number}} goes through Intl.NumberFormat for the current language: ar-EG gives ٣ and ١٬٢٥٠٫٥٠, plain ar gave 3 and 1,250.50 on ICU 77. Use lng: "ar-EG" with load: "languageOnly": texts come from ar, formatters use ar-EG.

Namespaces and lazy loading. Split messages per feature and let a backend load each one through dynamic import(), so each namespace is its own chunk. useTranslation("orders") from react-i18next 17 suspends while that namespace loads, so it needs a <Suspense> above it. A language change re-renders every component using the hook.

Direction belongs on <html>. Listen to languageChanged and set lang and dir using i18next.dir(). Logical CSS (taught here) then flips the layout with no extra code. For the Next.js App Router, use next-intl 4 instead, because you also need server rendering and locale routing there: section 06 covers it.

Part 2 — Dates and timezones 🔴 Advancedالجزء 2 — التواريخ والـ timezones

English

The base is already taught: Date and its traps in the JS lesson, Intl.DateTimeFormat in the Intl lesson. If you only format, Intl costs 0 KB. Here is what's new for a UI: three different kinds of time that Date treats as one. Most date bugs come from storing one kind in the type meant for another.

date-fns 4 with @date-fns/tz. TZDate is a Date subclass that carries a zone, and the date-fns functions respect it: format prints that zone's clock, startOfDay gives midnight there, addDays keeps the wall clock across DST (that day really is 23 hours long). The trap: a string with no offset is parsed in the process's zone and not in the zone you passed. On a UTC server "2026-04-23T12:00:00" became 14:00 Cairo time, and under TZ=America/New_York it became 18:00 for the same line. Pass numbers or an explicit offset.

What changed: Temporal is native. It ran in Chrome 156 with no import, and typeof Temporal is undefined in Node 22.19 unless you pass --harmony-temporal, which you shouldn't rely on. MDN's compat data says Safari only has it in preview, so a polyfill is still needed for real traffic. Load the polyfill conditionally: on Chrome the run below never requests that chunk. Temporal gives you separate types for separate kinds of time, so an invalid date throws and a calendar date has no zone to get wrong.

Store UTC, render the user's zone, and pass that zone explicitly during SSR. If the server formats in its own zone and the client in the browser's, the HTML doesn't match: in the run below the server wrote 3 Nov 2026, 22:30 and the client computed 4 Nov 2026, 00:30, a different day, and React threw error #418 and re-rendered on the client (more in the hydration lesson). Keep the zone in the user's profile or a cookie so both sides agree.

The date-only bug. A due date is a calendar date. new Date("2026-11-04") parses it as UTC midnight, so anyone west of UTC sees 3 November, and you can't see that from Cairo. It can start on the backend too: pg parses a date column into a Date at the server's midnight, and JSON.stringify then sends 2026-11-03T22:00:00.000Z. Keep it a string through the API, with setTypeParser or due_date::text (that cast ran on PGlite, Postgres in WebAssembly, not on a server), and render it with parseISO or Temporal.PlainDate.

Part 3 — Charts: Recharts vs visx, and 50k points 🔴 Advancedالجزء 3 — الـ Charts: Recharts ضد visx، و 50 ألف نقطة

English

Recharts 3 gives you a chart in ten lines: components for bars, axes and tooltips, rendered to SVG. It peers on react-is: npm installs that for you, but if you ever use --legacy-peer-deps the page dies with Failed to resolve module specifier "react-is" (it happened here). visx 4 is the opposite: low-level pieces (scaleBand, Bar, AxisLeft) where you compute the layout yourself. You get full control and pay with your own code for tooltips, legends and responsiveness.

ResponsiveContainer needs a parent with a real size. It measures its parent, and height="100%" of a parent with no height is zero. In the run below that gave a wrapper 0 px tall, zero <svg> elements, and no console message at all in either a production or a development build. Silent failure: give the parent an explicit height.

SVG means one DOM node per mark. The table below is real: 50,000 bars in Recharts are 150,142 DOM nodes and about 386 MB of heap. Removing nodes alone isn't enough either: a line with dot={false} has only 142 nodes and still takes about 1 s and 76 MB, because the library processes every point. An 800 px chart can't show 50,000 points anyway, so reduce the data first: aggregate in SQL at the API, or downsample on the client keeping each bucket's minimum and maximum so spikes survive. That gives about 90 ms and 9 MB through the same Recharts line. Reach for Canvas (one node, about 30 to 60 ms) only when every raw point really has to be drawn, like a dense scatter plot.

Lazy-load the chart. Recharts weighs about 103 KB gzip here, so eagerly importing it takes first-load JS from 70 to 172 KB (the method is in the bundle lesson). Accessibility: by default Recharts makes the SVG role="application" with tabindex, so arrow keys walk the tooltip, but it has no name for a screen reader. A pattern that holds up: a <figure>, a role="img" wrapper whose aria-label states the insight, accessibilityLayer={false} so there's no focus stop inside an image, and a real <table> one click away. Colors are CSS variables, so a theme switch needs no chart code: the computed fill went from rgb(37, 99, 235) to rgb(122, 162, 255) when data-theme="dark" was set. Don't rely on color alone (contrast lesson).

export type Point = { t: number; v: number };

// الشاشة 800 pixel بس: لكل pixel خلّي أعلى وأقل قيمة، فالـ spikes مش بتضيع
export function downsampleMinMax(points: Point[], buckets: number): Point[] {
  const size = Math.ceil(points.length / buckets);
  const out: Point[] = [];
  for (let i = 0; i < points.length; i += size) {
    let min = points[i];
    let max = points[i];
    for (let j = i; j < Math.min(i + size, points.length); j++) {
      if (points[j].v < min.v) min = points[j];
      if (points[j].v > max.v) max = points[j];
    }
    out.push(...(min.t <= max.t ? [min, max] : [max, min]));
  }
  return out;
}

English

The package is now motion, imported from motion/react (14.9). framer-motion is published at the same version and motion depends on it, so old imports still work and the README's "Framer Motion" means the same library.

AnimatePresence solves removal. React deletes a node as soon as it leaves the tree, so an exit animation has nothing to animate. AnimatePresence keeps the child mounted until its exit finishes. The timeline below shows it: without it the row is gone at 5 ms, with it the row fades until about 300 ms. It must stay mounted itself, so it goes outside the condition. layout uses FLIP: measure the old and new positions, then animate with transform from the difference. Sorting took 3 or 4 layouts in 600 ms and no layout per frame.

Respect reduced motion in two places. useReducedMotion() is true under prefers-reduced-motion, but it only changes what you write with it: with the hook alone the sort still produced 47 distinct transforms. <MotionConfig reducedMotion="user"> turns off transform and layout animation: 2 distinct values, the row simply lands in place.

Cost. Why transform is cheap is in the compositor lesson; the table below shows it through Motion. Animating left on 50 elements caused 146 layouts, and x caused 1. Motion hands x and transform to the browser's Web Animations API (50 running animations, script time under 10 ms). Motion also retargets: reversing mid-flight at x=149 continued from there, with a largest jump of 2 px per frame.

Native <ViewTransition> is stable in React 19.3, with addTransitionType. It wraps the browser's View Transitions API and costs about 0.1 KB. Facts from running it: plain setState made 0 calls to startViewTransition, and the same update in startTransition made 1 call with types: ["reorder"]. Only Transitions, Suspense and useDeferredValue activate it. It must come before any DOM node in the part being inserted: wrapped in a <div>, my slide never ran. React doesn't honor reduced motion here: the API was still called and only my @media rule removed the animations. Three clicks in about 180 ms produced 2 calls, since React waits for the running transition and batches the rest. With the API deleted from the page, the list still updated, with no error and no animation, so older browsers degrade fine. It animates snapshots of a whole boundary rather than each element, and React's docs say it only works in the DOM today.

import { useState } from "react";
import { AnimatePresence, MotionConfig, motion, useReducedMotion } from "motion/react";

type Order = { id: string; total: number };

function OrderRow({ order, onRemove }: { order: Order; onRemove: (id: string) => void }) {
  // الـ hook ده بيغطي الحركة اللي إنت كاتبها بس، مش الـ layout
  const reduced = useReducedMotion();
  return (
    <motion.li
      layout
      data-id={order.id}
      initial={{ opacity: 0 }}
      animate={{ opacity: 1 }}
      exit={reduced ? { opacity: 0, transition: { duration: 0 } } : { opacity: 0, x: 40 }}
      transition={{ duration: 0.3 }}
    >
      {order.id}: {order.total}
      <button onClick={() => onRemove(order.id)}>Remove {order.id}</button>
    </motion.li>
  );
}

import { ViewTransition, addTransitionType, startTransition, useState } from "react";
import "./view-transitions.css";

type Order = { id: string; total: number };

export function OrdersBoard({ initial }: { initial: Order[] }) {
  const [orders, setOrders] = useState(initial);
  const [showDetails, setShowDetails] = useState(false);

  // ❌ من غير transition: الـ state بيتغير والـ ViewTransition مش بيشتغل خالص
  const sortInstantly = () => setOrders((list) => [...list].sort((a, b) => b.total - a.total));

  // ✅ جوه startTransition، والـ type بيوصل للـ browser
  const sortAnimated = () =>
    startTransition(() => {
      addTransitionType("reorder");
      setOrders((list) => [...list].sort((a, b) => b.total - a.total));
    });

  const toggleDetails = () =>
    startTransition(() => {
      addTransitionType(showDetails ? "close-details" : "open-details");
      setShowDetails((open) => !open);
    });

  // كل صف boundary لوحده، و React بيدّيه اسم فريد من غير ما تكتب name
  // والـ ViewTransition لازم ييجي قبل أي DOM node في الجزء اللي بيدخل
  return (
    <main>
      <button id="plain" onClick={sortInstantly}>Sort now</button>
      <button id="animated" onClick={sortAnimated}>Sort animated</button>
      <button id="details" onClick={toggleDetails}>Details</button>
      <ul>
        {orders.map((order) => (
          <ViewTransition key={order.id}>
            <li data-id={order.id}>{order.id}: {order.total}</li>
          </ViewTransition>
        ))}
      </ul>
      {showDetails && (
        <ViewTransition enter={{ "open-details": "slide-in", default: "none" }}>
          <aside id="panel">Order details</aside>
        </ViewTransition>
      )}
    </main>
  );
}

type Status = "new" | "packing" | "shipped";
type Board = Record<Status, string[]>;
type MoveCommand = { orderId: string; to: Status; index: number };

// (1) ده بيمثّل الـ API: بياخد أمر الحركة بس مش الـ board كله
let server: Board = { new: ["o1", "o2", "o3"], packing: ["o4"], shipped: [] };
const api = {
  async getBoard(): Promise<Board> {
    await new Promise((r) => setTimeout(r, 20));
    return structuredClone(server);
  },
  async moveOrder(cmd: MoveCommand): Promise<void> {
    await new Promise((r) => setTimeout(r, 60));
    // السيرفر هو اللي بيقرر: لو الطلب اتشحن قبل كده هيرجّع 409 وإحنا نرجّع الكارت
    const next = structuredClone(server);
    for (const list of Object.values(next)) {
      const at = list.indexOf(cmd.orderId);
      if (at >= 0) list.splice(at, 1);
    }
    next[cmd.to].splice(cmd.index, 0, cmd.orderId);
    server = next;
  },
};

function OrderCard({ id, index, column }: { id: string; index: number; column: Status }) {
  const { ref, isDragging } = useSortable({ id, index, type: "order", accept: "order", group: column });
  return (

      {id}
    </li>
  );
}

function Column({ id, orders }: { id: Status; orders: string[] }) {
  // (2) العمود نفسه droppable عشان تقدر تسيب كارت في عمود فاضي
  const { ref } = useDroppable({ id, type: "column", accept: "order", collisionPriority: CollisionPriority.Low });

        ))}
      </ul>
    </section>
  );
}

const findColumn = (board: Board, orderId: string) =>
  (Object.keys(board) as Status[]).find((status) => board[status].includes(orderId))!;

function Kanban() {
  const queryClient = useQueryClient();
  const { data } = useQuery({ queryKey: ["board"], queryFn: api.getBoard });
  // (3) الـ draft بيعيش طول السحبة بس، والـ cache مش بيتلمس غير عند الإفلات
  const [draft, setDraft] = useState<Board | null>(null);

  const moveOrder = useMutation({
    mutationFn: api.moveOrder,
    onMutate: async (cmd) => {
      await queryClient.cancelQueries({ queryKey: ["board"] });
      const previous = queryClient.getQueryData<Board>(["board"]);
      queryClient.setQueryData<Board>(["board"], (board) => {
        const next = structuredClone(board!);
        const from = findColumn(next, cmd.orderId);
        next[from] = next[from].filter((id) => id !== cmd.orderId);
        next[cmd.to].splice(cmd.index, 0, cmd.orderId);
        return next;
      });
      // (4) الـ draft يتشال في نفس اللحظة اللي الـ cache اتحدّث فيها، فمفيش frame بالشكل القديم
      setDraft(null);
      return { previous };
    },
    onError: (_err, _cmd, ctx) => queryClient.setQueryData(["board"], ctx?.previous),
    onSettled: () => queryClient.invalidateQueries({ queryKey: ["board"] }),
  });

  const board = draft ?? data;
  if (!board) return <p>Loading…</p>;

  return (
    <DragDropProvider
      onDragStart={() => setDraft(data!)}
      onDragOver={(event) => setDraft((current) => (current ? move(current, event) : current))}
      onDragEnd={(event) => {
        const orderId = String(event.operation.source?.id);
        const to = draft && findColumn(draft, orderId);
        const index = to ? draft[to].indexOf(orderId) : -1;
        // (5) الـ Escape بيخلّي canceled بـ true، ولو الكارت رجع مكانه مفيش داعي لـ request
        const unchanged = to && data![to][index] === orderId;
        if (event.canceled || !to || unchanged) setDraft(null);
        else moveOrder.mutate({ orderId, to, index });
      }}
    >
      <div style={{ display: "flex", gap: 12 }}>
        {(Object.keys(board) as Status[]).map((status) => (
          <Column key={status} id={status} orders={board[status]} />
        ))}
      </div>
    </DragDropProvider>
  );
}

const queryClient = new QueryClient();
createRoot(document.getElementById("root")!).render(
  <QueryClientProvider client={queryClient}>
    <Kanban />
  </QueryClientProvider>,
);

Interview question "How do you persist a kanban's order when two people move cards at once?" → Send one move command per card, not the whole board. The server validates the transition and returns 409 on a conflict. On the client: optimistic cache update with a snapshot, rollback on error, invalidate on settle so the other person's moves arrive. Store a fractional rank per row so a move touches one row instead of renumbering a column. Make the endpoint idempotent, because retries happen. And support keyboard dragging.

export const OrderSchema = z.object({
  id: z.string(),
  status: z.enum(["new", "packing", "shipped"]),
  totalPiastres: z.number().int().nonnegative(),
});
export type Order = z.infer<typeof OrderSchema>;

export const useOrderFilters = create<{ onlyOpen: boolean; toggle: () => void }>((set) => ({
  onlyOpen: false,
  toggle: () => set((state) => ({ onlyOpen: !state.onlyOpen })),
}));

export async function fetchOrders(baseUrl: string): Promise<Order[]> {
  const res = await fetch(`${baseUrl}/orders`);
  if (!res.ok) throw new Error(`orders: HTTP ${res.status}`);
  return z.array(OrderSchema).parse(await res.json());
}

// مفيش سطر هنا بيلمس DOM: مفيش window ولا document ولا localStorage
export function useOrders(baseUrl: string) {
  const onlyOpen = useOrderFilters((state) => state.onlyOpen);
  return useQuery({
    queryKey: ["orders", baseUrl],
    queryFn: () => fetchOrders(baseUrl),
    select: (orders) => (onlyOpen ? orders.filter((order) => order.status !== "shipped") : orders),
  });
}

بالعامية

نفس React و renderer مختلف: الدرس 1 ورّاك إن react مفيهاش كود DOM. والـ React Native 0.88.1 (محتاج react ^19.3.0) بيعمل views حقيقية في iOS و Android بدل عقد DOM. مفيش div، ولا ملف CSS، ولا cascade، ولا onClick: بتستخدم View و Text و Pressable و FlatList و StyleSheet. وكل نص لازم يبقى جوه Text.

الغلطة الشائعة: تفتكر إن "نفس React" معناها تعيد استخدام الـ components. اللي بيتعاد استخدامه هو الـ logic، مش الـ UI.

فين هستخدمه في شغلي؟ لو الشركة قررت تعمل app للمندوبين يتابعوا الطلبات: في monorepo خلّي packages/shared فيها الـ Zod schemas (نفس بتاعة الـ Node backend) و fetchOrders و useOrders. والويب بـ Next والموبايل بـ Expo بيستخدموها، وكل واحد بيكتب الـ UI بتاعه. وبكده لما حقل يتغير في الـ API، الـ schema بتتغير في مكان واحد وكل الأطراف تطلع compile errors.
Interview question "We have a React web app. Can we reuse it for mobile with React Native?" → We reuse logic rather than UI. Schemas, API clients, query hooks and stores move to a shared package, and the screens get rewritten because there's no DOM or CSS. Budget for native work too: builds, store releases, push notifications. If mobile web is enough, a PWA is cheaper. If the core feature is the device itself, consider native.
"عندنا React web app. ينفع نعيد استخدامها للموبايل بـ React Native؟" ← بنعيد استخدام الـ logic مش الـ UI. الـ schemas والـ API clients والـ query hooks والـ stores بتروح package مشتركة، والشاشات بتتكتب تاني لأن مفيش DOM ولا CSS. وحط في الميزانية الشغل الـ native: الـ builds، والنشر في الـ stores، والـ push notifications. ولو الموبايل ويب كفاية، الـ PWA أرخص. ولو الـ feature الأساسية هي الجهاز نفسه، فكر في native.

Solution · الحل 
type Messages = Record<string, string>;

const PLURAL_SUFFIX = /_(zero|one|two|few|many|other)$/;

// كل لغة ليها الأشكال بتاعتها، والمصدر هو Intl مش ذاكرتك
export function missingPluralForms(lng: string, messages: Messages): string[] {
  const required = new Intl.PluralRules(lng).resolvedOptions().pluralCategories;
  const bases = new Set(Object.keys(messages).filter((key) => PLURAL_SUFFIX.test(key)).map((key) => key.replace(PLURAL_SUFFIX, "")));
  const problems: string[] = [];
  for (const base of bases) {
    for (const form of required) {
      if (!(`${base}_${form}` in messages)) problems.push(`${lng}: ${base}_${form}`);
    }
  }
  return problems;
}

Solution · الحل 
import { Temporal } from "temporal-polyfill";

// الاستحقاق يوم في التقويم، والـ now لحظة: اللي بيربطهم هو الـ zone بتاع المستخدم
export function isOverdue(dueDate: string, now: string, userZone: string): boolean {
  const today = Temporal.Instant.from(now).toZonedDateTimeISO(userZone).toPlainDate();
  return Temporal.PlainDate.compare(today, Temporal.PlainDate.from(dueDate)) > 0;
}

import { downsampleMinMax, type Point } from "../lesson/downsample.ts";

// ❌ الطريقة السهلة: كل نقطة رقم كذا وخلاص
const everyNth = (points: Point[], n: number) => points.filter((_, i) => i % n === 0);

// 50 ألف نقطة ثابتة، وفيها spike واحد عند النقطة 31,337

// → minMax  : 1588 points, peak 9000

Cheat sheet · الخلاصة

  • i18next 26 + react-i18next 17: one key per sentence, six plural forms for Arabic (100 is other, 103 few, 111 many). A missing form silently falls back to English: check it in CI.
  • lng: "ar-EG" + load: "languageOnly" + {{count, number}} gives Arabic-Indic digits. Set lang and dir on <html> in languageChanged. The fallback language always downloads.
  • Three kinds of time: instant (timestamptz), calendar date (date, a string on the wire), wall clock plus zone name. Don't store one as another.
  • new Date("2026-11-04") and the pg driver both shift date-only values. Use parseISO, PlainDate, or setTypeParser. Test under a US timezoneId.
  • TZDate with a string lacking an offset parses in the process's zone: pass numbers. In SSR pass the zone explicitly, or hydration fails with #418.
  • Temporal: native in Chrome and Edge 144+, Firefox 139+, Node 26+; Safari preview only (check MDN). Load temporal-polyfill (19 KB) conditionally.
  • Charts: reduce the data first (SQL aggregate, or min-max downsample). 50k Recharts bars: 150,142 nodes and 386 MB. ResponsiveContainer needs a sized parent or it silently renders nothing. Lazy-load: 172 → 70 KB first load.
  • Recharts for standard dashboards, visx for the one custom chart. figure, role="img" with the insight, a real table, CSS variable colors.
  • Animation order: CSS (0 KB), <ViewTransition> (0.1 KB, needs a Transition), Motion LazyMotion (31 KB), full Motion (45 KB, for layout and interruption).
  • Animate transform, not left (1 layout vs 146). AnimatePresence goes outside the condition. MotionConfig reducedMotion="user" also covers layout; ViewTransition needs your own @media rule.
  • dnd-kit: @dnd-kit/core is stable, smaller, last published in 2024; @dnd-kit/react is active, pre-1.0, simpler. Pin it, wrap it, test it. Translate the live region text.
  • Kanban: draft during the drag, send a move command, optimistic cache with snapshot, rollback on 409. React Native: reuse logic, rewrite UI, start with Expo. Not run on a device here.
بالعامية
  • الـ i18next 26 مع react-i18next 17: مفتاح لكل جملة، و 6 أشكال جمع للعربي (الـ 100 other والـ 103 few والـ 111 many). الشكل الناقص بيقع على الإنجليزي في صمت، فاعمله check في الـ CI.
  • lng: "ar-EG" مع load: "languageOnly" و {{count, number}} بيدوا أرقام هندية. حط lang و dir على <html> في languageChanged. ولغة الـ fallback بتتحمّل دايمًا.
  • 3 أنواع وقت: لحظة (timestamptz)، تاريخ في التقويم (date و string في الـ API)، وساعة الحيطة مع اسم الـ zone. متخزنش نوع مكان نوع.
  • new Date("2026-11-04") والـ driver بتاع pg الاتنين بيزحزحوا التاريخ من غير وقت. استخدم parseISO أو PlainDate أو setTypeParser. واعمل test بـ timezoneId أمريكي.
  • الـ TZDate مع string من غير offset بيتقرا بتوقيت الـ process: ابعت أرقام. وفي الـ SSR ابعت الـ zone صريح، وإلا الـ hydration هيقع بـ 418.
  • الـ Temporal: native في Chrome و Edge من 144، و Firefox من 139، و Node من 26؛ و Safari في الـ preview بس (بص على MDN). حمّل temporal-polyfill (19 KB) بشرط.
  • الـ Charts: قلّل الـ data الأول (aggregate في SQL أو downsample بـ min-max). 50 ألف bar في Recharts يعني 150,142 عقدة و 386 MB. الـ ResponsiveContainer محتاج parent ليه مقاس، وإلا مش هيرسم حاجة في صمت. والـ lazy بينزّل أول تحميل من 172 لـ 70 KB.
  • الـ Recharts للـ dashboards العادية و visx للـ chart الخاص الواحد. figure و role="img" بالخلاصة وجدول حقيقي وألوان CSS variables.
  • ترتيب الـ Animation: CSS بـ 0 KB، وبعدها <ViewTransition> بـ 0.1 KB ومحتاج Transition، وبعدها Motion بـ LazyMotion بـ 31 KB، وبعدها Motion كامل بـ 45 KB لـ layout وقطع الحركة.
  • حرّك transform مش left (layout واحد قصاد 146). والـ AnimatePresence بره الشرط. و MotionConfig reducedMotion="user" بيغطي layout كمان، والـ ViewTransition محتاج @media منك.
  • الـ dnd-kit: @dnd-kit/core ثابت وأصغر وآخر نشر 2024، و @dnd-kit/react نشط وقبل 1.0 وأبسط. ثبّت الـ version ولفّه واعمله test. وترجم نصوص الـ live region.
  • الـ Kanban: draft طول السحبة، وابعت أمر حركة، و optimistic cache مع snapshot، و rollback عند 409. والـ React Native: أعد استخدام الـ logic، واكتب الـ UI من الأول، وابدأ بـ Expo. ومتشغلش على جهاز هنا.
