Why this matters · ليه ده مهم

English

Number theory sounds like competition material until you look at a backend: permission masks that outgrow 31 flags, subscriptions that renew on different cycles, card numbers and IBANs with check digits, public order numbers that shouldn't look sequential, a 64-bit ID from a partner's API, a coupon code that must not repeat. Each of these is a few lines of math, and each fails silently: no exception, just a wrong permission, a wrong remainder or an ID that points at someone else's order.

This lesson takes the tools one by one (bits, GCD, modular arithmetic, primes, BigInt, counting), runs each on a real backend case, and shows the exact point where JavaScript's 53-bit integers or 32-bit bitwise operators give the wrong answer, with the fix measured.

Part 1 — Bit tricks beyond the basics 🟡 Intermediateالجزء 1 — حيل الـ bits بعد الأساسيات

English

CS lesson 10 part 1 covers the operators, the 32-bit trap, a permissions mask with grant/revoke/has, Kernighan's popcount and a DAU bitmap. New here:

  • popcount three ways. The loop x &= x - 1 costs one step per set bit. SWAR ("SIMD within a register") counts in parallel inside one integer: add neighbouring bits into 2-bit fields, then 4-bit, then 8-bit, then sum the four bytes with one multiply: about 12 operations whatever the input. A 16-bit lookup table (64 KB, built once) answers with two loads. Measured on 10^7 values, each variant in its own process.
  • Lowest set bit x & -x (two's complement flips everything above the lowest 1), clear it with x & (x - 1) (so (x & (x - 1)) === 0 tests a power of two), and floor(log2 x) = 31 - Math.clz32(x) (count leading zeros of the 32-bit value).
  • Every submask of a mask: s = (s - 1) & mask walks all 2^k subsets of the k set bits, from the mask down to 0. Use it to test pricing under every combination of a tenant's enabled add-ons. Summed over all masks of n bits it is 3^n steps, the cost behind bitmask DP (lesson 10).

Permissions past 31 flags. A Number mask stops at bit 30 (bit 31 is the sign, and 1 << 32 is 1 again). Two ways out: a BigInt mask (same code shape, 1n << BigInt(bit), but every operation allocates) or a bitset on Uint32Array (word bit >>> 5, bit bit & 31; no limit, no allocation). In Postgres, a bigint column holds 64 flags, but it is signed: bit 63 overflows unless you convert with BigInt.asIntN(64, mask), and pg hands int8 back as a string, which you turn back with BigInt.asUintN(64, …). The SQL check is permissions & $1 = $1. Past 64, bit(128) works if both operands have the same length, or use a join table. The tests sit exactly on the edges: bits 0, 30, 31, 32, 63, 64, 127.

// (1) عدّ الـ bits بتلات طرق: loop، و SWAR، وجدول جاهز
export function popcountLoop(x: number): number {
  let c = 0;
  // الـ ⁦x & (x - 1)⁩ بتمسح أصغر bit قيمته 1، فاللفة بعدد الـ bits مش 32 مرة
  for (x >>>= 0; x !== 0; x = (x & (x - 1)) >>> 0) c++;
  return c;
}

// الـ SWAR: بنجمع الـ bits جوه نفس الرقم على مراحل (2 ثم 4 ثم 8 bits) من غير أي loop
export function popcountSwar(x: number): number {
  x = x - ((x >>> 1) & 0x55555555);
  x = (x & 0x33333333) + ((x >>> 2) & 0x33333333);
  x = (x + (x >>> 4)) & 0x0f0f0f0f;
  // الضرب في 0x01010101 بيجمع الـ 4 bytes في أعلى byte
  return Math.imul(x, 0x01010101) >>> 24;
}

// (3) كل الـ submasks بتاعة mask: كل تركيبة من الـ features المفعّلة (ومعاهم الصفر)
export function* submasks(mask: number): Generator<number> {
  for (let s = mask; ; s = (s - 1) & mask) {
    yield s;
    if (s === 0) return;
  }
}

// (1) أكتر من 31 permission بـ BigInt: كود قصير، وكل عملية بتعمل allocation
export const flag = (bit: number): bigint => 1n << BigInt(bit);
export const hasAll = (mask: bigint, required: bigint): boolean => (mask & required) === required;

// الـ Postgres bigint رقم signed من 64 bit: لازم نحوّل قبل الكتابة وبعد القراية
export const toPg = (mask: bigint): string => BigInt.asIntN(64, mask).toString();
export const fromPg = (value: string): bigint => BigInt.asUintN(64, BigInt(value));

// (2) نفس الفكرة بـ bitset على Uint32Array: أسرع، ومفيش حد لعدد الـ flags
export class PermSet {
  readonly words: Uint32Array;
  constructor(flags = 128) {
    this.words = new Uint32Array(Math.ceil(flags / 32));
  }
  grant(bit: number): this {
    // الـ ⁦bit >>> 5 =⁩ رقم الكلمة، والـ ⁦bit & 31 =⁩ مكانه جوه الكلمة
    this.words[bit >>> 5] |= 1 << (bit & 31);
    return this;
  }
  has(bit: number): boolean {
    return (this.words[bit >>> 5] & (1 << (bit & 31))) !== 0;
  }
  hasAll(required: PermSet): boolean {
    for (let i = 0; i < this.words.length; i++)
      if ((this.words[i] & required.words[i]) >>> 0 !== required.words[i]) return false;
    return true;
  }
}

Part 2 — GCD, LCM and extended Euclid 🟡 Intermediateالجزء 2 — الـ GCD والـ LCM و Euclid الممتد

English

Two everyday questions. Billing: one plan renews every 30 days, another every 45; their renewals line up every lcm(30, 45) = 90 days, the natural day to batch invoices. Packing: the largest box size that divides both 84 and 126 units with nothing left over is gcd(84, 126) = 42.

  • Euclid: gcd(a, b) = gcd(b, a mod b), iteratively, until b is 0.
  • LCM = a / gcd(a, b) × b. Divide first: the textbook a × b / gcd builds a product that can pass 2^53 even when the answer doesn't. Folding the plan periods in milliseconds (7, 13, 30, 45, 90 and 365 days) gives a "least common multiple" that isn't even an integer with the naive order.
  • Extended Euclid also returns x and y with a·x + b·y = gcd(a, b) (Bézout coefficients), by carrying the same quotients through two extra columns. If gcd(a, m) = 1, then a·x ≡ 1 (mod m), so x mod m is the modular inverse of a; if the gcd isn't 1 there is no inverse. Part 3 uses it to reverse an order-code transformation; part 6 uses Fermat's shortcut for prime moduli instead.
  • Cost: O(log min(a, b)) steps. The worst case is two consecutive Fibonacci numbers, where every quotient is 1 (Lamé's theorem): F(78) and F(77), the largest pair below 2^53, take 76 steps, about logφ of the input. Random pairs of the same size average about 31.
// خوارزمية Euclid من غير ⁦recursion: gcd(a, b) = gcd(b, a mod b)⁩
export function gcd(a: number, b: number): number {
  a = Math.abs(a), b = Math.abs(b);
  while (b !== 0) [a, b] = [b, a % b];
  return a;
}

// اقسم الأول وبعدين اضرب: الناتج الوسيط عمره ما يعدّي الناتج النهائي
export const lcm = (a: number, b: number): number => (a === 0 || b === 0 ? 0 : (a / gcd(a, b)) * b);

// خوارزمية Euclid الممتدة: بترجع g و x و y بحيث ⁦a·x + b·y = g (⁩معاملات Bézout)
export function extGcd(a: number, b: number): { g: number; x: number; y: number } {
  let [oldR, r] = [a, b], [oldX, x] = [1, 0], [oldY, y] = [0, 1];
  while (r !== 0) {
    const q = Math.floor(oldR / r);
    [oldR, r] = [r, oldR - q * r];
    [oldX, x] = [x, oldX - q * x];
    [oldY, y] = [y, oldY - q * y];
  }
  return { g: oldR, x: oldX, y: oldY };
}

// المعكوس: الرقم اللي لو ضربته في a الباقي يبقى 1، وموجود بس لو gcd(a, m) = 1
export function modInverse(a: number, m: number): number | undefined {
  const { g, x } = extGcd(((a % m) + m) % m, m);
  if (g !== 1) return undefined;
  // الـ x ممكن تطلع سالبة، فبنرجّعها للمدى من 0 لـ m - 1
  return ((x % m) + m) % m;
}

Part 3 — Modular arithmetic and fast exponentiation 🟡 Intermediateالجزء 3 — الـ modular arithmetic والأس السريع

English

Check digits are modular arithmetic you already depend on. Luhn (mod 10, used by card numbers): from the right, double every second digit, subtract 9 if it passes 9, and the total must be divisible by 10. It catches every single-digit typo and most swaps of neighbouring digits (not 09 ↔ 90). Below it runs on published test card numbers only. IBAN (ISO 13616, mod 97): move the first four characters to the end, turn letters into numbers (A = 10 … Z = 35), and the result mod 97 must be 1; the two check digits are 98 − (that number with "00" in their place) mod 97. An Egyptian-format IBAN is EG + 2 check digits + 25 digits = 29 characters, which becomes a 31-digit number: far past 2^53, so Number(numeric) % 97 is simply wrong. Either reduce it in 7-digit chunks (the remainder stays below 97, so each step is under 10^9) or use BigInt; both agree. The IBAN below is made of invented digits.

(a · b) mod m with Numbers goes wrong silently once the product passes 2^53: with m = 1,000,000,007 and a, b near 10^9 the product is near 10^18. Fix it with BigInt, or with a split multiplication that keeps every partial product under 2^48 (valid for m up to 2^32): mulMod. One use: public order numbers that don't look sequential, code = id × A mod P, reversed with A's inverse from part 2. It is obfuscation, not security: two leaked pairs give A away (the output shows code(2) = 2 × code(1)).

Fast exponentiation (square-and-multiply): write e in binary, square the base once per bit and multiply it into the result when the bit is 1. O(log e) multiplications instead of e: 45 for e = 10^9 + 5, 66 for 2^64. That makes ap−2 mod p (Fermat inverses, part 6), Miller–Rabin (part 4) and RSA possible. The toy RSA at the end uses the textbook primes 61 and 53: it shows the mechanics and is not secure (tiny primes, no padding); real code uses node:crypto.

// خوارزمية ⁦Luhn (mod 10)⁩: كل تاني رقم من اليمين بيتضاعف، ولو عدّى 9 نطرح 9
export function luhnValid(digits: string): boolean {
  if (!/^\d{2,19}$/.test(digits)) return false;
  let sum = 0;
  for (let i = 0; i < digits.length; i++) {
    let d = digits.charCodeAt(digits.length - 1 - i) - 48;
    if (i % 2 === 1) d = d * 2 > 9 ? d * 2 - 9 : d * 2;
    sum += d;
  }
  return sum % 10 === 0;
}

// ضرب modular بالـ Number من غير ما نعدّي ⁦2^53: m⁩ لحد ⁦2^32⁩، و a و b أقل من m
export function mulMod(a: number, b: number, m: number): number {
  // بنقسم b لنصين كل واحد 16 bit: كل حاصل ضرب جزئي أقل من ⁦2^48⁩
  const hi = Math.floor(b / 65536), lo = b % 65536;
  return (((a * hi) % m) * 65536 + a * lo) % m;
}

// الأس بالتربيع ⁦(square-and-multiply): O(log e)⁩ عملية ضرب بدل e
export function powModBig(base: bigint, exp: bigint, mod: bigint, counter?: { mults: number }): bigint {
  let result = 1n;
  base %= mod;
  while (exp > 0n) {
    if (exp & 1n) {
      result = (result * base) % mod;
      if (counter) counter.mults++;
    }
    base = (base * base) % mod;
    if (counter) counter.mults++;
    exp >>= 1n;
  }
  return result;
}

// نفس الخوارزمية بالـ Number و mulMod: أسرع بكتير طول ما الـ mod تحت ⁦2^32⁩
export function powMod(base: number, exp: number, mod: number): number {
  let result = 1;
  base %= mod;
  while (exp > 0) {
    if (exp % 2 === 1) result = mulMod(result, base, mod);
    base = mulMod(base, base, mod);
    exp = Math.floor(exp / 2);
  }
  return result;
}

Part 4 — Primes: sieve and primality tests 🟡 Intermediateالجزء 4 — الـ primes: الغربال واختبارات الأولية

English

Sieve of Eratosthenes. To list every prime up to n, cross out the multiples of each prime p starting at p² (smaller multiples were already crossed by a smaller factor), and only for p ≤ √n. O(n log log n) time, one byte per number in a Uint8Array: up to 10^7 that is 10 MB and about 0.13 s here, against about 2.4 s for trial division of every number (O(√n) each). Memory tricks, as concept: sieve odd numbers only (half), or one bit per number (1.25 MB for 10^7, 0.625 MB odd-only).

Segmented sieve. For primes in a window [lo, hi] far from 0, you only need the primes up to √hi, then cross out their multiples inside the window. [10^12, 10^12 + 10^6] takes a 1 MB window plus a 1 MB base sieve, about 33 ms, and finds 36,249 primes, close to the 10^6 / ln(10^12) ≈ 36,191 the prime number theorem predicts.

Testing one big number. Fermat: if n is prime, an−1 ≡ 1 (mod n). The converse fails: Carmichael numbers such as 561 = 3 · 11 · 17 pass for every base coprime to them. Miller–Rabin writes n − 1 = d · 2s and checks the chain ad, a2d, …; a prime can only reach 1 through n − 1, so reaching 1 any other way proves n composite. With random bases it's a Monte Carlo test (each base wrong with probability ≤ 1/4; lesson 16 part 3). With the first 12 primes, 2 to 37, as bases it is deterministic for every n below 3.18·10^23, which covers all 64-bit numbers (Wikipedia's Miller–Rabin article, after Sorenson and Webster). Nine bases are not enough: 3,825,123,056,546,413,051 fools 2 to 23.

In backend work primes show up rarely: hash table capacities (a prime modulus spreads keys that share a pattern; most modern tables, V8's Map included, use power-of-two bucket counts and rely on a hash that mixes the bits instead, see section 04 · 1.5, Hash Tables from Scratch), moduli for rolling hashes (lesson 15 part 4), and keys, where you use crypto.generatePrime / crypto.checkPrime and never your own code. Here OpenSSL's checkPrimeSync is the oracle for the tests.

import { powModBig } from "./modular.ts";

// غربال Eratosthenes: byte لكل رقم، و 1 معناها ⁦composite. O(n log log n)⁩
export function sieve(n: number): Uint8Array {
  const composite = new Uint8Array(n + 1);
  composite[0] = composite[1] = 1;
  for (let p = 2; p * p <= n; p++) {
    if (composite[p]) continue;
    // نبدأ من ⁦p²⁩ لأن أي مضاعف أصغر اتشطب قبل كده بعامل أصغر
    for (let m = p * p; m <= n; m += p) composite[m] = 1;
  }
  return composite;
}

// القسمة على كل الأرقام لحد جذر n: تكلفتها ⁦O(√n)⁩ للرقم الواحد
export function isPrimeTrial(n: number): boolean {
  if (n < 2) return false;
  if (n % 2 === 0) return n === 2;
  for (let d = 3; d * d <= n; d += 2) if (n % d === 0) return false;
  return true;
}

// الغربال المقسّم: أولي الأرقام في ⁦[lo, hi]⁩ بس، بالـ primes لحد جذر hi
export function segmentedSieve(lo: number, hi: number): number[] {
  const base = sieve(Math.floor(Math.sqrt(hi)) + 1);
  const composite = new Uint8Array(hi - lo + 1);
  for (let p = 2; p < base.length; p++) {
    if (base[p]) continue;
    // أول مضاعف لـ p جوه الشريحة (ومش أقل من ⁦p²⁩)
    const first = Math.max(p * p, Math.ceil(lo / p) * p);
    for (let m = first; m <= hi; m += p) composite[m - lo] = 1;
  }
  const out: number[] = [];
  for (let i = 0; i < composite.length; i++) if (!composite[i] && lo + i > 1) out.push(lo + i);
  return out;
}

// اختبار Fermat: لو a^(n - 1) mod n مش 1 يبقى composite أكيد — بس العكس مش مضمون
export const fermatPasses = (n: bigint, a: bigint): boolean => powModBig(a, n - 1n, n) === 1n;

// أول 12 prime كـ bases: كفاية تكون إجابة أكيدة (deterministic) لكل n أقل من ⁦2^64⁩
export const BASES_64 = [2n, 3n, 5n, 7n, 11n, 13n, 17n, 19n, 23n, 29n, 31n, 37n];

export function millerRabin(n: bigint, bases: readonly bigint[] = BASES_64): boolean {
  if (n < 2n) return false;
  for (const p of BASES_64) if (n % p === 0n) return n === p;
  // اكتب ⁦n - 1 = d · 2^s⁩ و d فردي
  let d = n - 1n, s = 0;
  while ((d & 1n) === 0n) d >>= 1n, s++;
  next: for (const a of bases) {
    let x = powModBig(a, d, n);
    if (x === 1n || x === n - 1n) continue;
    for (let r = 1; r < s; r++) {
      x = (x * x) % n;
      if (x === n - 1n) continue next;
    }
    // الـ a هنا شاهد (witness) إن n مش prime
    return false;
  }
  return true;
}

Part 5 — BigInt, overflow and IDs 🟢 Basicالجزء 5 — الـ BigInt والـ overflow والـ IDs

English

The basics are in JS lesson 02 parts 3–4 (floating point, BigInt syntax) and Databases lesson 04 part 1 (numeric types and money). New here: what happens at the boundaries of a Node service, measured.

  • 53 bits. A double holds every integer up to 2^53 = 9,007,199,254,740,992; Number.MAX_SAFE_INTEGER is one less. Above it, only every 2nd, 4th, … integer exists: 2 ** 53 + 1 === 2 ** 53 is true.
  • JSON bodies. A partner sends {"orderId":12345678901234567891} (a 64-bit ID, like Snowflake IDs, System Design lesson 31 part 5). JSON.parse rounds it to the nearest double and prints 12345678901234567000, with no error. Fixes, best first: the producer sends IDs as strings; or read the exact digits with JSON.parse source text access, the reviver's third argument context.source (a TC39 Stage 4 feature; works in Node 22.19 here); and write them back with JSON.rawJSON.
  • BigInt doesn't mix. JSON.stringify(1n) throws TypeError, and 10n + 1 throws too. Convert at the edges, on purpose.
  • Postgres bigint comes out of pg as a string by default (and so does count(*), which is bigint). That's the safe default: Number(id) silently turns …993 into …992. pg.types.setTypeParser(20, BigInt) exists, but it is process-wide and then every res.json(row) throws. Keep IDs as strings end to end; parse to BigInt only to do arithmetic.
  • Money vs counts. Integer piastres in a Number are exact up to 2^53 piastres ≈ 90 trillion EGP: plenty for amounts. Counts are a different story: the number of ways to pay 10,000 EGP in coins is about 5.8·10^18 (lesson 09 part 5), past 2^53, so use BigInt or a modulus.
  • BigInt cost. The same multiply-add-mod loop ran about 12× slower with BigInt. Fine for IDs and occasional big math, not for hot loops.

Part 6 — Counting: nCr mod p and collision odds 🔴 Advancedالجزء 6 — العدّ: nCr mod p واحتمال التكرار

English

nCr mod p. Counting answers grow past 2^53 quickly, so problems (and some APIs) ask for them modulo a prime p = 1,000,000,007. Precompute fact[i] for i ≤ n and the inverse of fact[n] with Fermat (ap−2 mod p, part 3), then walk down: inv[i−1] = inv[i] · i. O(n + log p) once, then C(a, r) = fact[a] · inv[r] · inv[a−r] in O(1). For n = 10^6 that's about 60 ms. Watch the bounds: in the table loops one factor is at most 10^6, so the product stays below 2^50 and plain * is exact; in the final product both factors can be near 2^30, so it needs mulMod. Fermat needs p prime and p > n. Pascal's triangle (C(n, r) = C(n−1, r−1) + C(n−1, r)) only adds, so it works for any modulus, but it is O(n²): 5,000 rows took about 49 ms, so 10^6 rows would take about half an hour.

How long must a coupon code be? With an alphabet of 32 symbols (Crockford base32: no I, L, O, U, so nobody misreads them) and length L there are N = 32L codes. Issuing n random codes, the birthday bound gives P(at least one duplicate) ≈ 1 − e−n²/2N, and about n²/2N duplicate pairs. Compute it with -Math.expm1(-x): for tiny x, 1 - Math.exp(-x) loses digits. The table answers the product question directly, and the seeded simulation confirms the formula. Two lessons from running it: the length only sets how often you retry, so a UNIQUE constraint plus retry-on-conflict is still required; and the generator matters: mulberry32, a 32-bit-state PRNG common in snippets, produced 60.5% duplicates where the formula says 52.5%, because it repeats 32-bit outputs about twice as often as a uniform source (4,529 repeats in 2^22 calls vs 2,048 expected). Real codes come from crypto.randomInt (lesson 16 part 5), which is also what makes them hard to guess: with n codes live, each guess hits with probability n / N.

Why brute force dies. Bundles of 3 products out of 20: C(20, 3) = 1,140, enumerate freely. Delivery orders for n stops: n!. 10! takes 0.04 s at 108 routes per second, 15! takes 3.6 hours, 20! = 2.4·1018 takes 771 years and doesn't even fit in a Number. That is where bitmask DP takes over (lesson 10 part 4).

import { mulMod, powMod } from "./modular.ts";

export const MOD = 1_000_000_007;

// الـ factorials ومعكوساتها مرة واحدة ⁦O(n)⁩، وبعدها أي nCr في ⁦O(1)⁩
export function binomialTable(n: number, p = MOD) {
  const fact = new Uint32Array(n + 1), inv = new Uint32Array(n + 1);
  fact[0] = 1;
  // هنا الضرب العادي آمن: fact أقل من ⁦2^30⁩ و i أقل من ⁦2^20⁩، فالناتج تحت ⁦2^50⁩
  for (let i = 1; i <= n; i++) fact[i] = (fact[i - 1] * i) % p;
  // معكوس Fermat: a^(p - 2) mod p، لأن p أولي (من الجزء 3)
  inv[n] = powMod(fact[n], p - 2, p);
  for (let i = n; i > 0; i--) inv[i - 1] = (inv[i] * i) % p;
  // هنا الرقمين ممكن يقربوا من ⁦2^30⁩، فلازم mulMod
  return (a: number, r: number): number =>
    r < 0 || r > a ? 0 : mulMod(mulMod(fact[a], inv[r], p), inv[a - r], p);
}

// مثلث Pascal: كل خانة = مجموع الخانتين اللي فوقها — جمع بس، بس ⁦O(n²)⁩
export function pascalRow(n: number, p = MOD): Uint32Array {
  const row = new Uint32Array(n + 1);
  row[0] = 1;
  for (let i = 1; i <= n; i++) for (let r = i; r > 0; r--) row[r] = (row[r] + row[r - 1]) % p;
  return row;
}

// مولّدين بـ ⁦seed: sfc32 (⁩حالته 128 bit) و ⁦mulberry32 (⁩حالته 32 bit، ومنتشر في الـ snippets)
function sfc32(a: number, b: number, c: number, d: number): () => number {
  return () => {
    const t = (((a + b) | 0) + d) | 0;
    d = (d + 1) | 0;
    a = b ^ (b >>> 9);
    b = (c + (c << 3)) | 0;
    c = (c << 21) | (c >>> 11);
    c = (c + t) | 0;
    return (t >>> 0) / 4294967296;
  };
}
function mulberry32(seed: number): () => number {
  let s = seed >>> 0;
  return () => {
    s = (s + 0x6d2b79f5) >>> 0;
    let t = Math.imul(s ^ (s >>> 15), s | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

function simulate(rnd: () => number, len: number, n: number, trials: number): number {
  const N = ALPHABET ** len;
  let hits = 0;
  for (let t = 0; t < trials; t++) {
    const seen = new Set<number>();
    for (let i = 0; i < n; i++) {
      const code = Math.floor(rnd() * N);
      if (seen.has(code)) { hits++; break; }
      seen.add(code);
    }
  }
  return hits / trials;
}

الـ nCr mod p: إجابات العدّ بتعدّي 2^53 بسرعة، فالمسائل (وبعض الـ APIs) بتطلبها mod prime زي p = 1,000,000,007. احسب fact[i] لكل i ≤ n، ومعكوس fact[n] بـ Fermat (ap−2 mod p من الجزء 3)، وبعدين انزل: inv[i−1] = inv[i] · i. التكلفة O(n + log p) مرة واحدة، وبعدها C(a, r) = fact[a] · inv[r] · inv[a−r] في O(1). لـ n = مليون حوالي 60 ms. وخلي بالك من الحدود: في الـ loops واحد من الرقمين أقصاه مليون فالناتج تحت 2^50 والضرب العادي مضبوط، أما في الضرب الأخير الرقمين ممكن يقربوا من 2^30 فلازم mulMod. والـ Fermat محتاج p أولي و p أكبر من n. مثلث Pascal (C(n, r) = C(n−1, r−1) + C(n−1, r)) بيجمع بس، فبينفع مع أي modulus، بس O(n²): 5,000 صف خدوا حوالي 49 ms، فمليون صف هياخدوا حوالي نص ساعة.

الكوبون لازم يبقى طوله كام؟ بـ 32 رمز (Crockford base32: من غير I و L و O و U عشان محدش يقراهم غلط) وطول L عندك N = 32L كود. لو طلّعت n كود عشوائي، الـ birthday bound بيقول احتمال تكرار واحد على الأقل ≈ 1 − e−n²/2N، وعدد الأزواج المتكررة حوالي n²/2N. احسبها بـ -Math.expm1(-x)، لأن 1 - Math.exp(-x) بيضيّع أرقام لما x صغيرة جدًا. الجدول بيجاوب سؤال الـ product مباشرة، والمحاكاة بـ seed أكدت المعادلة. ودرسين من التشغيل: الطول بيحدد بس إنت هتعمل retry قد إيه، فلازم برضه UNIQUE constraint و retry لما يحصل conflict؛ والـ generator بيفرق: mulberry32 (مولّد حالته 32 bit ومنتشر في الـ snippets) طلّع 60.5% تكرار والمعادلة بتقول 52.5%، لأنه بيكرر قيم الـ 32 bit حوالي ضعف المصدر الـ uniform (4,529 تكرار في 2^22 call قصاد 2,048 متوقع). الأكواد الحقيقية بتطلع من crypto.randomInt (الدرس 16 الجزء 5)، وده كمان اللي بيصعّب تخمينها: لو فيه n كود شغال، كل تخمين بيصيب باحتمال n / N.

ليه الـ brute force بيموت: bundles من 3 منتجات من 20: C(20, 3) = 1,140، لف عليهم براحتك. ترتيب التوصيل لـ n محطة: n!. الـ 10! بتاخد 0.04 ثانية لو بتجرب 108 route في الثانية، والـ 15! بتاخد 3.6 ساعة، والـ 20! = 2.4·1018 بتاخد 771 سنة ومش بتتخزن في Number أصلًا. وهنا الـ bitmask DP بيستلم (الدرس 10 الجزء 4).

// أقل طول كود يخلّي احتمال أي تكرار ⁦≤ target⁩، واحتمال إن مهاجم يخمّن كود صح ⁦≤ guessTarget⁩
function codeLength(issued: number, target: number, guesses: number, guessTarget: number, alphabet = 32): number {
  // التكرار: ⁦n²/2N ≤ -ln(1 - target)  ⇒  N ≥ n² / (2 · -ln(1 - target))⁩
  const forCollisions = (issued * issued) / (2 * -Math.log1p(-target));
  // التخمين: كل تخمين بيصيب بنسبة n/N، و G تخمين ⁦≈ G·n/N⁩
  const forGuessing = (guesses * issued) / guessTarget;
  return Math.ceil(Math.log(Math.max(forCollisions, forGuessing)) / Math.log(alphabet));
}

Cheat sheet · الخلاصة

  • popcount: the x &= x - 1 loop costs one step per set bit; SWAR or a 16-bit table is about 8–9× faster; toString(2) roughly 700× slower. Benchmark each variant in its own process.
  • x & -x = lowest set bit; x & (x - 1) clears it (0 ⇒ power of two); 31 - Math.clz32(x) = floor(log2 x); s = (s - 1) & mask walks all submasks (3^n over all masks).
  • Past 31 flags: BigInt mask or Uint32Array bitset (≈2× faster). Postgres bigint is signed: asIntN(64) in, asUintN(64) out; pg returns it as a string. Past 64: bit(n) of equal lengths or a join table. Test bits 31, 32, 63.
  • Euclid is O(log min(a, b)), worst case consecutive Fibonacci (76 steps below 2^53). LCM = a / gcd × b. Extended Euclid gives Bézout coefficients and the modular inverse when gcd = 1.
  • Check digits: Luhn (mod 10), IBAN (mod 97) in 7-digit chunks or BigInt; Number() of a 31-digit string gives a wrong remainder.
  • (a * b) % m loses bits past 2^53: BigInt or mulMod (m ≤ 2^32). Normalise negatives with ((a % m) + m) % m.
  • Square-and-multiply: O(log e), 66 multiplications for e = 2^64. Toy RSA shows the idea; real keys come from node:crypto.
  • Sieve to 10^7: 10 MB, ≈0.13 s vs ≈2.4 s by trial division; segmented sieve for a window far from 0. Fermat is fooled by Carmichael numbers (561); Miller–Rabin with bases 2…37 is exact for 64-bit; in production, crypto.checkPrime.
  • Numbers are exact to 2^53: JSON.parse rounds 64-bit IDs silently. Send IDs as strings, or use context.source / JSON.rawJSON. BigInt doesn't serialize or mix with Number and was ≈12× slower in a loop.
  • nCr mod p: factorials + Fermat inverse, O(n) once then O(1) (≈60 ms for 10^6); Pascal works for any modulus but is O(n²).
  • Birthday bound: P ≈ 1 − e^(−n²/2N), computed with expm1. Base32 × 10 chars → 4.3% at 10^7 codes. Always UNIQUE + retry, codes from crypto.randomInt; a weak PRNG shows up as extra collisions.
بالعامية
  • الـ popcount: الـ loop بـ x &= x - 1 بيلف مرة لكل bit شغال؛ الـ SWAR أو جدول الـ 16 bit أسرع من 8 لـ 9 مرات؛ و toString(2) أبطأ حوالي 700 مرة. وقيس كل variant في process لوحده.
  • x & -x = أصغر bit شغال؛ x & (x - 1) بيمسحه (لو طلع 0 يبقى power of two)؛ 31 - Math.clz32(x) = floor(log2 x)؛ و s = (s - 1) & mask بيلف على كل الـ submasks (3^n على كل الـ masks).
  • بعد 31 flag: BigInt mask أو bitset على Uint32Array (أسرع حوالي مرتين). الـ bigint في Postgres signed: asIntN(64) وإنت داخل و asUintN(64) وإنت خارج، والـ pg بيرجّعه string. بعد 64: bit(n) بنفس الطول أو join table. واختبر bits 31 و 32 و 63.
  • الـ Euclid تكلفته O(log min(a, b))، وأسوأ حالة رقمين Fibonacci ورا بعض (76 خطوة تحت 2^53). الـ LCM = a / gcd × b. والـ extended Euclid بيدّي معاملات Bézout والـ modular inverse لما الـ gcd = 1.
  • الـ check digits: Luhn (mod 10) و IBAN (mod 97) على أجزاء من 7 أرقام أو BigInt؛ و Number() لـ string من 31 رقم بيدّي باقي غلط.
  • الـ (a * b) % m بيضيّع bits فوق 2^53: استخدم BigInt أو mulMod (لحد m = 2^32). وظبّط السالب بـ ((a % m) + m) % m.
  • الأس السريع: O(log e)، يعني 66 ضربة لـ e = 2^64. والـ RSA اللعبة بتوري الفكرة بس؛ المفاتيح الحقيقية من node:crypto.
  • الغربال لحد 10^7: 10 MB و ≈0.13 ثانية قصاد ≈2.4 ثانية بالقسمة؛ والغربال المقسّم لشباك بعيد عن الصفر. الـ Fermat بيتضحك عليه بأرقام Carmichael (561)؛ الـ Miller–Rabin بالـ bases من 2 لـ 37 مضبوط لأي رقم 64 bit؛ وفي production استخدم crypto.checkPrime.
  • الـ Number مضبوط لحد 2^53 بس: JSON.parse بيقرّب الـ IDs اللي 64 bit في صمت. ابعت الـ IDs كـ strings، أو استخدم context.source و JSON.rawJSON. الـ BigInt مبيتعملوش serialize ومبيختلطش بـ Number، وكان أبطأ حوالي 12 مرة في loop.
  • الـ nCr mod p: factorials ومعكوس Fermat، O(n) مرة واحدة وبعدها O(1) (حوالي 60 ms لمليون)؛ ومثلث Pascal بينفع مع أي modulus بس O(n²).
  • الـ birthday bound: P ≈ 1 − e^(−n²/2N)، واحسبها بـ expm1. base32 بـ 10 حروف ← 4.3% عند 10 مليون كود. ودايمًا UNIQUE و retry، والأكواد من crypto.randomInt؛ والـ PRNG الضعيف بيبان في صورة تكرار زيادة.
