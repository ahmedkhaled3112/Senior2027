Why this matters · ليه ده مهم

English

Every delivery ETA, every "nearest branch", every courier route and every pricing graph with fees is a shortest-path problem, and each one has a different right algorithm. Pick by the edge weights: all equal → BFS (lesson 11); 0 or 1 → 0-1 BFS; non-negative → Dijkstra, or A* when you have a target and a good estimate; negative → Bellman–Ford; many pairs on a small graph → Floyd–Warshall. Picking wrong doesn't crash: it returns a plausible, wrong number, like a route 40% slower than necessary or an arbitrage alarm caused by a rounding error.

The algorithm itself is in CS lesson 07, part 5. Here every variant runs on a synthetic, seeded street grid of 90,000 intersections, is checked against an oracle, and is measured in operations as well as milliseconds.

بالعامية

أي ETA للتوصيل، أي "أقرب فرع"، أي route لمندوب، وأي graph أسعار فيه رسوم، كلها مسائل shortest path، وكل واحدة ليها الـ algorithm الصح بتاعها. اختار حسب الـ weights: كلهم متساويين ← BFS (الدرس 11)، 0 أو 1 ← 0-1 BFS، مفيش سالب ← Dijkstra، أو A* لو عندك target وتقدير كويس للمسافة، فيه سالب ← Bellman–Ford، أزواج كتير على graph صغير ← Floyd–Warshall. الاختيار الغلط مبيوقّعش البرنامج: بيرجّع رقم شكله منطقي وهو غلط، زي route أبطأ من اللازم بـ 40%، أو إنذار arbitrage سببه rounding error.

Part 1 — Dijkstra with a binary heap 🟡 Intermediateالجزء 1 — الـ Dijkstra بـ binary heap

English

The test bed: a seeded 300 × 300 grid inspired by Cairo (not a real map): 90,000 intersections and 341,064 directed street segments in CSR form, with travel times in whole seconds. A normal block costs 20 s times a congestion factor between 1 and 2.5, about 10% of streets are one-way, and every 50th row is a one-way express corridor at 8 s per block (it matters in part 5).

There are two ways to handle "I found a shorter distance to v":

  • Lazy deletion: push a new (dist, v) pair and leave the old one in the heap; when an entry pops with a key larger than dist[v], it's stale, so skip it. Plain arrays, simple code, heap size up to E.
  • Indexed priority queue with decrease-key (built in section 04 · lesson 09): each node sits in the heap at most once, pos[v] records its slot, and an improvement sifts it up in place. No stale entries, heap size at most V, but more bookkeeping.

On the full city, lazy did 102,638 pushes and 12,638 stale pops; indexed did 90,000 inserts and 12,647 decrease-keys (the counts differ slightly because the two heaps break ties differently). Time was the same within a few percent in every run (≈12–47 ms depending on machine load). Lazy deletion is the usual default in practice; decrease-key pays off when memory for E heap entries matters or the graph is dense.

Why a settled node is final: with non-negative weights, when u is popped with the smallest key d, every other path to u must leave the settled set through some frontier node whose key is already ≥ d, and adding non-negative edges can't make it smaller. That's also why you may stop when the target is popped (6,038 pops instead of 102,638 for one 19-minute trip), but not when it is first pushed: that's mistake 1. Path reconstruction is the same parent array as BFS. The oracle is Bellman–Ford (part 3), which assumes nothing about weights: a property test compares both Dijkstra versions, full and with early exit, against it on 3,000 random graphs.

// الـ CSR بـ weights: نفس فكرة الدرس 11، ومعاها Float64Array للتكلفة (ثواني، جنيهات، أو ⁦-log⁩ للسعر)
export interface WGraph {
  readonly n: number;
  readonly offsets: Int32Array;
  readonly targets: Int32Array;
  readonly weights: Float64Array;
}

export function wgraph(n: number, from: ArrayLike<number>, to: ArrayLike<number>, w: ArrayLike<number>): WGraph {
  const offsets = new Int32Array(n + 1);
  for (let i = 0; i < from.length; i++) offsets[from[i] + 1]++;
  for (let v = 0; v < n; v++) offsets[v + 1] += offsets[v];
  const targets = new Int32Array(from.length);
  const weights = new Float64Array(from.length);
  const next = offsets.slice(0, n);
  for (let i = 0; i < from.length; i++) {
    const k = next[from[i]]++;
    targets[k] = to[i];
    weights[k] = w[i];
  }
  return { n, offsets, targets, weights };
}

// امشي على الـ parent من t لحد s واقلب
export function pathTo(parent: Int32Array, s: number, t: number): number[] {
  const path = [t];
  for (let v = t; v !== s; v = parent[v]) path.push(parent[v]);
  return path.reverse();
}
// (1) ده heap عادي لأزواج (key, node): بيقبل نسخ مكررة من نفس الـ ⁦node (⁩عشان الـ lazy deletion)
export class PairHeap {
  keys = new Float64Array(1024);
  vals = new Int32Array(1024);
  size = 0;
  // بعد كل pop: الـ key بتاع العنصر اللي طلع
  topKey = 0;
  push(key: number, val: number): void {
    if (this.size === this.keys.length) {
      const k = new Float64Array(this.size * 2);
      k.set(this.keys);
      this.keys = k;
      const v = new Int32Array(this.size * 2);
      v.set(this.vals);
      this.vals = v;
    }
    let i = this.size++;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (this.keys[p] <= key) break;
      this.keys[i] = this.keys[p];
      this.vals[i] = this.vals[p];
      i = p;
    }
    this.keys[i] = key;
    this.vals[i] = val;
  }
  pop(): number {
    const { keys, vals } = this;
    const val = vals[0];
    this.topKey = keys[0];
    const n = --this.size;
    const k = keys[n];
    const v = vals[n];
    let i = 0;
    for (;;) {
      let c = 2 * i + 1;
      if (c >= n) break;
      if (c + 1 < n && keys[c + 1] < keys[c]) c++;
      if (keys[c] >= k) break;
      keys[i] = keys[c];
      vals[i] = vals[c];
      i = c;
    }
    keys[i] = k;
    vals[i] = v;
    return val;
  }
}

// (2) الـ indexed priority queue: كل node مرة واحدة بالكتير، و ⁦pos[v]⁩ مكانها جوه الـ heap عشان الـ decrease-key
export class IndexedMinPQ {
  readonly pos: Int32Array;
  readonly heap: Int32Array;
  readonly key: Float64Array;
  size = 0;
  constructor(n: number) {
    this.pos = new Int32Array(n).fill(-1);
    this.heap = new Int32Array(n);
    this.key = new Float64Array(n);
  }
  insert(v: number, k: number): void {
    this.key[v] = k;
    this.heap[this.size] = v;
    this.up(this.size++);
  }
  decreaseKey(v: number, k: number): void {
    this.key[v] = k;
    this.up(this.pos[v]);
  }
  popMin(): number {
    const top = this.heap[0];
    const last = this.heap[--this.size];
    this.pos[top] = -1;
    if (this.size > 0) {
      this.heap[0] = last;
      this.down(0);
    }
    return top;
  }
  private up(i: number): void {
    const { heap, pos, key } = this;
    const v = heap[i];
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (key[heap[p]] <= key[v]) break;
      heap[i] = heap[p];
      pos[heap[i]] = i;
      i = p;
    }
    heap[i] = v;
    pos[v] = i;
  }
  private down(i: number): void {
    const { heap, pos, key } = this;
    const v = heap[i];
    for (;;) {
      let c = 2 * i + 1;
      if (c >= this.size) break;
      if (c + 1 < this.size && key[heap[c + 1]] < key[heap[c]]) c++;
      if (key[heap[c]] >= key[v]) break;
      heap[i] = heap[c];
      pos[heap[i]] = i;
      i = c;
    }
    heap[i] = v;
    pos[v] = i;
  }
}

export interface SpResult {
  dist: Float64Array;
  parent: Int32Array;
  // العدادات: عشان نقارن الطريقتين بأرقام مش بإحساس
  pushes: number;
  pops: number;
  stalePops: number;
  decreaseKeys: number;
}

function start(n: number, s: number): { dist: Float64Array; parent: Int32Array } {
  const dist = new Float64Array(n).fill(Infinity);
  const parent = new Int32Array(n).fill(-1);
  dist[s] = 0;
  parent[s] = s;
  return { dist, parent };
}

// (أ) الـ lazy deletion: كل تحسين ⁦= push⁩ جديد، والنسخ القديمة بنعدّيها لما تطلع
export function dijkstraLazy(g: WGraph, s: number, target = -1): SpResult {
  const { dist, parent } = start(g.n, s);
  const heap = new PairHeap();
  const r = { pushes: 1, pops: 0, stalePops: 0, decreaseKeys: 0 };
  heap.push(0, s);
  while (heap.size > 0) {
    const u = heap.pop();
    r.pops++;
    // نسخة قديمة: الـ node دي اتسوّت قبل كده بمسافة أقل
    if (heap.topKey > dist[u]) {
      r.stalePops++;
      continue;
    }
    // أول pop صالح للـ ⁦target =⁩ مسافته النهائية، فنقدر نقف هنا
    if (u === target) break;
    for (let i = g.offsets[u]; i < g.offsets[u + 1]; i++) {
      const v = g.targets[i];
      const nd = dist[u] + g.weights[i];
      if (nd < dist[v]) {
        dist[v] = nd;
        parent[v] = u;
        heap.push(nd, v);
        r.pushes++;
      }
    }
  }
  return { dist, parent, ...r };
}

// (ب) الـ indexed PQ: كل node موجودة مرة واحدة، والتحسين ⁦= decrease-key⁩ في مكانها
export function dijkstraIndexed(g: WGraph, s: number, target = -1): SpResult {
  const { dist, parent } = start(g.n, s);
  const pq = new IndexedMinPQ(g.n);
  const r = { pushes: 1, pops: 0, stalePops: 0, decreaseKeys: 0 };
  pq.insert(s, 0);
  while (pq.size > 0) {
    const u = pq.popMin();
    r.pops++;
    if (u === target) break;
    for (let i = g.offsets[u]; i < g.offsets[u + 1]; i++) {
      const v = g.targets[i];
      const nd = dist[u] + g.weights[i];
      if (nd < dist[v]) {
        const queued = dist[v] !== Infinity;
        dist[v] = nd;
        parent[v] = u;
        if (queued) {
          pq.decreaseKey(v, nd);
          r.decreaseKeys++;
        } else {
          pq.insert(v, nd);
          r.pushes++;
        }
      }
    }
  }
  return { dist, parent, ...r };
}

// شبكة شوارع synthetic بـ seed ثابت (مستوحاة من القاهرة، مش خريطة حقيقية⁦): W × H⁩ تقاطع
export const NORMAL_MIN = 20;
export const EXPRESS = 8;
export interface City extends WGraph {
  readonly w: number;
  readonly h: number;
}

export function city(w: number, h: number, seed: number): City {
  const rand = mulberry32(seed);
  const from: number[] = [];
  const to: number[] = [];
  const secs: number[] = [];
  const add = (a: number, b: number, s: number): void => {
    from.push(a);
    to.push(b);
    secs.push(s);
  };
  // الـ block العادي: 20 ثانية × زحمة من 1 لـ 2.5، والزحمة مختلفة في كل اتجاه
  const street = (): number => Math.round(NORMAL_MIN * (1 + 1.5 * rand() * rand()));
  for (let y = 0; y < h; y++) {
    for (let x = 0; x < w; x++) {
      const v = y * w + x;
      for (const [nx, ny] of [[x + 1, y], [x, y + 1]]) {
        if (nx >= w || ny >= h) continue;
        const u = ny * w + nx;
        // الـ express corridors: كل 50 صف فيه طريق سريع (8 ثواني للـ block) في اتجاه واحد بس
        if (ny === y && y % 50 === 25) {
          const east = ((y - 25) / 50) % 2 === 0;
          add(east ? v : u, east ? u : v, EXPRESS);
          add(east ? u : v, east ? v : u, street());
          continue;
        }
        // حوالي 10% من الشوارع one-way في اتجاه عشوائي
        const r = rand();
        if (r >= 0.05) add(u, v, street());
        if (r < 0.05 || r >= 0.1) add(v, u, street());
      }
    }
  }
  return { ...wgraph(w * h, from, to, secs), w, h };
}

بالعامية

أرض التجربة: grid بـ seed ثابت 300 × 300 مستوحى من القاهرة (مش خريطة حقيقية): 90,000 تقاطع و 341,064 شارع directed في شكل CSR، والتكلفة بالثواني. الـ block العادي 20 ثانية × زحمة من 1 لـ 2.5، وحوالي 10% من الشوارع one-way، وكل 50 صف فيه express corridor اتجاه واحد بـ 8 ثواني للـ block (ده هيفرق في الجزء 5).

فيه طريقتين تتعامل بيهم مع "لقيت مسافة أقصر لـ v":

  • الـ lazy deletion: حط زوج (dist, v) جديد وسيب القديم في الـ heap، ولما حاجة تطلع بـ key أكبر من dist[v] تبقى قديمة فعدّيها. arrays عادية وكود بسيط، والـ heap ممكن يوصل لـ E عنصر.
  • الـ indexed priority queue بالـ decrease-key (متبنية في section 04 · درس 09): كل node موجودة مرة واحدة بالكتير، و pos[v] بيسجّل مكانها، والتحسين بيطلّعها لفوق في مكانها. مفيش حاجة قديمة، والـ heap حجمه V بالكتير، بس الحسابات أكتر.

على المدينة كلها الـ lazy عمل 102,638 push و 12,638 stale pop، والـ indexed عمل 90,000 insert و 12,647 decrease-key (الأرقام مختلفة شوية لأن الـ heapين بيكسروا التعادل بشكل مختلف). والوقت كان واحد تقريبًا في كل run (≈12 لـ 47 ms حسب ضغط الجهاز). الـ lazy deletion هو الاختيار الافتراضي في الواقع، والـ decrease-key بيكسب لما memory الـ E عنصر تفرق أو الـ graph كثيف.

Part 2 — Why negative weights break Dijkstra 🟡 Intermediateالجزء 2 — ليه الـ negative weights بتكسر Dijkstra

English

Costs can be negative in real models: a leg that includes a partner pickup paying a 40 EGP cashback, a refund, a subsidy. Four nodes are enough to break Dijkstra. It settles nasr at 20 EGP, and only later finds heliopolis → nasr at 45 − 40 = 5. The textbook version (a settled set, never touched again) answers 50 EGP; Bellman–Ford answers 35 EGP via depot → heliopolis → nasr → customer. The proof from part 1 fails exactly where it assumed "adding edges can't make a path cheaper".

The lazy version from part 1 has no settled set; it re-expands a node whenever its distance drops. Here it happened to return 35 after 5 expansions for 4 nodes. That is no longer Dijkstra's bound: with negative edges, re-expansion can blow up exponentially on adversarial graphs, so "it worked on my example" proves nothing.

Shifting every weight by a constant is also wrong. Adding 40 to each leg removes the negative, but a path with k legs grows by 40·k, so paths with more legs are penalised: the 2-leg route becomes 130 and the 3-leg one 155, and Dijkstra picks the route that really costs 50. The correct transformation is Johnson's reweighting: run Bellman–Ford once from a virtual source to get potentials h(v), then use w'(u, v) = w(u, v) + h(u) − h(v), which is never negative. Every s → t path changes by the same h(s) − h(t), so the order of paths is preserved, and Dijkstra on w' answers 35. It's the standard way to do all-pairs on a sparse graph with negative edges: one Bellman–Ford, then V Dijkstras.

// الـ Johnson reweighting: h من Bellman–Ford مرة واحدة، وبعدها كل الـ edges بقت ⁦>= 0⁩ فـ Dijkstra يشتغل
export function johnsonPotentials(g: WGraph): Float64Array {
  // ضيف node وهمية q ليها edge بصفر لكل node، وشغّل Bellman–Ford منها
  const from: number[] = [];
  const to: number[] = [];
  const w: number[] = [];
  for (let u = 0; u < g.n; u++) {
    for (let i = g.offsets[u]; i < g.offsets[u + 1]; i++) {
      from.push(u);
      to.push(g.targets[i]);
      w.push(g.weights[i]);
    }
    from.push(g.n);
    to.push(u);
    w.push(0);
  }
  const bf = bellmanFord(wgraph(g.n + 1, from, to, w), g.n);
  if (bf.negativeCycle) throw new Error("negative cycle: no shortest paths exist");
  return bf.dist.subarray(0, g.n);
}

// الـ ⁦w'(u,v) = w(u,v) + h(u) - h(v)⁩: كل path من s لـ t اتزاد بنفس الثابت ⁦h(s) - h(t)⁩، فالترتيب مبيتغيرش
export function johnsonFrom(g: WGraph, s: number): Float64Array {
  const h = johnsonPotentials(g);
  const w2 = new Float64Array(g.weights.length);
  for (let u = 0; u < g.n; u++) {
    for (let i = g.offsets[u]; i < g.offsets[u + 1]; i++) w2[i] = g.weights[i] + h[u] - h[g.targets[i]];
  }
  const d = dijkstraLazy({ ...g, weights: w2 }, s).dist;
  return d.map((x, v) => x - h[s] + h[v]);
}

function dijkstraSettled(gr: WGraph, s: number): { dist: Float64Array; parent: Int32Array } {
  const dist = new Float64Array(gr.n).fill(Infinity);
  const parent = new Int32Array(gr.n).fill(-1);
  const settled = new Uint8Array(gr.n);
  dist[s] = 0;
  parent[s] = s;
  for (let k = 0; k < gr.n; k++) {
    let u = -1;
    for (let v = 0; v < gr.n; v++) if (!settled[v] && dist[v] < Infinity && (u === -1 || dist[v] < dist[u])) u = v;
    if (u === -1) break;
    settled[u] = 1;
    for (let i = gr.offsets[u]; i < gr.offsets[u + 1]; i++) {

        dist[v] = dist[u] + gr.weights[i];
        parent[v] = u;
      }
    }
  }
  return { dist, parent };

Part 3 — Bellman–Ford and currency arbitrage 🟡 Intermediateالجزء 3 — الـ Bellman–Ford والـ arbitrage في أسعار العملات

English

Bellman–Ford relaxes every edge, round after round. After round k, every shortest path that uses at most k edges is correct, and a simple path has at most V − 1 edges, so V − 1 rounds suffice: O(V·E). If a V-th round still improves something, a negative cycle is reachable. To print it, start from the last node that changed, walk parent V times (that guarantees you're inside the cycle), then follow parent until you return, and reverse. Stop early when a full round changes nothing: on the city grid that took 301 rounds instead of 89,999 (≈447 ms, against ≈24 ms for Dijkstra on the same graph).

Arbitrage. With rates among EGP, USD, EUR, SAR, AED and GBP (invented numbers for the example, not market data), turning money around a cycle is profitable when the product of the rates is above 1. Taking w = −log(rate) turns products into sums: product > 1 ⇔ sum of weights < 0, so arbitrage is a negative cycle. Initialise every distance to 0 (a virtual source connected to all currencies) so any cycle anywhere is found. Results:

  • Mid rates (va/vb, mathematically arbitrage-free): without an epsilon Bellman–Ford reports USD → EUR → USD, whose rate product prints as exactly 1 but whose weights sum to −2.78·10−17: a false positive from rounding. With eps = 1e-9 it's gone.
  • Dealer quotes with a 0.05–0.3% spread on every pair: no arbitrage, 3 rounds.
  • One stale quote (SAR → AED 0.8% too high in a cache): cycle SAR → AED → SAR, profit factor 1.00496: a million SAR comes back as about 1,004,960 SAR.
  • Plus a 0.3% fee per conversion: 1.00496 × 0.997² ≈ 0.9989 < 1, the arbitrage disappears.

SPFA ("shortest path faster algorithm") is Bellman–Ford with a queue: only nodes whose distance just changed get their edges relaxed. It's often much faster on random graphs, but its worst case is still O(V·E) and there are well-known inputs that force it, so don't put it on a path where an attacker or a weird dataset controls the graph. Detecting a negative cycle with it needs a counter of how many times each node entered the queue (≥ V means a cycle).

export interface BfResult {
  dist: Float64Array;
  parent: Int32Array;
  rounds: number;
  // الـ cycle نفسه لو فيه negative cycle يقدر الـ source يوصله
  negativeCycle: number[] | null;
}

// الـ Bellman–Ford: لحد V - 1 جولة relaxation، ونقف بدري لو جولة كاملة مغيّرتش حاجة
// لو s = -1: كل الـ nodes بتبدأ بصفر، كأن فيه source وهمي متوصل بالكل (عشان نلاقي أي negative cycle)
export function bellmanFord(g: WGraph, s: number, eps = 0): BfResult {
  const n = g.n;
  const dist = new Float64Array(n).fill(s < 0 ? 0 : Infinity);
  const parent = new Int32Array(n).fill(-1);
  if (s >= 0) dist[s] = 0;
  let rounds = 0;
  let changed = -1;
  // الجولة رقم V: لو لسه فيه تحسين يبقى فيه negative cycle
  for (let round = 1; round <= n; round++) {
    changed = -1;
    rounds = round;
    for (let u = 0; u < n; u++) {
      if (dist[u] === Infinity) continue;
      for (let i = g.offsets[u]; i < g.offsets[u + 1]; i++) {
        const v = g.targets[i];
        // الـ eps: أي تحسين أصغر منه نعتبره rounding error مش تحسين حقيقي
        if (dist[u] + g.weights[i] < dist[v] - eps) {
          dist[v] = dist[u] + g.weights[i];
          parent[v] = u;
          changed = v;
        }
      }
    }
    if (changed === -1) return { dist, parent, rounds, negativeCycle: null };
  }
  // امشي على الـ parent عدد V خطوة: كده أكيد إنت جوه الـ cycle، وبعدين لف لحد ما ترجع لنفس الـ node
  let x = changed;
  for (let i = 0; i < n; i++) x = parent[x];
  const cycle = [x];
  for (let v = parent[x]; v !== x; v = parent[v]) cycle.push(v);
  cycle.push(x);
  // الـ parent بيشاور لورا، فاقلب عشان الـ cycle يمشي في اتجاه الـ edges
  return { dist, parent, rounds, negativeCycle: cycle.reverse() };
}

بالعامية

الـ Bellman–Ford بيعمل relax لـ كل الـ edges، جولة ورا جولة. بعد الجولة رقم k، أي أقصر طريق فيه k edges بالكتير بيبقى صح، وأي طريق simple فيه V − 1 edge بالكتير، فـ V − 1 جولة كفاية: O(V·E). ولو الجولة رقم V لسه حسّنت حاجة، يبقى فيه negative cycle يقدر الـ source يوصله. عشان تطبعه: ابدأ من آخر node اتغيرت، وامشي على الـ parent عدد V خطوة (كده أكيد بقيت جوه الـ cycle)، وبعدين امشي على الـ parent لحد ما ترجع لنفس الـ node، واقلب. واقف بدري لو جولة كاملة مغيّرتش حاجة: على شبكة المدينة ده خد 301 جولة بدل 89,999 (≈447 ms، مقابل ≈24 ms للـ Dijkstra على نفس الـ graph).

الـ arbitrage: عندك أسعار بين الجنيه والدولار واليورو والريال والدرهم والإسترليني (أرقام متألفة للمثال، مش أسعار سوق). إنك تلف بالفلوس على cycle يكسب لو حاصل ضرب الأسعار أكبر من 1. لو خليت w = −log(rate) الضرب بيتحول لجمع: الحاصل أكبر من 1 ⇔ مجموع الأوزان أقل من صفر، فالـ arbitrage هو negative cycle. وابدأ كل المسافات بصفر (كأن فيه source وهمي متوصل بكل العملات) عشان أي cycle في أي حتة يتلقط. النتايج:

  • أسعار الـ mid (va/vb، يعني مفيش arbitrage رياضيًا): من غير epsilon الـ Bellman–Ford قال فيه cycle USD → EUR → USD، حاصل ضرب أسعاره بيتطبع 1 بالظبط بس مجموع أوزانه -2.78e-17: false positive من الـ rounding. ومع eps = 1e-9 اختفى.
  • أسعار الـ dealer بـ spread من 0.05% لـ 0.3% على كل زوج: مفيش arbitrage، 3 جولات.
  • سعر واحد قديم (SAR → AED أعلى بـ 0.8% في cache): cycle SAR → AED → SAR بمكسب 1.00496: المليون ريال بيرجع حوالي 1,004,960 ريال.
  • ومع رسوم 0.3% على كل تحويل: 1.00496 × 0.997² ≈ 0.9989، أقل من 1، والـ arbitrage اختفى.

الـ SPFA ("shortest path faster algorithm") هو Bellman–Ford بـ queue: بيعمل relax بس للـ edges بتاعة الـ nodes اللي مسافتها لسه متغيرة. غالبًا أسرع بكتير على graphs عشوائية، بس أسوأ حالة ليه لسه O(V·E)، وفيه inputs معروفة بتجبره عليها، فمتحطوش في مكان attacker أو data غريبة بتتحكم في الـ graph. ولو عايز تكشف بيه negative cycle محتاج تعدّ كل node دخلت الـ queue كام مرة (V مرة أو أكتر يبقى فيه cycle).

Part 4 — 0-1 BFS and multi-source BFS 🟡 Intermediateالجزء 4 — الـ zero-one BFS والـ multi-source BFS

English

0-1 BFS. When every weight is 0 or 1, you don't need a heap. Keep a deque whose contents always have distance d or d + 1: pop from the front; push a neighbour reached by a 0-edge to the front (same distance), and one reached by a 1-edge to the back. The front is always a smallest distance, like a heap's top, but every operation is O(1), so the whole thing is O(V + E). A node can be pushed twice (first via a 1-edge, later via a 0-edge), so skip it if it's already done. The deque is a ring buffer (section 04 · lesson 02): an Int32Array with a power-of-two capacity and a head index.

Example: the fewest paid transfers between 100,000 hubs, where legs run by a partner carrier are free (weight 0) and our own transfers cost 1. On 400,000 legs both 0-1 BFS and Dijkstra gave identical distances with nearly identical operation counts (114,305 vs 114,318 pushes), but the deque version was about 2× faster (≈6 vs ≈11 ms), because a deque push is a store and an index update while a heap push sifts through log n levels. A property test checks it against Dijkstra on 3,000 random 0/1 graphs.

Multi-source BFS. To get every cell's distance to the nearest branch, don't run one BFS per branch: put all branches in the queue at distance 0 and run one BFS. Each cell is reached first by its nearest branch. On a 60 × 16 block map with the Nile as a blocked column and two bridges, the output is a coverage map plus counts per band (93 blocks within 3, 315 within 4–8…). On a 1000 × 1000 grid with 50 branches, one multi-source pass made 1,000,000 visits (≈38 ms); one BFS per branch plus a min made 50,000,000 visits (≈1.2 s) for the same answer. It's the same trick as Dijkstra with several sources: push them all at 0.

 0-1 BFS: the deque only ever holds distances d and d + 1, in order

   front                                      back
   [ v1:d   v2:d   v3:d   v4:d+1   v5:d+1 ]

   pop v1 (distance d), then for each leg v1 -> x:
     weight 0  ->  pushFront(x) with distance d       (still the smallest)
     weight 1  ->  pushBack(x)  with distance d + 1

   queue = [B1:0, B2:0, B3:0, B4:0]  ->  each cell is reached first by its nearest branch
في الـ 0-1 BFS الـ deque عمره ما بيبقى فيه غير مسافتين: d و d + 1، ومترتبين. بنطلّع من قدّام، ولو الـ leg وزنه 0 الـ node الجديدة بتتحط قدّام بنفس المسافة (فهي لسه الأصغر)، ولو وزنه 1 بتتحط ورا بمسافة d + 1. وفي الـ multi-source BFS كل الفروع بتبدأ في الـ queue بمسافة صفر مع بعض، فكل خانة أول فرع يوصلها هو الأقرب ليها.
// الـ deque فوق ring buffer (Int32Array بحجم power of 2): push و pop من الناحيتين في ⁦O(1)⁩
export class IntDeque {
  private buf = new Int32Array(1024);
  private head = 0;
  size = 0;
  pushFront(x: number): void {
    if (this.size === this.buf.length) this.grow();
    this.head = (this.head - 1) & (this.buf.length - 1);
    this.buf[this.head] = x;
    this.size++;
  }
  pushBack(x: number): void {
    if (this.size === this.buf.length) this.grow();
    this.buf[(this.head + this.size) & (this.buf.length - 1)] = x;
    this.size++;
  }
  popFront(): number {
    const x = this.buf[this.head];
    this.head = (this.head + 1) & (this.buf.length - 1);
    this.size--;
    return x;
  }
  // لما يتملى: انسخ بالترتيب في buffer قد الضعف
  private grow(): void {
    const next = new Int32Array(this.buf.length * 2);
    for (let i = 0; i < this.size; i++) next[i] = this.buf[(this.head + i) & (this.buf.length - 1)];
    this.buf = next;
    this.head = 0;
  }
}

// خوارزمية zero-one BFS: الـ edges وزنها 0 أو 1 بس. وزن ⁦0 =⁩ قدّام الـ deque، وزن ⁦1 =⁩ ورا
export function zeroOneBfs(g: WGraph, s: number): { dist: Float64Array; pushes: number; pops: number; stale: number } {
  const dist = new Float64Array(g.n).fill(Infinity);
  const done = new Uint8Array(g.n);
  const dq = new IntDeque();
  let pushes = 1;
  let pops = 0;
  let stale = 0;
  dist[s] = 0;
  dq.pushBack(s);
  while (dq.size > 0) {
    const u = dq.popFront();
    pops++;
    // الـ node ممكن تكون اتحطت مرتين (مرة ورا بـ 1 وبعدين قدّام بـ 0): التانية قديمة
    if (done[u] === 1) {
      stale++;
      continue;
    }
    done[u] = 1;
    for (let i = g.offsets[u]; i < g.offsets[u + 1]; i++) {
      const v = g.targets[i];
      const w = g.weights[i];
      if (dist[u] + w < dist[v]) {
        dist[v] = dist[u] + w;
        if (w === 0) dq.pushFront(v);
        else dq.pushBack(v);
        pushes++;
      }
    }
  }
  return { dist, pushes, pops, stale };
}

export function multiSourceGrid(w: number, h: number, blocked: Uint8Array, sources: number[]): { dist: Int32Array; visits: number } {
  const dist = new Int32Array(w * h).fill(-1);
  const queue = new Int32Array(w * h);
  let head = 0;
  let tail = 0;
  for (const s of sources) {
    dist[s] = 0;
    queue[tail++] = s;
  }
  while (head < tail) {
    const u = queue[head++];
    const x = u % w;
    const y = (u - x) / w;
    // الجيران الأربعة: يمين، شمال، تحت، فوق
    if (x + 1 < w) visit(u + 1);
    if (x > 0) visit(u - 1);
    if (y + 1 < h) visit(u + w);
    if (y > 0) visit(u - w);
    function visit(v: number): void {
      if (dist[v] === -1 && blocked[v] === 0) {
        dist[v] = dist[u] + 1;
        queue[tail++] = v;
      }
    }
  }
  return { dist, visits: tail };
}

Part 5 — A* and admissible heuristics 🔴 Advancedالجزء 5 — الـ A* والـ heuristic المقبولة

English

A* is Dijkstra with the heap ordered by f(v) = g(v) + h(v): the cost so far plus an estimate of the cost still to go. With h = 0 it is Dijkstra. If h never overestimates the true remaining cost (admissible), the first time the target is popped its cost is optimal. On our grid, any trip needs at least |dx| + |dy| blocks and no block is cheaper than 8 s (the express corridors), so Manhattan × 8 s is admissible; Euclidean × 8 s is too, since the straight line is never longer than the Manhattan distance.

Over 100 seeded trips (table below): Dijkstra expanded 47,053 nodes on average; Manhattan × 8 expanded 28,315 and Euclidean × 8 32,061, all 100 optimal. Weighted A* (2 × Manhattan × 8) expanded 16,583 but only 62 routes were optimal, +0.58% on average and +14.7% at worst; with an admissible h, inflating it by ε guarantees cost ≤ ε × optimal, so a bounded loss for speed. The overestimating heuristic used 20 s per block, the cheapest normal street, and ignored the faster one-way corridors: 7,273 expansions, but only 43 optimal routes, +3.9% on average and +40% at worst. On its worst trip it returned a 102.5-minute route with no corridor blocks, while the optimal 73-minute route used 226 corridor blocks: the inflated estimate made the detour to the corridor look too expensive to explore.

Note how weak the admissible heuristic is here: a single fast corridor forces the multiplier down to 8 s everywhere, so it only saved 40% of the work. Production routers get tighter lower bounds from precomputation, such as landmark distances with the triangle inequality (ALT) or contraction hierarchies (named, not run here).

Consistent vs admissible. A heuristic is consistent when h(u) ≤ w(u, v) + h(v) for every edge and h(target) = 0. Consistency implies admissibility, and it guarantees each node is expanded once, so a closed set is safe. Manhattan × 8 is consistent here: one block changes the Manhattan distance by at most 1, so h changes by at most 8 s, and every block costs at least 8 s. An admissible but inconsistent h can find a cheaper path to an already-expanded node; the implementation below handles that by re-opening it (its stale check compares f, not a closed flag). For where ETA sits in a dispatch system, see System Design 54, part 4.

import type { WGraph } from "./wgraph.ts";
import { PairHeap } from "./heaps.ts";

export interface AStarResult {
  cost: number;
  parent: Int32Array;
  // عدد الـ nodes اللي اتوسّعت فعلًا (الـ pops اللي مش قديمة)
  expanded: number;
}

// الـ ⁦A*⁩: نفس Dijkstra بس الـ heap مترتب بـ f = g + h، يعني "اللي اتصرف⁦" + "⁩تقدير الباقي لحد الـ ⁦target"⁩
export function aStar(g: WGraph, s: number, t: number, h: (v: number) => number): AStarResult {
  const dist = new Float64Array(g.n).fill(Infinity);
  const parent = new Int32Array(g.n).fill(-1);
  const heap = new PairHeap();
  dist[s] = 0;
  parent[s] = s;
  heap.push(h(s), s);
  let expanded = 0;
  while (heap.size > 0) {
    const u = heap.pop();
    // نسخة قديمة: الـ f اللي اتحطت بيه أكبر من الـ f الحالي
    if (heap.topKey > dist[u] + h(u)) continue;
    expanded++;
    if (u === t) break;
    for (let i = g.offsets[u]; i < g.offsets[u + 1]; i++) {
      const v = g.targets[i];
      const nd = dist[u] + g.weights[i];
      if (nd < dist[v]) {
        dist[v] = nd;
        parent[v] = u;
        heap.push(nd + h(v), v);
      }
    }
  }
  return { cost: dist[t], parent, expanded };
}

Part 6 — Floyd–Warshall for all pairs 🟡 Intermediateالجزء 6 — الـ Floyd–Warshall لكل الأزواج

English

Floyd–Warshall fills a V × V matrix: after step k, d[i][j] is the shortest path from i to j whose intermediate stops all come from {0 … k}. Step k only asks whether going through k helps: d[i][j] = min(d[i][j], d[i][k] + d[k][j]). That's why k must be the outermost loop (mistake 4: with k innermost, 1,516 of 3,600 entries came out wrong). O(V³) time, O(V²) memory, three nested loops over a flat Float64Array, negative edges allowed. A next matrix (first hop from i towards j) rebuilds any path in O(length).

On 60 warehouses and pickup points (12 + 48, seeded coordinates in a 30 × 20 km box, each linked to its 4 nearest): exactly 216,000 relaxations, and W01 → P37 takes 48 minutes through 5 intermediate stops. When a bad import stored a return leg as −30 minutes instead of +30 (with a 4-minute leg the other way), every one of the 60 diagonal entries went negative and the values blew up to around −4.7·1011: a negative diagonal means a negative cycle, and then none of the numbers mean anything. Check the diagonal and reject the matrix.

Floyd–Warshall or V × Dijkstra? V runs of Dijkstra cost O(V·E log V). At V = 400: on a sparse graph (E = 1,600), V × Dijkstra ≈27 ms vs Floyd–Warshall ≈103 ms; on a complete graph (E = 159,600), ≈378 ms vs ≈133 ms. Sparse → V × Dijkstra (or Johnson if there are negative edges); dense or tiny → Floyd–Warshall, whose tight loop over contiguous memory is hard to beat. This matrix is exactly the input for the courier-route DP in lesson 10, part 4.

When to precompute and cache. All-pairs pays off when V is small, queries are many and the graph changes rarely: compute it on change or nightly, store it in Redis or a Postgres table (3,600 rows for 60 points), and serve lookups. Memory grows as V²: V = 1,000 → 8 MB (+4 MB for next), V = 10,000 → 800 MB (+400 MB), V = 100,000 → 80 GB. A whole city graph (V ≈ 105–106) is out of reach: answer per query with Dijkstra or A*, and keep all-pairs for the few hundred places you actually route between. Float32 seconds or Uint16 minutes cut the memory 2–4×.

       d[i][j] = min(d[i][j], d[i][k] + d[k][j])      next[i][j] = next[i][k] if improved

        i -------- d[i][j] --------> j
         \                         ^
       d[i][k]                  d[k][j]
           \                     /
            +-------> k --------+

 after k: d[i][j] = shortest i -> j using only stops in {0 .. k}
 at the end: any d[i][i] < 0  =>  i is on (or reaches) a negative cycle
الـ loop الخارجي k: كل خطوة بتسمح لـ node رقم k إنها تبقى محطة في النص. وجوه، لكل i و j بنسأل: هل الطريق من i لـ k وبعدين من k لـ j أقصر من اللي عندي؟ لو آه بنحدّث d[i][j] و next[i][j] بيبقى أول خطوة في الطريق لـ k. بعد الخطوة k، الـ d[i][j] هو أقصر طريق محطاته كلها من 0 لـ k. وفي الآخر لو أي خانة على القطر d[i][i] سالبة، يبقى i على negative cycle أو بتوصله.
// الـ ⁦Floyd–Warshall: d[i][j] =⁩ أقصر طريق مسموح له يعدّي بس على الـ nodes من 0 لحد k
// الـ matrix متخزنة flat: الخانة i * n + j، و ⁦next[i * n + j] =⁩ أول خطوة من i في الطريق لـ j
export function floydWarshall(n: number, d: Float64Array): { next: Int32Array; relaxations: number } {
  const next = new Int32Array(n * n).fill(-1);
  for (let i = 0; i < n; i++) {
    for (let j = 0; j < n; j++) if (d[i * n + j] !== Infinity) next[i * n + j] = j;
    next[i * n + i] = i;
  }
  let relaxations = 0;
  for (let k = 0; k < n; k++) {
    for (let i = 0; i < n; i++) {
      const dik = d[i * n + k];
      if (dik === Infinity) {
        relaxations += n;
        continue;
      }
      for (let j = 0; j < n; j++) {
        relaxations++;
        const via = dik + d[k * n + j];
        if (via < d[i * n + j]) {
          d[i * n + j] = via;
          next[i * n + j] = next[i * n + k];
        }
      }
    }
  }
  return { next, relaxations };
}

// إعادة بناء الطريق من الـ next matrix: من i امشي خطوة خطوة لحد j
export function fwPath(n: number, next: Int32Array, i: number, j: number): number[] {
  if (next[i * n + j] === -1) return [];
  const path = [i];
  while (i !== j) {
    i = next[i * n + j];
    path.push(i);
  }
  return path;
}

الـ Floyd–Warshall بيملا matrix حجمها V × V: بعد الخطوة k، d[i][j] هو أقصر طريق من i لـ j وكل المحطات اللي في النص من {0 … k}. الخطوة k بتسأل سؤال واحد: هل العدّي على k بيفيد؟ d[i][j] = min(d[i][j], d[i][k] + d[k][j]). وعشان كده الـ k لازم يبقى الـ loop الخارجي (الغلطة 4: لما k بقى جوه خالص، 1,516 خانة من 3,600 طلعوا غلط). الوقت O(V³) والـ memory O(V²)، 3 loops جوه بعض على Float64Array مسطّحة، والـ negative edges مسموحة. والـ next matrix (أول خطوة من i ناحية j) بتبني أي طريق في O(طوله).

على 60 مخزن ونقطة استلام (12 + 48، إحداثيات بـ seed ثابت في مربع 30 × 20 كم، وكل نقطة متوصلة بأقرب 4): 216,000 relaxation بالظبط، ومن W01 لـ P37 بياخد 48 دقيقة عن طريق 5 محطات. ولما import غلط سجّل leg رجوع بـ -30 دقيقة بدل +30 (والـ leg الرايح 4 دقايق)، الـ 60 خانة اللي على القطر كلهم بقوا سالبين والقيم انفجرت لحوالي -4.7e11: قطر سالب معناه negative cycle، وساعتها مفيش رقم في الـ matrix ليه معنى. شيّك على القطر وارفض الـ matrix.

Floyd–Warshall ولا Dijkstra من كل node؟ الـ V مرة Dijkstra تكلفتهم O(V·E log V). عند V = 400: على graph sparse (E = 1,600) الـ Dijkstra ≈27 ms والـ Floyd–Warshall ≈103 ms، وعلى graph كامل (E = 159,600) ≈378 ms مقابل ≈133 ms. sparse ← Dijkstra من كل node (أو Johnson لو فيه negative edges)، كثيف أو صغير جدًا ← Floyd–Warshall، لأن الـ loop بتاعه ضيق وعلى memory ورا بعض وصعب تغلبه. والـ matrix دي بالظبط هي المدخل لـ DP بتاع route المندوب في الدرس 10 الجزء 4.

إمتى تحسبها مقدمًا وتعملها cache؟ الـ all-pairs بتكسب لما V صغير، والأسئلة كتير، والـ graph بيتغير نادرًا: احسبها لما حاجة تتغير أو بالليل، وخزّنها في Redis أو جدول Postgres (3,600 صف لـ 60 نقطة)، والـ API يعمل lookup. والـ memory بتكبر بـ V²: V = 1,000 ← 8 MB (+4 MB للـ next)، V = 10,000 ← 800 MB (+400 MB)، V = 100,000 ← 80 GB. graph مدينة كاملة (V حوالي 105 لـ 106) مستحيل: رد على كل سؤال بـ Dijkstra أو A*، وخلّي الـ all-pairs للمئات القليلة من الأماكن اللي فعلًا بتعمل routing بينها. والثواني كـ Float32 أو الدقايق كـ Uint16 بيقللوا الـ memory من 2 لـ 4 مرات.

فين هستخدمه في شغلي؟ شركة توصيل عندها 40 مخزن و 200 نقطة استلام ثابتة: job كل ما الـ travel times تتحدث (أو كل ساعة في الـ rush) بتعمل Floyd–Warshall على الـ 240 نقطة (13.8 مليون relaxation، يعني عشرات الميلّي ثواني لو قستها على رقم الـ V = 400 اللي فوق)، وتشيّك على القطر، وتكتب الـ matrix في Redis hash أو جدول travel_minutes(from_id, to_id, minutes). بعد كده planner الـ routes (الـ DP في الدرس 10، أو heuristic زي nearest neighbour + 2-opt) بيقرا منها بدل ما يحسب Dijkstra في كل خطوة. والغلطة الشائعة: تحسب الـ all-pairs على graph الشوارع كله بدل الأماكن المهمة بس، فالـ job تاكل 800 MB وتقع OOM.
Trade-off: precompute all pairs or answer per query? Precomputed: O(1) lookups, predictable latency, but O(V²) memory, a recompute (O(V³) or V × Dijkstra) on every change, and stale answers between recomputes. Per query: always fresh (live traffic weights), no big memory, but every request pays a Dijkstra or A* (≈12–47 ms on 90,000 intersections here). Many systems mix them: all-pairs between hubs that change rarely, per-query search for the first and last mile.
المحسوب مقدمًا: lookup في O(1) و latency متوقعة، بس memory بـ O(V²)، وإعادة حساب (O(V³) أو V مرة Dijkstra) مع كل تغيير، وإجابات قديمة بين كل حساب والتاني. لكل سؤال: دايمًا جديد (بالزحمة الحالية)، ومن غير memory كبيرة، بس كل request بيدفع Dijkstra أو A* (≈12 لـ 47 ms على 90,000 تقاطع هنا). أنظمة كتير بتخلط الاتنين: all-pairs بين الـ hubs اللي نادرًا ما بتتغير، وبحث لكل سؤال لأول وآخر ميل.

function reverse(g: WGraph): WGraph {

  const to: number[] = [];
  const w: number[] = [];

// أقرب k فروع: Dijkstra من العميل على الـ graph المقلوب، ونقف بعد ما k فروع يطلعوا من الـ heap
function nearestBranches(rg: WGraph, customer: number, isBranch: Uint8Array, k: number): { found: [number, number][]; pops: number } {
  const dist = new Float64Array(rg.n).fill(Infinity);
  const heap = new PairHeap();
  const found: [number, number][] = [];
  let pops = 0;
  dist[customer] = 0;
  heap.push(0, customer);
  while (heap.size > 0 && found.length < k) {
    const u = heap.pop();
    pops++;
    if (heap.topKey > dist[u]) continue;
    if (isBranch[u] === 1) found.push([u, dist[u]]);
    for (let i = rg.offsets[u]; i < rg.offsets[u + 1]; i++) {
      const v = rg.targets[i];
      if (dist[u] + rg.weights[i] < dist[v]) {
        dist[v] = dist[u] + rg.weights[i];
        heap.push(dist[v], v);
      }
    }
  }
  return { found, pops };
}

// أرخص شحن من القاهرة لأسوان بعدد legs محدود: Bellman–Ford بـ K جولات بس، وكل جولة بتقرا من نسخة الجولة اللي قبلها
const hubs = ["CAI", "ALX", "BNS", "MNY", "AST", "SOH", "LXR", "ASW"];
const legs: [string, string, number][] = [
  ["CAI", "ASW", 900],
  ["CAI", "AST", 350],
  ["AST", "ASW", 380],
  ["CAI", "BNS", 90],
  ["BNS", "MNY", 80],
  ["MNY", "AST", 85],
  ["AST", "SOH", 70],
  ["SOH", "LXR", 95],
  ["LXR", "ASW", 110],
  ["CAI", "ALX", 120],
];
const id = new Map(hubs.map((h, i) => [h, i]));

function cheapestWithin(src: string, dst: string, maxLegs: number): number {
  let dist = new Array<number>(hubs.length).fill(Infinity);
  dist[id.get(src)!] = 0;
  for (let round = 0; round < maxLegs; round++) {
    // النسخة: من غيرها الجولة الواحدة ممكن تمشي أكتر من leg وتكسر الحد
    const next = dist.slice();
    for (const [a, b, price] of legs) {
      const [u, v] = [id.get(a)!, id.get(b)!];
      if (dist[u] + price < next[v]) next[v] = dist[u] + price;
    }
    dist = next;
  }
  return dist[id.get(dst)!];
}

import { city } from "../src/sp/city.ts";
import { dijkstraLazy } from "../src/sp/dijkstra.ts";
import { PairHeap } from "../src/sp/heaps.ts";
import { wgraph, type WGraph } from "../src/sp/wgraph.ts";
import { mulberry32 } from "../src/lib/rng.ts";

function reverse(g: WGraph): WGraph {
  const from: number[] = [];
  const to: number[] = [];
  const w: number[] = [];
  for (let u = 0; u < g.n; u++) {
    for (let i = g.offsets[u]; i < g.offsets[u + 1]; i++) {
      from.push(g.targets[i]);
      to.push(u);
      w.push(g.weights[i]);
    }
  }
  return wgraph(g.n, from, to, w);
}

// الـ bidirectional Dijkstra: واحد قدّام من s على g، وواحد ورا من t على الـ graph المقلوب
// قاعدة الوقوف: لما أصغر key في الـ ⁦heap-⁩ين مجموعهم ⁦>=⁩ أحسن طريق لقيناه. أول لقاء لوحده مش كفاية
function bidiDijkstra(g: WGraph, rg: WGraph, s: number, t: number): { cost: number; pops: number } {
  const df = new Float64Array(g.n).fill(Infinity);
  const db = new Float64Array(g.n).fill(Infinity);
  const hf = new PairHeap();
  const hb = new PairHeap();
  df[s] = 0;
  db[t] = 0;
  hf.push(0, s);
  hb.push(0, t);
  let best = s === t ? 0 : Infinity;
  let pops = 0;
  while (hf.size > 0 && hb.size > 0) {
    if (hf.keys[0] + hb.keys[0] >= best) break;
    // وسّع الناحية اللي الـ heap بتاعها أصغر
    const forward = hf.size <= hb.size;
    const [gr, heap, mine, other] = forward ? [g, hf, df, db] : [rg, hb, db, df];
    const u = heap.pop();
    pops++;
    if (heap.topKey > mine[u]) continue;
    for (let i = gr.offsets[u]; i < gr.offsets[u + 1]; i++) {
      const v = gr.targets[i];
      const nd = mine[u] + gr.weights[i];
      if (nd < mine[v]) {
        mine[v] = nd;
        heap.push(nd, v);
      }
      // كل edge بيوصل لحاجة الناحية التانية شافتها = طريق كامل مرشح
      if (other[v] !== Infinity && mine[u] + gr.weights[i] + other[v] < best) best = mine[u] + gr.weights[i] + other[v];
    }
  }
  return { cost: best, pops };
}

let mismatches = 0;

  const t = Math.floor(rand() * g.n);

  const bi = bidiDijkstra(g, rg, s, t);

  popsBi += bi.pops;
  popsOne += one.pops;
}

Cheat sheet · الخلاصة

  • Choose by weights: equal → BFS; 0/1 → 0-1 BFS; non-negative → Dijkstra (A* with a target and a good bound); negative → Bellman–Ford; all pairs, small V → Floyd–Warshall.
  • Dijkstra: lazy deletion (skip stale pops) or indexed PQ with decrease-key; same O((V + E) log V), similar speed here (102,638 pushes vs 90,000 inserts + 12,647 decrease-keys).
  • Stop when the target is popped, never when it's first pushed (11/100 trips wrong).
  • Negative edges break Dijkstra (50 vs 35 EGP); adding a constant is also wrong; Johnson's potentials h make w + h(u) − h(v) ≥ 0.
  • Bellman–Ford: V − 1 rounds, early stop (301 rounds instead of 89,999), round V detects a negative cycle; walk parents V times, then loop to print it.
  • Arbitrage = negative cycle with w = −log(rate); use an epsilon (−2.78·10−17 false positive) and include fees.
  • 0-1 BFS: deque, 0-edge to the front, 1-edge to the back; ≈2× faster than Dijkstra here. Multi-source: all sources at distance 0, one pass (106 vs 5·107 visits).
  • A*: f = g + h; admissible = never overestimates; consistent = h(u) ≤ w(u, v) + h(v). Build h from the cheapest edge anywhere; weighted A* trades a bounded ε for speed.
  • Floyd–Warshall: k outermost, O(V³) time, O(V²) memory, next matrix for paths, negative diagonal = negative cycle.
  • All pairs on sparse graphs → V × Dijkstra; dense → Floyd–Warshall. V = 10,000 is 800 MB of Float64: precompute only between the places you actually route.
بالعامية
  • اختار حسب الـ weights: متساويين ← BFS، صفر أو واحد ← 0-1 BFS، مفيش سالب ← Dijkstra (و A* لو فيه target و bound كويس)، فيه سالب ← Bellman–Ford، كل الأزواج و V صغير ← Floyd–Warshall.
  • الـ Dijkstra: lazy deletion (عدّي النسخ القديمة) أو indexed PQ بالـ decrease-key، نفس O((V + E) log V) وسرعة قريبة هنا (102,638 push مقابل 90,000 insert و 12,647 decrease-key).
  • اقف لما الـ target يطلع من الـ heap، عمرك ما تقف أول ما يتحط (11 رحلة من 100 طلعت غلط).
  • الـ negative edges بتكسر Dijkstra (50 مقابل 35 جنيه)، وزيادة ثابت غلط برضه، والـ potentials بتاعة Johnson بتخلّي w + h(u) − h(v) ≥ 0.
  • الـ Bellman–Ford: V − 1 جولة، ووقوف بدري (301 جولة بدل 89,999)، والجولة رقم V بتكشف الـ negative cycle؛ امشي على الـ parents عدد V خطوة وبعدين لف عشان تطبعه.
  • الـ arbitrage = negative cycle لما w = −log(rate)؛ استخدم epsilon (فيه false positive قيمته -2.78e-17) وحط الرسوم في الحسبة.
  • الـ 0-1 BFS: deque، الـ edge اللي وزنه صفر قدّام واللي وزنه واحد ورا، وأسرع من Dijkstra حوالي مرتين هنا. والـ multi-source: كل الـ sources بمسافة صفر و pass واحدة (مليون زيارة مقابل 50 مليون).
  • الـ A*: f = g + h، والـ admissible عمره ما يبالغ، والـ consistent معناه h(u) ≤ w(u, v) + h(v). ابني h من أرخص edge في الـ graph كله، والـ weighted A* بيبدّل ε محدودة بالسرعة.
  • الـ Floyd–Warshall: k برة خالص، O(V³) وقت و O(V²) memory، و next matrix للطرق، والقطر السالب = negative cycle.
  • الـ all pairs على graph sparse ← Dijkstra من كل node، وعلى graph كثيف ← Floyd–Warshall. و V = 10,000 يعني 800 MB بـ Float64: احسبها مقدمًا بس بين الأماكن اللي فعلًا بتعمل routing بينها.
