Why this matters · ليه ده مهم

English

You will almost never beat indexOf at finding one string in another. String algorithms matter in the places where indexOf can't go: a marker that arrives split across two chunks of an upload stream, 5,000 banned words checked against every product review, near-duplicate descriptions from sellers who copy each other, and Arabic text where "محمد" must find "مُحَمَّد" and an SMS costs double because of one emoji.

Interviews ask KMP and Rabin–Karp because they test whether you understand why an algorithm is linear and what a hash collision costs. Production asks them because a moderation filter that takes 4 seconds per batch, or a parser that silently drops 1 invoice in 70, is a real incident.

بالعامية

إنت تقريبًا عمرك ما هتكسب indexOf في إنك تدوّر على string جوه string. الـ string algorithms ليها لازمة في الأماكن اللي indexOf مبيوصلهاش: marker جاي متقسم بين chunkين في upload stream، و 5,000 كلمة ممنوعة لازم تتفحص في كل review، ووصف منتجات شبه بعض من بياعين بينسخوا من بعض، ونص عربي لازم فيه "محمد" يلاقي "مُحَمَّد"، ورسالة SMS بتتكلف الضعف عشان emoji واحد.

الـ interviews بتسأل في KMP و Rabin–Karp عشان تشوف إنت فاهم ليه الخوارزمية linear، وفاهم الـ hash collision بيكلّف إيه. والـ production بيسألك فيهم عشان filter للـ moderation بياخد 4 ثواني في الـ batch، أو parser بيضيّع فاتورة من كل 70 من غير ما حد ياخد باله، دي incidents حقيقية.

Part 1 — What indexOf already does 🟡 Intermediateالجزء 1 — الـ indexOf بيعمل إيه أصلًا

English

The naive search tries every start position i and compares character by character until the first mismatch. On ordinary text the first character usually differs, so it costs about n comparisons. On adversarial text it costs (n − m + 1) · m: a text of 200,000 a and a pattern of 1,000 a followed by b matches 1,000 characters at every position before failing. Counted below: 206,938 comparisons on random text (1.03·n) against 199,199,000 on the adversarial one (996·n).

Native indexOf is not that loop. The spec doesn't fix an algorithm; V8's src/strings/string-search.h picks one by pattern length: a memchr-style scan for one character, a simple linear scan for patterns shorter than 7, and for longer patterns an initial scan that counts wasted work ("badness") and escalates to Boyer–Moore–Horspool and then full Boyer–Moore. On the adversarial input it read a 2,000,000-character text in a few milliseconds, while our JS loop needed hundreds of milliseconds to seconds on a text 10 times smaller (the exact numbers swing a lot on this loaded machine; the ratio stays in the hundreds).

So don't hand-roll single-pattern search in JS "for speed". The algorithms in this lesson earn their place in three situations: the text arrives as a stream and you can't hold it whole, you search for many patterns at once, or you need structure (the period of a string, positions sharing a prefix, near-duplicate documents).

 text     a a a a a a a a a a a a a a a a ...   (n = 200,000)
 i = 0    a a a a b                             4 matches, fail on b
 i = 1      a a a a b                           the same 4 matches again
 i = 2        a a a a b                         ...and again
 cost     (n - m + 1) * m comparisons   ->   199,199,000 for m = 1,001
الرسمة بتوضح ليه الساذج بيبقى O(n·m): عند كل بداية i بيطابق نفس الـ a اللي طابقها في البداية اللي قبلها، ويفشل في الآخر عند b، ويرجع يبدأ من الأول من i + 1. يعني بيرمي كل اللي عرفه. والتكلفة (n − m + 1) × m مقارنة، يعني 199,199,000 لما m = 1,001.

// الـ PRNG بـ ⁦seed (mulberry32)⁩: نفس الـ ⁦seed =⁩ نفس الأرقام، عشان الـ tests والـ benchmarks تتكرر
export function mulberry32(seed: number): () => number {
  let s = seed >>> 0;
  return () => {
    s = (s + 0x6d2b79f5) >>> 0;
    let t = Math.imul(s ^ (s >>> 15), 1 | s);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

// الـ median لعدد من القياسات: أثبت من المتوسط على جهاز عليه ضغط
export function median(xs: number[]): number {
  const s = [...xs].sort((a, b) => a - b);
  return s[s.length >> 1];
}

// قيس دالة: warmup الأول وبعدين median لكذا تشغيل بالـ ms
export function timeIt(fn: () => unknown, runs = 5): number {
  fn();
  const ts: number[] = [];
  for (let r = 0; r < runs; r++) {
    const t0 = performance.now();
    fn();
    ts.push(performance.now() - t0);
  }
  return median(ts);
}

// البحث الساذج: جرّب كل بداية i وقارن حرف بحرف لحد أول اختلاف
export function naiveSearch(text: string, pat: string, stats = { cmp: 0 }): number {
  const n = text.length, m = pat.length;
  for (let i = 0; i + m <= n; i++) {
    let j = 0;
    while (j < m) {
      stats.cmp++;
      if (text.charCodeAt(i + j) !== pat.charCodeAt(j)) break;
      j++;
    }
    if (j === m) return i;
  }
  return -1;
}

البحث الساذج بيجرب كل بداية i ويقارن حرف حرف لحد أول اختلاف. في النص العادي أول حرف غالبًا بيختلف، فالتكلفة حوالي n مقارنة. بس في نص عدائي التكلفة (n − m + 1) · m: نص فيه 200,000 حرف a، و pattern فيه 1,000 a وبعدهم b، هيطابق 1,000 حرف عند كل بداية وبعدين يفشل. العدّ فوق: 206,938 مقارنة على النص العشوائي (1.03·n) قصاد 199,199,000 على العدائي (996·n).

الـ indexOf الأصلي مش الـ loop ده. الـ spec مش بتحدد خوارزمية، و V8 في src/strings/string-search.h بيختار حسب طول الـ pattern: scan زي memchr لو حرف واحد، و scan بسيط لو الـ pattern أقصر من 7، ولو أطول بيبدأ بـ scan بسيط وبيعدّ الشغل اللي بيضيع (اسمه "badness")، ولما يزيد بيطلع لـ Boyer–Moore–Horspool وبعدين Boyer–Moore الكامل. على المدخل العدائي قرا نص 2,000,000 حرف في كام millisecond، والـ loop بتاعنا في JS خد من مئات الـ ms لثواني على نص أصغر 10 مرات (الأرقام بتتهز كتير على الجهاز ده عشان عليه ضغط، بس النسبة بتفضل في المئات).

Part 2 — KMP and the prefix function 🟡 Intermediateالجزء 2 — الـ KMP والـ prefix function

English

The prefix function π[i] is the length of the longest proper prefix of p[0..i] that is also a suffix of it (a "border"). For ABABAC it is 0 0 1 2 3 0. KMP uses it so the text pointer never moves back: after matching j characters and failing, the longest border of what you matched, π[j − 1], is the longest prefix of the pattern that's still lined up with the text, so you continue from there instead of from zero.

Why it's linear: every comparison either matches (then i and j advance, and j can grow at most n times in total) or fails (then j drops, and it can't drop more than it grew). So the search does at most 2n comparisons and building π at most 2m. On the adversarial input from Part 1 the count is 399,000 (2.00·n) instead of 199,199,000.

Where it earns its place is a byte stream: the whole state of the search is one integer j, so it carries across chunks with no buffering. A BEGIN INVOICE marker or a multipart boundary that arrives split across two chunks is still found, at its exact absolute offset. Searching each chunk on its own misses exactly those straddling matches: 3 of 3,000 invoices with 16 KiB chunks and 44 with 1 KiB chunks in the run below, and nothing at 64 KiB, which is why the bug survives testing.

The prefix function has another use: the smallest period. If p = m − π[m − 1] divides m, the string is one block repeated m / p times, which lets you collapse a log line that repeats the same error 40 times.

 pattern   A  B  A  B  A  C
 index     0  1  2  3  4  5
 pi        0  0  1  2  3  0       pi[4] = 3: "ABA" is both a prefix and a suffix of "ABABA"

 text   ...  A  B  A  B  A  B  A  C ...
             A  B  A  B  A  C            j = 5: mismatch (text B vs pattern C)
                   A  B  A  B  A  C      j = pi[4] = 3: "ABA" is already matched,
                                         compare the same text char again, i never moves back
الـ pi لكل مكان في ABABAC: مثلًا pi[4] = 3 لأن "ABA" هي prefix و suffix في نفس الوقت لـ "ABABA". تحت: طابقنا 5 حروف وفشلنا عند C قصاد B. بدل ما نرجع للصفر، بنزحلق الـ pattern بحيث أطول border يفضل متطابق: j = pi[4] = 3، يعني "ABA" متطابقة من غير ما نقارنها تاني، ونقارن نفس حرف النص من تاني. الـ i عمره ما بيرجع لورا.
// الـ code units بتوع string في Uint16Array، عشان نفس الكود يشتغل على strings وعلى bytes
export function units(s: string): Uint16Array {
  const out = new Uint16Array(s.length);
  for (let i = 0; i < s.length; i++) out[i] = s.charCodeAt(i);
  return out;
}

// الـ prefix function: الـ ⁦pi[i] =⁩ طول أطول prefix صحيح للـ ⁦p[0..i]⁩ وهو كمان suffix ليه
export function prefixFunction(p: ArrayLike<number>): Int32Array {
  const pi = new Int32Array(p.length);
  for (let i = 1, k = 0; i < p.length; i++) {
    // ارجع لأطول border أصغر لحد ما الحرف الجاي يطابق أو توصل للصفر
    while (k > 0 && p[i] !== p[k]) k = pi[k - 1];
    if (p[i] === p[k]) k++;
    pi[i] = k;
  }
  return pi;
}

// البحث بـ KMP: كل مكان بيبدأ فيه الـ ⁦pattern (⁩حتى لو متداخلين)، و ⁦O(n + m)⁩
export function kmpSearch(text: ArrayLike<number>, pat: ArrayLike<number>, stats = { cmp: 0 }): number[] {
  const pi = prefixFunction(pat);
  const hits: number[] = [];
  let j = 0;
  for (let i = 0; i < text.length; i++) {
    // كل مقارنة بتتعد مرة واحدة: يا تطابق ونتقدم، يا نرجع بالـ pi لحد الصفر
    while (true) {
      stats.cmp++;
      if (text[i] === pat[j]) { j++; break; }
      if (j === 0) break;
      j = pi[j - 1];
    }
    if (j === pat.length) { hits.push(i - j + 1); j = pi[j - 1]; }
  }
  return hits;
}

// الـ matcher للـ streams: الحالة كلها رقم واحد j بيعدّي من chunk للي بعده
export class KmpMatcher {
  private readonly pat: Uint8Array;
  private readonly pi: Int32Array;
  private j = 0;
  private seen = 0;
  constructor(pattern: Uint8Array) {
    if (pattern.length === 0) throw new RangeError("empty pattern");
    this.pat = pattern;
    this.pi = prefixFunction(pattern);
  }
  // بيرجّع الـ offsets المطلقة (من أول الـ stream) لكل match خلص جوه الـ chunk ده
  push(chunk: Uint8Array): number[] {
    const { pat, pi } = this;
    const hits: number[] = [];
    let j = this.j;
    for (let i = 0; i < chunk.length; i++) {
      const b = chunk[i];
      while (j > 0 && b !== pat[j]) j = pi[j - 1];
      if (b === pat[j]) j++;
      if (j === pat.length) { hits.push(this.seen + i - j + 1); j = pi[j - 1]; }
    }
    this.j = j;
    this.seen += chunk.length;
    return hits;
  }
}

// أصغر period: لو s = block مكرر، طول الـ ⁦block = m - pi[m-1]⁩ بشرط إنه يقسم m
export function smallestPeriod(s: string): number {
  if (s.length === 0) return 0;
  const pi = prefixFunction(units(s));
  const p = s.length - pi[s.length - 1];
  return s.length % p === 0 ? p : s.length;
}

The stream version: a pass-through Transform that reports every marker, then the same upload read with three chunk sizes.

نسخة الـ stream: Transform بيعدّي الـ bytes زي ما هي وبيبلّغ عن كل marker، وبعدين نفس ملف الـ upload بنقراه بـ 3 أحجام chunks مختلفة.
import { Transform, type TransformCallback } from "node:stream";
import { KmpMatcher } from "./kmp.ts";

// الـ Transform ده بيعدّي الـ bytes زي ما هي، وبيطلّع event لكل marker حتى لو اتقسم بين chunkين
export class MarkerScanner extends Transform {
  private readonly matcher: KmpMatcher;
  readonly offsets: number[] = [];
  constructor(marker: string) {
    super();
    this.matcher = new KmpMatcher(Buffer.from(marker, "utf8"));
  }
  override _transform(chunk: Buffer, _enc: BufferEncoding, cb: TransformCallback): void {
    for (const off of this.matcher.push(chunk)) {
      this.offsets.push(off);
      this.emit("marker", off);
    }
    cb(null, chunk);
  }
}

Part 3 — The Z-algorithm 🟡 Intermediateالجزء 3 — الـ Z-algorithm

English

The Z-array of a string s gives, for every position i, z[i] = the length of the longest common prefix of s and s.slice(i). For aabxaab it is 7 1 0 0 3 1 0. It's built in linear time with a box [l, r): the rightmost segment found so far that matches a prefix of s. If i is inside the box, s[i..r) is a copy of s[i−l..r−l), so z[i] starts at min(r − i, z[i − l]) for free; you only compare past r, and r only moves right, so the total work is linear.

To search, build pattern + separator + text and report every position in the text part with z[i] ≥ m. The separator must be a value that can't appear in either string; in an Int32Array of code units, -1 is perfect, so no match can run across it.

Compared with KMP on the same inputs, both are linear: 399,000 vs 401,000 comparisons on the adversarial case, 293,171 vs 361,374 on random binary text (Z also scans the pattern part). Z's advantage is that every z[i] means something directly: for a long catalogue line, one pass tells you how many SKUs start with EGY, with EGY-TV- and with the full EGY-TV-55Q. The rule of thumb: KMP for streams (one integer of state), Z for text already in memory, where it's easier to reason about.

 z     7  1  0  0  3  1  0

الـ z لكل مكان في aabxaab. عند i = 4 بنقارن من الأول ونلاقي "aab" مطابقة للـ prefix، فـ z[4] = 3 والصندوق بقى [4, 7). عند i = 5 إحنا جوه الصندوق، والجزء ده نسخة من s[1..3)، فـ z[5] بيبدأ من min(2, z[1]) = 1، ولأن 1 أقل من المسافة لآخر الصندوق، الإجابة نهائية من غير ولا مقارنة.
// الـ Z-array: الـ ⁦z[i] =⁩ طول أطول prefix مشترك بين s و ⁦s.slice(i)⁩
export function zArray(s: ArrayLike<number>, stats = { cmp: 0 }): Int32Array {
  const n = s.length;
  const z = new Int32Array(n);
  if (n > 0) z[0] = n;
  // الصندوق ⁦[l, r⁩): أبعد segment لقيناه بيطابق prefix، وبنعيد استخدامه
  for (let i = 1, l = 0, r = 0; i < n; i++) {
    if (i < r) z[i] = Math.min(r - i, z[i - l]);
    while (i + z[i] < n && (stats.cmp++, s[z[i]] === s[i + z[i]])) z[i]++;
    if (i + z[i] > r) { l = i; r = i + z[i]; }
  }
  return z;
}

// البحث: ⁦pattern +⁩ فاصل ⁦+ text⁩، والفاصل ⁦-1⁩ مستحيل يبقى code unit فمفيش match بيعدّيه
export function zSearch(text: string, pat: string, stats = { cmp: 0 }): number[] {
  const m = pat.length;
  const s = new Int32Array(m + 1 + text.length);
  for (let i = 0; i < m; i++) s[i] = pat.charCodeAt(i);
  s[m] = -1;
  for (let i = 0; i < text.length; i++) s[m + 1 + i] = text.charCodeAt(i);
  const z = zArray(s, stats);
  const hits: number[] = [];
  for (let i = m + 1; i < s.length; i++) if (z[i] >= m) hits.push(i - m - 1);
  return hits;
}

// في نفس اللفة: لكل طول L، كام مكان في الـ text بيبدأ بأول L حرف من الـ pattern
export function prefixOccurrenceCounts(text: string, pat: string): number[] {
  const m = pat.length;
  const s = new Int32Array(m + 1 + text.length);
  for (let i = 0; i < m; i++) s[i] = pat.charCodeAt(i);
  s[m] = -1;
  for (let i = 0; i < text.length; i++) s[m + 1 + i] = text.charCodeAt(i);
  const z = zArray(s);
  const atLeast = new Array<number>(m + 2).fill(0);
  for (let i = m + 1; i < s.length; i++) atLeast[z[i]]++;
  // تجميع من فوق لتحت: عدد الأماكن اللي الـ z بتاعها ⁦>= L⁩
  for (let L = m - 1; L >= 0; L--) atLeast[L] += atLeast[L + 1];
  return atLeast.slice(0, m + 1);
}

Part 4 — Rabin–Karp and rolling hashes 🔴 Advancedالجزء 4 — الـ Rabin–Karp والـ rolling hash

English

Rabin–Karp compares hashes instead of strings. With a polynomial hash h = Σ s[i]·B^(m−1−i) mod M, sliding the window one character is O(1): subtract the outgoing character times B^(m−1), multiply by B, add the incoming one. The modular arithmetic is the one from lesson 14 part 3; the JS-specific constraint is exactness. Every intermediate value must stay below 2^53 or doubles silently round, so with Numbers keep M below 2^26 (then h · B < 2^52). For a bigger modulus such as 2^61 − 1 use BigInt: same answers, 7–9× slower across my runs (≈54 ms vs ≈382 ms per million characters in the run below).

Equal hashes don't prove equal strings, so always confirm a hash hit with a real comparison. For random text the expected number of false hits is about windows / M: over 10^6 windows, 99 false hits with M = 10,007 (expected 99.93) and 0 with M = 2^26 − 5 (expected 0.01). The confirmation keeps the answer right; a good M keeps it fast.

A fixed, known base is a denial-of-service hole: anyone who reads your code can generate inputs that all collide, forcing a full comparison at every window and bringing back O(n·m). The demo generates 300 SKUs that share the target's hash under base 256; with a base drawn at random per process, the same text produces 0 false hits. Pick the base with crypto.randomInt at startup.

Two uses where rolling hashes beat everything else here: near-duplicates (hash every 8-word shingle of a product description and compare the sets with Jaccard: a copied description with one changed word scores 0.79, while a hand-rewritten one scores 0.00, so shingles catch copy-paste, not paraphrase) and many patterns of the same length (1,000 leaked 10-character voucher codes in 20,000 support messages: one Map of hashes and one pass per message, 9–44× faster than 1,000 includes calls per message across my runs, with identical results).

export type RkStats = { hashHits: number; falseHits: number };

// الـ Rabin–Karp بـ Number: لازم M أقل من ⁦2^26⁩ عشان h * B يفضل تحت ⁦2^53⁩ والحساب يفضل exact
export function rabinKarp(text: string, pat: string, M: number, B: number,
  stats: RkStats = { hashHits: 0, falseHits: 0 }): number[] {
  if (M >= 2 ** 26 || B <= 0 || B >= M) throw new RangeError("need 0 < B < M < 2^26");
  const n = text.length, m = pat.length;
  const hits: number[] = [];
  if (m === 0 || m > n) return hits;
  // الـ pow = B^(m-1) mod M، عشان نشيل الحرف اللي خارج من الشباك
  let pow = 1;
  for (let i = 1; i < m; i++) pow = (pow * B) % M;
  let hp = 0, ht = 0;
  for (let i = 0; i < m; i++) {
    hp = (hp * B + pat.charCodeAt(i)) % M;
    ht = (ht * B + text.charCodeAt(i)) % M;
  }
  for (let i = 0; ; i++) {
    if (ht === hp) {
      stats.hashHits++;
      // دايمًا أكّد بمقارنة الـ strings: تساوي الـ hash مش دليل
      if (text.startsWith(pat, i)) hits.push(i); else stats.falseHits++;
    }
    if (i + m >= n) break;
    ht = (ht - ((text.charCodeAt(i) * pow) % M) + M) % M;
    ht = (ht * B + text.charCodeAt(i + m)) % M;
  }
  return hits;
}

// نفس الخوارزمية بـ BigInt و ⁦M = 2^61 - 1⁩: احتمال الـ collision أقل بكتير، بس أبطأ
export function rabinKarpBig(text: string, pat: string, B: bigint): number[] {
  const M = (1n << 61n) - 1n;
  const n = text.length, m = pat.length;
  const hits: number[] = [];
  if (m === 0 || m > n) return hits;
  let pow = 1n;
  for (let i = 1; i < m; i++) pow = (pow * B) % M;
  let hp = 0n, ht = 0n;
  for (let i = 0; i < m; i++) {
    hp = (hp * B + BigInt(pat.charCodeAt(i))) % M;
    ht = (ht * B + BigInt(text.charCodeAt(i))) % M;
  }
  for (let i = 0; ; i++) {
    if (ht === hp && text.startsWith(pat, i)) hits.push(i);
    if (i + m >= n) break;
    ht = (ht - BigInt(text.charCodeAt(i)) * pow % M + M) % M;
    ht = (ht * B + BigInt(text.charCodeAt(i + m))) % M;
  }
  return hits;
}

// الـ hash للكلمة نفسها (FNV-1a على 32 bit) قبل ما ندخلها في الـ rolling hash
function wordHash(w: string): number {
  let h = 0x811c9dc5;
  for (let i = 0; i < w.length; i++) h = Math.imul(h ^ w.charCodeAt(i), 0x01000193);
  return h >>> 0;
}

// كل shingle = 8 كلمات ورا بعض، والـ hash بيتحرك كلمة كلمة (rolling)
export function shingleSet(text: string, k = 8): Set<number> {
  const words = text.toLowerCase().normalize("NFKC").split(/[^\p{L}\p{N}]+/u).filter(Boolean).map(wordHash);
  const out = new Set<number>();
  if (words.length < k) return out;
  let p1 = 1, p2 = 1;
  for (let i = 1; i < k; i++) { p1 = (p1 * B1) % M1; p2 = (p2 * B2) % M2; }
  let h1 = 0, h2 = 0;
  for (let i = 0; i < words.length; i++) {
    if (i >= k) {
      h1 = (h1 - (words[i - k] % M1) * p1 % M1 + M1) % M1;
      h2 = (h2 - (words[i - k] % M2) * p2 % M2 + M2) % M2;
    }
    h1 = (h1 * B1 + words[i] % M1) % M1;
    h2 = (h2 * B2 + words[i] % M2) % M2;
    if (i >= k - 1) out.add(h1 * 2 ** 26 + h2);
  }
  return out;
}

export function jaccard(a: Set<number>, b: Set<number>): number {
  let inter = 0;
  for (const x of a) if (b.has(x)) inter++;
  return inter / (a.size + b.size - inter || 1);
}

export function sameLengthScanner(patterns: string[], M = 67_108_859, B = randomInt(256, M - 1)) {
  const m = patterns[0].length;
  const hash = (s: string) => { let x = 0; for (let i = 0; i < m; i++) x = (x * B + s.charCodeAt(i)) % M; return x; };
  const byHash = new Map<number, string[]>();
  for (const p of patterns) {
    if (p.length !== m) throw new RangeError(`pattern ${p} is not ${m} long`);
    const k = hash(p);
    const list = byHash.get(k);
    if (list) list.push(p); else byHash.set(k, [p]);
  }
  let pow = 1;
  for (let i = 1; i < m; i++) pow = (pow * B) % M;
  return (text: string): [number, string][] => {
    const out: [number, string][] = [];
    if (text.length < m) return out;
    let h = hash(text);
    for (let i = 0; ; i++) {
      const cands = byHash.get(h);
      // أكّد بالمقارنة: ممكن اتنين ليهم نفس الـ hash
      if (cands) for (const p of cands) if (text.startsWith(p, i)) out.push([i, p]);
      if (i + m >= text.length) break;
      h = (h - ((text.charCodeAt(i) * pow) % M) + M) % M;
      h = (h * B + text.charCodeAt(i + m)) % M;
    }
    return out;
  };
}

بالعامية

الـ Rabin–Karp بيقارن hashes بدل strings. لو الـ hash polynomial، يعني h = Σ s[i]·B^(m−1−i) mod M، تحريك الشباك حرف واحد بيبقى O(1): اطرح الحرف الخارج مضروب في B^(m−1)، واضرب في B، وزوّد الحرف الداخل. الحساب الـ modular هو نفسه اللي في الدرس 14 الجزء 3. القيد الخاص بـ JS هو الدقة: كل رقم في النص لازم يفضل تحت 2^53، وإلا الـ doubles بتقرّب من غير ما تقولك، فلو بتستخدم Number خلي M تحت 2^26 (ساعتها h · B أقل من 2^52). ولو عايز modulus أكبر زي 2^61 − 1 استخدم BigInt: نفس الإجابات، بس أبطأ من 7 لـ 9 مرات في تشغيلاتي (≈54 ms قصاد ≈382 ms لكل مليون حرف في التشغيل فوق).

الـ hash المتساوي مش دليل إن الـ strings متساوية، فـ دايمًا أكّد الـ hit بمقارنة حقيقية. في النص العشوائي عدد الـ false hits المتوقع حوالي عدد الشبابيك مقسوم على M: على مليون شباك، 99 false hit مع M = 10,007 (والمتوقع 99.93)، وصفر مع M = 2^26 − 5 (والمتوقع 0.01). المقارنة بتخلي الإجابة صح، والـ M الكويس بيخليها سريعة.

الـ base الثابت والمعروف ثغرة denial of service: أي حد قرا الكود بتاعك يقدر يولّد مدخلات كلها collisions، فتضطر تقارن مقارنة كاملة عند كل شباك وترجع O(n·m). الـ demo ولّد 300 SKU ليهم نفس hash الـ target مع base = 256، ومع base عشوائي لكل process نفس النص طلّع 0 false hits. اختار الـ base بـ crypto.randomInt وإنت بتبدأ.

استخدامين الـ rolling hash بيكسب فيهم: الـ near-duplicates (اعمل hash لكل shingle من 8 كلمات في وصف المنتج وقارن الـ sets بـ Jaccard: وصف منسوخ واتغيّرت فيه كلمة جاب 0.79، ووصف اتكتب بإيد من الأول جاب 0.00، يعني الـ shingles بتمسك النسخ واللزق مش إعادة الصياغة)، و patterns كتير بنفس الطول (1,000 كود voucher اتسربوا طولهم 10 حروف في 20,000 رسالة support: Map واحدة للـ hashes ولفة واحدة على كل رسالة، أسرع من 9 لـ 44 مرة من 1,000 includes لكل رسالة في تشغيلاتي، ونفس النتيجة بالظبط).

في الـ shingles استخدمنا double hashing: modulus اتنين أقل من 2^26 ونركّبهم في رقم واحد h1 · 2^26 + h2، وده أقل من 2^52 فـ exact، واحتمال الـ collision بقى حوالي 1 / (M1 · M2) من غير BigInt.

Part 5 — Aho–Corasick for thousands of banned words 🔴 Advancedالجزء 5 — الـ Aho–Corasick لآلاف الكلمات الممنوعة

English

Aho–Corasick is KMP for a whole dictionary. Build a trie of the words (the structure itself is section 04 · 2.5), then add two kinds of links with a breadth-first pass: a failure link from every node to the node of its longest proper suffix that is also a path in the trie, and an output link to the nearest node on that failure chain where a word ends. Scanning the text is then one pass: follow the edge for the next character, or failure links until one exists; at each position report the node's word and walk the output links for the shorter words that end there too. Cost: O(text + total word length + matches), independent of how many words you have.

The benchmark below checks 5,000 banned words (half Latin, half Arabic, all seeded pseudo-words) against 10,000 seeded reviews (1.9M characters): a loop of includes per word took ≈7.4 s in the run shown; one big RegExp alternation (≈3 s) is faster but reports non-overlapping matches only, so it missed 2 (review, word) pairs where a banned word was a prefix of another (facotodi hidden by facotodico); our Aho–Corasick took ≈181 ms; modern-ahocorasick 3.3.0 took ≈1.6 s because it segments the text into graphemes first (correct for emoji and combining marks, and it brings whole-word options, streams and serialization). All but the RegExp return exactly the oracle's 5,949 pairs. Over three runs on this loaded machine the absolute times moved by 2–4×, but the order never changed: Aho–Corasick was 31–61× faster than the includes loop and 7–9× faster than the library.

Three things decide whether the filter is right, not just fast. Normalize first, the same way for words and text: NFKC, lowercase, strip tashkeel and tatweel, fold أ إ آ ٱ → ا, ة → ه, ى → ي (the normalization from lesson 10 part 1). Word boundaries: a substring automaton finds scam inside scampi and نصب (fraud) inside منصب (job title), the Scunthorpe problem; check that the characters before and after a match aren't letters or digits. Overlaps: حرامي contains حرام and scammer contains scam; Aho–Corasick reports both, so you decide the policy (longest wins, or all). Normalization also has limits: نصّاب becomes نصاب, which doesn't contain نصب, so word forms need variants in the list or a stemmer.

export type AcMatch = { start: number; end: number; word: number };

// الـ Aho–Corasick = trie للكلمات ⁦+ failure links + output links⁩، ولفة واحدة على النص
export class AhoCorasick {
  readonly words: readonly string[];
  private readonly next: Map<number, number>[] = [new Map()];
  private readonly fail: number[] = [0];
  // الـ ⁦out[v] =⁩ رقم الكلمة اللي بتخلص عند v أو ⁦-1⁩
  private readonly out: number[] = [-1];
  // الـ ⁦outLink[v] =⁩ أقرب node على سلسلة الـ fail بتخلص عندها كلمة (عشان المتداخل)
  private readonly outLink: number[] = [-1];

  constructor(words: readonly string[]) {
    this.words = words;
    words.forEach((w, wi) => {
      if (w.length === 0) throw new RangeError("empty word");
      let v = 0;
      for (let i = 0; i < w.length; i++) {
        const c = w.charCodeAt(i);
        let u = this.next[v].get(c);
        if (u === undefined) {
          u = this.next.length;
          this.next.push(new Map()); this.fail.push(0); this.out.push(-1); this.outLink.push(-1);
          this.next[v].set(c, u);
        }
        v = u;
      }
      this.out[v] = wi;
    });
    // الـ BFS بالمستوى: الـ fail لأي ⁦node =⁩ أطول suffix صحيح ليها موجود في الـ trie
    const queue = [...this.next[0].values()];
    for (let qi = 0; qi < queue.length; qi++) {
      const v = queue[qi];
      for (const [c, u] of this.next[v]) {
        let f = this.fail[v];
        while (f !== 0 && !this.next[f].has(c)) f = this.fail[f];
        const fu = this.next[f].get(c) ?? 0;
        this.fail[u] = fu;
        this.outLink[u] = this.out[fu] !== -1 ? fu : this.outLink[fu];
        queue.push(u);
      }
    }
  }

  get nodes(): number { return this.next.length; }

  search(text: string): AcMatch[] {
    const hits: AcMatch[] = [];
    let v = 0;
    for (let i = 0; i < text.length; i++) {
      const c = text.charCodeAt(i);
      while (v !== 0 && !this.next[v].has(c)) v = this.fail[v];
      v = this.next[v].get(c) ?? 0;
      // كل الكلمات اللي بتخلص هنا: الـ node نفسها وبعدين سلسلة الـ output links
      for (let u = this.out[v] !== -1 ? v : this.outLink[v]; u !== -1; u = this.outLink[u]) {
        const w = this.out[u];
        hits.push({ start: i + 1 - this.words[w].length, end: i + 1, word: w });
      }
    }
    return hits;
  }
}

الـ Aho–Corasick ده KMP لقاموس كامل. ابني trie للكلمات (الـ structure نفسه في القسم 04 · 2.5)، وبعدين زوّد نوعين links بلفة BFS: failure link من كل node لأطول suffix صحيح ليها موجود كـ path في الـ trie، و output link لأقرب node على سلسلة الـ failure دي بتخلص عندها كلمة. ساعتها البحث في النص لفة واحدة: امشي على الـ edge بتاع الحرف الجاي، أو على الـ failure links لحد ما تلاقي edge. وعند كل مكان بلّغ عن كلمة الـ node، وامشي على الـ output links عشان الكلمات الأقصر اللي بتخلص هنا برضه. التكلفة O(النص + مجموع أطوال الكلمات + عدد الـ matches)، ومش بتفرق معاها عدد الكلمات.

New here, on Node 22.19 (ICU 77.1, Unicode 16): "مُحَمَّد 👨‍👩‍👧 لا ﻻ" has 22 UTF-16 units, 19 code points and 11 graphemes. The tashkeel marks join their letters into one grapheme each, the family emoji is one grapheme of 8 units, and لا is two graphemes even though it renders as one ligature, while the presentation form ﻻ (U+FEFB) is one. NFKC turns ﻻ into U+0644 U+0627, the two normal letters.

Cutting by units breaks text: "تمام 👍".slice(0, 6) keeps half of the emoji's surrogate pair, isWellFormed() returns false, toWellFormed() replaces the half with U+FFFD, and encodeURIComponent throws URIError: URI malformed, so a truncated push notification or a redirect URL becomes a 500.

SMS pricing is a string algorithm problem. A message that fits the GSM-7 alphabet costs 160 characters per single SMS and 153 per part when it's split; one character outside it (any Arabic letter, any emoji) switches the whole message to UCS-2: 70 per single SMS and 67 per part, as Twilio's documentation states. Emoji outside the Basic Multilingual Plane take two units, so 70 Arabic letters fit one SMS and 70 letters plus 👍 cost two. Twilio's own example reproduces: 152 GSM characters plus one Unicode character are 3 segments.

For search: exact matching on UTF-16 units is fine, because high and low surrogates occupy separate ranges, so a well-formed pattern can never start or end in the middle of a pair. It is wrong for counting characters (use graphemes), it can split a grapheme (👨 is found at index 0 inside 👨‍👩‍👧), and it misses text with marks (searching for "محمد" inside "مُحَمَّد" returns −1). So normalize, run KMP or Aho–Corasick on the normalized text, and keep an index map from each normalized unit back to the original positions, so you can highlight the match in the text the user actually typed.

export type SmsCost = { encoding: "GSM-7" | "UCS-2"; units: number; segments: number };

// عدد الـ segments: لو حرف واحد بس برّه GSM-7، الرسالة كلها بتتحول UCS-2
export function smsSegments(text: string): SmsCost {
  let gsmUnits = 0;
  for (const ch of text) {
    if (GSM_BASIC.has(ch)) gsmUnits += 1;
    else if (GSM_EXT.has(ch)) gsmUnits += 2;
    else return ucs2(text);
  }
  return { encoding: "GSM-7", units: gsmUnits, segments: gsmUnits <= 160 ? 1 : Math.ceil(gsmUnits / 153) };
}

// في الـ UCS-2 الإيموجي برّه الـ BMP بياخد unitين (surrogate pair)، يعني text.length بالظبط
function ucs2(text: string): SmsCost {
  const units = text.length;
  return { encoding: "UCS-2", units, segments: units <= 70 ? 1 : Math.ceil(units / 67) };
}

export type Mapped = { norm: string; from: Int32Array; to: Int32Array };

// طبّع code point بـ code point، واحفظ لكل unit في النص المطبّع هو جه منين في الأصل
export function normalizeWithMap(s: string): Mapped {
  let norm = "";
  const from: number[] = [], to: number[] = [];
  for (let i = 0; i < s.length; ) {
    const cp = String.fromCodePoint(s.codePointAt(i)!);
    const n = normalizeForSearch(cp);
    if (n.length === 0 && to.length > 0) {
      // التشكيل اللي اتشال بيتلزق في الحرف اللي قبله، عشان الـ highlight يغطيه
      to[to.length - 1] = i + cp.length;
    }
    // الـ expansion زي ﻻ ← ل ا: الاتنين بيشاوروا على نفس المكان في الأصل
    for (let k = 0; k < n.length; k++) { from.push(i); to.push(i + cp.length); }
    norm += n;
    i += cp.length;
  }
  return { norm, from: Int32Array.from(from), to: Int32Array.from(to) };
}

// دوّر في النص المطبّع، ورجّع الـ ranges على النص الأصلي
export function searchOriginal(text: string, query: string): [number, number][] {
  const { norm, from, to } = normalizeWithMap(text);
  const q = normalizeForSearch(query);
  return kmpSearch(units(norm), units(q)).map((a) => [from[a], to[a + q.length - 1]]);
}

Cheat sheet · الخلاصة

  • One pattern, text in memory: native indexOf. V8 escalates to Boyer–Moore on its own; a JS loop is hundreds of times slower.
  • Naive search is O(n·m) on adversarial input (199,199,000 comparisons for n = 200k, m = 1,001); KMP is ≤ 2n (399,000).
  • KMP's state is one integer, so it carries across stream chunks; per-chunk search silently loses straddling matches.
  • π also gives the smallest period: p = m − π[m − 1] if it divides m.
  • Z-array: z[i] = longest common prefix with the start; search with pattern + (-1) + text; best for in-memory text and prefix counts.
  • Rabin–Karp: rolling hash in O(1) per step; with Numbers keep M < 2^26, or BigInt with 2^61 − 1 (7–9× slower here).
  • False hits ≈ windows / M: always confirm with a comparison; random base per process against crafted collisions.
  • Rolling hashes for 8-word shingles + Jaccard (copy-paste detection) and for many same-length patterns at once.
  • Aho–Corasick: trie + failure links + output links; one pass for any number of words; normalize first, check word boundaries, decide the overlap policy.
  • A RegExp alternation returns non-overlapping matches and needs escaping (no RegExp.escape in Node 22.19).
  • UTF-16 units are fine for exact matching, wrong for counting; graphemes for cutting; GSM-7 160/153 vs UCS-2 70/67 for SMS.
  • Search normalized text and keep an index map back to the original for highlighting.
بالعامية
  • pattern واحد والنص في الـ memory: استخدم indexOf الأصلي. V8 بيطلع لـ Boyer–Moore لوحده، والـ loop في JS أبطأ مئات المرات.
  • البحث الساذج O(n·m) على المدخل العدائي (199,199,000 مقارنة لـ n = 200k و m = 1,001)، والـ KMP بالكتير 2n (399,000).
  • حالة الـ KMP رقم واحد، فبتعدّي بين chunks الـ stream؛ والبحث جوه كل chunk لوحده بيضيّع الـ matches اللي على الحدود من غير ما حد يحس.
  • الـ π بتدّيك كمان أصغر period: p = m − π[m − 1] لو بيقسم m.
  • الـ Z-array: z[i] = أطول prefix مشترك مع البداية؛ البحث بـ pattern + (-1) + text؛ الأحسن للنص اللي في الـ memory ولعدّ الـ prefixes.
  • الـ Rabin–Karp: rolling hash بـ O(1) لكل خطوة؛ بالـ Number خلي M أقل من 2^26، أو BigInt مع 2^61 − 1 (أبطأ من 7 لـ 9 مرات هنا).
  • الـ false hits حوالي عدد الشبابيك / M: أكّد دايمًا بمقارنة، واعمل base عشوائي لكل process ضد الـ collisions المعمولة مخصوص.
  • الـ rolling hash لـ shingles من 8 كلمات + Jaccard (كشف النسخ واللزق)، ولـ patterns كتير بنفس الطول مرة واحدة.
  • الـ Aho–Corasick: trie + failure links + output links؛ لفة واحدة لأي عدد كلمات؛ طبّع الأول، واعمل check لحدود الكلمة، وحدد سياسة التداخل.
  • الـ RegExp بالـ | بيرجّع matches مش متداخلة ومحتاج escape (مفيش RegExp.escape في Node 22.19).
  • الـ UTF-16 units تمام للمطابقة الـ exact وغلط للعدّ؛ الـ graphemes للقطع؛ وللـ SMS ‏GSM-7 ‏160/153 قصاد UCS-2 ‏70/67.
  • دوّر في النص المطبّع واحتفظ بـ index map للأصل عشان الـ highlight.
