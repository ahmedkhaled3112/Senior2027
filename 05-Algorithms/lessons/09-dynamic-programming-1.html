Why this matters · ليه ده مهم

English

Dynamic programming appears whenever a product question asks for the best, how many or is it possible over a sequence of choices under a constraint: splitting a marketing budget, paying out cash in coins, installment schedules, promotion calendars, buying stock at daily prices. The interview version is a recurrence on a whiteboard. The production version also needs a state you can defend in code review, a table that fits in memory, numbers that don't silently overflow, the actual plan instead of just its value, the same answer for the same request, and a test against brute force that proves all of it.

بالعامية

الـ dynamic programming بيظهر كل ما سؤال من الـ product يطلب أحسن حاجة أو كام طريقة أو ينفع ولا لأ، على سلسلة اختيارات وجوه قيد: تقسيم budget الـ marketing، صرف فلوس كاش بعملات، جداول تقسيط، تقويم العروض، شراء بضاعة بأسعار يومية. نسخة الـ interview هي معادلة على السبورة. نسخة الـ production محتاجة كمان state تقدر تدافع عنه في الـ code review، و table يكفي في الـ memory، وأرقام متعملش overflow من غير ما تحس، والخطة نفسها مش قيمتها بس، ونفس الإجابة لنفس الـ request، و test ضد الـ brute force يثبت كل ده.

Part 1 — Recognizing DP, with numbers 🟢 Basicالجزء 1 — إزاي تعرف إنها DP، وتثبتها بالأرقام

English

Section 03 already gives you the five-step recipe, the fib call tree and minimum coins (03 · 09 part 6), and section 16 drills the recursion → memo → table ladder under a clock (16 · 05 part 7). This part adds one habit: measure the two properties instead of arguing about them.

Overlapping subproblems is a number you can print. Wrap the naive recursion with a counter keyed by its arguments. For "how many ways can a customer pay X EGP with 25-piastre, 50-piastre, 1-EGP and 5-EGP coins", 50 EGP takes 1,436,101 calls but only 1,027 distinct (coin index, amount) pairs, and the pair (3, 25) alone is solved 9,900 times. The same function with a memo makes 1,601 calls. When the distinct count is tiny next to the call count, a memo pays. When every call is unique, as with the two halves of merge sort, it's divide and conquer, not DP (lesson 08).

Optimal substructure fails more quietly. Take "the longest route between two hubs that never revisits a hub". The best Nasr→Maadi route (37 km) and the best Maadi→Giza route (40 km) glue into 77 km, but the glued route visits Nasr, Shubra and Giza twice. The real best Nasr→Giza route through Maadi is 27 km. The halves aren't independent: what one half uses constrains the other. To restore independence you must put "which hubs are already used" into the state, which is a bitmask and therefore exponential: that is exactly Held–Karp in lesson 10 part 4. Shortest paths don't have this problem: with non-negative weights a shortest walk never repeats a hub, so every piece of a shortest route is itself shortest.

// بالقروش: ربع جنيه، نص جنيه، جنيه، 5 جنيه
const COINS = [25, 50, 100, 500];

const solvedTimes = new Map<string, number>();
let calls = 0;

// عدد الطرق إنك تدفع amount بالعملات من index i ولآخر القايمة (من غير ترتيب)
function waysNaive(i: number, amount: number): number {
  calls++;
  const key = `${i}:${amount}`;
  solvedTimes.set(key, (solvedTimes.get(key) ?? 0) + 1);
  if (amount === 0) return 1;
  if (amount < 0 || i === COINS.length) return 0;
  // يا إما تستخدم العملة i تاني، يا إما تعدّيها للي بعدها
  return waysNaive(i, amount - COINS[i]) + waysNaive(i + 1, amount);
}

for (const egp of [5, 10, 20, 50]) {
  calls = 0;
  solvedTimes.clear();
  const ways = waysNaive(0, egp * 100);
  const repeated = [...solvedTimes.values()].filter((t) => t > 1).length;
  const [worstKey, worstTimes] = [...solvedTimes].sort((a, b) => b[1] - a[1])[0];
  console.log(
    `${egp} EGP: ways=${ways} calls=${calls.toLocaleString("en-US")} distinct=${solvedTimes.size}` +
      ` repeated=${repeated} worst=${worstKey} solved ${worstTimes.toLocaleString("en-US")}x`,
  );
}

// نفس الـ recursion بـ memo: كل subproblem بيتحل مرة واحدة بس
function waysMemo(amount: number): { ways: number; calls: number } {
  const memo = new Map<string, number>();
  let n = 0;
  const go = (i: number, a: number): number => {
    n++;
    if (a === 0) return 1;
    if (a < 0 || i === COINS.length) return 0;
    const key = `${i}:${a}`;
    const hit = memo.get(key);
    if (hit !== undefined) return hit;
    const v = go(i, a - COINS[i]) + go(i + 1, a);
    memo.set(key, v);
    return v;
  };
  return { ways: go(0, amount), calls: n };
}
console.log("memo 50 EGP:", waysMemo(5000));

// الخاصية التانية: ⁦optimal substructure —⁩ هنا بتفشل، فالمسألة مش DP بالشكل ده
type Hub = "Nasr" | "Maadi" | "Giza" | "Shubra";
// مسافات طرق تقريبية بالكيلو، متألفة للمثال
const roads: [Hub, Hub, number][] = [
  ["Nasr", "Maadi", 15],
  ["Maadi", "Giza", 12],
  ["Nasr", "Shubra", 11],
  ["Shubra", "Giza", 14],
];
const adj = new Map<Hub, [Hub, number][]>();
for (const [a, b, km] of roads) {
  adj.set(a, [...(adj.get(a) ?? []), [b, km]]);
  adj.set(b, [...(adj.get(b) ?? []), [a, km]]);
}

// أطول route بسيط (مفيش hub بيتكرر) من from لـ to — brute force بالـ DFS
function longestSimple(from: Hub, to: Hub, visited = new Set<Hub>([from])): { km: number; path: Hub[] } {
  if (from === to) return { km: 0, path: [to] };
  let best = { km: -Infinity, path: [] as Hub[] };
  for (const [next, km] of adj.get(from) ?? []) {
    if (visited.has(next)) continue;
    visited.add(next);
    const rest = longestSimple(next, to, visited);
    visited.delete(next);
    if (km + rest.km > best.km) best = { km: km + rest.km, path: [from, ...rest.path] };
  }
  return best;
}

الـ overlapping subproblems رقم تقدر تطبعه: لف الـ recursion الساذجة بـ counter مفتاحه الـ arguments. في "كام طريقة العميل يدفع X جنيه بعملات 25 قرش و 50 قرش وجنيه و 5 جنيه"، الـ 50 جنيه أخدت 1,436,101 call على 1,027 زوج (رقم العملة، المبلغ) بس، والزوج (3, 25) لوحده اتحل 9,900 مرة. نفس الـ function بـ memo عملت 1,601 call. لما عدد الأزواج المختلفة يبقى صغير جدًا جنب عدد الـ calls، الـ memo هيكسب. لما كل call تبقى جديدة زي نصّين الـ merge sort، يبقى ده divide and conquer مش DP (الدرس 08).

الـ optimal substructure بيفشل بهدوء أكتر. خد "أطول طريق بين two hubs من غير ما تعدّي على hub مرتين". أحسن طريق Nasr→Maadi (37 كيلو) وأحسن طريق Maadi→Giza (40 كيلو) لو لزقتهم يطلعوا 77، بس الطريق الملزوق بيعدّي على Nasr و Shubra و Giza مرتين. الإجابة الحقيقية لأطول طريق Nasr→Giza عن طريق Maadi هي 27 كيلو. النصّين مش مستقلين: اللي نص بيستخدمه بيقيّد النص التاني. عشان ترجّع الاستقلال لازم تحط "الـ hubs اللي اتزارت" جوه الـ state، وده bitmask يعني exponential — وده بالظبط Held–Karp في الدرس 10 الجزء 4. الـ shortest paths معندهاش المشكلة دي: مع أوزان مش سالبة أقصر طريق عمره ما يكرر hub، فأي حتة من أقصر طريق هي نفسها أقصر طريق.

والجدول اللي فوق بيوريك إن الإشارات لوحدها مش كفاية: فيه مسألتين شكلهم DP وهما فخ — واحدة الـ greedy بيحلها لأن فئات الفلوس canonical، والتانية مسألة graph عادية.

Interview question "How do you know a problem is DP? Define the state and the transition for coin change." → Two properties: optimal substructure (the best answer is built from best answers to independent smaller problems) and overlapping subproblems (the same smaller problems recur; you can count them). Minimum coins: state dp[a] = fewest pieces that pay exactly a; transition dp[a] = 1 + min(dp[a − c]) over coins c ≤ a; base dp[0] = 0; unreachable = Infinity. Number of ways: dp[a] += dp[a − c] with the coin loop outside the amount loop so each combination is counted once.
"إزاي تعرف إن المسألة DP؟ عرّف الـ state والـ transition لـ coin change." ← خاصيتين: optimal substructure (أحسن إجابة مبنية من أحسن إجابات لمسائل أصغر مستقلة) و overlapping subproblems (نفس المسائل الصغيرة بتتكرر وتقدر تعدّها). أقل عدد عملات: الـ state هو dp[a] = أقل عدد قطع تدفع بيها a بالظبط، والـ transition dp[a] = 1 + min(dp[a − c]) على كل عملة c ≤ a، والـ base هو dp[0] = 0، والمستحيل = Infinity. عدد الطرق: dp[a] += dp[a − c] والـ loop بتاع العملات بره loop المبلغ عشان كل combination يتعد مرة واحدة.

Part 2 — Write the state before the code 🟢 Basicالجزء 2 — اكتب الـ state قبل الكود

English

Most DP bugs are state bugs, and they're cheaper to catch in a comment than in a test. Before any code, fill in six lines: (1) the state in words, (2) the transition, (3) the base cases, (4) where the answer is, (5) the evaluation order (every state only reads states already computed), and (6) the cost = number of states × cost per transition. If you can't write line 1 in one plain sentence, you don't have a state yet.

Two worked examples. Promo days (house robber): each day has an expected extra revenue, which can be negative when the discount costs more than it brings, and promos may not run on two consecutive days. Installment schedules (climbing stairs): how many ways to pay an n-month delivery subscription when each installment covers 1 or 2 months; 12 months give 233 schedules.

Then the business changes the rule, which is where real bugs come from: promos may now run several days in a row, but after a run ends there must be two days without a promo. The old state "best total for the first i days" no longer tells you whether day i+1 may run a promo, because that depends on how day i ended. A tempting patch keeps the old array plus a flag "did the best plan end with a promo?". It is wrong: on a tie, or when a slightly worse plan that ends with a promo is better for tomorrow, the flag has thrown that plan away. The fix is a new dimension: the state becomes (day, how the day ended) with three values: run, cool1 (first rest day after a run) and free. fast-check finds the bug in 3 runs and shrinks it to [1, 0, 1]; the hand example [5, −1, 5] gives 5 instead of 9.

The buggy versions in this lesson sit next to the correct ones only so you can watch the oracle catch them, which is why some tests below are red on purpose. In your algorithms-ts repo, delete them, or wrap the property in assert.throws so CI stays green and the lesson stays executable.

// المسألة: أكبر إيراد إضافي من أيام العروض، ومينفعش عرض في يومين ورا بعض
// (1) الـ state بالكلام: ⁦best[i] =⁩ أكبر إيراد من أول i أيام بس (الأيام من 0 لـ i-1)
// (2) الـ ⁦transition: best[i] = max(best[i-1], best[i-2] + gain[i-1])⁩
// يعني يا إما اليوم i-1 من غير عرض، يا إما فيه عرض واليوم اللي قبله فاضي أكيد
// (3) الـ base cases: best[0] = 0 و ⁦best[1] = max(0, gain[0])⁩
// (4) الإجابة فين: ⁦best[n]⁩
// (5) ترتيب الحساب: i من 2 لحد n، لأن كل خانة محتاجة الخانتين اللي قبلها
// (6) التكلفة: ⁦n+1 states ×⁩ شغل ⁦O(1)⁩ لكل ⁦state = O(n)⁩ وقت
export function promoDays(gain: readonly number[]): number {
  let twoBack = 0; // يعني ⁦best[i-2]⁩
  let oneBack = Math.max(0, gain[0] ?? 0); // يعني ⁦best[i-1]⁩
  if (gain.length === 0) return 0;
  for (let i = 2; i <= gain.length; i++) {
    const cur = Math.max(oneBack, twoBack + gain[i - 1]);
    twoBack = oneBack;
    oneBack = cur;
  }
  return oneBack;
}

// الـ ⁦state: ways[m] =⁩ عدد جداول الدفع لـ m شهر، كل قسط بيغطي شهر أو شهرين
// الـ ⁦transition: ways[m] = ways[m-1] + ways[m-2] (⁩آخر قسط شهر واحد أو شهرين)
// الـ ⁦base: ways[0] = 1 (⁩جدول فاضي) و ⁦ways[1] = 1 —⁩ والإجابة ⁦ways[months]⁩
export function installmentPlans(months: number): number {
  let prev = 1, cur = 1;
  for (let m = 2; m <= months; m++) [prev, cur] = [cur, prev + cur];
  return cur;
}

الـ state machine بعد القاعدة الجديدة. كل يوم بيخلص في حالة من تلاتة: run = فيه عرض النهارده، وتيجي من run (بنكمّل) أو من free (بنبدأ). cool1 = أول يوم راحة بعد run، ومش جاية غير من run. free = عدّى يومين راحة أو أكتر ومسموح نبدأ run، وجاية من cool1 أو free. السطر الأخير بيمشّي مثال: حر ← عرض ← عرض ← راحة أولى ← حر ← حر.
// القاعدة الجديدة: العروض ممكن تبقى أيام ورا بعض (run)، بس بعد ما الـ run يخلص لازم يومين من غير عرض

// ❌ الـ state القديم: ⁦best[i]⁩ بس، ومعاه ⁦flag "⁩الخطة الأحسن لحد امبارح خلصت بعرض؟"
export function cooldownBuggy(gain: readonly number[]): number {
  const n = gain.length;
  const best = new Array<number>(n + 1).fill(0);
  const endsWithPromo = new Array<boolean>(n + 1).fill(false);
  for (let i = 1; i <= n; i++) {
    const g = gain[i - 1];
    // نبدأ run جديد: لازم اليومين اللي قبله من غير عرض
    const fresh = (i >= 3 ? best[i - 3] : 0) + g;
    // نكمّل الـ run: بس لو "الخطة الأحسن" بالصدفة خلصت بعرض
    const promo = endsWithPromo[i - 1] ? Math.max(fresh, best[i - 1] + g) : fresh;
    best[i] = Math.max(best[i - 1], promo);
    endsWithPromo[i] = promo > best[i - 1];
  }
  return best[n];
}

// ✅ زوّد dimension: اليوم خلص على إيه؟ عرض ⁦(run) /⁩ أول يوم راحة ⁦(cool1) /⁩ حر (free)
export function cooldownPlan(gain: readonly number[]): number {
  let run = -Infinity, cool1 = -Infinity, free = 0;
  for (const g of gain) {
    // عرض النهارده: يا إما بنكمّل run، يا إما بنبدأ من حالة free
    const nextRun = Math.max(run, free) + g;
    // أول يوم راحة: لازم امبارح كان عرض
    const nextCool1 = run;
    // حر: عدّى يومين راحة على الأقل (أو مفيش عروض خالص لسه)
    const nextFree = Math.max(cool1, free);
    [run, cool1, free] = [nextRun, nextCool1, nextFree];
  }
  return Math.max(run, cool1, free);
}

أغلب bugs الـ DP هي bugs في الـ state، ومسكها في comment أرخص من مسكها في test. قبل أي كود املا 6 سطور: (1) الـ state بالكلام، (2) الـ transition، (3) الـ base cases، (4) الإجابة فين، (5) ترتيب الحساب (كل state بيقرا states اتحسبت قبله)، و(6) التكلفة = عدد الـ states × تكلفة الـ transition. لو مش قادر تكتب سطر 1 في جملة واحدة بسيطة، يبقى لسه معندكش state.

مثالين محلولين. أيام العروض (house robber): كل يوم ليه إيراد إضافي متوقع، وممكن يبقى بالسالب لو الخصم بيكلف أكتر ما بيجيب، وممنوع عرضين في يومين ورا بعض. جداول التقسيط (climbing stairs): كام طريقة تدفع اشتراك توصيل n شهر لو كل قسط بيغطي شهر أو شهرين؛ الـ 12 شهر ليهم 233 جدول.

Part 3 — Memo vs table vs O(1) space 🟡 Intermediateالجزء 3 — memo ولا table ولا O(1) space

English

One problem, four implementations, measured: the fewest coins a self-checkout dispenser loaded with 25-piastre, 50-piastre and 1-EGP coins must give for an amount. (This set is canonical, so greedy would also be optimal; we use it to compare techniques, and the DP stays correct when the set changes, for example when the 50-piastre tube runs empty.)

  • Memo with a Map: recursion that only visits reachable states. For 100,000 piastres it makes 11,997 calls over the 4,001 multiples of 25.
  • Memo with an array: same calls, but the cache is allocated for all 100,001 amounts even though only 1 in 25 is ever touched.
  • Table: a loop over every piastre from 0 to the amount, no recursion. It does 25× more cells than needed here, but has no depth limit.
  • Rolling variables: divide by 25 first; then dp[k] reads only dp[k−1], dp[k−2] and dp[k−4], so four variables replace the table.

The memo's recursion depth equals amount ÷ 25. At 1,000 EGP that is 4,000 frames and works; at 5,000 EGP (20,000 frames) both memo versions throw RangeError: Maximum call stack size exceeded, while the table and the rolling version don't care. Node's limit is about 9–15k frames for a small function and depends on frame size and JIT state (lesson 02 part 1).

Memory is the other axis. In Node 22 a packed number[] costs the same 8 bytes per element as a Float64Array, so the typed array's win isn't size by default: it's that you can pick Int32Array (half) or Uint8Array/a bitset when values fit, that it's one contiguous allocation, and that it can't silently degrade. A memo initialised with null and then filled with doubles turns into an array of pointers to boxed heap numbers: 22.9 MB instead of 7.6 MB for a million entries. A Map costs ≈43 MB per million entries, but only 2.4 MB if you store just the reachable multiples of 25: memo wins when the reachable states are sparse. Elements kinds are covered in section 04 (04 · 01).

// ماكينة صرف فكّة في self-checkout: عندها عملات 25 و 50 قرش وجنيه بس
export const DISPENSER = [25, 50, 100] as const;
export const counters = { calls: 0 };

// (1) الـ memo بـ Map: بيحسب بس الـ states اللي بيوصلها (مضاعفات الـ 25)
export function fewestCoinsMemoMap(amount: number): number {
  const memo = new Map<number, number>();
  const go = (a: number): number => {
    counters.calls++;
    if (a === 0) return 0;
    const hit = memo.get(a);
    if (hit !== undefined) return hit;
    let best = Infinity;
    for (const c of DISPENSER) if (c <= a) best = Math.min(best, 1 + go(a - c));
    memo.set(a, best);
    return best;
  };
  return go(amount);
}

// (2) نفس الكلام بس الـ cache مصفوفة: ⁦-1⁩ معناها "لسه ماتحسبتش"
export function fewestCoinsMemoArray(amount: number): number {
  const memo = new Float64Array(amount + 1).fill(-1);
  const go = (a: number): number => {
    counters.calls++;
    if (a === 0) return 0;
    if (memo[a] !== -1) return memo[a];
    let best = Infinity;
    for (const c of DISPENSER) if (c <= a) best = Math.min(best, 1 + go(a - c));
    memo[a] = best;
    return best;
  };
  return go(amount);
}

// (3) الـ tabulation: loop من تحت لفوق على كل قرش من 0 لـ amount، ومفيش recursion
export function fewestCoinsTable(amount: number): number {
  const dp = new Float64Array(amount + 1).fill(Infinity);
  dp[0] = 0;
  for (let a = 1; a <= amount; a++) {
    for (const c of DISPENSER) if (c <= a && dp[a - c] + 1 < dp[a]) dp[a] = dp[a - c] + 1;
  }
  return dp[amount];
}

// (4) الـ rolling variables: بوحدات الـ 25 قرش، الخانة k محتاجة k-1 و k-2 و k-4 بس
export function fewestCoinsRolling(amount: number): number {
  if (amount % 25 !== 0) return Infinity;
  const k = amount / 25;
  // الـ ⁦d1 = dp[i-1]⁩ و ⁦d2 = dp[i-2]⁩ و ⁦d3 = dp[i-3]⁩ و ⁦d4 = dp[i-4]⁩
  let d1 = 0, d2 = Infinity, d3 = Infinity, d4 = Infinity;
  for (let i = 1; i <= k; i++) {
    const cur = 1 + Math.min(d1, d2, d4);
    [d4, d3, d2, d1] = [d3, d2, d1, cur];
  }
  return d1;
}

Part 4 — 1D DP on business problems 🟢 Basicالجزء 4 — الـ 1D DP على مسائل الشغل

English

The classic 1D problems, each mapped to a real request and each checked against brute force with fast-check for inputs up to 14–15 days:

  • Climbing stairs → installment schedules with any set of lengths: ways[m] = Σ ways[m − L]. With 1-, 3- and 6-month installments, 12 months have 91 schedules.
  • House robber → promo days, plus the circular version: the plan repeats every week, so Saturday (last) is adjacent to next Sunday (first). Solve two straight lines, without the first day and without the last, and take the better one. On the sample week the straight answer is 2,800 EGP, the circular one 2,100.
  • Max profit from a stock → buying shipments at daily wholesale prices, holding at most one shipment: one trade (keep the running minimum: 11), unlimited trades (sum every rise: 42), unlimited with a 3 EGP fee per sale (20), and unlimited with a one-day cooldown after each sale (33). The last two are small state machines: hold/cash, and hold/sold/rest, the same idea as the promo cooldown in Part 2.

The oracle for the stock family is a single exponential function that tries every buy/sell/wait sequence and takes the options (maxTrades, fee, cooldown) as parameters. One oracle, four fast versions, 300 random cases each.

One fast-check detail decides whether "up to 15 days" is true: its default size is "small", and with maxLength: 14 none of 2,000 sampled arrays had more than 10 items. With size: "medium", 477 of 2,000 had 11–14 items. Every array arbitrary in these tests with maxLength above 10 passes size: "medium", so the bigger, more interesting inputs really get exercised.

import { promoDays } from "./promo.ts";

// تقسيط اشتراك توصيل: كل قسط بيغطي 1 أو 3 أو 6 شهور — كام جدول مختلف لـ months شهر؟
export function installmentSchedules(months: number, lengths: readonly number[] = [1, 3, 6]): number {
  const ways = new Array<number>(months + 1).fill(0);
  ways[0] = 1;
  for (let m = 1; m <= months; m++) {
    // آخر قسط طوله L، واللي قبله أي جدول لـ m-L شهر
    for (const L of lengths) if (L <= m) ways[m] += ways[m - L];
  }
  return ways[months];
}

// العروض الأسبوعية بتتكرر: آخر يوم (السبت) جنب أول يوم (الحد) في الأسبوع اللي بعده
export function weeklyPromo(gain: readonly number[]): number {
  if (gain.length === 1) return Math.max(0, gain[0]);
  // يا إما من غير أول يوم، يا إما من غير آخر يوم — وكل واحدة منهم خط مستقيم عادي
  return Math.max(promoDays(gain.slice(1)), promoDays(gain.slice(0, -1)));
}

// تاجر بيشتري شحنة موبايلات بسعر الجملة النهارده ويبيعها بعدين — شحنة واحدة في الإيد في أي وقت

// صفقة واحدة بس: أقل سعر شفناه لحد النهارده، وأحسن فرق
export function oneTrade(price: readonly number[]): number {
  let minSoFar = Infinity, best = 0;
  for (const p of price) {
    minSoFar = Math.min(minSoFar, p);
    best = Math.max(best, p - minSoFar);
  }
  return best;
}

// صفقات بلا حدود: كل يوم السعر طلع فيه ضيف الزيادة
export function unlimitedTrades(price: readonly number[]): number {
  let total = 0;
  for (let d = 1; d < price.length; d++) total += Math.max(0, price[d] - price[d - 1]);
  return total;
}

// مع عمولة fee على كل بيعة: state machine بحالتين — ماسك شحنة (hold) أو فاضي (cash)
export function tradesWithFee(price: readonly number[], fee: number): number {
  let hold = -Infinity, cash = 0;
  for (const p of price) {
    const nextHold = Math.max(hold, cash - p);
    const nextCash = Math.max(cash, hold + p - fee);
    [hold, cash] = [nextHold, nextCash];
  }
  return cash;
}

// مع cooldown: بعد أي بيعة لازم يوم راحة قبل ما تشتري تاني ⁦— 3⁩ حالات
export function tradesWithCooldown(price: readonly number[]): number {
  // الـ ⁦hold =⁩ ماسك شحنة، ⁦sold =⁩ بايع النهارده، ⁦rest =⁩ فاضي وحر يشتري بكرة
  let hold = -Infinity, sold = -Infinity, rest = 0;
  for (const p of price) {
    const nextHold = Math.max(hold, rest - p);
    const nextSold = hold + p;
    const nextRest = Math.max(rest, sold);
    [hold, sold, rest] = [nextHold, nextSold, nextRest];
  }
  return Math.max(sold, rest);
}

// الـ oracle: جرّب كل تسلسل أفعال ممكن (اشتري/بيع/استنى⁦) —⁩ أُسّي، بس صح أكيد
export function bruteTrades(
  price: readonly number[],
  opts: { maxTrades?: number; fee?: number; cooldown?: boolean } = {},
): number {
  const { maxTrades = Infinity, fee = 0, cooldown = false } = opts;
  const go = (d: number, holding: boolean, trades: number, blocked: boolean): number => {
    if (d === price.length) return 0;
    let best = go(d + 1, holding, trades, false);
    if (!holding && !blocked && trades < maxTrades) best = Math.max(best, -price[d] + go(d + 1, true, trades, false));
    if (holding) best = Math.max(best, price[d] - fee + go(d + 1, false, trades + 1, cooldown));
    return best;
  };
  return go(0, false, 0, false);
}

English

0/1 knapsack (each campaign at most once): section 03 walks through the 2D table, the 1D array iterated backwards and why forwards breaks it (03 · 09 part 6). What's new here is turning that warning into a test: the same oracle runs against all three versions, and the forwards loop fails with the smallest possible counterexample, one campaign costing 1 with budget 2, bought twice. Forwards silently is the unbounded knapsack: on the sample plan it reports 660 by buying "Influencers" twice, while the real best is 615.

Unbounded knapsack is the case where forwards is correct: filling a delivery van with as many cartons of each kind as fit. At 125 units of space the DP earns 1,815 EGP of margin; greedy by margin per unit earns 1,790 and leaves 2 units empty.

Coin change in piastres with the EGP denominations (25 and 50 piastres; 1, 5, 10, 20, 50, 100 and 200 EGP): minimum pieces for 387.75 EGP is 10, and 10.10 EGP is impossible (Infinity, not 0). Comparing greedy with DP for every amount up to 300 EGP gives 0 mismatches; by a classic result (Kozen & Zaks, 1994) a non-canonical system already fails below the sum of its two largest coins, so this check covers every amount. The number of ways to pay 1,000 EGP is 186,985,595,336, still a safe integer. For 10,000 EGP the true count is 5,775,357,367,834,431,101, above Number.MAX_SAFE_INTEGER: the Number version prints …431,488 with no error. Use BigInt (exact, slower) or a modulus such as 109+7 (what interviews ask for; both agree mod p).

Pseudo-polynomial: the cost is O(n × amount), and the amount is a value, not an input size. 100,000 EGP is 107 piastres, so a 107-cell table. Divide every denomination and the amount by their GCD (25) and the table shrinks to 4×105 cells with the same answer.

// الـ cost بالألف جنيه
export type Campaign = { name: string; cost: number; revenue: number };

// 0/1 بـ table كامل: ⁦dp[i][b] =⁩ أحسن إيراد من أول i حملات بـ budget قدره b
export function campaigns2D(items: readonly Campaign[], budget: number): number {
  const dp = Array.from({ length: items.length + 1 }, () => new Array<number>(budget + 1).fill(0));
  for (let i = 1; i <= items.length; i++) {
    const { cost, revenue } = items[i - 1];
    for (let b = 0; b <= budget; b++) {
      dp[i][b] = dp[i - 1][b];
      if (cost <= b) dp[i][b] = Math.max(dp[i][b], dp[i - 1][b - cost] + revenue);
    }
  }
  return dp[items.length][budget];
}

// 0/1 بصف واحد: لازم b ينزل لتحت عشان ⁦dp[b - cost]⁩ لسه بتاع "من غير الحملة دي"
export function campaigns1D(items: readonly Campaign[], budget: number): number {
  const dp = new Float64Array(budget + 1);
  for (const { cost, revenue } of items)
    for (let b = budget; b >= cost; b--) dp[b] = Math.max(dp[b], dp[b - cost] + revenue);
  return dp[budget];
}

// ❌ نفس الكود بس b طالع لفوق: الحملة ممكن تتاخد أكتر من مرة من غير ما حد ياخد باله
export function campaignsForwardBug(items: readonly Campaign[], budget: number): number {
  const dp = new Float64Array(budget + 1);
  for (const { cost, revenue } of items)
    for (let b = cost; b <= budget; b++) dp[b] = Math.max(dp[b], dp[b - cost] + revenue);
  return dp[budget];
}

export type Carton = { kind: string; space: number; margin: number };
export function fillVan(cartons: readonly Carton[], capacity: number): number {
  const dp = new Float64Array(capacity + 1);
  for (const { space, margin } of cartons)
    for (let b = space; b <= capacity; b++) dp[b] = Math.max(dp[b], dp[b - space] + margin);

}

export function minPieces(amount: number, denoms: readonly number[] = EGP): number {
  const dp = new Float64Array(amount + 1).fill(Infinity);
  dp[0] = 0;
  for (let a = 1; a <= amount; a++)
    for (const c of denoms) if (c <= a && dp[a - c] + 1 < dp[a]) dp[a] = dp[a - c] + 1;
  return dp[amount];
}

  dp[0] = 1;

  return dp[amount];
}

}

export function waysMod(amount: number, denoms: readonly number[] = EGP, mod = 1_000_000_007): number {
  const dp = new Int32Array(amount + 1);
  dp[0] = 1;
  for (const c of denoms) for (let a = c; a <= amount; a++) dp[a] = (dp[a] + dp[a - c]) % mod;

}

  const g = denoms.reduce(gcd);
  if (amount % g !== 0) return Infinity;
  return minPieces(amount / g, denoms.map((c) => c / g));
}

بالعامية

الـ 0/1 knapsack (كل حملة مرة واحدة على الأكتر): القسم 03 شرح الـ table الـ 2D، والـ array الـ 1D اللي بيلف لتحت، وليه اللف لفوق بيبوّظه (03 · 09 الجزء 6). الجديد هنا إننا بنحوّل التحذير ده لـ test: نفس الـ oracle بيتشغل على التلات نسخ، واللف لفوق بيقع بأصغر مثال ممكن — حملة تكلفتها 1 و budget = 2، اتشترت مرتين. اللف لفوق هو نفسه الـ unbounded knapsack من غير ما يقولك: في خطة المثال قال 660 لأنه اشترى "Influencers" مرتين، والصح 615.

الـ unbounded knapsack هو الحالة اللي اللف لفوق فيها صح: تملا عربية توصيل بأي عدد من كل نوع كرتونة يكفي. عند 125 وحدة مساحة الـ DP كسب 1,815 جنيه هامش، والـ greedy بالهامش لكل وحدة كسب 1,790 وساب وحدتين فاضيين.

Part 6 — Getting the choice back, not just the value 🟡 Intermediateالجزء 6 — رجّع الاختيارات نفسها مش القيمة بس

English

An API that answers "615" is useless: marketing needs the list of campaigns, the cashier needs the coins, the calendar needs the days. Two ways to get the choice back: walk the full table backwards (if dp[i][b] ≠ dp[i−1][b], item i was taken) or record the choice at each state while filling (pick[a] = the coin that last improved amount a; one bit per (campaign, budget)). Both need O(n × W) memory even when the value alone needs O(W). At W = 106 and 50 campaigns the value row is 7.6 MB, a choice bitset 6.0 MB, a byte per choice 47.7 MB, and the full Float64 table 389 MB. A bitset is the default.

You can't reconstruct from the rolled 1D row. After the loop it reflects all items, so asking "was item i taken?" against it gives wrong sets. The property "the returned items really add up to the value, fit the budget and don't repeat" catches that immediately: one campaign, budget 2, value 1, items [].

Ties make plans flap. The same request served by two pods, or the same campaigns returned by a query without ORDER BY, can produce different plans with equal value. Fix it in two steps: process items in a canonical order (sort by id), and add a tie rule to the comparison (higher revenue, then lower spend). Here the rule picks the 5k "push" campaign over the 10k "SMS" one at equal revenue, spending 95 instead of 100. A property test shuffles the input and demands an identical plan. Without the sort, the same test fails on two campaigns with identical cost and revenue.

import { EGP } from "./knapsack.ts";

export type Campaign = { id: string; cost: number; revenue: number };
export type Plan = { value: number; spent: number; chosen: string[] };

// القيمة محتاجة صف واحد ⁦O(W)⁩، بس الاختيارات محتاجة bit لكل (حملة، budget) = O(n × W) bits
export function planCampaigns(input: readonly Campaign[], budget: number): Plan {
  // ترتيب ثابت بالـ id: نفس الحملات بأي ترتيب جاية من الـ DB تدي نفس الخطة
  const items = input.toSorted((a, b) => (a.id < b.id ? -1 : a.id > b.id ? 1 : 0));
  const n = items.length, width = budget + 1;
  const value = new Float64Array(width);
  const spent = new Float64Array(width);
  // الـ bitset: bit لكل (i, b)
  const took = new Uint8Array(Math.ceil((n * width) / 8));
  for (let i = 0; i < n; i++) {
    const { cost, revenue } = items[i];
    for (let b = budget; b >= cost; b--) {
      const v = value[b - cost] + revenue, s = spent[b - cost] + cost;
      // قاعدة التعادل: إيراد أعلى، ولو متساوي يبقى الأرخص — عشان الـ API ترجّع نفس الخطة دايمًا
      if (v > value[b] || (v === value[b] && s < spent[b])) {
        value[b] = v;
        spent[b] = s;
        const bit = i * width + b;
        took[bit >> 3] |= 1 << (bit & 7);
      }
    }
  }
  // امشي لورا: لو الحملة i اتاخدت عند budget b، انقص تكلفتها وكمّل على اللي قبلها
  const chosen: string[] = [];
  for (let i = n - 1, b = budget; i >= 0; i--) {
    const bit = i * width + b;
    if (took[bit >> 3] & (1 << (bit & 7))) {
      chosen.push(items[i].id);
      b -= items[i].cost;
    }
  }
  return { value: value[budget], spent: spent[budget], chosen: chosen.reverse() };
}

// ❌ استرجاع من الصف الأخير بس: الصف ده فيه كل الحملات، فمش بيقولك مين اتاخد فعلًا
export function planCampaignsBuggy(input: readonly Campaign[], budget: number): Plan {

    for (let b = budget; b >= cost; b--) dp[b] = Math.max(dp[b], dp[b - cost] + revenue);
  const chosen: string[] = [];
  let b = budget, spent = 0;
  for (let i = items.length - 1; i >= 0; i--) {
    const { id, cost, revenue } = items[i];
    if (cost <= b && dp[b] === dp[b - cost] + revenue) { chosen.push(id); b -= cost; spent += cost; }
  }
  return { value: dp[budget], spent, chosen: chosen.reverse() };
}

  dp[0] = 0;
  for (let a = 1; a <= amount; a++)
    for (const c of denoms) if (c <= a && dp[a - c] + 1 < dp[a]) { dp[a] = dp[a - c] + 1; pick[a] = c; }
  if (dp[amount] === Infinity) return null;
  const pieces: number[] = [];
  for (let a = amount; a > 0; a -= pick[a]) pieces.push(pick[a]);
  return pieces;
}

// أيام العروض نفسها: احتفظ بالـ best كله، وامشي لورا
export function promoSchedule(gain: readonly number[]): { value: number; days: number[] } {
  const n = gain.length;
  const best = new Float64Array(n + 1);
  for (let i = 1; i <= n; i++) best[i] = Math.max(best[i - 1], (i >= 2 ? best[i - 2] : 0) + gain[i - 1]);
  const days: number[] = [];
  // لو ⁦best[i]⁩ زي ⁦best[i-1]⁩ يبقى اليوم i-1 من غير عرض؛ غير كده فيه عرض ونقفز يومين
  for (let i = n; i >= 1; ) {
    if (best[i] === best[i - 1]) i -= 1;
    else { days.push(i - 1); i -= 2; }
  }
  return { value: best[n], days: days.reverse() };
}

❌ -1 means impossible, then + 1 
// ❌ القيمة ⁦-1⁩ معناها "مستحيل"، بس محدش بيشيك عليها قبل ما يزود 1
function fewestBad(amount: number, coins: readonly number[]): number {
  const dp = new Array<number>(amount + 1).fill(-1);
  dp[0] = 0;
  for (let a = 1; a <= amount; a++) {
    let best = Infinity;
    for (const c of coins) if (c <= a) best = Math.min(best, dp[a - c] + 1);
    dp[a] = best === Infinity ? -1 : best;
  }
  return dp[amount];
}

export function cheapestPasses(workDays: readonly number[], [day, week, month]: readonly [number, number, number]): number {
  const last = workDays.at(-1) ?? 0;
  const isWork = new Uint8Array(last + 1);
  for (const d of workDays) isWork[d] = 1;
  const cost = new Float64Array(last + 1);
  for (let d = 1; d <= last; d++) {
    // يوم إجازة: مفيش حاجة جديدة نغطيها
    if (!isWork[d]) { cost[d] = cost[d - 1]; continue; }
    cost[d] = Math.min(
      cost[d - 1] + day,
      cost[Math.max(0, d - 7)] + week,
      cost[Math.max(0, d - 30)] + month,
    );
  }
  return cost[last];
}

export function fewestWithStock(amount: number, stock: ReadonlyArray<{ value: number; count: number }>): number {
  const dp = new Float64Array(amount + 1).fill(Infinity);
  dp[0] = 0;
  for (const { value, count } of stock)
    for (let k = 0; k < count; k++)
      for (let a = amount; a >= value; a--) if (dp[a - value] + 1 < dp[a]) dp[a] = dp[a - value] + 1;

// تمرين 3: أحسن ربح بـ k صفقات على الأكتر — زوّد dimension لعدد الصفقات
export function atMostKTrades(price: readonly number[], k: number): number {
  // الـ ⁦hold[t] =⁩ أحسن رصيد وإنت ماسك شحنة وبادئ الصفقة رقم t؛ الـ ⁦cash[t] =⁩ بعد ما قفلت t صفقات
  const hold = new Array<number>(k + 1).fill(-Infinity);
  const cash = new Array<number>(k + 1).fill(-Infinity);
  cash[0] = 0;
  for (const p of price) {
    for (let t = k; t >= 1; t--) {
      cash[t] = Math.max(cash[t], hold[t] + p);
      hold[t] = Math.max(hold[t], cash[t - 1] - p);
    }
  }
  return Math.max(...cash);
}
لكل t من 1 لـ k فيه حالتين: ماسك شحنة في الصفقة رقم t، أو قفلت t صفقات. بنلف t لتحت عشان hold[t] يقرا cash[t-1] بتاع امبارح. اتجرّب على 100 مثال عشوائي بـ k من 0 لـ 4 ضد الـ brute force.

Cheat sheet · الخلاصة

  • DP = optimal substructure + overlapping subproblems. Measure overlap with a call counter; check substructure by asking if the halves are independent.
  • Signals: min / max / count / possible + a sequence of choices + a constraint. Traps: canonical coins (greedy) and routing (graphs).
  • Six lines before code: state in words, transition, base, answer, order, cost. If a new rule changes what tomorrow depends on, add a dimension.
  • Memo = reachable states only, but depth = longest chain (5,000 EGP in 25-piastre steps overflows). Table = no stack. Rolling = only the window.
  • Typed arrays with numeric sentinels (Infinity, -1 checked); never fill(null) for numbers. Map memo when states are sparse.
  • 0/1 knapsack: budget loop downwards. Unbounded: upwards. Prove it with an oracle test, not a comment.
  • Coin change: coins outer loop for combinations; counts overflow 253, so use BigInt or mod 109+7.
  • Pseudo-polynomial: cost grows with the amount's value; divide by the GCD (25 piastres) first.
  • Return { value, items }; choices in a bitset; test that the items achieve the value; never reconstruct from the rolled row.
  • Deterministic plans: canonical order + explicit tie rule + a shuffle property test.

  • الـ DP = optimal substructure + overlapping subproblems. قيس الـ overlap بـ counter للـ calls، واتأكد من الـ substructure بإنك تسأل هل النصّين مستقلين.
  • الإشارات: أقل / أكتر / كام طريقة / ينفع ولا لأ + سلسلة اختيارات + قيد. والفخاخ: عملات canonical (greedy) والـ routing (graphs).
  • 6 سطور قبل الكود: الـ state بالكلام، الـ transition، الـ base، الإجابة فين، الترتيب، التكلفة. لو قاعدة جديدة غيّرت بكرة معتمد على إيه، زوّد dimension.
  • الـ memo = الـ states اللي بتوصلها بس، بس العمق = أطول سلسلة (5,000 جنيه بخطوات 25 قرش بتعمل overflow). الـ table = مفيش stack. الـ rolling = الشباك بس.
  • typed arrays و sentinels رقمية (Infinity، أو -1 مع شيك)؛ وعمرك ما تعمل fill(null) لأرقام. الـ Map للـ memo لما الـ states متفرقة.
  • الـ 0/1 knapsack: loop الـ budget لتحت. الـ unbounded: لفوق. وأثبتها بـ oracle test مش بـ comment.
  • الـ coin change: loop العملات بره عشان تعد combinations؛ العدد بيعدّي 253 فاستخدم BigInt أو mod 109+7.
  • الـ pseudo-polynomial: التكلفة بتكبر مع قيمة المبلغ؛ اقسم على الـ GCD (25 قرش) الأول.
  • رجّع { value, items }؛ الاختيارات في bitset؛ اختبر إن الـ items بتحقق القيمة؛ وعمرك ما تسترجع من الصف الملفوف.
  • خطط deterministic: ترتيب ثابت + قاعدة تعادل صريحة + property test بالـ shuffle.
