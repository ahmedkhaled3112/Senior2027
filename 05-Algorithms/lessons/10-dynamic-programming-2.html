Why this matters · ليه ده مهم

English

Lesson 09 covered DP over a line of choices. Real features need DP over other shapes: two strings ("did you mean محمد عبد الرحمن?", what changed in an invoice template), a range (merging export files that must stay in date order), a tree (an on-call rota from the org chart), a set (a courier's route through 15 stops) and the state of a search (can these pallets fill a truck?). Each one works in a textbook and has a size where it stops working: an O(n·m) comparison per name, an O(n³) table, a recursion as deep as the org chart, a 2n table, a memo key that forgot part of the state. This lesson finds those limits with real numbers and shows what production does at each one.

بالعامية

الدرس 09 غطّى الـ DP على خط من الاختيارات. الـ features الحقيقية محتاجة DP على أشكال تانية: two strings ("قصدك محمد عبد الرحمن؟"، أو إيه اللي اتغير في template الفاتورة)، مدى متصل (دمج ملفات export لازم تفضل بترتيب التاريخ)، شجرة (جدول on-call من الهيكل الإداري)، مجموعة (طريق مندوب على 15 محطة)، وحالة بحث (البالتات دي تملا العربية؟). كل واحدة شغالة في الكتاب، وليها حجم بتبطل تشتغل عنده: مقارنة O(n·m) لكل اسم، table بـ O(n³)، recursion عمقها قد عمق الهيكل الإداري، table بـ 2n، أو memo key نسي جزء من الـ state. الدرس ده بيلاقي الحدود دي بأرقام حقيقية، ويوريك الـ production بيعمل إيه عند كل واحد.

Part 1 — Edit distance and LCS, production-grade 🟡 Intermediateالجزء 1 — الـ edit distance والـ LCS بمستوى production

English

Section 03 builds Levenshtein, LCS and a line diff from scratch (03 · 09 part 7). Here is what you add before shipping a fuzzy search on customer names in Arabic and English.

1. Normalize first. NFKC (so the ligature ﻻ becomes لا), strip tashkeel and tatweel, map أ إ آ ٱ to ا, ة to ه and ى to ي, lowercase, collapse spaces. These are the same rules as the SQL function in 09 · 12 part 5, so the app and Postgres agree. Without it, a hamza costs one edit and a fully voweled محمد is 4 edits away from the bare one; after it, both are 0. Normalize at write time into a stored column, not on every comparison.

2. Count transpositions. Typing الرحنم for الرحمن swaps two neighbours: 2 edits for Levenshtein, 1 for OSA (optimal string alignment, the restricted Damerau–Levenshtein distance). OSA isn't the full Damerau–Levenshtein distance: it never edits a substring twice, so "CA" → "ABC" is 3 in OSA and 2 in the unrestricted version. For typo matching OSA is the usual, simpler choice.

3. Bound the work. You only need "is the distance ≤ k?" with k = 1–2 for names. Reject names whose length differs by more than k; compute only the cells with |i − j| ≤ k (a band); and stop as soon as a whole row exceeds k, because row minima never decrease. That is O(n·k) instead of O(n·m). On 100,000 seeded names the full DP computes 17.5M cells; the band at most 2.7M, after the length check drops 63,935 names. Here that was ≈278 ms vs ≈41 ms for the same 1,509 hits. fastest-levenshtein (Myers' bit-parallel algorithm, 32 cells per machine word, no transpositions) took ≈63 ms in this run and anywhere from ≈11 to ≈105 ms across runs on this loaded machine: trust the cell counts more than the clock.

4. Watch precision, not just speed. Distance 1 also matches أحمد عبد الرحمن and محمود عبد الرحمن, which are different people, and distance 2 matches عبد الرحيم. Edit distance over-matches short names, so rank by distance, cap the list, present it as suggestions, and consider a threshold relative to length. When the table outgrows one process or the service runs on many pods, let Postgres pg_trgm produce candidates (and check the LC_CTYPE trap in 09 · 12 part 4), then rerank the top 50 with banded OSA in the app.

5. Diffs. An LCS line diff of two versions of an invoice template shows the added ETA UUID and discount lines and the changed payment terms. The full table is (n+1)(m+1) cells: two 10,000-line files need 382 MB as Uint32Array, peak RSS ≈447 MB, ≈1.3 s. Trimming the common prefix and suffix first, since real edits are small, brings a 10,000-line file with 2 edits to ≈2 ms. Git doesn't fill this table: Myers' O((N+M)·D) algorithm finds the same shortest edit script in time proportional to the size of the change (lesson 18 part 1), and Hirschberg's method gets an LCS in linear space.

// وحّد الكتابة قبل أي مقارنة: نفس القواعد اللي في الـ SQL function بتاعة درس الـ Databases
export function normalizeName(raw: string): string {
  return raw
    .normalize("NFKC") // يعني ﻻ تبقى لا، والحروف المركّبة تتجمع
    .replace(/[\u064B-\u065F\u0670\u0640]/g, "") // التشكيل والـ tatweel
    .replace(/[أإآٱ]/g, "ا")
    .replace(/ة/g, "ه")
    .replace(/ى/g, "ي")
    .toLowerCase()
    .replace(/\s+/g, " ")
    .trim();
}

// الـ ⁦OSA (⁩نسخة Damerau–Levenshtein المقيدة⁦): insert⁩ و delete و substitute وتبديل حرفين جنب بعض ⁦= 1⁩
export function osaDistance(a: string, b: string): number {
  const n = a.length, m = b.length;
  let prev2 = new Int32Array(m + 1), prev = new Int32Array(m + 1), cur = new Int32Array(m + 1);
  for (let j = 0; j <= m; j++) prev[j] = j;
  for (let i = 1; i <= n; i++) {
    cur[0] = i;
    for (let j = 1; j <= m; j++) {
      const cost = a.charCodeAt(i - 1) === b.charCodeAt(j - 1) ? 0 : 1;
      let d = Math.min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + cost);
      // التبديل: ab ↔ ba بيتحسب غلطة واحدة مش اتنين
      if (i > 1 && j > 1 && a.charCodeAt(i - 1) === b.charCodeAt(j - 2) && a.charCodeAt(i - 2) === b.charCodeAt(j - 1))
        d = Math.min(d, prev2[j - 2] + 1);
      cur[j] = d;
    }
    [prev2, prev, cur] = [prev, cur, prev2];
  }
  return prev[m];
}

// نفس الـ OSA بس بنحسب الخانات اللي ⁦|i - j| ≤ k⁩ بس، ونقف بدري لو الصف كله عدّى k
// بيرجّع الـ distance لو ⁦≤ k⁩، أو k + 1 معناها "أبعد من ⁦k" — O(n·k)⁩ بدل ⁦O(n·m)⁩
export function osaWithin(a: string, b: string, k: number): number {
  const n = a.length, m = b.length;
  if (Math.abs(n - m) > k) return k + 1;
  const BIG = k + 1;
  let prev2 = new Int32Array(m + 1).fill(BIG), prev = new Int32Array(m + 1).fill(BIG), cur = new Int32Array(m + 1).fill(BIG);
  for (let j = 0; j <= Math.min(m, k); j++) prev[j] = j;
  for (let i = 1; i <= n; i++) {
    const lo = Math.max(1, i - k), hi = Math.min(m, i + k);
    cur.fill(BIG);
    if (i <= k) cur[0] = i;
    let rowMin = cur[0];
    for (let j = lo; j <= hi; j++) {
      const cost = a.charCodeAt(i - 1) === b.charCodeAt(j - 1) ? 0 : 1;
      let d = Math.min(prev[j] + 1, cur[j - 1] + 1, prev[j - 1] + cost);
      if (i > 1 && j > 1 && a.charCodeAt(i - 1) === b.charCodeAt(j - 2) && a.charCodeAt(i - 2) === b.charCodeAt(j - 1))
        d = Math.min(d, prev2[j - 2] + 1);
      cur[j] = Math.min(d, BIG);
      if (cur[j] < rowMin) rowMin = cur[j];
    }
    // الخروج بدري: الأرقام مبتقلش وإنت نازل، فلو الصف كله ⁦> k⁩ خلاص
    if (rowMin > k) return BIG;
    [prev2, prev, cur] = [prev, cur, prev2];
  }
  return Math.min(prev[m], BIG);
}

// الـ oracle للـ OSA: الـ recursion المباشرة بالتعريف، على strings قصيرة
function osaBrute(a: string, b: string): number {
  const memo = new Map<string, number>();
  const go = (i: number, j: number): number => {
    if (i === 0) return j;
    if (j === 0) return i;
    const key = i + "," + j;
    const hit = memo.get(key);
    if (hit !== undefined) return hit;
    let d = Math.min(go(i - 1, j) + 1, go(i, j - 1) + 1, go(i - 1, j - 1) + (a[i - 1] === b[j - 1] ? 0 : 1));
    if (i > 1 && j > 1 && a[i - 1] === b[j - 2] && a[i - 2] === b[j - 1]) d = Math.min(d, go(i - 2, j - 2) + 1);
    memo.set(key, d);
    return d;
  };
  return go(a.length, b.length);
}

export type Op = { kind: " " | "-" | "+"; line: string };

// الـ LCS على سطور بـ table واحد flat: الخانة (i, j) في الـ index ده i * (m + 1) + j
export function lineDiff(a: readonly string[], b: readonly string[]): Op[] {
  // شيل البداية والنهاية المشتركة الأول: أغلب الـ diffs الحقيقية صغيرة في النص
  let pre = 0;
  while (pre < a.length && pre < b.length && a[pre] === b[pre]) pre++;
  let suf = 0;
  while (suf < a.length - pre && suf < b.length - pre && a[a.length - 1 - suf] === b[b.length - 1 - suf]) suf++;
  const A = a.slice(pre, a.length - suf), B = b.slice(pre, b.length - suf);
  const n = A.length, m = B.length, W = m + 1;
  const dp = new Uint32Array((n + 1) * W);
  for (let i = 1; i <= n; i++)
    for (let j = 1; j <= m; j++)
      dp[i * W + j] = A[i - 1] === B[j - 1] ? dp[(i - 1) * W + j - 1] + 1 : Math.max(dp[(i - 1) * W + j], dp[i * W + j - 1]);
  // امشي من الركن لورا: ⁦diagonal =⁩ سطر زي ما هو، فوق = اتمسح، شمال = اتضاف
  const mid: Op[] = [];
  for (let i = n, j = m; i > 0 || j > 0; ) {
    if (i > 0 && j > 0 && A[i - 1] === B[j - 1]) { mid.push({ kind: " ", line: A[i - 1] }); i--; j--; }
    else if (j > 0 && (i === 0 || dp[i * W + j - 1] >= dp[(i - 1) * W + j])) { mid.push({ kind: "+", line: B[j - 1] }); j--; }
    else { mid.push({ kind: "-", line: A[i - 1] }); i--; }
  }
  return [
    ...a.slice(0, pre).map((line) => ({ kind: " " as const, line })),
    ...mid.reverse(),
    ...a.slice(a.length - suf).map((line) => ({ kind: " " as const, line })),
  ];
}

Part 2 — Interval DP 🟡 Intermediateالجزء 2 — الـ interval DP

English

The shape: dp[i][j] is the best answer for the contiguous range i..j, computed from a split point k inside it, and the table is filled by increasing length so both halves are always ready. That's O(n²) states × O(n) splits = O(n³).

Matrix chain is the classic. For the six matrices of the textbook example (dimensions 30, 35, 15, 5, 10, 20, 25) the best order costs 15,125 scalar multiplications, ((A1(A2A3))((A4A5)A6)), against 40,500 left to right, 2.7× more. You meet the same problem when a query planner orders joins or a pipeline chains matrix transforms.

Burst balloons as a concept: bursting a balloon earns left × it × right of the balloons still standing. Choosing which balloon to burst first makes the two sides depend on each other. Choose the one to burst last in (i, j) instead: at that moment its neighbours are exactly i and j, so the two sub-ranges are independent. [3, 1, 5, 8] gives 167. When a split creates dependent halves, look for the "last action" formulation.

At work: merge sorted daily export files into one, where merging two files costs the sum of their sizes and only adjacent files may be merged so the date order holds. That's interval DP. If any two files may merge, Huffman's greedy (always the two smallest, from a min-heap: lesson 07 part 3) is optimal. Adjacency changes the answer: [10, 100, 10, 100, 10] costs 570 with neighbours only and 410 with any pair. And the greedy that's optimal without adjacency isn't with it: "merge the smallest adjacent pair" on [19, 15, 4, 14, 19] costs 174, the DP 160.

Cost, measured: the inner loop runs exactly (n³ − n)/6 times, 10.7M at n = 400 and 85.3M at n = 800, and the time grows ×9.4 and ×8.0 over the last two doublings, once n is large enough to hide the overhead (×4.6 and ×5.8 below that). For this cost function (sum of a range) the Knuth–Yao speedup applies: the best split is monotone, opt[i][j−1] ≤ opt[i][j] ≤ opt[i+1][j], and the total work telescopes to O(n²): ≈11 ms instead of ≈570 ms at n = 800, with identical answers on 100 random tests. It doesn't apply to every interval DP, so always test it against the O(n³) version.

// الـ ⁦cost[i][j] =⁩ أقل عدد ضربات scalar عشان تضرب من i لـ j؛ والـ ⁦split[i][j] =⁩ فين آخر ضربة
export function matrixChain(dims: readonly number[]): { cost: number[][]; split: number[][] } {
  const n = dims.length - 1;
  const cost = Array.from({ length: n }, () => new Array<number>(n).fill(0));
  const split = Array.from({ length: n }, () => new Array<number>(n).fill(-1));
  // املا بالطول: الأول كل مدى طوله 2، بعدين 3، ... لحد ⁦n —⁩ كل مدى محتاج الأقصر منه بس
  for (let len = 2; len <= n; len++) {
    for (let i = 0; i + len - 1 < n; i++) {
      const j = i + len - 1;
      cost[i][j] = Infinity;
      for (let k = i; k < j; k++) {
        const c = cost[i][k] + cost[k + 1][j] + dims[i] * dims[k + 1] * dims[j + 1];
        if (c < cost[i][j]) { cost[i][j] = c; split[i][j] = k; }
      }
    }
  }
  return { cost, split };
}

// الـ burst balloons: فرقعة بالونة بتكسب ⁦left ×⁩ هي ⁦× right⁩ من اللي لسه موجودين جنبها
// الفكرة: اختار ⁦k =⁩ آخر بالونة تتفرقع في المدى (i, j)، فجيرانها وقتها هما i و j نفسهم
export function burstBalloons(nums: readonly number[]): number {
  const v = [1, ...nums, 1];
  const n = v.length;
  const dp = Array.from({ length: n }, () => new Array<number>(n).fill(0));
  for (let len = 2; len < n; len++) {
    for (let i = 0; i + len < n; i++) {
      const j = i + len;
      for (let k = i + 1; k < j; k++) dp[i][j] = Math.max(dp[i][j], dp[i][k] + v[i] * v[k] * v[j] + dp[k][j]);
    }
  }
  return dp[0][n - 1];
}

// دمج ملفات export مترتبة: تكلفة دمج ملفين = مجموع أحجامهم، ومسموح ندمج الجيران بس
export function mergeAdjacent(sizes: readonly number[]): number {
  const n = sizes.length;
  const prefix = [0];
  for (const s of sizes) prefix.push(prefix.at(-1)! + s);
  const dp = Array.from({ length: n }, () => new Float64Array(n));
  for (let len = 2; len <= n; len++) {
    for (let i = 0; i + len - 1 < n; i++) {
      const j = i + len - 1;
      let best = Infinity;
      for (let k = i; k < j; k++) best = Math.min(best, dp[i][k] + dp[k + 1][j]);
      // الدمجة الأخيرة بتقرا المدى كله مرة واحدة
      dp[i][j] = best + prefix[j + 1] - prefix[i];
    }
  }
  return n === 0 ? 0 : dp[0][n - 1];
}

// لو مسموح ندمج أي ملفين: ⁦Huffman —⁩ دايمًا أصغر اتنين (min-heap؛ هنا sort بسيط عشان n صغير)
export function mergeAny(sizes: readonly number[]): number {
  const q = [...sizes];
  let total = 0;
  while (q.length > 1) {
    q.sort((a, b) => a - b);
    const merged = q.shift()! + q.shift()!;
    total += merged;
    q.push(merged);
  }
  return total;
}

// الـ greedy البديهي للجيران: ادمج أصغر جارين في كل خطوة
export function mergeAdjacentGreedy(sizes: readonly number[]): number {
  const q = [...sizes];
  let total = 0;
  while (q.length > 1) {
    let best = 0;
    for (let i = 1; i + 1 < q.length; i++) if (q[i] + q[i + 1] < q[best] + q[best + 1]) best = i;
    const merged = q[best] + q[best + 1];
    total += merged;
    q.splice(best, 2, merged);
  }
  return total;
}

// تسريع Knuth–Yao: أحسن split للمدى (i, j) بين أحسن split لـ (i, j-1) و ⁦(i+1, j) —⁩ فالمجموع ⁦O(n²)⁩
export function mergeAdjacentKnuth(sizes: readonly number[]): number {
  const n = sizes.length;
  if (n < 2) return 0;
  const prefix = [0];
  for (const s of sizes) prefix.push(prefix.at(-1)! + s);
  // جداول flat بحجم n × n: الخانة (i, j) في i * n + j
  const dp = new Float64Array(n * n);
  const opt = new Int32Array(n * n);
  for (let i = 0; i < n; i++) opt[i * n + i] = i;
  for (let len = 2; len <= n; len++) {
    for (let i = 0; i + len - 1 < n; i++) {
      const j = i + len - 1;
      let best = Infinity, arg = i;
      const lo = opt[i * n + j - 1], hi = Math.min(j - 1, opt[(i + 1) * n + j]);
      for (let k = lo; k <= hi; k++) {
        const c = dp[i * n + k] + dp[(k + 1) * n + j];
        if (c < best) { best = c; arg = k; }
      }
      dp[i * n + j] = best + prefix[j + 1] - prefix[i];
      opt[i * n + j] = arg;
    }
  }
  return dp[n - 1];
}

Part 3 — DP on trees 🟡 Intermediateالجزء 3 — الـ DP على الـ trees

English

Choose this week's on-call team to maximize total score (availability, seniority, recent load) with one rule: nobody is on call together with their direct manager. On the org chart that's a maximum-weight independent set on a tree. Each employee keeps two numbers: with[v] = score[v] + Σ without[child] (if v is in, every direct report is out) and without[v] = Σ max(with[child], without[child]) (if v is out, each report takes whatever is better for them). Children must be computed before parents, which is post-order, and the whole thing is O(n).

Getting the team back is a top-down pass: a direct report of a chosen manager is out; anyone else is in exactly when with > without (a tie keeps them out, which gives a smaller team with the same score). A property test checks that no chosen person's manager is chosen and that the scores add up to the total.

Variant: the fewest reviewers so that every manager–report pair has at least one of them is a minimum vertex cover, and its size is n − (maximum independent set). That identity holds in every graph, because the complement of an independent set covers every edge. On trees both are O(n); on general graphs both are NP-hard. The test checks the identity against brute force on trees up to 15 people.

What breaks: the depth. A buggy HR import made every employee the manager of the next one, a 50,000-deep chain. Recursive DFS throws RangeError; the iterative version builds an order with an explicit stack (parents before children) and processes it backwards. Both org shapes take tens of milliseconds. Iterative traversals are covered in section 04 (04 · 07).

// الموظف: managerId = -1 للـ CEO؛ والـ ⁦score =⁩ قد إيه مناسب للـ on-call الأسبوع ده
export type Employee = { id: number; managerId: number; score: number };
type Result = { total: number; chosen: number[] };

function childrenOf(staff: readonly Employee[]): { kids: number[][]; root: number } {
  const kids: number[][] = staff.map(() => []);
  let root = -1;
  for (const e of staff) {
    if (e.managerId === -1) root = e.id;
    else kids[e.managerId].push(e.id);
  }
  return { kids, root };
}

// ❌ الـ post-order بالـ recursion: صح، بس عمقه = عمق الشجرة
export function onCallRecursive(staff: readonly Employee[]): number {
  const { kids, root } = childrenOf(staff);
  // بيرجّع [أحسن مجموع لو v في الفريق، أحسن مجموع لو v مش في الفريق]
  const dfs = (v: number): [number, number] => {
    let withV = staff[v].score, withoutV = 0;
    for (const c of kids[v]) {
      const [cw, co] = dfs(c);
      withV += co; // لو المدير في الفريق، المرؤوس المباشر لأ
      // لو المدير برّه، كل مرؤوس ياخد الأحسن ليه
      withoutV += Math.max(cw, co);
    }
    return [withV, withoutV];
  };
  const [w, o] = dfs(root);
  return Math.max(w, o);
}

// ✅ نفس الـ DP بـ stack صريح: نرتّب الموظفين بحيث كل مدير قبل مرؤوسينه، ونمشي بالعكس
export function onCall(staff: readonly Employee[]): Result {
  const { kids, root } = childrenOf(staff);
  const n = staff.length;
  const order: number[] = [];
  const stack = [root];
  while (stack.length) {
    const v = stack.pop()!;
    order.push(v);
    for (const c of kids[v]) stack.push(c);
  }
  const withV = new Float64Array(n), withoutV = new Float64Array(n);
  // بالعكس = كل المرؤوسين اتحسبوا قبل مديرهم (post-order)
  for (let idx = n - 1; idx >= 0; idx--) {
    const v = order[idx];
    withV[v] = staff[v].score;
    for (const c of kids[v]) {
      withV[v] += withoutV[c];
      withoutV[v] += Math.max(withV[c], withoutV[c]);
    }
  }
  // استرجاع الفريق: من فوق لتحت؛ لو المدير اتاخد يبقى المرؤوس لأ
  const taken = new Uint8Array(n);
  const chosen: number[] = [];
  for (const v of order) {
    const m = staff[v].managerId;
    const managerTaken = m !== -1 && taken[m] === 1;
    // قاعدة التعادل: لو متساويين متاخدوش (فريق أصغر بنفس المجموع)
    if (!managerTaken && withV[v] > withoutV[v]) { taken[v] = 1; chosen.push(v); }
  }
  return { total: Math.max(withV[root], withoutV[root]), chosen: chosen.sort((a, b) => a - b) };
}

Part 4 — Bitmask DP: a route for 15 stops 🔴 Advancedالجزء 4 — الـ bitmask DP: طريق لـ 15 محطة

English

One courier leaves the Nasr City depot, visits 15 stops and comes back. Brute force tries 15! ≈ 1.3×1012 orders. Held–Karp notices that the rest of the route depends only on which stops are done and where the courier is, not on the order so far: dp[mask][last] = the shortest route from the depot that visits exactly the stops in mask and ends at last. Each state extends to every unvisited stop; the answer is the best dp[full][last] plus the way back. That's O(2n·n²) time and O(2n·n) memory, which is exactly the "which hubs are used" state that lesson 09 part 1 said longest routes would need.

The data: the depot and up to 18 stops at approximate, rounded centres of Cairo and Giza districts, with haversine (straight-line) kilometres. Real roads are longer and not symmetric; production uses a road-network matrix from a routing engine, or the all-pairs matrix from lesson 12 part 6. The optimal tour of the first 15 stops is 124.9 km.

Implementation details that matter: one flat Float64Array of 2n·n cells indexed mask * n + last (not 2n small arrays), an Int8Array of parents to rebuild the route, and bit operations (mask & (1 << j), mask | (1 << j)) from lesson 14. Measured: n = 10 → 10,240 states in ≈1 ms, while brute force needs 3,628,800 permutations (≈0.4 s) for the same answer. Every extra stop roughly doubles time and memory: n = 15 → 4.2 MB, ≈44 ms; n = 18 → 40.5 MB, ≈0.46 s; n = 25 would need 7 GiB.

The production answer for 60 stops is a heuristic: nearest neighbour (always drive to the closest unvisited stop) then 2-opt (reverse any segment that shortens the tour, until none does). On the Cairo 15: NN is 22.6% above optimal, NN + 2-opt 0.7%. Over 50 random 15-stop instances, NN + 2-opt averages +1.9% (worst +13.4%) and is optimal in 21 of 50. For 60 stops it runs in well under a millisecond. Real dispatch adds time windows, vehicle capacity and several couriers: that's vehicle routing, and you use a solver such as OR-Tools routing or VROOM (named here, not run). Keep Held–Karp as the exact oracle for small instances in your tests.

// مسافة خط مستقيم على الكرة بالكيلو — الطرق الحقيقية أطول، والـ production بيستخدم matrix من routing engine
export function haversineKm(a: Point, b: Point): number {
  const rad = Math.PI / 180, R = 6371;
  const dLat = (b.lat - a.lat) * rad, dLon = (b.lon - a.lon) * rad;
  const h = Math.sin(dLat / 2) ** 2 + Math.cos(a.lat * rad) * Math.cos(b.lat * rad) * Math.sin(dLon / 2) ** 2;
  return 2 * R * Math.asin(Math.sqrt(h));
}

  return points.map((a) => Float64Array.from(points, (b) => haversineKm(a, b)));

// الـ ⁦Held–Karp: dp[mask][last] =⁩ أقصر طريق من الـ depot زار المحطات اللي في الـ mask بالظبط وواقف عند last
export function heldKarp(d: readonly Float64Array[]): { km: number; route: number[] } {
  const n = d.length - 1; // عدد المحطات من غير الـ depot
  const full = (1 << n) - 1;
  // جدول flat: الخانة (mask, last) في ⁦mask * n + last —⁩ مصفوفة واحدة بدل ⁦2^n array⁩ صغيرة
  const dp = new Float64Array((1 << n) * n).fill(Infinity);
  const parent = new Int8Array((1 << n) * n).fill(-1);
  for (let j = 0; j < n; j++) dp[(1 << j) * n + j] = d[0][j + 1];
  for (let mask = 1; mask <= full; mask++) {
    for (let last = 0; last < n; last++) {
      const cur = dp[mask * n + last];
      if (cur === Infinity || !(mask & (1 << last))) continue;
      for (let next = 0; next < n; next++) {
        if (mask & (1 << next)) continue;
        const to = (mask | (1 << next)) * n + next;
        const cand = cur + d[last + 1][next + 1];
        if (cand < dp[to]) { dp[to] = cand; parent[to] = last; }
      }
    }
  }
  // ارجع للـ depot في الآخر، واختار أحسن محطة أخيرة
  let best = Infinity, last = -1;
  for (let j = 0; j < n; j++) {
    const total = dp[full * n + j] + d[j + 1][0];
    if (total < best) { best = total; last = j; }
  }
  // استرجاع الطريق من الـ parent: امشي لورا وشيل المحطة من الـ mask كل مرة
  const route: number[] = [];
  for (let mask = full; last !== -1; ) {
    route.push(last + 1);
    const p = parent[mask * n + last];
    mask &= ~(1 << last);
    last = p;
  }
  return { km: best, route: [0, ...route.reverse(), 0] };
}

// كل الترتيبات: ⁦n! —⁩ بنعدّها عشان نشوف الفرق
export function bruteRoute(d: readonly Float64Array[]): { km: number; perms: number } {
  const n = d.length - 1;
  const used = new Uint8Array(n + 1);
  let best = Infinity, perms = 0;
  const go = (at: number, count: number, km: number): void => {
    if (count === n) { perms++; best = Math.min(best, km + d[at][0]); return; }
    for (let s = 1; s <= n; s++) {
      if (used[s]) continue;
      used[s] = 1;
      go(s, count + 1, km + d[at][s]);
      used[s] = 0;
    }
  };
  go(0, 0, 0);
  return { km: best, perms };
}

export const tourKm = (d: readonly Float64Array[], tour: readonly number[]) =>
  tour.slice(1).reduce((s, v, i) => s + d[tour[i]][v], 0);

// أقرب جار: من مكانك روح لأقرب محطة لسه متزارتش ⁦— O(n²)⁩
export function nearestNeighbour(d: readonly Float64Array[]): number[] {
  const n = d.length;
  const seen = new Uint8Array(n);
  const tour = [0];
  seen[0] = 1;
  for (let step = 1; step < n; step++) {
    const at = tour.at(-1)!;
    let best = -1;
    for (let s = 1; s < n; s++) if (!seen[s] && (best === -1 || d[at][s] < d[at][best])) best = s;
    seen[best] = 1;
    tour.push(best);
  }
  return [...tour, 0];
}

// الـ 2-opt: لو عكس جزء من الطريق بيقصّره، اعكسه — وكرّر لحد ما مفيش تحسين
export function twoOpt(d: readonly Float64Array[], start: readonly number[]): number[] {
  const t = [...start];
  for (let improved = true; improved; ) {
    improved = false;
    for (let i = 1; i < t.length - 2; i++) {
      for (let j = i + 1; j < t.length - 1; j++) {
        // بنشيل الضلعين (i-1, i) و (j, j+1) ونحط (i-1, j) و (i, j+1)
        const delta = d[t[i - 1]][t[j]] + d[t[i]][t[j + 1]] - d[t[i - 1]][t[i]] - d[t[j]][t[j + 1]];
        if (delta < -1e-9) {
          t.splice(i, j - i + 1, ...t.slice(i, j + 1).reverse());
          improved = true;
        }
      }
    }
  }
  return t;
}

English

"Can these pallets fill a truck to exactly 2,000 kg?" Backtracking takes or skips each pallet and prunes when the weight is exceeded: 2n paths in the worst case. The conversion test is one question: does the rest of the search depend only on a small tuple of values? Here it does: what's still possible depends on the next pallet index and the kilograms still missing, not on which pallets made up the weight so far. So memoize on (i, remaining): at most (n + 1)·(target + 1) = 41 × 2,001 ≈ 82k states.

The worst case for backtracking is a "no". In this batch every pallet holds whole 30 kg cartons, so every weight is a multiple of 30 and 2,000 kg is unreachable, but the code doesn't know that. Backtracking: 131,069 calls at n = 16, 2.0M at 20, 23.9M at 24, and it gave up at the 50M-call budget from n = 28 on. The memo version: 583 to 2,191 states and at most 4,383 calls up to n = 40. With random weights the answer was "yes" and backtracking found it after 4,129 calls. That's luck, not a guarantee.

The classic conversion bug is a memo key that leaves out part of the state. Add a rule, "at most 2 fragile pallets per truck", and forget to add the fragile count to the key: a "no" computed after two fragile pallets were taken gets reused for a path that took none. The oracle test finds it; the hand example [100 F, 100 F, 200, 300 F] with target 500 returns false, though 200 + 300 F works. Fix: key on (i, remaining, fragileUsed). Rule of thumb: every argument that can change the future belongs in the key.

When it doesn't convert: the state space is too large. Matching a bank transfer against 40 open invoices with amounts up to 109 piastres would need a 1.39×1011-cell table. Meet in the middle: list the 220 subset sums of each half (2,097,152 in total), sort one half, and binary-search target − s for every sum of the other, in O(2n/2·n) time and O(2n/2) memory. It took ≈1.1 s here, and it found 13 invoices summing to the transfer although 6 different invoices were actually paid: with 240 ≈ 1012 subsets and totals up to ~2×1010, many subsets share the same total. Reconciliation needs dates and references, and ambiguous matches go to a human. Backtracking with node budgets and deadlines, for when nothing converts, is in lesson 02 part 6.

// ❌ الـ backtracking: لكل بالتة يا تتحمّل يا لأ ⁦— 2^n⁩ في أسوأ حالة
export function canFillBacktrack(weights: readonly number[], target: number, budget = Infinity): boolean {
  const go = (i: number, remaining: number): boolean => {
    if (++stats.calls > budget) throw new Error(`node budget ${budget} exceeded`);
    if (remaining === 0) return true;
    if (i === weights.length || remaining < 0) return false;
    return go(i + 1, remaining - weights[i]) || go(i + 1, remaining);
  };
  return go(0, target);
}

export function canFillMemo(weights: readonly number[], target: number): { ok: boolean; states: number } {
  const W = target + 1;
  // القيم: ⁦0 =⁩ لسه، ⁦1 =⁩ لأ، ⁦2 =⁩ أيوه
  const memo = new Uint8Array((weights.length + 1) * W);
  let states = 0;
  const go = (i: number, remaining: number): boolean => {
    stats.calls++;
    if (remaining === 0) return true;
    if (i === weights.length || remaining < 0) return false;
    const key = i * W + remaining;
    if (memo[key] !== 0) return memo[key] === 2;
    states++;
    const ok = go(i + 1, remaining - weights[i]) || go(i + 1, remaining);
    memo[key] = ok ? 2 : 1;
    return ok;
  };
  return { ok: go(0, target), states };
}

function subsetSums(xs: readonly number[]): { sum: number; mask: number }[] {
  const out = [{ sum: 0, mask: 0 }];
  xs.forEach((x, i) => {
    const len = out.length;
    for (let k = 0; k < len; k++) out.push({ sum: out[k].sum + x, mask: out[k].mask | (1 << i) });
  });
  return out;
}
export function meetInTheMiddle(amounts: readonly number[], target: number): { picked: number[]; sums: number } | null {
  const half = amounts.length >> 1;
  const left = subsetSums(amounts.slice(0, half));
  const right = subsetSums(amounts.slice(half)).sort((a, b) => a.sum - b.sum);
  for (const l of left) {
    // نعمل binary search في النص التاني على target - l.sum
    const want = target - l.sum;
    let lo = 0, hi = right.length - 1;
    while (lo <= hi) {
      const mid = (lo + hi) >> 1;
      if (right[mid].sum === want) {
        const picked: number[] = [];
        for (let i = 0; i < half; i++) if (l.mask & (1 << i)) picked.push(i);
        for (let i = 0; i < amounts.length - half; i++) if (right[mid].mask & (1 << i)) picked.push(half + i);
        return { picked, sums: left.length + right.length };
      }
      if (right[mid].sum < want) lo = mid + 1;
      else hi = mid - 1;
    }
  }
  return null;
}

Interview question "You have an exponential backtracking solution. When can you turn it into DP, and what can go wrong?" → When the result of a recursive call is fully determined by a small tuple of its arguments (here index and remaining weight), memoize on that tuple; complexity becomes states × choices. What goes wrong: the key misses something that affects the future (a counter, a flag, the last choice), and you get wrong answers that only an oracle test finds. If the tuple's range is huge (amounts up to 109), use meet in the middle (2n/2) or a solver instead.
"عندك حل backtracking exponential. إمتى تقدر تحوّله لـ DP، وإيه اللي ممكن يبوظ؟" ← لما نتيجة الـ call الـ recursive تبقى متحددة بالكامل بـ tuple صغير من الـ arguments (هنا الـ index والوزن الباقي)، اعمل memo على الـ tuple ده؛ والـ complexity تبقى عدد الـ states × الاختيارات. اللي بيبوظ: المفتاح ناقص حاجة بتأثر على المستقبل (عدّاد، flag، آخر اختيار)، فتطلع إجابات غلط محدش بيمسكها غير oracle test. ولو مدى الـ tuple ضخم (مبالغ لحد 109)، استخدم meet in the middle (2n/2) أو solver.

  const n = sizes.length;
  const prefix = [0];
  for (const s of sizes) prefix.push(prefix.at(-1)! + s);
  const dp = Array.from({ length: n }, () => new Float64Array(n));
  const cut = Array.from({ length: n }, () => new Int32Array(n));
  for (let len = 2; len <= n; len++) {
    for (let i = 0; i + len - 1 < n; i++) {
      const j = i + len - 1;
      dp[i][j] = Infinity;
      for (let k = i; k < j; k++) {
        const c = dp[i][k] + dp[k + 1][j];
        if (c < dp[i][j]) { dp[i][j] = c; cut[i][j] = k; }
      }
      dp[i][j] += prefix[j + 1] - prefix[i];
    }
  }
  // الـ post-order على شجرة الـ cuts: الأجزاء الصغيرة تندمج الأول
  const steps: string[] = [];
  const walk = (i: number, j: number): void => {
    if (i === j) return;
    const k = cut[i][j];
    walk(i, k);
    walk(k + 1, j);
    steps.push(`[${i}..${k}] + [${k + 1}..${j}]`);
  };
  if (n > 1) walk(0, n - 1);
  return { cost: n > 1 ? dp[0][n - 1] : 0, steps };
}

2. Couriers to zones with a bitmask 🟡 medium n couriers, n zones, minutes[c][z] = time for courier c to cover zone z. Assign one zone per courier with the least total time, for n ≤ 15. Use dp[mask] over the zones already assigned. Check: [[9,2,7,8],[6,4,3,7],[5,8,1,8],[7,6,9,4]] → 13.

Hint · تلميح The next courier to place is popcount(mask), so the state doesn't need a courier index: O(2n·n). For large n the same problem is solved in O(n³) by the Hungarian algorithm (lesson 17).
المندوب اللي عليه الدور = عدد الـ bits في الـ mask، فالـ state مش محتاج رقم المندوب: O(2n·n). ولـ n كبير نفس المسألة بتتحل في O(n³) بالـ Hungarian algorithm (الدرس 17).
Solution · الحل 
// تمرين 2: وزّع n مندوب على n منطقة بأقل وقت إجمالي ⁦— dp[mask] =⁩ أحسن توزيع لأول ⁦popcount(mask)⁩ مندوبين على المناطق اللي في الـ mask
export function assignCouriers(minutes: readonly (readonly number[])[]): number {
  const n = minutes.length;
  const dp = new Float64Array(1 << n).fill(Infinity);
  dp[0] = 0;
  for (let mask = 0; mask < 1 << n; mask++) {
    if (dp[mask] === Infinity) continue;
    // المندوب اللي عليه الدور = عدد المناطق اللي اتوزعت لحد دلوقتي
    let courier = 0;
    for (let m = mask; m; m &= m - 1) courier++;
    if (courier === n) continue;
    for (let zone = 0; zone < n; zone++) {
      if (mask & (1 << zone)) continue;
      const next = mask | (1 << zone);
      dp[next] = Math.min(dp[next], dp[mask] + minutes[courier][zone]);
    }
  }
  return dp[(1 << n) - 1];
}

Solution · الحل 
// تمرين 3: أقل عدد on-call بحيث كل موظف مغطّى: هو نفسه، أو مديره، أو حد من مرؤوسينه المباشرين
// تلات حالات لكل موظف ⁦v: on =⁩ هو on-call؛ ⁦coveredByKid =⁩ مش on بس واحد من ولاده on؛ ⁦needsParent =⁩ مش متغطي لسه
export function minOnCallCover(managerOf: readonly number[]): number {
  const n = managerOf.length;
  const kids: number[][] = Array.from({ length: n }, () => []);
  let root = 0;
  managerOf.forEach((m, v) => (m === -1 ? (root = v) : kids[m].push(v)));
  const order: number[] = [];
  for (const stack = [root]; stack.length; ) {
    const v = stack.pop()!;
    order.push(v);
    stack.push(...kids[v]);
  }
  const on = new Float64Array(n), coveredByKid = new Float64Array(n), needsParent = new Float64Array(n);
  for (let idx = n - 1; idx >= 0; idx--) {
    const v = order[idx];
    on[v] = 1;
    needsParent[v] = 0;
    let sumBest = 0, extra = Infinity;
    for (const c of kids[v]) {
      // لو v نفسه on: الابن ممكن يكون أي حالة (حتى needsParent لأن v بيغطيه)
      on[v] += Math.min(on[c], coveredByKid[c], needsParent[c]);
      // لو v مش on: الابن لازم يكون متغطي من غير v
      needsParent[v] += coveredByKid[c];
      const best = Math.min(on[c], coveredByKid[c]);
      sumBest += best;
      extra = Math.min(extra, on[c] - best);
    }
    // متغطي من ابن: كل ولد متغطي لوحده، وواحد منهم على الأقل on
    coveredByKid[v] = kids[v].length ? sumBest + extra : Infinity;
  }
  // الـ CEO مالوش مدير، فلازم يبقى متغطي من نفسه أو من ابن
  return Math.min(on[root], coveredByKid[root]);
}

Cheat sheet · الخلاصة

  • Fuzzy names: normalize at write time (NFKC, tashkeel, tatweel, alef forms, ة→ه, ى→ي, case), the same rules in the app and SQL.
  • OSA counts adjacent swaps as 1 (not full Damerau–Levenshtein). Band |i − j| ≤ k + length check + early exit: O(n·k), 17.5M → ≤ 2.7M cells.
  • Precision is the real problem: one edit separates أحمد from محمد. Rank, cap, suggest; pg_trgm for candidates, OSA to rerank.
  • LCS diff: (n+1)(m+1) cells, 382 MB at 10k × 10k lines; trim the common prefix and suffix; Myers O((N+M)·D) in production.
  • Interval DP: dp[i][j] over a split k, filled by length, O(n³). Burst balloons: choose the last action. Knuth–Yao → O(n²) when the cost qualifies.
  • Adjacent-only merging is interval DP; any-pair merging is Huffman. Greedy that's optimal for one is wrong for the other.
  • Tree DP: (with, without) per node in post-order, O(n); rebuild top-down; vertex cover = n − MIS. Iterative order for deep trees.
  • Held–Karp: dp[mask][last], O(2n·n²) time, 2n·n cells in one flat typed array; ≈44 ms at 15 stops, 7 GiB at 25.
  • Beyond ~16 stops: nearest neighbour + 2-opt (+1.9% avg at 15), solvers for real VRP; Held–Karp stays as the test oracle.
  • Backtracking → DP when the future depends on a small tuple; the memo key must contain every argument that changes the future.
  • Huge values: meet in the middle (2n/2), and expect many equal-sum subsets.
بالعامية
  • البحث في الأسماء: وحّد وقت الكتابة (NFKC، التشكيل، الـ tatweel، أشكال الألف، ة←ه، ى←ي، الـ case)، وبنفس القواعد في الـ app والـ SQL.
  • الـ OSA بيعد تبديل حرفين جنب بعض بـ 1 (ومش هو الـ Damerau–Levenshtein الكامل). الـ band بـ |i − j| ≤ k + فحص الطول + خروج بدري: O(n·k)، من 17.5 مليون لـ ≤ 2.7 مليون خانة.
  • الدقة هي المشكلة الحقيقية: غلطة واحدة بين أحمد ومحمد. رتّب، وحط حد، واعرضها اقتراحات؛ pg_trgm للمرشّحين و OSA للترتيب.
  • الـ LCS diff: (n+1)(m+1) خانة، 382 MB لـ 10k × 10k سطر؛ شيل البداية والنهاية المشتركين؛ وفي الـ production خوارزمية Myers بـ O((N+M)·D).
  • الـ interval DP: dp[i][j] على نقطة تقسيم k، بيتملى بالطول، O(n³). الـ burst balloons: اختار آخر خطوة. والـ Knuth–Yao بينزّلها لـ O(n²) لما دالة التكلفة تسمح.
  • دمج الجيران بس = interval DP؛ دمج أي اتنين = Huffman. الـ greedy اللي صح في واحدة غلط في التانية.
  • الـ tree DP: (with، without) لكل node بـ post-order و O(n)؛ الاسترجاع من فوق لتحت؛ الـ vertex cover = n − MIS. وترتيب iterative للأشجار العميقة.
  • الـ Held–Karp: dp[mask][last]، وقت O(2n·n²)، و 2n·n خانة في typed array واحدة flat؛ ≈44 ms عند 15 محطة و 7 GiB عند 25.

  • الـ backtracking يتحول لـ DP لما المستقبل يعتمد على tuple صغير؛ والـ memo key لازم يبقى فيه كل argument بيغيّر المستقبل.
  • القيم الضخمة: meet in the middle (2n/2)، واتوقع subsets كتير ليها نفس المجموع.
