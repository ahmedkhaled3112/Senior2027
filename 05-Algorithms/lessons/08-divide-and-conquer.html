Why this matters · ليه ده مهم

English

Divide and conquer is the shape behind merge sort, quickselect, Postgres's parallel aggregates, map-reduce and the BigInt multiply in your runtime. Knowing the shape lets you do three senior things: write the recurrence and predict the cost before running anything, spot where splitting buys real wins (parallelism, a cheaper combine, fewer sub-problems) and where it only adds overhead, and recognise the D&C answer to work questions like "median order value per tenant", "how out of order were these messages?" or "which two couriers are suspiciously close?". Interviewers love quickselect, counting inversions and "why is this O(n) and not O(n log n)?".

Part 1 — The pattern and what it buys 🟢 Basicالجزء 1 — النمط، وبيكسّبك إيه

English

Split → solve → combine. Cut the input into a sub-problems of size n/b, solve each recursively, then combine the answers in f(n). The cost is T(n) = a·T(n/b) + f(n), and the Master theorem from lesson 01 part 2 reads it off (writing recurrences from code is part 1). The pattern buys something in only three situations: the sub-problems are independent (so they can run in parallel), the combine step is cheap compared with solving the whole thing directly, or a clever split needs fewer sub-problems (Karatsuba, Part 5).

When it buys nothing. Totals per tenant over 106 invoices: a loop is O(n). The recursive version is O(n) too, but splitting down to single invoices builds and merges about two million small Maps, and it ran about ten times slower. With a base-case cutoff of 4,096 rows it's back to the loop's speed, because the leaves are loops. One unexpected bonus on floats: summing 106 × 0.1 left-to-right drifts to 100000.00000133288, while pairwise (D&C) summation prints 100000, since its rounding error grows like log n instead of n. Money is in integer piastres here, so both are exact.

// فواتير كـ struct-of-arrays: tenant و amount بالقروش (integers، فالجمع exact)
export type Invoices = { tenant: Uint16Array; amount: Float64Array };

// (1) الـ loop العادي: ⁦O(n)⁩ ومفيش أي حاجة زيادة
export function loopTotals(inv: Invoices): Map<number, number> {
  const totals = new Map<number, number>();
  for (let i = 0; i < inv.tenant.length; i++) {
    totals.set(inv.tenant[i], (totals.get(inv.tenant[i]) ?? 0) + inv.amount[i]);
  }
  return totals;
}

// (2) نفس الحساب بـ divide & conquer: قسّم النص، احسب كل نص، وادمج الـ Maps
export function dcTotals(inv: Invoices, lo = 0, hi = inv.tenant.length, cutoff = 1): Map<number, number> {
  if (hi - lo <= cutoff) {
    // الـ base case: نطاق صغير يتحسب بـ loop
    const m = new Map<number, number>();
    for (let i = lo; i < hi; i++) m.set(inv.tenant[i], (m.get(inv.tenant[i]) ?? 0) + inv.amount[i]);
    return m;
  }
  const mid = (lo + hi) >>> 1;
  const left = dcTotals(inv, lo, mid, cutoff);
  const right = dcTotals(inv, mid, hi, cutoff);
  // الـ combine: ادمج الـ Map الأصغر في الأكبر — تكلفته على عدد الـ tenants في الناحيتين
  const [big, small] = left.size >= right.size ? [left, right] : [right, left];
  for (const [t, v] of small) big.set(t, (big.get(t) ?? 0) + v);
  return big;
}
// مولّد أرقام عشوائية بـ seed ثابت (mulberry32): نفس الـ ⁦seed =⁩ نفس الأرقام في كل run وعلى أي جهاز
export function mulberry32(seed: number): () => number {
  return () => {
    seed = (seed + 0x6d2b79f5) | 0;
    let t = Math.imul(seed ^ (seed >>> 15), 1 | seed);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

English

Where it does buy something: parallelism. Fork-join sort of 4·106 floats: put them in one SharedArrayBuffer, let four workers each sort a quarter in place (no copying between threads), then merge in the main thread. The recurrence on the critical path becomes T(n) = T(n/4) + O(n): the four sorts overlap in time and only the merge is sequential. Measured against a single-threaded Float64Array.prototype.sort including the copy: about 2× faster when the four workers are created for the run (startup ≈60 ms on this Windows machine), about 2.6× with a warm pool. At 105 elements the same code is six times slower cold, because worker startup costs more than the whole sort. Sharing vs transferring memory and pools are in Node 34 parts 2–3.

// الـ combine: دمج two sorted runs في ⁦output (⁩نفس merge بتاع merge sort)
function merge(a: Float64Array, b: Float64Array, out: Float64Array): void {
  let i = 0, j = 0, k = 0;
  while (i < a.length && j < b.length) out[k++] = a[i] <= b[j] ? a[i++] : b[j++];
  while (i < a.length) out[k++] = a[i++];
  while (j < b.length) out[k++] = b[j++];
}

async function startWorkers(): Promise<Worker[]> {
  const ws = Array.from({ length: P }, () => new Worker(workerUrl));
  await Promise.all(ws.map((w) => once(w, "message")));
  return ws;
}

// الـ fork: كل worker ياخد ربع؛ الـ join: نستنى الأربعة؛ الـ combine: دمج على مرحلتين في الـ main thread
async function forkJoinSort(ws: Worker[]): Promise<{ out: Float64Array; copy: number; sort: number; merge: number }> {
  let t = performance.now();
  const sab = new SharedArrayBuffer(N * 8);
  const shared = new Float64Array(sab);
  shared.set(base);
  const copy = performance.now() - t;
  t = performance.now();
  const bounds = Array.from({ length: P + 1 }, (_, i) => Math.floor((i * N) / P));
  await Promise.all(ws.map((w, i) => {
    w.postMessage({ sab, from: bounds[i], to: bounds[i + 1] });
    return once(w, "message");
  }));
  const sort = performance.now() - t;
  t = performance.now();
  const q = bounds.slice(0, P).map((from, i) => shared.subarray(from, bounds[i + 1]));
  const left = new Float64Array(q[0].length + q[1].length);
  const right = new Float64Array(q[2].length + q[3].length);
  merge(q[0], q[1], left);
  merge(q[2], q[3], right);
  const out = new Float64Array(N);
  merge(left, right, out);
  return { out, copy, sort, merge: performance.now() - t };
}

Base-case cutoff. Recursing to size 1 makes merge sort do 2n − 1 calls (1,999,999 at 106), most of them on tiny ranges where the call costs more than the work. Switching to insertion sort at 32 cuts the calls 30-fold (65,535) and the time by about 18%; at 128 insertion sort's n² starts to show and time goes back up. The recurrence doesn't change the Big-O, only the constant: T(n) = 2T(n/2) + n with leaves of size c costs n·log2(n/c) for merging plus (n/c)·O(c2) = O(n·c) for the leaves. The production-shaped merge sort with this cutoff is in lesson 03 part 1. Run each variant in its own process if numbers look odd: one variant's JIT feedback can slow another (lesson 01 part 7).

// نسخة merge sort بـ buffer واحد، والـ base case قابل للتغيير: لحد عنصر واحد، أو insertion sort تحت cutoff
export function mergeSort(a: Float64Array, cutoff: number): { calls: number } {
  const stats = { calls: 0 };
  sortRange(a, new Float64Array(a.length), 0, a.length, cutoff, stats);
  return stats;
}

function sortRange(a: Float64Array, buf: Float64Array, lo: number, hi: number, cutoff: number, stats: { calls: number }): void {
  stats.calls++;
  if (hi - lo <= cutoff) {
    // الـ base case: insertion sort على نطاق صغير — مفيش recursion ولا merge
    for (let i = lo + 1; i < hi; i++) {
      const x = a[i];
      let j = i - 1;
      while (j >= lo && a[j] > x) {
        a[j + 1] = a[j];
        j--;
      }
      a[j + 1] = x;
    }
    return;
  }
  const mid = (lo + hi) >>> 1;
  sortRange(a, buf, lo, mid, cutoff, stats);
  sortRange(a, buf, mid, hi, cutoff, stats);
  // لو آخر الشمال ≤ أول اليمين، النطاق مترتب أصلًا
  if (a[mid - 1] <= a[mid]) return;
  for (let k = lo; k < hi; k++) buf[k] = a[k];
  let i = lo, j = mid, k = lo;
  while (i < mid && j < hi) a[k++] = buf[i] <= buf[j] ? buf[i++] : buf[j++];
  while (i < mid) a[k++] = buf[i++];
  while (j < hi) a[k++] = buf[j++];
}

بالعامية

قسّم → حل → اجمع: قطّع الـ input لـ a مسائل حجم كل واحدة n/b، حل كل واحدة recursive، وبعدين اجمع الإجابات في f(n). التكلفة T(n) = a·T(n/b) + f(n)، والـ Master theorem من الدرس 01 الجزء 2 بيقراها (وإزاي تكتب الـ recurrence من الكود في الجزء 1). النمط ده بيكسّبك في 3 حالات بس: الـ sub-problems مستقلة (فتقدر تشغّلها parallel)، أو خطوة الـ combine رخيصة بالنسبة لحل المسألة كلها مباشرة، أو تقسيمة ذكية بتحتاج sub-problems أقل (Karatsuba في الجزء 5).

لما مبيكسّبكش حاجة: إجمالي كل tenant على مليون فاتورة: الـ loop O(n). والنسخة الـ recursive O(n) برضه، بس التقسيم لحد فاتورة واحدة بيعمل ويدمج حوالي 2 مليون Map صغيرة، فكانت أبطأ بحوالي 10 مرات. ولما حطينا cutoff عند 4,096 صف رجعت بسرعة الـ loop، لأن الـ leaves نفسها بقت loops. ومكسب مش متوقع في الـ floats: جمع 0.1 مليون مرة بالترتيب بيبعد لـ 100000.00000133288، والجمع الـ pairwise (D&C) بيطبع 100000، لأن خطأ التقريب فيه بيكبر زي log n مش n. الفلوس هنا بالقروش integers، فالاتنين exact.

فين بيكسّبك فعلًا: الـ parallelism. fork-join sort لـ 4 مليون float: حطهم في SharedArrayBuffer واحد، وخلّي 4 workers كل واحد يرتّب ربع في مكانه (من غير copy بين الـ threads)، وبعدين ادمج في الـ main thread. الـ recurrence على الـ critical path بقت T(n) = T(n/4) + O(n): الـ sorts الأربعة بيحصلوا مع بعض والدمج بس هو اللي sequential. قدام Float64Array.prototype.sort على thread واحد ومعاه الـ copy: أسرع حوالي مرتين لما الـ 4 workers بيتعملوا للـ run ده (تشغيلهم ≈60 ms على الجهاز ده)، وحوالي 2.6 مرة مع pool جاهز. وعند 100 ألف عنصر نفس الكود أبطأ 6 مرات وهو بارد، لأن تشغيل الـ workers أغلى من الـ sort كله. الفرق بين مشاركة الـ memory ونقلها، والـ pools، في Node 34 الجزء 2 و 3.

Part 2 — Quickselect through the D&C lens 🟡 Intermediateالجزء 2 — الـ quickselect بعين الـ D&C

English

Quickselect (built in lesson 04 part 5, with Hoare partitioning) is D&C that throws half the work away: partition around a pivot, then recurse into one side only. Its recurrence depends entirely on the pivot:

  • Good pivots (each split keeps at most a constant fraction): T(n) = T(n/2) + O(n) → n + n/2 + n/4 + … = O(n). Case 3 of the Master theorem: the root's work dominates.
  • Bad pivots: T(n) = T(n − 1) + O(n) → O(n2). Asking for the median of sorted latencies with "first element as pivot" removes one element per partition: 1,502,501 comparisons at n = 2,000 (≈3n²/8), exactly ×4.00 per doubling. A random pivot needs only a few n (2.84n on random data at 106); why random pivots make the expectation hold is lesson 16 part 3.
  • Median of medians guarantees a good pivot without randomness: split into groups of 5, take each group's median, recursively select the median of those n/5 medians. At least 3n/10 elements are ≤ it and 3n/10 are ≥ it, so the recursion keeps ≤ 7n/10: T(n) ≤ T(n/5) + T(7n/10) + O(n), and since 1/5 + 7/10 < 1 the total is O(n) worst case (an uneven split the Master theorem can't read; Akra–Bazzi can).
  • The price: on random data MoM made 3.0× the comparisons of a random pivot and took about 4× the time. That's why libraries use introselect: a cheap pivot first, and a fallback when the input is fighting back. Here the guard is a work budget (6n comparisons), which keeps the worst case linear: on sorted input it settles at about 13.5n, and on random data it costs the same as quickselect. GCC's libstdc++ std::nth_element uses median-of-3 pivots with a depth limit of 2·⌊log2 n⌋ and falls back to heap select, so its worst case is O(n log n), not O(n).

// الـ quickselect بقاعدة pivot قابلة للتغيير — بيرتّب الـ input جزئيًا ⁦in place (⁩اعمل copy لو محتاجه)
export type PivotRule = "first" | "random" | "mom";
export type Stats = { cmp: number; partitions: number };

const swap = (a: Float64Array, i: number, j: number) => {
  const t = a[i];
  a[i] = a[j];
  a[j] = t;
};

// الـ k-th أصغر قيمة (k من 0) في ⁦a[lo..hi]⁩، وبتفضل في مكانها ⁦a[k]⁩ بعد ما نخلص
export function selectRange(a: Float64Array, lo: number, hi: number, k: number, rule: (lo: number, hi: number) => number, s: Stats): number {
  while (lo < hi) {
    swap(a, lo, rule(lo, hi));
    const v = a[lo];
    s.partitions++;
    // الـ Hoare partition: الـ i من الشمال والـ j من اليمين، وبيقفوا على اللي يساوي ⁦v (⁩فالـ duplicates بتتقسم بالنص)
    let i = lo - 1;
    let j = hi + 1;
    for (;;) {
      do { i++; s.cmp++; } while (a[i] < v);
      do { j--; s.cmp++; } while (a[j] > v);
      if (i >= j) break;
      swap(a, i, j);
    }
    // كمّل في ناحية واحدة بس — ده اللي بيخلّيها T(n) = T(n/2) + n مش 2T(n/2) + n
    if (k <= j) hi = j;
    else lo = j + 1;
  }
  return a[k];
}

// اعمل insertion sort على مجموعة ⁦≤ 5⁩ وارجع index الـ median بتاعها
function median5(a: Float64Array, lo: number, hi: number, s: Stats): number {
  for (let i = lo + 1; i <= hi; i++) {
    const x = a[i];
    let j = i - 1;
    while (j >= lo && (s.cmp++, a[j] > x)) {
      a[j + 1] = a[j];
      j--;
    }
    a[j + 1] = x;
  }
  return (lo + hi) >>> 1;
}

// الـ median of medians: medians المجموعات الخماسية يتجمعوا في أول النطاق، وبعدين select عليهم بنفس القاعدة
export function momPivot(a: Float64Array, lo: number, hi: number, s: Stats): number {
  if (hi - lo < 5) return median5(a, lo, hi, s);
  let m = lo;
  for (let i = lo; i <= hi; i += 5) swap(a, median5(a, i, Math.min(i + 4, hi), s), m++);
  const mid = lo + ((m - 1 - lo) >>> 1);
  selectRange(a, lo, m - 1, mid, (l, h) => momPivot(a, l, h, s), s);
  return mid;
}

export function select(a: Float64Array, k: number, rule: PivotRule, rnd: () => number = Math.random): { value: number; stats: Stats } {
  const s: Stats = { cmp: 0, partitions: 0 };
  const pick =
    rule === "first" ? (lo: number) => lo
    : rule === "random" ? (lo: number, hi: number) => lo + Math.floor(rnd() * (hi - lo + 1))
    : (lo: number, hi: number) => momPivot(a, lo, hi, s);
  return { value: selectRange(a, 0, a.length - 1, k, pick, s), stats: s };
}

// الـ introselect: pivot رخيص (أول عنصر هنا عشان نشوف الحارس شغال) طول ما الشغل أقل من 6n مقارنة،
// ولو عدّاها يبقى الـ input بيضحك على الـ pivot فنحوّل لـ ⁦median of medians —⁩ الـ worst case يفضل ⁦O(n)⁩
export function introselect(a: Float64Array, k: number): { value: number; stats: Stats } {
  const s: Stats = { cmp: 0, partitions: 0 };
  const budget = 6 * a.length;
  const pick = (lo: number, hi: number) => (s.cmp < budget ? lo : momPivot(a, lo, hi, s));
  return { value: selectRange(a, 0, a.length - 1, k, pick, s), stats: s };
}

import { selectRange, type Stats } from "../src/dc/select.ts";
import { mulberry32 } from "./rng.ts";

// مليون order على 200 tenant: قيمة الـ order بالقروش، وكل tenant حجمه مختلف
const N = 1_000_000;
const T = 200;
const rnd = mulberry32(5);
const tenant = Uint16Array.from({ length: N }, () => Math.floor(T * rnd() ** 2));
const amount = Float64Array.from({ length: N }, () => 1000 + Math.floor(rnd() * 400_000));

// جمّع كل tenant في نطاق متصل (counting sort على الـ tenant)، من غير ما نرتّب القيم نفسها
function groupByTenant(): { values: Float64Array; start: Int32Array } {
  const start = new Int32Array(T + 1);
  for (let i = 0; i < N; i++) start[tenant[i] + 1]++;
  for (let t = 0; t < T; t++) start[t + 1] += start[t];
  const pos = start.slice();
  const values = new Float64Array(N);
  for (let i = 0; i < N; i++) values[pos[tenant[i]]++] = amount[i];
  return { values, start };
}

// الـ ⁦median (⁩الأدنى لو العدد زوجي) لكل tenant: quickselect على النطاق بتاعه بس
function mediansBySelect(): Float64Array {
  const { values, start } = groupByTenant();
  const out = new Float64Array(T);
  const s: Stats = { cmp: 0, partitions: 0 };
  const r = mulberry32(1);
  for (let t = 0; t < T; t++) {
    const lo = start[t], hi = start[t + 1] - 1;
    if (hi < lo) continue;
    out[t] = selectRange(values, lo, hi, lo + ((hi - lo) >> 1), (l, h) => l + Math.floor(r() * (h - l + 1)), s);
  }
  return out;
}

function mediansBySort(): Float64Array {
  const { values, start } = groupByTenant();
  const out = new Float64Array(T);
  for (let t = 0; t < T; t++) {
    const seg = values.subarray(start[t], start[t + 1]).sort();
    if (seg.length) out[t] = seg[(seg.length - 1) >> 1];
  }
  return out;
}

  • الـ median of medians بيضمن pivot كويس من غير عشوائية: قسّم لمجموعات من 5، خد الـ median بتاع كل مجموعة، واختار recursive الـ median بتاع الـ n/5 medians دول. على الأقل 3n/10 عنصر ≤ منه و 3n/10 ≥ منه، فالـ recursion بتكمّل على 7n/10 بالكتير: T(n) ≤ T(n/5) + T(7n/10) + O(n)، وعشان 1/5 + 7/10 < 1 المجموع O(n) حتى في الـ worst case (تقسيمة مش متساوية الـ Master theorem مبيقراهاش، و Akra–Bazzi بيقراها).
  • التمن: على data عشوائية الـ MoM عمل 3 أضعاف مقارنات الـ random pivot وخد حوالي 4 أضعاف الوقت. عشان كده الـ libraries بتستخدم introselect: pivot رخيص الأول، و fallback لما الـ input يبان إنه بيعاند. هنا الحارس ميزانية شغل (6n مقارنة)، فالـ worst case بيفضل خطي: على input مترتب بيوصل حوالي 13.5n، وعلى data عشوائية بنفس تكلفة الـ quickselect. و std::nth_element في libstdc++ بتاع GCC بيستخدم median-of-3 مع حد عمق 2·⌊log2 n⌋ وبعدين heap select، فالـ worst case بتاعه O(n log n) مش O(n).

Part 3 — Counting inversions with merge sort 🟡 Intermediateالجزء 3 — عدّ الـ inversions بالـ merge sort

English

Write each message's arrival number in the order it was processed. An inversion is a pair (i < j) where the message processed first arrived later: processed[i] > processed[j]. The count measures how out of order the processing was: 0 for perfect FIFO, n(n − 1)/2 for fully reversed. Brute force checks all pairs, O(n²). D&C counts them during merge sort: inversions = those inside the left half + inside the right half + across the halves, and the cross ones fall out of the merge for free: whenever the merge takes an element from the right half, every element still waiting in the left half is bigger, so it adds (mid − i). T(n) = 2T(n/2) + O(n) = O(n log n). The code is bottom-up (no recursion) with two buffers swapped each pass.

  • Ties are not inversions: on equal keys take from the left (<=). Using < counts every equal pair; fast-check shrinks that bug to [3, 3].
  • Kendall tau distance is the inversion count between two rankings of the same items: map version B's items to their positions in version A and count inversions. Normalise by n(n − 1)/2 to get a 0–1 distance, or τ = 1 − 2·distance to get a correlation from 1 (identical) to −1 (reversed). It only works on the same set of items; top-k lists with different members need an extended definition.

// الـ ⁦inversion =⁩ زوج (i < j) والعنصر اللي اتعالج الأول وصل بعد التاني: ⁦processed[i] > processed[j]⁩
// الـ input: رقم الوصول (arrival seq) لكل رسالة بترتيب المعالجة

// الـ oracle: كل الأزواج ⁦O(n²)⁩
export function inversionsBrute(seq: ArrayLike<number>): number {
  let count = 0;
  for (let i = 0; i < seq.length; i++) for (let j = i + 1; j < seq.length; j++) if (seq[i] > seq[j]) count++;
  return count;
}

// الـ merge sort بيعدّ وهو بيدمج: لما ناخد من اليمين، كل اللي فاضل في الشمال أكبر منه ⁦= inversions⁩
export function countInversions(seq: ArrayLike<number>): number {
  let src = Float64Array.from(seq);
  let dst = new Float64Array(src.length);
  let count = 0;
  // بنمشي bottom-up: runs بطول 1، 2، 4، ⁦… —⁩ مفيش recursion، والـ buffers بتتبادل كل ⁦pass (ping-pong)⁩
  for (let width = 1; width < src.length; width *= 2) {
    for (let lo = 0; lo < src.length; lo += 2 * width) {
      const mid = Math.min(lo + width, src.length);
      const hi = Math.min(lo + 2 * width, src.length);
      let i = lo, j = mid, k = lo;
      while (i < mid && j < hi) {
        if (src[i] <= src[j]) dst[k++] = src[i++];
        else {
          // العنصر اليمين أصغر من كل اللي باقي في الشمال (mid − i عنصر)، فكلهم inversions معاه
          count += mid - i;
          dst[k++] = src[j++];
        }
      }
      while (i < mid) dst[k++] = src[i++];
      while (j < hi) dst[k++] = src[j++];
    }
    [src, dst] = [dst, src];
  }
  return count;
}

// الـ Kendall tau distance بين ترتيبين لنفس العناصر: عدد الأزواج اللي ترتيبها اتعكس، متطبّع من 0 لـ 1
export function kendallTau<T>(a: readonly T[], b: readonly T[]): { distance: number; normalized: number; tau: number } {
  const pos = new Map(a.map((x, i) => [x, i] as const));
  const seq = b.map((x) => {
    const p = pos.get(x);
    if (p === undefined) throw new Error("rankings must contain the same items");
    return p;
  });
  const distance = countInversions(seq);
  const pairs = (a.length * (a.length - 1)) / 2;
  const normalized = pairs ? distance / pairs : 0;
  return { distance, normalized, tau: 1 - 2 * normalized };
}

English

Use: how much disorder do parallel consumers add? A simulation of 100,000 order events on one queue (four events per order: created, paid, shipped, delivered) at 80% utilisation, with a long-tailed processing time. One consumer: zero inversions. With 4 and 16 consumers pulling from the shared queue, global disorder climbs to about 11k and 54k inversions per 10k messages, and, more importantly, events of the same order get reordered (67 and 297 per 10k): "shipped" handled before "paid". Partitioning by key (order id hash → consumer, like Kafka partitions or SQS FIFO message groups) brings per-order inversions to exactly zero, but global disorder grows and the average wait jumps from 1.3 ms to 43 ms with 16 consumers, because a busy partition can't borrow idle consumers. So: measure disorder per key, not globally, and pay for ordering only where the business needs it. Backpressure and queue scheduling are in System Design 21.

import { countInversions } from "../src/dc/inversions.ts";

// 100,000 رسالة على queue واحدة: رسالة كل ⁦~1ms⁩، وكل order ليه ⁦4 events (created, paid, shipped, delivered)⁩
const N = 100_000;
type Msg = { seq: number; key: number; arrive: number };
function makeStream(seed: number): Msg[] {
  const rnd = mulberry32(seed);
  const msgs: Msg[] = [];
  let t = 0;
  const open: number[] = [];
  let nextOrder = 0;
  const stage = new Map<number, number>();
  for (let seq = 0; seq < N; seq++) {
    t += -Math.log(1 - rnd());
    // يا order جديد، يا الـ event اللي بعده لـ order مفتوح
    if (open.length < 50 || rnd() < 0.25) open.push(nextOrder++);
    const idx = Math.floor(rnd() * open.length);
    const key = open[idx];
    const s = (stage.get(key) ?? 0) + 1;
    stage.set(key, s);
    if (s === 4) open.splice(idx, 1);
    msgs.push({ seq, key, arrive: t });
  }
  return msgs;
}

// زمن المعالجة ⁦log-normal (⁩ذيل طويل)، ومتوسطه 0.8·k ms عشان الـ utilization يفضل ⁦≈80%⁩ مع k consumers
function simulate(msgs: Msg[], k: number, mode: "shared" | "byKey", seed: number) {
  const rnd = mulberry32(seed);
  const service = () => 0.8 * k * Math.exp(0.8 * Math.sqrt(-2 * Math.log(1 - rnd())) * Math.cos(2 * Math.PI * rnd()) - 0.32);
  const freeAt = new Float64Array(k);
  const done: Array<{ seq: number; key: number; at: number }> = [];
  let wait = 0;
  for (const m of msgs) {
    // في shared: أي consumer فاضي يسحب الرسالة؛ byKey: hash(key) % k زي partitions في Kafka أو message groups
    let c = 0;
    if (mode === "byKey") c = m.key % k;
    else for (let i = 1; i < k; i++) if (freeAt[i] < freeAt[c]) c = i;
    const start = Math.max(m.arrive, freeAt[c]);
    wait += start - m.arrive;
    freeAt[c] = start + service();
    done.push({ seq: m.seq, key: m.key, at: freeAt[c] });
  }
  done.sort((a, b) => a.at - b.at);
  // عدّ الـ inversions على مستوى الـ queue كلها، وجوه كل key لوحده (اللي فعلًا بيبوّظ الـ business)
  const global = countInversions(done.map((d) => d.seq));
  const perKey = new Map<number, number[]>();
  for (const d of done) {
    let list = perKey.get(d.key);
    if (!list) perKey.set(d.key, (list = []));
    list.push(d.seq);
  }
  let keyInv = 0;
  for (const seqs of perKey.values()) keyInv += countInversions(seqs);
  return { global: (global / N) * 10_000, keyInv: (keyInv / N) * 10_000, wait: wait / N };
}

بالعامية

اكتب رقم وصول كل رسالة بالترتيب اللي اتعالجت بيه. الـ inversion هو زوج (i < j) الرسالة اللي اتعالجت الأول فيه وصلت بعد التانية: processed[i] > processed[j]. العدد ده بيقيس المعالجة كانت مش مترتبة قد إيه: صفر لو FIFO مظبوط، و n(n − 1)/2 لو مقلوبة خالص. الـ brute force بيبص على كل الأزواج O(n²). والـ D&C بيعدّهم وهو بيعمل merge sort: الـ inversions = اللي جوه النص الشمال + اللي جوه اليمين + اللي بين النصين، واللي بينهم بيطلعوا من الـ merge ببلاش: كل ما الـ merge ياخد عنصر من اليمين، كل العناصر اللي لسه مستنية في الشمال أكبر منه، فبنزوّد (mid − i). T(n) = 2T(n/2) + O(n) = O(n log n). والكود bottom-up (من غير recursion) باتنين buffers بيتبادلوا كل pass.

  • الـ Kendall tau distance هو عدد الـ inversions بين ترتيبين لنفس العناصر: حوّل عناصر النسخة B لأماكنها في النسخة A وعدّ الـ inversions. اقسم على n(n − 1)/2 تاخد مسافة من 0 لـ 1، أو τ = 1 − 2 × المسافة تاخد correlation من 1 (متطابقين) لـ −1 (مقلوبين). بيشتغل بس على نفس مجموعة العناصر؛ قوائم top-k فيها عناصر مختلفة محتاجة تعريف موسّع.

The job: in a snapshot of every active courier's latest GPS ping, find pings closer than 5 m, a hint of one phone running two courier accounts or a spoofed location. First, degrees aren't meters: one degree of longitude in Cairo is cos(30°) ≈ 0.866 of a degree of latitude, so "degrees × 111 km" overstates east-west distances by 15.5% (5.78 m for a real 5 m). Project around a reference point (equirectangular: x = R·Δλ·cos φ₀, y = R·Δφ); within a city the error is tiny (0.18% at 20 km north of Tahrir), but reusing Cairo's reference for Aswan is off by 5.2%, so project per region. It also breaks near the poles and across the ±180° meridian.

D&C closest pair, O(n log n): sort by x once; split at the middle x; solve both halves, giving δ = the smaller of the two answers; the only pairs that could beat δ cross the dividing line, so keep points with |x − midX| < δ (the strip), in y order (merge sort by y runs alongside, so no re-sorting), and compare each point only with the following points whose y differs by less than δ. A packing argument bounds that at 7 per point: a δ × 2δ box above the point holds at most 8 points that are ≥ δ apart. Counted: on real-shaped data the strip is nearly empty (δ gets small fast), and on 20,000 adversarial small integer point sets (ties, collinear points) the worst point needed 3 checks.

// النقط بالمتر بعد الـ projection: xs و ys، والـ index هو رقم المندوب
export type Points = { xs: Float64Array; ys: Float64Array };
export type Pair = { a: number; b: number; d: number };

const R = 6_371_008.8; // نص قطر الأرض المتوسط بالمتر
const rad = (deg: number) => (deg * Math.PI) / 180;

// الـ equirectangular حوالين نقطة مرجعية: سريع ودقيق في نطاق مدينة، ومش دقيق لو بعدت عن lat0
export function project(lat: number, lng: number, lat0: number, lng0: number): [number, number] {
  return [R * rad(lng - lng0) * Math.cos(rad(lat0)), R * rad(lat - lat0)];
}

export function haversine(lat1: number, lng1: number, lat2: number, lng2: number): number {
  const s = Math.sin(rad(lat2 - lat1) / 2) ** 2 + Math.cos(rad(lat1)) * Math.cos(rad(lat2)) * Math.sin(rad(lng2 - lng1) / 2) ** 2;
  return 2 * R * Math.asin(Math.sqrt(s));
}

// ملحوظة: Math.hypot أبطأ بكتير من sqrt هنا (بيحمي من الـ overflow)، والأرقام بالمتر مش محتاجاه
const dist = (p: Points, i: number, j: number) => {
  const dx = p.xs[i] - p.xs[j];
  const dy = p.ys[i] - p.ys[j];
  return Math.sqrt(dx * dx + dy * dy);
};

// الـ oracle: كل الأزواج ⁦O(n²)⁩
export function closestBrute(p: Points): Pair {
  let best: Pair = { a: -1, b: -1, d: Infinity };
  for (let i = 0; i < p.xs.length; i++)
    for (let j = i + 1; j < p.xs.length; j++) {
      const d = dist(p, i, j);
      if (d < best.d) best = { a: i, b: j, d };
    }
  return best;
}

// الـ D&C: قسّم بالـ x، حل النصين، وبعدين شريط عرضه δ حوالين خط القسمة مترتب بالـ y
export function closestDC(p: Points): Pair & { stripChecks: number; maxChecksPerPoint: number } {
  const n = p.xs.length;
  const idx = Int32Array.from({ length: n }, (_, i) => i).sort((a, b) => p.xs[a] - p.xs[b]);
  const buf = new Int32Array(n);
  const strip = new Int32Array(n);
  let best: Pair = { a: -1, b: -1, d: Infinity };
  let stripChecks = 0;
  let maxChecksPerPoint = 0;
  const consider = (i: number, j: number) => {
    const d = dist(p, i, j);
    if (d < best.d) best = { a: Math.min(i, j), b: Math.max(i, j), d };
  };
  // بعد ما ⁦rec(lo, hi)⁩ تخلص: النطاق idx[lo..hi) بقى مترتب بالـ y (merge sort ماشي جنبها)
  const rec = (lo: number, hi: number): void => {
    if (hi - lo <= 3) {
      for (let i = lo; i < hi; i++) for (let j = i + 1; j < hi; j++) consider(idx[i], idx[j]);
      // رتّب النطاق الصغير ده بالـ ⁦y (insertion sort)⁩ عشان الـ merge اللي فوق
      for (let i = lo + 1; i < hi; i++) {
        const v = idx[i];
        let j = i - 1;
        while (j >= lo && p.ys[idx[j]] > p.ys[v]) idx[j + 1] = idx[j--];
        idx[j + 1] = v;
      }
      return;
    }
    const mid = (lo + hi) >>> 1;
    const midX = p.xs[idx[mid]];
    rec(lo, mid);
    rec(mid, hi);
    // الـ ⁦combine (1)⁩: ادمج النصين بالـ y
    let i = lo, j = mid, k = lo;
    while (i < mid && j < hi) buf[k++] = p.ys[idx[i]] <= p.ys[idx[j]] ? idx[i++] : idx[j++];
    while (i < mid) buf[k++] = idx[i++];
    while (j < hi) buf[k++] = idx[j++];
    for (let t = lo; t < hi; t++) idx[t] = buf[t];
    // الـ ⁦combine (2)⁩: النقط اللي بعدها عن خط القسمة أقل من δ بس هي اللي ممكن تعمل زوج أقرب
    let m = 0;
    for (let t = lo; t < hi; t++) if (Math.abs(p.xs[idx[t]] - midX) < best.d) strip[m++] = idx[t];
    for (let s = 0; s < m; s++) {
      let checks = 0;
      // كل نقطة بتتقارن بس باللي فوقها بفرق y أقل من δ — مش أكتر من 7 نقط
      for (let t = s + 1; t < m && p.ys[strip[t]] - p.ys[strip[s]] < best.d; t++) {
        consider(strip[s], strip[t]);
        checks++;
      }
      stripChecks += checks;
      if (checks > maxChecksPerPoint) maxChecksPerPoint = checks;
    }
  };
  if (n >= 2) rec(0, n);
  return { ...best, stripChecks, maxChecksPerPoint };
}

// الـ grid hash: لو δ معروفة (5 متر)، كل زوج أقرب من δ لازم يكون في نفس الخلية أو خلية جنبها
export function closePairsGrid(p: Points, delta: number): { pairs: Pair[]; checks: number } {
  const cells = new Map<number, number[]>();
  // مفتاح الخلية رقم صغير (SMI) مش string: ±16,384 خلية في كل اتجاه (⁦±82 km⁩ لو δ ⁦= 5 m⁩)
  const key = (cx: number, cy: number) => (cx + 16_384) * 32_768 + (cy + 16_384);
  const pairs: Pair[] = [];
  let checks = 0;
  for (let i = 0; i < p.xs.length; i++) {
    const cx = Math.floor(p.xs[i] / delta);
    const cy = Math.floor(p.ys[i] / delta);
    if (Math.abs(cx) >= 16_383 || Math.abs(cy) >= 16_383) throw new RangeError("point outside the grid: project per region");
    for (let dx = -1; dx <= 1; dx++)
      for (let dy = -1; dy <= 1; dy++) {
        const list = cells.get(key(cx + dx, cy + dy));
        if (!list) continue;
        for (const j of list) {
          checks++;
          const d = dist(p, i, j);
          if (d < delta) pairs.push({ a: j, b: i, d });
        }
      }
    const k = key(cx, cy);
    const own = cells.get(k);
    if (own) own.push(i);
    else cells.set(k, [i]);
  }
  return { pairs, checks };
}

Part 5 — Karatsuba and BigInt 🔴 Advancedالجزء 5 — Karatsuba و BigInt

English

Store a big number as limbs in base 107 (a limb product is below 1014, so with carries everything stays under 253 in a plain number). Schoolbook multiplication multiplies every limb by every limb: n² limb products. Split each number in half, a = a₁·Bm + a₀ and b = b₁·Bm + b₀, and the product needs a₁b₁, a₀b₀ and the middle a₁b₀ + a₀b₁. Computed directly that's four half-size products, T(n) = 4T(n/2) + O(n) = O(n²): no gain. Karatsuba's trick: (a₀ + a₁)(b₀ + b₁) − a₁b₁ − a₀b₀ equals the middle term, so three products suffice, T(n) = 3T(n/2) + O(n) = O(nlog₂3) = O(n1.585), case 1 of the Master theorem (the leaves dominate). The counts show it exactly: schoolbook ×4.00 per doubling, Karatsuba ×3.00. At 128,000 digits that's 334 million limb products against 19.5 million, and about 9× less time; every result is checked against BigInt as the oracle.

// ليه ⁦10^7⁩؟ حاصل ضرب limbين ⁦< 10^14⁩، ومعاه carry يفضل تحت ⁦2^53⁩ فالـ number العادي يكفي
export const BASE = 10_000_000;
export type Limbs = number[];
export const stats = { limbMuls: 0 };

export function fromDecimal(s: string): Limbs {
  const out: Limbs = [];
  for (let end = s.length; end > 0; end -= 7) out.push(Number(s.slice(Math.max(0, end - 7), end)));
  return trim(out);
}

export function toDecimal(a: Limbs): string {
  if (a.length === 0) return "0";
  return String(a[a.length - 1]) + a.slice(0, -1).reverse().map((x) => String(x).padStart(7, "0")).join("");
}

function trim(a: Limbs): Limbs {
  while (a.length > 0 && a[a.length - 1] === 0) a.pop();
  return a;
}

function add(a: Limbs, b: Limbs): Limbs {
  const out: Limbs = [];
  let carry = 0;
  for (let i = 0; i < Math.max(a.length, b.length) || carry; i++) {
    const s = (a[i] ?? 0) + (b[i] ?? 0) + carry;
    out.push(s % BASE);
    carry = s >= BASE ? 1 : 0;
  }
  return out;
}

// اطرح b من a في مكانها (مفروض a ≥ b)
function subInPlace(a: Limbs, b: Limbs): void {
  let borrow = 0;
  for (let i = 0; i < a.length; i++) {
    let s = a[i] - (b[i] ?? 0) - borrow;
    borrow = s < 0 ? 1 : 0;
    if (s < 0) s += BASE;
    a[i] = s;
  }
  trim(a);
}

// ضيف b × BASE^shift على a في مكانها
function addShifted(a: Limbs, b: Limbs, shift: number): void {
  let carry = 0;
  for (let i = 0; i < b.length || carry; i++) {
    const s = (a[i + shift] ?? 0) + (b[i] ?? 0) + carry;
    a[i + shift] = s % BASE;
    carry = s >= BASE ? 1 : 0;
  }
}

// الضرب المدرسي: كل limb في كل ⁦limb → n²⁩ عملية ضرب
export function mulSchool(a: Limbs, b: Limbs): Limbs {
  if (a.length === 0 || b.length === 0) return [];
  const out = new Array<number>(a.length + b.length).fill(0);
  for (let i = 0; i < a.length; i++) {
    let carry = 0;
    for (let j = 0; j < b.length; j++) {
      stats.limbMuls++;
      const cur = out[i + j] + a[i] * b[j] + carry;
      carry = Math.floor(cur / BASE);
      out[i + j] = cur - carry * BASE;
    }
    out[i + b.length] += carry;
  }
  return trim(out);
}

// فكرة Karatsuba: a = a1·B^m + a0 و b = b1·B^m + b0
// ونحسب ⁦z0 = a0·b0⁩، ⁦z2 = a1·b1⁩، و ⁦z1 = (a0 + a1)(b0 + b1) − z0 − z2 → 3⁩ ضربات بدل 4
export function karatsuba(a: Limbs, b: Limbs, cutoff = 32): Limbs {
  const n = Math.max(a.length, b.length);
  if (Math.min(a.length, b.length) <= cutoff) return mulSchool(a, b);
  const m = n >> 1;
  const a0 = trim(a.slice(0, m)), a1 = a.slice(m);
  const b0 = trim(b.slice(0, m)), b1 = b.slice(m);
  const z0 = karatsuba(a0, b0, cutoff);
  const z2 = karatsuba(a1, b1, cutoff);
  const z1 = karatsuba(add(a0, a1), add(b0, b1), cutoff);
  subInPlace(z1, z0);
  subInPlace(z1, z2);
  const out = new Array<number>(a.length + b.length + 1).fill(0);
  addShifted(out, z0, 0);
  addShifted(out, z1, m);
  addShifted(out, z2, 2 * m);
  return trim(out);
}

فين هستخدمه في شغلي؟ غالبًا مش هتكتب Karatsuba، بس هتقابل اللي بيعتمد عليه: RSA و Diffie-Hellman في node:crypto، وحسابات BigInt لـ IDs بـ 64-bit أو فلوس بدقة عالية، ومكتبات decimal. الفكرة نفسها ("قلّل عدد الـ sub-problems حتى لو الـ combine بقى أغلى شوية") بتظهر في الـ design: batch واحد بـ 3 queries بدل 4، أو cache لنتيجة وسطانية بتوفر فرع كامل من الشغل. ولما تقيس حاجة زي BigInt: الـ exponent بيتغيّر مع الحجم لأن الـ engine بيبدّل الـ algorithm عند حدود معينة، فمتعممش رقم واحد. الغلطة الشائعة: تقيس عملية الجهاز ممكن يشيلها (dead code)؛ خزّن الناتج في sink.

import { selectRange, type Stats } from "../src/dc/select.ts";

// الحل: p95 الأول على المصفوفة كلها، وبعدين p99 على الجزء اللي يمين p95 بس (كله ⁦≥ p95⁩)
export function p95p99(samples: Float64Array): { p95: number; p99: number; cmp: number } {
  const a = samples.slice();
  const s: Stats = { cmp: 0, partitions: 0 };
  const rand = (lo: number, hi: number) => lo + Math.floor(Math.random() * (hi - lo + 1));
  const k95 = Math.ceil(0.95 * a.length) - 1;
  const k99 = Math.ceil(0.99 * a.length) - 1;
  const p95 = selectRange(a, 0, a.length - 1, k95, rand, s);
  const p99 = selectRange(a, k95, a.length - 1, k99, rand, s);
  return { p95, p99, cmp: s.cmp };
}

// قيم latency شكلها حقيقي: أغلبها بين 20 و 80 ms وذيل طويل

const sorted = lat.slice().sort();

import { once } from "node:events";
import { isMainThread, parentPort, Worker, workerData } from "node:worker_threads";

const T = 200;
type Job = { tenants: SharedArrayBuffer; amounts: SharedArrayBuffer; from: number; to: number };

if (!isMainThread) {
  // الـ worker: يجمع نطاقه في Float64Array صغيرة (200 خانة) ويرجّعها — ده الـ "solve"
  const { tenants, amounts, from, to } = workerData as Job;
  const t = new Uint16Array(tenants), a = new Float64Array(amounts);
  const totals = new Float64Array(T);
  for (let i = from; i < to; i++) totals[t[i]] += a[i];
  parentPort?.postMessage(totals);
} else {
  const N = 4_000_000, P = 4;
  const tenants = new SharedArrayBuffer(N * 2), amounts = new SharedArrayBuffer(N * 8);
  const t = new Uint16Array(tenants), a = new Float64Array(amounts);
  for (let i = 0; i < N; i++) {
    t[i] = (Math.imul(i, 2654435761) >>> 0) % T;
    a[i] = 500 + ((i * 40503) % 200_000);
  }
  const t0 = performance.now();
  // الـ fork: كل worker ياخد ربع، والـ combine: جمع 4 مصفوفات ⁦× 200⁩ خانة بس
  const parts = await Promise.all(
    Array.from({ length: P }, async (_, w) => {
      const worker = new Worker(new URL(import.meta.url), { workerData: { tenants, amounts, from: (w * N) / P, to: ((w + 1) * N) / P } });
      const [totals] = (await once(worker, "message")) as [Float64Array];
      await worker.terminate();
      return totals;
    }),
  );
  const totals = new Float64Array(T);
  for (const p of parts) for (let k = 0; k < T; k++) totals[k] += p[k];
  const tPar = performance.now() - t0;
  const t1 = performance.now();
  const check = new Float64Array(T);
  for (let i = 0; i < N; i++) check[t[i]] += a[i];
  const tSeq = performance.now() - t1;
  console.log(`same totals: ${totals.every((v, k) => v === check[k])}; 4 workers (incl. startup) ≈${tPar.toFixed(0)} ms, one loop ≈${tSeq.toFixed(0)} ms`);
}

// 20,000 مندوب في مربع ⁦40×40 km (⁩بالمتر بعد الـ projection)، و 3 snapshots كل دقيقتين
const n = 20_000;
const rnd = mulberry32(12);
const planted: Array<[number, number]> = [[11, 4321], [900, 15000]];
let cur: Points = { xs: Float64Array.from({ length: n }, () => (rnd() - 0.5) * 40_000), ys: Float64Array.from({ length: n }, () => (rnd() - 0.5) * 40_000) };
const snapshots: Points[] = [];
for (let s = 0; s < 3; s++) {
  // كل مندوب بيتحرك لحد 300 متر؛ الحسابين اللي على نفس الموبايل بيتحركوا مع بعض (⁦±1⁩ متر)

  for (const [a, b] of planted) {
    next.xs[b] = next.xs[a] + (rnd() - 0.5) * 2;
    next.ys[b] = next.ys[a] + (rnd() - 0.5) * 2;
  }
  snapshots.push((cur = next));

Cheat sheet · الخلاصة

  • D&C = split → solve → combine; T(n) = aT(n/b) + f(n), read with the Master theorem. It pays off with independent sub-problems (parallelism), a cheap combine, or fewer sub-problems.
  • Same Big-O as a loop is no win: recursive per-tenant totals were ≈10× slower until the base case became a loop. Bonus on floats: pairwise summation error grows like log n.
  • Fork-join in Node: SharedArrayBuffer + workers sorting in place + main-thread merge: ≈2–2.6× on 4M floats, 6× slower on 100k cold. Measure the break-even; keep pools warm.
  • Base-case cutoff (~32): 30× fewer calls, ≈18% faster; same Big-O.
  • Quickselect: T(n/2) + n = O(n) with good pivots, T(n − 1) + n = O(n²) with first-element pivots on sorted input (×4.00 per doubling).
  • Median of medians: T(n/5) + T(7n/10) + n = O(n) worst case, but ≈3× the comparisons; introselect = cheap pivot + fallback. libstdc++ nth_element falls back to heap select (O(n log n)).
  • Inversions: count across halves during the merge (add mid − i when taking from the right); <= on ties; Kendall tau = inversions between two rankings.
  • Parallel consumers reorder events of the same entity; key partitioning fixes that and costs load balancing (wait 1.3 → 43 ms at 16 consumers).
  • Closest pair: sort by x, strip of width δ in y order, ≤ 7 checks per point (3 seen). With a known δ, a grid hash is simpler, O(n) expected, and returns all close pairs.
  • Project lat/lng to meters per region; degrees × 111 km is 15.5% off east-west in Cairo.
  • Karatsuba: 3 half-size products instead of 4 → n1.585 (×3.00 per doubling). V8 BigInt: schoolbook → Karatsuba → Toom-3 → FFT at 34 / 193 / 1,500 64-bit digits.
