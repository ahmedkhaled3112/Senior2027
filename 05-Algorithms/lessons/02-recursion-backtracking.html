Why this matters · ليه ده مهم

English

Recursion is how you walk anything tree-shaped: categories, menus, comment threads, org charts, permission inheritance, nested JSON. In Node the call stack holds only about 10k frames, so recursion over data someone else controls is a latent crash: one bad import or one malicious request body and the process throws RangeError. Seniors convert those walks to an explicit stack and cap depth at the boundary.

Backtracking is how you enumerate options under rules: valid product bundles, ways to pay with gift cards, delivery orderings, staff rosters. It is easy to write and easy to make explode. The skills that matter are the template (so the code is correct the first time), pruning (so it finishes), and production discipline: a node budget, a deadline, a worker thread, and knowing when to hand the problem to a real solver. Interviewers test exactly these: N-Queens, subsets with duplicates, combination sum.

Part 1 — Why Node throws RangeError, and the explicit stack 🟢 Basicالجزء 1 — ليه Node بيرمي RangeError، والـ explicit stack

English

The conversion recipe (the call stack becomes an array, each frame becomes an entry) is in section 03 · lesson 09 part 1. Here is the production version. collectSubcategoryIds walks category rows recursively; a bad CSV import made every category the child of the previous one, a 20,000-deep chain, and the walk throws RangeError: Maximum call stack size exceeded. The limit isn't one number: it is the stack size divided by the frame size, which depends on locals and on the JIT tier (lesson 01 part 5 measured 9,642 frames cold, 15,659 warm, 7,323 with five locals). A tail-recursive version overflows too: V8 has no tail-call optimization.

Raising the limit is not the fix. --stack-size is a V8 flag, not a Node option: Node's CLI docs don't list it and say V8 options have "no stability guarantee"; V8's own help describes it as the "default size of stack region v8 is allowed to use (in kBytes)", default 984. It tells V8 how much stack it may use; it does not enlarge the thread's real stack, so a value beyond it ends in a native crash instead of a catchable RangeError (not demonstrated here). On this machine --stack-size=4000 happened to work (42,968 frames). The supported knob is a worker: new Worker(file, { resourceLimits: { stackSizeMb } }), documented as "the default maximum stack size for the thread", default 4. Measured: at 4 MB the 20,000-deep chain still throws, at 16 MB a 60,000-deep chain passes. Even that only moves the cliff; the real fix is an explicit stack on the heap, bounded by memory instead of ~1 MB.

Pre-order is easy: pop a node, emit it, push its children in reverse so the first child comes out first. Post-order (a parent needs its children's results, like product counts rolled up per category) needs an exit marker: push the node again flagged exit before its children, and do the parent's work when the exit entry pops. Prove the iterative versions equal the recursive ones with a fast-check property over random trees. Two more traps: an explicit stack turns a parent-pointer cycle in bad data into an infinite loop instead of a RangeError, so keep a visited set when the data isn't guaranteed to be a tree; and JSON.parse accepts a 100,000-deep body (V8's parser isn't recursive) but JSON.stringify of it throws the same RangeError later, in your logger, cache or response. Cap nesting depth at the API boundary.

export type CategoryRow = { id: number; parentId: number | null; name: string; productCount: number };

// الـ rows زي ما جاية من الـ DB، وبنبني منها map من الأب لولاده
export function childrenIndex(rows: readonly CategoryRow[]): Map<number, number[]> {
  const kids = new Map<number, number[]>();
  for (const r of rows) {
    if (r.parentId === null) continue;
    const list = kids.get(r.parentId);
    if (list) list.push(r.id);
    else kids.set(r.parentId, [r.id]);
  }
  return kids;
}

// ❌ الـ recursive: stack frame لكل مستوى، فالعمق محدود بالـ call stack
export function collectSubcategoryIds(kids: Map<number, number[]>, id: number, out: number[] = []): number[] {
  out.push(id);
  for (const child of kids.get(id) ?? []) collectSubcategoryIds(kids, child, out);
  return out;
}

// ❌ شكل tail call: الـ call آخر حاجة، بس V8 مبيعملش TCO فبرضه بيقع
export function chainLengthTail(kids: Map<number, number[]>, id: number, acc = 1): number {
  const next = kids.get(id)?.[0];
  return next === undefined ? acc : chainLengthTail(kids, next, acc + 1);
}

// ✅ الـ pre-order بـ explicit stack: نفس ترتيب الـ recursive بالظبط
export function collectSubcategoryIdsIterative(kids: Map<number, number[]>, rootId: number): number[] {
  const out: number[] = [];
  const stack = [rootId];
  while (stack.length > 0) {
    const id = stack.pop()!;
    out.push(id);
    const children = kids.get(id) ?? [];
    // بنعمل push بالعكس عشان أول ابن يطلع الأول
    for (let i = children.length - 1; i >= 0; i--) stack.push(children[i]);
  }
  return out;
}

// الـ post-order: إجمالي المنتجات في كل category شامل الـ ⁦subcategories (⁩الأب محتاج ولاده يخلصوا الأول)
export function rollupProductsRecursive(kids: Map<number, number[]>, own: Map<number, number>, id: number, out = new Map<number, number>()): Map<number, number> {
  let total = own.get(id) ?? 0;
  for (const child of kids.get(id) ?? []) {
    rollupProductsRecursive(kids, own, child, out);
    total += out.get(child)!;
  }
  out.set(id, total);
  return out;
}

// ✅ الـ post-order بـ explicit stack: كل node بتتحط مرتين، والمرة التانية (exit) هي اللي بتجمع
export function rollupProductsIterative(kids: Map<number, number[]>, own: Map<number, number>, rootId: number): Map<number, number> {
  const out = new Map<number, number>();
  const stack: Array<{ id: number; exit: boolean }> = [{ id: rootId, exit: false }];
  while (stack.length > 0) {
    const { id, exit } = stack.pop()!;
    const children = kids.get(id) ?? [];
    if (!exit) {
      // أول زيارة: ارجعلي تاني بعد الولاد (الـ exit marker)
      stack.push({ id, exit: true });
      for (let i = children.length - 1; i >= 0; i--) stack.push({ id: children[i], exit: false });
    } else {
      let total = own.get(id) ?? 0;
      for (const child of children) total += out.get(child)!;
      out.set(id, total);
    }
  }
  return out;
}

// شجرة عشوائية: كل category أبوها واحد من اللي قبلها (فمفيش cycles) ومعاها عدد منتجات
const randomTree = fc.integer({ min: 1, max: 300 }).chain((n) =>
  fc.tuple(
    fc.array(fc.nat(), { minLength: n - 1, maxLength: n - 1 }),
    fc.array(fc.nat({ max: 50 }), { minLength: n, maxLength: n }),
  ).map(([parentPicks, counts]): CategoryRow[] =>
    counts.map((productCount, i) => ({
      id: i + 1, parentId: i === 0 ? null : (parentPicks[i - 1] % i) + 1, name: `c${i + 1}`, productCount,
    }))));

test("pre-order: explicit stack == recursion", () => {
  fc.assert(fc.property(randomTree, (rows) => {
    const kids = childrenIndex(rows);
    assert.deepEqual(collectSubcategoryIdsIterative(kids, 1), collectSubcategoryIds(kids, 1));
  }), { seed: 7, numRuns: 500 });
});

test("post-order rollup: explicit stack == recursion", () => {
  fc.assert(fc.property(randomTree, (rows) => {
    const kids = childrenIndex(rows);
    const own = new Map(rows.map((r) => [r.id, r.productCount]));
    assert.deepEqual(rollupProductsIterative(kids, own, 1), rollupProductsRecursive(kids, own, 1));
  }), { seed: 7, numRuns: 500 });
});

// حارس على حدود الـ API: ارفض أي body متداخل أكتر من maxDepth قبل ما أي كود recursive يلمسه
export function assertMaxDepth(value: unknown, maxDepth: number): void {
  // نفس فكرة الـ explicit stack: الحارس نفسه لازم ميبقاش recursive
  const stack: Array<[unknown, number]> = [[value, 1]];
  while (stack.length > 0) {
    const [v, depth] = stack.pop()!;
    if (v === null || typeof v !== "object") continue;
    if (depth > maxDepth) throw new RangeError(`JSON body nested deeper than ${maxDepth}`);
    for (const child of Object.values(v)) stack.push([child, depth + 1]);
  }
}

الـ pre-order سهل: اعمل pop لـ node، طلّعها، واعمل push لولادها بالعكس عشان أول ابن يطلع الأول. الـ post-order (الأب محتاج نتايج ولاده، زي إجمالي المنتجات لكل category) محتاج exit marker: حط الـ node تاني بعلامة exit قبل ولادها، واعمل شغل الأب لما الـ exit ده يطلع. واثبت إن النسخ الـ iterative بتساوي الـ recursive بـ fast-check property على شجر عشوائي. وفيه فخّين كمان: الـ explicit stack بيحوّل cycle في الـ parent pointers (data بايظة) لـ infinite loop بدل RangeError، فخلّي معاك visited set لو الـ data مش مضمون إنها tree؛ وJSON.parse بيقبل body متداخل 100,000 مستوى (الـ parser بتاع V8 مش recursive) بس JSON.stringify عليه بيرمي نفس الـ RangeError بعدين، في الـ logger أو الـ cache أو الـ response. حط حد للعمق على حدود الـ API.

(3) الـ rollup بالـ post-order هو نفسه "إجمالي الـ revenue لكل department شامل الـ sub-departments" أو "عدد الـ comments تحت كل comment".

Part 2 — The backtracking template 🟢 Basicالجزء 2 — الـ template بتاع الـ backtracking

English

Every backtracking search has the same shape: a mutable state, the choices available from it, choose (apply a choice), explore (recurse), unchoose (undo it), plus a completion test and an acceptance test. Writing that skeleton once, typed, means each concrete problem only fills in six small functions, and the undo logic sits right next to the apply logic where you can check it.

The concrete problem: every valid add-on bundle for a laptop order. Warranty tiers are mutually exclusive, a bag requires a sleeve, and the add-ons must fit a 3,500 EGP budget. The rules live in choices(): "take" is only offered when it fits the budget, its group is still free and its requirement is already in the bundle, so invalid branches are never entered. That gives 15 valid bundles after visiting 36 nodes, where the unpruned decision tree has 63 nodes and 32 leaves.

Two details decide correctness and memory. Snapshot, don't share: the state is mutated and undone, so a result must be a copy; returning the live picked array makes every result the same array, which is empty once the search has undone everything (the failing test below). Yield, don't collect: written as a generator, the caller can stop after the first 10 bundles (43 nodes, ≈0.6 ms) and memory stays O(depth) instead of O(results). The price: every yielded value climbs through one yield* frame per level, so enumerating all 804,027 bundles of a 24-item catalog took ≈944 ms with the generator against ≈69 ms with plain recursion and a counter. Use generators where callers want "the first N" or paging; use plain recursion in hot counting loops.

// الـ template العام: أي مسألة ⁦backtracking =⁩ الـ 6 حاجات دول
export interface BacktrackProblem<S, C, R> {
  isComplete(state: S): boolean;
  // الاختيارات الممكنة من الحالة دي (الـ pruning بيحصل هنا: متطلّعش اختيار مستحيل)
  choices(state: S): Iterable<C>;
  apply(state: S, choice: C): void;
  undo(state: S, choice: C): void;
  accept(state: S): boolean;
  // نسخة مستقلة من الحل: الـ state نفسه هيتغيّر بعد كده
  snapshot(state: S): R;
}

export const stats = { nodes: 0 };

export function* backtrack<S, C, R>(p: BacktrackProblem<S, C, R>, state: S): Generator<R> {
  stats.nodes++;
  if (p.isComplete(state)) {
    if (p.accept(state)) yield p.snapshot(state);
    return;
  }
  for (const choice of p.choices(state)) {
    // اختار ← استكشف ← ارجع في اختيارك
    p.apply(state, choice);
    yield* backtrack(p, state);
    p.undo(state, choice);
  }
}

  { sku: "BAG", price: 900, requires: "SLEEVE" },
  { sku: "MOUSE", price: 350 },

export function bundleProblem(addOns: AddOn[], budget: number): BacktrackProblem<State, Choice, string[]> {
  return {
    isComplete: (s) => s.i === addOns.length,
    *choices(s) {
      yield "skip";
      const a = addOns[s.i];
      const fits = s.spent + a.price <= budget;
      const groupFree = !a.group || !s.picked.some((p) => p.group === a.group);
      const requirementMet = !a.requires || s.picked.some((p) => p.sku === a.requires);
      // الـ ⁦pruning: "take"⁩ مش بيتعرض أصلًا لو بيكسر قيد
      if (fits && groupFree && requirementMet) yield "take";
    },
    apply(s, c) {
      if (c === "take") { s.picked.push(addOns[s.i]); s.spent += addOns[s.i].price; }
      s.i++;
    },
    undo(s, c) {
      s.i--;
      if (c === "take") { s.picked.pop(); s.spent -= addOns[s.i].price; }
    },
    accept: (s) => s.picked.length > 0,
    snapshot: (s) => s.picked.map((a) => a.sku),
  };
}

Part 3 — Subsets, permutations, combinations, with and without duplicates 🟢 Basicالجزء 3 — الـ subsets والـ permutations والـ combinations، بتكرار ومن غيره

English

Three shapes of the same template. Subsets: every node is a result, and a start index makes each set appear once in one canonical order → 2ⁿ results (all coupon combinations). Permutations: a used[] array, a result at depth n → n! results (orderings of delivery stops). Combinations: stop at size k, and prune when too few items remain to reach k → C(n, k) results (k of n promo slots). A counter over n = 1…10 matches 2ⁿ, n! and C(n, 3) exactly.

Duplicates. A cart [LAPTOP, LAPTOP, MOUSE] has two identical laptops, and the naive subsets list LAPTOP and LAPTOP+MOUSE twice. Sort first, then at each level skip a value equal to the previous one: if (i > start && a[i] === a[i - 1]) continue. The i > start part matters: it skips duplicates among siblings (same level) but still lets the second laptop follow the first one down the same path. For permutations: if (i > 0 && a[i] === a[i - 1] && !used[i - 1]) continue, meaning a duplicate may only be used after its twin is already in the path, which fixes one canonical order among equal items (3 orders instead of 6). Prove both with fast-check against a brute force that enumerates everything and deduplicates through a Set of keys (with size: "medium", 70 of 100 generated carts contain a repeated SKU, so duplicates are really exercised); a planted bug (i > 0 instead of i > start) is caught at once and shrunk to [MOUSE, MOUSE], whose MOUSE+MOUSE bundle silently disappeared.

Then look at the output sizes before you write the endpoint. At 10 million results per second, 2²⁰ takes 0.1 s but 15! takes ≈36 hours and 20! ≈7,700 years. Enumeration is an option for subsets up to ~25 items and permutations up to ~10–12; beyond that you need pruning (Part 4), DP (lesson 10, TSP for 15 stops) or a solver.

// (1) الـ subsets: كل مجموعة كوبونات ممكنة ⁦← 2^n⁩
export function subsets<T>(items: readonly T[]): T[][] {
  const out: T[][] = [];
  const path: T[] = [];
  const go = (start: number) => {
    out.push([...path]);
    for (let i = start; i < items.length; i++) {
      path.push(items[i]);
      go(i + 1);
      path.pop();
    }
  };
  go(0);
  return out;
}

// (2) الـ permutations: كل ترتيب لمحطات التوصيل ⁦← n!⁩
export function permutations<T>(items: readonly T[]): T[][] {
  const out: T[][] = [];
  const path: T[] = [];
  const used = new Array<boolean>(items.length).fill(false);
  const go = () => {
    if (path.length === items.length) { out.push([...path]); return; }
    for (let i = 0; i < items.length; i++) {
      if (used[i]) continue;
      used[i] = true; path.push(items[i]);
      go();
      path.pop(); used[i] = false;
    }
  };
  go();
  return out;
}

// (3) الـ combinations: k من ⁦n (⁩أماكن الـ promo على الصفحة الرئيسية⁦) ← C(n, k⁩)
export function combinations<T>(items: readonly T[], k: number): T[][] {
  const out: T[][] = [];
  const path: T[] = [];
  const go = (start: number) => {
    if (path.length === k) { out.push([...path]); return; }
    // تقليم بسيط: لو العناصر الباقية مش كفاية نكمّل k، متدخلش
    for (let i = start; i <= items.length - (k - path.length); i++) {
      path.push(items[i]);
      go(i + 1);
      path.pop();
    }
  };
  go(0);
  return out;
}

// (4) الـ subsets من غير تكرار: الـ cart فيها ⁦[A, A, B] ←⁩ رتّب، وفي نفس المستوى متختارش نفس القيمة مرتين
export function uniqueSubsets(items: readonly string[]): string[][] {
  const a = items.toSorted();
  const out: string[][] = [];
  const path: string[] = [];
  const go = (start: number) => {
    out.push([...path]);
    for (let i = start; i < a.length; i++) {
      if (i > start && a[i] === a[i - 1]) continue;
      path.push(a[i]);
      go(i + 1);
      path.pop();
    }
  };
  go(0);
  return out;
}

// (5) الـ permutations من غير تكرار: نسخة مكررة تتاخد بس لو اللي قبلها اتاخد في نفس الـ path
export function uniquePermutations(items: readonly string[]): string[][] {
  const a = items.toSorted();
  const out: string[][] = [];
  const path: string[] = [];
  const used = new Array<boolean>(a.length).fill(false);
  const go = () => {
    if (path.length === a.length) { out.push([...path]); return; }
    for (let i = 0; i < a.length; i++) {
      if (used[i]) continue;
      if (i > 0 && a[i] === a[i - 1] && !used[i - 1]) continue;
      used[i] = true; path.push(a[i]);
      go();
      path.pop(); used[i] = false;
    }
  };
  go();
  return out;
}

Part 4 — Pruning 🟡 Intermediateالجزء 4 — الـ pruning

English

Pruning means refusing to enter a subtree that can't contain an answer. N-Queens shows three levels on the same problem. Check at the end: place one queen per row in any column and validate only complete boards: Σ nᵏ nodes, 19,173,961 at n = 8 (≈266 ms) and already 435 million at n = 9, so it stops there. Check on each placement: reject a column as soon as it is attacked: 2,057 nodes at n = 8 and 4,674,890 at n = 13. Bitmasks: the same tree (identical node counts, asserted in the code), but columns and both diagonals live in three integers, so "which squares are free" is one expression instead of an O(n) scan: ≈83 ms instead of ≈1.5 s at n = 13. Two independent levers: pruning shrinks the tree, representation shrinks the cost per node.

Combination sum at work: which gift cards from a customer's wallet (30 seeded cards, 125–875 EGP) pay an order total of 2,350 EGP exactly? Each card can be used once; duplicates are skipped like in Part 3. With the cards sorted ascending, once a card exceeds the remaining amount every later card does too, so break is valid: same 1,083 combinations and the same 17,634 calls as continue, but 44,916 loop checks instead of 147,318 (×3.3 less work). With unlimited reuse of each denomination the recursion passes i instead of i + 1: 59 ways to make 1,000 EGP from 20 denominations in 474 nodes.

Bound pruning (branch and bound): when you want the best answer, not all of them, stop a branch when even its most optimistic completion can't beat the best found so far. For "fewest cards that pay 4,975 EGP exactly", the optimistic completion is cards so far + ceil(remaining / largest card still available); trying big cards first finds a good answer early so the bound bites: 1,828,974 nodes without the bound, 149 with it, same 7-card answer. Both classic mistakes show up in tests: break on unsorted input silently drops answers (the oracle test shrinks it to [[100, 50], 50]: the 100 card stops the loop before the 50 card that pays exactly is ever tried; with the medium size setting 68 of 100 generated wallets were unsorted, so the property really exercises this), and continue where break was valid gives the right answers with 3.3× the work, which no test catches; only counting does.

// المستوى 1: حط ملكة في كل صف في أي عمود، واتأكد من الصحة في الآخر بس
function checkAtEnd(n: number): number {
  const cols: number[] = [];
  const valid = () => {
    for (let r1 = 0; r1 < n; r1++)
      for (let r2 = r1 + 1; r2 < n; r2++)
        if (cols[r1] === cols[r2] || Math.abs(cols[r1] - cols[r2]) === r2 - r1) return false;
    return true;
  };
  const go = (row: number): number => {
    nodes++;
    if (row === n) return valid() ? 1 : 0;
    let found = 0;
    for (let c = 0; c < n; c++) { cols.push(c); found += go(row + 1); cols.pop(); }
    return found;
  };
  return go(0);
}

// المستوى 2: اتأكد عند كل وضع ملكة (O(n) scan للصفوف اللي فاتت⁦) ←⁩ الفرع الغلط بيتقص فورًا
function checkEachPlacement(n: number): number {
  const cols: number[] = [];
  const safe = (row: number, c: number) => {
    for (let r = 0; r < row; r++) if (cols[r] === c || Math.abs(cols[r] - c) === row - r) return false;
    return true;
  };
  const go = (row: number): number => {
    nodes++;
    if (row === n) return 1;
    let found = 0;
    for (let c = 0; c < n; c++) {
      if (!safe(row, c)) continue;
      cols.push(c); found += go(row + 1); cols.pop();
    }
    return found;
  };
  return go(0);
}

// المستوى 3: نفس الشجرة بالظبط، بس الأعمدة والقطرين ⁦bitmasks ←⁩ كل check بقى ⁦O(1)⁩
function bitmask(n: number): number {
  const full = (1 << n) - 1;
  const go = (cols: number, diag1: number, diag2: number): number => {
    nodes++;
    if (cols === full) return 1;
    let found = 0;
    // الأماكن الفاضية في الصف ده كلها في رقم واحد
    let free = full & ~(cols | diag1 | diag2);
    while (free) {
      const bit = free & -free;
      free -= bit;
      found += go(cols | bit, ((diag1 | bit) << 1) & full, (diag2 | bit) >> 1);
    }
    return found;
  };
  return go(0, 0, 0);
}

// (1) كل كارت مرة واحدة: إيه مجموعات الكروت اللي بتدفع الـ total بالظبط؟
export function exactCombos(cards: readonly number[], total: number, mode: "break" | "continue"): number[][] {
  const out: number[][] = [];
  const path: number[] = [];
  const go = (start: number, remaining: number) => {
    stats.nodes++;
    if (remaining === 0) { out.push([...path]); return; }
    for (let i = start; i < cards.length; i++) {
      stats.checks++;
      if (i > start && cards[i] === cards[i - 1]) continue;
      if (cards[i] > remaining) {
        // الـ break صح بس لو الـ cards مترتبة تصاعدي (كل اللي بعده أكبر)
        if (mode === "break") break;
        continue;
      }
      path.push(cards[i]);
      go(i + 1, remaining - cards[i]);
      path.pop();
    }
  };
  go(0, total);
  return out;
}

// (2) استخدام غير محدود لكل فئة: الـ i مش بيزيد بعد الاختيار
export function reuseCombos(values: readonly number[], total: number): number[][] {
  const out: number[][] = [];
  const path: number[] = [];
  const go = (start: number, remaining: number) => {
    stats.nodes++;
    if (remaining === 0) { out.push([...path]); return; }
    for (let i = start; i < values.length && values[i] <= remaining; i++) {
      path.push(values[i]);
      go(i, remaining - values[i]);
      path.pop();
    }
  };
  go(0, total);
  return out;
}

// (3) الـ bound pruning: أقل عدد كروت يدفع الـ total بالظبط (branch and bound)
export function fewestCards(cardsAsc: readonly number[], total: number, useBound: boolean): number[] | null {
  const desc = cardsAsc.toReversed();
  let best: number[] | null = null;
  const path: number[] = [];
  const go = (start: number, remaining: number) => {
    stats.nodes++;
    if (remaining === 0) { if (!best || path.length < best.length) best = [...path]; return; }
    if (start === desc.length) return;
    // أقل عدد كروت ممكن نحتاجه للباقي لو كل كارت قد أكبر كارت متاح
    const optimistic = path.length + Math.ceil(remaining / desc[start]);
    if (useBound && best && optimistic >= best.length) return;
    for (let i = start; i < desc.length; i++) {
      if (i > start && desc[i] === desc[i - 1]) continue;
      if (desc[i] > remaining) continue;
      path.push(desc[i]);
      go(i + 1, remaining - desc[i]);
      path.pop();
    }
  };
  go(0, total);
  return best;
}

Part 5 — At work: a shift-scheduling solver 🔴 Advancedالجزء 5 — في الشغل: solver لتوزيع الـ shifts

English

A support team serving the Gulf and Europe: 8 agents (4 Arabic speakers), 14 shifts a week (Saturday to Friday, Day and Night), 2 agents per shift. The constraints are typed data in an Instance, not code: availability, at most 5 shifts per agent, at most one shift per day, no night shift followed by the next morning, at least one Arabic speaker per shift, and weekend fairness (at most 1 Friday/Saturday shift each). This is a constraint satisfaction problem: variables (shifts), domains (teams of 2), constraints. Unary constraints (availability, an Arabic speaker in the team) are filtered into the domains once; the rest are checked when a team is assigned.

Version 1 is plain backtracking: shifts in calendar order, teams in a fixed order. Version 2 adds three classic heuristics. MRV (minimum remaining values, "fail first"): assign next the shift with the fewest teams left, because that's where a dead end shows up soonest. Forward checking: after each assignment, remove from every unassigned shift the teams that just became impossible; if any domain becomes empty, undo now instead of ten levels later. LCV (least constraining value, "succeed first"): try first the team that removes the fewest options from the other shifts. Measured with a 1,000,000-node budget on the same seeded week: plain, MRV-only and FC-only all gave up; MRV + FC solved it in 104 nodes; v2 in 14 nodes, which is 14 assignments and zero backtracking. On a week that is impossible (only Mona can cover both Thursday night and Friday day), v1 burned its whole budget while every version with MRV proved there is no roster in 3 nodes.

A solver nobody can verify is a liability, so the tests use an independent checker that re-reads every rule from the roster, and an oracle property: on 300 random tiny instances (212 infeasible, 88 solvable), v2's answer must equal exhaustive v1's.

export type Instance = {

export type Result = {

  ms: number;

export function solveRoster(inst: Instance, opt: Options): Result {
  const K = inst.shiftNames.length;
  const S = inst.days.length * K;
  const A = inst.agents.length;
  const dayOf = (s: number) => Math.floor(s / K);
  const kindOf = (s: number) => s % K;
  const isWeekend = (s: number) => inst.weekendDays.includes(dayOf(s));

  // كل القيم الممكنة لأي shift: مجموعات من perShift موظف
  const teams: number[][] = [];
  const pick = (start: number, cur: number[]) => {
    if (cur.length === inst.perShift) { teams.push([...cur]); return; }
    for (let a = start; a < A; a++) { cur.push(a); pick(a + 1, cur); cur.pop(); }
  };
  pick(0, []);

  // القيود الأحادية (⁦availability +⁩ متحدث عربي واحد على الأقل) بتتفلتر مرة واحدة في الأول
  let domains: number[][] = Array.from({ length: S }, (_, s) =>
    teams.flatMap((team, v) =>
      team.every((a) => !inst.agents[a].unavailable.includes(s)) && team.some((a) => inst.agents[a].arabic) ? [v] : []));

  const count = new Int32Array(A);
  const weekend = new Int32Array(A);
  const shiftOfAgentOnDay = new Int32Array(A * inst.days.length).fill(-1);
  const roster: (number[] | null)[] = new Array(S).fill(null);

  // هل الموظف a ينفع ياخد الـ shift s بالحالة الحالية؟ (القيود اللي بين الـ shifts)
  const agentOk = (a: number, s: number) => {
    const d = dayOf(s);
    if (count[a] >= inst.maxShifts) return false;
    if (shiftOfAgentOnDay[a * inst.days.length + d] !== -1) return false;
    if (isWeekend(s) && weekend[a] >= inst.maxWeekendShifts) return false;
    // ممنوع night وبعده morning اليوم اللي بعده
    if (kindOf(s) === 0 && d > 0 && shiftOfAgentOnDay[a * inst.days.length + d - 1] === K - 1) return false;
    if (kindOf(s) === K - 1 && d + 1 < inst.days.length && shiftOfAgentOnDay[a * inst.days.length + d + 1] === 0) return false;
    return true;
  };
  const teamOk = (v: number, s: number) => teams[v].every((a) => agentOk(a, s));
  const assign = (s: number, v: number, sign: 1 | -1) => {
    for (const a of teams[v]) {
      count[a] += sign;
      if (isWeekend(s)) weekend[a] += sign;
      shiftOfAgentOnDay[a * inst.days.length + dayOf(s)] = sign === 1 ? kindOf(s) : -1;
    }
    roster[s] = sign === 1 ? teams[v] : null;
  };

  let nodes = 0;
  let filled = 0;
  let best: { filled: number; roster: (number[] | null)[] } = { filled: 0, roster: [...roster] };
  let stop: Result["status"] | null = null;
  const t0 = performance.now();

  const search = (): boolean => {
    if (filled > best.filled) best = { filled, roster: [...roster] };
    if (filled === S) return true;

    // الـ MRV: اختار الـ shift اللي فاضله أقل اختيارات؛ من غيره: بالترتيب الزمني
    let s = -1;
    for (let t = 0; t < S; t++) {
      if (roster[t] !== null) continue;
      if (!opt.mrv) { s = t; break; }
      if (s === -1 || domains[t].length < domains[s].length) s = t;
    }

    let values = domains[s].filter((v) => teamOk(v, s));
    if (opt.lcv) {
      // الـ LCV: جرّب الأول الفريق اللي بيشيل أقل اختيارات من الـ shifts التانية
      const cost = new Map<number, number>();
      for (const v of values) {
        assign(s, v, 1);
        let removed = 0;
        for (let t = 0; t < S; t++) if (roster[t] === null) for (const w of domains[t]) if (!teamOk(w, t)) removed++;
        assign(s, v, -1);
        cost.set(v, removed);
      }
      values = values.toSorted((x, y) => cost.get(x)! - cost.get(y)!);
    }

    for (const v of values) {
      // الـ ⁦node =⁩ تعيين واحد اتجرّب (فريق لـ shift)
      nodes++;
      if (nodes > opt.nodeBudget) { stop = "budget"; return false; }
      // كل 1024 node بنبص على الساعة والـ ⁦signal (⁩الـ timer callback مش هيشتغل وإحنا blocking)
      if ((nodes & 1023) === 0) {
        if (opt.signal?.aborted) { stop = "aborted"; return false; }
        if (opt.deadlineMs !== undefined && performance.now() - t0 > opt.deadlineMs) { stop = "deadline"; return false; }
      }
      assign(s, v, 1);
      filled++;
      const saved = domains;
      let wipeout = false;
      if (opt.forwardCheck) {
        // الـ forward checking: شيل من كل shift فاضي الفرق اللي بقت مستحيلة؛ لو shift بقى من غير اختيارات ← ارجع فورًا
        domains = domains.map((dom, t) => (roster[t] !== null ? dom : dom.filter((w) => teamOk(w, t))));
        wipeout = domains.some((dom, t) => roster[t] === null && dom.length === 0);
      }
      if (!wipeout && search()) return true;
      domains = saved;
      filled--;
      assign(s, v, -1);
      if (stop) return false;
    }
    return false;
  };

  const ok = search();
  return {
    status: ok ? "solved" : stop ?? "infeasible",
    nodes,
    ms: performance.now() - t0,
    roster: ok ? roster : best.roster,
    bestFilled: ok ? S : best.filled,
  };
}

export function printRoster(inst: Instance, roster: (readonly number[] | null)[]): string {
  const K = inst.shiftNames.length;
  const cell = (team: readonly number[] | null) =>
    (team ? team.map((a) => inst.agents[a].name + (inst.agents[a].arabic ? "*" : "")).join(", ") : "—").padEnd(18);
  const lines = [`${"".padEnd(5)}${inst.shiftNames.map((n) => n.padEnd(18)).join("")}`];
  inst.days.forEach((day, d) => {
    lines.push(`${day.padEnd(5)}${inst.shiftNames.map((_, k) => cell(roster[d * K + k])).join("")}`);
  });
  return lines.join("\n");
}

function violations(inst: Instance, roster: (readonly number[] | null)[]): string[] {
  const K = inst.shiftNames.length, out: string[] = [];
  const shiftsOf = (a: number) => roster.flatMap((t, s) => (t?.includes(a) ? [s] : []));
  roster.forEach((team, s) => {
    if (!team || team.length !== inst.perShift) out.push(`shift ${s} not staffed`);
    else if (!team.some((a) => inst.agents[a].arabic)) out.push(`shift ${s} has no Arabic speaker`);
    team?.forEach((a) => { if (inst.agents[a].unavailable.includes(s)) out.push(`agent ${a} unavailable at ${s}`); });
  });
  inst.agents.forEach((_, a) => {
    const mine = shiftsOf(a);
    if (mine.length > inst.maxShifts) out.push(`agent ${a} over cap`);
    if (mine.filter((s) => inst.weekendDays.includes(Math.floor(s / K))).length > inst.maxWeekendShifts) out.push(`agent ${a} weekend`);
    const days = mine.map((s) => Math.floor(s / K));
    if (new Set(days).size !== days.length) out.push(`agent ${a} twice a day`);
    for (const s of mine) if (s % K === K - 1 && mine.includes(s + 1)) out.push(`agent ${a} night→morning`);
  });
  return out;
}

Part 6 — What breaks: exponential search in production 🔴 Advancedالجزء 6 — اللي بيبوظ: البحث الـ exponential في الـ production

English

Same solver, real size: 30 agents, 28 shifts (Morning, Afternoon, Evening, Night × 7 days), only 5 Arabic speakers. 5 speakers × 5 shifts = 25 < 28 shifts that need one, so there is no roster, but no single shift reveals it, so forward checking can't see it and the search explodes: after 2 s it had explored ≈0.6–1.1 million nodes (it varies with machine load) and the deepest partial roster covered 20 of 28 shifts. Four production fixes:

  • Budget and deadline inside the search. A node budget plus deadlineMs, checked every 1,024 nodes against performance.now(). The solver returns the deepest partial roster; completeGreedily fills the rest with the least-bad team and lists the broken rules by name (7 here). The API answers in ≈2 s with something a team lead can act on. A cheap global pre-check ("Arabic capacity 25 < 28") proves the impossibility in 0 nodes; real solvers get this effect from global and redundant constraints.
  • An AbortSignal can't stop synchronous code. AbortSignal.timeout(300) passed to the search never fired: the search ran ≈1,014 ms until its node budget, signal.aborted was still false right after it returned, and became true one event-loop turn later. Timers need the event loop, and the loop is the thing you're blocking. Inside synchronous work, check a clock.
  • Move it off the event loop. On the main thread the 2 s search pushed event-loop delay to ≈2,022 ms (2 of ~200 10 ms timer ticks ran); in a worker thread (section 06 · worker threads) the main thread's max delay was ≈19 ms and 133 ticks ran, against an idle baseline of 127 (on Windows a 10 ms interval fires about every 15.6 ms). In the worker version the main thread can also honor the request's AbortSignal by calling worker.terminate(): the client left at 300 ms and the worker was gone ≈309 ms after the call.
  • Know when to stop hand-rolling. Production rostering with soft constraints, preferences and fairness objectives is the job of CP-SAT (Google OR-Tools), MiniZinc or Timefold. The CP-SAT model below expresses the same rules declaratively and turns "at least one Arabic speaker" into a soft constraint it minimizes; it is not run here (no OR-Tools on this machine). The cheap middle ground is a greedy start plus local search (min-conflicts: repeatedly swap the agent in a violated shift for the one that reduces violations): our greedy completion leaves 7 violations where the capacity bound says 3 is the minimum, and local search is how you close that gap without exhaustive search.
import type { Instance } from "./roster.ts";

// كمّل أحسن roster جزئي بـ greedy: كل shift فاضي ياخد الفريق اللي بيكسر أقل قيود،
// وارجع الـ roster كامل + قايمة القيود المكسورة (عشان مدير الفريق يقرر بنفسه)
export function completeGreedily(inst: Instance, partial: (readonly number[] | null)[]) {
  const K = inst.shiftNames.length, D = inst.days.length, A = inst.agents.length;
  const count = new Array<number>(A).fill(0);
  const weekend = new Array<number>(A).fill(0);
  const kindOn = Array.from({ length: A }, () => new Array<number>(D).fill(-1));
  const take = (a: number, s: number) => {
    count[a]++;
    if (inst.weekendDays.includes(Math.floor(s / K))) weekend[a]++;
    kindOn[a][Math.floor(s / K)] = s % K;
  };
  partial.forEach((team, s) => team?.forEach((a) => take(a, s)));

  const broken = (a: number, s: number): string[] => {
    const d = Math.floor(s / K), k = s % K, name = inst.agents[a].name, v: string[] = [];
    if (inst.agents[a].unavailable.includes(s)) v.push(`${name} unavailable`);
    if (count[a] >= inst.maxShifts) v.push(`${name} goes over ${inst.maxShifts} shifts`);
    if (kindOn[a][d] !== -1) v.push(`${name} works twice that day`);
    if (inst.weekendDays.includes(d) && weekend[a] >= inst.maxWeekendShifts) v.push(`${name} over weekend cap`);
    if ((k === 0 && d > 0 && kindOn[a][d - 1] === K - 1) || (k === K - 1 && d + 1 < D && kindOn[a][d + 1] === 0)) v.push(`${name} night→morning`);
    return v;
  };

  const roster = [...partial];
  const violations: string[] = [];
  roster.forEach((team, s) => {
    if (team) return;
    const cost = (a: number) => broken(a, s).length;
    // متحدث عربي واحد على الأقل (أرخصهم)، والباقي أرخص الموجودين
    const arabic = [...inst.agents.keys()].filter((a) => inst.agents[a].arabic).sort((x, y) => cost(x) - cost(y))[0];
    const others = [...inst.agents.keys()].filter((a) => a !== arabic).sort((x, y) => cost(x) - cost(y)).slice(0, inst.perShift - 1);
    const chosen = [arabic, ...others];
    const label = `${inst.days[Math.floor(s / K)]} ${inst.shiftNames[s % K]}`;
    for (const a of chosen) for (const v of broken(a, s)) violations.push(`${label}: ${v}`);
    chosen.forEach((a) => take(a, s));
    roster[s] = chosen;
  });
  return { roster, violations };
}

from ortools.sat.python import cp_model

def solve_roster(agents, days, shift_names, per_shift=2, max_shifts=5,
                 max_weekend=2, weekend_days=(0, 6), seconds=2.0):
    K = len(shift_names)
    S = range(len(days) * K)
    model = cp_model.CpModel()
    # متغير bool لكل (موظف، shift): 1 يعني شغال فيه
    x = {(a, s): model.new_bool_var(f"x_{a}_{s}") for a in range(len(agents)) for s in S}

    # متغير "slack" لكل shift: لو مفيش متحدث عربي، بندفع غرامة بدل ما المسألة تبقى مستحيلة
    no_arabic = {s: model.new_bool_var(f"no_arabic_{s}") for s in S}
    for s in S:
        model.add(sum(x[a, s] for a in range(len(agents))) == per_shift)
        model.add(sum(x[a, s] for a, ag in enumerate(agents) if ag["arabic"]) + no_arabic[s] >= 1)

    for a, ag in enumerate(agents):
        model.add(sum(x[a, s] for s in S) <= max_shifts)
        for s in ag["unavailable"]:
            model.add(x[a, s] == 0)
        for d in range(len(days)):
            # مسموح بـ shift واحد في اليوم بالكتير
            model.add_at_most_one(x[a, d * K + k] for k in range(K))
            # ممنوع night وبعده morning اليوم اللي بعده
            if d + 1 < len(days):
                model.add(x[a, d * K + K - 1] + x[a, (d + 1) * K] <= 1)
        model.add(sum(x[a, d * K + k] for d in weekend_days for k in range(K)) <= max_weekend)

    # الهدف: أقل عدد shifts من غير متحدث عربي (الحد الأدنى هنا 3، لأن المطلوب 28 والسعة 25)
    model.minimize(sum(no_arabic.values()))
    solver = cp_model.CpSolver()
    # نفس فكرة الـ deadline بتاعتنا: الـ solver بيرجّع أحسن حل لقاه لحد دلوقتي
    solver.parameters.max_time_in_seconds = seconds
    status = solver.solve(model)
    if status in (cp_model.OPTIMAL, cp_model.FEASIBLE):
        return solver.status_name(status), solver.objective_value
    return solver.status_name(status), None

نفس الـ solver بالحجم الحقيقي: 30 موظف، 28 shift (صبح وضهر ومسا وليل × 7 أيام)، و5 بس بيتكلموا عربي. كل متحدث بالكتير 5 shifts، فالخمسة مع بعض يغطّوا 25 shift بس، والمطلوب 28 shift فيهم متحدث، فمفيش roster، بس ولا shift لوحده بيبيّن ده، فالـ forward checking مش شايفه والبحث بيفرقع: بعد ثانيتين كان زار ≈0.6 لـ 1.1 مليون node (بيختلف مع حمل الجهاز)، وأعمق roster جزئي غطّى 20 من 28 shift. 4 حلول للـ production:

  • budget و deadline جوه البحث. node budget و deadlineMs، والـ check كل 1,024 node بـ performance.now(). الـ solver بيرجّع أعمق roster جزئي؛ والـ completeGreedily بتكمّل الباقي بأقل فريق ضرر وبتكتب القواعد المكسورة بالاسم (7 هنا). الـ API بيرد في ≈2 ثانية بحاجة الـ team lead يقدر يتصرف فيها. وفحص global رخيص قبل البحث ("سعة العربي 25 أقل من 28") بيثبت الاستحالة في 0 node؛ والـ solvers الحقيقية بتعمل ده بالـ global constraints والـ redundant constraints.
  • الـ AbortSignal مبيقدرش يوقّف كود synchronous. AbortSignal.timeout(300) اتبعت للبحث وعمره ما اشتغل: البحث فضل ≈1,014ms لحد الـ budget، وsignal.aborted كان لسه false بعد ما رجع، وبقى true بعد لفّة event loop واحدة. الـ timers محتاجة الـ event loop، والـ loop هو بالظبط اللي إنت قافله. جوه الشغل الـ synchronous، بص على الساعة.
  • طلّعه برّه الـ event loop. على الـ main thread البحث بتاع الثانيتين خلّى تأخير الـ event loop ≈2,022ms (2 بس من ~200 tick اشتغلوا)؛ في worker thread (section 06 · الـ worker threads) أقصى تأخير للـ main thread كان ≈19ms و133 tick اشتغلوا، والـ loop وهو فاضي بيعمل 127 (على Windows الـ interval بتاع 10ms بيلف كل ≈15.6ms). وفي نسخة الـ worker الـ main thread يقدر كمان يحترم الـ AbortSignal بتاع الـ request بإنه ينادي worker.terminate(): العميل مشي عند 300ms والـ worker اتقفل بعد ≈309ms.
  • اعرف إمتى تبطّل تكتب بإيدك. الـ rostering الحقيقي اللي فيه قيود soft وتفضيلات وأهداف عدالة شغلانة CP-SAT (Google OR-Tools) أو MiniZinc أو Timefold. الـ model بتاع CP-SAT اللي فوق بيوصف نفس القواعد بشكل declarative وبيحوّل "متحدث عربي واحد على الأقل" لقيد soft بيقلّله؛ ومتشغّلش هنا (مفيش OR-Tools على الجهاز ده). والحل الوسط الرخيص: greedy في الأول + local search (الـ min-conflicts: بدّل الموظف في shift فيه مخالفة بواحد يقلّل المخالفات، وكرّر): الـ greedy بتاعنا سايب 7 مخالفات والـ capacity بتقول إن أقل حاجة ممكنة 3، والـ local search هو اللي بيقفل الفرق ده من غير بحث كامل.
فين هستخدمه في شغلي؟ endpoint زي POST /rosters/generate في HR system: مدير بيضيف قيد جديد ("الجمعة محتاجة 3 عرب")، والـ API فجأة ميردّش، والـ health checks تقع، والـ Kubernetes يعمل restart للـ pod، وكل الـ requests التانية على نفس الـ pod ضاعت. الحل اللي فوق بالظبط: pre-check للسعة يرد 422 برسالة "محتاجين 28 والمتاح 25" في 0ms؛ والبحث نفسه في worker بـ deadline ثانيتين، ولو العميل قفل الـ tab الـ worker يتقفل؛ والرد فيه أحسن roster جزئي والقواعد المكسورة بالاسم عشان المدير يقرر يكسر أنهي واحدة. ولما القواعد تكتر (تفضيلات، عدالة على شهور)، ده الوقت اللي تكتب فيه ADR إنكم تنقلوا لـ OR-Tools في service جنب.
Interview question "When do you use backtracking and when DP?" → DP when the problem has overlapping subproblems with a small state (the answer for "items 0..i with budget b" is reused many times), so you compute each state once. Backtracking when you need every solution, when constraints are global or irregular (rosters, N-Queens) so states don't repeat usefully, or when pruning keeps the tree small. A slow backtracking search whose recursive calls repeat the same (index, remaining) arguments is a DP waiting to happen: memoize it (lesson 10 part 5).
"إمتى تستخدم backtracking وإمتى DP؟" ← الـ DP لما المسألة فيها subproblems بتتكرر والـ state صغير (إجابة "العناصر من 0 لـ i بـ budget b" بتتستخدم كتير)، فبتحسب كل state مرة واحدة. والـ backtracking لما تكون محتاج كل الحلول، أو القيود global أو مش منتظمة (rosters، N-Queens) فالـ states مش بتتكرر بشكل مفيد، أو لما الـ pruning مخلّي الشجرة صغيرة. وأي backtracking بطيء الـ recursive calls بتاعته بتتكرر بنفس الـ arguments (index، remaining) هو DP مستني تكتشفه: اعمله memoization (الدرس 10 الجزء 5).
What breaks at scale Exponential search behaves fine in every test and explodes on one customer's data: the 8-agent week solved in 14 nodes, the 30-agent week ran out of time. Any endpoint that searches must have a node budget, a clock-based deadline, a capacity pre-check where one exists, and must not run on the event loop that serves other requests.
البحث الـ exponential بيعدّي كل الـ tests وبيفرقع على data عميل واحد: أسبوع الـ 8 موظفين اتحل في 14 node، وأسبوع الـ 30 موظف الوقت خلص عليه. أي endpoint بيدوّر لازم يبقى فيه node budget، و deadline بالساعة، و pre-check للسعة لو ينفع، ومينفعش يشتغل على نفس الـ event loop اللي بيخدم الـ requests التانية.

Hint · تلميح Each stack entry carries the node and its depth; the answer is the largest depth you pop.

Solution · الحل 
import { test } from "node:test";
import assert from "node:assert/strict";
import fc from "fast-check";

type Comment = { id: number; parentId: number | null };

// الـ recursive: أعمق مستوى replies تحت comment معيّن
function depthRecursive(kids: Map<number, number[]>, id: number): number {
  let deepest = 0;
  for (const c of kids.get(id) ?? []) deepest = Math.max(deepest, depthRecursive(kids, c));
  return 1 + deepest;
}

// الـ iterative: كل عنصر في الـ stack شايل الـ node والعمق بتاعه
function depthIterative(kids: Map<number, number[]>, rootId: number): number {
  let deepest = 0;
  const stack: Array<[id: number, depth: number]> = [[rootId, 1]];
  while (stack.length > 0) {
    const [id, depth] = stack.pop()!;
    deepest = Math.max(deepest, depth);
    for (const c of kids.get(id) ?? []) stack.push([c, depth + 1]);
  }
  return deepest;
}

const index = (rows: Comment[]) => {
  const kids = new Map<number, number[]>();
  for (const r of rows) if (r.parentId !== null) kids.set(r.parentId, [...(kids.get(r.parentId) ?? []), r.id]);
  return kids;
};
const thread = fc.array(fc.nat(), { maxLength: 300, size: "max" }).map((picks): Comment[] =>
  [{ id: 1, parentId: null }, ...picks.map((p, i) => ({ id: i + 2, parentId: (p % (i + 1)) + 1 }))]);

test("iterative depth == recursive depth", () => {
  fc.assert(fc.property(thread, (rows) => {
    const kids = index(rows);
    assert.equal(depthIterative(kids, 1), depthRecursive(kids, 1));
  }), { seed: 1 });
});

test("iterative survives a 200,000-deep bot thread", () => {
  const rows: Comment[] = Array.from({ length: 200_000 }, (_, i) => ({ id: i + 1, parentId: i === 0 ? null : i }));
  const kids = index(rows);
  assert.equal(depthIterative(kids, 1), 200_000);
  assert.throws(() => depthRecursive(kids, 1), RangeError);
});

Solution · الحل 
import { test } from "node:test";
import assert from "node:assert/strict";
import fc from "fast-check";

// كل الطرق المختلفة إنك تختار k items للشحنة الأولى من order فيه SKUs مكررة
function firstShipments(items: readonly string[], k: number): string[][] {
  const a = items.toSorted();
  const out: string[][] = [];
  const path: string[] = [];
  const go = (start: number) => {
    if (path.length === k) { out.push([...path]); return; }
    for (let i = start; i < a.length; i++) {
      if (i > start && a[i] === a[i - 1]) continue;
      path.push(a[i]);
      go(i + 1);
      path.pop();
    }
  };
  go(0);
  return out;
}

// الـ oracle: كل الـ masks اللي فيها k bits، والتكرار بيتشال بـ Set
function brute(items: readonly string[], k: number): string[] {
  const keys = new Set<string>();
  for (let m = 0; m < 1 << items.length; m++) {
    const pick = items.filter((_, i) => m & (1 << i));
    if (pick.length === k) keys.add(pick.toSorted().join("|"));
  }
  return [...keys].sort();
}

test("example: [A, A, B, C] choose 2", () => {
  assert.deepEqual(firstShipments(["SKU-A", "SKU-A", "SKU-B", "SKU-C"], 2).map((s) => s.join("+")),
    ["SKU-A+SKU-A", "SKU-A+SKU-B", "SKU-A+SKU-C", "SKU-B+SKU-C"]);
});

test("matches the brute force", () => {
  fc.assert(fc.property(fc.array(fc.constantFrom("SKU-A", "SKU-B", "SKU-C"), { maxLength: 10 }), fc.nat(5), (items, k) => {
    assert.deepEqual(firstShipments(items, k).map((s) => s.join("|")).sort(), brute(items, k));
  }), { seed: 2 });
});

Cheat sheet · الخلاصة

  • Node's stack ≈ 984 KB → ≈7k–16k frames depending on frame size and JIT tier; no TCO. Data-driven depth → explicit stack.
  • --stack-size is an unsupported V8 flag that doesn't grow the real thread stack; Worker resourceLimits.stackSizeMb is the supported knob (default 4), and it only moves the cliff.
  • Pre-order: pop, emit, push children reversed. Post-order: push an exit marker before the children, do the parent's work on exit.
  • Explicit stack + bad data = possible infinite loop: keep a visited set. JSON.parse accepts 100k-deep bodies, JSON.stringify doesn't: cap depth at the boundary.
  • Template: state, choices, apply (choose), recurse (explore), undo (unchoose), isComplete, accept, snapshot. Put the rules in choices().
  • Snapshot a copy, never the live path. Generators give "first N" in O(depth) memory but cost O(depth) per yielded value.
  • Subsets 2ⁿ (start index), permutations n! (used[]), combinations C(n, k) (stop at k, prune when too few remain).
  • Duplicates: sort, then skip i > start && a[i] === a[i − 1]; permutations add !used[i − 1]. Oracle-test against brute force + Set.
  • Pruning shrinks the tree, representation shrinks the cost per node (N-Queens bitmask ×18). break needs sorted, positive candidates.
  • Branch and bound: cut when the optimistic completion can't beat the best; try promising choices first (1.8M → 149 nodes).
  • CSP: MRV (fail first), forward checking (wipeout → undo now), LCV (succeed first, but costs work per node). Verify with an independent checker.
  • Production search: node budget + clock deadline + capacity pre-check + worker thread; AbortSignal can't stop sync code. Real rostering → CP-SAT / MiniZinc / Timefold.
بالعامية
  • الـ stack في Node ≈ 984 KB ← حوالي 7 لـ 16 ألف frame حسب حجم الـ frame وحالة الـ JIT؛ ومفيش TCO. لو العمق جاي من الـ data ← explicit stack.
  • الـ --stack-size ده V8 flag مش مدعوم ومبيكبّرش الـ stack الحقيقي للـ thread؛ والطريقة المدعومة resourceLimits.stackSizeMb في الـ Worker (الافتراضي 4)، وبرضه بتحرّك الحافة بس.
  • الـ pre-order: pop، طلّع، push للولاد بالعكس. الـ post-order: حط exit marker قبل الولاد، واعمل شغل الأب وقت الـ exit.
  • الـ explicit stack مع data بايظة ممكن يعمل infinite loop: خلّي معاك visited set. وJSON.parse بيقبل 100 ألف مستوى وJSON.stringify لأ: حط حد للعمق على الحدود.
  • الـ template: state، choices، apply (choose)، recurse (explore)، undo (unchoose)، isComplete، accept، snapshot. والقواعد مكانها choices().
  • سجّل نسخة، عمرك ما تسجّل الـ path نفسه. والـ generators بتدّيك "أول N" بـ O(depth) memory بس كل قيمة بتكلّف O(depth).
  • الـ subsets 2ⁿ (start index)، والـ permutations n! (used[])، والـ combinations C(n, k) (وقّف عند k واقطع لو الباقي مش كفاية).
  • التكرار: رتّب وبعدين اتخطّى i > start && a[i] === a[i − 1]؛ والـ permutations تزوّد !used[i − 1]. واعمل oracle test ضد brute force + Set.

  • الـ CSP: الـ MRV (افشل بدري)، والـ forward checking (لو domain فضي ارجع دلوقتي)، والـ LCV (انجح بدري، بس ليه تمن في كل node). واتأكد بـ checker مستقل.
  • البحث في الـ production: node budget + deadline بالساعة + pre-check للسعة + worker thread؛ والـ AbortSignal مبيوقّفش كود sync. والـ rostering الحقيقي ← CP-SAT أو MiniZinc أو Timefold.
