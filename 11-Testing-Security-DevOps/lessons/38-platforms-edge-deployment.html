Why this matters · ليه ده مهم

English

Most products should start on a platform: you get a deploy pipeline, TLS, logs and rollbacks without hiring anyone. The senior skill is knowing what you're buying, where its edges are, and how you'd leave. That means treating the platform's contract (an injected PORT, env vars, a health path, stdout logs) as an interface your app implements. No account was created for this lesson: platform configs are labelled Not run here, while the build steps, the health checks, TLS and a real local Workers runtime all ran.

بالعامية

أغلب المنتجات المفروض تبدأ على platform: بتاخد deploy pipeline و TLS و logs و rollbacks من غير ما توظف حد. مهارة السنيور إنه يعرف بيشتري إيه، وحدوده فين، وهيمشي إزاي لو احتاج. يعني تتعامل مع عقد الـ platform (PORT محقون، env vars، health path، logs على stdout) كـ interface الـ app بتاعك بينفّذه. مفيش حساب اتعمل عشان الدرس ده: ملفات الـ platforms مكتوب عليها Not run here، وخطوات الـ build والـ health checks والـ TLS و Workers runtime محلي حقيقي كلهم اشتغلوا.

Part 1 — Deploy in five minutes 🟢 Basicالجزء 1 — الـ deploy في 5 دقايق

English

All these platforms take a Git push or a container image and give you a URL with TLS. Vercel is built around Next.js: push, and it creates serverless functions plus edge caching, with a preview URL per branch. Its costs and limits are in section 06, lesson 20, part 1. Railway, Render and Fly.io run long-lived containers: they detect your app or use your Dockerfile, run a build, and start it. Fly.io adds control over regions and Machines.

Whatever the brand, the contract is the same: install from the lockfile, run the build, start a process, inject a PORT, poll a health path, then send traffic. An app that binds a hard-coded port, or takes minutes to answer its first health check, fails on all of them. The script below performs those steps on this machine, with no platform involved.

One real change: Railway's docs (read 2026-11-09) mark its Config as Code files (railway.json and railway.toml) as deprecated, with existing files working for legacy services until 2026-12-01, and they point to its Infrastructure as Code feature instead. The file is shown because you'll meet it in existing projects; for a new project, follow the migration guide.

كل الـ platforms دي بتاخد Git push أو container image وتديك URL عليه TLS. Vercel معمول حوالين Next.js: تعمل push وهو يطلّع serverless functions و edge caching، و preview URL لكل branch. تكلفته وحدوده في القسم 06، الدرس 20، الجزء 1. فين هستخدمه في شغلي؟ MVP لـ orders API وعايز تعرضه على عميل النهارده: Railway أو Render من الـ repo، و URL شغال قبل الغدا. والغلطة الشائعة: app.listen(3000). الـ platform بتحقن PORT تاني فالـ health check يفشل والـ deploy يترجع، وإنت شايف "شغال عندي". الحل في الكود فوق: اقرا PORT وارفض تقوم من غيره.
Trade-off: Git-push builds vs your own image Letting the platform build is the fastest start, but the image is whatever its builder decides today. Building your own Dockerfile takes more effort, gives a reproducible artifact, and is also your exit path (part 7).

Part 2 — Env vars and secrets on a platform 🟢 Basicالجزء 2 — الـ env vars والـ secrets على الـ platform

English

A platform stores your variables and injects them, usually with scopes per environment: production, preview and development each get their own values. Keep it that way: preview builds run code from any branch, so they must never hold production secrets.

The distinction that bites is build-time vs runtime. Runtime variables are read when the process starts, so changing one needs a restart at most. Build-time variables are copied into the output: anything prefixed NEXT_PUBLIC_ is inlined into the client bundle as a literal, covered in section 06, lesson 20, part 4. Changing it after the build does nothing, and anything put there is public.

Validate everything at boot with a schema, the pattern from section 04, lesson 32, part 2. A missing variable should stop the process with exit 1, so the platform keeps the old version running instead of swapping in a broken one. Print the variable's name and the reason, never its value, because logs end up in a third-party system.

import { z } from "zod";

// الـ schema: أي متغير ناقص أو غلط يوقّف الـ boot، قبل ما الـ traffic يوصل

  PORT: z.coerce.number().int().min(1).max(65535),
  NODE_ENV: z.enum(["development", "preview", "production"]),

بالعامية

الـ platform بتخزن المتغيرات وتحقنها، وغالبًا فيه scopes لكل environment: production و preview و development كل واحد ليه قيمه. خليها كده: الـ preview builds بتشغّل كود من أي branch، فمينفعش يبقى معاها secrets بتاعة production.

الفرق اللي بيعضّ هو build-time ضد runtime. متغيرات الـ runtime بتتقرا لما الـ process يبدأ، فتغييرها أقصاه restart. متغيرات الـ build بتتنسخ جوه الناتج: أي حاجة بتبدأ بـ NEXT_PUBLIC_ بتتحط في الـ client bundle كنص حرفي، ده في القسم 06، الدرس 20، الجزء 4. تغييرها بعد الـ build مش بيعمل حاجة، وأي حاجة تتحط فيها بتبقى عامة.

اعمل validate لكل حاجة وقت الـ boot بـ schema، نفس النمط من القسم 04، الدرس 32، الجزء 2. المتغير الناقص لازم يوقّف الـ process بـ exit 1، عشان الـ platform تفضل مشغّلة النسخة القديمة بدل ما تحط نسخة بايظة. واطبع اسم المتغير والسبب، وأبدًا مش القيمة، لأن الـ logs بتوصل لنظام طرف تالت.

فين هستخدمه في شغلي؟ حد نسي يضيف PAYMENTS_WEBHOOK_SECRET في الـ production scope. من غير validation، الـ app يقوم عادي وكل webhook يقع بعد ساعات في الليل. مع Zod الـ deploy نفسه يفشل والنسخة القديمة تفضل شغالة. والغلطة الشائعة: تحط API key سرّي في NEXT_PUBLIC_ عشان "مكانش بيشتغل من غيره"، فيبقى ظاهر لأي حد يفتح الـ bundle.
What breaks: a secret set only after the build If a server-side value is read at module scope during a static build, the build captures whatever was set then. Read secrets inside functions or at server start, and treat a preview deployment as an untrusted environment.
لو قيمة server-side اتقرت على مستوى الـ module أثناء static build، الـ build هياخد اللي كان موجود ساعتها. اقرا الـ secrets جوه functions أو وقت بداية السيرفر، واعتبر الـ preview deployment environment مش موثوق فيه.

Part 3 — Health and logs 🟢 Basicالجزء 3 — الـ health والـ logs

English

The liveness and readiness split is taught in section 04, lesson 24, part 6. On a platform it becomes configuration: you name a path, and the platform polls it to decide whether a new version takes traffic and whether an instance stays in rotation. A liveness path must not touch the database, or a database blip restarts every instance at once.

Platforms capture stdout and stderr, one event per line. So write one JSON object per line. A multi-line stack trace from console.error(err) becomes several separate events that can't be parsed or linked to a request. Platform log viewers keep logs for a limited time, so a log drain ships them somewhere you control and can query. Add a request ID to every line to follow one request across them.

Stand-in: a script plays the platform, polling health and forwarding stdout lines to a loopback drain. It doesn't capture real routing, restarts on other hosts, sampling, or a real drain's retries.

ده بديل تعليمي: سكريبت بيعمل دور الـ platform، بيعمل poll على الـ health وبيبعت سطور stdout لـ drain على الـ loopback. مش بيغطي الـ routing الحقيقي، ولا الـ restarts على hosts تانية، ولا الـ sampling، ولا الـ retries بتاعة drain حقيقي.

Part 4 — Domain and TLS 🟢 Basicالجزء 4 — الدومين والـ TLS

English

Connecting a domain usually means one or two DNS records. A subdomain gets a CNAME to the platform's hostname. The apex (acme-example.com) can't be a CNAME under the DNS rules, so you use the platform's A records or your DNS provider's ALIAS/flattening. A CAA record limits which CAs may issue for you.

The platform then gets a certificate over ACME, the protocol behind Let's Encrypt. It proves control of the name with HTTP-01 (serve a token at /.well-known/acme-challenge/) or DNS-01 (publish a TXT record at _acme-challenge). Wildcards need DNS-01.

Renewal must be hands-off, and that became urgent. CA/Browser Forum ballot SC-081v3 caps publicly trusted certificates at 200 days since 2026-03-15, 100 days from 2027-03-15, and 47 days from 2029-03-15. Let's Encrypt has an opt-in 45-day tlsserver profile since 2026-05-13, a default of 64 days from 2027-02-10 and 45 days from 2028-02-16. A calendar reminder can't keep up. Monitor what the server actually presents, because a renewal job can succeed while the running process still serves the old certificate.

const DAY = 86_400_000;

async function makeCert(issuedDaysAgo, lifetimeDays) {
  const alg = { name: "ECDSA", namedCurve: "P-256", hash: "SHA-256" };
  const keys = await webcrypto.subtle.generateKey(alg, true, ["sign", "verify"]);
  const notBefore = new Date(Date.now() - issuedDaysAgo * DAY);
  const cert = await x509.X509CertificateGenerator.createSelfSigned({
    serialNumber: "01", name: "CN=api.acme-example.com", notBefore,
    notAfter: new Date(notBefore.getTime() + lifetimeDays * DAY),
    signingAlgorithm: alg, keys,
  });
  const pkcs8 = await webcrypto.subtle.exportKey("pkcs8", keys.privateKey);
  return { cert: cert.toString("pem"), key: x509.PemConverter.encode(pkcs8, "PRIVATE KEY") };
}

    const c = socket.getPeerCertificate();
    socket.end();
    resolve({ validFrom: new Date(c.valid_from), validTo: new Date(c.valid_to) });
  });
  socket.on("error", reject);
});

function verdict({ validFrom, validTo }, now = Date.now()) {
  const lifetime = (validTo - validFrom) / DAY;
  const left = (validTo - now) / DAY;
  if (left <= 0) return `CRITICAL expired ${Math.abs(left).toFixed(0)} days ago`;
  if (left < lifetime / 3) return `WARN ${left.toFixed(0)} of ${lifetime.toFixed(0)} days left: renewal should have happened`;
  return `OK ${left.toFixed(0)} of ${lifetime.toFixed(0)} days left`;
}

ربط الدومين غالبًا record أو اتنين في الـ DNS. الـ subdomain بياخد CNAME على hostname الـ platform. الدومين الأساسي (acme-example.com) مينفعش يبقى CNAME حسب قواعد الـ DNS، فبتستخدم A records بتاعة الـ platform أو ALIAS/flattening من مزوّد الـ DNS. و CAA record بيحدد مين من الـ CAs يقدر يصدر شهادات ليك.

English

Decide on team size, speed, scale, compliance and networking, in that order. The price calculation below uses official list prices read on 2026-11-09 (RDS from the AWS Price List published 2026-10-29, N. Virginia). Render's pricing table didn't load through my fetch, so it's left out rather than guessed.

The numbers contradict a common belief: at list price AWS isn't automatically cheaper. Fargate and Railway compute are close, and AWS adds an ALB, NAT gateways and $0.09/GB egress. What changes the picture is the shape of the workload: Railway charges about three times more for memory, so a memory-heavy instance (1 vCPU, 8 GB) costs $100 there against $56 on Fargate. Commitment discounts and egress tiers aren't included here; lesson 36 covers compute decisions on AWS. The Railway figures assume 100% of allocated resources for the full month, and it actually bills measured usage, so they're an upper bound.

The strongest reasons to leave a platform are usually not the invoice: a compliance demand (SOC 2 scope, data residency, a BAA), private networking to existing systems, or needing control over the load balancer or database. Vercel's Pro plan lists SAML SSO at $300/month and a HIPAA BAA at $350/month, which shows that compliance has a price on platforms too. Lock-in is concrete, so list it per feature (the table below).

Part 6 — Edge runtimes for real 🟡 Intermediateالجزء 6 — الـ edge runtimes على أصولها

English

An edge runtime such as Cloudflare Workers runs your code in V8 isolates close to users, with Web APIs (fetch, Request, crypto.subtle) as the base. The architecture is covered in section 04, lesson 33, part 3. The usual claim is "no fs, Web APIs only", which the README repeats. That is out of date: with Node compatibility, node:fs works on a virtual, memory-based filesystem.

The run below uses workerd, the real open-source Workers runtime, through miniflare, with no account. Without the flag the import fails with No such module "node:fs". With nodejs_compat, /bundle lists the Worker's own modules, /tmp is writable, and writing to /bundle fails with EPERM. Cloudflare's docs add that /tmp is unique to each request.

The docs and this local build disagree on one point. Cloudflare's documentation (read 2026-11-09) says Node compatibility is on by default for compatibility dates of 2026-08-04 or later. On miniflare 4.20260730.0, the newest date it accepts here is 2026-08-06, and the run without the flag still failed at that date. So treat the docs as the rule for the platform, and keep the flag in local examples with this build.

The limits that shape what fits: Cloudflare lists 10 ms of CPU per request on the Free plan, 30 seconds by default on Paid (up to 5 minutes), 128 MB of memory per isolate, and 6 simultaneous outgoing connections. The run below burned about 300 ms of CPU and returned 200, so the local runtime doesn't enforce the plan limit. Test CPU cost separately. The second trap is real and reproduced: I/O objects belong to the request that created them, so a Node-style global connection pool doesn't work. Good fits are auth checks, redirects, light personalization and caching. Poor fits are heavy CPU work and chatty database transactions.

Part 7 — Exit strategy 🟡 Intermediateالجزء 7 — خطة الخروج

English

An exit strategy is cheap insurance that you buy before you need it. Keep two things true: a Dockerfile that works, so the app can run anywhere containers run, and platform specifics behind adapters, so business logic never imports a vendor SDK. Web-standard frameworks like Hono make this easier, since the same fetch handler runs on Node, Workers and others.

The run below takes one Hono app and runs it on Node with a Map store and on workerd with a real local KV binding. All 5 responses were identical. The rule is checked by a script rather than by goodwill: platform imports are allowed only under src/adapters. Data is the hard part of any move, so export it regularly and test a restore; the database dump is usually the longest step of a migration. The base image follows the current LTS: node:26-slim in place of the README's node:22-slim, since Node 26 is LTS as of this writing.

    const order = await store.get(c.req.param("id"));
    return order ? c.json(order) : c.json({ error: "not found" }, 404);

  return app;
}

const walk = (dir: string): string[] =>
  readdirSync(dir).flatMap((f) => {

  });

export function check(root: string) {
  const problems: string[] = [];
  for (const file of walk(root)) {
    const rel = relative(root, file).split(sep).join("/");
    if (rel.startsWith("adapters/")) continue;
    for (const m of readFileSync(file, "utf8").matchAll(/from\s+["']([^"']+)["']/g)) {
      if (PLATFORM.some((re) => re.test(m[1]!))) problems.push(`${rel}: imports ${m[1]}`);
    }
  }
  return problems;
}

بالعامية

خطة الخروج تأمين رخيص بتشتريه قبل ما تحتاجه. خلّي حاجتين صح دايمًا: Dockerfile شغال عشان الـ app يشتغل في أي مكان فيه containers، وتفاصيل الـ platform ورا adapters عشان الـ business logic عمره ما يعمل import لـ vendor SDK. الـ frameworks المبنية على Web standards زي Hono بتسهّل ده، لأن نفس الـ fetch handler بيشتغل على Node و Workers وغيرهم.

التشغيل تحت بياخد Hono app واحد ويشغّله على Node بـ Map store، وعلى workerd بـ KV binding محلي حقيقي. الـ 5 ردود طلعوا متطابقين. والقاعدة بيفحصها سكريبت مش حسن النية: الـ imports الخاصة بالـ platform مسموحة بس تحت src/adapters. والبيانات هي الجزء الصعب في أي نقل، فاعمل export بانتظام وجرّب الـ restore؛ الـ database dump غالبًا أطول خطوة في الـ migration. والـ base image ماشية مع الـ LTS الحالي: node:26-slim بدل node:22-slim اللي في الـ README، لأن Node 26 هو الـ LTS وقت كتابة الدرس.

قايمة الـ portability:

  • الـ Dockerfile بيتبني ويشتغل في الـ CI، حتى لو الـ deploy مش بيستخدمه.
  • مفيش vendor SDK بره src/adapters، ودي بيفحصها سكريبت.
  • الـ config كله من env vars، ومتحقق منه بـ schema وقت الـ boot.
  • الـ logs JSON على stdout، والـ drain قابل للتغيير.
  • الـ DB عادية (Postgres) ومفيش feature خاصة بالـ platform من غير خطة بديلة.
  • الملفات في تخزين متوافق مع S3، والـ export والـ restore متجربين.
  • الدومين والـ DNS عندك إنت، مش عند الـ platform.
  • IaC أو ملف config في الـ repo، مش ضغطات في dashboard.
فين هستخدمه في شغلي؟ الـ platform رفعت الأسعار أو طلب امتثال جديد نزل. لو الـ app ورا adapters وعندك Dockerfile بيتبني في الـ CI، النقل بيبقى أسبوع شغل على البيانات والشبكة. لو @vercel/kv متناثر في 40 ملف، هتعيد الكتابة. وحتى في المشروع الجانبي، ابدأ بالقاعدة دي من أول route.
Trade-off: portability has a cost too Abstracting everything "just in case" wastes time and hides useful platform features. Put adapters around things that are costly to change (storage, queues, auth), and accept direct use of a feature when replacing it later would be cheap.
إنك تعمل abstraction لكل حاجة "احتياطي" بيضيّع وقت وبيخبّي ميزات مفيدة في الـ platform. حط adapters حوالين الحاجات الغالية في التغيير (storage، queues، auth)، واقبل الاستخدام المباشر لأي ميزة استبدالها بعدين رخيص.

Common mistakes · غلطات شائعة

❌ Hard-coded port 
// الغلط: الـ platform بتحقن PORT تاني
app.listen(3000);
✅ Read the injected PORT

بالعامية

❌ الـ port الثابت بيخلّي الـ health check يفشل والـ deploy يترجع، وإنت شايفه شغال على جهازك. ✅ اقرا PORT من الـ env، ولو مش موجود وقّف بـ exit 1 عشان المشكلة تبان فورًا.

❌ A secret in a public variable 
# الغلط: القيمة دي بتتحط في الـ client bundle
NEXT_PUBLIC_PAYMENTS_KEY=fake-key-not-real
✅ Server-side only 
# الصح: بتتقرا على السيرفر بس
PAYMENTS_KEY=fake-key-not-real
بالعامية

❌ أي متغير بيبدأ بـ NEXT_PUBLIC_ بيتنسخ حرفيًا في الـ JavaScript اللي بيروح للمتصفح، وأي حد يقدر يقراه. ✅ سيب الـ secret من غير الـ prefix، واستخدمه من Server Component أو Route Handler.

❌ Liveness touches the database 
// الغلط: عطل صغير في الـ DB يعمل restart للكل
if (req.url === "/healthz") await db.query("select 1");
✅ Liveness is process-only 
// الصح: الـ DB في readiness بس
if (req.url === "/healthz") return send(200, { ok: true });
if (req.url === "/readyz") return dbUp ? send(200, {}) : send(503, {});
بالعامية

❌ الـ liveness اللي بيفحص الـ DB بيحوّل مشكلة DB صغيرة لـ restart لكل الـ instances. ✅ الـ liveness بيقول الـ process عايش بس، والـ readiness هو اللي يقرر ياخد traffic ولا لأ.

❌ A global pool on the edge 
// الغلط: I/O object بين requests مختلفة
let pool;
export default { fetch: () => (pool ??= connect()).query("...") };
✅ Per request, behind an adapter 
// الصح: connection لكل request أو pooling service
export default { fetch: (req, env) => handle(req, connect(env)) };
بالعامية

❌ الـ global pool بيقع بـ Cannot perform I/O on behalf of a different request، زي ما شفت في الـ output. ✅ افتح connection لكل request أو استخدم pooling service، وخلّي الكود ورا adapter.

❌ Vendor SDK in a route 
// الغلط: الـ business logic مربوط بالـ platform
import { kv } from "@vercel/kv";
export const read = (id: string) => kv.get(id);
✅ A port, with the SDK in an adapter 
// الصح: الـ route بيعرف الـ interface بس
export const read = (store: OrderStore, id: string) => store.get(id);
بالعامية

❌ الـ vendor SDK جوه الـ routes معناه إن كل ملف لازم يتغيّر لما تنقل. ✅ الـ route بيتكلم مع OrderStore، والـ SDK يتحط في ملف واحد تحت src/adapters.

import { X509Certificate } from "node:crypto";

export function exitCodeFor(pem, now = Date.now(), minDays = 14) {
  const left = (new Date(new X509Certificate(pem).validTo).getTime() - now) / 86_400_000;
  console.log(`days left: ${left.toFixed(1)}`);
  return left < minDays ? 1 : 0;
}

Cheat sheet · الخلاصة

  • The platform contract: install from the lockfile, build, start on an injected PORT, answer a health path, log to stdout.
  • Scope variables per environment and keep production secrets away from previews.
  • Build-time values are copied into the bundle. NEXT_PUBLIC_ is public and frozen at build.
  • Validate env at boot and exit 1, so the platform keeps the old version running.
  • Liveness never touches the DB. Readiness may. One JSON object per log line, with a request ID.
  • Public certificates: 200 days now, 100 from 2027-03-15, 47 from 2029-03-15. Automate renewal and monitor the live endpoint.
  • At list price, AWS isn't automatically cheaper. Memory-heavy shapes, compliance and networking are what move the decision.
  • Edge: node:fs is virtual with nodejs_compat. Docs say on by default from 2026-08-04; the local 4.20260730 build still needs the flag.
  • I/O objects are per request on Workers, so there is no global pool. CPU limits aren't enforced locally.
  • Keep a working Dockerfile and vendor SDKs under src/adapters, enforced by a script.
  • Data is the hard part of leaving: export regularly and test the restore.
بالعامية
  • عقد الـ platform: install من الـ lockfile، و build، و start على PORT محقون، ورد على health path، و logs على stdout.
  • المتغيرات ليها scope لكل environment، وخلّي secrets الـ production بعيد عن الـ previews.
  • قيم الـ build-time بتتنسخ في الـ bundle. و NEXT_PUBLIC_ عام ومتجمّد وقت الـ build.
  • اعمل validate للـ env وقت الـ boot و exit 1، عشان الـ platform تفضل على النسخة القديمة.
  • الـ liveness عمره ما يلمس الـ DB، والـ readiness ممكن. و JSON object واحد لكل سطر log مع request ID.
  • الشهادات العامة: 200 يوم دلوقتي، و 100 من 2027-03-15، و 47 من 2029-03-15. خلّي التجديد أوتوماتيك وراقب الـ endpoint الحقيقي.
  • بالسعر المعلن AWS مش أرخص أوتوماتيك. الـ workloads اللي بتاكل memory والامتثال والشبكات هم اللي بيغيّروا القرار.
  • الـ edge: node:fs افتراضي مع nodejs_compat. الـ docs بتقول default من 2026-08-04، والنسخة المحلية 4.20260730 لسه محتاجة الـ flag.
