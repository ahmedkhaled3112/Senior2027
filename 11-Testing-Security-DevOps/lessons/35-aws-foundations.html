Why this matters · ليه ده مهم

English

Most Node services in the Gulf and European job market end up on AWS, and a Mid-level developer who only knows docker push cannot answer "why is the database public?", "who pays for this NAT gateway?" or "why did the deploy lose a whole AZ?". You do not need to be a cloud architect. You need a working map: where things live, who patches what, how a request reaches your container, how your code gets permissions, and how to read the invoice. Those five questions come up in code review, in incidents and in system design interviews.

بالعامية

معظم شغل Node في الخليج وأوروبا بيخلص على AWS، والـ Mid اللي كل اللي يعرفه docker push مش هيعرف يرد على "الـ database ليه public؟" أو "مين بيدفع الـ NAT gateway ده؟" أو "الـ deploy ضيّع AZ كامل ليه؟". إنت مش محتاج تبقى cloud architect. إنت محتاج خريطة شغالة: الحاجات قاعدة فين، مين بيعمل patch لإيه، الـ request بيوصل لـ container بتاعك إزاي، الكود بياخد permissions منين، وإزاي تقرا الفاتورة. الخمس أسئلة دول بيطلعوا في الـ code review وفي الـ incidents وفي interviews الـ system design.

Part 1 — The mental model 🟢 Basicالجزء 1 — الصورة الذهنية: regions و AZs ومين مسؤول عن إيه

English

A Region is a separate geographic area such as us-east-1. An Availability Zone is one or more data centres inside a Region with independent power and networking, linked to the other AZs by low-latency connections. Almost everything you create is scoped to one of those: an EC2 instance and a subnet live in one AZ, a VPC and an S3 bucket live in one Region, and IAM is global. AZ names are per account, so your us-east-1a may be a different building from a colleague's; AZ IDs such as use1-az1 are the stable form when two accounts must line up.

You pick a Region by four things: latency to your users, data-residency law, price (the same instance costs different amounts in different Regions) and whether the service you need exists there.

Managed vs self-managed is about who carries the operational work. AWS's shared responsibility model splits it: AWS is responsible for security of the cloud (hardware, facilities, the managed service's internals), you are responsible for security in the cloud (your data, your IAM, your network rules, your application). The further up you move, EC2 to Fargate to Lambda, the more of the middle moves to AWS, but your code, your data and your permissions never do.

Availability arithmetic is where AZs earn their cost. The EC2 SLA itself states two numbers: 99.5% for a single instance and 99.99% for instances spread across two or more AZs. The naive formula says two 99.9% AZs give 99.9999%. That formula assumes failures are independent, and they are not: a bad deploy, a wrong config or a dependency outage takes out both AZs at once. The script below adds that correlated share. The nines method itself is in section 10 · availability and latency.

// حساب: الـ availability بتاعة AZ واحدة ضد اتنين، ومعاها الفشل المشترك
const HOURS_PER_YEAR = 8760;

const downtime = (availability: number) => {
  const hours = (1 - availability) * HOURS_PER_YEAR;
  return hours >= 1 ? `${hours.toFixed(2)} h/yr` : `${(hours * 60).toFixed(1)} min/yr`;
};

// التوازي: كل الـ replicas لازم يقعوا عشان الـ tier يقع، بافتراض إن الفشل مستقل
const parallel = (a: number, n: number) => 1 - (1 - a) ** n;

// الفشل المشترك: نسبة c من الأعطال بتضرب الـ AZs كلها مع بعض (deploy بايظ، config غلط، مشكلة في الـ region)
const parallelCorrelated = (a: number, n: number, c: number) => {
  const u = 1 - a;
  return 1 - (u * c + (u * (1 - c)) ** n);
};

// السلسلة: الـ request بيعدّي على كل الطبقات، فالأرقام بتتضرب في بعض
const serial = (...tiers: number[]) => tiers.reduce((x, y) => x * y, 1);

const app = 0.999;
const lines: [string, number][] = [
  ["1 AZ, app tier", app],
  ["2 AZs, independent", parallel(app, 2)],
  ["2 AZs, 10% correlated", parallelCorrelated(app, 2, 0.1)],
  ["3 AZs, 10% correlated", parallelCorrelated(app, 3, 0.1)],
];
for (const [name, a] of lines) {
  console.log(`${name.padEnd(24)} ${(a * 100).toFixed(4).padStart(9)}%   ${downtime(a)}`);
}

// المسار كله: ALB، بعدين الـ app، بعدين الـ DB
const lb = 0.9999;
const db = 0.9995;
const oneAz = serial(lb, app, db);
const twoAz = serial(lb, parallelCorrelated(app, 2, 0.1), db);
console.log(`\nwhole path, 1 AZ app:   ${(oneAz * 100).toFixed(4)}%   ${downtime(oneAz)}`);
console.log(`whole path, 2 AZ app:   ${(twoAz * 100).toFixed(4)}%   ${downtime(twoAz)}`);

بالعامية

الـ Region منطقة جغرافية منفصلة زي us-east-1. الـ AZ واحد أو أكتر من الـ data centers جوه الـ Region، كهربته وشبكته مستقلين، ومتوصل بباقي الـ AZs بوصلات latency قليلة. تقريبًا كل حاجة بتتعمل مربوطة بواحد منهم: الـ EC2 instance والـ subnet في AZ واحد، الـ VPC والـ S3 bucket في Region واحد، والـ IAM global. خلي بالك إن أسماء الـ AZs خاصة بكل account، فـ us-east-1a بتاعتك ممكن تبقى مبنى تاني غير بتاع زميلك، ولو حسابين لازم يتظبطوا على نفس المكان استخدم الـ AZ ID زي use1-az1.

بتختار الـ Region بأربع حاجات: الـ latency للـ users، قوانين مكان تخزين الـ data، السعر (نفس الـ instance سعرها بيختلف من Region لـ Region)، وهل الخدمة اللي محتاجها موجودة هناك أصلًا.

Managed ضد self-managed معناها مين شايل الشغل التشغيلي. الـ shared responsibility model بتاع AWS بيقسمها: AWS مسؤولة عن أمان الـ cloud نفسه (الـ hardware، المباني، جوه الخدمة الـ managed)، وإنت مسؤول عن الأمان جوه الـ cloud (الـ data بتاعتك، الـ IAM، قواعد الشبكة، الـ application). كل ما تطلع لفوق من EC2 لـ Fargate لـ Lambda، الجزء اللي في النص بيروح لـ AWS، بس الكود والـ data والـ permissions عمرهم ما بيروحوا.

حساب الـ availability هو اللي بيبرر سعر الـ AZs. الـ SLA بتاع EC2 نفسه فيه رقمين: 99.5% للـ instance الواحدة و 99.99% للـ instances الموزعة على AZ اتنين أو أكتر. المعادلة الساذجة بتقول إن AZ اتنين بـ 99.9% يدوا 99.9999%. المعادلة دي بتفترض إن الأعطال مستقلة، وهي مش مستقلة: deploy بايظ أو config غلط أو dependency وقعت بيوقعوا الاتنين مع بعض. السكريبت فوق ضاف النسبة المشتركة دي. طريقة حساب الـ nines نفسها في القسم 10 · الـ availability والـ latency.

فين هستخدمه في شغلي؟ لما الـ PM يقول "عايزين 99.99%": بتحسب المسار كله (ALB × app × DB) بدل ما تعد AZs. ولو زميلك اقترح يوفّر فلوس ويشغّل Postgres على EC2، بتحط عدد الساعات والسعر في نفس الجدول، والقرار يبقى بأرقام مش بالإحساس. الغلطة الشائعة: تضيف AZ تالتة وإنت أصلًا بتوقع من deploy بايظ، والأرخص والأنفع هنا canary و rollback سريع.
Interview question "Each AZ gives 99.9%. Does deploying to two AZs give 99.9999%?" → Only if failures are independent. Deploys, configs and shared dependencies are correlated, so with even 10% correlation you land near 99.99%, and a third AZ barely moves it. Reduce the correlated share first: safe rollouts, independent dependencies, tested failover.
"كل AZ بتدي 99.9%. لو نشرت على اتنين هاخد 99.9999%؟" ← بس لو الأعطال مستقلة. الـ deploys والـ configs والـ dependencies المشتركة بتقع مع بعض، فحتى بـ 10% ارتباط هتيجي عند 99.99% تقريبًا، و AZ تالتة بالكاد بتغيّر الرقم. قلّل الجزء المشترك الأول: rollouts آمنة، dependencies مستقلة، و failover متجرّب.

Part 2 — Compute, one sentence each 🟢 Basicالجزء 2 — الـ compute في جملة لكل خدمة

English
  • EC2 is a virtual machine: you choose the size and own everything from the OS up.
  • ECS on Fargate runs your container image with no servers to see: you declare CPU, memory and a role per task.
  • Lambda runs a function per event and bills per request and per millisecond: one invocation is capped at 15 minutes.
  • EKS is a managed Kubernetes control plane: you still run nodes (or Fargate) and you still own Kubernetes upgrades and add-ons.

All four can run the same orders-api. What changes is the wrapper around it. If the business logic knows nothing about the host, moving between them is a config change plus a thin adapter. The real example below puts one createOrder behind an Express route and behind a Lambda-shaped handler, and proves that both give identical responses.

Not run here: no AWS account, and aws, kubectl are not installed. The ECS and Lambda JSON were checked against the AWS SDK's own input types, the Deployment against the Kubernetes schema. user-data.sh was not executed.

// قلب الـ service: مفيهوش Express ولا Lambda، بياخد input ويرجّع نتيجة
export type Order = { id: string; userId: string; totalCents: number; status: "pending" };
export type Result =
  | { status: 201; body: Order }
  | { status: 400; body: { error: string } };

type Line = { sku: string; qty: number; unitCents: number };

const isLine = (l: unknown): l is Line => {
  if (typeof l !== "object" || l === null) return false;
  const { sku, qty, unitCents } = l as Record<string, unknown>;
  return typeof sku === "string" && Number.isInteger(qty) && (qty as number) > 0
    && Number.isInteger(unitCents) && (unitCents as number) >= 0;
};

export function createOrder(input: unknown, newId: () => string): Result {
  if (typeof input !== "object" || input === null) {
    return { status: 400, body: { error: "body must be a JSON object" } };
  }
  const { userId, items } = input as Record<string, unknown>;
  if (typeof userId !== "string" || userId === "") {
    return { status: 400, body: { error: "userId is required" } };
  }
  if (!Array.isArray(items) || items.length === 0 || !items.every(isLine)) {
    return { status: 400, body: { error: "items must be a non-empty list of lines" } };
  }
  const totalCents = items.reduce((sum, l) => sum + l.qty * l.unitCents, 0);
  return { status: 201, body: { id: newId(), userId, totalCents, status: "pending" } };
}

Part 3 — Data services 🟢 Basicالجزء 3 — خدمات الـ data

English
  • RDS is managed Postgres (or MySQL and others): AWS handles patching, backups and failover, you connect with the normal pg driver.
  • ElastiCache is managed Redis or Valkey. Valkey is the open-source fork, and on the price list a cache.m7g.large node costs $0.1264 per hour on Valkey against $0.158 on Redis, 20% less. Your ioredis code stays the same.
  • S3 is object storage: keys and whole-object writes, not a filesystem and not a place for partial updates.
  • SQS is a queue: one consumer takes each message, and you delete it when you are done. SNS is pub/sub: one publish, many subscribers. They are commonly combined as SNS into several SQS queues.

The SDK is v3: one small client per service, one command object per call. That design makes it easy to test: aws-sdk-client-mock replaces the client's send, so the real logic runs with no network. Below, archiveInvoice writes a PDF then publishes an event, and the tests also pin down what breaks: if SQS fails after S3 succeeded, the object is orphaned and no event exists.

A presigned URL lets a browser fetch or upload one object directly, without your credentials and without the bytes passing through your API. The signature is a local HMAC calculation, which is why it works offline here with fake keys. Whoever holds the URL can use it until it expires, so treat it as a short-lived bearer token. Two limits matter: SigV4 presigned URLs last at most 7 days, and if the URL was signed with temporary role credentials it dies when those credentials expire, even if you asked for longer.

English

A VPC is your private network with a CIDR range. It is divided into subnets, each in one AZ. A subnet is public if its route table sends 0.0.0.0/0 to an internet gateway, and private if it does not; nothing else makes it so. A security group is a stateful firewall attached to a network interface: allow the inbound side and the reply is allowed automatically. Its best feature is that a rule can reference another security group instead of an IP range, so "port 5432 only from the app's group" keeps working as tasks come and go.

Route 53 is DNS. CloudFront is the CDN at the edge, with TLS and caching. The ALB is a layer-7 load balancer that sits in public subnets and forwards to private targets. Read the diagram top to bottom as a single request: the public surface is only DNS, the CDN and the load balancer.

// الحساب: بنحوّل الـ IPv4 لرقم 32-bit ونشتغل بالـ bits
const toInt = (ip: string) => {
  const parts = ip.split(".").map(Number);
  if (parts.length !== 4 || parts.some((p) => !Number.isInteger(p) || p < 0 || p > 255)) {
    throw new Error(`bad IPv4: ${ip}`);
  }
  return parts.reduce((acc, p) => acc * 256 + p, 0);
};
const toIp = (n: number) => [n / 2 ** 24, n / 2 ** 16, n / 2 ** 8, n].map((x) => Math.floor(x) % 256).join(".");

export type Subnet = { name: string; cidr: string; first: string; last: string; usable: number };

// الـ 5 عناوين: AWS بتحجز أول 4 وآخر عنوان في كل subnet
const AWS_RESERVED = 5;

export function splitVpc(vpcCidr: string, azs: string[], tiers: string[]): Subnet[] {
  const [ip, prefixText] = vpcCidr.split("/");
  const prefix = Number(prefixText);
  const base = toInt(ip!);
  if (base % 2 ** (32 - prefix) !== 0) throw new Error(`${vpcCidr}: host bits are set`);

  // العدد: 3 AZ في 3 tiers يبقوا 9 subnets، يعني محتاجين 4 bits (16 مكان)
  const needed = azs.length * tiers.length;
  const extraBits = Math.ceil(Math.log2(needed));
  const newPrefix = prefix + extraBits;
  if (newPrefix > 28) throw new Error(`/${newPrefix} is smaller than the AWS minimum of /28`);

  const size = 2 ** (32 - newPrefix);
  const out: Subnet[] = [];
  let index = 0;
  for (const tier of tiers) {
    for (const az of azs) {
      const start = base + index * size;
      out.push({
        name: `${tier}-${az}`,
        cidr: `${toIp(start)}/${newPrefix}`,
        first: toIp(start + 4),
        last: toIp(start + size - 2),
        usable: size - AWS_RESERVED,
      });
      index++;
    }
  }
  return out;

Part 5 — IAM: the app takes a role 🟢 Basicالجزء 5 — IAM: الـ app بياخد role

English

A user is a long-lived identity with permanent credentials, for a human or a legacy system. A role has no permanent credentials: something assumes it and receives temporary ones. A policy is a JSON document of statements: Effect, Action, Resource, optionally Condition. Applications should always run with a role: an ECS task role, a Lambda execution role, an EC2 instance profile or an EKS pod identity. No access key is created, so none can leak from a repo, an image layer or a log, and the temporary credentials rotate themselves.

Evaluation has one rule that decides most questions: everything starts as denied, an Allow can open it, and any explicit Deny wins over every allow. The stand-in below shows that on sample policies. It is labelled as a stand-in because real IAM also evaluates conditions, resource policies, permission boundaries, session policies and organisation SCPs.

The SDK finds credentials through a chain and stops at the first source that works: environment variables, then SSO and shared config files, then a credential process, a web identity token, the container endpoint and finally the instance metadata service. The script runs that real chain in three isolated processes with fake values and metadata turned off.

// بديل تعليمي: مش الـ IAM الحقيقي. مفيهوش Conditions ولا SCPs ولا permission boundaries ولا resource policies
type Statement = { Sid: string; Effect: "Allow" | "Deny"; Action: string[]; Resource: string[] };
type Policy = { Statement: Statement[] };

const matches = (pattern: string, value: string) =>
  new RegExp("^" + pattern.split("*").map((p) => p.replace(/[.+?^${}()|[\]\\]/g, "\\$&")).join(".*") + "$").test(value);

const applies = (s: Statement, action: string, resource: string) =>
  s.Action.some((a) => matches(a, action)) && s.Resource.some((r) => matches(r, resource));

export function evaluate(policies: Policy[], action: string, resource: string) {
  const hits = policies.flatMap((p) => p.Statement).filter((s) => applies(s, action, resource));
  // الترتيب: أي Deny بيكسب، وبعده أي Allow، ولو مفيش حاجة يبقى implicit deny
  const deny = hits.find((s) => s.Effect === "Deny");
  if (deny) return { decision: "DENY (explicit)", by: deny.Sid };
  const allow = hits.find((s) => s.Effect === "Allow");
  if (allow) return { decision: "ALLOW", by: allow.Sid };
  return { decision: "DENY (implicit)", by: "-" };
}

Part 6 — Console vs CLI vs IaC 🟢 Basicالجزء 6 — الـ console ضد الـ CLI ضد الـ IaC

English

The same bucket can be made three ways, and the difference is what you are left with afterwards. The console is the best way to explore and the worst way to reproduce: nothing records what you clicked, and nobody reviews it. The CLI gives you a script you can read and re-run, but it describes steps and not an end state, so running it twice fails or does something different. Infrastructure as code describes the end state: a tool compares desired with actual and shows a plan, the change goes through a pull request, and the same file builds staging and production.

A practical rule: use the console to look and to learn, use the CLI for one-off questions and break-glass work, and let everything that must exist tomorrow go through IaC. Part 7 — Reading the bill 🟢 Basicالجزء 7 — قراية الفاتورة

English

The first thing to do in any new account, before running anything, is to create a budget alert: AWS Budgets notifies you when actual or forecast spend crosses a threshold. Billing data can lag behind usage by hours, so an alert is a safety net and not a hard stop. Budgets do not shut anything down unless you configure budget actions.

Then learn to read Cost Explorer: group by service, compare two months, and look at the top three lines and the biggest mover. A line named EC2-Other confuses everybody the first time. It holds NAT gateways, EBS volumes and some data transfer, so when it jumps you group by usage type next.

Free-tier terms changed in 2025. The current AWS pages describe a new customer getting $100 in credits at sign-up, with up to $100 more earned through activities, and a choice between a Free plan (ends after six months or when the credits run out, with no charges unless you upgrade) and a Paid plan. More than 30 services keep an always-free monthly allowance. Older blog posts about a 12-month free tier describe the previous model, so read the current Free Tier page before trusting any article. This lesson creates no account.

Sample data, invented for this lesson. The CSV is shaped like a Cost Explorer download. Check the header of your own export, since the format is not a stable API.
الـ data عينة متألفة للدرس. الـ CSV بشكل ملف Cost Explorer، بس راجع الـ header في ملفك إنت لأن الشكل مش API ثابت.
import { readFileSync } from "node:fs";

// الملف عينة من تأليفنا بشكل تصدير Cost Explorer. راجع شكل الـ header في ملفك إنت
const csv = readFileSync(new URL("./sample-cost-explorer.csv", import.meta.url), "utf8").trim();
const [header, ...rows] = csv.split(/\r?\n/).map((l) => l.split(","));

const services = header!.slice(1).filter((h) => h !== "Total costs($)").map((h) => h.replace("($)", ""));
const months = rows
  .filter((r) => /^\d{4}-\d{2}-\d{2}$/.test(r[0]!))
  .map((r) => ({ month: r[0]!.slice(0, 7), cost: Object.fromEntries(services.map((s, i) => [s, Number(r[i + 1])])) }))
  .sort((a, b) => a.month.localeCompare(b.month));

const last = months.at(-1)!;
const prev = months.at(-2)!;
const total = (m: typeof last) => Object.values(m.cost).reduce((a, b) => a + b, 0);

const lines = services.map((s) => {
  const now = last.cost[s]!;
  const before = prev.cost[s]!;
  return { s, now, delta: now - before, pct: before === 0 ? Infinity : ((now - before) / before) * 100 };
});

console.log(`${last.month} total: $${total(last).toFixed(2)} (${prev.month}: $${total(prev).toFixed(2)}, ${(((total(last) - total(prev)) / total(prev)) * 100).toFixed(1)}%)\n`);
console.log("top 3 services by spend:");
for (const l of [...lines].sort((a, b) => b.now - a.now).slice(0, 3)) {
  console.log(` ${l.s.padEnd(40)} $${l.now.toFixed(2).padStart(8)}  ${((l.now / total(last)) * 100).toFixed(1).padStart(5)}%`);
}
console.log("\nbiggest month-over-month movers:");
for (const l of [...lines].sort((a, b) => b.delta - a.delta).slice(0, 3)) {
  console.log(` ${l.s.padEnd(40)} +$${l.delta.toFixed(2).padStart(7)}  ${l.pct.toFixed(1).padStart(5)}%`);
}

بالعامية

أول حاجة تعملها في أي account جديد، قبل ما تشغّل أي حاجة، هي budget alert: الـ AWS Budgets بيبعتلك لما الصرف الفعلي أو المتوقع يعدّي حد معين. بيانات الفاتورة ممكن تتأخر ساعات عن الاستخدام، فالـ alert شبكة أمان مش فرملة. والـ Budgets مش بتقفل حاجة لوحدها إلا لو ظبطت budget actions.

بعدها اتعلم تقرا الـ Cost Explorer: group by service، قارن شهرين، وبص على أكبر 3 بنود وأكبر حاجة زادت. البند اللي اسمه EC2-Other بيلخبط أي حد أول مرة. جواه الـ NAT gateways و EBS volumes وجزء من الـ data transfer، فلما يزيد الخطوة الجاية إنك تعمل group by usage type.

شروط الـ free tier اتغيرت في 2025. صفحات AWS الحالية بتقول إن الـ customer الجديد بياخد 100 دولار credits عند التسجيل، ويقدر يكسب لحد 100 دولار كمان بأنشطة، وبيختار بين Free plan (بيخلص بعد 6 شهور أو لما الـ credits تخلص، ومفيش فلوس إلا لو عملت upgrade) و Paid plan. وأكتر من 30 خدمة ليها حد مجاني شهري دايم. المقالات القديمة اللي بتتكلم عن free tier لمدة 12 شهر بتوصف النظام القديم، فاقرا صفحة الـ Free Tier الحالية قبل ما تصدق أي مقال. الدرس ده مش بيعمل أي account.

فين هستخدمه في شغلي؟ آخر الشهر تفتح الـ billing dashboard وتشوف أكبر 3 بنود، وتحط alert عند 80% من الميزانية. لو الفاتورة قفزت من غير traffic زيادة، أول مشتبه فيه EC2-Other (NAT) و CloudWatch logs. الغلطة الشائعة: حد يعمل account تجربة ويسيب RDS شغال، وأول مرة يعرف لما الفاتورة توصل.

// الـ deploy بيضاعف العدد، فأقصى عدد tasks ثابت في الـ AZ

Cheat sheet · الخلاصة

  • Region contains AZs. Subnets and instances are per AZ, VPCs and buckets per Region, IAM global.
  • Two AZs help only against independent failures: correlated failures decide the real number.
  • Count engineer hours when comparing managed with self-managed.
  • EC2 = VM, Fargate = containers with no servers, Lambda = function per event (15 min per invocation), EKS = managed Kubernetes control plane.
  • Keep the logic host-free: Express and Lambda should be thin adapters.
  • S3 presigned URL: short-lived bearer token, at most 7 days, shorter with role credentials.
  • Public subnet = route to an internet gateway. Security groups are stateful and can reference each other.
  • Each subnet loses 5 addresses. Allowed sizes run from /28 to /16.
  • Apps use roles, not access keys. Explicit deny beats allow beats implicit deny.
  • Console to look, CLI for one-offs, IaC for anything that persists.
  • Budget alert first. Top 3 lines, biggest mover, then group by usage type. EC2-Other usually hides NAT.
بالعامية
  • الـ Region فيه AZs. الـ subnets والـ instances لكل AZ، والـ VPCs والـ buckets لكل Region، والـ IAM global.
  • الـ AZ التانية بتفيد ضد الأعطال المستقلة بس: الأعطال المشتركة هي اللي بتحدد الرقم الحقيقي.
  • احسب ساعات المهندس وإنت بتقارن managed بـ self-managed.
  • EC2 جهاز افتراضي، Fargate containers من غير servers، Lambda function لكل event (15 دقيقة للـ invocation)، EKS هو Kubernetes control plane managed.
  • خلّي المنطق مش عارف حاجة عن الـ host: Express و Lambda يبقوا adapters خفاف.
  • الـ S3 presigned URL هو bearer token قصير: أقصاه 7 أيام، وأقل مع credentials الـ role.
  • الـ subnet الـ public يعني route لـ internet gateway. الـ security groups stateful وتقدر تشاور على بعض.
  • كل subnet بيخسر 5 عناوين. الأحجام المسموحة من /28 لـ /16.
  • الـ apps بتستخدم roles مش access keys. الـ explicit deny بيكسب الـ allow، والـ allow بيكسب الـ implicit deny.
  • الـ console تبص، الـ CLI للحاجات اللي مرة واحدة، والـ IaC لأي حاجة هتفضل موجودة.
  • الـ budget alert الأول. أكبر 3 بنود، أكبر زيادة، وبعدها group by usage type. EC2-Other غالبًا مخبّي NAT.
