Why this matters · ليه ده مهم

English

Where an object gets created decides what you can test, what you can swap and when bad config blows up. A new StripeClient(process.env.STRIPE_KEY) scattered across five services means a missing key shows up on the first payment instead of at boot. Factories put that decision in one place, and in TypeScript most of them are plain functions. Cloning is the other half: copying a template the wrong way is how one tenant's edit ends up on another tenant's invoice. In interviews, "factory vs constructor vs DI" comes up constantly.

بالعامية

المكان اللي الـ object بيتعمل فيه هو اللي بيحدد تقدر تعمل test لإيه، وتبدّل إيه، وإمتى الـ config الغلط هينفجر. new StripeClient(process.env.STRIPE_KEY) متفرقة على 5 services معناها إن المفتاح الناقص هيبان في أول عملية دفع، مش وقت الـ boot. الـ factories بتحط القرار ده في مكان واحد، وفي TypeScript أغلبها functions عادية. والنص التاني هو الـ cloning: لو نسخت template غلط، تعديل tenant هينزل على فاتورة tenant تاني. وفي الـ interviews سؤال "factory ولا constructor ولا DI" بييجي كتير جدًا.

Part 1 — Factory function 🟢 Basicالجزء 1 — الـ factory function

English

A factory function returns an object, so callers say what they need and never call new on a concrete class. Start with the problem. Three modules each decide which logger to use, and each decides differently. Under NODE_ENV=staging they disagree: checkout and notifier print plain text while billing prints JSON, so your log pipeline parses one of the three.

After the change, createLogger(env) makes the decision once and returns a Logger, and no caller knows that pino exists. A factory also gives you two things a new can't:

  • Closure-private state. lines below can't be reached from outside: it isn't a property at all, so "lines" in prod is false.
  • Async construction. A constructor can't be async and must return the instance synchronously, so await createDbClient(config) is how you hand back a client that's already connected.

That second point moves failure to boot. Invalid config is rejected by the schema before any connection attempt, and an unreachable server fails inside the factory. A plain new pg.Pool with the same bad port constructs happily and fails on your first real request. Reject port 0 and empty strings explicitly: Number("") is 0, and pg treats 0 as unset and uses 5432, so an empty DB_PORT silently points at whatever listens on the default port.

The cost is memory. Methods created inside a factory exist once per object, while class methods live once on the prototype (lesson 02 · 06). At 1M objects with three methods each, this machine measured about 288 bytes per object against about 48. That's irrelevant for a logger you create once, and it matters for a million order rows.

export type Fields = Record<string, unknown>;
export interface Logger {
  info(msg: string, fields?: Fields): void;
  stats(): { lines: number };
}
export type LoggerEnv = { NODE_ENV?: string; LOG_LEVEL?: string };

// القرار في مكان واحد، والـ concrete logger متخبّي عن كل اللي بيستخدمه
export function createLogger(env: LoggerEnv): Logger {
  const write = env.NODE_ENV === "development" ? consoleWriter() : pinoWriter(env.LOG_LEVEL ?? "info");
  // متغير private بجد: مفيش أي طريقة توصله من بره غير stats
  let lines = 0;
  return {
    info(msg, fields = {}) {
      lines++;
      write(msg, fields);
    },
    stats: () => ({ lines }),
  };
}

function consoleWriter() {
  return (msg: string, fields: Fields) => console.log(`INFO ${msg}`, fields);
}

function pinoWriter(level: string) {
  const instance = pino({ level, base: undefined, timestamp: false });
  return (msg: string, fields: Fields) => instance.info(fields, msg);
}

export async function createDbClient(raw: unknown): Promise<DbClient> {
  const config = DbConfig.parse(raw);
  const pool = new pg.Pool({ ...config, max: 5, connectionTimeoutMillis: 2_000 });
  try {
    await pool.query("select 1");
  } catch (cause) {
    await pool.end();
    throw new Error(`database unreachable at ${config.host}:${config.port}`, { cause });
  }
  return {
    one: async <T>(sql: string) => (await pool.query(sql)).rows[0] as T,
    close: () => pool.end(),
  };
}

بالعامية

الـ factory function هي function بترجع object، فالـ caller بيقول محتاج إيه ومبيعملش new على concrete class. نبدأ بالمشكلة: تلات modules كل واحد بيقرر يستخدم أنهي logger، وكل واحد بيقرر بطريقته. مع NODE_ENV=staging هتلاقيهم مختلفين: الـ checkout والـ notifier نص عادي والـ billing JSON، فالـ log pipeline بيقرا واحد من التلاتة بس.

بعد التغيير، createLogger(env) بتاخد القرار مرة واحدة وبترجع Logger، ومفيش caller يعرف إن pino موجود أصلًا. والـ factory بتديك حاجتين الـ new مبيدهومش:

  • State خاص بجد بالـ closure. lines مفيش حد يوصلها من بره: دي مش property أصلًا، فـ "lines" in prod بترجع false.
  • إنشاء async. الـ constructor مينفعش يبقى async ولازم يرجّع الـ instance على طول، فـ await createDbClient(config) هي الطريقة اللي بترجّعلك client متصل فعلًا.

النقطة التانية بتنقل الفشل لوقت الـ boot. الـ config الغلط بيترفض من الـ schema قبل أي محاولة اتصال، والـ server اللي مش موجود بيوقّع الـ factory نفسها. أما new pg.Pool عادي بنفس الـ port الغلط فبيتعمل من غير مشاكل وبيقع في أول request حقيقي. وارفض الـ port 0 والنص الفاضي صراحةً: Number("") بتساوي 0، وpg بيعتبر 0 كأنها مش موجودة وبيروح لـ 5432، فـ DB_PORT الفاضي بيوصلك من غير ما تحس لأي حاجة سامعة على الـ default port.

التكلفة هي الـ memory. الـ methods اللي بتتعمل جوه factory موجودة مرة لكل object، أما methods الـ class فموجودة مرة واحدة على الـ prototype (درس 02 · 06). مع مليون object وتلات methods لكل واحد، الجهاز ده قاس حوالي 288 byte للـ object قصاد حوالي 48. ده ملوش أي تأثير في logger بتعمله مرة، ومهم جدًا في مليون order row.

فين هستخدمه في شغلي؟ await createDbClient(config) في أول سطور main()، قبل app.listen. لو الـ database مش موجودة أو الـ config ناقص، الـ pod يقع في الـ deploy والـ rollout يقف، بدل ما يعدّي الـ health check ويبدأ يرجّع 500 لأول عميل. ونفس الكلام لـ createLogger(process.env): سطر واحد في الـ composition root، وباقي الـ modules بتاخد Logger.

Interview question "How do you do async initialization for a class, given constructors can't be async?" → A static or standalone async factory: do the I/O first, then construct. const db = await createDbClient(config) means nobody can hold a half-ready object. "بتعمل async initialization لـ class إزاي، والـ constructor مينفعش يبقى async؟" ← async factory، static أو function لوحدها: اعمل الـ I/O الأول وبعدين ابني الـ object. const db = await createDbClient(config) معناها مفيش حد يمسك object نص جاهز. لكن لو بدأت الـ promise جوه الـ constructor وطلّعت ready، كل caller لازم يفتكر يستناها، ولو فشلت ومحدش مستنيها هتبقى unhandled rejection.

Part 2 — Simple Factory, Factory Method, Abstract Factory 🟡 Intermediateالجزء 2 — الـ Simple Factory والـ Factory Method والـ Abstract Factory

English

Three names that get mixed up all the time. The difference is what varies and who decides.

  • Simple Factory isn't one of the GoF 23. It's one function that knows all the variants: createPaymentProvider(kind) with a map.
  • Factory Method is a fixed algorithm with one creation step left open. In GoF form, abstract InvoiceExporter runs the export and a subclass decides createWriter(). The TypeScript form drops the inheritance and passes the factory as a parameter.
  • Abstract Factory creates a family of objects that must match. createUIKit("dark") returns a Button, an Input and a Modal in one theme. The backend version is createCloudKit("local" | "aws"), returning Storage, Queue and Mailer, so a test can't end up with an AWS queue beside local storage.

"Can't mix" needs real proof, and the obvious typing fails. exportOrders<P> taking BlobStorage<P> and JobQueue<P> looks safe, yet mixing a local storage with an AWS queue compiles: TypeScript has two literal candidates for P and unions them into "local" | "aws". The fix is JobQueue<NoInfer<P>>, so that P is inferred from the storage alone and the queue has to match it. Now it's a compile error.

The local kit below ran for real. The AWS kit was compiled against the real @aws-sdk types and not run here, since there's no AWS account on this machine. Each family loads through a dynamic import(), so tests never load the AWS SDK.

type Invoice = { id: string; lines: { sku: string; cents: number }[] };
interface InvoiceWriter {
  row(sku: string, cents: number): void;
  finish(): string;
}

// الـ skeleton ثابت هنا، والـ subclass بتقرر الـ writer
abstract class InvoiceExporter {
  protected abstract createWriter(): InvoiceWriter;
  export(invoice: Invoice): string {
    const writer = this.createWriter();
    for (const line of invoice.lines) writer.row(line.sku, line.cents);
    return writer.finish();
  }
}

class CsvExporter extends InvoiceExporter {
  protected createWriter(): InvoiceWriter {
    const rows = ["sku,cents"];
    return {
      row: (sku, cents) => void rows.push(`${sku},${cents}`),
      finish: () => rows.join("\n"),
    };
  }
}

class JsonExporter extends InvoiceExporter {
  protected createWriter(): InvoiceWriter {
    const rows: { sku: string; cents: number }[] = [];
    return {
      row: (sku, cents) => void rows.push({ sku, cents }),
      finish: () => JSON.stringify(rows),
    };
  }
}

Part 3 — Type-safe factories 🟡 Intermediateالجزء 3 — factories بـ types مظبوطة

English

The usual starting point is create(kind: string): any. The any turns off the compiler for everything downstream, so the typo below passes and crashes at runtime. Three moves fix it:

  • satisfies checks that the map has the right shape while keeping each entry's exact type. Annotating it as Record<string, ProviderFactory> would throw those exact types away.
  • A generic key: create<K extends keyof typeof providers>(kind: K) makes the return type follow the argument. The compile-time tests below prove create("card") is exactly CardProvider, on TS 7.0.2.
  • Exhaustiveness with never: add a provider and forget one switch, and the build breaks at the default branch.

All of that ends at the boundary. A kind from config or req.body is a plain string at runtime, so parse it first. Below, the Zod 4 schema is built from the map's own keys so there's no second list to forget (lesson 03 · 08).

One runtime trap survives all the typing if a raw string reaches the lookup. providers["constructor"] on a plain object finds Object through the prototype chain. Calling that returns {}, so the "is it there?" check passes and you crash later on .charge. Fix it with Object.hasOwn or a Map.

Part 4 — Object literal & Object.create 🟢 Basicالجزء 4 — الـ object literal و Object.create

English

JavaScript's simplest "prototype" needs no pattern. A literal of defaults, copied with spread, is a template. Object.create(orderProto) gives shared behaviour without a class: total exists once, and each order owns only its data. The internals are in lesson 02 · 06; here we only use it.

Object.create(null) makes a dictionary with no prototype at all: "constructor" in {} is true, and on a null-prototype object it's false. That matters when keys come from outside. In the run below, counting a tenant named constructor on a plain object concatenates a string onto the inherited function. For new code a Map is usually better; a null-prototype object suits data that has to stay a plain object.

This is not a toy. Fastify builds each encapsulated plugin scope with const instance = Object.create(old) at fastify/lib/plugin-override.js:38 in 5.12.8. A child scope reads everything from its parent through the prototype chain, and what it adds stays invisible to the parent.

The classic mistake: an array or object on the prototype is shared by every child. a.tags.push("vip") doesn't create anything on a. It mutates the one array everybody sees.

Part 5 — Prototype: cloning 🟡 Intermediateالجزء 5 — الـ Prototype: النسخ

English

The GoF Prototype says: when building an object is expensive, build it once and copy it. Scenario: an invoiceTemplate with tax rules parsed and loaded from Postgres, cloned per tenant with overrides. JavaScript gives you three ways to copy, and each fails differently:

  • structuredClone is deep and handles Date and Set, but drops prototypes: total instanceof Money is false. TypeScript still calls it Money, because the return type is the input type, so copy.total.add(...) compiles and crashes. A function property throws DataCloneError.
  • Spread is shallow. Edit a nested line in the clone and the original changes too.
  • A clone() method copies exactly what your class needs, at every level, and keeps class identity. You write it and you maintain it.

Now let the number decide. For a 1,000-line invoice on this loaded Windows machine: hand-written clone() took about 0.013 ms. Building from already-parsed JSON took about 0.18 ms. Building from Postgres on loopback took about 0.83 ms. structuredClone took about 0.92 ms, slower than querying a local Postgres and rebuilding. Spread took about 0.0001 ms and gave a wrong copy. So "clone instead of build" isn't automatically a win: it pays when construction involves real I/O or heavy parsing, and when the copy is cheaper than that. A remote database adds network latency that this loopback run doesn't have.

import { Money } from "./money.ts";

export type Line = { sku: string; qty: number; unit: Money; taxRate: number };
export type TaxRule = { sku: string; rate: number };

export class Invoice {
  readonly tenant: string;
  readonly issuedAt: Date;
  readonly lines: Line[];
  constructor(tenant: string, issuedAt: Date, lines: Line[]) {
    this.tenant = tenant;
    this.issuedAt = issuedAt;
    this.lines = lines;
  }
  // النسخ على المقاس: عمق حقيقي، والـ classes بتفضل classes
  clone(overrides: { tenant?: string } = {}): Invoice {
    const lines = this.lines.map((line) => ({ ...line, unit: new Money(line.unit.cents) }));
    return new Invoice(overrides.tenant ?? this.tenant, new Date(this.issuedAt), lines);
  }
  total(): Money {
    return this.lines.reduce((sum, l) => sum.add(new Money(l.unit.cents * l.qty)), new Money(0));
  }
}

  return new Invoice(tenant, new Date(0), lines);
}

Part 6 — Choosing 🟡 Intermediateالجزء 6 — تختار إزاي

English

Treat creation as a ladder: start on the lowest rung and climb only when you see the sign for the next step. Three code-review cases show the verdicts:

  • new StripeClient(process.env.STRIPE_KEY) in 5 services. Change it. A missing key passes boot and fails on the first payment (real output below). Use one factory that validates, called once.
  • An AbstractFactory with one family. Delete it. Nothing can mismatch, so there's nothing to protect.
  • A factory wrapping one new. Delete it, unless it validates, hides a choice or does async work.

The practical payoff is at test time. Passing the factory in lets a test swap it for a fake: below, four tests through the real factory took about 157 ms each (a simulated 150 ms network call), and the same four with a fake took about 1 ms or less. The fake also lets you assert that a bad amount never reaches the provider.

Who calls the factory is a separate decision, covered in lesson 06. The mechanical steps for getting from scattered new calls to a factory are in lesson 32.

 1. object literal      data with defaults, no behaviour
        |  same shape built in several places, needs validation or private state

        |  several methods over shared state, instanceof, framework needs it
        v

Interview question "Factory vs constructor vs dependency injection?" → A constructor builds one known type and must return synchronously. A factory decides which type to build, can validate and can be async. DI answers a different question, who supplies the dependency, and a DI container often calls factories. They combine: a factory creates the client once at the composition root, and injection hands it to whoever needs it. Use a plain constructor unless you have a choice to hide, a failure to surface at boot, or async work to do.
"Factory ولا constructor ولا dependency injection؟" ← الـ constructor بيبني نوع واحد معروف ولازم يرجّع synchronously. الـ factory بتقرر أنهي نوع يتبني، وتقدر تعمل validation وتكون async. والـ DI بيجاوب سؤال تاني: مين بيدّي الـ dependency، وكتير الـ DI container بينادي factories. وبيشتغلوا مع بعض: factory بتعمل الـ client مرة في الـ composition root، والـ injection بيوصّله لكل اللي محتاجه. استخدم constructor عادي إلا لو عندك قرار تخبّيه، أو فشل عايزه يظهر وقت الـ boot، أو شغل async.

Common mistakes · غلطات شائعة

❌ Async work started in the constructor 
type Connect = (url: string) => Promise<void>;
// ❌ الشغل الـ async اتساب جوه الـ constructor
export class Db {
  ready: Promise<void>;
  constructor(url: string, connect: Connect) {
    this.ready = connect(url);
  }
}
✅ An async factory 
type Connect = (url: string) => Promise<void>;
export type Db = { url: string };
// ✅ الـ object مبيوصلكش غير وهو جاهز
export async function createDb(url: string, connect: Connect): Promise<Db> {
  await connect(url);
  return { url };
}
بالعامية

❌ الـ object بيتعمل قبل ما يبقى جاهز، وكل caller لازم يفتكر await db.ready. لما جرّبناها بـ connect بيفشل ومحدش مستني، الفشل طلع كـ unhandled rejection، وده في Node بيوقّع الـ process بالـ default. ✅ الـ factory ما بترجّعش غير object جاهز، والـ error بيطلع عند الـ await نفسه ويتمسك في مكانه.

❌ Raw lookup on a plain object 
const factories: Record<string, () => object> = { card: () => ({ kind: "card" }) };
// ❌ مفتاح زي constructor بيلاقي Object
export const create = (kind: string) => {
  const make = factories[kind];
  if (!make) throw new Error(`unknown: ${kind}`);
  return make();
};
✅ A Map, or Object.hasOwn 
const factories = new Map<string, () => object>([["card", () => ({ kind: "card" })]]);
// ✅ مفيش prototype chain في الـ Map
export const create = (kind: string) => {
  const make = factories.get(kind);
  if (!make) throw new Error(`unknown: ${kind}`);
  return make();
};
بالعامية

❌ factories["constructor"] بتلاقي Object، فالـ check بيعدّي والـ factory بترجّع {} (ده اللي طلع لما شغلناها). ✅ الـ Map ملهاش prototype chain في الـ lookup، فـ constructor بترجع undefined وبتترفض. وObject.hasOwn بديل صح لو لازم تفضل object.

❌ Spread as a deep copy 
type Tpl = { tenant: string; lines: { cents: number }[] };
// ❌ الـ lines لسه نفس الـ array بتاعة الـ template
export const forTenant = (t: Tpl, tenant: string): Tpl => ({ ...t, tenant });
✅ Copy every level you change 
type Tpl = { tenant: string; lines: { cents: number }[] };
// ✅ كل مستوى بيتغير ليه نسخته
export const forTenant = (t: Tpl, tenant: string): Tpl => ({
  ...t,
  tenant,
  lines: t.lines.map((line) => ({ ...line })),
});
بالعامية

❌ النسخة والـ template شايلين نفس الـ lines، فلما عدّلنا النسخة الـ template بقت 9. ده بيخلي tenant يأثر على tenant تاني. ✅ كل مستوى هيتعدّل بياخد نسخته، والـ template فضل 1. لو فيه classes استخدم clone() زي الجزء 5.

❌ A factory around new Date() 
// ❌ الـ factory دي مبتخبّيش قرار، والـ test لسه مش متحكم في الوقت
export const createNow = () => new Date();
export const isExpired = (dueAt: Date) => createNow() > dueAt;
✅ Pass the time in 
// ✅ الوقت parameter ليه default، والـ test بيبعت الوقت اللي عايزه
export const isExpired = (dueAt: Date, now = new Date()) => now > dueAt;
بالعامية

❌ createNow مش بتخبّي أي قرار، والـ test لسه مش عارف يتحكم في الوقت، فالتعقيد زاد والمشكلة زي ما هي. ✅ الوقت parameter ليه default: الـ production مش محتاج يبعت حاجة، والـ test بيبعت الوقت اللي عايزه. وفي Vitest فيه كمان vi.setSystemTime.

Try it yourself · جرّب بنفسك

1. A notifier with private state 🟢 easy Write createNotifier(channel) for "email" | "sms". It returns send(to) and sentCount(). The counter must be unreachable from outside: "sent" in notifier has to be false.
اكتب createNotifier(channel) لـ "email" | "sms"، بترجّع send(to) وsentCount(). الـ counter لازم ميتوصلش له من بره: "sent" in notifier لازم تطلع false.
Solution · الحل 
type Channel = "email" | "sms";
type Notifier = { send(to: string): string; sentCount(): number };

// حل التمرين 1: الـ counter جوه الـ closure
const senders: Record<Channel, (to: string) => string> = {
  email: (to) => `email to ${to}`,
  sms: (to) => `sms to ${to}`,
};

export function createNotifier(channel: Channel): Notifier {
  let sent = 0;
  return {
    send(to) {
      sent++;
      return senders[channel](to);
    },
    sentCount: () => sent,
  };
}

const sms = createNotifier("sms");
console.log(sms.send("+201000000000"));
sms.send("+201000000001");
console.log(sms.sentCount(), "sent" in sms);
sms to +201000000000
2 false
بعتنا رسالتين، فالـ count بقى 2، و"sent" in sms طلعت false لأن sent متغير في الـ closure مش property.
2. Add a provider, keep the proof 🟡 medium Build a typed factory with card and bank where only the bank has iban(). Prove the return type with Expect<Equal<…>>, and add an isKind(value: string) guard that rejects "constructor".
ابني typed factory فيها card وbank، والـ bank بس عندها iban(). اثبت نوع الـ return بـ Expect<Equal<…>>، وضيف guard اسمه isKind(value: string) يرفض "constructor".
Solution · الحل 
type CardProvider = { kind: "card"; refund(id: string): string };
type BankProvider = { kind: "bank"; iban(): string };

const providers = {
  card: (): CardProvider => ({ kind: "card", refund: (id) => `refunded ${id}` }),
  bank: (): BankProvider => ({ kind: "bank", iban: () => "EG00" }),
} satisfies Record<string, () => { kind: string }>;

type Kind = keyof typeof providers;

// حل التمرين 2: مرة بالنوع للكود بتاعنا، ومرة وقت الـ runtime للـ input
export function isKind(value: string): value is Kind {
  return Object.hasOwn(providers, value);
}

export function create<K extends Kind>(kind: K): ReturnType<(typeof providers)[K]> {
  return providers[kind]() as ReturnType<(typeof providers)[K]>;
}

type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
const bank = create("bank");
export type Tests = [Expect<Equal<typeof bank, BankProvider>>];

// الدالة دي عمرها ما بتتنادى: الاختبار هنا للـ compiler بس
export function typeOnly() {
  // @ts-expect-error
  bank.refund("ch_1");
}

console.log(bank.iban(), isKind("bank"), isKind("constructor"));
EG00 true false
الـ iban اشتغلت، وisKind("bank") طلعت true، وisKind("constructor") طلعت false. والملف عدّى الـ compile على TS 7.
3. A clone you can trust 🔴 hard Give an Invoice with nested rules and Money lines a clone(tenant) method. Write two tests: a change at any level of the clone leaves the template alone, and instanceof still holds, unlike structuredClone.
ادّي Invoice فيها rules متداخلة وسطور فيها Money method اسمها clone(tenant). اكتب اتنين tests: تعديل أي مستوى في النسخة ميأثرش على الـ template، وinstanceof تفضل صح، عكس structuredClone.
Solution · الحل 
import assert from "node:assert/strict";
import { it } from "node:test";

class Money {
  readonly cents: number;
  constructor(cents: number) {
    this.cents = cents;
  }
}
type Rule = { name: string; rate: number };

// حل التمرين 3: نسخ عميق للـ lines والـ rules، والـ Money بتفضل Money
class Invoice {
  readonly tenant: string;
  readonly rules: Rule[];
  readonly lines: { sku: string; unit: Money }[];
  constructor(tenant: string, rules: Rule[], lines: { sku: string; unit: Money }[]) {
    this.tenant = tenant;
    this.rules = rules;
    this.lines = lines;
  }
  clone(tenant = this.tenant): Invoice {
    return new Invoice(
      tenant,
      this.rules.map((rule) => ({ ...rule })),
      this.lines.map((line) => ({ ...line, unit: new Money(line.unit.cents) })),
    );
  }
}

const template = new Invoice("base", [{ name: "vat", rate: 0.14 }], [{ sku: "plan", unit: new Money(1000) }]);

it("a clone is independent at every level", () => {
  const copy = template.clone("acme");
  copy.rules[0].rate = 0;
  copy.lines[0].sku = "changed";
  assert.equal(template.rules[0].rate, 0.14);
  assert.equal(template.lines[0].sku, "plan");
});

it("keeps class identity, unlike structuredClone", () => {
  assert.ok(template.clone() instanceof Invoice);
  assert.ok(template.clone().lines[0].unit instanceof Money);
  assert.equal(structuredClone(template) instanceof Invoice, false);
});
✔ a clone is independent at every level
✔ keeps class identity, unlike structuredClone
ℹ tests 2
ℹ suites 0
ℹ pass 2
ℹ fail 0
الـ test الأول غيّر الـ rate والـ sku في النسخة واتأكد إن الـ template زي ما هو. والتاني اتأكد إن clone بتحافظ على Invoice وMoney، وإن structuredClone مبتحافظش.

Cheat sheet · الخلاصة

  • A factory function hides the concrete class, allows private state and can be async. A constructor can't.
  • Validate config in the factory so failure happens at boot. pg treats port 0 as unset and uses 5432.
  • Methods in closures cost memory: ≈288 vs ≈48 bytes per object at 1M objects.
  • Simple Factory: one function, N variants. Factory Method: one creation step varies. Abstract Factory: a family that must match.
  • <P> on two arguments unions literals and allows mixing. Use NoInfer<P> on one of them.
  • Typed factory: satisfies + K extends keyof typeof providers. Exhaustiveness: never in default.
  • Parse a kind from outside with Zod. A raw providers["constructor"] finds Object; use Object.hasOwn or a Map.
  • Object.create(null) or Map for keys from outside. Never put arrays on a shared prototype.
  • structuredClone drops classes and throws on functions; spread is shallow; clone() keeps identity.
  • 1,000 lines: clone() ≈0.013 ms, JSON build ≈0.18, Postgres build ≈0.83, structuredClone ≈0.92. Measure before you clone.
  • Ladder: literal, factory function, class, factory map, abstract factory. Climb only on a real sign.
بالعامية
  • الـ factory function بتخبّي الـ concrete class، وبتسمح بـ state خاص، وممكن تبقى async. الـ constructor لأ.
  • اعمل validation للـ config في الـ factory عشان الفشل يحصل وقت الـ boot. وpg بيعتبر port 0 مش موجود وبيروح لـ 5432.
  • الـ methods جوه الـ closures بتكلّف memory: ≈288 قصاد ≈48 byte للـ object مع مليون object.
  • الـ Simple Factory: function واحدة وN نوع. الـ Factory Method: خطوة إنشاء واحدة بتتغير. الـ Abstract Factory: عيلة لازم تتطابق.
  • الـ <P> على اتنين arguments بيعمل union للـ literals وبيسمح بالخلط. استخدم NoInfer<P> على واحد منهم.
  • الـ factory المتأمنة: satisfies مع K extends keyof typeof providers. والـ exhaustiveness: never في الـ default.
  • اعمل parse بـ Zod لأي kind جاي من بره. وproviders["constructor"] الخام بتلاقي Object، فاستخدم Object.hasOwn أو Map.
  • Object.create(null) أو Map للمفاتيح اللي جاية من بره. وعمرك ما تحط arrays على prototype مشترك.
  • structuredClone بترمي الـ classes وبتقع مع الـ functions، والـ spread سطحي، وclone() بتحافظ على الـ class.
  • 1000 سطر: clone() ≈0.013 ms، والبناء من JSON ≈0.18، والبناء من Postgres ≈0.83، وstructuredClone ≈0.92. قيس قبل ما تنسخ.
  • السلم: literal، ثم factory function، ثم class، ثم factory map، ثم abstract factory. واطلع بس لما تشوف إشارة حقيقية.
