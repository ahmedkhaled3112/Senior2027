Why this matters · ليه ده مهم

English

Thirty-four lessons taught you the patterns. This one teaches the skill they exist for: deciding. Seniors are judged less on whether they can write a Circuit Breaker and more on whether they can look at a PR and say, with evidence, "this one is worth it" or "this one isn't". The same judgement is what system-design and code-review interviews probe: why this, what did it cost, what would you have done instead?

Part 1 — Pattern cards 🔴 Advancedالجزء 1 — كروت الـ patterns

English

The README's test is this whole section in one sentence: if you can't state the problem a pattern solves, the cost it adds and the simpler alternative, you haven't learned that pattern. Recognising a name is recall. Judgement is those three facts, applied to the code in front of you today.

Each one is a different question. The problem has to be visible in the current code or in a committed requirement, not in a hypothetical. The cost is what the pattern adds to everything you maintain: more names, more indirection, more places a reader has to jump to. The simpler alternative is what you would write with no pattern at all. In TypeScript that is often very close, because a Strategy can be a Record of functions, so the honest comparison is usually against a function and not against a Java class hierarchy.

The reference below is a 30-card deck in patterns.json: one source for the tables in this lesson and for a quiz. The quiz refuses to count a card unless you give all three facts. Pattern names are matched automatically, including aliases such as "middleware". Cost and alternative are free text, so you read the model answer and grade yourself honestly. A --script mode replays a file of answers, which is how the output below was captured without a terminal. Notice that Ask is just a function type, so the terminal and the script swap with no classes: a Strategy nobody had to name.

لما PR يقول "ضفنا pattern كذا" بتعدّي على 3 أسئلة بالترتيب. الأول: المشكلة: تقدر تشاور عليها في كود النهارده؟ لو لأ، ده YAGNI: ارفضها أو أجّلها. التاني: التكلفة: إيه اللي هنفضل نصونه بسببها؟ لو مش عارف، يبقى لسه ماتعلمتش الـ pattern ده. التالت: البديل الأبسط: النسخة العادية شكلها إيه؟ لو كفاية، سلّم النسخة العادية. ولو النسخة العادية وقفت تنفع فعلًا، ساعتها استخدم الـ pattern واكتب السبب في الـ PR.

الكود ده هو الـ quiz كامل، ومفيش فيه أي dependency غير Node نفسه:
import { readFileSync } from "node:fs";
import path from "node:path";
import { createInterface } from "node:readline/promises";
import { parseArgs } from "node:util";

type Card = {
  id: string;
  name: string;
  aliases: string[];
  family: string;
  lesson: string;
  problem: string;
  cost: string;
  simpler: string;
};

// السؤال مجرد function، فالـ terminal والـ script بيتبدلوا من غير أي class
type Ask = (prompt: string) => Promise<string>;

const cards: Card[] = JSON.parse(
  readFileSync(path.join(import.meta.dirname, "patterns.json"), "utf8"),
);

const { values: opts } = parseArgs({
  options: {
    seed: { type: "string", default: String(Date.now() % 100000) },
    count: { type: "string", default: "5" },
    // ملف JSON فيه الإجابات بالترتيب، عشان الـ output يتسجل من غير terminal
    script: { type: "string" },
    check: { type: "boolean", default: false },
  },
});

// خلط ثابت لنفس الـ seed عشان تقدر تعيد نفس الجولة
function shuffled<T>(items: readonly T[], seed: number): T[] {
  let s = seed >>> 0;
  const rand = () => {
    s = (s + 0x6d2b79f5) >>> 0;
    let t = s;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
  const out = [...items];
  for (let i = out.length - 1; i > 0; i--) {
    const j = Math.floor(rand() * (i + 1));
    [out[i], out[j]] = [out[j]!, out[i]!];
  }
  return out;
}

const norm = (s: string) => s.toLowerCase().replace(/[^a-z]/g, "");
const namesMatch = (card: Card, answer: string) =>
  [card.name, ...card.aliases].some((n) => norm(n) === norm(answer));

// الـ cost والبديل نص حر، فمفيش تصحيح أوتوماتيك: بتقارن بالـ model وتحكم بأمانة
async function round(card: Card, ask: Ask, label: string) {
  console.log(`\n${label} PROBLEM: ${card.problem}`);
  const name = await ask("  pattern?     > ");
  await ask("  cost?        > ");
  await ask("  simpler alt? > ");
  const nameOk = namesMatch(card, name);
  console.log(`  MODEL   ${card.name} (./${card.lesson})`);
  console.log(`  cost    ${card.cost}`);
  console.log(`  simpler ${card.simpler}`);
  const costOk = (await ask("  cost matched? [y/n] > ")) === "y";
  const altOk = (await ask("  alt matched?  [y/n] > ")) === "y";
  const missing = [!nameOk && "pattern", !costOk && "cost", !altOk && "alternative"].filter(
    (m): m is string => Boolean(m),
  );
  return { card, missing };
}

function checkDeck(deck: Card[]): string[] {
  const errors: string[] = [];
  const seen = new Set<string>();
  for (const c of deck) {
    if (seen.has(c.id)) errors.push(`duplicate id: ${c.id}`);
    seen.add(c.id);
    for (const field of ["name", "family", "lesson", "problem", "cost", "simpler"] as const) {
      if (!c[field]?.trim()) errors.push(`${c.id}: empty ${field}`);
    }
  }
  return errors;
}

if (opts.check) {
  const errors = checkDeck(cards);
  console.log(errors.length ? errors.join("\n") : `deck ok: ${cards.length} cards`);
  process.exit(errors.length ? 1 : 0);
}

let ask: Ask;
let close = () => {};
if (opts.script) {
  const answers: string[] = JSON.parse(readFileSync(opts.script, "utf8"));
  ask = async (prompt) => {
    const answer = answers.shift();
    if (answer === undefined) throw new Error("script ran out of answers");
    console.log(prompt + answer);
    return answer;
  };
} else {
  const rl = createInterface({ input: process.stdin, output: process.stdout });
  ask = (prompt) => rl.question(prompt);
  close = () => rl.close();
}

const picked = shuffled(cards, Number(opts.seed)).slice(0, Number(opts.count));
const results = [];
for (const [i, card] of picked.entries()) {
  results.push(await round(card, ask, `[${i + 1}/${picked.length}]`));
}
close();

const complete = results.filter((r) => r.missing.length === 0).length;
console.log(`\nRESULT ${complete}/${results.length} cards complete (pattern + cost + alternative)`);
for (const r of results.filter((x) => x.missing.length > 0)) {
  console.log(`  not learned yet: ${r.card.name} (missing ${r.missing.join(", ")})`);
}

أول سطر معناه إن الـ 30 كارت سليمين. بعد كده 3 جولات: في الأولى جاوبت صح على التلاتة (Visitor) فالكارت اتحسب. في التانية الاسم اتقبل بالـ alias وهو middleware، بس الـ cost كان غلط، فاتسجل missing cost. في التالتة التكلفة والبديل صح، بس الاسم غلط (قلت Circuit Breaker والمشكلة بتاعة Retry)، فاتسجل missing pattern. النتيجة 1 من 3، يعني كارت واحد بس اتعلمته فعلًا.
بالعامية

اختبار الـ README هو القسم ده كله في جملة: لو مش قادر تقول المشكلة اللي الـ pattern بيحلها، والتكلفة اللي بيضيفها، والبديل الأبسط، يبقى لسه ماتعلمتوش. إنك تعرف الاسم ده حفظ. الحكم هو التلات حقايق دول، مطبقين على الكود اللي قدامك النهارده.

كل واحدة سؤال مختلف. المشكلة لازم تكون باينة في الكود الحالي أو في requirement متفق عليه، مش في "يمكن بعدين". التكلفة هي اللي الـ pattern بيزوّده على كل حاجة بتصونها: أسماء أكتر، indirection أكتر، وأماكن أكتر القارئ لازم ينط لها. البديل الأبسط هو اللي كنت هتكتبه من غير أي pattern. وفي TypeScript ده غالبًا قريب جدًا، لأن الـ Strategy ممكن تبقى Record فيه functions، فالمقارنة الأمينة بتبقى قدام function مش قدام class hierarchy بتاعة Java.

المرجع هو patterns.json: 30 كارت، ومصدر واحد للجداول اللي تحت وللـ quiz. الـ quiz مش بيحسب الكارت غير لو جبت التلاتة. اسم الـ pattern بيتقارن أوتوماتيك وبيقبل aliases زي middleware. الـ cost والبديل نص حر، فبتقرا الإجابة النموذجية وتحكم على نفسك بأمانة. ومود --script بيعيد إجابات من ملف، وده اللي خلّى الـ output اللي فوق يتسجل من غير terminal. لاحظ كمان إن Ask مجرد function type، فالـ terminal والـ script بيتبدلوا من غير classes: ده Strategy من غير ما حد يسميه.

فين هستخدمه في شغلي؟ زميل فتح PR فيه NotificationRepository و NotificationService حوالين query واحدة. بدل ما تقول "ده over-engineering"، اسأل التلات أسئلة في الـ comment: المشكلة فين في الكود النهارده؟ هنصون إيه زيادة؟ والنسخة العادية شكلها إيه؟ ولنفسك: كل أسبوع 5 جولات من الـ quiz، وأي كارت يقع منك ارجع لدرسه من الـ link اللي في الجدول. الغلطة الشائعة: تحسب نفسك عارف الـ pattern عشان عرفت اسمه، وده اللي الـ quiz مانعه.

PatternProblemCostSimpler alternative
Factory functionCreating an object needs logic (validation, defaults, picking a concrete type) that every caller would otherwise repeat.One more name to find; a factory that only calls new adds nothing.new or an object literal while construction stays one line.
Abstract FactorySeveral related objects must be swapped together as a family, such as a provider's charger, refunder and webhook verifier.An interface per product plus a factory per family; a new product touches every family.A module of plain functions, until a second family really exists.

  • Factory function: المشكلة: إنشاء الـ object محتاج logic (validation، defaults، اختيار نوع) وكل caller هيكررها. التكلفة: اسم زيادة تدوّر عليه، والـ factory اللي بتنادي new وبس مش بتضيف حاجة. البديل الأبسط: new أو object literal طول ما الإنشاء سطر واحد.
  • Abstract Factory: المشكلة: كذا object مرتبطين لازم يتبدلوا مع بعض كعيلة، زي الـ charger والـ refunder والـ webhook verifier بتوع provider واحد. التكلفة: interface لكل منتج و factory لكل عيلة، وأي منتج جديد بيلمس كل العيلات. البديل الأبسط: module فيه functions عادية لحد ما عيلة تانية تظهر فعلًا.
  • Builder: المشكلة: object فيه أجزاء optional كتير، أو validation على خطوات، أو query بيتبني على كذا branch. التكلفة: class موازية بتكرر الـ fields، و build() بتتنسي، و state نص مبني وقابل للتغيير. البديل الأبسط: object literal بـ options typed و defaults.
  • Singleton: المشكلة: instance واحدة مشتركة لمورد غالي في الـ process، زي الـ connection pool. التكلفة: dependency عالمية مستخبية، والـ state بيسرّب بين الـ tests وبين الـ tenants. البديل الأبسط: تنشئه مرة في الـ composition root وتباصيه.
  • Object Pool: المشكلة: إنشاء المورد بطيء أو ليه حد أقصى، زي DB connections أو sockets أو browser pages. التكلفة: leak لو release اتنسى، وحجم و queue لازم تضبطهم وتراقبهم. البديل الأبسط: الـ pool الجاهز في الـ driver، أو من غير pool لو الإنشاء رخيص.
  • Dependency Injection: المشكلة: الـ class بتنشئ الـ collaborators بتوعها بنفسها، فالـ tests والتبديل محتاجين module mocking. التكلفة: كود wiring، ومع container كمان errors وقت الـ runtime و indirection. البديل الأبسط: تباصي الـ dependencies كـ parameters وتوصّلهم بإيدك في main.ts.

  • State Machine: المشكلة: الـ ifs بتاعة الـ status بتسمح بـ transitions غلط، زي شحن order متلغي. التكلفة: جدول أو library تتعلمها، وأي status جديد محتاج قرار design. البديل الأبسط: UPDATE واحد بشرط لو عندك حالتين أو تلاتة.
  • Observer: المشكلة: event واحد لازم يوصل لكذا listener مستقلين من غير ما المصدر يعرفهم. التكلفة: control flow مستخبي، و listeners بتسرّب، والـ events جوه الـ process بتضيع مع الـ crash. البديل الأبسط: calls مباشرة بالترتيب لو عندك مستقبل أو اتنين معروفين.
  • Chain of Responsibility: المشكلة: الـ request بيعدّي على خطوات مستقلة بترتيب، وأي خطوة ممكن توقفه. التكلفة: bugs في الترتيب، والمسار كله مش باين من ملف واحد. البديل الأبسط: functions بتتنادى ورا بعض جوه الـ handler.
  • Command: المشكلة: عملية لازم تتحط في queue أو تتسجل أو تتعاد أو تترجع كـ data. التكلفة: type لكل action و handlers ومكان تسجّلهم فيه. البديل الأبسط: call مباشر لو محدش محتاج يخزّن العملية.
  • Mediator: المشكلة: components كتير بتكلم بعضها في شبكة n×n. التكلفة: الـ mediator بيبقى god object وبيخبّي الـ flow. البديل الأبسط: callback مباشر لو عندك two components.
  • Visitor: المشكلة: عمليات كتير على مجموعة مقفولة من أنواع الـ nodes في tree. التكلفة: boilerplate للـ double dispatch، وأي node type جديد بيلمس كل visitor. البديل الأبسط: discriminated union و switch exhaustive.
  • Specification: المشكلة: قواعد business بتتركب بـ and/or/not، وبتتستخدم في الـ memory وفي الـ queries. التكلفة: لغة صغيرة تبقى مسؤول عنها، وترجمتها لـ SQL هي الجزء الصعب. البديل الأبسط: predicate functions ليها أسماء، أو WHERE builder.

Part 2 — "We don't need a pattern here" 🔴 Advancedالجزء 2 — "مش محتاجين pattern هنا"

English

Saying no to a pattern is a skill with a format: what the PR adds, the evidence from the code (implementers, call sites, lines), the simpler code already checked against the same tests, and the condition under which you would agree with the pattern. Evidence, not taste. "This is over-engineered" gives the author nothing to act on. "One implementer, one caller, 25 lines become 8, tests still pass" does.

Below are six real diffs. Each has a contract test that runs the same assertions against both the "before" and the "after", so the reduction is proven rather than claimed. Line counts are non-blank, non-comment lines, printed by a script. The six are: Abstract Factory with one family, Repository over one query, Mediator for two components, a plugin system with one plugin, Strategy with one strategy, and Builder for three fields.

The discipline runs in both directions, so after the six come three diffs where the pattern is overdue, each with the signals that show it. The rule that decides either way: count the variation you have today, not the variation you can imagine.

بالعامية

إنك تقول "لأ" لـ pattern مهارة ليها شكل: الـ PR بيضيف إيه، الدليل من الكود (عدد الـ implementers والـ call sites والسطور)، الكود الأبسط متجرّب على نفس الـ tests، والشرط اللي هتوافق عنده على الـ pattern. دليل مش ذوق. جملة "ده over-engineering" مابتدّيش صاحب الـ PR حاجة يعملها، إنما "implementer واحد، و caller واحد، و 25 سطر بقوا 8، والـ tests لسه شغالة" بتدّيله.

تحت 6 diffs حقيقيين، وكل واحد عليه contract test بيشغّل نفس الـ assertions على "قبل" و"بعد"، فالاختصار متثبت مش كلام. السطور محسوبة من غير الفاضية والـ comments، وطالعة من script. الستة هما: Abstract Factory بعيلة واحدة، و Repository على query واحدة، و Mediator لـ two components، و plugin system بـ plugin واحد، و Strategy بـ strategy واحدة، و Builder لـ 3 fields.

الموضوع في الاتجاهين، فبعد الستة فيه 3 diffs الـ pattern فيهم اتأخر، ومع كل واحد العلامات اللي بتبيّن ده. القاعدة اللي بتحسم في الحالتين: عدّ الـ variation اللي عندك النهارده، مش اللي تقدر تتخيله.

فين هستخدمه في شغلي؟ في أي code review: قبل ما تكتب الـ comment، اعمل checkout للـ branch، طبّق النسخة الأبسط، وشغّل الـ tests. لما تكتب "جربت ده، 14 سطر بدل 35 والـ tests خضرا" الرد بيبقى مناقشة مش خناقة. الغلطة الشائعة: تعلّق على شكل الكود من غير ما تجرب البديل، فصاحب الـ PR يرد بـ "وإنت عرفت منين؟" وعنده حق.

    return this;

    return (this.#hooks.get(hook) ?? []).reduce((inv, fn) => fn(inv), invoice);
  }
}

Trade-off: rejecting abstraction by reflex is its own golden hammer "No patterns" can become as lazy as "patterns everywhere". If you answer every PR with YAGNI, you ship the three "before" files above: silent zero fees, retries on expired cards, shipped cancelled orders. The goal is the cheapest code that handles today's variation, sometimes that is a pattern.
"مفيش patterns" ممكن تبقى كسل زي "patterns في كل حتة". لو كل PR بترد عليه بـ YAGNI، هتسلّم ملفات "قبل" التلاتة اللي فوق: رسوم صفر من غير صوت، و retry على كروت منتهية، و orders متلغية بتتشحن. الهدف هو أرخص كود يتعامل مع الـ variation بتاع النهارده، وساعات ده بيبقى pattern.
Interview question "Your colleague added an interface with one implementation 'in case we need it'. What's your response?" → Ask what varies today. A vendor boundary or a seam for a test fake is a reason to keep it; "in case" isn't. Otherwise inline it, because extracting an interface later is a mechanical refactor and TypeScript finds every call site. See lesson 30.

When names misleadلما الأسماء تضحك عليك

English

Frameworks reuse pattern names for different things, so a shared word can hide a real disagreement. Fastify's decorate() adds a property to the instance; it wraps nothing. React's Hooks are per-component state slots read by call order; the Hooks pattern is named extension points in a fixed flow, like Git hooks or tapable. Nest's interceptors are around-advice over the handler, closest to a Decorator on the route, with an RxJS stream as the return value. The run below proves the Fastify case.

Part 4 — Audit your codebase 🔴 Advancedالجزء 4 — راجع الـ codebase بتاعك

English

The README's last item asks what repeats in your codebase today, what is missing and what is excess. You cannot answer that from memory, so build a small tool that gathers facts. pattern-audit.ts uses the TypeScript compiler API: ts.createSourceFile parses one file to an AST with no type-checking and no tsconfig, so it is fast and also works on plain JS. It uses TS 6.0.3 on purpose. On this machine require("typescript") fails with MODULE_NOT_FOUND on TS 7.0.2, while 6.0.3 exposes createSourceFile.

Six detectors: a repeated switch on one discriminant (matched by the last property name, so order.paymentMethod and o.paymentMethod count together), interfaces with one implementer, classes with one public method, SDK imports outside adapter folders, functions with more than four parameters, and mutable module-level state. The last rule ignores a const that is never mutated, so a read-only lookup map is not reported.

Every finding is a question, not a verdict, and the tool prints the question next to each group. Because it reads syntax only, it matches by name: it cannot tell that two interfaces in different folders with the same name are different, and it does not see implementers it isn't pointed at. function discriminant(e: ts.Expression): string | undefined {
  if (ts.isPropertyAccessExpression(e)) return e.name.text;

const MUTATORS = new Set(["push", "pop", "shift", "unshift", "splice", "set", "add", "delete", "clear"]);

// بنجمع أسماء اللي بيتغيروا فعلًا، عشان الـ const المقروءة بس متتحسبش
function mutatedNames(sf: ts.SourceFile): Set<string> {
  const names = new Set<string>();
  const visit = (n: ts.Node): void => {
    if (ts.isCallExpression(n) && ts.isPropertyAccessExpression(n.expression)) {
      const target = n.expression.expression;
      if (ts.isIdentifier(target) && MUTATORS.has(n.expression.name.text)) names.add(target.text);
    }
    if (
      ts.isBinaryExpression(n) &&
      n.operatorToken.kind === ts.SyntaxKind.EqualsToken &&
      (ts.isPropertyAccessExpression(n.left) || ts.isElementAccessExpression(n.left)) &&
      ts.isIdentifier(n.left.expression)
    ) {
      names.add(n.left.expression.text);
    }
    ts.forEachChild(n, visit);
  };
  visit(sf);
  return names;
}

function isMutableInitializer(init: ts.Expression | undefined): boolean {
  if (!init) return false;
  if (ts.isArrayLiteralExpression(init) || ts.isObjectLiteralExpression(init)) return true;
  return ts.isNewExpression(init) && /^(Map|Set|WeakMap|Array)$/.test(init.expression.getText());
}

function functionName(n: ts.SignatureDeclaration, sf: ts.SourceFile): string {
  if (n.name) return n.name.getText(sf);
  const parent = n.parent;
  if (ts.isVariableDeclaration(parent) || ts.isPropertyAssignment(parent)) return parent.name.getText(sf);
  return "(anonymous)";
}

function scan(file: string): void {
  const rel = toRel(file);
  const sf = ts.createSourceFile(file, readFileSync(file, "utf8"), ts.ScriptTarget.Latest, true);
  const at = (n: ts.Node) => `${rel}:${sf.getLineAndCharacterOfPosition(n.getStart(sf)).line + 1}`;
  const insideAdapter = rel.split("/").some((seg) => ADAPTER_DIRS.has(seg));
  const isSdk = (spec: string) => SDKS.some((s) => spec === s || spec.startsWith(`${s}/`));
  const mutated = mutatedNames(sf);
  scanned++;

  for (const statement of sf.statements) {
    if (!ts.isVariableStatement(statement)) continue;
    const isConst = (statement.declarationList.flags & ts.NodeFlags.Const) !== 0;
    for (const d of statement.declarationList.declarations) {
      const name = d.name.getText(sf);
      if (!isConst) moduleState.push(`let ${name}  ${at(d)}`);
      else if (isMutableInitializer(d.initializer) && mutated.has(name)) moduleState.push(`const ${name} (mutated)  ${at(d)}`);
    }
  }

  const visit = (n: ts.Node): void => {
    if (ts.isSwitchStatement(n)) {
      const key = discriminant(n.expression);
      if (key && n.caseBlock.clauses.length >= 2) push(switches, key, at(n));
    }
    if (ts.isInterfaceDeclaration(n)) interfaces.set(n.name.text, at(n));
    if (ts.isVariableDeclaration(n) && n.type && ts.isTypeReferenceNode(n.type) && n.initializer && ts.isObjectLiteralExpression(n.initializer)) {
      push(implementers, n.type.typeName.getText(sf), n.name.getText(sf));
    }
    if (ts.isClassLike(n)) {
      const className = n.name?.text ?? "(anonymous)";
      for (const clause of n.heritageClauses ?? []) {
        if (clause.token !== ts.SyntaxKind.ImplementsKeyword) continue;
        for (const t of clause.types) push(implementers, t.expression.getText(sf), className);
      }
      const publicMethods = n.members.filter(
        (m) =>
          ts.isMethodDeclaration(m) &&
          !ts.isPrivateIdentifier(m.name) &&
          !(ts.getCombinedModifierFlags(m) & (ts.ModifierFlags.Static | ts.ModifierFlags.Private)),
      );
      const extendsSomething = n.heritageClauses?.some((c) => c.token === ts.SyntaxKind.ExtendsKeyword);
      if (publicMethods.length === 1 && !extendsSomething) oneMethod.push(`${className}.${publicMethods[0]!.name!.getText(sf)}  ${at(n)}`);
    }
    if (ts.isImportDeclaration(n) && ts.isStringLiteral(n.moduleSpecifier) && isSdk(n.moduleSpecifier.text) && !insideAdapter) {
      sdkLeaks.push(`${n.moduleSpecifier.text}  ${at(n)}`);
    }
    if (ts.isFunctionDeclaration(n) || ts.isMethodDeclaration(n) || ts.isArrowFunction(n) || ts.isFunctionExpression(n) || ts.isConstructorDeclaration(n)) {
      const count = n.parameters.filter((p) => p.name.getText(sf) !== "this").length;
      if (count > 4) longParams.push(`${functionName(n, sf)}(${count} params)  ${at(n)}`);
    }
    ts.forEachChild(n, visit);
  };
  visit(sf);
}

Q1 · 10 min Write Strategy, Decorator and Chain of Responsibility in TypeScript, with no classes.

Solution · الحل Strategy is a Record of functions, Decorator is a function that returns the same signature, and Chain is a recursive call on an index. See 09, 08 and 12. 
// السؤال 1: الـ Strategy والـ Decorator والـ Chain من غير ولا class
type Order = { id: string; totalCents: number; country: "EG" | "SA" };

// الـ Strategy: جدول functions بيتختار منه وقت الـ runtime
const taxByCountry: Record<Order["country"], (cents: number) => number> = {
  EG: (c) => Math.round(c * 0.14),
  SA: (c) => Math.round(c * 0.15),
};

// الـ Decorator: نفس الـ signature، وسلوك زيادة حوالين الأصل
const withCallCount = <A extends unknown[], R>(fn: (...args: A) => R) => {
  const wrapped = (...args: A): R => {
    wrapped.calls++;
    return fn(...args);
  };
  wrapped.calls = 0;
  return wrapped;
};

// الـ Chain: كل handler يا بيكمّل بـ next يا بيوقف

  return go(0);
};

  (o, next) => (o.totalCents <= 1_000_000 ? next() : "manual review"),
);

// السؤال 4: الـ compose بتاعة Koa من الذاكرة
type Next = () => Promise<void>;
type Middleware<C> = (ctx: C, next: Next) => Promise<void> | void;

function compose<C>(middleware: Middleware<C>[]) {
  return (ctx: C): Promise<void> => {
    let last = -1;
    const dispatch = (i: number): Promise<void> => {
      if (i <= last) return Promise.reject(new Error("next() called multiple times"));
      last = i;
      const fn = middleware[i];
      if (!fn) return Promise.resolve();
      try {
        return Promise.resolve(fn(ctx, () => dispatch(i + 1)));
      } catch (err) {
        return Promise.reject(err);
      }
    };
    return dispatch(0);
  };
}

export async function relayOnce(

  crashBeforeMark = false,
): Promise<number> {

  const { rows } = await db.query(
    `SELECT id, topic, payload FROM outbox WHERE published_at IS NULL
     ORDER BY id LIMIT 10 FOR UPDATE SKIP LOCKED`,
  );

    if (crashBeforeMark) {

      return rows.length;

Q6 · 8 min Circuit breaker: the three states and the transitions. Write it.
الـ circuit breaker: الـ 3 states والـ transitions، واكتبه.
Solution · الحل Closed counts failures and opens at the threshold. Open fails fast until the cooldown ends, then moves to half-open. Half-open lets one probe through: success closes it, failure opens it again. The clock is injected, so the test needs no sleeping. Production detail is in 23. 
// السؤال 6: الـ circuit breaker بالتلات states
type BreakerState = "closed" | "open" | "half-open";

function circuitBreaker<A extends unknown[], R>(
  fn: (...args: A) => Promise<R>,
  opts: { failureThreshold: number; cooldownMs: number; now: () => number },
) {
  let state: BreakerState = "closed";
  let failures = 0;
  let openedAt = 0;
  let probing = false;

  const trip = () => {
    state = "open";
    openedAt = opts.now();
    probing = false;
  };

  return {
    state: () => state,
    async call(...args: A): Promise<R> {
      if (state === "open") {
        if (opts.now() - openedAt < opts.cooldownMs) throw new Error("circuit open");
        state = "half-open";
      }
      if (state === "half-open") {
        if (probing) throw new Error("circuit open");
        probing = true;
      }
      try {
        const result = await fn(...args);
        state = "closed";
        failures = 0;
        probing = false;
        return result;
      } catch (err) {
        failures++;
        if (state === "half-open" || failures >= opts.failureThreshold) trip();
        throw err;
      }
    },
  };
}

Q10 · 3 min When do you not need Visitor in TypeScript, and what replaces it?
إمتى الـ Visitor مش محتاجه في TypeScript، وإيه البديل؟
Solution · الحل When you own a closed set of node types: a discriminated union plus an exhaustive switch, with assertNever so a new kind stops compiling. Visitor still earns its place when operations must be added by code that cannot touch the tree, or when a library exposes one, as compilers do. See 14. 
// السؤال 10: مفيش Visitor: union مقفول و switch بيتأكد الـ compiler إنه مغطي كل حاجة
type InvoiceNode =
  | { kind: "line"; cents: number }
  | { kind: "discount"; cents: number }
  | { kind: "group"; items: InvoiceNode[] };

function total(node: InvoiceNode): number {
  switch (node.kind) {
    case "line":
      return node.cents;
    case "discount":
      return -node.cents;
    case "group":
      return node.items.reduce((sum, item) => sum + total(item), 0);
    default:
      return assertNever(node);
  }
}
function assertNever(x: never): never {
  throw new Error(`unhandled node: ${JSON.stringify(x)}`);
}
console.log("Q10:", total({ kind: "group", items: [{ kind: "line", cents: 5000 }, { kind: "discount", cents: 500 }] }));
Q10: 4500
لما تكون صاحب مجموعة nodes مقفولة: discriminated union مع switch exhaustive و assertNever، فأي kind جديد الكود مايعملش compile. الـ Visitor لسه بيستاهل لما عمليات لازم تتضاف من كود مش قادر يلمس الـ tree، أو لما library بتعرضه زي الـ compilers. الـ output: 4500 يعني 5000 ناقص خصم 500. الدرس: 14.

import assert from "node:assert/strict";

type Invoice = { id: string; netCents: number };

// قبل: Template Method بـ subclass واحدة
abstract class InvoiceExporter {
  export(invoices: Invoice[]): string {
    return [this.header(), ...invoices.map((i) => this.row(i))].join("\n");
  }
  protected abstract header(): string;
  protected abstract row(invoice: Invoice): string;
}
class CsvInvoiceExporter extends InvoiceExporter {
  protected header() { return "id,net"; }
  protected row(i: Invoice) { return `${i.id},${i.netCents}`; }
}

// بعد: function واحدة
const invoicesCsv = (invoices: Invoice[]) =>
  ["id,net", ...invoices.map((i) => `${i.id},${i.netCents}`)].join("\n");

const sample = [{ id: "inv1", netCents: 900 }, { id: "inv2", netCents: 1500 }];

Solution · الحل 
import ts from "typescript";

// الـ detector السابع: call فيها 2 boolean literals أو أكتر، زي ⁦save(user, true, false)⁩
export function booleanFlagCalls(code: string, fileName = "sample.ts"): string[] {
  const sf = ts.createSourceFile(fileName, code, ts.ScriptTarget.Latest, true);
  const out: string[] = [];
  const isBool = (a: ts.Expression) =>
    a.kind === ts.SyntaxKind.TrueKeyword || a.kind === ts.SyntaxKind.FalseKeyword;
  const visit = (n: ts.Node): void => {
    if (ts.isCallExpression(n) && n.arguments.filter(isBool).length >= 2) {
      const line = sf.getLineAndCharacterOfPosition(n.getStart(sf)).line + 1;
      out.push(`${n.expression.getText(sf)}(${n.arguments.length} args)  ${fileName}:${line}`);
    }
    ts.forEachChild(n, visit);
  };
  visit(sf);
  return out;
}

const code = `
await saveUser(user, true, false);
await saveUser(user, { sendEmail: true, audit: false });
retry(chargeCard, 3, true);
`;
console.log(booleanFlagCalls(code));

Cheat sheet · الخلاصة

  • A pattern you've learned is three facts: the problem in today's code, the cost, the simpler alternative.
  • A card only counts with all three. The name is the easy part.
  • "No pattern here" needs a format: what's added, evidence (implementers, call sites, lines), the simpler code run against the same tests, and when you'd agree.
  • Count today's variation, not the variation you can imagine.
  • Overdue signals: the same switch in 3+ places, vendor codes in business files, illegal transitions in data.
  • Rejecting abstraction by reflex is its own golden hammer.
  • Naming helps when it comes with what it buys and one concrete suggestion. Skip it if it changes nobody's actions.
  • Framework words mislead: Fastify's decorate, React Hooks and Nest interceptors aren't the patterns those names suggest. Keep a glossary.
  • An audit gives questions, not verdicts: check test fakes, closed unions and deliberate caches before acting.
  • Fail CI only on new findings against a baseline.
  • Sort the results into what repeats, what's missing and what's excess, and fix bugs first.

  • "مش محتاجين pattern هنا" ليها شكل: اللي اتضاف، والدليل (implementers و call sites وسطور)، والكود الأبسط متجرّب على نفس الـ tests، وإمتى هتوافق.
