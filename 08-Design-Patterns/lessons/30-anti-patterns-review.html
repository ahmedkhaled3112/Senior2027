Why this matters · ليه ده مهم

English

Most of what a senior does in code review is catching an anti-pattern before it costs a quarter of refactoring, and saying so in one sentence the author can act on. This lesson finds ten of them with real tools on a generated sample codebase (ESLint 10, madge, knip, jscpd, the TS compiler API), shows when each one is not a problem, and ends with a 10-item checklist with the comment to write for each. The README's artifact for this section is exactly that list.

Part 1 — God object and god module 🟡 Intermediateالجزء 1 — الـ God object والـ God module

English

A god object knows and does too much: one class that owns many unrelated reasons to change. A god module is the same thing as a file: utils.ts, where everything without a home ends up. The sample's UserService (generated) mixes auth, profile, billing, notifications, admin and reports, with 11 constructor dependencies.

Find them with numbers rather than taste. ESLint gives you size and shape: max-lines, max-lines-per-function, complexity, max-params. madge gives you position in the graph: fan-in (how many modules import this one) and fan-out (how many it imports). High fan-in on a file that also changes often is the expensive combination, because every change risks everything that imports it. Churn comes from git log, which you'll run on your own repo in exercise 1.

What they cost: every feature touches the same file, so merge conflicts become routine; and any test of one method needs 11 fakes for the constructor. The fix is decomposition by concern, covered step by step in Refactoring II. When a big file is fine: generated code, or a flat table of data. The 900-row vat-rates.ts below is exempt on purpose.

الرسمة دي فوق هي شكل الـ god module: كل الـ modules بتشاور على ملف واحد، فأي تعديل فيه بيوصل لـ 12 ملف.

لاقيهم بالأرقام مش بالذوق. Part 2 — Anemic domain model 🟡 Intermediateالجزء 2 — الـ Anemic domain model

English

An anemic model is objects that hold data and no behaviour, with every rule in services. Fowler's complaint in AnemicDomainModel is that it costs you the data-and-behaviour pairing OO exists for, while you still pay for the object mapping. The README's point matters more: in a CRUD app with no real rules, an anemic model is fine, and a rich one is ceremony (Domain Model shows the rich version).

The sign that it's a real problem isn't "this class has no methods". It's the same rule appearing in several services, written at different times, and drifting. The test below feeds the same orders to all three services: they disagree on three of the four, and the 30-day boundary is off by one between refunds and reporting.

export type OrderDto = { id: string; status: "placed" | "paid" | "shipped"; paidAt: number | null; totalCents: number };

export const DAY_MS = 86_400_000;
export const NOW = Date.UTC(2026, 10, 9);

// الـ 3 services دي نفس القاعدة، بس كل واحدة اتكتبت في وقت مختلف
export const RefundService = {
  canRefund: (o: OrderDto) => o.status === "paid" && o.paidAt !== null && NOW - o.paidAt < 30 * DAY_MS,
};

};
export const AdminService = {
  showRefundButton: (o: OrderDto) => o.status !== "shipped" && (o.paidAt === null || NOW - o.paidAt < 14 * DAY_MS),

الـ anemic model هو objects شايلة data ومفيهاش behavior، وكل القواعد في الـ services. وشكوى Fowler في AnemicDomainModel إنك بتخسر الربط بين الـ data والـ behavior اللي الـ OO معمول عشانه، وفي نفس الوقت لسه بتدفع تمن الـ object mapping. بس نقطة الـ README أهم: في CRUD app مفيهوش قواعد حقيقية، الـ anemic model تمام، والـ rich model هيبقى زيادة شغل (درس الـ Domain Model بيوري النسخة الغنية).

Part 3 — Spaghetti code and lava flow 🟡 Intermediateالجزء 3 — الـ Spaghetti code والـ lava flow

English

Spaghetti is control flow you can't follow: nested conditions where each new rule goes inside the previous one. ESLint's complexity and max-depth put numbers on it. The honest detail: at a threshold of 10, complexity wouldn't flag this function (it scores 9). max-depth does, because nesting is what makes it hard to read. Complexity alone misses the shape. The rewrite below uses guard clauses and one function per country, and the same table of cases passes on both versions.

export type Parcel = { country: string; city: string; weightKg: number; totalCents: number; express: boolean };

// ❌ كل شرط جديد بيدخل جوه اللي قبله
export function shippingFee(p: Parcel): number {
  let fee = 0;
  if (p.weightKg > 0) {
    if (p.country === "EG") {
      if (p.express) {
        if (p.totalCents < 50000) {
          if (p.city === "cairo") {
            fee = 6000;
          } else {
            fee = 9000;
          }
        } else {
          fee = 3000;
        }
      } else {
        if (p.totalCents < 50000) {
          fee = 2500;
        } else {
          fee = 0;
        }
      }
    } else {
      if (p.country === "SA") {
        if (p.express) {
          fee = 15000;
        } else {
          fee = 8000;
        }
      } else {
        throw new Error("unsupported country");
      }
    }
  } else {
    throw new Error("bad weight");
  }
  return fee;
}

const FREE_ABOVE_CENTS = 50000;

// ✅ الحالات الغلط تخرج بدري، وكل بلد في function لوحدها
function egyptFee(p: Parcel): number {
  const large = p.totalCents >= FREE_ABOVE_CENTS;
  if (!p.express) return large ? 0 : 2500;
  if (large) return 3000;
  return p.city === "cairo" ? 6000 : 9000;
}

const saudiFee = (p: Parcel): number => (p.express ? 15000 : 8000);

export function shippingFee(p: Parcel): number {
  if (p.weightKg <= 0) throw new Error("bad weight");
  if (p.country === "EG") return egyptFee(p);
  if (p.country === "SA") return saudiFee(p);
  throw new Error("unsupported country");
}

English

Lava flow is code nobody dares delete: it solidified, nobody knows what it does, and everyone routes around it. knip finds the static part: unused files, exports and dependencies. On the sample it reports the legacy folder, two dead dependencies, and 21 of the 45 exports in utils.ts.

Static tools can't see dynamic use. load-exporter.ts builds a path at runtime, so knip reports exporters/csv.ts as unused while production loads it. Delete that and CSV export dies in production. Tell the tool about the entry instead, then re-run. And for code you can't prove is dead: log before delete for one full release, watch the metric, remove the flag, then delete with tests in place. Never in the same PR as a feature.

English

Premature abstraction (speculative generality) is structure for a future that hasn't arrived: an interface with one implementation "because we might need it". The audit below uses the TS compiler API to count implementers per interface on the sample: 4 of 6 have exactly one. The script needs the JS compiler API, so it uses TS 6.0.3: the TS 7.0.2 package has no lib/typescript.js, only the native tsc wrapper. A tool can count; deciding is your job, because some single-implementation interfaces earn their place:

  • A vendor boundary: IPaymentGateway around Stripe, so the SDK doesn't spread (Gateway).
  • A seam for a fake: the same gateway has a FakeGateway in tests. The audit counts it, which is why it shows 2.

The other four (ICacheKeyBuilder, IInvoiceFormatter, ...) are pure ceremony. The Rule of Three (when a pattern does harm): wait for the third real variation before abstracting.

Sandi Metz's point is about the failure mode: "duplication is far cheaper than the wrong abstraction". Once a shared function exists, each new caller adds a flag instead of questioning the abstraction. Below, formatLine has grown to four booleans for four callers. The fix is her recipe: inline it back into the callers, then let the real commonality (money) re-emerge.

export function creditNoteTotal(lines: Line[], _tenant: Tenant, discountCents: number): number {
  let subtotal = 0;

  const vat = Math.round(discounted * 0.14);
  const shipping = discounted > 100000 ? 0 : 2500;
  const total = discounted + vat + shipping;
  return total;
}

English

Async hell has three generations in the same file below: callback pyramids, then nested .then chains (promise hell), then the modern trap, a flat-looking await inside a loop. no-await-in-loop flags it: 100 payments at 5 ms each took about 1.5 s in series against about 13 ms in parallel (Windows stretches each 5 ms sleep to about 15 ms, so 100 of them add up to 1.5 s, not 0.5 s). Singleton abuse and global mutable state. A module-level currentTenant is a shared variable across every concurrent request in the process. Below, 100 concurrent requests across two tenants returned the wrong tenant's data 50 times: a data leak between customers, the worst bug this lesson shows. 7) Async hell: no-await-in-loop و .then متداخلة. الـ comment: "ده sequential بقصد؟ لو آه اكتب ليه، لو لأ Promise.all بـ limit."

8) Singleton / global state: let على مستوى الـ module فيه data بتاعة request. الـ comment: "ده state لكل request في متغير عام؛ استخدم AsyncLocalStorage."

9) Leaky abstraction: ORM أو SDK types بره الـ repository. الـ comment: "رجّع النوع بتاعنا واعمل map عند الحدود، عشان الـ rename يلمس ملف واحد."

10) Distributed monolith: نشر مع بعض و DB مشتركة وسلاسل sync و domain library مشتركة. الـ comment: "لو دول دايمًا بيطلعوا مع بعض، إيه المكسب من فصلهم؟"

Interview question: "You join a codebase with a 2,000-line utils.ts and lots of duplication. Where do you start?" Don't start by refactoring. Measure first: run madge for fan-in, get churn from git, jscpd for duplicates, knip for dead code. The hot spots are files with high churn and high fan-in; a big file nobody touches can wait. Delete what's provably dead first, as the cheapest win. Then split the hottest module by concern in small PRs with tests in place, never mixed with features. And keep the rule enforced in CI so it doesn't grow back.
السؤال: "دخلت على codebase فيها utils.ts بـ 2000 سطر وتكرار كتير. تبدأ منين؟" الإجابة: متبدأش بـ refactoring. قيس الأول: madge للـ fan-in، و churn من git، و jscpd للتكرار، و knip للكود الميت. الأماكن الساخنة هي الملفات اللي الـ churn والـ fan-in بتوعها عاليين؛ الملف الكبير اللي محدش بيلمسه يستنى. امسح الميت المؤكد الأول لأنه أرخص مكسب. وبعدين قسّم أسخن module بالـ concern في PRs صغيرة والـ tests موجودة، ومش مخلوطة بـ features. وثبّت القاعدة في الـ CI عشان متكبرش تاني.
Interview question: "How do you give review feedback on an anti-pattern without it becoming a style argument?" Tie it to a cost and a number, not to taste: "this rule exists in 3 services and they already disagree on the 30-day boundary", not "this is anemic". Say what it costs (a bug, a merge conflict, a release coupled to another team), propose the smallest fix, and say when it's fine to leave it. And separate blocking from non-blocking comments, so the author knows what must change.
السؤال: "إزاي تدّي feedback على anti-pattern من غير ما يتحول لخناقة ذوق؟" الإجابة: اربطه بتكلفة ورقم مش بذوق: "القاعدة دي في 3 services واختلفوا فعلًا في حد الـ 30 يوم"، مش "ده anemic". قول بيكلّف إيه (bug أو merge conflict أو release مربوط بـ team تاني)، واقترح أصغر حل، وقول إمتى عادي يتساب. وافصل الـ comments اللي blocking عن اللي non-blocking، عشان الـ author يعرف إيه اللي لازم يتغير.

Common mistakes · غلطات شائعة

❌ Turning a size rule off everywhere 
// الـ rule اتطفت عشان ملف واحد متولّد
{ rules: { "max-lines": "off" } }
✅ Exempt only the generated folder 
// الاستثناء محدد، والـ rule لسه شغالة على الباقي
{ files: ["src/data/**/*.ts"], rules: { "max-lines": "off" } }
بالعامية

❌ لما ملف متولّد يكسر الـ max-lines، الناس بتطفي القاعدة كلها، فالـ god module الجاي يعدّي من غير حد ما يحس. ✅ استثني المسار بتاع الـ generated بس، وسيب القاعدة شغالة على الكود اللي بني آدم بيكتبه.

❌ Deleting whatever the tool lists 
# كده الـ exporters اتمسحت وهي شغالة في production
xargs rm < knip-unused-files.txt
✅ Declare dynamic entries, then verify 
{ "entry": ["src/index.ts", "src/export/exporters/*.ts"] }
بالعامية

❌ الـ knip بيقول "unused" عن أي حاجة بتتحمّل بـ import() باسم متركّب وقت التشغيل، فلو مسحت القايمة زي ما هي، الـ CSV export بيقع في production. ✅ ضيف الـ entries الديناميكية في الـ config، وبعدين امسح اللي فاضل، ولو مش متأكد سجّل الاستخدام release كامل.

❌ Extracting a shared function at the second copy 
// كل caller جديد بيزود flag
formatLine(name, cents, true, false, false, false);
✅ Keep it simple until the shape is known 
// الحالات المختلفة ليها functions بأسماء
creditLine(name, cents);
بالعامية

❌ لما تستخرج function مشتركة بدري قبل ما الشكل يبان، كل caller جديد بيزود flag، و 4 booleans معناها 16 تركيبة ومحدش مختبرهم كلهم. ✅ سيب التكرار القليل لحد ما يبان اللي مشترك فعلًا، وادّي كل حالة اسم بيقول هي إيه.

❌ A blanket eslint-disable with no reason 
// eslint-disable-next-line no-await-in-loop
for (const id of ids) await charge(id);
✅ Disable with the reason, or fix it 
// eslint-disable-next-line no-await-in-loop -- each page needs the previous cursor
const page = await fetchPage(cursor);
بالعامية

❌ الـ eslint-disable من غير سبب بيقول "مش عارف ليه بس اسكت"، واللي بعدك مش هيعرف هل ده مقصود. ✅ اكتب السبب بعد -- في نفس السطر، ولو مفيش سبب حقيقي يبقى صلّح الـ loop بـ Promise.all.

2. Name the magic numbers 🟡 medium Rewrite discount.ts so no-magic-numbers passes with only 0, 1 and -1 ignored. Note: 365 * DAY_MS in a const is still flagged, because the rule only allows a number as the direct value of the const.
اكتب discount.ts من تاني بحيث no-magic-numbers يعدّي مع تجاهل 0 و 1 و -1 بس. وخد بالك: 365 * DAY_MS جوه const بتتمسك برضه، لأن القاعدة بتسمح بالرقم كقيمة مباشرة للـ const بس.
Solution · الحل 
const DAY_MS = 86_400_000;
const LOYAL_DAYS = 365;
const LOYAL_AGE_MS = LOYAL_DAYS * DAY_MS;
const GOLD_RATE = 0.15;
const BULK_MIN_CENTS = 500_000;
const BULK_RATE = 0.05;

// الأسماء بتقول الـ business rule، و ESLint بقى ساكت
export function discountFor(tier: string, totalCents: number, ageMs: number): number {
  if (tier === "gold" && ageMs > LOYAL_AGE_MS) return Math.round(totalCents * GOLD_RATE);
  if (totalCents > BULK_MIN_CENTS) return Math.round(totalCents * BULK_RATE);
  return 0;
}
الملف ده عدّى ESLint بـ exit code صفر بعد ما سمّينا كل رقم، و 365 خد اسم لوحده الأول.
3. Fix the VAT in one place 🔴 hard Make the three billing files share one computeTotal, so the failing test goes green and jscpd reports no clones. Then write one sentence explaining why these three should share code, when billing and shipping shouldn't.
خلي ملفات الـ billing التلاتة يستخدموا computeTotal واحدة، عشان الـ test الفاشل يعدّي و jscpd يطلّع صفر clones. وبعدين اكتب جملة واحدة: ليه التلاتة دول لازم يتشاركوا الكود، بينما الـ billing والـ shipping لأ.
Solution · الحل 
export type Line = { cents: number; qty: number };
export type Tenant = { vatExempt: boolean };

const VAT_RATE = 0.14;
const FREE_SHIPPING_ABOVE = 100_000;
const SHIPPING_CENTS = 2500;

// الحساب بقى في مكان واحد، فالـ fix الجاي مش ممكن ينسى نسخة
export function computeTotal(lines: Line[], tenant: Tenant, discountCents: number): number {
  const subtotal = lines.reduce((sum, line) => sum + line.cents * line.qty, 0);
  const discounted = Math.max(subtotal - discountCents, 0);
  const vat = tenant.vatExempt ? 0 : Math.round(discounted * VAT_RATE);
  const shipping = discounted > FREE_SHIPPING_ABOVE ? 0 : SHIPPING_CENTS;
  return discounted + vat + shipping;
}
export { computeTotal as invoiceTotal } from "./total.ts";

Cheat sheet · الخلاصة

  • God object or module: find it with max-lines, max-params and madge fan-in. High churn plus high fan-in is the expensive combination. Generated code and data tables are fine.
  • Anemic model is fine for CRUD. The real sign: the same rule in several services, drifting apart.
  • Spaghetti: max-depth catches what complexity misses. Guard clauses, tests before and after.
  • Lava flow: knip lists it, but it can't see import() with a built path. Declare entries, log for a release, then delete.
  • Golden hammer: ask what problem we have today. Five sync services at 99.9% are ≈99.5%, about 44 hours down a year against 9.
  • Distributed monolith: deploy together, shared DB, sync chains, shared domain library.
  • Premature abstraction: count implementers, but a vendor boundary or a seam for a fake is justified. Duplication is cheaper than the wrong abstraction.
  • Copy-paste: jscpd finds clones, and the question is whether the copies must change together. Tune no-magic-numbers; replace boolean params with options or two functions.
  • await in a loop is sequential: flag it, parallelise with a limit, or disable with a written reason.
  • Per-request state in a module variable leaks between tenants: use AsyncLocalStorage.
  • ORM types outside the repository are a leak: map at the boundary, and a rename touches one file.
بالعامية
  • الـ God object أو module: لاقيه بـ max-lines و max-params و fan-in من madge. الـ churn العالي مع الـ fan-in العالي هي التركيبة الغالية. والكود المتولّد وجداول الـ data عادي.
  • الـ Anemic model تمام للـ CRUD. والعلامة الحقيقية: نفس القاعدة في كذا service وبدأت تختلف.
  • الـ Spaghetti: max-depth بيمسك اللي complexity بتفوّته. استخدم guard clauses، و tests قبل وبعد.
  • الـ Lava flow: knip بيطلّعه، بس مش شايف import() بمسار متركّب. سجّل الـ entries، وراقب الاستخدام release، وبعدين امسح.
  • الـ Golden hammer: اسأل إيه المشكلة النهارده. خمسة services sync على 99.9% يعني ≈99.5%، حوالي 44 ساعة في السنة مقابل 9.
  • الـ Distributed monolith: نشر مع بعض، و DB مشتركة، وسلاسل sync، و domain library مشتركة.
  • الـ Premature abstraction: عد الـ implementers، بس حدود الـ vendor أو seam الـ fake ليهم مبرر. والتكرار أرخص من الـ abstraction الغلط.
  • الـ Copy-paste: jscpd بيلاقي النسخ، والسؤال هل لازم يتغيروا مع بعض. ظبط no-magic-numbers، وبدّل الـ boolean params بـ options أو two functions.
  • الـ await جوه loop معناه تسلسل: يا تصلحه بـ limit، يا تعمل disable بسبب مكتوب.
  • الـ state بتاع الـ request في متغير module بيسرّب بين الـ tenants: استخدم AsyncLocalStorage.
  • الـ ORM types بره الـ repository تسريب: اعمل map عند الحدود، والـ rename يبقى ملف واحد.
