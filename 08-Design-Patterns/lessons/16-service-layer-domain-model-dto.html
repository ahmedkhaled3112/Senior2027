Why this matters · ليه ده مهم

English

Where does business logic live? Every codebase answers that, on purpose or by accident, and the answer decides how expensive the next rule change will be. This lesson gives you the vocabulary and a way to choose: a procedure per use case or a rich object, what a service is allowed to do, and which type crosses which boundary.

The stakes are concrete. Below, a copied script loses a coupon rule, a raw row leaks a password hash, and a column rename breaks the mobile app. Each of those ran for real, and each has a small fix once you know the pattern.

بالعامية

الـ business logic تعيش فين؟ أي codebase بيجاوب على السؤال ده، بقصد أو بالصدفة، والإجابة بتحدد تعديل القاعدة الجاية هيكلفك قد إيه. الدرس ده بيدّيك الكلمات وطريقة الاختيار: procedure لكل use case ولا object غني، الـ service مسموحله يعمل إيه، وأنهي type بيعدّي أنهي حد.

المشاكل هنا حقيقية: تحت، script متنسخ ضاعت منه قاعدة كوبون، و row خام سرّب password hash، وتغيير اسم column كسر الـ mobile app. الـ 3 اتشغلوا بجد، وكل واحدة ليها حل صغير لما تعرف الـ pattern.

Part 1 — Transaction Script 🟡 Intermediateالجزء 1 — الـ Transaction Script

English

A Transaction Script is one procedure per use case: it reads, decides, writes, and returns, top to bottom. It is readable, fast to write and easy to debug, and for CRUD it is the right answer. Say that plainly, because engineers learning patterns tend to skip it. Here is placeOrder on a real Postgres.

import { randomUUID } from "node:crypto";
import type { Pool } from "pg";

export interface PlaceOrderCmd {
  customerId: string;
  coupon?: string;
  lines: { productId: string; qty: number }[];
}
export interface Totals { subtotal: number; discount: number; tax: number; total: number }

// الـ Transaction Script: function واحدة بتعمل الـ use case كله من أوله لآخره
export async function placeOrder(db: Pool, cmd: PlaceOrderCmd): Promise<Totals & { orderId: string }> {
  if (cmd.lines.length === 0) throw new Error("order is empty");
  const client = await db.connect();
  try {
    await client.query("BEGIN");
    let subtotal = 0;
    for (const line of cmd.lines) {
      if (!Number.isInteger(line.qty) || line.qty <= 0) throw new Error("quantity must be a positive integer");
      const { rows } = await client.query("SELECT price_cents, stock FROM products WHERE id = $1 FOR UPDATE", [line.productId]);
      if (!rows[0]) throw new Error(`unknown product: ${line.productId}`);
      if (rows[0].stock < line.qty) throw new Error(`out of stock: ${line.productId}`);
      subtotal += rows[0].price_cents * line.qty;
      await client.query("UPDATE products SET stock = stock - $2 WHERE id = $1", [line.productId, line.qty]);
    }
    let discount = 0;
    if (cmd.coupon) {
      const { rows } = await client.query("SELECT * FROM coupons WHERE code = $1", [cmd.coupon]);
      if (!rows[0]) throw new Error(`unknown coupon: ${cmd.coupon}`);
      if (subtotal >= rows[0].min_subtotal_cents) discount = Math.round((subtotal * rows[0].percent) / 100);
    }
    const tax = Math.round(((subtotal - discount) * 14) / 100);
    const total = subtotal - discount + tax;
    const orderId = randomUUID();
    await client.query(
      `INSERT INTO orders (id, customer_id, status, coupon, subtotal_cents, discount_cents, tax_cents, total_cents)
       VALUES ($1, $2, 'placed', $3, $4, $5, $6, $7)`,
      [orderId, cmd.customerId, cmd.coupon ?? null, subtotal, discount, tax, total]);
    await client.query("COMMIT");
    return { orderId, subtotal, discount, tax, total };
  } catch (err) {
    await client.query("ROLLBACK");
    throw err;
  } finally {
    client.release();
  }
}

بالعامية

الـ Transaction Script هو procedure واحد لكل use case: بيقرا، يقرر، يكتب، ويرجّع، من فوق لتحت. مقروء، وسريع في الكتابة، وسهل في الـ debugging، وللـ CRUD هو الإجابة الصح. وده لازم يتقال بوضوح، لأن اللي بيتعلم patterns بيميل يتخطاه. فوق placeOrder على Postgres حقيقي.

بيبوظ لما نفس القواعد تبقى مطلوبة في أكتر من script. منطق الكوبون والضريبة والـ stock بيتنسخ في quote لمعاينة الـ cart وفي reorder لـ "اشتري تاني". بعدها الـ product يضيف حد أدنى للكوبون، حد يعدّل نسختين من تلاتة، والتالتة تفضل تدّي خصم. الـ test اللي بيشغّل نفس الحالات على التلاتة هو اللي بيمسكها، والـ diff الحقيقي بيوضح ليه محدش خد باله في الـ review.

فين هستخدمه في شغلي؟ لوحة admin لتغيير حالة ticket أو إضافة banner؟ Transaction Script وخلاص، ملف واحد ومفهوم. بس لو لقيت نفس Math.round(... * 0.14) في checkout وفي الفاتورة وفي الـ refund، ده الوقت اللي القاعدة تستاهل مكان واحد. ابدأ بـ test بيلف على النسخ كلها زي اللي فوق، هيقولك إيه اللي بايظ قبل ما تعمل refactor.

Part 2 — Domain Model 🟡 Intermediateالجزء 2 — الـ Domain Model

English

A Domain Model moves the rules into objects that protect their own invariants. Order below has addLine, applyCoupon and place; you cannot add a line after placing, cannot have zero quantity, and cannot read a total that ignores the coupon minimum, because there is no other way in. Money is the Value Object from Part 3: read it as integer cents plus a currency for now.

The payoff is the test run. One table of 12 cases runs through the model with no database, and the same table runs through the script on Postgres. The costs are real too: a mapping layer, more types, and a concept the team must learn. Judge by domain complexity: an admin panel gets a script, a pricing engine gets a model. Aggregates and DDD proper are in Section 09 · 2.6 and aren't taught here.

import { DomainError } from "./errors.ts";
import { Money } from "./money.ts";

export interface Product { id: string; price: Money; stock: number }
export interface Coupon { code: string; percent: number; minSubtotal: Money }
export interface OrderLine { productId: string; unitPrice: Money; qty: number }
export type OrderStatus = "draft" | "placed";

const VAT_PERCENT = 14;

export class Order {
  readonly id: string;
  readonly customerId: string;
  #lines = new Map<string, OrderLine>();
  #coupon: Coupon | null = null;
  #status: OrderStatus = "draft";

  constructor(id: string, customerId: string) { this.id = id; this.customerId = customerId; }

  get status(): OrderStatus { return this.#status; }
  get lines(): OrderLine[] { return [...this.#lines.values()]; }
  get couponCode(): string | null { return this.#coupon?.code ?? null; }

  addLine(product: Product, qty: number): void {
    this.#assertDraft();
    if (!Number.isInteger(qty) || qty <= 0) throw new DomainError("quantity must be a positive integer");
    // نفس المنتج مرتين يعني سطر واحد، والـ stock بيتحسب على المجموع
    const nextQty = (this.#lines.get(product.id)?.qty ?? 0) + qty;
    if (nextQty > product.stock) throw new DomainError(`out of stock: ${product.id}`);
    this.#lines.set(product.id, { productId: product.id, unitPrice: product.price, qty: nextQty });
  }

  applyCoupon(coupon: Coupon): void {
    this.#assertDraft();
    this.#coupon = coupon;
  }

  place(): void {
    this.#assertDraft();
    if (this.#lines.size === 0) throw new DomainError("order is empty");
    this.#status = "placed";
  }

  get subtotal(): Money {
    return this.lines.reduce((sum, l) => sum.add(l.unitPrice.times(l.qty)), Money.of(0, this.#currency));
  }
  get discount(): Money {
    if (!this.#coupon || this.subtotal.isLessThan(this.#coupon.minSubtotal)) return Money.of(0, this.#currency);
    return this.subtotal.percent(this.#coupon.percent);
  }
  get tax(): Money { return this.subtotal.minus(this.discount).percent(VAT_PERCENT); }
  get total(): Money { return this.subtotal.minus(this.discount).add(this.tax); }

  get #currency(): string { return this.lines[0]?.unitPrice.currency ?? "EGP"; }

  #assertDraft(): void {
    if (this.#status !== "draft") throw new DomainError(`order is already ${this.#status}`);
  }
}

بالعامية

الـ Domain Model بينقل القواعد جوه objects بتحمي الـ invariants بتاعتها. Part 3 — Value Object & Entity 🟡 Intermediateالجزء 3 — الـ Value Object والـ Entity

English

A Value Object has no identity: two equal values are interchangeable. Money is immutable, compares by value, refuses a currency mismatch, and stores integer minor units so 0.1 + 0.2 can't bite. Email has a private constructor, so the only way to get one is through parse, and any Email you hold is already valid. An Entity is the opposite: same id means same thing, whatever else differs.

The traps are all at the edges. === on two equal Money objects is false. structuredClone and a JSON round trip both lose the class, so write toJSON and Money.from, and validate again on the way in. Storing money is in Section 07 · 3.7, and why a Money object needs care with coercion is in the Symbol.toPrimitive part.

import { DomainError } from "./errors.ts";

// فلوس دايمًا ⁦integer minor units (⁩قروش/سنتات⁦):⁩ عشان 0.1 + 0.2 مايعضّش
export class Money {
  readonly cents: number;
  readonly currency: string;

  private constructor(cents: number, currency: string) {
    this.cents = cents;
    this.currency = currency;
    Object.freeze(this);
  }

  static of(cents: number, currency: string): Money {
    if (!Number.isSafeInteger(cents)) throw new DomainError(`cents must be an integer, got ${cents}`);
    if (!/^[A-Z]{3}$/.test(currency)) throw new DomainError(`bad currency: ${currency}`);
    return new Money(cents, currency);
  }

  // الطريق الوحيد لرجوع Money من JSON أو queue، بيعيد الـ validation
  static from(raw: { cents: number; currency: string }): Money {
    return Money.of(raw.cents, raw.currency);
  }

  #assertSame(other: Money): void {
    if (other.currency !== this.currency) {
      throw new DomainError(`currency mismatch: ${this.currency} vs ${other.currency}`);
    }
  }
  add(other: Money): Money { this.#assertSame(other); return new Money(this.cents + other.cents, this.currency); }
  minus(other: Money): Money { this.#assertSame(other); return new Money(this.cents - other.cents, this.currency); }
  times(n: number): Money { return Money.of(this.cents * n, this.currency); }
  percent(p: number): Money { return new Money(Math.round((this.cents * p) / 100), this.currency); }
  isLessThan(other: Money): boolean { this.#assertSame(other); return this.cents < other.cents; }
  equals(other: Money): boolean { return this.cents === other.cents && this.currency === other.currency; }

  toJSON(): { cents: number; currency: string } { return { cents: this.cents, currency: this.currency }; }
  toDecimal(): string {
    const sign = this.cents < 0 ? "-" : "";

English

A Service Layer (Application Service) is the entry point for a use case. OrderService.place(cmd) loads what it needs, calls the domain, saves, and publishes. That is orchestration, not business logic: if you see a rule here, it wants to move into the domain. The transaction boundary lives here too, because the service is what knows that these writes belong together.

The test of a good service is that it doesn't care who called it. Below, the same place runs from an HTTP route, from a handler shaped like a BullMQ processor, and from a CLI script in a separate process. Pure CRUD with nothing to orchestrate doesn't need a service at all.

export interface PlaceOrderCommand {
  customerId: string;
  coupon?: string | undefined;
  lines: { productId: string; qty: number }[];

export class OrderService {
  #uow: UnitOfWork;
  constructor(uow: UnitOfWork) { this.#uow = uow; }

  // الـ service بينسّق وبس: يحمّل، يكلّم الـ domain، يحفظ، ينشر. مفيش حساب هنا
  place(cmd: PlaceOrderCommand): Promise<Order> {
    return this.#uow.run(async ({ products, coupons, orders, outbox }) => {
      const order = new Order(randomUUID(), cmd.customerId);
      if (cmd.coupon) {
        const coupon = await coupons.get(cmd.coupon);
        if (!coupon) throw new DomainError(`unknown coupon: ${cmd.coupon}`);
        order.applyCoupon(coupon);
      }
      for (const { productId, qty } of cmd.lines) {
        const product = await products.getForUpdate(productId);
        if (!product) throw new DomainError(`unknown product: ${productId}`);
        order.addLine(product, qty);
        await products.reserve(productId, qty);
      }
      order.place();
      await orders.save(order);
      await outbox.add("order.placed", { orderId: order.id, total: order.total });
      return order;
    });
  }
}

function reposFor(tx: PoolClient): Repos {
  return {
    products: {
      async getForUpdate(id) {
        const { rows } = await tx.query("SELECT * FROM products WHERE id = $1 FOR UPDATE", [id]);
        return rows[0] ? { id: rows[0].id, price: Money.of(rows[0].price_cents, "EGP"), stock: rows[0].stock } : null;
      },
      async reserve(id, qty) { await tx.query("UPDATE products SET stock = stock - $2 WHERE id = $1", [id, qty]); },
    },
    coupons: {
      async get(code) {
        const { rows } = await tx.query("SELECT * FROM coupons WHERE code = $1", [code]);
        return rows[0]
          ? { code: rows[0].code, percent: rows[0].percent, minSubtotal: Money.of(rows[0].min_subtotal_cents, "EGP") }
          : null;
      },
    },
    orders: {
      async save(o) {
        await tx.query(
          `INSERT INTO orders (id, customer_id, status, coupon, subtotal_cents, discount_cents, tax_cents, total_cents)
           VALUES ($1, $2, $3, $4, $5, $6, $7, $8)`, orderToRow(o));
        for (const l of o.lines) {
          await tx.query("INSERT INTO order_lines VALUES ($1, $2, $3, $4)", [o.id, l.productId, l.qty, l.unitPrice.cents]);
        }
      },
    },
    outbox: {
      async add(type, payload) { await tx.query("INSERT INTO outbox (type, payload) VALUES ($1, $2)", [type, payload]); },
    },
  };
}

export class PgUnitOfWork implements UnitOfWork {
  #pool: Pool;
  constructor(pool: Pool) { this.#pool = pool; }
  async run<T>(work: (repos: Repos) => Promise<T>): Promise<T> {
    const client = await this.#pool.connect();
    try {
      await client.query("BEGIN");
      const result = await work(reposFor(client));
      await client.query("COMMIT");
      return result;
    } catch (err) {
      await client.query("ROLLBACK");
      throw err;
    } finally {
      client.release();
    }
  }
}

class Percentage {
  readonly value: number;
  private constructor(value: number) { this.value = value; Object.freeze(this); }

  static of(value: number): Percentage {
    if (!Number.isInteger(value) || value < 0 || value > 100) {
      throw new DomainError(`percentage must be 0..100, got ${value}`);
    }
    return new Percentage(value);
  }
  applyTo(amount: Money): Money { return amount.percent(this.value); }
  equals(other: Percentage): boolean { return this.value === other.value; }
}

Cheat sheet · الخلاصة

  • Transaction Script: one procedure per use case. Right for CRUD; it rots when rules are copied.
  • Domain Model: rules live in objects that guard their invariants; tests run without a database.
  • Judge by domain complexity: an admin panel gets a script, a pricing engine gets a model.
  • Value Object: immutable, equal by value. Money in integer minor units, one currency per value.
  • structuredClone and JSON lose the class: write toJSON and Money.from.
  • Entity: same id means same thing. Branded types are the free alternative when you need no behaviour.
  • Service Layer orchestrates: load, call the domain, save, publish. It owns the transaction boundary.
  • A rule in a service wants to move to the domain; prove it with a characterization test.
  • Pass-through services are a smell. Pure CRUD doesn't need one.
  • One type per boundary: an explicit mapper plus input and output DTOs in Zod.
  • An output DTO is an allowlist; Omit is erased at runtime and guards nothing.
  • Start with a script; move when a rule is shared, repeated, or needs fast tests.
بالعامية
  • الـ Transaction Script: procedure واحد لكل use case. صح للـ CRUD، وبيبوظ لما القواعد تتنسخ.
  • الـ Domain Model: القواعد جوه objects بتحمي الـ invariants بتاعتها، والـ tests بتشتغل من غير database.
  • احكم حسب تعقيد الـ domain: الـ admin panel ليها script، والـ pricing engine ليه model.
  • الـ Value Object: immutable وبيتقارن بالقيمة. Money بالـ integer minor units وعملة واحدة لكل قيمة.
  • structuredClone والـ JSON بيضيّعوا الـ class: اكتب toJSON وMoney.from.
  • الـ Entity: نفس الـ id يعني نفس الشيء. والـ branded types بديل ببلاش لو مش محتاج behaviour.
  • الـ Service Layer بينسق: يحمّل، يكلّم الـ domain، يحفظ، وينشر، وهو صاحب حدود الـ transaction.
  • قاعدة جوه service مكانها الـ domain، وأثبت النقل بـ characterization test.
  • الـ pass-through services رائحة كود، والـ CRUD الصافي مش محتاج service.
  • type لكل حد: mapper صريح و input و output DTOs بـ Zod.
  • الـ output DTO هو allowlist، وOmit بيتمسح في الـ runtime ومش بيحمي حاجة.
  • ابدأ بـ script، وانقل لما قاعدة تتشارك أو تتكرر أو تحتاج tests سريعة.
