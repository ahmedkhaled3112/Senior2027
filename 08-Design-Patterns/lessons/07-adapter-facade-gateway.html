Why this matters · ليه ده مهم

English

Every backend depends on code it doesn't own: a payment SDK, a legacy ERP, an email provider. If that code's shapes reach your services, a vendor change becomes a change across your whole codebase. These three patterns put a boundary in place, and each works at a different size: Adapter over one interface, Facade over a subsystem, Gateway over a whole external system.

The harder question, and the one interviews ask, is what the wrapper costs. It can hide the vendor feature you need, and it can give you tests that stay green while production breaks. This lesson runs the real Stripe SDK against a local stand-in server, so every count below comes from a real run.

بالعامية

أي backend بيعتمد على كود مش بتاعه: SDK للدفع، ERP قديم، provider للإيميلات. لو الأشكال بتاعة الكود ده وصلت لجوه الـ services بتاعتك، أي تغيير من الـ vendor بيبقى تغيير في الـ codebase كله. التلات patterns دول بيحطوا حدود، وكل واحد على حجم مختلف: الـ Adapter فوق interface واحد، والـ Facade فوق subsystem، والـ Gateway فوق external system كامل.

السؤال الأصعب، وده اللي بيتسأل في الـ interviews: الـ wrapper ده بيكلفك إيه؟ ممكن يخبّي ميزة عند الـ vendor إنت محتاجها، وممكن يديك tests خضرا والـ production واقع. الدرس ده بيشغّل الـ Stripe SDK الحقيقي قدام stand-in server محلي، فكل رقم هتشوفه طالع من run حقيقي.

Part 1 — Adapter: your interface over a vendor SDK 🟢 Basicالجزء 1 — الـ Adapter: الـ interface بتاعك فوق SDK خارجي

English

An Adapter converts the interface of one object into the interface its caller expects. The important word is expects: the interface belongs to you and is written in your domain's terms, and the vendor is what gets bent to fit it.

Look at what leaks in the "before" version: the caller converts pounds to minor units by hand, and 19.99 * 100 is really 1998.9999999999998, while Stripe documents amount as a positive integer. It compares vendor status strings. It imports the vendor's error class and reads card_declined. Each of those appears in every service that takes a payment.

The "after" version has a PaymentProvider interface you own, plus one adapter per vendor that translates three things: amounts, statuses and errors. Translation tables are closed: a status the table doesn't know becomes an error instead of passing through silently. Both adapters then run the same contract test, so "a new provider works" has a definition you can execute.

Everything here is local. The Stripe adapter uses the real stripe 23.1.0 SDK pointed at a stand-in with { host, port, protocol: "http" }. No Stripe or Paymob account is involved. PaymobLikeAdapter is an illustrative shape, not Paymob's real API.

import Stripe from "stripe";
import {
  PaymentDeclinedError,
  PaymentProviderError,
  type Charge,
  type ChargeRequest,
  type ChargeStatus,
  type Currency,
  type DeclineReason,
  type Money,
  type PaymentProvider,
} from "./domain.ts";

// جدول الترجمة: أي status مش هنا بيتحوّل لـ error بدل ما يعدّي بصمت
const STATUS: Record<string, ChargeStatus> = {
  succeeded: "succeeded",
  requires_action: "requires_action",
  processing: "pending",
};
const DECLINE: Record<string, DeclineReason> = {
  insufficient_funds: "insufficient_funds",
  expired_card: "expired_card",
};

export class StripeAdapter implements PaymentProvider {
  #stripe: Stripe;
  constructor(stripe: Stripe) {
    this.#stripe = stripe;
  }

  async charge(req: ChargeRequest): Promise<Charge> {
    try {
      const intent = await this.#stripe.paymentIntents.create(
        {
          amount: req.amount.minor,
          currency: req.amount.currency.toLowerCase(),
          payment_method: req.paymentToken,
          confirm: true,
        },
        { idempotencyKey: req.idempotencyKey },
      );
      return toCharge(intent);
    } catch (err) {
      throw translateError(err);
    }
  }

  async refund(chargeId: string, amount: Money, idempotencyKey: string): Promise<void> {
    try {
      await this.#stripe.refunds.create({ payment_intent: chargeId, amount: amount.minor }, { idempotencyKey });
    } catch (err) {
      throw translateError(err);
    }
  }
}

function toCharge(intent: Stripe.PaymentIntent): Charge {
  const status = STATUS[intent.status];
  if (!status) throw new PaymentProviderError(`unknown stripe status: ${intent.status}`, false);
  const charge: Charge = {
    id: intent.id,
    status,
    amount: { minor: intent.amount, currency: intent.currency.toUpperCase() as Currency },
  };
  const url = intent.next_action?.redirect_to_url?.url;
  if (url) charge.actionUrl = url;
  return charge;
}

function translateError(err: unknown): Error {
  if (err instanceof PaymentProviderError) return err;
  if (err instanceof Stripe.errors.StripeCardError) {
    return new PaymentDeclinedError(DECLINE[err.decline_code ?? ""] ?? "other");
  }
  if (err instanceof Stripe.errors.StripeError) {
    return new PaymentProviderError(err.message, (err.statusCode ?? 500) >= 500);
  }
  return err instanceof Error ? err : new Error(String(err));
}

import {
  PaymentDeclinedError,
  PaymentProviderError,
  type Charge,
  type ChargeRequest,
  type ChargeStatus,
  type Currency,
  type DeclineReason,
  type Money,
  type PaymentProvider,
} from "./domain.ts";

type GwCharge = { txn: string; state: string; total?: string; cur?: string; otp_url?: string; reject_code?: string };

const DECIMALS: Record<Currency, number> = { EGP: 2, USD: 2, JPY: 0 };
const STATES: Record<string, ChargeStatus> = { PAID: "succeeded", OTP_REQUIRED: "requires_action", QUEUED: "pending" };
const REJECTS: Record<string, DeclineReason> = { E51: "insufficient_funds", E54: "expired_card" };

// (1) الترجمة هنا حقيقية: الـ minor integer بيبقى decimal string
export function minorToDecimal({ minor, currency }: Money): string {
  const d = DECIMALS[currency];
  return d === 0 ? String(minor) : (minor / 10 ** d).toFixed(d);
}
// (2) والرجوع بـ Math.round عشان الـ float ميطلعش 1998.9999999999998
export function decimalToMinor(total: string, currency: Currency): number {
  return Math.round(Number(total) * 10 ** DECIMALS[currency]);
}

export class PaymobLikeAdapter implements PaymentProvider {
  #baseUrl: string;
  constructor(baseUrl: string) {
    this.#baseUrl = baseUrl;
  }

  async charge(req: ChargeRequest): Promise<Charge> {
    const res = await fetch(`${this.#baseUrl}/gw/charges`, {
      method: "POST",
      headers: { "content-type": "application/json", "idempotency-key": req.idempotencyKey },
      body: JSON.stringify({
        total: minorToDecimal(req.amount),
        cur: req.amount.currency,
        token: req.paymentToken,
      }),
    });
    if (!res.ok) throw new PaymentProviderError(`gateway said ${res.status}`, res.status >= 500);
    const body = (await res.json()) as GwCharge;
    if (body.state === "REJECTED") throw new PaymentDeclinedError(REJECTS[body.reject_code ?? ""] ?? "other");
    const status = STATES[body.state];
    if (!status) throw new PaymentProviderError(`unknown gateway state: ${body.state}`, false);
    const charge: Charge = {
      id: body.txn,
      status,
      amount: { minor: decimalToMinor(body.total ?? "0", req.amount.currency), currency: req.amount.currency },
    };
    if (body.otp_url) charge.actionUrl = body.otp_url;
    return charge;
  }

  async refund(_chargeId: string, _amount: Money, _idempotencyKey: string): Promise<void> {
    throw new PaymentProviderError("refund not implemented in this illustrative adapter", false);
  }
}
// تنبيه: ده server محلي بديل (stand-in) مش Stripe ولا Paymob، ومفيش أي حساب حقيقي اتستخدم
import http from "node:http";
import type { AddressInfo } from "node:net";

export type Seen = { path: string; idempotencyKey: string | null; body: string };
export type VendorChange = { renameRequiresAction?: boolean };

export async function startProviderStandIn(change: VendorChange = {}) {
  const seen: Seen[] = [];
  const server = http.createServer((req, res) => {
    let body = "";
    req.on("data", (d) => (body += d));
    req.on("end", () => {
      const key = req.headers["idempotency-key"];
      seen.push({ path: req.url ?? "", idempotencyKey: typeof key === "string" ? key : null, body });
      res.setHeader("content-type", "application/json");
      const send = (status: number, payload: unknown) => {
        res.statusCode = status;
        res.end(JSON.stringify(payload));
      };

      // (1) شكل شبه Stripe: الـ body بـ form-encoded والمبلغ integer بالـ minor units
      if (req.url === "/v1/payment_intents") {
        const f = new URLSearchParams(body);
        const base = {
          id: "pi_1",
          object: "payment_intent",
          amount: Number(f.get("amount")),
          currency: f.get("currency"),
        };
        const pm = f.get("payment_method");
        if (pm === "tok_ok") return send(200, { ...base, status: "succeeded" });
        if (pm === "tok_3ds") {
          // المحاكاة دي بتمثّل تغيير من الـ vendor: اسم الـ status اتغيّر فجأة
          const status = change.renameRequiresAction ? "requires_customer_step" : "requires_action";
          const next_action = { type: "redirect_to_url", redirect_to_url: { url: "https://bank.test/3ds" } };
          return send(200, { ...base, status, next_action });
        }
        if (pm === "tok_no_funds") {
          const error = {
            type: "card_error",
            code: "card_declined",
            decline_code: "insufficient_funds",
            message: "Your card has insufficient funds.",
          };
          return send(402, { error });
        }
        return send(500, { error: { type: "api_error", message: "boom" } });
      }

      // (2) شكل توضيحي عام لـ provider تاني: الـ body بـ JSON والمبلغ decimal string
      if (req.url === "/gw/charges") {
        const b = JSON.parse(body) as { total: string; cur: string; token: string };
        if (b.token === "tok_ok") return send(200, { txn: "pb_1", state: "PAID", total: b.total, cur: b.cur });
        if (b.token === "tok_3ds") {
          return send(200, { txn: "pb_2", state: "OTP_REQUIRED", total: b.total, cur: b.cur, otp_url: "https://bank.test/otp" });
        }
        if (b.token === "tok_no_funds") return send(200, { txn: "pb_3", state: "REJECTED", reject_code: "E51" });
        return send(503, { message: "maintenance" });
      }
      send(404, { message: "not found" });
    });
  });
  await new Promise<void>((r) => server.listen(0, "127.0.0.1", r));
  const { port } = server.address() as AddressInfo;
  return { port, seen, stop: () => new Promise((r) => server.close(r)) };
}

import { after, before, describe, it } from "node:test";
import assert from "node:assert/strict";
import Stripe from "stripe";
import { PaymentDeclinedError, type PaymentProvider } from "./domain.ts";
import { PaymobLikeAdapter } from "./other-adapter.ts";
import { startProviderStandIn } from "./stand-in.ts";
import { StripeAdapter } from "./stripe-adapter.ts";

type Api = Awaited<ReturnType<typeof startProviderStandIn>>;

function paymentProviderContract(name: string, make: (api: Api) => PaymentProvider) {
  describe(`contract: ${name}`, () => {
    let api: Api;
    let provider: PaymentProvider;
    before(async () => {
      api = await startProviderStandIn();
      provider = make(api);
    });
    after(() => api.stop());

    const amount = { minor: 12345, currency: "EGP" } as const;

    it("approved charge keeps the exact amount", async () => {
      const c = await provider.charge({ amount, paymentToken: "tok_ok", idempotencyKey: "k1" });
      assert.equal(c.status, "succeeded");
      assert.deepEqual(c.amount, amount);
    });

    it("3DS maps to requires_action with a url", async () => {
      const c = await provider.charge({ amount, paymentToken: "tok_3ds", idempotencyKey: "k2" });
      assert.equal(c.status, "requires_action");
      assert.match(c.actionUrl ?? "", /^https:/);
    });

    it("decline maps to a domain error", async () => {
      await assert.rejects(
        provider.charge({ amount, paymentToken: "tok_no_funds", idempotencyKey: "k3" }),
        (e: unknown) => e instanceof PaymentDeclinedError && e.reason === "insufficient_funds",
      );
    });

    it("idempotency key reaches the server", async () => {
      await provider.charge({ amount, paymentToken: "tok_ok", idempotencyKey: "order-42" });
      assert.equal(api.seen.at(-1)?.idempotencyKey, "order-42");
    });
  });
}

بالعامية

الـ Adapter بيحوّل الـ interface بتاع object لـ interface تاني الـ caller مستنيه. الكلمة المهمة هنا "مستنيه": الـ interface بتاعك إنت ومكتوب بلغة الـ domain بتاعك، والـ vendor هو اللي بيتظبط عليه.

بص إيه اللي بيتسرب في نسخة "قبل": الـ caller بيحوّل من جنيه لـ minor units بإيده، و19.99 * 100 بتطلع فعلًا 1998.9999999999998، مع إن Stripe كاتب في الـ docs إن amount لازم يبقى positive integer. وبيقارن strings بتاعة status الـ vendor. وبيعمل import للـ error class بتاع الـ vendor ويقرا card_declined. وكل ده بيتكرر في أي service بتاخد فلوس.

في نسخة "بعد" عندك interface اسمه PaymentProvider بتاعك، وadapter لكل vendor بيترجم 3 حاجات: المبالغ والـ statuses والـ errors. وجداول الترجمة مقفولة: أي status مش موجود في الجدول بيتحول لـ error بدل ما يعدّي بصمت. والـ adapterين بيشغلوا نفس الـ contract test، فجملة "الـ provider الجديد شغال" بقى ليها تعريف تقدر تشغّله.

كل ده محلي. الـ Stripe adapter بيستخدم الـ stripe 23.1.0 SDK الحقيقي وموجّه لـ stand-in بـ { host, port, protocol: "http" }. ومفيش أي حساب Stripe أو Paymob اتستخدم. والـ PaymobLikeAdapter شكل توضيحي، مش الـ API الحقيقي بتاع Paymob.

الغلطة الشائعة: تعمل default في جدول الترجمة، زي إن أي status غريب يبقى pending. كده الـ order هيفضل معلق ومحدش هياخد باله.

فين هستخدمه في شغلي؟ الـ checkout بتاعك في Express بيكلّم Stripe، والشركة عايزة تضيف Paymob للسوق المصري. من غير adapter هتدور على كل intent.status وerr.code في 12 ملف. بالـ adapter بتكتب كلاس واحد جديد، وتشغّل عليه نفس الـ contract، والـ checkout ميتلمسش. وفي الـ tests بتدي الـ OrderService أي PaymentProvider بسيط من غير ما تعمل mock للـ SDK.
When not to use it A pass-through that translates nothing, used from one call site, for a vendor you will never replace or fake, adds a file and a name and nothing else. An adapter earns its place when it translates something, or when you need a test seam.
الـ pass-through اللي مش بيترجم أي حاجة، ومستخدم في مكان واحد، لـ vendor عمرك ما هتغيّره ولا هتعمل له fake، بيزوّد ملف واسم وخلاص. الـ adapter بيستاهل مكانه لما يترجم حاجة فعلًا، أو لما تكون محتاج نقطة تدخل للـ tests.
Interview question "Why not call the Stripe SDK directly from the service?" → It works until something needs to change. The service then knows the vendor's units, statuses and errors, can't be tested without faking the SDK, and a second provider means editing every caller. The adapter puts that knowledge in one file and gives you one test suite for each provider. If there's one call site and nothing to translate, calling it directly is the right answer.
"ليه متنادي الـ Stripe SDK مباشرة من الـ service؟" ← ده شغال لحد ما حاجة تتغير. الـ service ساعتها بيبقى عارف وحدات الـ vendor والـ statuses والـ errors بتاعته، ومينفعش يتعمله test من غير fake للـ SDK، وأي provider تاني معناه تعديل كل caller. الـ adapter بيحط المعرفة دي في ملف واحد ويديك test suite واحد لكل provider. ولو عندك call site واحد ومفيش حاجة تتترجم، النداء المباشر هو الإجابة الصح.

Part 2 — Adapter in depth: object, class, two-way 🟡 Intermediateالجزء 2 — الـ Adapter بعمق: object و class و two-way

English

GoF describes two structures. An object adapter holds the vendor object and delegates to it. A class adapter inherits from it. In TypeScript the object adapter is the default, and the reason is what each one exposes: inheritance publishes the entire parent. The run below counts it: the object adapter exposes 2 names and the class adapter 121, including customers and payouts. Any caller can reach around your contract, and your tests can't tell.

A two-way adapter implements both interfaces. It exists for migrations: during the move, callers of the old chargeCard(cents) can reach the new API, and callers of the new pay({ amount }) can reach the old one, so traffic can move in stages. Keep each side's error style, make rollout decisions sticky per customer, and give the adapter a removal date that a test enforces.

The smallest adapter in Node is util.promisify: same operation, with the interface changed from a callback to a Promise. util.callbackify goes the other way. Its classic trap is this: pass an unbound method and it fails at call time.

export class TwoWayBillingAdapter implements LegacyBilling, ModernPayments {

Part 3 — Anti-Corruption Layer 🟡 Intermediateالجزء 3 — الـ Anti-Corruption Layer

English

An Adapter translates an interface. An Anti-Corruption Layer (ACL) translates a model. A legacy ERP sends { CUST_NO, STAT_CD: "A", AMT: "00012345" }; that isn't just awkward naming, it's another system's way of thinking about a customer. The ACL is the only code allowed to know that model, and it gives the rest of your service a Customer and a Money, in both directions.

The defining rule is what happens with something unknown. The bad version says "anything that isn't S is active", so a new ERP code F (frozen for fraud review) becomes an active customer who can buy. A good ACL fails loudly and increments a metric. It never picks a default for a value it doesn't understand, because a wrong default is silent data corruption, and that is exactly what the layer is named after.

Legacy data is messy, so test it as a table: leading zeros, padding, lowercase codes, a COBOL-style trailing minus, wrong JavaScript types, missing fields. Below, 20 payloads: 10 translated, 10 rejected, and the metric says which field failed.

An ACL sits at the boundary between models. Here it's a module in your service; section 09 · 3.3 covers it between services and legacy systems.

// الـ ACL: الموديل بتاع الـ ERP بيقف هنا، وجوه الـ service مفيش غير Customer و Money
export type LegacyCustomerRow = {
  CUST_NO: string;
  STAT_CD: string;
  AMT: string;
};

export type CustomerStatus = "active" | "suspended" | "closed";
export type Money = { minor: number; currency: "EGP" };
export type Customer = { id: string; status: CustomerStatus; balance: Money };

export class LegacyTranslationError extends Error {
  readonly field: string;
  readonly raw: unknown;
  constructor(field: string, raw: unknown) {
    super(`cannot translate ${field}: ${JSON.stringify(raw)}`);
    this.name = "LegacyTranslationError";
    this.field = field;
    this.raw = raw;
  }
}

// عدّاد بسيط مكان الـ metric الحقيقي، عشان الـ dashboard يبان عليه الكود الغريب
export const translationFailures = new Map<string, number>();
function fail(field: string, raw: unknown): never {
  translationFailures.set(field, (translationFailures.get(field) ?? 0) + 1);
  throw new LegacyTranslationError(field, raw);
}

const STATUS_FROM_LEGACY: Record<string, CustomerStatus> = { A: "active", S: "suspended", C: "closed" };
const STATUS_TO_LEGACY: Record<CustomerStatus, string> = { active: "A", suspended: "S", closed: "C" };

// الـ AMT بيجي padded ومكتوب بالقروش، وأحيانًا السالب في الآخر زي الـ COBOL
function parseAmount(raw: unknown): number {
  if (typeof raw !== "string") return fail("AMT", raw);
  const m = /^\s*(\d{1,12})(-?)\s*$/.exec(raw);
  if (!m) return fail("AMT", raw);
  const value = Number(m[1]);
  return m[2] === "-" ? -value : value;
}

export function customerFromLegacy(row: LegacyCustomerRow): Customer {
  const id = typeof row.CUST_NO === "string" ? row.CUST_NO.trim().replace(/^0+(?=\d)/, "") : "";
  if (!/^\d+$/.test(id)) fail("CUST_NO", row.CUST_NO);
  const code = typeof row.STAT_CD === "string" ? row.STAT_CD.trim().toUpperCase() : "";
  const status = STATUS_FROM_LEGACY[code];
  if (!status) fail("STAT_CD", row.STAT_CD);
  return { id, status, balance: { minor: parseAmount(row.AMT), currency: "EGP" } };
}

// الاتجاه التاني: الـ ERP عايز 8 خانات بالظبط، والـ id بـ 10 خانات padded
export function customerToLegacy(c: Customer): LegacyCustomerRow {
  const digits = String(Math.abs(c.balance.minor)).padStart(8, "0");
  return {
    CUST_NO: c.id.padStart(10, "0"),
    STAT_CD: STATUS_TO_LEGACY[c.status],
    AMT: c.balance.minor < 0 ? `${digits}-` : digits,
  };
}

شمال: موديل الـ ERP بأسماءه الغريبة. في النص: الـ ACL، وهو الكود الوحيد اللي يعرف الموديل ده، وبيترجم في الاتجاهين. يمين: الـ service بيشوف Customer وMoney بس. وأي قيمة مش معروفة بتنزل لتحت: throw وزيادة في الـ metric، مش default.
بالعامية

الـ Adapter بيترجم interface. الـ Anti-Corruption Layer (ACL) بيترجم موديل. الـ ERP القديم بيبعت { CUST_NO, STAT_CD: "A", AMT: "00012345" }، ودي مش مجرد أسماء وحشة، دي طريقة نظام تاني في التفكير في العميل. الـ ACL هو الكود الوحيد المسموح له يعرف الموديل ده، وبيدي باقي الـ service بتاعك Customer وMoney، في الاتجاهين.

القاعدة اللي بتعرّفه هي بيحصل إيه مع حاجة مش معروفة. النسخة السيئة بتقول "أي حاجة مش S تبقى active"، فكود جديد في الـ ERP زي F (موقوف لمراجعة fraud) بيبقى عميل active يقدر يشتري. الـ ACL الكويس بيقع بصوت عالي ويزوّد metric. عمره ما بيختار default لقيمة مش فاهمها، لأن الـ default الغلط ده data corruption ساكت، وده بالظبط اللي الطبقة دي واخدة اسمها منه.

الـ data القديمة مبهدلة، فاعمل لها table test: أصفار على الشمال، مسافات، أكواد lowercase، علامة سالب في الآخر بطريقة COBOL، أنواع JavaScript غلط، حقول ناقصة. فوق 20 payload: 10 اتترجموا و10 اترفضوا، والـ metric بيقول أنهي حقل وقع.

الـ ACL بيقعد على الحدود بين الموديلات. هنا هو module جوه الـ service، والقسم 09 · 3.3 بيغطيه بين الـ services والأنظمة القديمة.

الغلطة الشائعة: STATUS[code] ?? "active". سطر واحد، وعميل موقوف بقى يقدر يدفع.

فين هستخدمه في شغلي؟ الشركة عندها نظام مالي قديم بيطلّع ملفات أو SOAP، وإنت بتبني Node service جديد فوقه. لو سيبت STAT_CD وAMT يدخلوا الـ Prisma models بتاعتك، الموديل القديم هيفضل عايش في كودك سنين. بتحط ACL عند الـ consumer اللي بيقرا من النظام ده، وتعمل alert على الـ metric، ولما حد في الـ ERP يضيف كود جديد هتعرف في نفس اليوم مش بعد ما العملاء يشتكوا.
When not to use it If both sides already share a stable model, such as two modules you own with the same Customer, an ACL is translation between two identical things. Use it when the other model is really different and you don't control it.
لو الناحيتين عندهم موديل واحد مستقر، زي اتنين modules بتوعك بنفس الـ Customer، الـ ACL هيبقى ترجمة بين حاجتين زي بعض. استخدمه لما الموديل التاني يكون مختلف فعلًا ومش في إيدك.

Part 4 — Facade 🟢 Basicالجزء 4 — الـ Facade

English

A Facade gives a simple interface to a group of objects that have to be used together. Sending one notification needs preferences, a template, and up to three channels, in the right order. Scatter that across 6 call sites and they drift. The three shown below (of the 6) produce two real bugs: one sends SMS before checking preferences, so a user who opted out gets a message, and one forgot push entirely.

After the change, each call site is one line: notifications.send(userId, "order.shipped", data). The order now lives in one place and is covered by fakes that record every call, so the test proves ordering and counts, not just a return value.

Two limits worth knowing. A Facade simplifies many objects; it doesn't translate one (that's Adapter). And it doesn't stop direct access: the second test calls the SMS sender straight past the Facade. If you need enforcement, that's a job for module boundaries or a lint rule.

The trap is the god facade, the AppService with 40 methods that every module imports. A rule of thumb, not a law: split when it passes roughly 7–10 public methods, when groups of methods share no collaborators, or when most callers use only one or two methods.

// الـ subsystem: كل واحد فيهم بسيط، بس الترتيب والتنسيق بينهم هو اللي بيتعب
export type Channel = "email" | "sms" | "push";
export type Trail = string[];

export function makeSubsystem(trail: Trail) {
  const prefs: Record<string, Channel[]> = {
    u_all: ["email", "sms", "push"],
    u_email_only: ["email"],
    u_none: [],
  };
  return {
    preferences: {
      async channelsFor(userId: string): Promise<Channel[]> {
        trail.push(`prefs:${userId}`);
        return prefs[userId] ?? [];
      },
    },
    templates: {
      render(event: string, channel: Channel, data: Record<string, string>): string {
        trail.push(`render:${channel}`);
        return `[${channel}] ${event} ${JSON.stringify(data)}`;
      },
    },
    email: { async send(userId: string, _body: string) { trail.push(`email:${userId}`); } },
    sms: { async send(userId: string, _body: string) { trail.push(`sms:${userId}`); } },
    push: { async send(userId: string, _body: string) { trail.push(`push:${userId}`); } },
  };
}
export type Subsystem = ReturnType<typeof makeSubsystem>;

}

فين هستخدمه في شغلي؟ أي service عنده sendEmail وsendSms متنادين من الـ orders والـ payments والـ refunds. بتعمل notifications.send واحدة، وتحط وراها الـ preferences. لما الـ legal يطلب "مفيش SMS بعد 10 بالليل" بتعدّل مكان واحد. وفي Next.js نفس الفكرة: getProductPage(slug) بتجمع product وreviews وstock من 3 data sources، والـ Server Component ينادي function واحدة.

Part 5 — Gateway 🟡 Intermediateالجزء 5 — الـ Gateway

English

Fowler defines a Gateway as "an object that encapsulates access to an external system or resource". Think of it as an Adapter at system level. An adapter maps shapes; a gateway owns the whole conversation: timeouts, auth refresh, idempotency keys, error mapping, pagination and metrics.

The stand-in below (local, port 0) hangs, returns 429 with Retry-After, returns 500 and expires tokens on command. Read the numbers: the hung call is aborted at about 1 s by AbortSignal.timeout, the 429 waits the requested second, the 500s back off, and the 401 refreshes the token once, without using up a retry attempt. Every retry sends the same idempotency key. That's what makes retrying a POST safe, because a timeout tells you nothing about whether the charge happened.

Note the cost: with 3 attempts at 1 s each, a dead provider holds the caller for about 3 s, which is the hungAlways line. The retry policy here is deliberately small. Jitter, deadlines and fallbacks are taught in lesson 22, and breakers in lesson 23.

Retry-After can be a number of seconds or an HTTP date, and Number() on a date is NaN, so retryAfterMs handles both and caps the wait. Section 09 · 2.3 places Repository and Gateway within ports and adapters (the hexagonal lesson shows the structure).

// تنبيه: ده stand-in محلي على port 0 بيمثّل payment API بيهنّج ويرجع 429 و 500 و 401
import http from "node:http";
import type { AddressInfo } from "node:net";

type Hit = { path: string; idempotencyKey: string | null; auth: string | null };
type Script = { [scenario: string]: Array<"hang" | "429" | "500" | "401" | "ok"> };

export async function startGatewayStandIn(script: Script) {
  const hits: Hit[] = [];
  const tokens = { issued: 0, valid: "" };
  const hanging = new Set<http.ServerResponse>();
  const server = http.createServer((req, res) => {
    let body = "";
    req.on("data", (d) => (body += d));
    req.on("end", () => {
      const url = new URL(req.url ?? "/", "http://x");
      const key = req.headers["idempotency-key"];
      const auth = req.headers["authorization"] ?? null;
      hits.push({ path: url.pathname, idempotencyKey: typeof key === "string" ? key : null, auth });
      const send = (status: number, payload: unknown, headers: Record<string, string> = {}) => {
        res.writeHead(status, { "content-type": "application/json", ...headers });
        res.end(JSON.stringify(payload));
      };

      if (url.pathname === "/oauth/token") {
        tokens.issued++;
        tokens.valid = `token-${tokens.issued}`;
        return send(200, { access_token: tokens.valid, expires_in: 3600 });
      }
      if (auth !== `Bearer ${tokens.valid}`) return send(401, { message: "expired token" });

      if (url.pathname === "/charges" && req.method === "GET") {
        const page = Number(url.searchParams.get("cursor") ?? 0);
        const items = Array.from({ length: 2 }, (_, i) => ({ id: `ch_${page}_${i}`, amount: 100 }));
        return send(200, { items, next: page < 2 ? String(page + 1) : null });
      }

      const scenario = JSON.parse(body || "{}").scenario as string;
      const step = script[scenario]?.shift() ?? "ok";
      if (step === "hang") {
        hanging.add(res);
        return;
      }
      if (step === "429") return send(429, { message: "slow down" }, { "retry-after": "1" });
      if (step === "500") return send(500, { message: "boom" });
      if (step === "401") {
        tokens.valid = "";
        return send(401, { message: "expired token" });
      }
      send(200, { id: `ch_${scenario}`, state: "captured" });
    });
  });
  await new Promise<void>((r) => server.listen(0, "127.0.0.1", r));
  const { port } = server.address() as AddressInfo;
  return {
    port,
    hits,
    tokens,
    stop: () =>
      new Promise((r) => {
        for (const res of hanging) res.destroy();
        server.closeAllConnections();
        server.close(r);
      }),
  };
}
// الـ Gateway: حاجة واحدة بتعرف كل تفاصيل الكلام مع الـ payment system الخارجي
export class GatewayTimeoutError extends Error { override name = "GatewayTimeoutError"; }
export class GatewayUnavailableError extends Error { override name = "GatewayUnavailableError"; }

export type GatewayCharge = { id: string; state: string };
export type GatewayConfig = {
  baseUrl: string;
  clientSecret: string;
  timeoutMs: number;
  maxAttempts: number;
  backoffMs: number;
};
export type Outcome = "ok" | "timeout" | "rate_limited" | "server_error" | "auth_refreshed";

export class PaymentGateway {
  #cfg: GatewayConfig;
  #token = "";
  // المقاييس: بعدّها هنا عشان الـ dashboard يقرا مكان واحد
  readonly metrics: Record<Outcome, number> = { ok: 0, timeout: 0, rate_limited: 0, server_error: 0, auth_refreshed: 0 };

  constructor(cfg: GatewayConfig) {
    this.#cfg = cfg;
  }

  async charge(input: { scenario: string; amountMinor: number }, idempotencyKey: string): Promise<GatewayCharge> {
    const res = await this.#send("/charges", { method: "POST", body: JSON.stringify(input) }, idempotencyKey);
    return (await res.json()) as GatewayCharge;
  }

  // الـ pagination مستخبية: الـ caller بيعمل for await وخلاص
  async *listCharges(): AsyncGenerator<{ id: string; amount: number }> {
    let cursor: string | null = "0";
    while (cursor !== null) {
      const res = await this.#send(`/charges?cursor=${cursor}`, { method: "GET" });
      const page = (await res.json()) as { items: { id: string; amount: number }[]; next: string | null };
      yield* page.items;
      cursor = page.next;
    }
  }

  async #refreshToken(): Promise<void> {
    const res = await fetch(`${this.#cfg.baseUrl}/oauth/token`, {
      method: "POST",
      body: JSON.stringify({ secret: this.#cfg.clientSecret }),
      signal: AbortSignal.timeout(this.#cfg.timeoutMs),
    });
    this.#token = ((await res.json()) as { access_token: string }).access_token;
  }

  async #send(path: string, init: RequestInit, idempotencyKey?: string): Promise<Response> {
    if (!this.#token) await this.#refreshToken();
    let refreshed = false;
    let attempt = 0;
    while (true) {
      attempt++;
      const headers: Record<string, string> = { authorization: `Bearer ${this.#token}` };
      // نفس المفتاح في كل محاولة: ده اللي بيمنع إن العميل يتخصم مرتين
      if (idempotencyKey) headers["idempotency-key"] = idempotencyKey;
      try {
        const res = await fetch(this.#cfg.baseUrl + path, {
          ...init,
          headers,
          signal: AbortSignal.timeout(this.#cfg.timeoutMs),
        });
        if (res.ok) {
          this.metrics.ok++;
          return res;
        }
        await res.body?.cancel();
        if (res.status === 401 && !refreshed) {
          // تجديد الـ token مرة واحدة بس ومش بيتحسب من الـ attempts
          refreshed = true;
          attempt--;
          this.metrics.auth_refreshed++;
          await this.#refreshToken();
          continue;
        }
        if (res.status === 429) {
          this.metrics.rate_limited++;
          if (attempt >= this.#cfg.maxAttempts) throw new GatewayUnavailableError("rate limited");
          await sleep(retryAfterMs(res.headers.get("retry-after"), this.#cfg.backoffMs));
          continue;
        }
        if (res.status >= 500) {
          this.metrics.server_error++;
          if (attempt >= this.#cfg.maxAttempts) throw new GatewayUnavailableError(`status ${res.status}`);
          await sleep(this.#cfg.backoffMs * 2 ** (attempt - 1));
          continue;
        }
        throw new Error(`gateway rejected: ${res.status}`);
      } catch (err) {
        if (err instanceof DOMException && err.name === "TimeoutError") {
          this.metrics.timeout++;
          if (attempt >= this.#cfg.maxAttempts) throw new GatewayTimeoutError(`no answer in ${this.#cfg.timeoutMs} ms`);
          continue;
        }
        throw err;
      }
    }
  }
}

const sleep = (ms: number) => new Promise((r) => setTimeout(r, ms));

// الـ Retry-After يا إما ثواني يا إما تاريخ HTTP، و Number على التاريخ بيطلع NaN
export function retryAfterMs(header: string | null, fallbackMs: number, now = Date.now()): number {
  if (header === null) return fallbackMs;
  const seconds = Number(header);
  const ms = Number.isNaN(seconds) ? Date.parse(header) - now : seconds * 1000;
  if (Number.isNaN(ms) || ms < 0) return fallbackMs;
  return Math.min(ms, 30_000);
}

Part 6 — What a wrapper costs 🟡 Intermediateالجزء 6 — الـ wrapper بيكلفك إيه

English

A shared interface is limited to what every provider can do, the lowest common denominator. Stripe's 3DS flow and its webhooks are exactly the kind of thing a second provider may lack or do differently. There are three honest ways out, and each one leaks something. The code below shows a capability interface, a provider-specific method and a raw() escape hatch. Webhooks are usually provider-specific by nature, since each vendor signs them differently: verify inside that provider's adapter and emit a domain event.

A real example to read: BullMQ 6.5.4 wraps two Redis clients behind one interface. In dist/esm/classes/node-redis-client.js:21, NodeRedisAdapter carries the comment "Full wrapper (not augmentation) because node-redis's API is structurally different from ioredis and cannot be patched in-place". bun-redis-client.js:47 has BunRedisAdapter. Both extend EventEmitter and translate each client's state into one status vocabulary (wait, connect, ready, end), and the contract is IRedisClient in dist/esm/interfaces/redis-client.d.ts:16. The Bun adapter's own comment calls Bun's send() "the universal escape hatch", which is the raw() trade-off inside a major library.

Finally, which test catches a vendor change? Below the vendor renames a status. The test that mocks the SDK stays green, because the mock replays your old assumption. The contract test running the real SDK against the changed response fails. One honest limit: a stand-in only knows what you taught it, so the catch that protects production is the same contract run on a schedule against the vendor's sandbox (not run here, because it needs an account).

The mechanical steps for extracting an adapter from existing code are in lesson 31.

type Money = { minor: number; currency: Currency };

const DECIMALS: Record<Currency, number> = { EGP: 2, USD: 2, JPY: 0, KWD: 3 };

function minorToDecimal({ minor, currency }: Money): string {
  const d = DECIMALS[currency];
  return d === 0 ? String(minor) : (minor / 10 ** d).toFixed(d);
}

console.log(minorToDecimal({ minor: 12345, currency: "EGP" }));
console.log(minorToDecimal({ minor: 500, currency: "JPY" }));

Cheat sheet · الخلاصة

  • Adapter: an interface you own over one vendor; translate amounts, statuses and errors.
  • Translation tables are closed: unknown means an error and a metric, never a default.
  • Object adapter by default. Inheriting from the SDK exposed 121 names instead of 2.
  • Two-way adapter: for migrations only, sticky rollout, a removal date enforced by a test.
  • util.promisify is the smallest adapter in Node; bind methods first.
  • ACL translates a model, in both directions, and is tested with a table of messy payloads.
  • Facade simplifies many objects, doesn't translate one, and doesn't block direct access. Split it past roughly 7–10 methods.
  • Gateway owns the conversation: timeout, auth refresh, idempotency, error mapping, paging, metrics.
  • The same idempotency key on every retry. One layer owns retries.
  • Provider-only feature: capability interface, then provider-specific method, then raw().
  • A mocked SDK stayed green through a vendor change; run the contract against the vendor's sandbox on a schedule.
بالعامية
  • الـ Adapter: interface بتاعك فوق vendor واحد، وبيترجم المبالغ والـ statuses والـ errors.
  • جداول الترجمة مقفولة: المجهول يبقى error و metric، عمره ما يبقى default.
  • الـ object adapter هو الأساس. الوراثة من الـ SDK كشفت 121 اسم بدل 2.
  • الـ two-way adapter: للـ migrations بس، وrollout ثابت لكل customer، وتاريخ شيل بيفرضه test.
  • util.promisify أصغر adapter في Node، واعمل bind للـ methods الأول.
  • الـ ACL بيترجم موديل في الاتجاهين، وبيتعمله test بجدول payloads مبهدلة.
  • الـ Facade بيبسّط objects كتير، ومش بيترجم واحد، ومش بيمنع الوصول المباشر. وقسّمه لما يعدّي حوالي 7 لـ 10 methods.
  • الـ Gateway بيملك الكلام كله: timeout وتجديد auth وidempotency وترجمة errors وpagination وmetrics.
  • نفس الـ idempotency key في كل retry، وطبقة واحدة بس هي اللي تملك الـ retries.
  • ميزة عند provider واحد: capability interface، وبعدها provider-specific method، وبعدها raw().
  • الـ SDK المعمول له mock فضل أخضر رغم تغيير الـ vendor، فشغّل الـ contract على sandbox الـ vendor بشكل دوري.
