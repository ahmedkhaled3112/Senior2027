Why this matters · ليه ده مهم

English

Sooner or later someone hands you a design and asks "is this OK?", or hands you a codebase and asks "should we buy this?". A senior answers with evidence inside a fixed amount of time. In this lesson you review the shared orders service for real: a scanner answers half the checklist, and killing its dependencies produces findings nobody saw in the code. One of them is that a Postgres restart kills the whole Node process. Then you run the same discipline on a codebase you've never seen, and write it up for a CTO and for an investor. Scripts go in a new l37/ folder next to after/.

Part 1 — The checklist 🔴 Advancedالجزء 1 — الـ checklist

English

An architecture review asks six kinds of question, and each one is only useful if you know what would answer it. Boundaries: who may call whom, answered by the dependency graph. Data ownership: which module is the single writer of each table, answered by grepping the writes. Failure modes: what happens when each dependency fails, answered by an experiment. Security: who can do what to which object, answered by reading the authorization path. Observability: could on-call explain a failed order, answered by the logs and metrics that exist today. Cost: what grows with traffic and history, answered by a query plan or a bill.

A finding has three parts: the risk in business terms, the evidence that shows it's real, and a suggestion. "This won't scale" has none of them, so it's an opinion, and the author can only argue with it or ignore it. Without evidence you are asking the author to trust your taste.

Below, the checklist is applied as data to the RFC from lesson 34, "move order emails to an outbox". Every evidence line is a true statement about the code in after/: the event type really has no customer email in it, and the schema really has no index on published_at.

بالعامية

الـ architecture review فيه 6 أنواع أسئلة، وكل سؤال بيفيد بس لو عارف إيه اللي بيجاوبه. الـ boundaries: مين يقدر يكلّم مين، والـ dependency graph بيجاوب. الـ data ownership: أنهي module هو الكاتب الوحيد لكل جدول، والـ grep على الكتابات بيجاوب. الـ failure modes: إيه اللي بيحصل لما كل dependency تقع، والتجربة بتجاوب. الـ security: مين يقدر يعمل إيه في أنهي object، وقراية مسار الـ authorization بتجاوب. الـ observability: هل الـ on-call يقدر يشرح order فشل، واللي بيجاوب الـ logs والـ metrics الموجودة فعلًا النهارده. الـ cost: إيه اللي بيكبر مع الـ traffic والتاريخ، والـ query plan أو الفاتورة بيجاوبوا.

الـ finding ليه 3 حاجات: الـ risk بلغة الـ business، والـ evidence اللي بتثبت إنه حقيقي، وsuggestion. جملة "ده مش هيستحمل scale" مفيهاش ولا واحدة منهم، فهي رأي، والـ author يا يجادل فيها يا يتجاهلها. من غير دليل إنت بتطلب منه يثق في ذوقك.

فوق، الـ checklist متطبّق كـ data على الـ RFC بتاع الدرس 34، "نقل إيميلات الـ orders لـ outbox". وكل سطر evidence جملة صح عن الكود في after/: الـ event فعلًا مفيهوش إيميل العميل، والـ schema فعلًا مفيهاش index على published_at.

فين هستخدمه في شغلي؟ زميلك فتح design doc إنه ينقل حساب الفواتير لـ service لوحده. بدل ما تكتب "أنا قلقان"، بتمشي على الـ 6 مناطق في 30 دقيقة: مين هيكتب في جدول invoices بعد النقل؟ لو الـ service الجديد وقع، الـ checkout هيعمل إيه؟ وكل قلق بيتكتب risk و evidence و suggestion. الزميل بيعرف بالظبط يصلّح إيه، وإنت مش محتاج تقعد اجتماع.

Part 2 — Automate half of it 🔴 Advancedالجزء 2 — نص الـ checklist بيشتغل لوحده

English

Half of those questions have mechanical answers, and a person shouldn't spend review time on them. review-scan.mjs runs the architecture rules from lesson 16 and four text checks: process.env outside a config module, fetch with no deadline, SQL built by string, and missing health endpoints. Its report has three verdicts: yes, no and needs a human. That third verdict is the honest part: a script can't say whether a table has the right owner, so it should say that it can't.

A checker is itself code that can be wrong, so we prove it. plant.mjs copies the service and plants two problems: it removes the payment deadline and builds a catalog query by string concatenation. Both get flagged with file and line. Note what the clean run also found by itself: there's no health endpoint in after/src, a real gap nobody had planted.

On the planted copy the architecture rules report "needs a human", because the rules are anchored to after/src. Reporting "yes" there would be the same false green that lesson 16 caught, where a tool passes because it looked at 0 modules. These checks are regexes, so they can miss a fetch behind a wrapper or flag a harmless string. That's fine for a first pass, and it's another reason a human reads the "no" list.

// ملف l37/review-scan.mjs: نص الـ checklist اللي الماكينة تقدر تجاوبه لوحدها
// التشغيل: ⁦node l37/review-scan.mjs after/src [--json]⁩
import { spawnSync } from "node:child_process";
import { readFileSync, readdirSync } from "node:fs";
import path from "node:path";

const target = process.argv[2] ?? "after/src";
const walk = (d) =>
  readdirSync(d, { withFileTypes: true }).flatMap((e) =>
    e.isDirectory() ? walk(path.join(d, e.name)) : /\.(ts|mjs|js)$/.test(e.name) ? [path.join(d, e.name)] : [],
  );
const files = walk(target).map((f) => ({ f: f.replaceAll("\\", "/"), src: readFileSync(f, "utf8") }));
const lineOf = (src, i) => src.slice(0, i).split("\n").length;

// بنقرا الـ call لحد القوس اللي بيقفله، عشان الـ options بتيجي على كذا سطر
const callBody = (src, open) => {
  let depth = 0;
  for (let i = open; i < src.length; i++) {
    if (src[i] === "(") depth++;
    if (src[i] === ")" && --depth === 0) return src.slice(open + 1, i);
  }
  return src.slice(open + 1);
};
const hits = (re, test) =>
  files.flatMap(({ f, src }) =>
    [...src.matchAll(re)].filter((m) => test(m, src)).map((m) => `${f}:${lineOf(src, m.index)}`),
  );

const checks = [];
const add = (area, question, verdict, evidence = []) => checks.push({ area, question, verdict, evidence });

// (1) قواعد الـ boundaries: بنشغّل الـ fitness function بتاعة الدرس 16 زي ما هي
if (target === "after/src") {
  const arch = spawnSync(process.execPath, ["scripts/arch-check.mjs", target], { encoding: "utf8" });
  add("boundaries", "dependency rules pass, on more than 0 modules?", arch.status === 0 ? "yes" : "no", [arch.stdout.trim().split("\n").at(-1)]);
} else {
  add("boundaries", "dependency rules pass, on more than 0 modules?", "needs a human", ["rules are anchored to after/src: run them on the real tree"]);
}

// (2) الـ config: أي process.env بره ملف config معناها رقم مستخبي
const env = files.filter((x) => !/config\.(ts|mjs|js)$/.test(x.f)).flatMap(({ f, src }) =>
  [...src.matchAll(/process\.env\b/g)].map((m) => `${f}:${lineOf(src, m.index)}`),
);
add("security", "process.env read only in a config module?", env.length ? "no" : "yes", env);

// (3) الـ timeouts: كل fetch لازم يكون معاه deadline
const noTimeout = hits(/\bfetch\(/g, (m, src) => !/AbortSignal\.(timeout|any)|\bsignal\s*[:,]/.test(callBody(src, m.index + m[0].length - 1)));
add("failure modes", "every fetch has a deadline?", noTimeout.length ? "no" : "yes", noTimeout);

// (4) الـ SQL: أول argument لازم يبقى string ثابت من غير concat ومن غير interpolation
const sqlByString = hits(/\.query\(/g, (m, src) => {
  const body = callBody(src, m.index + m[0].length - 1).trimStart();
  const first = /^(?:"[^"]*"|'[^']*'|`[^`]*`)/.exec(body);
  if (!first) return false;
  const after = body.slice(first[0].length).trimStart();
  return first[0].includes("${") || after.startsWith("+");
});
add("security", "SQL always parameterised?", sqlByString.length ? "no" : "yes", sqlByString);

// (5) الـ health endpoints: الـ orchestrator هيسأل مين لو مفيش route؟
const health = hits(/["'`]\/(healthz?|readyz?|livez?)["'`]/g, () => true);
add("observability", "health and readiness endpoints exist?", health.length ? "yes" : "no", health);

// (6) الباقي: دي أسئلة حكم، سكريبت بيدّعي إنه جاوبها بيكدب
for (const [area, question] of [
  ["data ownership", "does each table have one writer, and is that the right owner?"],
  ["failure modes", "is the behaviour after a partial failure acceptable to the business?"],
  ["security", "is authorisation checked on the object, not just the route?"],
  ["observability", "could on-call explain a failed order from logs and metrics alone?"],
  ["cost", "what does this cost per 1,000 orders, and what grows fastest?"],
]) add(area, question, "needs a human");

if (process.argv.includes("--json")) console.log(JSON.stringify(checks, null, 2));
else {
  for (const c of checks) {
    console.log(`[${c.verdict.padEnd(13)}] ${c.area.padEnd(14)} ${c.question}`);
    for (const e of c.evidence) console.log(`${" ".repeat(16)}${e}`);
  }
  const n = (v) => checks.filter((c) => c.verdict === v).length;
  console.log(`\nyes ${n("yes")}, no ${n("no")}, needs a human ${n("needs a human")} (of ${checks.length})`);
}
process.exitCode = checks.some((c) => c.verdict === "no") ? 1 : 0;

// ملف l37/plant.mjs: نسخة من after/src فيها مشكلتين مزروعتين، عشان نثبت إن الـ scanner بيمسك

const out = "l37/.planted/src";
rmSync("l37/.planted", { recursive: true, force: true });
cpSync("after/src", out, { recursive: true });

  const p = `${out}/${file}`;
  const src = readFileSync(p, "utf8");
  if (!src.includes(from)) throw new Error(`nothing to plant in ${file}`);
  writeFileSync(p, src.replace(from, to));
};

بالعامية

نص الأسئلة دي إجابتها ميكانيكية، ومينفعش حد يضيّع وقت الـ review عليها. الـ review-scan.mjs بيشغّل الـ architecture rules من الدرس 16 و4 checks نصية: process.env بره config module، وfetch من غير deadline، وSQL متركّب بالـ string، وhealth endpoints ناقصة. التقرير فيه 3 نتايج: yes وno وneeds a human. والتالتة دي هي الجزء الأمين: السكريبت ميعرفش الجدول ليه الـ owner الصح ولا لأ، فلازم يقول إنه ميعرفش.

الـ checker نفسه كود وممكن يبقى غلط، فلازم نثبته. الـ plant.mjs بينسخ الـ service ويزرع مشكلتين: بيشيل الـ deadline بتاع الدفع، وبيبني query الـ catalog بـ string concatenation. الاتنين اتمسكوا بالملف والسطر. وبص كمان الـ run النضيف لقى إيه لوحده: مفيش health endpoint في after/src، ودي ثغرة حقيقية محدش زرعها.

على النسخة المزروعة الـ architecture rules بتقول "needs a human"، لأن الـ rules مربوطة بـ after/src. لو قالت "yes" هناك هيبقى نفس الـ false green اللي الدرس 16 مسكه، لما tool بتعدّي عشان شافت 0 modules. والـ checks دي regex، فممكن تفوّت fetch ورا wrapper أو تعلّم على string بريء. ده مقبول كمرور أول، وده سبب تاني إن إنسان يقرا قايمة الـ "no".

فين هستخدمه في شغلي؟ حط الـ scan في الـ CI على كل PR بيلمس src/. الـ reviewer بيفتح الـ PR يلاقي الـ timeouts والـ SQL اتراجعوا خلاص، فبيصرف وقته على السؤال اللي الماكينة متعرفوش: "لو الـ payment provider بطّأ، الفلوس هتروح فين؟".
Trade-off Regex scanners are cheap and shallow. An AST rule in ESLint is more accurate and costs more to write and keep working, especially while tools catch up with TypeScript 7. Start with regex to learn which checks earn their place, then promote the ones that keep finding real problems.

Part 3 — The failure-mode walk 🔴 Advancedالجزء 3 — الـ failure-mode walk

English

A failure-mode walk takes one critical request, here POST /orders, and asks of each dependency: what if it's down, slow, or lying? First write down what you assume will happen. Then kill the dependency in a lab and record what did happen. The gap between the two columns is the review's most valuable output, because code reading produced the assumption and it was wrong.

The script runs the real after/ code against a throwaway Postgres and a fake payment provider. Crashes run in a child process, so a crash really is a crash. All five dependency scenarios plus the fix ran here. Redis is the one row that didn't: after/ has no Redis, so the honest entry is "not a dependency today", and it becomes a real question the moment the cache from lesson 23 lands.

Three results contradict the assumption. Postgres down kills the process: when the server goes away, idle clients in the pool emit an error, and with no pool.on("error") listener Node treats it as uncaught. Exit code 1, every in-flight request gone, and an orchestrator restart loop against a database that's still down. A payment timeout strands the order: the request fails after about 2 s as designed, but the order stays placed, the stock stays held, and the provider did receive the charge. A crash after reserve leaks stock: exit 137, zero orders, stock 9 instead of 10, and nothing in the system will ever notice, because stock is a counter with no ledger.

English

A reviewer who has to approve everything becomes the queue the whole team waits in. Four rules keep a review useful. Ask rather than decree: a question leaves the author thinking, and an order leaves them waiting for your next order. Authors decide two-way doors: if the choice is cheap to reverse (lesson 36), you advise and they choose. Block only on one-way doors and security: a schema that will hold production data, a public contract, a hole. Review early and time-box it: at the design doc, when changing direction costs a paragraph, with a decision date. After the code is written, the same comment costs a week.

Andrew Harmel-Law's "advice process" states it well: anyone can make an architectural decision, as long as they consult the people affected and those with expertise. The reviewer is one of those advisers. The approval isn't theirs to give, except in the narrow blocking cases.

The script below enforces this mechanically: findings with no risk, evidence and suggestion are returned to the reviewer, and the rest are split into blocking and non-blocking by door type. Each finding ends in a question for the author. It also reports the metric that keeps reviewers honest: time to first feedback. The sample data has a median of 8 hours and a p90 of 216 hours, because one RFC sat for nine days. A median alone would have hidden it.

dd-scan.mjs is hours 1 and 2 in one script: lines by language, test ratio, dependency counts, licences, npm outdated and npm audit, cycles through dependency-cruiser, and churn and bus factor from git log. Bus factor here means the smallest number of people responsible for more than half of all changed lines. There are several definitions, so state yours. The orders service has no real team history, so make-history.mjs scripts a git repo in a temp folder with invented authors. git log reads it for real, but the names and commits are synthetic and it shouldn't be read as a measurement of a team.

Three runs show how to read the numbers. The orders service is clean, with 0 outdated because it was freshly installed. pg from node_modules has a test ratio of 0, and that doesn't mean it's untested: npm packages don't ship their tests. A number can only tell you where to look. An old fixture with four pinned dependencies shows what age looks like: 2 majors behind and 8 high vulnerabilities, while its cycle count is meaningless because it has no source code, which the script says out loud.

// ملف l37/dd-scan.mjs: أول ساعتين من الـ due diligence في سكريبت واحد
// التشغيل: ⁦node l37/dd-scan.mjs <target> [--history <repo>] [--outdated] [--json out.json]⁩
import { spawnSync } from "node:child_process";
import { existsSync, readFileSync, readdirSync, statSync, writeFileSync } from "node:fs";
import path from "node:path";

const [target] = process.argv.slice(2);
const flag = (n) => (process.argv.includes(n) ? process.argv[process.argv.indexOf(n) + 1] : undefined);
const SKIP = new Set(["node_modules", ".git", "dist", "out", "l37", "l38", "pages"]);
const LANG = { ".ts": "TypeScript", ".mts": "TypeScript", ".js": "JavaScript", ".mjs": "JavaScript", ".cjs": "JavaScript", ".sql": "SQL", ".json": "JSON", ".md": "Markdown" };

const walk = (d) =>
  readdirSync(d, { withFileTypes: true }).flatMap((e) =>
    SKIP.has(e.name) || e.name.startsWith("pgdata-") ? [] : e.isDirectory() ? walk(path.join(d, e.name)) : [path.join(d, e.name)],
  );

// (1) حجم وأنواع الكود: السطور الفاضية مش بتتعد
const byLang = {};
let testLines = 0;
let codeLines = 0;
let testFiles = 0;
let biggest = { file: "", lines: 0 };
for (const f of walk(target)) {
  const lang = LANG[path.extname(f)];
  if (!lang || f.endsWith("package-lock.json")) continue;
  const lines = readFileSync(f, "utf8").split("\n").filter((l) => l.trim()).length;
  byLang[lang] = (byLang[lang] ?? 0) + lines;
  if (lang !== "TypeScript" && lang !== "JavaScript") continue;
  if (/(^|[\\/])tests?[\\/]|\.(test|spec)\./.test(f)) {
    testLines += lines;
    testFiles++;
  } else {
    codeLines += lines;
    if (lines > biggest.lines) biggest = { file: path.relative(target, f).replaceAll("\\", "/"), lines };
  }
}

// (2) الـ dependencies: المباشرة من package.json والـ transitive من الـ lockfile
const pkg = JSON.parse(readFileSync(path.join(target, "package.json"), "utf8"));
const lockPath = path.join(target, "package-lock.json");
const lock = existsSync(lockPath) ? JSON.parse(readFileSync(lockPath, "utf8")) : null;
const deps = {
  direct: Object.keys(pkg.dependencies ?? {}).length,
  dev: Object.keys(pkg.devDependencies ?? {}).length,
  transitive: lock ? Object.keys(lock.packages).filter((k) => k.includes("node_modules/")).length : null,
  lockfile: Boolean(lock),
};

// (3) الـ licences: بنقرا الـ license بتاع كل package متسطبة فعلًا
const licences = {};
if (lock) {
  for (const k of Object.keys(lock.packages).filter((x) => x.includes("node_modules/"))) {
    const p = path.join(target, k, "package.json");
    if (!existsSync(p)) continue;
    const id = JSON.parse(readFileSync(p, "utf8")).license ?? "UNKNOWN";
    const name = typeof id === "string" ? id : "UNKNOWN";
    licences[name] = (licences[name] ?? 0) + 1;
  }
}
const risky = Object.keys(licences).filter((l) => /GPL|AGPL|SSPL|UNKNOWN/i.test(l));

// (4) الـ outdated: npm بيسأل الـ registry، والـ exit code بتاعه 1 لو فيه حاجة قديمة
let outdated = null;
if (process.argv.includes("--outdated")) {
  const run = spawnSync("npm", ["outdated", "--json"], { cwd: target, encoding: "utf8", shell: true });
  const list = JSON.parse(run.stdout || "{}");
  const major = (v) => Number(String(v).split(".")[0]);
  const rows = Object.entries(list).filter(([, v]) => v.current);
  outdated = { total: rows.length, majorsBehind: rows.filter(([, v]) => major(v.latest) > major(v.current)).map(([k, v]) => `${k} ${v.current} -> ${v.latest}`) };
}

// كمان npm audit: رقم الثغرات المعروفة، وبيحتاج lockfile
let audit = null;
if (process.argv.includes("--outdated") && lock) {
  const run = spawnSync("npm", ["audit", "--json"], { cwd: target, encoding: "utf8", shell: true });
  audit = JSON.parse(run.stdout || "{}").metadata?.vulnerabilities ?? null;
}

// (5) الـ cycles: depcruise بقاعدة واحدة، وبيفشل لو ملقاش modules خالص
const cfg = path.resolve("l37/dd.depcruise.cjs");
const srcDir = flag("--src") ?? ".";
const dc = spawnSync(process.execPath, [path.resolve("node_modules/dependency-cruiser/bin/dependency-cruiser.mjs"), srcDir, "--config", cfg, "--output-type", "json"], {
  cwd: target,
  encoding: "utf8",
  maxBuffer: 1 << 28,
});
const summary = JSON.parse(dc.stdout).summary;
const cycles = {
  modules: summary.totalCruised,
  count: summary.violations.filter((v) => v.rule.name === "no-cycles").length,
  examples: summary.violations.filter((v) => v.rule.name === "no-cycles").slice(0, 2).map((v) => `${v.from} -> ${v.to}`),
};

// (6) الـ churn و bus factor من git log: مين غيّر إيه، وكام حد لو مشي المعرفة تضيع
let history = null;
const repo = flag("--history");
if (repo) {
  const log = spawnSync("git", ["-C", repo, "log", "--format=@%an", "--numstat"], { encoding: "utf8" }).stdout;
  const churn = {};
  const byAuthor = {};
  const authorsOf = {};
  let author = "";
  for (const line of log.split("\n")) {
    if (line.startsWith("@")) author = line.slice(1);
    const m = /^(\d+)\t(\d+)\t(.+)$/.exec(line);
    if (!m) continue;
    const changed = Number(m[1]) + Number(m[2]);
    churn[m[3]] = (churn[m[3]] ?? 0) + changed;
    byAuthor[author] = (byAuthor[author] ?? 0) + changed;
    (authorsOf[m[3]] ??= new Set()).add(author);
  }
  const total = Object.values(byAuthor).reduce((a, b) => a + b, 0);
  const ranked = Object.entries(byAuthor).sort((a, b) => b[1] - a[1]);
  let sum = 0;
  let busFactor = 0;
  for (const [, n] of ranked) {
    busFactor++;
    sum += n;
    if (sum > total / 2) break;
  }
  history = {
    busFactor,
    authors: ranked.map(([a, n]) => `${a} ${Math.round((n / total) * 100)}%`),
    hotFiles: Object.entries(churn).sort((a, b) => b[1] - a[1]).slice(0, 3).map(([f, n]) => `${f} (${n} lines, ${authorsOf[f].size} author${authorsOf[f].size > 1 ? "s" : ""})`),
    soloFiles: Object.values(authorsOf).filter((s) => s.size === 1).length,
    files: Object.keys(authorsOf).length,
  };
}

const report = { target: path.basename(path.resolve(target)), byLang, code: { codeLines, testLines, testFiles, ratio: Number((testLines / Math.max(1, codeLines)).toFixed(2)), biggest }, deps, licences, risky, outdated, audit, cycles, history };
if (flag("--json")) writeFileSync(flag("--json"), JSON.stringify(report, null, 2));

console.log(`target: ${report.target}`);
console.log(`lines: ${Object.entries(byLang).map(([k, v]) => `${k} ${v}`).join(", ")}`);
console.log(`tests: ${testFiles} files, ${testLines} lines vs ${codeLines} code lines, ratio ${report.code.ratio}`);

English

A list of 40 problems is a failure of the review, because nobody can act on it. dd-report.mjs turns the scan into a severity × effort matrix: high severity with low effort goes first, and high severity with high effort needs a plan and a budget. It also separates red flags from normal mess. Every real codebase has thin tests, some outdated packages and a few ugly files, and calling those alarming costs you credibility. A red flag is something that changes the decision: one person holds all the knowledge, no lockfile, copyleft code inside a closed product, secrets in the history. Rules like these are a starting point, so adjust them to the deal.

Code can't tell you everything, so the report always prints what it didn't check: incident history, who really has production access, data volumes and cost per order, why odd decisions were made, vendor contracts. Those become the questions for the team in hour 8. Be plain about unknowns: "we didn't check X" is worth more than a confident guess, and a buyer who discovers the guess later stops trusting the rest of the report.

Then one decision goes out in the two languages from lesson 34. The CTO page has stack, numbers, top risk and first moves. The investor page answers the three questions they actually have, in plain words: can this team keep shipping, is anything legally risky, and is this a rewrite waiting to happen. The "1 to 2 months" in that output is a judgement call, and the report labels it as an estimate.

Solution · الحل

// ملف l37/exercises.ts: حلول التمرينين 2 و 3، على Postgres مؤقت
// التشغيل: node l37/exercises.ts
import { readFileSync } from "node:fs";
import { fileURLToPath } from "node:url";
import pg from "pg";
import { startPg } from "../lib/pg-throwaway.mjs";

const cluster = await startPg();
const n = Number(cluster.port);
if (!/^\d+$/.test(String(cluster.port)) || n < 1024 || n > 65535 || [27017, 5432, 6379].includes(n)) throw new Error("refusing port " + cluster.port);
const pool = new pg.Pool({ connectionString: cluster.url, max: 5 });
pool.on("error", () => {});
try {
  await pool.query(readFileSync(fileURLToPath(new URL("../after/schema.sql", import.meta.url)), "utf8"));

  // ⁦----------⁩ التمرين 2: الـ reservation بقى صف في جدول، فالـ crash بقى ليه أثر ⁦----------⁩
  await pool.query(`create table catalog.reservations (
    id bigint generated always as identity primary key,
    sku text not null, qty int not null check (qty > 0),
    expires_at timestamptz not null, committed_at timestamptz)`);

  const reserve = async (sku: string, qty: number, ttlSeconds: number): Promise<number | null> => {
    const c = await pool.connect();
    try {
      await c.query("begin");
      const u = await c.query("update catalog.products set stock = stock - $2 where sku = $1 and stock >= $2", [sku, qty]);
      if (u.rowCount !== 1) {
        await c.query("rollback");
        return null;
      }
      const r = await c.query("insert into catalog.reservations (sku, qty, expires_at) values ($1, $2, now() + make_interval(secs => $3)) returning id", [sku, qty, ttlSeconds]);
      await c.query("commit");
      return r.rows[0].id;
    } finally {
      c.release();
    }
  };
  const commit = (id: number) => pool.query("update catalog.reservations set committed_at = now() where id = $1", [id]);
  // لازم group by: الـ update ... from بيطبّق صف واحد بس لو الـ sku متكرر في الـ join
  const sweep = async (): Promise<number> => {
    const r = await pool.query(`with expired as (
        delete from catalog.reservations where committed_at is null and expires_at < now() returning sku, qty),
      totals as (select sku, sum(qty)::int as qty from expired group by sku)
      update catalog.products p set stock = p.stock + t.qty from totals t where p.sku = t.sku returning p.sku`);
    return r.rowCount ?? 0;
  };
  const stock = async () => (await pool.query("select stock from catalog.products where sku = 'SKU-MUG'")).rows[0].stock as number;

  await reserve("SKU-MUG", 1, -1);
  await reserve("SKU-MUG", 2, -1);
  const kept = await reserve("SKU-MUG", 1, -1);
  await commit(kept!);
  console.log("after 3 reserves, 1 committed, 2 crashed: stock", await stock());
  console.log("sweeper fixed", await sweep(), "sku, stock", await stock());

  // ⁦----------⁩ التمرين 3: كل صف ليه transaction لوحده، والـ poison بيتركن بعد 3 محاولات ⁦----------⁩
  await pool.query("alter table orders.outbox add column attempts int not null default 0, add column parked_at timestamptz");
  for (const orderId of ["o1", "poison", "o3"]) {
    await pool.query("insert into orders.outbox (type, payload, occurred_at) values ('OrderPaid', $1, now())", [JSON.stringify({ orderId })]);
  }
  const sent: string[] = [];
  const send = (orderId: string) => {
    if (orderId === "poison") throw new Error("mail provider rejects this address");
    sent.push(orderId);
  };
  const MAX_ATTEMPTS = 3;
  const relayOne = async (): Promise<boolean> => {
    const c = await pool.connect();
    try {
      await c.query("begin");
      const r = await c.query(
        `select id, payload from orders.outbox where published_at is null and parked_at is null and attempts < $1
         order by attempts, id limit 1 for update skip locked`, [MAX_ATTEMPTS]);
      const row = r.rows[0];
      if (!row) {
        await c.query("rollback");
        return false;
      }
      try {
        send(row.payload.orderId);
        await c.query("update orders.outbox set published_at = now() where id = $1", [row.id]);
      } catch {
        await c.query("update orders.outbox set attempts = attempts + 1, parked_at = case when attempts + 1 >= $2 then now() end where id = $1", [row.id, MAX_ATTEMPTS]);
      }
      await c.query("commit");
      return true;
    } finally {
      c.release();
    }
  };
  let turns = 0;
  while (await relayOne()) turns++;
  const parked = (await pool.query("select payload->>'orderId' as id, attempts from orders.outbox where parked_at is not null")).rows;
  console.log("relay turns:", turns, "sent:", sent, "parked:", parked);
} finally {
  await pool.end();
  await cluster.stop();
}

Cheat sheet · الخلاصة

  • Six areas: boundaries, data ownership, failure modes, security, observability, cost. Know what evidence answers each.
  • A finding is risk + evidence + suggestion. Anything less is an opinion.
  • Scanner verdicts are yes, no and needs a human. Prove the scanner by planting problems.
  • A tool that saw 0 modules hasn't passed anything.
  • Failure walk: write the assumption, kill the dependency, compare. The gap is the finding.
  • pg.Pool without on("error") dies with the database. Here: exit 1 without it, 500 in ~8 ms with it.
  • Block only one-way doors and security. Authors decide two-way doors. Ask, don't decree.
  • Review at the design doc, time-boxed. Track time to first feedback, and look at the p90.
  • Due diligence in a day is a fixed schedule: run it, scan, structure, tests, deps, debt, risk, people.
  • A number shows where to look. pg's test ratio of 0 is packaging, not quality.
  • Report severity × effort, red flags apart from normal mess, and always what you couldn't verify.
  • One decision, two pages: stack and risk for the CTO; can they ship, legal risk, rewrite risk for the investor.
