Why this matters · ليه ده مهم

English

Tooling decides whether the code you wrote is the code that runs. A production error reads at n (crash.min.js:1:145) and nobody can tell which function that is. A worker runs on your laptop and dies in the Docker image because it imported a package nobody declared. A customer's older browser throws toSorted is not a function even though "we transpile". Your whole source code sits in a public .map file. Seniors are expected to own this layer, and interviewers ask about all of it. Every command in this lesson was really run; the output blocks are what the tools printed, with long folder paths shortened to C:\work.

بالعامية

الأدوات هي اللي بتحدد هل الكود اللي كتبته هو نفس الكود اللي بيشتغل. error في production مكتوب فيه at n (crash.min.js:1:145) ومحدش عارف دي أنهي function. worker شغال على جهازك وبيموت في الـ Docker image لأنه عامل import لباكدج محدش أعلن عنها. متصفح قديم عند عميل بيرمي toSorted is not a function رغم إننا "بنعمل transpile". والكود بتاعك كله قاعد في ملف .map متاح للناس. السنيور متوقع منه يمسك الطبقة دي، والـ interviews بتسأل فيها كلها. كل أمر في الدرس ده اتشغّل فعلًا، وبلوكات الناتج هي اللي الأدوات طبعته بالظبط، بس المسارات الطويلة متقصّرة لـ C:\work.

Part 1 — npm & package.json 🟢 Basicالجزء 1 — الـ npm والـ package.json

English

package.json is your project's manifest: name, version, the ranges of packages it accepts, and its commands. dependencies are needed at runtime; devDependencies are only needed to build and test, and npm ci --omit=dev leaves them out of a production image. Note that npm init -y writes "type": "commonjs", so ESM needs "type": "module" (see lesson 12).

الـ package.json هو بطاقة المشروع: الاسم، والـ version، والـ ranges بتاعة الباكدجات اللي بيقبلها، والأوامر. الـ dependencies محتاجها وقت التشغيل، والـ devDependencies محتاجها في الـ build والـ tests بس، وnpm ci --omit=dev بيسيبها بره الـ production image.

وأمر npm install debug واحد بيغيّر 3 حاجات، زي الرسمة فوق. معنى الـ ^ وليه الـ lockfile مهم موجودين في جزء الـ semver في درس 18، ومش هنكررهم هنا.

الـ scripts هي الأوامر الرسمية بتاعة المشروع. npm run بيزوّد node_modules/.bin على الـ PATH، فكلمة eslint معناها النسخة بتاعة المشروع مش نسخة global. وnpm بيشغّل pre<name> وpost<name> لوحده حوالين الـ script. ولو أي خطوة خرجت بكود غير صفر، الباقي بيقف. أما npx فبيشغّل الـ binary بتاع باكدج: المحلي لو موجود، ولو مش موجود بينزّله، وده بالظبط اللي بيخلي غلطة إملائية ممكن تشغّل كود حد تاني. و--no-install بيقفل التنزيل.

الـ lifecycle scripts هي الجزء الخطر في التسطيب. أي dependency ممكن تعلن عن postinstall، وnpm بيشغّله على جهازك وفي الـ CI افتراضيًا (ignore-scripts = false). وباكدجات اتخترقت استخدمت ده بالظبط عشان تسرق tokens.

فين هستخدمه في شغلي؟ في الـ Dockerfile: مرحلة build بتعمل npm ci وnpm run build، ومرحلة تشغيل بتعمل npm ci --omit=dev، فالـ image مفيهاش TypeScript ولا ESLint. وفي الـ CI ضيف --ignore-scripts لو مفيش native modules محتاجة تتبني. والغلطة الشائعة: باكدج بتستخدمها وقت التشغيل في devDependencies، وده بيقع في الـ production بس (شوف الغلطات تحت).

Part 2 — pnpm vs npm vs yarn, and semver 🟡 Intermediateالجزء 2 — pnpm ضد npm ضد yarn، والـ semver

English

npm and Yarn classic hoist: they flatten the tree into the top of node_modules so packages can be shared. The side effect is that Node's lookup finds everything there, so your code can import packages you never declared. Those are phantom dependencies. pnpm links only your declared dependencies at the top, and the rest live under node_modules/.pnpm. Files are hard-linked from one global content-addressed store, so the same file on disk is shared between projects. Yarn 4 goes further with Plug'n'Play, which has no node_modules at all.

export type Coupon = { code: string; percent: number; maxDiscount?: number };

// الفلوس كلها بالقروش ⁦(integers)⁩ عشان نهرب من مشاكل الـ floating point
export function calculateDiscount(subtotal: number, coupon?: Coupon): number {
  if (!Number.isInteger(subtotal) || subtotal < 0) {
    throw new RangeError(`invalid subtotal: ${subtotal}`);
  }
  if (!coupon) return 0;
  if (coupon.percent <= 0 || coupon.percent > 100) {
    throw new RangeError(`invalid percent: ${coupon.percent}`);
  }
  const raw = Math.round((subtotal * coupon.percent) / 100);
  return Math.min(raw, coupon.maxDiscount ?? raw);
}

Interview question: "We transpile to ES2019, so why does toSorted crash on an older browser?" Transpiling only rewrites syntax. arr.toSorted() is a valid method call in any version, so nothing changes it and it fails at runtime because the method doesn't exist. You need a polyfill such as core-js, ideally added on usage based on your browserslist targets, or you can write the code without that API.

English

describe groups tests, it defines one, and expect asserts. A test passes unless something throws. toBe compares with Object.is, toThrow needs a function so it can catch the error, and it.each runs one test per row. Test the edges where bugs live, not just the happy path. The test below that catches a real bug is the one that treats maxDiscount: 0 as a real cap: with || instead of ??, a paused coupon gives a 50% discount.

  it("returns 0 when there is no coupon", () => {
    expect(calculateDiscount(10000)).toBe(0);
  });

  it("applies the percentage in minor units and rounds", () => {
    expect(calculateDiscount(19999, { code: "SAVE15", percent: 15 })).toBe(3000);
  });

  it("caps the discount at maxDiscount", () => {

A mock replaces a dependency so the test doesn't send real email. 2. A phantom dependency finder 🟡 medium Write a script that scans src for bare imports, including dynamic import() and scoped packages, and lists every package that isn't declared in package.json. Ignore Node built-ins and relative paths. Exit non-zero if it finds any, so it can run in CI on a team that stays on npm.

Hint · تلميح node:module exports builtinModules. Package names come from the specifier: lodash/get is lodash, and @scope/a/b is @scope/a. A regex scan is good enough for a CI warning but isn't a parser, so it can be fooled by imports inside strings and comments.

Solution · الحل 
import { readdirSync, readFileSync } from "node:fs";
import { builtinModules } from "node:module";
import path from "node:path";

// الاستخدام: ⁦node scripts/find-phantoms.mjs src⁩
const pkg = JSON.parse(readFileSync("package.json", "utf8"));
const declared = new Set([
  ...Object.keys(pkg.dependencies ?? {}),
  ...Object.keys(pkg.devDependencies ?? {}),
  ...Object.keys(pkg.peerDependencies ?? {}),
]);
const builtin = new Set(builtinModules);

// بنلقط import و export from و ⁦import()⁩ و require
const IMPORT = /(?:from\s+|import\s*\(\s*|import\s+|require\s*\(\s*)["']([^"']+)["']/g;

// اسم الباكدج من الـ ⁦specifier: lodash/get⁩ تبقى lodash، و⁦@scope/a/b⁩ تبقى ⁦@scope/a⁩
const packageName = (s) => (s.startsWith("@") ? s.split("/").slice(0, 2).join("/") : s.split("/")[0]);

const phantoms = new Map();
for (const entry of readdirSync(process.argv[2], { recursive: true, withFileTypes: true })) {
  if (!entry.isFile() || !/\.[cm]?[jt]sx?$/.test(entry.name)) continue;
  const file = path.join(entry.parentPath, entry.name);
  for (const [, spec] of readFileSync(file, "utf8").matchAll(IMPORT)) {
    if (spec.startsWith(".") || spec.startsWith("/") || spec.startsWith("node:")) continue;
    const name = packageName(spec);
    if (declared.has(name) || builtin.has(name) || name === pkg.name) continue;
    phantoms.set(name, file);
  }
}

for (const [name, file] of phantoms) console.log(`phantom: ${name} (imported in ${file})`);
console.log(`${phantoms.size} phantom dependencies`);
process.exitCode = phantoms.size ? 1 : 0;

Cheat sheet · الخلاصة

  • npm install touches three things: the range in package.json, the exact tree in the lockfile, and the files in node_modules. Commit the first two.
  • npm ci --omit=dev for production. npm install x doesn't move a package out of devDependencies; --save-prod does.
  • npm runs dependencies' postinstall by default. pnpm 12 blocks them and fails until you choose, using allowBuilds.
  • Phantom dependency: importing what you didn't declare. It works on npm and Yarn 1, fails on pnpm and Yarn 4 PnP.
  • pnpm's store plus hard links: a second project with the same dependencies added 0.0 MB. Settings live in pnpm-workspace.yaml.
  • Prettier handles format, ESLint handles bugs. ESLint 10 is flat config only, and @eslint/js is a separate install.
  • Typed lint catches floating promises, which tsc passes. typescript-eslint 8.72 needs typescript <6.1.
  • Bundlers: resolve → transform → bundle → minify. Vite dev serves modules unbundled; vite build is a real bundle, on Rolldown in Vite 8.
  • A public .map publishes your source. Use hidden maps: upload in CI, delete, deploy. On Node, --enable-source-maps.
  • Transpiling rewrites syntax; polyfills add APIs. Babel 8 removed useBuiltIns: use babel-plugin-polyfill-corejs3.
  • Targets cost bytes: the same source was 0.4 KB for Chrome 150, about 22 KB for Chrome 90, and 73.5 KB for IE 11.
  • Vitest: TS and ESM with no config. Assert rejections with await expect(p).rejects, never with expect inside catch.
