Why this matters · ليه ده مهم

English

Metaprogramming is code that changes how other code behaves, and you already depend on it every day. Vue, MobX and Immer are built on Proxy. NestJS is built on decorators and the type metadata the compiler emits for them. Prisma's $queryRaw and postgres.js are tagged templates. Zod 4 and Fastify's serializer generate code with new Function. When these break, the symptoms look like magic: a watcher that never updates, a Nest service whose dependency is undefined, a decorated file that compiles and then dies with a SyntaxError, a "harmless" pricing formula field that leaks your secrets. A senior reads through the magic, can say what it costs, and knows when a plain function is the better answer.

بالعامية

الـ metaprogramming هو كود بيغيّر تصرّف كود تاني، وإنت معتمد عليه كل يوم حتى لو مش واخد بالك. Vue و MobX و Immer مبنيين على Proxy. و NestJS مبني على الـ decorators والـ type metadata اللي الـ compiler بيطلّعها ليهم. والـ $queryRaw بتاع Prisma و postgres.js عبارة عن tagged templates. و Zod 4 والـ serializer بتاع Fastify بيولّدوا كود بـ new Function. ولما حاجة من دول تقع، الأعراض بتبان سحر: watcher مش بيتحدّث، service في Nest الـ dependency بتاعتها undefined، ملف فيه decorators بيعدّي الـ compile وبعدين يموت بـ SyntaxError، أو خانة "بريئة" لـ formula السعر بتسرّب الـ secrets بتاعتك. السنيور بيشوف اللي ورا السحر، وبيعرف يقول بيتكلف كام، وبيعرف إمتى function عادية تبقى هي الإجابة الأحسن.

Part 1 — Proxy traps 🔴 Advancedالجزء 1 — الـ traps بتاعة الـ Proxy

English

A Proxy wraps a target object and intercepts the language's fundamental operations through traps on a handler object. There are 13 traps; six do most of the work: get (read), set (write), has (the in operator), deleteProperty (delete), and, for function targets only, apply (a call) and construct (new). The other seven (ownKeys, defineProperty, getOwnPropertyDescriptor, getPrototypeOf, setPrototypeOf, isExtensible, preventExtensions) cover the rest of the object model. Any trap you don't define forwards to the target untouched.

Three contracts bite people. First, a set or deleteProperty trap must return a boolean, and in strict mode (all ES modules) returning false makes the operation throw a TypeError. Second, traps must respect invariants: a trap can't report a different value for a non-writable, non-configurable property, so it can't lie about frozen data. Third, a proxy is a new object with its own identity, and it can't see inside a target's private fields or internal slots.

A proxy is the right tool when you can't list the keys in advance or don't own the code you're wrapping: a config object that rejects typos, a feature-flag bag with safe defaults, metrics around a third-party SDK. If you know the keys up front, a plain function or a class is simpler, faster and easier to debug.

  operation on the proxy     trap that runs                then usually
  ----------------------     --------------                ------------
  config.port           -->  get(target, key, receiver)    Reflect.get(...)
  config.port = 1       -->  set(target, key, val, recv)   validate, Reflect.set(...)

  delete config.port    -->  deleteProperty(target, key)   Reflect.deleteProperty(...)
  charge("o_1", 1500)   -->  apply(target, this, args)     Reflect.apply(...)
  new DbPool(url)       -->  construct(target, args, nt)   Reflect.construct(...)

  trap not defined?     -->  the operation goes straight to the target
الرسمة بتوري كل عملية بتتعمل على الـ proxy والـ trap اللي بيشتغل معاها: القراية بتشغّل get، والكتابة set، وin بتشغّل has، وdelete بتشغّل deleteProperty، وندا الـ function بيشغّل apply، وnew بيشغّل construct (الاتنين الأخرانيين للـ functions بس). وفي العمود الأخير اللي بيحصل عادةً جوه الـ trap: تعمل اللي إنت عايزه وبعدين تكمّل العملية بـ Reflect. ولو الـ trap مش متعرّف، العملية بتروح للـ target على طول.
// شغّله كده: node proxy-traps.ts
import { inspect } from "node:util";

// (1) الـ get و set: config فيه validation وقت الكتابة
type AppConfig = { port: number; dbUrl: string; logLevel: string; [k: string]: unknown };
const LEVELS = new Set(["debug", "info", "warn", "error"]);

function strictConfig(initial: AppConfig): AppConfig {
  return new Proxy(initial, {
    // الـ get بيمنع القراية من مفتاح مش موجود بدل ما يرجّع undefined في صمت
    get(target, key, receiver) {
      if (typeof key === "string" && !Reflect.has(target, key)) {
        throw new Error(`Unknown config key: ${key}`);
      }
      return Reflect.get(target, key, receiver);
    },
    // الـ set لازم يرجّع true، ولو رجّع false في strict mode هيترمي TypeError
    set(target, key, value, receiver) {
      if (key === "port" && (!Number.isInteger(value) || value < 1 || value > 65535)) {
        throw new RangeError(`Invalid port: ${value}`);
      }
      if (key === "logLevel" && !LEVELS.has(value)) return false;
      return Reflect.set(target, key, value, receiver);
    },
    // الـ has بيتحكم في operator الـ in: بنخبّي الـ secret منه
    has(target, key) {
      return key !== "dbUrl" && Reflect.has(target, key);
    },
    // الـ deleteProperty بيمنع مسح أي key أساسي
    deleteProperty(target, key) {
      if (key === "port") throw new Error("Refusing to delete required key: port");
      return Reflect.deleteProperty(target, key);
    },
  });
}

// (2) الـ apply: بنلف function من غير ما نلمس الكود بتاعها (metrics حوالين payment client)
const calls: Record<string, number> = {};
function withMetrics<F extends (...args: any[]) => any>(name: string, fn: F): F {
  return new Proxy(fn, {
    apply(target, thisArg, args) {
      calls[name] = (calls[name] ?? 0) + 1;
      return Reflect.apply(target, thisArg, args);
    },
  });
}
const chargeCard = withMetrics("chargeCard", function charge(orderId: string, cents: number) {
  return `${orderId}:${cents}`;
});

chargeCard("o_2", 900);
console.log("calls", calls, "| fn name still", chargeCard.name);

// (3) الـ construct: بنتحكم في new، هنا عشان نخلي الـ pool واحد بس لكل url
class DbPool {
  url: string;
  constructor(url: string) { this.url = url; }
}
const pools = new Map<string, DbPool>();
const SharedPool = new Proxy(DbPool, {
  construct(target, args, newTarget) {
    const url = args[0] as string;
    if (!pools.has(url)) pools.set(url, Reflect.construct(target, args, newTarget));
    return pools.get(url)!;
  },
});

بالعامية

الـ Proxy بيلف object اسمه target، وبيعترض العمليات الأساسية في اللغة عن طريق traps في object اسمه handler. فيه 13 trap، وستة منهم بيعملوا أغلب الشغل: get للقراية، set للكتابة، has لـ operator الـ in، deleteProperty لـ delete، وللـ functions بس apply للندا وconstruct لـ new. الـ 7 الباقيين (ownKeys وdefineProperty وgetOwnPropertyDescriptor وgetPrototypeOf وsetPrototypeOf وisExtensible وpreventExtensions) بيغطوا باقي الـ object model. وأي trap مش كاتبه، العملية بتعدّي للـ target زي ما هي.

فيه 3 قواعد بتعضّ الناس. الأولى: الـ set والـ deleteProperty لازم يرجّعوا boolean، وفي strict mode (يعني كل ES modules) لو رجّعوا false العملية بترمي TypeError. بص في الـ output: logLevel = "loud" رمت trap returned falsish. التانية: الـ invariants: الـ trap مش من حقه يرجّع قيمة مختلفة لـ property مش writable ومش configurable، يعني مش هيعرف يكدب على data متجمّدة. التالتة: الـ proxy هو object جديد ليه identity لوحده، ومش شايف الـ private fields ولا الـ internal slots بتاعة الـ target.

الـ proxy هو الأداة الصح لما مش عارف الـ keys من الأول أو الكود مش بتاعك: config بيرفض الـ typos، feature flags ليها default آمن، أو metrics حوالين SDK خارجي. ولو عارف الـ keys مقدمًا، function أو class عادية أبسط وأسرع وأسهل في الـ debugging.

فين هستخدمه في شغلي؟ لف process.env في strictConfig وقت الـ startup: لو حد كتب env.DATABSE_URL غلط، الـ service هيقع فورًا بـ Unknown config key بدل ما تكتشف في production إن الـ pool اتعمل بـ undefined. وفي feature flags: flags.betaInvoices بترجع false بدل undefined، ومعاها log بكل flag اتقرت، فتعرف أنهي flags ميتة وتمسحها. ولو عندك SDK بتاع payment مش بتاعك وعايز تعد الـ calls، withMetrics بيعمل ده من غير ما تلمس كوده، وزي ما شايف في الـ output chargeCard.name لسه charge، لأن الـ wrapper شفاف.

// شغّله كده: node proxy-gotchas.ts
const passthrough = <T extends object>(t: T): T => new Proxy(t, {});
const attempt = (label: string, fn: () => unknown) => {
  try { console.log(label, "=>", fn()); }
  catch (e) { console.log(label, "=> threw", (e as Error).name + ":", (e as Error).message); }
};

// (1) الـ private fields مش بتعدّي من الـ proxy: الـ this بقى الـ proxy مش الـ object الأصلي
class Invoice {
  #total = 500;
  get total() { return this.#total; }
}
attempt("private field", () => passthrough(new Invoice()).total);

// (2) نفس المشكلة مع أي internal slot: Map و Date و Set
attempt("Map.get", () => passthrough(new Map([["a", 1]])).get("a"));
attempt("Date.getTime", () => passthrough(new Date(0)).getTime());

// (3) الحل: اربط الـ methods بالـ target، أو سيب الـ getter يشتغل على الـ target
const fixed = new Proxy(new Map([["a", 1]]), {
  get(target, key) {
    const value = Reflect.get(target, key, target);
    return typeof value === "function" ? value.bind(target) : value;
  },
});
attempt("Map.get (bound)", () => fixed.get("a"));

// (4) الـ proxy object جديد: الـ identity مختلفة، وده بيكسر Map و ⁦===⁩ و Set
const order = { id: "o_1" };
const wrapped = passthrough(order);
const seen = new Set([order]);
console.log("=== :", wrapped === order, "| Set.has :", seen.has(wrapped));

// (5) الـ invariants: الـ trap مش من حقها تكدب على property مش configurable
const frozen = Object.freeze({ currency: "EGP" });
const liar = new Proxy(frozen, { get: () => "USD" });

// (6) في strict mode، set trap بترجّع false = TypeError
const readOnly = new Proxy({ total: 1 }, { set: () => false });
attempt("set returns false", () => { readOnly.total = 2; });

// (7) الـ typeof والـ instanceof بيعدّوا عادي، وده اللي بيخلي الـ proxy شفاف

الغلطة الأشهر: this جوه الـ getter بيبقى الـ proxy، والـ proxy معندوش #total، فبتاخد Cannot read private member. ونفس الكلام مع Map وDate، لأن الـ methods بتاعتهم بتدوّر على internal slot مش موجود على الـ proxy. الحل إنك تربط الـ methods بالـ target زي النسخة fixed. والـ Set.has رجّعت false لأن الـ proxy object تاني خالص، فلو خزّنت الأصل في Set أو Map ودوّرت بالـ proxy مش هتلاقيه. أما الـ typeof والـ instanceof فبيعدّوا عادي، وده اللي بيخلي الـ proxy شفاف لأغلب الكود.

// شغّله كده: ⁦node proxy-cost.ts  (⁩هيطبع الـ median بتاع 7 جولات)
const N = 20_000_000;
const plain = { total: 1 };
const noTrap = new Proxy({ total: 1 }, {});
const withGet = new Proxy({ total: 1 }, {
  get(target, key, receiver) { return Reflect.get(target, key, receiver); },
});

function median(xs: number[]) { return xs.toSorted((a, b) => a - b)[xs.length >> 1]; }
function measure(fn: () => number): number {
  const runs: number[] = [];
  let sink = 0;
  for (let r = 0; r < 7; r++) {
    const t = performance.now();
    sink += fn();
    runs.push(((performance.now() - t) * 1e6) / N);
  }
  if (sink === 0) console.log("unreachable");
  return median(runs);
}

// كل حالة في function لوحدها عشان الـ inline cache ميتلخبطش بين الـ shapes
function readPlain() { let s = 0; for (let i = 0; i < N; i++) s += plain.total; return s; }
function readNoTrap() { let s = 0; for (let i = 0; i < N; i++) s += noTrap.total; return s; }
function readWithGet() { let s = 0; for (let i = 0; i < N; i++) s += withGet.total; return s; }

const plainNs = measure(readPlain);
const noTrapNs = measure(readNoTrap);
const withGetNs = measure(readWithGet);
console.log(`plain object     ${plainNs.toFixed(2)} ns/read`);
console.log(`Proxy, no traps  ${noTrapNs.toFixed(2)} ns/read`);
console.log(`Proxy + get trap ${withGetNs.toFixed(2)} ns/read`);

// الـ output الحقيقي (Node 22.19 على Windows):
// → plain object     0.60 ns/read
// → Proxy, no traps  12.19 ns/read
// → Proxy + get trap 48.80 ns/read
بالعامية

شغّلته 6 مرات على جهاز عليه ضغط من شغل تاني، فخد الأرقام كـ ترتيب حجم مش كـ قيمة مظبوطة: الـ object العادي ≈ 0.5–1.4 ns للقراية، الـ Proxy من غير traps ≈ 9–22 ns (يعني ≈ 15–25 مرة)، والـ Proxy بـ get trap ≈ 20–50 ns (يعني ≈ 35–80 مرة). السبب إن القراية العادية الـ JIT بيحوّلها لقراية من offset ثابت (هتشوف ده في Lesson 18)، إنما الـ proxy بيعدّي على handler وندا function.

فين هستخدمه في شغلي؟ 50 ns يعني حوالي 20 مليون قراية في الثانية. على config أو feature flags ده مش فارق خالص، حتى لو بتقرا منهم في كل request. إنما لو لفّيت كل row في export بمليون صف وبتقرا 10 columns من كل واحد، ده 10 مليون قراية، يعني ≈ نص ثانية CPU زيادة على الـ event loop. القاعدة: Proxy على الحدود (config، SDK)، مش جوه أهم loop عندك.
Trade-off A proxy buys you interception without touching the wrapped code, and pays with tens of nanoseconds per operation, a new identity, and stack traces that go through your handler. Prefer an explicit wrapper function when you know exactly which methods you need to wrap.
الـ proxy بيديك إنك تعترض العمليات من غير ما تلمس الكود الملفوف، وتمنه عشرات الـ nanoseconds لكل عملية، و identity جديدة، و stack traces بتعدّي على الـ handler بتاعك. لو عارف بالظبط أنهي methods محتاج تلفها، function wrapper صريحة أحسن.
Interview question "Why does new Proxy(new Map(), {}).get('a') throw, and how do you fix it?" → Map.prototype.get reads an internal slot on this, and this is the proxy, which has no such slot. Fix: in the get trap, read with the target as receiver and return methods bound to the target. The same happens with #private fields, because private names are not forwarded by the proxy.
"ليه new Proxy(new Map(), {}).get('a') بترمي error، وتصلحها إزاي؟" ← Map.prototype.get بتقرا internal slot من this، وthis هنا الـ proxy، والـ proxy معندوش الـ slot ده. الحل: في الـ get trap اقرا بالـ target كـ receiver، ورجّع الـ methods مربوطة بالـ target. ونفس الموضوع بيحصل مع #private fields، لأن الـ proxy مش بيعدّي الـ private names.

Part 2 — A reactive store from scratch 🔴 Advancedالجزء 2 — reactive store من الصفر

English

Reactivity is two traps and a data structure. While a watcher function runs, every get trap records "this effect read this key on this object" (track). Every set looks up who read that key and re-runs them (trigger). You never declare dependencies: running the function discovers them. Vue 3's reactive()/effect() and MobX's observable/autorun are built on this idea. The version below is about 65 lines and passes 8 tests.

Four details separate a toy from something that works. Lazy nesting: nested objects get wrapped when first read, so cart.lines[0].qty = 3 is tracked too. Dependency cleanup: before each run an effect removes itself from its old dependencies and re-collects them, so a branch it no longer reads can't wake it. Change detection: writing the same value does nothing (Object.is). Iteration: ownKeys tracks a special ITERATE key, which gets triggered when a key is added or deleted, so Object.keys stays correct.

The tests caught a real bug in the first draft: cart.lines.push(item) did not wake a watcher reading the array. push writes the new index first, and that write grows length on its own. When push then assigns length, the old and new values are already equal, so nothing fires. The fix is to trigger "length" whenever a new index is added. This store is synchronous and has no computed, no Map/Set support and no batching (exercise 2 adds batching). A push inside a watcher would loop forever, which real libraries guard against.

type Key = string | symbol;

const targetMap = new WeakMap<object, Map<Key, Set<Effect>>>();
// كاش عشان نفس الـ object يرجّع نفس الـ proxy دايمًا
const proxies = new WeakMap<object, object>();
const ITERATE = Symbol("iterate");
let activeEffect: Effect | null = null;

function track(target: object, key: Key): void {
  if (!activeEffect) return;
  let deps = targetMap.get(target);
  if (!deps) targetMap.set(target, (deps = new Map()));
  let dep = deps.get(key);
  if (!dep) deps.set(key, (dep = new Set()));
  dep.add(activeEffect);
  activeEffect.deps.add(dep);
}

function trigger(target: object, key: Key): void {
  // نسخة من الـ Set عشان الـ cleanup بيعدّل فيه وإحنا بنلف عليه
  for (const effect of new Set(targetMap.get(target)?.get(key))) effect();
}

export function reactive<T extends object>(target: T): T {
  const cached = proxies.get(target);
  if (cached) return cached as T;
  const proxy = new Proxy(target, {
    get(t, key, receiver) {
      track(t, key);
      const value = Reflect.get(t, key, receiver);
      // الـ nested objects بتتلف lazy أول ما حد يقراها
      return typeof value === "object" && value !== null ? reactive(value) : value;
    },
    set(t, key, value, receiver) {
      const isNew = !Reflect.has(t, key);
      const old = Reflect.get(t, key, receiver);
      const ok = Reflect.set(t, key, value, receiver);
      if (isNew) {
        trigger(t, ITERATE);
        // الكتابة في index جديد بتزوّد الـ length لوحدها، فلازم نصحّي اللي قاريه
        if (Array.isArray(t)) trigger(t, "length");
      }
      if (isNew || !Object.is(old, value)) trigger(t, key);
      return ok;
    },
    has(t, key) {
      track(t, key);
      return Reflect.has(t, key);
    },
    ownKeys(t) {
      track(t, ITERATE);
      return Reflect.ownKeys(t);
    },
    deleteProperty(t, key) {
      const existed = Reflect.has(t, key);
      const ok = Reflect.deleteProperty(t, key);
      if (existed) { trigger(t, key); trigger(t, ITERATE); }
      return ok;
    },
  });
  proxies.set(target, proxy);
  return proxy;
}

export function watch(fn: () => void): () => void {
  const effect = (() => {
    // امسح الـ deps القديمة: الفرع اللي مبقاش بيتقري ميصحّيش الـ effect
    for (const dep of effect.deps) dep.delete(effect);
    effect.deps.clear();
    const previous = activeEffect;
    activeEffect = effect;
    try { fn(); } finally { activeEffect = previous; }
  }) as Effect;
  effect.deps = new Set();
  effect();
  // الـ stop: بيفصل الـ effect عن كل الـ deps بتاعته
  return () => { for (const dep of effect.deps) dep.delete(effect); effect.deps.clear(); };
}

Interview question "How does Vue 3 know what to re-render, and why did it move from Object.defineProperty to Proxy?" → While a component's render effect runs, each read goes through a get trap that records the effect against that key. A write looks up the effects for that key and schedules them. defineProperty needs each key to exist up front, so it can't see new keys, deletes or array index writes. A proxy intercepts all of them, and it can wrap nested objects lazily.
"إزاي Vue 3 بيعرف يعمل re-render لإيه، وليه سابت Object.defineProperty وراحت لـ Proxy؟" ← وهو بيشغّل الـ render effect بتاع الـ component، كل قراية بتعدّي على get trap بيسجّل الـ effect على الـ key ده. والكتابة بتدوّر على الـ effects بتاعة الـ key وبتعملهم schedule. الـ defineProperty محتاج كل key يبقى موجود من الأول، فمش شايف الـ keys الجديدة ولا الـ delete ولا الكتابة في index في array. إنما الـ proxy بيعترض ده كله، وكمان يقدر يلف الـ nested objects بشكل lazy.

Part 3 — Reflect 🔴 Advancedالجزء 3 — الـ Reflect

English

Reflect has one static method for each proxy trap, with the same name and the same arguments. It exists for two reasons. First, it gives a trap a correct way to perform the default behaviour, including the part you can't reproduce with target[key]: the receiver. Second, it turns operators and throwing APIs into plain functions with useful return values.

The receiver is the value this takes inside a getter or setter. When you read proxy.gross, the receiver is the proxy. If your trap forwards with target[key], the getter runs with this = target and reads bypass the proxy. That shows up in two ways: an object that inherits from the proxy gets the wrong this, and a reactive store stops tracking whatever the getter reads. Reflect.get(target, key, receiver) fixes both.

The return values matter outside proxies too. Object.defineProperty throws on failure, while Reflect.defineProperty returns false. Reflect.set and Reflect.deleteProperty also report failure with false instead of throwing in strict mode. Reflect.ownKeys is the only single call that returns string keys, symbols and non-enumerable keys together.

Interview question "Why write Reflect.get(target, key, receiver) instead of target[key] in a proxy?" → The receiver keeps this correct inside getters. Part 4 — Tagged templates 🔴 Advancedالجزء 4 — الـ tagged templates

English

A tag is an ordinary function called with special arguments. For tag`a${x}b${y}c`, it receives strings = ["a", "b", "c"] and then x, y. There is always one more string than there are values. The array is frozen, and strings.raw holds the source text with escapes unprocessed. The same call site gets the same array object on every call, which makes it an ideal cache key (the output below prints true false false).

The key property is that the tag can tell code you wrote (strings) from data that arrived at runtime (values). A plain template literal glues them into one string and that distinction is gone for good. A sql tag therefore never concatenates values: it emits placeholders and sends the values separately, so the database never parses them as SQL. An html tag escapes every value unless it was explicitly marked safe. An i18n tag uses the strings as a lookup key and can reorder values for another language. A styled-components-style tag can even take functions as values and return a function of props.

Placeholders protect values only. A table name, a column name or a sort direction can't be a parameter. If you pass one anyway, you don't get an error: ORDER BY $1 sorts by a constant, so the sort silently does nothing. Identifiers must come from an allowlist in your code.

import { DatabaseSync } from "node:sqlite";

class SqlQuery {
  readonly text: string;
  readonly values: unknown[];
  constructor(text: string, values: unknown[]) {
    this.text = text;
    this.values = values;
  }
}

// الـ tag: كل قيمة بتبقى parameter، وأي ⁦sql``⁩ جوه ⁦sql``⁩ بيتدمج بأرقام صح
export function sql(strings: TemplateStringsArray, ...args: unknown[]): SqlQuery {
  let text = strings[0];
  const values: unknown[] = [];
  args.forEach((arg, i) => {
    if (arg instanceof SqlQuery) {
      text += arg.text.replace(/\$(\d+)/g, (_, n) => `$${Number(n) + values.length}`);
      values.push(...arg.values);
    } else {
      values.push(arg);
      text += `$${values.length}`;
    }
    text += strings[i + 1];
  });
  return new SqlQuery(text, values);
}

بالعامية

الـ tag ده function عادية بتتنده بـ arguments مخصوصة. مع tag`a${x}b${y}c` بتاخد strings = ["a", "b", "c"] وبعدين x, y، ودايمًا عدد الـ strings أكتر من الـ values بواحد. الـ array متجمّدة، وstrings.raw فيها النص الأصلي من غير ما الـ escapes تتفك. ونفس الـ call site بياخد نفس الـ array object كل مرة، وده بيخليها cache key ممتاز، وعشان كده الـ output طبع true false false.

أهم حاجة إن الـ tag يقدر يفرّق بين الكود اللي إنت كتبته (strings) والـ data اللي جاية وقت التشغيل (values). الـ template literal العادي بيلزقهم في string واحد، والفرق ده بيضيع للأبد. فالـ sql tag عمره ما بيلزق القيم: بيطلّع placeholders وبيبعت القيم لوحدها، فالـ DB عمرها ما بتحللهم كـ SQL. وبص الفرق في الـ output الحقيقي (node:sqlite شغال بجد): النص الملزوق رجّع كل الـ orders بتاعة كل الناس [ 'o_1', 'o_2', 'o_3' ]، والـ tag رجّع [].

والـ placeholders بتحمي القيم بس. اسم جدول أو column أو اتجاه sort مينفعش يبقى parameter. ولو عملت كده مش هتاخد error: ORDER BY $1 بيرتّب بقيمة ثابتة، فالترتيب مش بيحصل في صمت. بص param sort رجع بترتيب الإدخال o_1, o_2, o_3، وreal sort رتّب صح. الـ identifiers لازم تيجي من allowlist في الكود بتاعك، زي SORTABLE.

فين هستخدمه في شغلي؟ ده بالظبط شكل postgres.js و sql بتاع Drizzle و $queryRaw بتاع Prisma، ولاحظ إن Prisma عندها $queryRawUnsafe للي بياخد string عادي، وده اللي لازم يقلقك في code review. عندك endpoint زي GET /orders?sort=biggest؟ ماب sort على allowlist زي SORTABLE، ومتحطش الـ query param في الـ SQL أبدًا. ولو عايز IN مع list في Postgres، ابعت array واحدة كـ value واكتب WHERE id = ANY(${ids}).
A tag doesn't protect you if nobody calls it as a tag Calling it as a normal function with a built string skips the protection. In TypeScript the compiler stops this, because a string isn't a TemplateStringsArray: error TS2345: Argument of type 'string' is not assignable to parameter of type 'TemplateStringsArray'. In plain JavaScript nothing stops it, so a library should check Array.isArray(strings?.raw) at runtime.
الـ tag مش هيحميك لو حد ندهله كـ function عادية بـ string مبني بالإيد. في TypeScript الـ compiler بيوقف ده لأن string مش TemplateStringsArray، والرسالة اللي فوق هي الرسالة الحقيقية من TS 7. إنما في JavaScript العادي مفيش حاجة هتوقفه، فأي library المفروض تتأكد وقت التشغيل بـ Array.isArray(strings?.raw).

// (1) الـ html tag: كل قيمة بتتعمل لها escape إلا لو اتعلّمت إنها آمنة صراحةً
class SafeHtml {
  readonly value: string;
  constructor(value: string) { this.value = value; }
  toString() { return this.value; }
}
const ESCAPES: Record<string, string> = { "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;", "'": "&#39;" };
const escapeHtml = (s: string) => s.replace(/[&<>"']/g, (c) => ESCAPES[c]);

function html(strings: TemplateStringsArray, ...values: unknown[]): SafeHtml {
  const render = (v: unknown): string =>
    v instanceof SafeHtml ? v.value
    : Array.isArray(v) ? v.map(render).join("")
    : v === null || v === undefined || v === false ? ""
    : escapeHtml(String(v));
  return new SafeHtml(strings.reduce((out, part, i) => out + part + (i < values.length ? render(values[i]) : ""), ""));
}

// (2) الـ i18n tag: الـ strings هي مفتاح الترجمة، والقيم بتتحط بالرقم عشان الترتيب يتغيّر
const catalogs: Record<string, Record<string, string>> = {
  ar: { "{0} has {1} open orders": "عند {0} عدد {1} طلبات مفتوحة" },
  de: { "{0} has {1} open orders": "{1} offene Bestellungen für {0}" },
};
function i18n(locale: string) {
  return (strings: TemplateStringsArray, ...values: unknown[]) => {
    const key = strings.reduce((k, part, i) => k + part + (i < values.length ? `{${i}}` : ""), "");
    const template = catalogs[locale]?.[key] ?? key;
    return template.replace(/\{(\d+)\}/g, (_, n) => String(values[Number(n)]));
  };
}

Part 5 — Symbol.toPrimitive, valueOf, toString 🔴 Advancedالجزء 5 — الـ Symbol.toPrimitive و valueOf و toString

English

When an operator needs a primitive and gets an object, the engine runs ToPrimitive with a hint: "string", "number" or "default". The hint comes from the context: template literals and String(x) ask for "string"; arithmetic, unary + and relational comparisons ask for "number"; binary + and == ask for "default", because they can't know yet whether they want text or a number.

If the object has [Symbol.toPrimitive], it's called with the hint and must return a primitive, or you get a TypeError. Otherwise the engine tries two methods in order: for "string", toString then valueOf; for the other two, valueOf then toString. Date is the built-in exception: its default hint behaves as a string, so date + 1 concatenates while date - 1 subtracts.

This matters for domain types. A plain object in "Total: " + money prints [object Object], and a class with valueOf would quietly add EGP to USD. A Money class can use toPrimitive to refuse implicit arithmetic and still print correctly. toJSON and util.inspect.custom are separate hooks: JSON.stringify and console.log don't go through toPrimitive.

class Money {
  readonly cents: number;
  readonly currency: string;
  constructor(cents: number, currency: string) {
    if (!Number.isInteger(cents)) throw new TypeError(`cents must be an integer: ${cents}`);
    this.cents = cents;
    this.currency = currency;
  }
  add(other: Money): Money {
    if (other.currency !== this.currency) {
      throw new TypeError(`Currency mismatch: ${this.currency} vs ${other.currency}`);
    }
    return new Money(this.cents + other.cents, this.currency);
  }
  compare(other: Money): number {
    if (other.currency !== this.currency) throw new TypeError("Currency mismatch");
    return this.cents - other.cents;
  }
  toString(): string {
    return `${(this.cents / 100).toFixed(2)} ${this.currency}`;
  }
  // الـ string بس مسموح، أي حساب ضمني بيترفض
  [Symbol.toPrimitive](hint: "string" | "number" | "default"): string {
    if (hint === "string") return this.toString();
    throw new TypeError(`Money can't be used as a ${hint} primitive: call .add()/.compare()/.cents`);
  }
  toJSON() {
    return { cents: this.cents, currency: this.currency };
  }
  [inspect.custom]() {
    return `Money<${this.toString()}>`;
  }
}

لما operator يحتاج primitive ويلاقي object، الـ engine بيشغّل ToPrimitive ومعاه hint: "string" أو "number" أو "default". والـ hint جاي من السياق: الـ template literal وString(x) عايزين "string"، والحساب و+ الأحادية والمقارنات عايزين "number"، و+ بين قيمتين و== عايزين "default"، لأنهم لسه مش عارفين هيبقى نص ولا رقم. أول 4 أجزاء في الـ output بتوري كل hint بيطلع إمتى.

لو الـ object فيه [Symbol.toPrimitive]، بيتنده بالـ hint ولازم يرجّع primitive، وإلا تاخد TypeError. غير كده الـ engine بيجرّب method ورا التانية: مع "string" بيبدأ بـ toString وبعدين valueOf، ومع الاتنين التانيين بيبدأ بـ valueOf وبعدين toString، وده اللي طبعه [ 'toString', 'valueOf', 'valueOf' ]. وDate هي الاستثناء الجاهز: الـ default hint بتاعها بيتعامل كـ string، فـ date + 1 بتلزق نص (string في الـ output)، وdate - 1 بتطرح. وده حاجة تكمل على الـ coercion اللي في Lesson 01، والـ Symbols في Lesson 06.

الموضوع بيفرق في الـ domain types. الـ object العادي في "Total: " + money بيطبع [object Object]، والـ class اللي فيها valueOf ممكن تجمع EGP على USD في صمت. الـ Money هنا بتستخدم toPrimitive عشان ترفض الحساب الضمني، وفي نفس الوقت تتطبع صح في الـ template literal. وtoJSON وutil.inspect.custom دول hooks منفصلة: JSON.stringify وconsole.log مش بيعدّوا على toPrimitive، وLesson 19 بيكمّل في toJSON.

English

A decorator is a function that runs once, when the class is defined, receives the thing being decorated, and can return a replacement. Two different systems share the @ syntax. The TC39 proposal (often called standard decorators) has the signature (value, context) => replacement, and TypeScript has compiled it by default since 5.0. Legacy decorators have the signature (target, key, descriptor), sit behind the experimentalDecorators flag, and are the only form with parameter decorators and emitDecoratorMetadata.

No runtime I could test parses the syntax. Node 22.19 throws SyntaxError: Invalid or unexpected token, with or without --experimental-transform-types, and so does Chrome 156. Decorators are a compile-time feature today. tsc with --target es2025 or lower, or esbuild with --target=node22, lowers them to plain JavaScript. The trap: --target esnext leaves @logged in the output, because it assumes the runtime supports it. The compile succeeds and Node crashes.

Execution order: decorator expressions evaluate top to bottom, then decorators apply bottom to top, so the one written first ends up outermost. With @logged @retry, the log line prints once per call while retries happen inside it. Return a function, not an arrow, so this arrives correctly and #private fields keep working. context.addInitializer runs for each instance, which is how @bound fixes the lost-this bug from Lesson 04.

type Method<This, Args extends unknown[], R> = (this: This, ...args: Args) => R;

// الـ decorator function عادية: بتاخد الـ method والـ context وبترجّع البديل
function logged<This, Args extends unknown[], R>(
  original: Method<This, Args, R>,
  context: ClassMethodDecoratorContext<This, Method<This, Args, R>>,
): Method<This, Args, R> {
  const name = String(context.name);
  // لازم function عادية مش arrow عشان الـ this يوصل صح
  return function (this: This, ...args: Args): R {
    console.log(`[log] ${name}(${args.join(", ")})`);

  };
}

const sleep = (ms: number) => new Promise((resolve) => setTimeout(resolve, ms));

// الـ decorator factory: function بترجّع decorator، عشان تاخد options
function retry(options: { attempts: number; baseMs: number }) {
  return function <This, Args extends unknown[], R>(
    original: Method<This, Args, Promise<R>>,
    context: ClassMethodDecoratorContext<This, Method<This, Args, Promise<R>>>,
  ): Method<This, Args, Promise<R>> {
    return async function (this: This, ...args: Args): Promise<R> {
      for (let attempt = 1; ; attempt++) {
        try {
          return await original.apply(this, args);
        } catch (err) {
          console.log(`[retry] ${String(context.name)} attempt ${attempt} failed: ${(err as Error).message}`);
          if (attempt >= options.attempts) throw err;
          await sleep(options.baseMs * 2 ** (attempt - 1));
        }
      }
    };
  };
}

// الـ addInitializer بيشتغل مع كل instance، وده بيحل مشكلة الـ lost this
function bound<This, Args extends unknown[], R>(
  original: Method<This, Args, R>,
  context: ClassMethodDecoratorContext<This, Method<This, Args, R>>,
): void {
  context.addInitializer(function (this: This) {
    (this as Record<string | symbol, unknown>)[context.name] = original.bind(this);
  });
}

Legacy decorators and NestJSالـ legacy decorators و NestJS

English

NestJS 12 (the current major, checked on npm) still runs on the legacy form: its official starter's tsconfig.json sets both experimentalDecorators and emitDecoratorMetadata. The second flag is what makes constructor injection work. The compiler writes the constructor's parameter types into design:paramtypes, and Nest reads them through reflect-metadata to know what to inject. The standard form can't replace this today: TypeScript rejects parameter decorators like @Body() with TS1206, and rejects emitDecoratorMetadata without the legacy flag with TS5052.

The dangerous failure is silent. Remove either flag from a Nest project and tsc still exits with code 0, because Nest's Injectable() happens to fit both signatures. At runtime no metadata exists, so the dependency is undefined and you only find out at the first call. esbuild has the same effect: it has no type checker, so it can't emit design:paramtypes even with the flag on. The flag is per project, so a Nest codebase writes its own decorators in the legacy signature too.

Part 7 — eval & new Function 🔴 Advancedالجزء 7 — الـ eval و new Function

English

eval and new Function compile a string into code at runtime. They differ in scope: direct eval(...) sees the local variables around it, while indirect eval (0, eval)(...) and new Function see only globals. Neither is a sandbox. Global scope in Node contains process, and process.getBuiltinModule("fs") hands out any built-in module without an import. If a user can reach this string, the user can read your env vars and files, or hang the event loop with while (true) {}. node:vm doesn't fix this: the Node docs state plainly that it is not a security mechanism, and the one-line escape below proves it.

Performance is more nuanced than "eval is slow". What's slow is compiling repeatedly: a new Function per call costs ≈ 500 times a plain call. A new Function compiled once costs the same as a normal function afterwards, because V8 optimizes it like any other. Direct eval also has a cost when it never runs: its mere presence forces the surrounding variables to stay available by name, measured at ≈ 7 times slower here.

In browsers, a Content Security Policy without 'unsafe-eval' blocks both with an EvalError, and a site that needs unsafe-eval weakens its XSS protection. Node has an equivalent flag: --disallow-code-generation-from-strings. The legitimate exceptions share one property: the source text is authored by the developer, not the user. Template compilers, Zod 4's fast path (new F("") probes whether eval is allowed, and z.config({ jitless: true }) turns it off), and fast-json-stringify (used by Fastify) all generate code from a schema you wrote. For user-defined logic, parse it into a small AST and interpret only what you allow.

// البديل الآمن: parser صغير بيفهم حساب ومتغيرات ودوال من allowlist بس
type Node =
  | { type: "num"; value: number }
  | { type: "var"; name: string }
  | { type: "bin"; op: string; left: Node; right: Node }
  | { type: "neg"; arg: Node }
  | { type: "call"; name: string; args: Node[] };

const FUNCTIONS: Record<string, (...args: number[]) => number> = {
  min: Math.min,
  max: Math.max,
  round: Math.round,
};
const MAX_LENGTH = 200;

export function parseFormula(source: string): Node {
  if (source.length > MAX_LENGTH) throw new Error(`Formula too long (max ${MAX_LENGTH})`);
  const tokens = source.match(/\d+(?:\.\d+)?|[a-zA-Z_]\w*|[-+*/(),]|\S/g) ?? [];
  let pos = 0;
  const peek = () => tokens[pos];
  const next = () => tokens[pos++];
  const expect = (t: string) => {
    if (next() !== t) throw new Error(`Expected "${t}" at token ${pos}`);
  };

  // كل مستوى precedence ليه function: الجمع فوق، الضرب تحته، والقيم في الآخر
  function expr(): Node {
    let left = term();
    while (peek() === "+" || peek() === "-") left = { type: "bin", op: next(), left, right: term() };
    return left;
  }
  function term(): Node {
    let left = factor();
    while (peek() === "*" || peek() === "/") left = { type: "bin", op: next(), left, right: factor() };
    return left;
  }
  function factor(): Node {
    const t = next();
    if (t === undefined) throw new Error("Unexpected end of formula");
    if (t === "-") return { type: "neg", arg: factor() };
    if (t === "(") {
      const inner = expr();
      expect(")");
      return inner;
    }
    if (/^\d/.test(t)) return { type: "num", value: Number(t) };
    if (/^[a-zA-Z_]/.test(t)) {
      if (peek() !== "(") return { type: "var", name: t };
      next();
      const args: Node[] = [];
      if (peek() !== ")") {
        args.push(expr());
        while (peek() === ",") { next(); args.push(expr()); }
      }
      expect(")");
      if (!Object.hasOwn(FUNCTIONS, t)) throw new Error(`Unknown function: ${t}`);
      return { type: "call", name: t, args };
    }
    throw new Error(`Unexpected token: ${t}`);
  }

  const tree = expr();
  if (pos !== tokens.length) throw new Error(`Unexpected token: ${peek()}`);
  return tree;
}

export function evaluate(node: Node, vars: Record<string, number>): number {
  switch (node.type) {
    case "num": return node.value;
    case "neg": return -evaluate(node.arg, vars);
    case "var":
      // الـ hasOwn بيمنع constructor و ⁦__proto__⁩ وأي حاجة موروثة
      if (!Object.hasOwn(vars, node.name)) throw new Error(`Unknown variable: ${node.name}`);
      return vars[node.name];
    case "call": return FUNCTIONS[node.name](...node.args.map((a) => evaluate(a, vars)));
    case "bin": {
      const l = evaluate(node.left, vars), r = evaluate(node.right, vars);
      if (node.op === "+") return l + r;
      if (node.op === "-") return l - r;
      if (node.op === "*") return l * r;
      if (r === 0) throw new Error("Division by zero");
      return l / r;
    }
  }
}

الفكرة إن الـ formula بقت data مش كود: الـ tokenizer بيقطعها، والـ parser بيبني شجرة (كل مستوى precedence ليه function: expr للجمع، term للضرب، factor للقيم)، والـ evaluate بيمشي على الشجرة. مفيش eval في أي حتة، فكل الـ exploits اللي نجحت فوق اترفضت هنا. وObject.hasOwn هو اللي منع constructor و__proto__ إنهم يوصلوا لحاجة موروثة، وده غلطة شائعة لو كتبت vars[name] على طول. والـ while اترفضت لأنها مش في الـ allowlist، فمفيش loops ومفيش DoS منها، والـ MAX_LENGTH بيحدد حجم الـ input، فعمق الـ recursion محدود.

فين هستخدمه في شغلي؟ خزّن الـ formula كـ string في جدول pricing_rules، واعمل parse وقت الحفظ عشان التاجر ياخد error فوري لو غلط، وخزّن الـ AST كـ JSONB لو عايز توفّر الـ parse. وبعدين evaluate(ast, { price, qty, discount }) مع كل order. ولو هتستخدم library جاهزة بدل ما تكتب parser، بص الأول إنها مش بتعمل compile لـ new Function من جوه. ولو لازم فعلًا تشغّل كود حقيقي بتاع user، يبقى process أو container منفصل، من غير secrets، وبحدود CPU و memory.
Interview question "A merchant wants custom pricing formulas. Can you run them with new Function inside vm with a timeout?" → No. vm isn't a security boundary (this.constructor.constructor escapes it), and a timeout does nothing for secrets. Define a small expression language: parse into an AST, allowlist variables and functions, cap the input length, and interpret it. For real user code, isolate it in a separate process or container with no secrets.
"تاجر عايز formulas مخصوصة للسعر. ينفع تشغّلها بـ new Function جوه vm مع timeout؟" ← لأ. الـ vm مش security boundary (this.constructor.constructor بيهرب منه)، والـ timeout مش بيحمي الـ secrets. اعمل expression language صغيرة: parse لـ AST، و allowlist للمتغيرات والـ functions، وحد أقصى لطول الـ input، وinterpreter. ولو هو كود user حقيقي، اعزله في process أو container منفصل من غير secrets.

Common mistakes · غلطات شائعة

❌ Forwarding with target[key] 
new Proxy(invoice, {
  get(target, key) {
    track(key);
    // الـ getter هيشتغل والـ this بتاعه الـ target
    return target[key];
  },
});
// tracked: [ 'gross' ]
✅ Reflect.get with the receiver 
new Proxy(invoice, {
  get(target, key, receiver) {
    track(key);
    // الـ getter بيقرا من الـ proxy فكل حاجة بتتتبع
    return Reflect.get(target, key, receiver);
  },
});
// gross after net = 200: 214
بالعامية

❌ target[key] بيشغّل الـ getter وthis بتاعه هو الـ target الخام، فأي قراية جوه الـ getter بتعدّي من غير الـ proxy، ويتسجل gross بس، والـ watcher ميتحدّثش لما net تتغير. ✅ الـ receiver بيوصّل الـ proxy كـ this، فـ net وvat بيتتبعوا، والـ watcher بيدي 214.

❌ Proxy around a Map or a class with #private 
const sessions = new Proxy(new Map(), {});
sessions.get("s_1");
// ✗ TypeError: Method Map.prototype.get called on incompatible receiver #<Map>
✅ Bind methods to the target 
const sessions = new Proxy(new Map(), {
  get(target, key) {
    const value = Reflect.get(target, key, target);
    return typeof value === "function" ? value.bind(target) : value;
  },
});
sessions.get("s_1");
بالعامية

❌ this جوه Map.prototype.get بيبقى الـ proxy، والـ proxy معندوش الـ internal slot، فبيرمي incompatible receiver، ونفس الكلام مع #private بس بـ Cannot read private member. ✅ بنقرا بالـ target كـ receiver وبنربط الـ methods بيه، فالـ method بتشتغل على الـ Map الأصلية.

❌ A column name as a parameter 
const sort = req.query.sort;
sql`SELECT id FROM orders ORDER BY ${sort}`;
// [ 'o_1', 'o_2', 'o_3' ]

if (!Object.hasOwn(SORTABLE, key)) throw new Error("Bad sort");
sql`SELECT id FROM orders ${orderBy(key)}`;
// [ 'o_2', 'o_3', 'o_1' ]
بالعامية

❌ الـ parameter بيتبعت كـ string ثابت، فالـ DB بترتّب بقيمة واحدة لكل الصفوف، يعني مفيش ترتيب ومفيش error، والـ bug بيعدّي من الـ review. وأسوأ حاجة ممكن حد يعملها إنه "يصلحها" بلزق النص في الـ SQL، وساعتها رجعت الـ injection. ✅ الـ user بيختار اسم من الـ allowlist، والـ SQL نفسه مكتوب في كودك، وأي قيمة تانية بتترفض.

1. Deep read-only config 🟢 easy Write deepReadonly(obj) with a Proxy: any write, delete or defineProperty throws at any depth, while reads keep working. Test it with assert.throws.
اكتب deepReadonly(obj) بـ Proxy: أي كتابة أو مسح أو defineProperty ترمي error في أي عمق، والقراية تفضل شغالة. واختبره بـ assert.throws.
Hint · تلميح In the get trap, wrap nested objects before returning them, otherwise the protection is only one level deep.
في الـ get trap، لف الـ nested objects قبل ما ترجّعها، وإلا الحماية هتبقى مستوى واحد بس.
Solution · الحل 
// الحل: deep readonly بـ Proxy، وبيتجرب بـ node ex1-readonly.ts
import assert from "node:assert/strict";

function deepReadonly<T extends object>(target: T): T {
  return new Proxy(target, {
    get(t, key, receiver) {
      const value = Reflect.get(t, key, receiver);
      // الـ nested لازم يتلف هو كمان، وإلا الحماية تبقى سطحية
      return typeof value === "object" && value !== null ? deepReadonly(value) : value;
    },
    set(_t, key) {
      throw new TypeError(`Read-only config: cannot set ${String(key)}`);
    },
    deleteProperty(_t, key) {
      throw new TypeError(`Read-only config: cannot delete ${String(key)}`);
    },
    defineProperty(_t, key) {
      throw new TypeError(`Read-only config: cannot define ${String(key)}`);
    },
  });
}

assert.throws(() => { config.port = 1; }, /cannot set port/);
assert.throws(() => { config.db.pool.max = 99; }, /cannot set max/);
assert.throws(() => { delete (config.db as { host?: string }).host; }, /cannot delete host/);
assert.throws(() => Object.defineProperty(config, "x", { value: 1 }), /cannot define x/);
console.log("all assertions passed");

2. Batch the watcher 🟡 medium Our watch re-runs on every write, so three writes mean three runs. Build batched(fn) on top of watch so that all writes in the same tick cause one run, using queueMicrotask. It must still support stopping.
الـ watch بتاعنا بيشتغل مع كل كتابة، يعني 3 كتابات = 3 runs. ابني batched(fn) فوق watch بحيث كل الكتابات في نفس الـ tick تعمل run واحد، باستخدام queueMicrotask، ولازم الـ stop يفضل شغال.
Hint · تلميح On the first trigger, stop the current effect so later writes can't wake it, and schedule one microtask that starts a fresh watch. Running fn again inside that new watch re-collects the dependencies.
أول trigger: وقّف الـ effect الحالي عشان الكتابات اللي بعدها متصحّيهوش، واعمل schedule لـ microtask واحد بيبدأ watch جديد. وتشغيل fn جوه الـ watch الجديد هو اللي بيجمع الـ deps من الأول.
Solution · الحل 
// الحل: watch بـ scheduler بيجمّع كل الكتابات في microtask واحد
import assert from "node:assert/strict";
import { reactive, watch } from "../src/reactive.ts";

function batched(fn: () => void): () => void {
  let scheduled = false, stopped = false;
  let stopCurrent = () => {};
  const start = () => {
    let initial = true;
    stopCurrent = watch(() => {
      if (initial) { initial = false; fn(); return; }
      // أي تغيير بعد كده: افصل الـ effect وأجّل التشغيل، فالكتابات اللي بعدها مش بتصحّيه
      stopCurrent();
      if (scheduled) return;
      scheduled = true;
      queueMicrotask(() => {
        scheduled = false;
        if (!stopped) start();
      });
    });
  };
  start();
  return () => { stopped = true; stopCurrent(); };
}

const cart = reactive({ qty: 1, cents: 100, coupon: 0 });
let runs = 0, total = 0;
const stop = batched(() => { runs++; total = cart.qty * cart.cents - cart.coupon; });
assert.deepEqual([runs, total], [1, 100]);

// 3 كتابات ورا بعض، ومفيش ولا run لحد الـ microtask
cart.qty = 2;
cart.cents = 200;
cart.coupon = 50;
assert.equal(runs, 1);
await Promise.resolve();
assert.deepEqual([runs, total], [2, 350]);

cart.qty = 3;
await Promise.resolve();
assert.deepEqual([runs, total], [3, 550]);

stop();
cart.qty = 10;
await Promise.resolve();
assert.equal(runs, 3);
console.log("all assertions passed, runs =", runs);

3. A @cached decorator 🟡 medium Write @cached({ ttlMs }) in the TC39 form for async repository methods. Concurrent calls with the same arguments must share one query, a failed call must not stay in the cache, and two instances must not share entries. Compile with TS 7 and run it.
اكتب @cached({ ttlMs }) بشكل الـ TC39 لـ async methods في repository. الـ calls المتزامنة بنفس الـ arguments لازم تشارك query واحدة، والـ call اللي فشلت متفضلش في الـ cache، واتنين instances ميشاركوش نفس الـ entries. اعمله compile بـ TS 7 وشغّله.
Hint · تلميح Store the promise rather than the value, so concurrent callers share it. Key the per-instance caches by this in a WeakMap.
خزّن الـ promise نفسها مش القيمة، عشان الـ callers المتزامنين يشاركوها. وخلّي الـ cache بتاع كل instance في WeakMap المفتاح بتاعها this.
Solution · الحل 
// اعمله compile الأول: tsc ex3-cached.ts --target es2023 --module nodenext
import assert from "node:assert/strict";

type AsyncMethod<This, Args extends unknown[], R> = (this: This, ...args: Args) => Promise<R>;

function cached(options: { ttlMs: number }) {
  return function <This extends object, Args extends unknown[], R>(
    original: AsyncMethod<This, Args, R>,
    _context: ClassMethodDecoratorContext<This, AsyncMethod<This, Args, R>>,
  ): AsyncMethod<This, Args, R> {
    // الـ WeakMap بالـ instance: كل object ليه cache لوحده، ولما يموت الـ cache يموت معاه
    const perInstance = new WeakMap<This, Map<string, { at: number; value: Promise<R> }>>();
    return function (this: This, ...args: Args): Promise<R> {
      let cache = perInstance.get(this);
      if (!cache) perInstance.set(this, (cache = new Map()));
      const key = JSON.stringify(args);
      const hit = cache.get(key);
      if (hit && Date.now() - hit.at < options.ttlMs) return hit.value;
      // بنخزن الـ promise نفسها عشان requests متزامنة تاخد نفس النتيجة
      const value = original.apply(this, args);
      const entry = { at: Date.now(), value };
      cache.set(key, entry);
      // لو فشلت متتخزنش: الـ error ميتكاش
      value.catch(() => { if (cache.get(key) === entry) cache.delete(key); });
      return value;
    };
  };
}

class ProductRepo {
  queries = 0;

  @cached({ ttlMs: 30 })
  async findPrice(sku: string): Promise<number> {
    this.queries++;
    if (sku === "bad") throw new Error("db down");
    return 100;
  }
}

const repo = new ProductRepo();

assert.deepEqual(results, [100, 100, 100]);
assert.equal(repo.queries, 2);

await new Promise((r) => setTimeout(r, 40));
await repo.findPrice("kbd");
assert.equal(repo.queries, 3);

await assert.rejects(repo.findPrice("bad"));
await new Promise((r) => setTimeout(r, 0));
await assert.rejects(repo.findPrice("bad"));
assert.equal(repo.queries, 5);

const other = new ProductRepo();

assert.equal(other.queries, 1);

Cheat sheet · الخلاصة

  • Proxy has 13 traps; six matter most. An omitted trap forwards to the target. set returning false throws in strict mode, and invariants stop traps lying about frozen data.
  • Proxy limits: new identity (proxy !== target), no #private or internal slots (Map, Date), and ≈ 20–50 ns per trapped read versus ≈ 1 ns. Use it at boundaries, not in hot loops.
  • Reactivity = track in get + trigger in set + WeakMap → Map → Set. Clean up deps on each run, and trigger length when a new array index appears.
  • Reflect mirrors the traps. Always forward with the receiver. It returns false where Object.* and strict-mode operators throw.
  • Tags receive strings (your code, frozen, same object per call site) and values (runtime data). That split is what makes sql and html tags safe.
  • Placeholders protect values only. ORDER BY $1 silently doesn't sort. Identifiers come from an allowlist.
  • Hints: template literal → string; arithmetic and > → number; + and == → default. Date treats default as string. JSON.stringify uses toJSON.
  • Decorators are Stage 2.7 since May 2026, not Stage 3. No engine ships them: Node 22.19 and Chrome 156 throw SyntaxError. Compile with target ≤ es2025; esnext leaves @ in the output.
  • Legacy vs standard: (target, key, descriptor) vs (value, context). NestJS 12 needs legacy for @Body() and design:paramtypes. Missing flag or esbuild: compiles fine, dependency is undefined.
  • Never run user strings with eval, new Function or vm. Compiling once from developer-owned text is fine and fast. For user logic: parse → AST → allowlist → interpret.
بالعامية
  • الـ Proxy فيه 13 trap وأهمهم ستة. أي trap مش كاتبه العملية بتعدّي للـ target. وset لو رجّعت false بترمي في strict mode، والـ invariants بتمنع الـ trap يكدب على data متجمّدة.
  • حدود الـ Proxy: identity جديدة (proxy !== target)، مش بيوصل لـ #private ولا الـ internal slots (Map وDate)، و ≈ 20–50 ns للقراية بـ trap قصاد ≈ 1 ns. استخدمه على الحدود مش في الـ hot loops.
  • الـ reactivity = track في get + trigger في set + WeakMap → Map → Set. نضّف الـ deps مع كل run، واعمل trigger لـ length لما index جديد يتضاف في array.
  • الـ Reflect نسخة من الـ traps. دايمًا كمّل بالـ receiver. وبيرجّع false في الحالات اللي Object.* والـ operators في strict mode بيرموا فيها.
  • الـ tags بتاخد strings (كودك، متجمّدة، ونفس الـ object لكل call site) وvalues (data وقت التشغيل). والفصل ده هو اللي بيخلي sql وhtml tags آمنين.
  • الـ placeholders بتحمي القيم بس. ORDER BY $1 مش بيرتّب في صمت. والـ identifiers تيجي من allowlist.
  • الـ hints: الـ template literal ← string، الحساب و> ← number، و+ و== ← default. وDate بتعامل الـ default كـ string. وJSON.stringify بيستخدم toJSON.
  • الـ decorators في Stage 2.7 من مايو 2026، مش Stage 3. ومفيش engine بيشغّلها: Node 22.19 و Chrome 156 بيرموا SyntaxError. اعمل compile بـ target لحد es2025، وesnext بيسيب @ في الناتج.
  • الـ legacy والـ standard: (target, key, descriptor) قصاد (value, context). و NestJS 12 محتاج الـ legacy عشان @Body() وdesign:paramtypes. ولو الـ flag ناقص أو بتستخدم esbuild: الـ compile بيعدّي والـ dependency بتبقى undefined.
  • متشغّلش strings بتاعة users أبدًا بـ eval أو new Function أو vm. الـ compile مرة واحدة من نص كاتبه المطور تمام وسريع. ومنطق الـ user: parse ← AST ← allowlist ← interpret.
