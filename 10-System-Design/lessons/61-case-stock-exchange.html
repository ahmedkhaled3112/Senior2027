Why this matters · ليه ده مهم

English

An exchange is the system-design question where every comfortable habit fails: no database in the hot path, no await in the handler, and "fair" has a precise meaning. You will probably never build one, but the design teaches four ideas you reuse everywhere: a single writer per key, a total order assigned before the work happens, recovery by replaying a log, and treating slow consumers as a first-class failure. Any system where order matters, like inventory, wallets or seat booking, uses the same ideas at a lower speed.

بالعامية

الـ exchange هو سؤال الـ system design اللي كل عادة مريحة بتقع فيه: مفيش database في الـ hot path، مفيش await في الـ handler، وكلمة "عادل" ليها معنى محدد. غالبًا عمرك ما هتبني واحد، بس التصميم بيعلّمك 4 أفكار هتستخدمهم في كل حتة: writer واحد لكل key، ترتيب كلّي بيتحدد قبل ما الشغل يبدأ، recovery عن طريق replay لـ log، وإن الـ slow consumer ده فشل لازم تصمم له من الأول. أي نظام الترتيب فيه مهم، زي inventory أو wallet أو حجز مقاعد، بيستخدم نفس الأفكار بسرعة أقل.

English

Be plain from the start: you would not ship this in Node. A real matching engine runs on pinned cores in C++, Rust or Java with no allocation in the hot path. We build it in TypeScript because the lesson is the design, and the code below is small enough to run and break. Every latency on this page is from one loaded Windows machine: read them as ratios.

Functional: place limit and market orders, cancel, partial fills, execution reports to the owner, and a public book feed. Non-functional: throughput from the calculator below; p99 under 1 ms from sequencer to acknowledgement; a total order on every symbol; zero loss of acknowledged orders; failover in seconds, not minutes. Deliberately out of scope: clearing, settlement, margin, and multi-leg orders.

Per-symbol load is what matters, because one symbol is one thread. Symbol popularity is heavily skewed, so a uniform average is wrong; we use a Zipf distribution. API: gateways speak a binary protocol (FIX in the real world); conceptually POST /orders, DELETE /orders/:id, GET /orders/:id, and a market-data subscribe by symbol. Data model: an order is {id, user, side, kind, priceTicks, qty, seq}, a level is {price, total, head, tail}, a journal record is 40 fixed bytes, a trade is {takerId, makerId, price, qty, seq}. Prices are integer ticks, never floats.

// الـ calculator ده نسخة من بتاع الدرس 02 متفصّلة على الـ exchange
const SESSION_SECONDS = 6.5 * 3600;

export function exchangeLoad(input: {
  symbols: number;
  messagesPerDay: number;
  peakFactor: number;
  recordBytes: number;
  subscribers: number;
  updateBytes: number;
}) {
  const avg = input.messagesPerDay / SESSION_SECONDS;
  const peak = avg * input.peakFactor;
  // توزيع Zipf: السهم رقم k نصيبه 1/k من المجموع ⁦H(n)⁩
  let harmonic = 0;
  for (let k = 1; k <= input.symbols; k++) harmonic += 1 / k;
  const topShare = 1 / harmonic;
  let top10 = 0;
  for (let k = 1; k <= 10; k++) top10 += 1 / k / harmonic;
  const hotSymbolPeak = peak * topShare;
  // الميزانية: الـ thread الواحد يفضل عند 50% utilization عشان الـ queue متطولش
  const budgetMicros = (0.5 / hotSymbolPeak) * 1e6;
  return {
    avg,
    peak,
    topShare,
    top10,
    hotSymbolPeak,
    budgetMicros,
    journalGBPerDay: (input.messagesPerDay * input.recordBytes) / 1e9,
    // كل رسالة بتطلع update واحد على الأقل لكل subscriber بالـ unicast
    unicastGbps: (peak * input.updateBytes * input.subscribers * 8) / 1e9,
    multicastGbps: (peak * input.updateBytes * 8) / 1e9,
  };
}

بالعامية

خلينا صرحاء من الأول: إنت مش هتشغّل ده في production بـ Node. الـ matching engine الحقيقي بيجري على cores مخصصة بـ C++ أو Rust أو Java من غير allocation في الـ hot path. بنبنيه هنا بـ TypeScript لأن الدرس عن التصميم، والكود صغير كفاية إنك تشغّله وتكسره. كل الأرقام هنا من جهاز Windows واحد عليه ضغط: اقراها كنِسَب.

الـ Functional: limit و market orders، cancel، partial fills، execution reports لصاحب الأوردر، و feed عام للـ book. الـ Non-functional: الـ throughput من الـ calculator، p99 أقل من 1 ms من الـ sequencer للـ ack، ترتيب كلّي على كل سهم، صفر فقدان للأوردرات اللي أخدت ack، و failover بالثواني. برّه الـ scope عن قصد: clearing، settlement، margin، و multi-leg orders.

الحمل لكل سهم هو اللي يهم، لأن السهم الواحد = thread واحد. وتوزيع الأسهم ملتوي جدًا، فالمتوسط العادي غلط، وبنستخدم Zipf. الـ API: الـ gateways بتتكلم binary protocol (في الواقع FIX)، ومفهوميًا POST /orders وDELETE /orders/:id وGET /orders/:id و subscribe للـ market data بالسهم. الـ Data model: الأوردر {id, user, side, kind, priceTicks, qty, seq}، الـ level هو {price, total, head, tail}، سجل الـ journal 40 byte ثابتين، والـ trade {takerId, makerId, price, qty, seq}. الأسعار integer ticks، عمرها ما تبقى float.

فين هستخدمه في شغلي؟ لما تصمم flash sale لمنتج واحد عليه ضغط: نفس حساب "الحمل على أسخن key" (مش المتوسط) هو اللي بيحدد إذا كان Postgres row واحد هيستحمل ولا محتاج queue لكل product. والـ Zipf ده نفس اللي بتشوفه في top tenants وtop products.

Part 2 — The order book, for real 🔴 Advancedالجزء 2 — الـ order book بجد

English

A book has two sides. Each side holds price levels; each level is a FIFO queue of resting orders. A new order matches against the best opposite level, oldest first (price-time priority), and the trade prints at the maker's price. A partial fill leaves the rest of a limit order resting; the rest of a market order is cancelled. Cancels are a large share of real traffic, so cancel must be O(1): a Map from order id to its node in a doubly linked list, unlinking without any search.

The level index is the design choice. Four structures behind one interface: a sorted array with the best price at the end, a binary heap with lazy deletion (see heaps and priority queues), a red-black tree, and a tick array where the price is the index. The tick array needs a bounded price range, which exchanges have (price bands), and its only slow operation is walking to the next non-empty level when the best one empties.

The measurement below shows why theory alone misleads. Near the top of the book, orders cluster, the array is short and everything is about 100 ns. With orders spread across 20,000 ticks the O(n) splice finally shows: 738 ns against 240 ns for the tick array. All four produce the identical state hash, which is the strongest test in this lesson.

  ---------------- spread ----------------
    price 100 |  o1 q6 -> o4 q1       <-- best bid
    price  99 |  o2 q3
  BIDS (best = highest)

  byId: Map { o4 -> node(level=100, prev=o1, next=null) }

شكل الـ book: كل سعر level فيه طابور FIFO (o1 دخل قبل o4 فهو الأول). أحسن ask هو أقل سعر بيع، وأحسن bid هو أعلى سعر شراء، والفرق بينهم الـ spread. والـ byId الـ Map بتوصّلك لـ node الأوردر مباشرة، فالـ cancel بيفك الـ node بالمؤشرات من غير أي search.

export type Side = "buy" | "sell";
export interface Resting {
  id: number;
  user: number;
  side: Side;
  price: number;
  qty: number;

  next: Resting | null;

export interface Level {
  price: number;
  total: number;
  head: Resting | null;
  tail: Resting | null;
}
// العقد اللي كل الـ structures بتنفّذه، والأفضل دايمًا أصغر key
export interface LevelIndex {
  get(price: number): Level | undefined;
  add(level: Level): void;
  remove(price: number): void;
  best(): Level | undefined;
  all(): Level[];
}

// الأفضل في آخر الـ array، عشان أغلب الشغل بيبقى عند الـ top of book
export class SortedArrayIndex implements LevelIndex {
  private keys: number[] = [];
  private byPrice = new Map<number, Level>();
  private dir: number;
  constructor(dir: number) { this.dir = dir; }
  private find(k: number): number {
    let lo = 0, hi = this.keys.length;
    while (lo < hi) {
      const mid = (lo + hi) >>> 1;
      if (this.keys[mid]! > k) lo = mid + 1; else hi = mid;
    }
    return lo;
  }
  get(price: number) { return this.byPrice.get(price); }
  add(level: Level) {
    const k = this.dir * level.price;
    this.keys.splice(this.find(k), 0, k);
    this.byPrice.set(level.price, level);
  }
  remove(price: number) {
    this.keys.splice(this.find(this.dir * price), 1);
    this.byPrice.delete(price);
  }
  best() {
    const n = this.keys.length;
    return n ? this.byPrice.get(this.dir * this.keys[n - 1]!) : undefined;
  }
  all() { return [...this.keys].reverse().map((k) => this.byPrice.get(this.dir * k)!); }
}

// الـ heap مبيعرفش يمسح من النص، فبنسيب الـ key القديم ونشيله لما يوصل للقمة
export class HeapIndex implements LevelIndex {
  private heap: number[] = [];
  private byPrice = new Map<number, Level>();
  private dir: number;
  constructor(dir: number) { this.dir = dir; }
  get(price: number) { return this.byPrice.get(price); }
  add(level: Level) {
    this.byPrice.set(level.price, level);
    const h = this.heap;
    let i = h.push(this.dir * level.price) - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (h[p]! <= h[i]!) break;
      [h[p], h[i]] = [h[i]!, h[p]!];
      i = p;
    }
  }
  remove(price: number) { this.byPrice.delete(price); }
  private pop() {
    const h = this.heap;
    const last = h.pop()!;
    if (!h.length) return;
    h[0] = last;
    let i = 0;
    for (;;) {
      const l = 2 * i + 1, r = l + 1;
      let m = i;
      if (l < h.length && h[l]! < h[m]!) m = l;
      if (r < h.length && h[r]! < h[m]!) m = r;
      if (m === i) break;
      [h[m], h[i]] = [h[i]!, h[m]!];
      i = m;
    }
  }
  best() {
    while (this.heap.length) {
      const lvl = this.byPrice.get(this.dir * this.heap[0]!);
      if (lvl) return lvl;
      this.pop();
    }
    return undefined;
  }
  all() { return [...this.byPrice.values()].sort((a, b) => this.dir * (a.price - b.price)); }
}

export class TreeIndex implements LevelIndex {
  private tree: InstanceType<typeof rbt.RBTree<number>>;
  private byPrice = new Map<number, Level>();
  private dir: number;
  constructor(dir: number) {
    this.dir = dir;
    this.tree = new rbt.RBTree<number>((a, b) => a - b);
  }
  get(price: number) { return this.byPrice.get(price); }
  add(level: Level) { this.tree.insert(this.dir * level.price); this.byPrice.set(level.price, level); }
  remove(price: number) { this.tree.remove(this.dir * price); this.byPrice.delete(price); }
  best() {
    const k = this.tree.min();
    return k === null ? undefined : this.byPrice.get(this.dir * k);
  }
  all() { return [...this.byPrice.values()].sort((a, b) => this.dir * (a.price - b.price)); }
}

// الـ tick array: السعر هو الـ index، ودي بتشتغل لأن الـ exchange بيحدد price band
export class TickArrayIndex implements LevelIndex {
  private slots: (Level | undefined)[];
  private bestIdx: number;
  private dir: number;
  constructor(dir: number, ticks = 200_000) {
    this.dir = dir;
    this.slots = new Array(ticks).fill(undefined);
    this.bestIdx = dir > 0 ? ticks : -1;
  }
  get(price: number) { return this.slots[price]; }
  add(level: Level) {
    this.slots[level.price] = level;
    if (this.dir * level.price < this.dir * this.bestIdx) this.bestIdx = level.price;
  }
  remove(price: number) {
    this.slots[price] = undefined;
    if (price !== this.bestIdx) return;
    // دي الحالة الوحيدة اللي بتمشي خطوات: دوّر على أقرب سعر فيه أوردرات
    let i = price + this.dir;
    while (i >= 0 && i < this.slots.length && !this.slots[i]) i += this.dir;
    this.bestIdx = i;
  }
  best() { return this.slots[this.bestIdx]; }
  all() {
    const out: Level[] = [];
    if (this.dir > 0) { for (const l of this.slots) if (l) out.push(l); }
    else { for (let i = this.slots.length - 1; i >= 0; i--) if (this.slots[i]) out.push(this.slots[i]!); }
    return out;
  }
}

import { createHash } from "node:crypto";
import { makeIndex, type Level, type LevelIndex, type Resting, type Side } from "./levels.ts";

export interface Ev {
  seq: number;
  act: "new" | "cancel";
  id: number;
  user: number;
  side: Side;
  kind: "limit" | "market";
  price: number;
  qty: number;
}
export type OnFill = (takerId: number, makerId: number, price: number, qty: number) => void;

export class Book {
  private bids: LevelIndex;
  private asks: LevelIndex;
  // الـ map دي هي اللي بتخلي الـ cancel بـ ⁦O(1)⁩ من غير أي search
  private byId = new Map<number, Resting>();
  private free: Resting[] = [];
  private pool: boolean;
  lastSeq = 0;
  fills = 0;
  onFill: OnFill | null = null;

  constructor(opts: { index?: string; pool?: boolean } = {}) {
    const name = opts.index ?? "sorted-array";
    this.bids = makeIndex(name, -1);
    this.asks = makeIndex(name, 1);
    this.pool = opts.pool ?? false;
  }

  apply(ev: Ev): void {
    this.lastSeq = ev.seq;
    if (ev.act === "cancel") this.cancel(ev.id);
    else this.submit(ev);
  }

  private submit(o: Ev): void {
    const opposite = o.side === "buy" ? this.asks : this.bids;
    let left = o.qty;
    while (left > 0) {
      const lvl = opposite.best();
      if (!lvl) break;
      if (o.kind === "limit" && (o.side === "buy" ? lvl.price > o.price : lvl.price < o.price)) break;
      // الأقدم الأول: ده اللي بنسميه price-time priority
      let maker = lvl.head;
      while (maker && left > 0) {
        const q = Math.min(left, maker.qty);
        this.fills++;
        this.onFill?.(o.id, maker.id, lvl.price, q);
        maker.qty -= q;
        lvl.total -= q;
        left -= q;
        if (maker.qty > 0) break;
        const done = maker;
        maker = maker.next;
        this.unlink(done, lvl);
        this.byId.delete(done.id);
        this.release(done);
      }
      if (!lvl.head) opposite.remove(lvl.price);
    }
    // الـ market order الباقي منه بيتلغي، مش بيقعد في الـ book
    if (left > 0 && o.kind === "limit") this.rest(o, left);
  }

  private rest(o: Ev, qty: number): void {
    const own = o.side === "buy" ? this.bids : this.asks;
    let lvl = own.get(o.price);
    if (!lvl) {
      lvl = { price: o.price, total: 0, head: null, tail: null };
      own.add(lvl);
    }
    const r = this.acquire();
    r.id = o.id; r.user = o.user; r.side = o.side; r.price = o.price; r.qty = qty;
    r.level = lvl; r.prev = lvl.tail; r.next = null;
    if (lvl.tail) lvl.tail.next = r; else lvl.head = r;
    lvl.tail = r;
    lvl.total += qty;
    this.byId.set(o.id, r);
  }

  cancel(id: number): boolean {
    const r = this.byId.get(id);
    if (!r) return false;
    const lvl = r.level!;
    lvl.total -= r.qty;
    this.unlink(r, lvl);
    this.byId.delete(id);
    if (!lvl.head) (r.side === "buy" ? this.bids : this.asks).remove(lvl.price);
    this.release(r);
    return true;
  }

  private unlink(r: Resting, lvl: Level): void {
    if (r.prev) r.prev.next = r.next; else lvl.head = r.next;
    if (r.next) r.next.prev = r.prev; else lvl.tail = r.prev;
  }

  // الـ pool بيرجّع نفس الـ objects بدل ما يسيب الـ GC يلمّها
  private acquire(): Resting {
    return this.free.pop() ?? { id: 0, user: 0, side: "buy", price: 0, qty: 0, level: null, prev: null, next: null };
  }
  private release(r: Resting): void {
    r.level = r.prev = r.next = null;
    if (this.pool) this.free.push(r);
  }

  depth(side: Side, n = 5): [number, number][] {
    return (side === "buy" ? this.bids : this.asks).all().slice(0, n).map((l) => [l.price, l.total]);
  }
  levelQty(side: Side, price: number): number {
    return (side === "buy" ? this.bids : this.asks).get(price)?.total ?? 0;
  }
  get size() { return this.byId.size; }

  // الـ snapshot بيحفظ الأوردرات بنفس ترتيب الأولوية، وده اللي بيخلي الـ restore مطابق

    const dump = (idx: LevelIndex) => idx.all().flatMap((l) => {
      const out: [number, number, number, number][] = [];
      for (let r = l.head; r; r = r.next) out.push([r.id, r.user, r.price, r.qty]);
      return out;
    });
    return { lastSeq: this.lastSeq, fills: this.fills, bids: dump(this.bids), asks: dump(this.asks) };
  }
  static restore(s: ReturnType<Book["snapshot"]>, opts: { index?: string; pool?: boolean } = {}): Book {
    const b = new Book(opts);
    const load = (rows: [number, number, number, number][], side: Side) => {
      for (const [id, user, price, qty] of rows) b.rest({ seq: 0, act: "new", id, user, side, kind: "limit", price, qty }, qty);
    };
    load(s.bids, "buy");
    load(s.asks, "sell");
    b.lastSeq = s.lastSeq;
    b.fills = s.fills;
    return b;
  }
  stateHash(): string {
    return createHash("sha256").update(JSON.stringify(this.snapshot())).digest("hex").slice(0, 16);
  }
}

export function mulberry32(seed: number): () => number {
  let a = seed >>> 0;
  return () => {
    a = (a + 0x6d2b79f5) >>> 0;
    let t = a;
    t = Math.imul(t ^ (t >>> 15), t | 1);
    t ^= t + Math.imul(t ^ (t >>> 7), t | 61);
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}

export function genLog(n: number, seed: number, spread = 12): Ev[] {
  const rand = mulberry32(seed);
  const out: Ev[] = new Array(n);
  let mid = 100_000;
  let nextId = 1;
  const live: number[] = [];
  for (let seq = 1; seq <= n; seq++) {
    if (rand() < 0.02) mid += rand() < 0.5 ? -1 : 1;
    const r = rand();
    const side = rand() < 0.5 ? "buy" : "sell";
    if (r < 0.30 && live.length) {
      const i = Math.floor(rand() * live.length);
      const id = live[i]!;
      live[i] = live[live.length - 1]!;
      live.pop();
      out[seq - 1] = { seq, act: "cancel", id, user: 0, side, kind: "limit", price: 0, qty: 0 };
      continue;
    }
    const id = nextId++;
    const user = 1 + Math.floor(rand() * 500);
    const qty = 1 + Math.floor(rand() * 200);
    if (r > 0.88) {
      out[seq - 1] = { seq, act: "new", id, user, side, kind: "market", price: 0, qty };
      continue;
    }
    const offset = Math.floor(rand() * spread);
    const price = side === "buy" ? mid - offset : mid + 1 + offset;
    live.push(id);
    out[seq - 1] = { seq, act: "new", id, user, side, kind: "limit", price, qty };
  }
  return out;
}

Part 3 — Determinism 🔴 Advancedالجزء 3 — الـ Determinism

English

Run a matching engine on the same input twice and you must get the same output, byte for byte. That single property gives you recovery (replay the log), the hot standby (replay it live), and testing (replay production traffic on a laptop). It only holds with one thread per symbol applying events strictly in sequence, because a thread pool or an async gap lets two orders interleave.

The bad version looks harmless: await a risk check inside the handler, then apply. In Node, every message that hits that await resumes when its I/O completes, and libuv's pool finishes them in a different order than they started. The run below uses a real fs.stat: 1,976 orders applied out of sequence, and two runs give two different books. In an exchange that is a lawsuit; in an inventory service it is two users owning the last seat.

The fix is structural. Do anything asynchronous before the sequencer, then apply events from a queue in one synchronous step with no await between read and write. If the engine must reach out mid-match, you have designed the wrong boundary.

Part 4 — Sequencer & fairness 🔴 Advancedالجزء 4 — الـ Sequencer والعدل

English

The sequencer stamps every incoming message with a monotonically increasing number. From that point the system has one truth: the sequence. Everything downstream is a replicated state machine following it. Because the sequence is gapless, consumers detect loss by arithmetic: if the next message is not last + 1, something is missing, and it is fetched from the log (retransmit) before anything else is applied.

Fairness is a definition, not a feeling. With three gateways at 5, 50 and 200 microseconds, plain arrival order means the nearest gateway wins every race. Equalising delay (making every gateway as far as the slowest) buys fairness by adding latency to everyone; real venues do this with equal-length cables, and IEX is known for a 350 microsecond delay using a 38-mile fibre coil. Trusting gateway timestamps moves the problem to clock skew: you would have to wait out the worst skew, and clocks are never exact. Frequent batch auctions remove the race entirely but cost you the batch interval. There is no free option, so you state the definition you chose.

function lossyLink(events: Ev[]): Ev[] {
  const out: Ev[] = [];
  for (const ev of events) {
    const r = rand();
    if (r < 0.01) continue;
    out.push(ev);
    if (r < 0.015) out.push(ev);
    if (r > 0.99 && out.length >= 2) {
      const n = out.length;
      [out[n - 1], out[n - 2]] = [out[n - 2]!, out[n - 1]!];
    }
  }
  return out;
}

class Gapless {
  next = 1;
  gaps = 0;
  dups = 0;
  retransmitted = 0;
  private held = new Map<number, Ev>();
  private apply: (ev: Ev) => void;
  private fetch: (seq: number) => Ev;
  constructor(apply: (ev: Ev) => void, fetch: (seq: number) => Ev) { this.apply = apply; this.fetch = fetch; }
  receive(ev: Ev): void {
    if (ev.seq < this.next) { this.dups++; return; }
    if (ev.seq > this.next) {
      // الرسالة دي سبقت دورها: نحتفظ بيها ونطلب اللي ناقص من الـ log
      this.held.set(ev.seq, ev);
      this.gaps++;
      this.fill(ev.seq);
      return;
    }
    this.deliver(ev);
  }
  private deliver(ev: Ev): void {
    this.apply(ev);
    this.next = ev.seq + 1;
    for (let h = this.held.get(this.next); h; h = this.held.get(this.next)) {
      this.held.delete(this.next);
      this.apply(h);
      this.next = h.seq + 1;
    }
  }
  private fill(upTo: number): void {
    while (this.next < upTo) {
      const ev = this.held.get(this.next) ?? this.fetch(this.next);
      if (!this.held.has(this.next)) this.retransmitted++;
      this.held.delete(this.next);
      this.deliver(ev);
    }
  }
}

Part 5 — Durability 🔴 Advancedالجزء 5 — الـ Durability

English

The rule is one line: journal, then match, then acknowledge. The journal is a write-ahead log: fixed 40-byte records with a CRC, appended and fsynced before the engine touches the book. If the process dies after the fsync, the order is on disk and replay restores it; if it dies before, nobody got an ack, so nothing was promised. Acknowledging first is the bug that loses money.

One fsync per order costs about 0.8 ms on this disk, so it caps you near 1,000 orders per second, which is below even the hot symbol's peak. Group commit fixes it: collect a batch, fsync once, ack them all. Fsync time barely changes with batch size, but each order now waits for its batch to fill: half the batch time on average. At 10,000 orders per second, 1,000-order batches add 50 ms of waiting. Tune batch size to your arrival rate, or flush on a timer.

Recovery is snapshot plus journal tail. A snapshot captures the book at sequence N (written to a temp file and renamed, so it is either complete or absent), then you replay only the records after N. The test that matters: kill the process for real with SIGKILL, recover, and compare the state hash against a clean replay of the same input. A torn final record must be detected by the CRC and dropped, never parsed.

// السجل حجمه ثابت 40 byte: الـ crc في الأول عشان نكشف الكتابة الناقصة
export const RECORD = 40;

export function encode(ev: Ev, buf: Buffer, at: number): void {
  buf.writeUInt32LE(0, at);
  buf.writeBigUInt64LE(BigInt(ev.seq), at + 4);
  buf.writeBigUInt64LE(BigInt(ev.id), at + 12);
  buf.writeUInt32LE(ev.user, at + 20);
  buf.writeUInt8(ev.act === "new" ? 1 : 2, at + 24);
  buf.writeUInt8(ev.side === "buy" ? 1 : 2, at + 25);
  buf.writeUInt8(ev.kind === "limit" ? 1 : 2, at + 26);
  buf.writeUInt32LE(ev.price, at + 28);
  buf.writeUInt32LE(ev.qty, at + 32);
  buf.writeUInt32LE(crc32(buf.subarray(at + 4, at + RECORD)), at);
}

function decode(buf: Buffer, at: number): Ev | null {
  if (at + RECORD > buf.length) return null;
  if (buf.readUInt32LE(at) !== crc32(buf.subarray(at + 4, at + RECORD))) return null;
  return {
    seq: Number(buf.readBigUInt64LE(at + 4)),
    id: Number(buf.readBigUInt64LE(at + 12)),
    user: buf.readUInt32LE(at + 20),
    act: buf.readUInt8(at + 24) === 1 ? "new" : "cancel",
    side: buf.readUInt8(at + 25) === 1 ? "buy" : "sell",
    kind: buf.readUInt8(at + 26) === 1 ? "limit" : "market",
    price: buf.readUInt32LE(at + 28),
    qty: buf.readUInt32LE(at + 32),
  };
}

// بنقف عند أول سجل ناقص أو بايظ، وأي حاجة بعده ماتعتبرش اتكتبت أصلًا
export function readJournal(path: string): Ev[] {
  const buf = readFileSync(path);
  const out: Ev[] = [];
  for (let at = 0; ; at += RECORD) {
    const ev = decode(buf, at);
    if (!ev) return out;
    out.push(ev);
  }
}

export class Journal {
  private fd: number;
  private buf: Buffer;
  private used = 0;
  constructor(path: string, batch: number) {
    this.fd = openSync(path, "a");
    this.buf = Buffer.alloc(RECORD * batch);
  }
  append(ev: Ev): void {
    encode(ev, this.buf, this.used);
    this.used += RECORD;
  }
  // الـ fsync هو اللحظة اللي الأوردر بيبقى فيها durable، قبلها ولا حاجة مضمونة
  commit(): void {
    if (this.used === 0) return;
    writeSync(this.fd, this.buf, 0, this.used);
    fsyncSync(this.fd);
    this.used = 0;
  }
  close(): void { this.commit(); closeSync(this.fd); }
}

// الكتابة في ملف مؤقت وبعدين rename، عشان الـ snapshot يا إما كامل يا إما مش موجود
export function writeSnapshot(path: string, data: unknown): number {
  const tmp = `${path}.tmp`;
  const body = JSON.stringify(data);
  writeFileSync(tmp, body);
  const fd = openSync(tmp, "r+");
  fsyncSync(fd);
  closeSync(fd);
  renameSync(tmp, path);
  return body.length;
}

القاعدة سطر واحد: journal، بعدين match، بعدين ack. الـ journal ده write-ahead log: سجلات ثابتة 40 byte فيها CRC، بتتكتب وبيتعملها fsync قبل ما الـ engine يلمس الـ book. لو الـ process مات بعد الـ fsync، الأوردر على الـ disk والـ replay بيرجعه. لو مات قبله، محدش خد ack، فمفيش وعد اتكسر. لو عملت ack الأول، ده الـ bug اللي بيضيع فلوس.

fsync لكل أوردر بيكلف حوالي 0.8ms على الـ disk ده، فبيوقفك عند حوالي 1,000 أوردر في الثانية، وده أقل من الـ peak بتاع أسخن سهم أصلًا. الحل group commit: تجمع batch، fsync واحد، ack للكل. وقت الـ fsync تقريبًا مبيتغيرش مع حجم الـ batch، بس كل أوردر بيستنى الـ batch يتملى، في المتوسط نص وقت الـ batch. عند 10,000 أوردر في الثانية، batch بـ 1,000 أوردر بيزود 50ms انتظار. ظبط الحجم على معدل الوصول، أو اعمل flush بـ timer.

الـ recovery هو snapshot + ذيل الـ journal: الـ snapshot بيحفظ الـ book عند sequence N (بيتكتب في ملف مؤقت وبعدين rename، فيا كامل يا مش موجود)، وبعدين replay للسجلات اللي بعد N بس. الاختبار اللي يهم: اقتل الـ process بجد بـ SIGKILL، ارجع، وقارن الـ state hash بـ replay نضيف لنفس الـ input. والسجل الأخير الناقص لازم الـ CRC يكشفه ويتجاهله، عمره ما يتقري.

فين هستخدمه في شغلي؟ الـ outbox pattern (درس الـ outbox) هو نفس القاعدة: الـ commit في الـ DB الأول، وبعدين publish. ولما تكتب service بيسجل payment webhooks في ملف أو Redis قبل ما يرد 200: لازم الـ fsync أو الـ AOF appendfsync always لو الـ provider مش هيبعت تاني، وده بالظبط سؤال "إيه الـ ack بتاعي بيوعد بإيه؟".
Interview question "Your engine acks 200,000 orders per second, then the box dies. What did you lose?" Nothing that was acknowledged, if the journal fsync comes before the ack. Orders in the current unsynced batch are not acked, so the client retries them with the same client order id and they are deduplicated.
"الـ engine بتاعك بيعمل ack لـ 200,000 أوردر في الثانية، والجهاز وقع. ضيعت إيه؟" ولا حاجة أخدت ack، لو الـ journal fsync قبل الـ ack. الأوردرات اللي في الـ batch اللي لسه ما اتعملش fsync ما أخدتش ack، فالـ client بيعيد إرسالها بنفس الـ client order id وبتتعمل deduplicate.

Part 6 — Market data 🔴 Advancedالجزء 6 — الـ Market data

English

Market data is a one-way, high-rate, fan-out stream, and the protocol shape is standard: a snapshot of the book plus incremental updates numbered with a sequence. A client takes a snapshot at sequence S, applies updates after S, and on any gap throws away its book and takes a new snapshot. Exchanges send this over UDP multicast: the network duplicates the packet, so the cost does not grow with subscribers (the calculator's 49 Gbps becomes 0.025 Gbps), and loss is handled with sequence numbers and a retransmit channel. Multicast is the concept here and was not run; the demo uses real TCP sockets.

The dangerous case is a slow consumer. If you keep writing to a socket that is not being read, Node queues the data in memory, per client. The experiment pauses a client for 2.5 seconds and measures both designs on a real socket. "Buffer" keeps everything queued: 41.6 MB buffered and RSS up 342 MB, for one client. "Drop and resync" stops sending when the socket passes a 512 KB high-water mark, then sends one snapshot when it drains: 0.5 MB buffered, and the client's final book is still byte-identical to the server's. That is why you drop and resync instead of buffer; a retail client that is 2 seconds behind cannot trade on stale data anyway. See backpressure and streams for the Node mechanics.

Conflation is the retail version: send only the latest top-of-book every N milliseconds, so nobody needs every tick. Trades are never conflated.

// الـ conflation: في كل window بنحتفظ بآخر قيمة بس، والقيم اللي في النص بتروح
function conflate(input: Tick[], windowMs: number): Tick[] {
  const out: Tick[] = [];
  let pending: Tick | null = null;
  let edge = windowMs;
  for (const t of input) {
    while (t.atMs >= edge) {
      if (pending) { out.push(pending); pending = null; }
      edge += windowMs;
    }
    pending = t;
  }
  if (pending) out.push(pending);
  return out;
}

Part 7 — Trade-offs & review 🔴 Advancedالجزء 7 — الـ Trade-offs والمراجعة

English

Hot standby. A second engine replays the same sequenced stream and publishes nothing. Because of determinism it is byte-identical, so failover is "promote and continue from the next sequence", and consumers deduplicate by sequence number. Detecting the failure and fencing the old primary remain the hard parts (see replication and split-brain).

Why not a database in the path? The measured Postgres commit below is excellent at about 0.2 ms, and it is still around 2,000 times the 0.1 µs a match costs, before any locking between orders. Note that this Windows Postgres uses wal_sync_method=open_datasync, so don't compare it to the 0.8 ms from Part 5, which is a plain Node fsync. A database belongs behind the stream for order history, reporting and settlement. (createPrimary and connect in the code are a small helper that starts a throwaway Postgres on a random port for this lesson; in your own project use your normal connection.)

The speed tiers, by name. Below a few microseconds you stop using the kernel network stack: kernel bypass (DPDK, OpenOnload, RDMA), then FPGAs for parsing and risk checks. You won't build those, but you should be able to name them and say what they trade: engineering cost and flexibility for microseconds. Breaks first at 10×: not the matching, which stays well within budget, but a single stall queueing a growing number of orders; then unicast market data, which grows with both load and subscribers; then the single sequencer, which you partition by symbol.

الـ Hot standby: engine تاني بيعمل replay لنفس الـ stream ومبينشرش حاجة. وبسبب الـ determinism هو مطابق بالبايت، فالـ failover يبقى "رقّيه وكمل من الـ sequence اللي بعده"، والـ consumers بيعملوا dedupe بالـ seq. الصعب فعلًا هو اكتشاف الفشل و fencing للـ primary القديم (درس الـ replication والـ split-brain).

مستويات السرعة بالاسم: تحت كام ميكرو بتبطل تستخدم network stack بتاع الـ kernel: kernel bypass (DPDK، OpenOnload، RDMA)، وبعدها FPGAs للـ parsing و risk checks. إنت مش هتبنيهم، بس لازم تعرف أساميهم وبيبدلوا إيه بإيه: تكلفة هندسية ومرونة مقابل ميكروثواني. اللي بيقع الأول عند 10×: مش الـ matching، ده لسه جوه الميزانية، بل الوقفة الواحدة اللي بتعمل طابور بيكبر؛ بعدها الـ unicast market data اللي بتكبر مع الحمل ومع الـ subscribers؛ وبعدها الـ sequencer الواحد، اللي بتقسمه بالسهم.

فين هستخدمه في شغلي؟ لما حد في design review يقول "نحط الـ DB في كل خطوة عشان نبقى آمنين": ارجع لرقمين، كام commit بيستحمل، وكام request/s هيجي على أسخن key. وعند 10× الأسئلة دي: إيه اللي بيتقسم بالـ tenant/product (زي الـ sequencer)، وإيه اللي بيتكرر مع كل subscriber (زي الـ market data).

import { closeSync, fsyncSync, mkdtempSync, openSync, rmSync, writeSync } from "node:fs";
import path from "node:path";

// الـ group commit: الـ ack بيتأجل لحد ما batch كامل يتعمله fsync واحد
class GroupCommit {
  private buf: Buffer[] = [];
  private waiters: (() => void)[] = [];
  private timer: NodeJS.Timeout | null = null;
  private fd: number;
  private maxBatch: number;
  private maxWaitMs: number;
  flushes = 0;
  constructor(file: string, maxBatch: number, maxWaitMs: number) {
    this.fd = openSync(file, "a");
    this.maxBatch = maxBatch;
    this.maxWaitMs = maxWaitMs;
  }
  append(rec: Buffer): Promise<void> {
    return new Promise((resolve) => {
      this.buf.push(rec);
      this.waiters.push(resolve);
      if (this.buf.length >= this.maxBatch) this.flush();
      else this.timer ??= setTimeout(() => this.flush(), this.maxWaitMs);
    });
  }
  private flush(): void {
    if (this.timer) { clearTimeout(this.timer); this.timer = null; }
    if (!this.buf.length) return;
    writeSync(this.fd, Buffer.concat(this.buf));
    fsyncSync(this.fd);
    this.flushes++;
    for (const w of this.waiters) w();
    this.buf = [];
    this.waiters = [];
  }
  close(): void { this.flush(); closeSync(this.fd); }
}

Cheat sheet · الخلاصة

  • One symbol = one thread = one writer. Determinism gives you recovery, a standby, and testing for free.
  • Order path: gateway (risk, auth) → sequencer (total order) → journal + fsync → match → ack.
  • Book: FIFO per level, prices in integer ticks, trade at the maker's price, O(1) cancel with a Map to a linked-list node.
  • Level index: a sorted array is fine near the top of book; a tick array is the production default.
  • Fairness is a chosen definition: arrival order, equalised delay, timestamps, or batch auctions. Each has a latency price.
  • Sequence numbers make loss detectable by arithmetic; fetch the gap from the log before applying.
  • Group commit: fsync time is about flat, so batch to raise throughput and tune batch size to arrival rate.
  • Recovery = snapshot + journal tail; test it with a real SIGKILL and a state hash; a CRC stops at a torn record.
  • Market data: snapshot + incremental with sequence; slow consumer means drop and resync, never buffer; multicast for fan-out; conflation for retail.
  • Latency: closed-loop p99 hides queues; one stall hits everyone behind it at a real arrival rate.
  • Breaks first at 10×: stalls and market data fan-out, not matching. Partition the sequencer by symbol.
بالعامية
  • سهم واحد = thread واحد = writer واحد. الـ determinism بيديك الـ recovery والـ standby والـ testing ببلاش.
  • مسار الأوردر: gateway (risk، auth) ← sequencer (ترتيب كلّي) ← journal + fsync ← match ← ack.
  • الـ book: FIFO لكل level، الأسعار integer ticks، الـ trade بسعر الـ maker، و cancel بـ O(1) عن طريق Map لـ node في linked list.
  • الـ level index: الـ sorted array كويسة قرب الـ top، والـ tick array هي الاختيار الافتراضي في production.
  • العدل تعريف إنت بتختاره: ترتيب الوصول، equalised delay، timestamps، أو batch auctions. وكل واحد ليه تمن latency.
  • أرقام الـ sequence بتخلي اكتشاف الفقد بالحساب، وبتجيب الناقص من الـ log قبل ما تطبق.
  • الـ group commit: وقت الـ fsync تقريبًا ثابت، فاعمل batch عشان الـ throughput، وظبط الحجم على معدل الوصول.
  • الـ recovery = snapshot + ذيل الـ journal؛ اختبره بـ SIGKILL حقيقي و state hash؛ والـ CRC بيوقف عند السجل الناقص.
  • الـ market data: snapshot + incremental بـ sequence؛ الـ slow consumer معناه drop و resync مش buffer؛ multicast للـ fan-out؛ و conflation للـ retail.
  • الـ latency: الـ closed-loop p99 بيخبي الطوابير؛ وقفة واحدة بتضرب كل اللي وراها عند معدل وصول حقيقي.
  • اللي بيقع الأول عند 10×: الوقفات و fan-out الـ market data، مش الـ matching. قسّم الـ sequencer بالسهم.
