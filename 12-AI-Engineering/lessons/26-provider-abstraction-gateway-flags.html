Why this matters · ليه ده مهم

English

Providers go down, models get retired, and a new model that scores better on your eval can still cost three times as much in production. If your code calls one SDK directly from everywhere, each of those events is an incident. This lesson puts a port in front of the provider, adds a failover that keeps answering during an outage, rolls out a model to 1 percent of tenants with a rollback that needs no deploy, and builds a gateway so you can judge what one really costs you. Expect this in system design interviews, usually phrased as "what happens when your LLM provider has a two-hour outage?"

الـ providers بتقع، والـ models بتتشال، و model جديد بيجيب نتيجة أحسن في الـ eval ممكن يكلفك 3 أضعاف في production. لو الكود بتاعك بينادي SDK واحد مباشرة من كل حتة، كل حدث من دول بيبقى incident. الدرس ده بيحط port قدام الـ provider، ويضيف failover يفضل يرد وقت الـ outage، ويعمل rollout لـ model على 1% من الـ tenants مع rollback من غير deploy، ويبني gateway عشان تحكم بنفسك بيكلفك إيه فعلًا. ده بييجي في الـ system design interviews، وغالبًا بالشكل ده: "إيه اللي هيحصل لو الـ LLM provider وقع ساعتين؟"

Part 1 — Your own port 🔴 Advancedالجزء 1 — الـ port بتاعك

English

Apply the Adapter pattern: define LlmPort with complete and stream, and return your own usage shape and your own error type. An adapter over @anthropic-ai/sdk and another over the AI SDK both satisfy it, and neither library's types appear outside its adapter.

Then be honest about what leaks through any abstraction, because this is where wrappers go wrong:

  • Caching rules. Breakpoints, minimum sizes and prices differ per provider. A real leak turned up here: Claude's input_tokens excludes cached tokens, the AI SDK's inputTokens includes them. Your port must pick one meaning and convert, or your cost numbers are silently wrong.
  • Thinking. On current Claude models it's thinking: { type: "adaptive" } plus output_config.effort, and the older budget_tokens returns 400.
  • Tool choice. The same field is accepted by one model and rejected by another, as the output below shows.
  • Refusals. Claude returns stop_reason: "refusal" as a normal response, so a port that only models errors will treat a refusal as a success.

So keep the common path small and give explicit escape hatches. The bad design is a lowest-common-denominator wrapper with no way to reach cache_control: it looks clean and it costs 3.7× more in the run below. Here, a typed hints field carries what most providers can honour in some form, and providerOptions is the labelled non-portable exit.

// الـ port بتاعنا: الكود بتاعك بيعتمد على ده، مش على أي SDK
export type LlmMessage = { role: "user" | "assistant"; content: string };
export type LlmRequest = {

  system?: string;
  messages: LlmMessage[];
  maxTokens: number;
  signal?: AbortSignal;
  // المسار المشترك صغير، وأي حاجة بتختلف من provider لتاني بتعدي من هنا بصراحة
  hints?: { cacheSystem?: boolean };
  // باب الطوارئ: حقول خام لـ provider معين، والكلام هنا مقصود إنه مش portable
  providerOptions?: { anthropic?: Record<string, unknown> };
};
export type LlmUsage = { inputTokens: number; outputTokens: number; cacheReadTokens: number; cacheWriteTokens: number };
export type StopReason = "end_turn" | "max_tokens" | "tool_use" | "refusal" | "other";
export type LlmResponse = { text: string; usage: LlmUsage; stopReason: StopReason; model: string; provider: string };
export type LlmChunk = { type: "text"; text: string } | { type: "done"; response: LlmResponse };

export interface LlmPort {
  readonly provider: string;
  complete(req: LlmRequest): Promise<LlmResponse>;
  stream(req: LlmRequest): AsyncIterable<LlmChunk>;
}

// الخطأ بتاعنا: الـ caller ميعرفش أنواع أخطاء أي SDK
export type LlmErrorKind = "rate_limit" | "overloaded" | "server" | "bad_request" | "auth" | "aborted" | "network";
export class LlmError extends Error {
  readonly kind: LlmErrorKind;
  readonly status?: number;
  constructor(message: string, kind: LlmErrorKind, status?: number) { super(message); this.kind = kind; this.status = status; }
  get retryable() { return ["rate_limit", "overloaded", "server", "network"].includes(this.kind); }
}
// الـ adapters: واحد فوق الـ Anthropic SDK وواحد فوق الـ AI SDK، وكل واحد بيترجم للـ port
import Anthropic from "@anthropic-ai/sdk";
import { createAnthropic } from "@ai-sdk/anthropic";
import { generateText, streamText, type LanguageModelUsage } from "ai";
import { LlmError, type LlmChunk, type LlmPort, type LlmRequest, type LlmResponse, type LlmUsage, type StopReason } from "./port.ts";

const mapStop = (s: string | null | undefined): StopReason =>
  s === "end_turn" || s === "max_tokens" || s === "tool_use" || s === "refusal" ? s : "other";

function toLlmError(err: unknown): LlmError {
  if (err instanceof LlmError) return err;
  if (err instanceof Anthropic.APIUserAbortError) return new LlmError("aborted", "aborted");
  if (err instanceof Anthropic.RateLimitError) return new LlmError(err.message, "rate_limit", 429);
  if (err instanceof Anthropic.AuthenticationError) return new LlmError(err.message, "auth", 401);
  if (err instanceof Anthropic.BadRequestError) return new LlmError(err.message, "bad_request", 400);
  if (err instanceof Anthropic.InternalServerError) return new LlmError(err.message, err.status === 529 ? "overloaded" : "server", err.status);
  if (err instanceof Anthropic.APIError) return new LlmError(err.message, "server", err.status);
  return new LlmError(String(err), "network");
}

export function anthropicAdapter(opts: { apiKey: string; baseURL?: string; maxRetries?: number; name?: string }): LlmPort {
  const client = new Anthropic({ apiKey: opts.apiKey, baseURL: opts.baseURL, maxRetries: opts.maxRetries ?? 0 });
  const params = (req: LlmRequest) => ({
    model: req.model,
    max_tokens: req.maxTokens,
    // الـ caching مش portable: هنا بس بنعرف إزاي نحط الـ cache_control
    ...(req.system ? { system: [{ type: "text" as const, text: req.system, ...(req.hints?.cacheSystem ? { cache_control: { type: "ephemeral" as const } } : {}) }] } : {}),
    messages: req.messages.map((m) => ({ role: m.role, content: m.content })),
    ...(req.providerOptions?.anthropic ?? {}),
  });
  const toResponse = (m: Anthropic.Message): LlmResponse => ({
    text: m.content.flatMap((b) => (b.type === "text" ? [b.text] : [])).join(""),
    stopReason: mapStop(m.stop_reason),
    usage: { inputTokens: m.usage.input_tokens, outputTokens: m.usage.output_tokens, cacheReadTokens: m.usage.cache_read_input_tokens ?? 0, cacheWriteTokens: m.usage.cache_creation_input_tokens ?? 0 },
    model: m.model, provider: opts.name ?? "anthropic",
  });
  return {
    provider: opts.name ?? "anthropic",
    async complete(req) {
      try { return toResponse(await client.messages.create(params(req) as Anthropic.MessageCreateParamsNonStreaming, { signal: req.signal })); }
      catch (e) { throw toLlmError(e); }
    },
    async *stream(req): AsyncGenerator<LlmChunk> {
      try {
        const s = client.messages.stream(params(req) as Anthropic.MessageStreamParams, { signal: req.signal });
        for await (const ev of s) if (ev.type === "content_block_delta" && ev.delta.type === "text_delta") yield { type: "text", text: ev.delta.text };
        yield { type: "done", response: toResponse(await s.finalMessage()) };
      } catch (e) { throw toLlmError(e); }
    },
  };
}

// نفس الـ port فوق الـ AI SDK: لو عايز تبدّل provider بسطر واحد في الـ wiring
export function aiSdkAdapter(opts: { apiKey: string; baseURL: string }): LlmPort {
  const anthropic = createAnthropic({ baseURL: opts.baseURL + "/v1", apiKey: opts.apiKey });
  // نفس الـ hint بس بشكل تاني: الـ AI SDK عايز providerOptions على الـ message
  const common = (req: LlmRequest) => ({
    model: anthropic(req.model), maxOutputTokens: req.maxTokens,
    instructions: req.system && req.hints?.cacheSystem
      ? { role: "system" as const, content: req.system, providerOptions: { anthropic: { cacheControl: { type: "ephemeral" as const } } } }
      : req.system,
    messages: req.messages, abortSignal: req.signal, maxRetries: 0,
  });
  // انتبه: الـ inputTokens في الـ AI SDK شامل الـ cached، و input_tokens في Claude مش شاملها
  const toUsage = (u: LanguageModelUsage): LlmUsage => {
    const read = u.inputTokenDetails?.cacheReadTokens ?? 0, write = u.inputTokenDetails?.cacheWriteTokens ?? 0;
    return { inputTokens: (u.inputTokens ?? 0) - read - write, outputTokens: u.outputTokens ?? 0, cacheReadTokens: read, cacheWriteTokens: write };
  };
  return {
    provider: "ai-sdk",
    async complete(req) {
      const r = await generateText(common(req));
      return { text: r.text, stopReason: r.finishReason === "stop" ? "end_turn" : r.finishReason === "length" ? "max_tokens" : "other",
        usage: toUsage(r.usage), model: req.model, provider: "ai-sdk" };
    },
    async *stream(req) {
      const r = streamText(common(req));
      let text = "";
      for await (const t of r.textStream) { text += t; yield { type: "text", text: t }; }
      yield { type: "done", response: { text, stopReason: "end_turn", usage: toUsage(await r.usage), model: req.model, provider: "ai-sdk" } };
    },
  };
}

بالعامية

طبّق الـ Adapter pattern: عرّف LlmPort فيه complete و stream، ورجّع شكل الـ usage بتاعك ونوع الـ error بتاعك. adapter فوق @anthropic-ai/sdk و adapter فوق الـ AI SDK بيحققوا نفس الـ interface، وأنواع المكتبتين مش بتظهر بره الـ adapter بتاعها.

وبعدين كن صريح في اللي بيتسرب من أي abstraction، لأن هنا الـ wrappers بتغلط:

  • قواعد الـ caching. الـ breakpoints وأقل حجم والأسعار بتختلف من provider لتاني. وطلع لنا تسريب حقيقي: الـ input_tokens في Claude مش شامل الـ cached tokens، و inputTokens في الـ AI SDK شاملها. لازم الـ port يختار معنى واحد ويحوّل، وإلا أرقام التكلفة هتطلع غلط من غير ما حد ياخد باله.
  • الـ thinking. على الـ Claude models الحالية بيبقى thinking: { type: "adaptive" } و output_config.effort، و budget_tokens القديم بيرجع 400.
  • الـ tool choice. نفس الحقل بيتقبل على model ويترفض على model تاني، زي ما الـ output بيوضح.
  • الـ refusals. Claude بيرجّع stop_reason: "refusal" كرد عادي، فالـ port اللي بيهتم بالـ errors بس هيعتبر الرفض نجاح.

فخلّي المسار المشترك صغير، وادّي مخارج طوارئ صريحة. التصميم الغلط هو wrapper بأقل قاسم مشترك من غير أي طريق لـ cache_control: شكله نضيف وبيكلف 3.7 مرة زيادة في التشغيل اللي فوق. هنا حقل hints typed فيه اللي معظم الـ providers يقدروا ينفذوه بشكل ما، و providerOptions هو المخرج الصريح اللي مش portable.

فين هستخدمه في شغلي؟ لو بتبني تلخيص فواتير في NestJS: الـ service بيستلم LlmPort في الـ constructor ومش بيعرف Anthropic من OpenAI، وفي الـ tests بتديله fake في 5 سطور. ولما حد في الـ code review يقترح "نوحّد كل حاجة في function واحدة askAI(prompt)"، وريه الـ 3.7×. الغلطة الشائعة: تحسب التكلفة من inputTokens بتاع الـ AI SDK وتجمع عليه الـ cached فتحسبه مرتين.
Trade-off: your own port or just the AI SDK? The AI SDK already is a provider abstraction, and for a chat UI with streaming it's the right starting point. Add your own thin port when you need one error type, one usage meaning, your own failover policy, or a fake in tests that doesn't know any SDK exists. Don't write a port to avoid learning the SDK; that's how the lowest-common-denominator wrapper starts.

Part 2 — Fallback and multi-region 🔴 Advancedالجزء 2 — الـ fallback والـ multi-region

English

Run two stand-ins. The primary returns 529 for a window; a circuit breaker notices and sends traffic to the fallback directly. Three lessons from the run:

  • Retries in the wrong layer are the expensive part. With the SDK's default of 2 retries and no breaker, each of 30 requests hit the dead primary 3 times, 90 requests in total, and p50 went to ≈1.4 s. Switching retries off dropped p50 to ≈48 ms. Adding the breaker cut the primary to 3 requests.
  • A fallback model answers differently, so it needs its own eval run; part 5 catches a real format difference.
  • Failover is also a cost event. Prompt caches are per model, so the fallback starts cold. With a 26,676-token cached prefix, a normal Sonnet 5.5 call is $0.0027. The first call after failing over to Opus 5.5 is $0.1334, about 49 times as much, and to Haiku 5.5 is $0.0033.

Know what the built-in option does. Claude's server-side fallbacks parameter (beta, header server-side-fallback-2026-07-01) retries a refused request on another model inside one API call. The docs describe it for refusals, and a 529 is an overload error, so it isn't a failover for outages: you still need your own.

Decide failover before the first token. Once a stream has sent text to the user, switching models mid-sentence produces nonsense, so the adapter chooses before streaming starts. Don't fail over on 400s either: a bad request fails on the fallback too, and you pay to learn it.

Multi-region and other platforms are the same pattern with a different adapter: Claude is also offered on Amazon Bedrock, Google Cloud and Microsoft Foundry. Not run here: they need cloud accounts. The inference_geo setting for US-only inference costs 1.1×, and its availability guarantees come from your provider contract rather than from this code.

One thing to check before going live: SDK 1.x sends the key as Authorization: Bearer. A corporate proxy or an older gateway that reads only X-Api-Key will reject it; part 4 reproduces that.

الطلب بيعدي على الـ breaker الأول. لو مقفول يروح للـ primary، ولو الـ primary رجّع 529 أو 429 أو 5xx يتحوّل للـ fallback. لو الـ breaker مفتوح (3 فشل ورا بعض) بيعدّي الـ primary خالص ويروح للـ fallback، وده اللي بيخلي الـ primary ياخد 3 طلبات بس. الـ fallback ليه breaker لوحده، ولو الاتنين مفتوحين بنرد بسرعة بـ 503 all providers down من غير ما نلمس الشبكة.
// الـ port المرن: primary ورا circuit breaker، و fallback لما الـ primary يقع
import { CircuitBreakerPolicy, ConsecutiveBreaker, handleWhen, circuitBreaker, BrokenCircuitError } from "cockatiel";
import { LlmError, type LlmChunk, type LlmPort, type LlmRequest, type LlmResponse } from "./port.ts";

export type Metrics = { primary: number; fallback: number; rejected: number; failedOver: number };

export function resilient(primary: LlmPort, fallback: LlmPort, cfg: { fallbackModel: string; halfOpenAfterMs: number; threshold: number }) {
  const breaker: CircuitBreakerPolicy = circuitBreaker(handleWhen((e) => e instanceof LlmError && e.retryable), {
    halfOpenAfter: cfg.halfOpenAfterMs,
    breaker: new ConsecutiveBreaker(cfg.threshold),
  });
  // الـ fallback ليه breaker لوحده: لو الاتنين وقعوا نفشل بسرعة بدل ما نضرب الاتنين على كل طلب
  const fallbackBreaker: CircuitBreakerPolicy = circuitBreaker(handleWhen((e) => e instanceof LlmError && e.retryable), {
    halfOpenAfter: cfg.halfOpenAfterMs,
    breaker: new ConsecutiveBreaker(cfg.threshold),
  });
  const metrics: Metrics = { primary: 0, fallback: 0, rejected: 0, failedOver: 0 };

  async function complete(req: LlmRequest): Promise<LlmResponse> {
    try {
      return await breaker.execute(() => { metrics.primary++; return primary.complete(req); });
    } catch (err) {
      // الـ 400 بيفشل على الـ fallback كمان، فمتدفعش عليها مرتين
      const open = err instanceof BrokenCircuitError;
      if (!open && !(err instanceof LlmError && err.retryable)) throw err;
      if (open) metrics.rejected++;
      metrics.failedOver++;
      try {
        return await fallbackBreaker.execute(() => { metrics.fallback++; return fallback.complete({ ...req, model: cfg.fallbackModel, hints: req.hints }); });
      } catch (e2) {
        if (e2 instanceof BrokenCircuitError) throw new LlmError("all providers down", "overloaded", 503);
        throw e2;
      }
    }
  }
  const port: LlmPort & { metrics: Metrics } = {
    provider: "resilient", metrics, complete,
    async *stream(req): AsyncGenerator<LlmChunk> {
      // الفشل بعد أول chunk مينفعش يتعمله failover بأمان، فبنقرر قبل أول token بس
      const r = await complete(req);
      yield { type: "text", text: r.text };
      yield { type: "done", response: r };
    },
  };
  return { port, breaker };
}

Part 3 — Feature flags for prompts and models 🔴 Advancedالجزء 3 — Feature flags للـ prompts والـ models

English

A prompt or model change is a production change whose effect you can't fully predict offline, so ship it the way section 09 ships risky changes: behind a flag, gradually, with a rollback that needs no deploy.

A stable bucket. Hash flag:tenantId into 0..9999. A tenant keeps the same variant across requests and processes, and everyone in the 1 percent stays in when you move to 10. Mixing the flag name into the hash keeps two experiments independent, so one tenant isn't in every canary at once.

Guardrails, not vibes. Log the variant with every call, compare candidate against control on error rate and cost once there are enough samples, and flip the flag automatically when a limit is crossed. In this run, a scripted bad candidate (30 percent broken output and a longer reply) was caught after 20 candidate calls out of 200, and the flip took effect within the cache TTL. Rollback is one Redis write.

Log the flag value with every call. Without it, your cost report and your eval can't tell which prompt produced what, and "the bill doubled on Tuesday" has no answer.

When the flag store fails, keep the last known value and mark it stale. With no cached value at all, fall back to control. Note the honest side effect: a flag can be left stuck at 50 percent during a Redis outage, so alert on flag age.

// مفتاح تشغيل (feature flag) للـ model والـ prompt: bucket ثابت، و rollback بكتابة واحدة في Redis
import { createHash } from "node:crypto";
import type { Redis } from "ioredis";

export type Variant = { name: "control" | "candidate"; model: string; promptVersion: string };
export type FlagState = { rollout: number; control: Variant; candidate: Variant };
export type Decision = Variant & { flag: string; bucket: number; rollout: number; stale: boolean };

// نفس الـ tenant دايمًا في نفس المكان: اللي دخل الـ 1% بيفضل جوه في الـ 10% والـ 100%
export const bucketOf = (flag: string, tenantId: string): number =>
  createHash("sha256").update(`${flag}:${tenantId}`).digest().readUInt32BE(0) % 10_000;

export const decide = (flag: string, state: FlagState, tenantId: string, stale = false): Decision => {
  const bucket = bucketOf(flag, tenantId);
  const v = bucket < state.rollout * 100 ? state.candidate : state.control;
  return { ...v, flag, bucket, rollout: state.rollout, stale };
};

export function flagStore(redis: Pick<Redis, "get" | "set">, flag: string, safeDefault: FlagState, ttlMs = 500) {
  let cached: FlagState | null = null;
  let readAt = 0;
  return {
    // الـ cache المحلي بيقلل الحمل على Redis، و TTL هو زمن وصول الـ rollback
    async decide(tenantId: string): Promise<Decision> {
      if (cached && Date.now() - readAt < ttlMs) return decide(flag, cached, tenantId);
      try {
        const raw = await redis.get(`flag:${flag}`);
        cached = raw ? (JSON.parse(raw) as FlagState) : safeDefault;
        readAt = Date.now();
        return decide(flag, cached, tenantId);
      } catch {
        // لو Redis وقع: كمّل بآخر قيمة معروفة، ولو مفيش خالص ارجع للـ control
        return decide(flag, cached ?? { ...safeDefault, rollout: 0 }, tenantId, true);
      }
    },
    async set(state: FlagState) { await redis.set(`flag:${flag}`, JSON.stringify(state)); },
    async rollback() {
      const raw = await redis.get(`flag:${flag}`);
      const state = raw ? (JSON.parse(raw) as FlagState) : safeDefault;
      await redis.set(`flag:${flag}`, JSON.stringify({ ...state, rollout: 0 }));
    },
  };
}

Part 4 — Build a small gateway 🔴 Advancedالجزء 4 — ابني gateway صغير

English

A gateway is one endpoint in front of all providers that does routing, per-key rate limits, cost tracking and holds the provider keys, so applications carry only a gateway key. About 100 lines gets you the core. It speaks the Anthropic wire format, so the real SDK talks to it by changing baseURL.

What the code below does: authenticates with a gateway key stored as a hash, reads Bearer and x-api-key, checks a model allowlist per team, applies a per-key limit in Redis, routes by model, swaps the client key for the provider key, passes bytes through while reading usage from the SSE events in flight, aborts upstream when the client disconnects, and records cost by team.

The trade-off is sharp. A gateway is a single point of failure and a single vault of every key. LiteLLM and Portkey are the common products (not run here: this machine only runs the npm packages this lesson installs). The risk isn't hypothetical. LiteLLM's own advisory reports that malicious litellm==1.82.7 and 1.82.8 reached PyPI on 2026-03-24, live from 10:39 UTC for about 40 minutes before PyPI quarantined them (its "who is affected" section uses a wider window ending at 16:00 UTC). The payload harvested environment variables, SSH keys, cloud credentials, Kubernetes tokens and database passwords. The advisory says the official Docker image, LiteLLM Cloud and GitHub source installs were not affected, and that the compromise likely came through a Trivy dependency in the project's CI. A package on the box that holds every provider key is the worst possible place for a supply-chain hit, whether you buy the gateway or build it: your own gateway's npm dependencies are the same attack surface.

import express, { type Express, type Request, type Response } from "express";
import type { Redis } from "ioredis";
import { costOf, type Usage } from "../kit/prices.ts";

export type Upstream = { name: string; baseUrl: string; apiKey: string; models: RegExp };
export type GatewayKey = { team: string; rps: number; allowedModels: RegExp };
export type GatewayConfig = { upstreams: Upstream[]; keys: Map<string, GatewayKey>; redis: Redis; log?: (e: object) => void };

// الـ keys متخزنة كـ hash: لو الجدول اتسرب، المفتاح نفسه مش معاه
export const keyHash = (k: string) => createHash("sha256").update(k).digest("hex");

export function createGateway(cfg: GatewayConfig): Express {
  const app = express();
  app.use(express.json({ limit: "4mb" }));

  async function allow(token: string, key: GatewayKey): Promise<boolean> {
    const bucket = `gw:rl:${keyHash(token).slice(0, 16)}:${Math.floor(Date.now() / 1000)}`;
    const n = await cfg.redis.incr(bucket);
    if (n === 1) await cfg.redis.expire(bucket, 2);
    return n <= key.rps;
  }
  async function record(team: string, model: string, usage: Usage, ms: number, status: number) {
    const cost = costOf(model, usage);
    const day = new Date().toISOString().slice(0, 10);
    await cfg.redis.hincrbyfloat(`gw:cost:${day}`, team, cost);
    cfg.log?.({ team, model, inTok: usage.input_tokens, outTok: usage.output_tokens, costUsd: Number(cost.toFixed(6)), ms, status });
  }

    const started = performance.now();
    // الـ SDK 1.x بيبعت Bearer، والعملاء الأقدم بيبعتوا x-api-key: لازم الاتنين
    const auth = req.get("authorization");
    const token = auth?.startsWith("Bearer ") ? auth.slice(7) : req.get("x-api-key");
    const key = token ? cfg.keys.get(keyHash(token)) : undefined;
    if (!token || !key) return void res.status(401).json({ type: "error", error: { type: "authentication_error", message: "invalid gateway key" } });

    if (!upstream) return void res.status(400).json({ type: "error", error: { type: "invalid_request_error", message: `no upstream for ${model}` } });

    const ctrl = new AbortController();
    res.on("close", () => { if (!res.writableEnded) ctrl.abort(); });

        signal: ctrl.signal,
      });
    } catch {
      return void res.status(502).json({ type: "error", error: { type: "api_error", message: `upstream ${upstream.name} unreachable` } });
    }

    res.status(up.status);

    res.flushHeaders();

    if (!req.body.stream) {
      const text = await up.text();
      res.end(text);
      const body = JSON.parse(text);
      if (up.ok) await record(key.team, model, body.usage, performance.now() - started, up.status);
      return;
    }

    for await (const chunk of up.body as unknown as AsyncIterable<Uint8Array>) {
      res.write(chunk);
      buf += decoder.decode(chunk, { stream: true });
      let i: number;
      while ((i = buf.indexOf("\n\n")) >= 0) {
        const frame = buf.slice(0, i); buf = buf.slice(i + 2);
        const data = frame.match(/^data: (.*)$/m)?.[1];
        if (!data) continue;

        if (ev.type === "message_start") Object.assign(usage, ev.message.usage);
        if (ev.type === "message_delta") usage.output_tokens = ev.usage.output_tokens;
      }
    }
    res.end();
    await record(key.team, model, usage, performance.now() - started, up.status);
  });
  return app;
}

Part 5 — Cost, latency, failure, and an eval 🔴 Advancedالجزء 5 — التكلفة والزمن والفشل والـ eval

English

The failover eval sends 20 requests during a simulated outage. All must answer, and every answer must pass the same assertions the primary passes. The stand-in fallback is scripted to wrap its JSON in a markdown fence, which is the kind of difference a real fallback model can show. The result is the point of the lesson: 20/20 answered and 0/20 passed. An uptime dashboard would have stayed green. Note too that 20 concurrent requests all hit the primary before the breaker could open: a breaker saves the requests after the burst.

The gateway's cost is in the numbers: ≈0.5 ms added to TTFT on localhost, and a network hop in production. The cost of failover is the cache rebuild from part 2.

Cheat sheet · الخلاصة

  • LlmPort with complete and stream, your usage shape and your error type. SDK types stay inside adapters.
  • Keep the common path small. Give typed hints and a labelled providerOptions exit. Never hide cache_control.
  • What leaks: caching and token-count meaning, thinking, tool_choice per model, refusals as normal responses.
  • Failover on 429/5xx/529 before the first token, never on 400. SDK maxRetries: 0 behind it.
  • Claude's server-side fallbacks is documented for refusals, not outages.
  • Caches are per model: price the cold start before choosing a fallback.
  • Stable bucket by hash of flag and tenant, rollout 1 → 10 → 100, guardrails on error rate and cost, rollback is one write.
  • Log flag, variant, model and prompt version with every call. Alert on stale flags.
  • A gateway gives routing, per-key limits, cost by team and one place for keys, and it is a single point of failure and a single vault.
  • Pin and minimise gateway dependencies. The malicious litellm 1.82.7 and 1.82.8 show why.
  • "Answered" isn't "passed": run the same assertions on the fallback, in CI, before the outage.
