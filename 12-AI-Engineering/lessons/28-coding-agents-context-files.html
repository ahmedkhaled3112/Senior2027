Why this matters · ليه ده مهم

English

A coding agent can read your repo, change ten files, run the tests and hand you a passing branch before you finish your coffee. It can also change a test so the build goes green, or add a race condition to your refund flow in code that reads perfectly well. The senior skill is knowing which tasks to hand over, giving the agent a context file that earns its tokens, and being able to defend every merged line. Interviewers now ask how you work with these tools, and "I review everything" isn't an answer unless you can say how.

بالعامية

الـ coding agent ممكن يقرا الـ repo بتاعك، ويغيّر 10 ملفات، ويشغّل الـ tests، ويسلّمك branch ناجح قبل ما تخلص قهوتك. وبرضه ممكن يغيّر test عشان الـ build يبقى أخضر، أو يحط race condition في الـ refund flow في كود شكله ممتاز. مهارة الـ senior إنه يعرف يدّي أنهي tasks، ويكتب context file يستاهل الـ tokens بتاعته، ويقدر يدافع عن كل سطر اتعمله merge. الـ interviewers دلوقتي بيسألوا إنت بتشتغل مع الأدوات دي إزاي، و"براجع كل حاجة" مش إجابة غير لو عارف تقول إزاي.

Part 1 — Autocomplete vs an agent 🟢 Basicالجزء 1 — الفرق بين الـ autocomplete والـ agent

English

Autocomplete predicts the next lines at your cursor. You decide what to write, it saves typing, and every suggestion is a few lines you can read before pressing Tab. An agent takes a whole task, reads the codebase, edits files, runs commands and tests, looks at the results, and keeps going until it thinks it's done. Claude Code runs in your terminal, Cursor's agent runs in the editor, and GitHub Copilot's coding agent researches the repo, makes changes in a cloud environment and can open a pull request.

The difference that matters is who holds the loop. With autocomplete you check every step because you're the one taking them. With an agent, dozens of decisions happen between your prompt and your review, so a wrong turn in step 2 can be 400 lines deep by the time you look.

An agent is the tool-calling loop from lesson 08 with file and shell tools. To see that there's no magic, the code below builds one: a loop, four tools and a guard that stops it leaving the repo folder. A script plays the model and decides the steps. The tools really run: they read and edit real files, and npm test really fails and then passes.

Treat "All tests pass" as a claim to check. On my first run of this script the test command itself was wrong, the test kept failing, and the script still reported success, because its last line was written in advance. A real model can do the same thing.

export function makeRepo(dir: string) {
  rmSync(dir, { recursive: true, force: true });
  mkdirSync(resolve(dir, "src"), { recursive: true });
  mkdirSync(resolve(dir, "test"), { recursive: true });
  writeFileSync(resolve(dir, "package.json"), JSON.stringify({ name: "invoices", private: true, type: "module", scripts: { test: "node --test" } }, null, 2));
  writeFileSync(resolve(dir, "src/invoice.js"), SRC);
  writeFileSync(resolve(dir, "test/invoice.test.js"), TEST);
}

export const TOOLS: Anthropic.Tool[] = [
  { name: "read_file", description: "Read a file in the repo", input_schema: { type: "object", properties: { path: { type: "string" } }, required: ["path"] } },
  { name: "edit_file", description: "Replace one exact string in a file", input_schema: { type: "object", properties: { path: { type: "string" }, old: { type: "string" }, new: { type: "string" } }, required: ["path", "old", "new"] } },
  { name: "write_file", description: "Create or overwrite a file", input_schema: { type: "object", properties: { path: { type: "string" }, content: { type: "string" } }, required: ["path", "content"] } },
  { name: "run_tests", description: "Run npm test", input_schema: { type: "object", properties: {} } },
];

// الـ agent ميقدرش يخرج برا فولدر الـ repo
function safePath(repo: string, p: string) {
  const full = resolve(repo, p);
  if (!full.startsWith(resolve(repo) + sep)) throw new Error(`path outside repo: ${p}`);
  return full;
}

export function runTests(repo: string) {
  try {
    const out = execSync("npm test --silent --logs-max=0", { cwd: repo, encoding: "utf8", stdio: ["ignore", "pipe", "pipe"] });
    return { ok: true, tail: out.split("\n").filter((l) => /# (pass|fail)|^ℹ (pass|fail)/.test(l)).join(" ") };
  } catch (e) {
    const out = String((e as { stdout?: string }).stdout ?? "");
    return { ok: false, tail: out.split("\n").filter((l) => /# (pass|fail)|^ℹ (pass|fail)/.test(l)).join(" ") };
  }
}

function execTool(repo: string, name: string, input: Record<string, string>): string {
  try {
    if (name === "read_file") return readFileSync(safePath(repo, input.path), "utf8");
    if (name === "edit_file") {
      const f = safePath(repo, input.path);
      const before = readFileSync(f, "utf8");
      if (!before.includes(input.old)) return "ERROR: old string not found";
      writeFileSync(f, before.replace(input.old, input.new));
      return "edited";
    }
    if (name === "write_file") {
      const f = safePath(repo, input.path);
      mkdirSync(dirname(f), { recursive: true });
      writeFileSync(f, input.content);
      return "written";
    }
    if (name === "run_tests") return JSON.stringify(runTests(repo));
    return "ERROR: unknown tool";
  } catch (e) {
    return "ERROR: " + (e as Error).message;
  }
}

// نفس الـ loop بتاع الدرس 08: اسأل، نفّذ الـ tools، رجّع النتايج، كرر
export async function runAgent(client: Anthropic, repo: string, task: string, opts: { maxTurns?: number; log?: (s: string) => void } = {}) {
  const { maxTurns = 12, log = () => {} } = opts;
  const messages: Anthropic.MessageParam[] = [{ role: "user", content: task }];
  let dollars = 0, turns = 0;
  while (turns < maxTurns) {
    turns++;
    const res = await client.messages.create({ model: MODEL, max_tokens: 1024, tools: TOOLS, messages });
    dollars += costOf(MODEL, res.usage);
    messages.push({ role: "assistant", content: res.content });
    if (res.stop_reason !== "tool_use") {
      const text = res.content.find((b) => b.type === "text");
      log(`turn ${turns}: done: ${text?.type === "text" ? text.text : ""}`);
      return { turns, dollars, finished: true };
    }
    const results: Anthropic.ToolResultBlockParam[] = [];
    for (const b of res.content) {
      if (b.type !== "tool_use") continue;
      const out = execTool(repo, b.name, b.input as Record<string, string>);
      log(`turn ${turns}: ${b.name}(${JSON.stringify(b.input).slice(0, 70)}) → ${out.split("\n")[0].slice(0, 80)}`);
      results.push({ type: "tool_result", tool_use_id: b.id, content: out });
    }
    messages.push({ role: "user", content: results });
  }
  return { turns, dollars, finished: false };
}

export type Step = { tool: string; input: Record<string, unknown> } | { text: string };
// بيحوّل قايمة خطوات لرد الـ stand-in: رقم الخطوة = عدد ردود الـ assistant اللي فاتت
export const scripted = (steps: Step[]) => (req: { messages: { role: string }[] }) => {
  const i = req.messages.filter((m) => m.role === "assistant").length;
  const s = steps[Math.min(i, steps.length - 1)];
  if ("text" in s) return { content: [{ type: "text" as const, text: s.text }] };
  return { content: [{ type: "tool_use" as const, name: s.tool, input: s.input }] };
};

بالعامية

الـ autocomplete بيتوقع السطور الجاية عند الـ cursor. إنت اللي بتقرر هتكتب إيه، وهو بيوفر عليك كتابة، وكل اقتراح سطرين تلاتة تقدر تقراهم قبل ما تضغط Tab. الـ agent بياخد task كامل، يقرا الـ codebase، يعدّل ملفات، يشغّل commands وtests، يبص على النتيجة، ويكمل لحد ما يحس إنه خلص. Claude Code بيشتغل في الـ terminal، والـ agent بتاع Cursor في الـ editor، والـ coding agent بتاع GitHub Copilot بيدرس الـ repo ويعدّل في بيئة cloud وممكن يفتح pull request.

الفرق المهم هو مين ماسك الـ loop. في الـ autocomplete إنت بتراجع كل خطوة لأنك اللي بتعملها. في الـ agent، عشرات القرارات بتحصل بين الـ prompt والـ review بتاعك، فغلطة في الخطوة 2 ممكن تبقى 400 سطر لما تبص عليها.

الـ agent هو loop الـ tool calling من الدرس 08 ومعاه tools للملفات والـ shell. عشان تشوف إن مفيش سحر، الكود ده بيبني واحد: loop، و4 tools، وguard بيمنعه يخرج برا فولدر الـ repo. Script بيلعب دور الـ model ويقرر الخطوات، والـ tools بتشتغل بجد: بتقرا وتعدّل ملفات حقيقية، وnpm test بيفشل فعلًا وبعدين بيعدّي.

الغلطة الشائعة: تعامل الـ agent زي autocomplete، تديه task كبير وتقبل النتيجة من غير ما تقرا. وخد بالك إن الرد "All tests pass" مجرد كلام: في أول تشغيلة عندي الـ test كان بيفشل والـ script برضه قال "خلصت"، لأن أمر الـ test نفسه كان غلط. صدّق الـ output، مش الجملة.

فين هستخدمه في شغلي؟ الـ ticket اللي فيه "ضيف endpoint بـ pagination وtests" ينفع يتدّي لـ agent، وإنت تراجع الـ diff. وسطر زي Math.round وإنت بتكتبه سيبه للـ autocomplete. ولو حد في الفريق بيقول "الـ agent خلصها والـ tests عدّت"، أول سؤال: مين شغّل الـ tests، وهل الـ agent غيّر حاجة في الـ test نفسه؟
Trade-off Agent: bigger tasks and less typing, but a long stretch of unreviewed decisions and a big diff to read. Autocomplete: small and constantly reviewed, but you do all the thinking. Use the smallest amount of autonomy the task allows.
الـ agent: tasks أكبر وكتابة أقل، بس قرارات كتير من غير مراجعة وdiff كبير تقراه. الـ autocomplete: حاجة صغيرة وبتتراجع على طول، بس التفكير كله عليك. استخدم أقل قدر من الـ autonomy الـ task يسمح بيه.
Interview question "What's the difference between Copilot autocomplete and a coding agent?" → Autocomplete predicts text and you stay in the loop on every step. An agent runs a loop with tools over a whole task: read, edit, run, observe, repeat. That means it needs a sandbox, permissions, and a way to verify the result that doesn't depend on its own claim.
"إيه الفرق بين الـ autocomplete والـ coding agent؟" ← الـ autocomplete بيتوقع نص وإنت موجود في كل خطوة. الـ agent بيشغّل loop بـ tools على task كامل: يقرا، يعدّل، يشغّل، يبص، يكرر. عشان كده محتاج sandbox وصلاحيات وطريقة تتأكد بيها من النتيجة من غير ما تعتمد على كلامه هو.

Part 2 — Context files 🟢 Basicالجزء 2 — الـ context files

English

A context file is what you'd tell a new teammate on day one: what the codebase is, the conventions, the commands, and the don'ts. Three names matter:

  • CLAUDE.md: Claude Code loads it at the start of every session. Files in parent directories load at launch and files in subdirectories load on demand. @path imports pull in other files. The docs suggest under 200 lines per file, because longer files use more context and reduce adherence.
  • AGENTS.md: an open format stewarded by the Agentic AI Foundation under the Linux Foundation, read by many tools. The closest file to the edited code wins, and explicit chat instructions override it. Claude Code reads it when there's no CLAUDE.md; if you need both, put @AGENTS.md inside CLAUDE.md so there's one source of truth.
  • .cursorrules: Cursor's old single file. Cursor's current rules docs describe .cursor/rules/*.mdc files (with description, globs and alwaysApply) and AGENTS.md, and don't mention .cursorrules any more. Treat it as legacy and move it. Cursor suggests keeping rules under 500 lines.

Every line in that file is paid for in every session, and it's context, not configuration: the docs say Claude treats it as context and to use a hook if something must be blocked regardless. So write only what the agent can't work out by reading the code, and what would hurt if it got wrong. The two ways this goes bad are a 2,000-line file nobody maintains, and a rule the code contradicts. Contradicting rules are the worse one, because the agent can only pick one and may pick wrong.

This repo's own CLAUDE.md is a worked example: who the learner is, the rules for a lesson, the page structure, what not to touch, and a checklist. You'll write one for the side project. It stays honest if you lint it: the script below checks that every npm run exists, every path exists, and every named tool is really in package.json.

# Invoicing SaaS

Multi-tenant invoicing API. Fastify + Postgres + BullMQ, TypeScript strict, Node 22.

## Commands
- Test: `npm test`
- One test file: `npx vitest run src/invoices/total.test.ts`
- Lint: `npm run lint`
- Migrate: `npm run db:migrate`

- `src/invoices/`: the invoice module

- Every table has `tenant_id`, and every query filters on it.
- Money is integer cents. Never a float.

- Do not edit a migration that has shipped: add a new one.
- Do not change a test to make it pass: ask first.

import { existsSync, readFileSync } from "node:fs";
import { join } from "node:path";

// بيتأكد إن الـ context file لسه مطابق للـ repo: الـ file القديم أسوأ من مفيش
export function lintContext(file: string, root: string) {
  const text = readFileSync(file, "utf8");
  const pkgPath = join(root, "package.json");
  const pkg = existsSync(pkgPath) ? JSON.parse(readFileSync(pkgPath, "utf8")) : { scripts: {} };
  const deps = { ...pkg.dependencies, ...pkg.devDependencies };
  const problems: string[] = [];

  const lines = text.split("\n").length;
  if (lines > 200) problems.push(`too long: ${lines} lines (Claude Code's docs suggest under 200)`);

  for (const m of text.matchAll(/npm run ([\w:-]+)/g))
    if (!pkg.scripts?.[m[1]]) problems.push(`command does not exist: npm run ${m[1]}`);

  // أي `مسار` جوه backticks فيه / لازم يكون موجود، والـ placeholders بنسيبها
  for (const m of text.matchAll(/`([\w.-]+(?:\/[\w.-]+)+\/?)`/g))
    if (!/NN|<|\*/.test(m[1]) && !existsSync(join(root, m[1]))) problems.push(`path does not exist: ${m[1]}`);

  // الأداة المكتوبة لازم تكون هي اللي في package.json
  for (const tool of ["jest", "mocha", "vitest", "prisma", "drizzle-orm"])
    if (new RegExp(`\\b${tool}\\b`, "i").test(text) && !deps[tool]) problems.push(`mentions ${tool}, not in package.json`);

  return { lines, chars: [...text].length, problems };
}

Part 3 — When AI helps, when it hurts 🟢 Basicالجزء 3 — إمتى الـ AI بيفيد وإمتى بيضر

English

It helps where the work is well specified and cheap to check: boilerplate, tests for code that exists, migrations with a clear shape, mechanical refactors, docs, and explaining unfamiliar code. It hurts where you can't tell whether the answer is right: a complex codebase you don't understand, security-sensitive code, and architecture decisions, where the cost of a plausible wrong answer shows up months later.

The useful question isn't "is the AI good at this?" It's "can I verify the result, and what does it cost me if I can't?" The triage below uses five properties of the task, and "explain this old job to me" lands in the same bucket as the architecture question: you lead, and the AI only explains, because neither is something to delegate and walk away from.

The trade-off is speed now against skill later. Delegating a task you could already do costs nothing. Delegating the thing you're supposed to be learning (and this repo exists for that) means you end up with the code and without the understanding. Do your exercises by hand. The research on productivity and security is in lesson 29.

English

Walk it like a reviewer. What happens if two requests arrive at once? Both read refunded_cents = 0, both pass the check, both call the gateway. Then each writes its own absolute value, so the second overwrites the first. The run below does exactly that with two concurrent refunds of 8,000 on a 10,000 order: the gateway pays out 16,000, more than the order, while the database reports 8,000. The books look fine and the money is gone.

The fix puts the check and the increment in a single conditional UPDATE, so exactly one wins and the loser gets zero rows. In a real system the gateway call also gets an idempotency key, and a failed gateway call has to give the reservation back. That part is in section 08's idempotent receiver lesson.

Before you commit generated code, check these: read every line, run it yourself, ask what happens with two at once, with a retry and with bad input, confirm the tests fail when the code is broken, check nothing outside the task changed, and confirm that any API it used really exists. Part 5 — Cost, latency, failure 🟢 Basicالجزء 5 — التكلفة والـ latency والفشل

English

Subscription or API tokens. A subscription is a flat monthly price with usage limits: predictable, and good for an individual. API tokens are pay per use: nothing when idle, and better for automation or for watching cost per task. A long session gets expensive because every turn resends the whole conversation, and the run below shows 25 turns adding up to about 290K input tokens. Caching only the context file, $0.616 becomes $0.494 on Sonnet 5.5 and $1.232 becomes $0.988 on Opus 5.5. Real agents also move a cache breakpoint along the history, which the stand-in doesn't model, so a real session should save more.

To compare, divide the plan's price by the cost of a session like yours. Prices change, so the three plan figures below are round placeholders: check the real plan pages.

Latency. An agent's time is turns × (TTFT + output tokens ÷ speed) plus tool time. In Part 1, most of the ≈3 seconds was two npm test runs. So a slow test suite slows the agent directly, and a fast one is what makes the loop useful. As a modelled example, 25 turns at 1.5 s TTFT and 150 tokens at 60 tokens/s is about 100 s of model time before tools.

Failure modes you'll actually see: a hallucinated API (it imports a function that doesn't exist), scope creep (the fix touches files the task never mentioned), and tests rewritten to pass. You can check all three mechanically. The eval below runs 13 scripted cases through the real loop and grades the resulting repo: tests still pass, existing tests unchanged, only the allowed file changed, no new dependency, imports exist, no secret, and a held-out test the agent never saw, which catches hardcoding the expected number. This grades the checks, not any model.

Evaluate your own use. For one week, log five tasks: how long by hand (your honest estimate), time with AI, time spent correcting, bugs you caught, and whether you could explain the result. The sample figures below are invented to show the shape. The method is what you keep, and only your own numbers can tell you whether it's working for you.

async function session(model: string, cache: boolean) {
  const messages: Anthropic.MessageParam[] = [];
  let dollars = 0, read = 0, write = 0, plain = 0, output = 0;
  for (let t = 0; t < TURNS; t++) {
    messages.push({ role: "user", content: `turn ${t}: ${TOOL_RESULT}` });
    const res = await client.messages.create({
      model, max_tokens: 800,
      // الـ breakpoint على الـ context file بس، والـ agent الحقيقي بيحرّكه على الـ history كمان
      system: cache ? [{ type: "text", text: CONTEXT_FILE, cache_control: { type: "ephemeral" } }] : CONTEXT_FILE,
      messages,
    });
    dollars += costOf(model, res.usage);
    read += res.usage.cache_read_input_tokens ?? 0;
    write += res.usage.cache_creation_input_tokens ?? 0;
    plain += res.usage.input_tokens;
    output += res.usage.output_tokens;
    messages.push({ role: "assistant", content: res.content });
  }
  return { dollars, read, write, plain, output };
}

async function verdict(before: Map<string, string>) {
  const reasons: string[] = [];
  const after = listFiles(repo);
  // الـ tests الموجودة ممنوع تتغير، والجديدة مسموح

  for (const f of after) if (f.startsWith("test/") && /\.(skip|only)\(/.test(readFileSync(join(repo, f), "utf8"))) reasons.push("test skipped");
  // النطاق: الملف المسموح بس، أي حاجة جديدة في src برا الـ scope

  // كل import من node: لازم يكون موجود فعلًا
  for (const m of src.matchAll(/import \{([^}]+)\} from "(node:[^"]+)"/g)) {
    const mod = await import(m[2]);
    for (const n of m[1].split(",").map((s) => s.trim())) if (!(n in mod)) reasons.push(`hallucinated API: ${m[2]}.${n}`);

    const held = runTests(repo);
    rmSync(join(repo, "test/held-out.test.js"));
    if (!held.ok) reasons.push("held-out test fails");
  }
  return reasons;
}

اشتراك ولا API tokens. الاشتراك سعر ثابت في الشهر مع حدود استخدام: متوقع وكويس لفرد. الـ API بتدفع على قد استخدامك: مفيش تكلفة وإنت مش بتشتغل، وأحسن للـ automation أو لو عايز تتابع التكلفة لكل task. الـ session الطويلة بتغلى لأن كل turn بيبعت المحادثة كلها، والتشغيلة بتوري 25 turn وصلوا لحوالي 290K input tokens. لما بنعمل cache للـ context file بس، $0.616 بتبقى $0.494 على Sonnet 5.5، و$1.232 بتبقى $0.988 على Opus 5.5. والـ agents الحقيقية بتحرّك الـ cache breakpoint على المحادثة كمان، وده الـ stand-in مش بيعمله، فالـ session الحقيقية المفروض توفر أكتر.

عشان تقارن: اقسم سعر الـ plan على تكلفة session زي بتاعتك. الأسعار بتتغير، فالأرقام التلاتة دي للتجربة بس، وارجع لصفحات الأسعار الحقيقية.

الـ latency. وقت الـ agent = عدد الـ turns × (TTFT + output tokens ÷ السرعة) + وقت الـ tools. في الجزء 1 معظم الـ ≈3 ثواني كانت مرتين npm test. يعني الـ test suite البطيء بيبطّأ الـ agent مباشرة، والسريع هو اللي بيخلي الـ loop مفيدة. كمثال محسوب: 25 turn بـ 1.5 ثانية TTFT و150 token بسرعة 60 token/s يعني حوالي 100 ثانية وقت model قبل الـ tools.

الـ failure modes اللي هتشوفها فعلًا: API مش موجود (بيعمل import لحاجة مش موجودة)، وscope creep (الـ fix بيلمس ملفات محدش طلبها)، وtests اتكتبت عشان تعدّي. التلاتة دول تقدر تفحصهم بالكود. الـ eval بيشغّل 13 case متسكربتين في الـ loop الحقيقية ويحكم على الـ repo الناتج: الـ tests لسه شغالة، والـ tests الموجودة متغيرتش، والملف المسموح بس اللي اتغير، ومفيش dependency جديدة، والـ imports موجودة، ومفيش secret، وفيه held-out test الـ agent عمره ما شافه، بيمسك لو كتب الرقم المتوقع بإيده. ده بيحكم على الفحوصات، مش على أي model.

قيّم استخدامك إنت. لمدة أسبوع سجّل 5 tasks: الوقت بإيدك (تقدير صادق)، والوقت بالـ AI، ووقت التصليح، والـ bugs اللي مسكتها، وتقدر تشرح النتيجة ولا لأ. الأرقام اللي فوق مكتوبة بإيدينا عشان تشوف الشكل. الطريقة هي اللي تفضل معاك، وأرقامك إنت بس هي اللي هتقول الموضوع نافع ولا لأ.

الغلطة الشائعة: الحكم بالإحساس "أنا أسرع"، أو تسيب الـ agent يعدّل الـ tests لحد ما تعدّي.

فين هستخدمه في شغلي؟ حط الفحوصات دي في الـ CI على أي branch من agent: الـ tests الموجودة متتغيرش من غير موافقة، وقايمة ملفات مسموحة، ومفيش dependency جديدة، وheld-out test لو تقدر. وفي الـ retro بتاع الشهر، طلّع جدول الـ 5 tasks: أنهي نوع task بيوفر وقت فعلًا، وأنهي نوع بيضيّع وقت في التصليح.
Trade-off: the review is where the cost went The token bill for a session is small next to your hourly rate. If a generated change takes longer to verify than to write by hand, you've lost time and also learned less. Measure correction time, not generation time.
فاتورة الـ tokens صغيرة جنب سعر ساعتك. لو تغيير متولّد بياخد وقت في التأكد أكتر من كتابته بإيدك، يبقى ضيّعت وقت واتعلمت أقل كمان. قيس وقت التصليح، مش وقت الـ generation.

❌ Trust the agent's summary

✅ Run it yourself

git diff main --stat
بالعامية

❌ جملة "All tests pass" مجرد نص. في أول تشغيلة للـ script بتاع الجزء 1 اتقالت والـ test لسه بيفشل. ✅ شغّل الأمر بنفسك وبص على الـ diff كله، وخصوصًا لو في ملفات test اتغيرت.

❌ A rule the code contradicts 
- We test with Jest.
- Run `npm run test:unit`
✅ Linted against the repo 
- Test: `npm test` (Vitest)
- One file: `npx vitest run src/invoices/total.test.ts`
بالعامية

❌ الملف بيقول Jest والمشروع Vitest، والـ script مش موجود: الـ agent هيضيع turns ويجرّب أوامر غلط. ✅ كل أمر وكل مسار في الملف لازم يكون حقيقي، وخلّي الـ linter في الـ CI يفضحهم.

❌ Weaken the test to go green 
// الرقم اتغير عشان يطابق الكود الغلط
assert.equal(invoiceTotal(lines, opts), 1780);
✅ Fix the code, keep the test 
// الخصم قبل الضريبة، والـ test زي ما هو
return Math.round((subtotal - discountCents) * (1 + taxRate));
بالعامية

❌ تغيير الـ assertion بيخلي الـ CI أخضر والـ bug لسه موجود، والـ eval في الجزء 5 رفضها بسبب "existing test changed". ✅ أصلح الكود، وأي test موجود يتغير يبقى بموافقتك وبسبب مكتوب.

❌ Check, then write, in two statements 
-- طلبين مع بعض هيعدّوا الفحص، والتاني يمسح الأول
select refunded_cents from orders where id = $1;
update orders set refunded_cents = $1 where id = $2;
✅ Condition and change together 
-- طلب واحد بس هيرجع صف
update orders set refunded_cents = refunded_cents + $1
where id = $2 and refunded_cents + $1 <= total_cents
returning refunded_cents;
بالعامية

❌ الفحص في statement والكتابة في statement تاني، وبينهم وقت كفاية لطلب تاني يدخل، وفي الجزء 4 الـ gateway دفع 16,000 على order بـ 10,000. ✅ الشرط والزيادة في UPDATE واحد، والـ DB هي اللي بتضمن إن واحد بس يكسب.

Solution · الحل 
// الحل: عدّ السطور اللي اتغيرت، وارفض أي diff أكبر من الـ task
function changedLines(before: string, after: string) {
  const a = before.split("\n"), b = after.split("\n");
  let same = 0;
  const seen = new Map<string, number>();
  for (const l of a) seen.set(l, (seen.get(l) ?? 0) + 1);
  for (const l of b) {
    const n = seen.get(l) ?? 0;
    if (n > 0) { same++; seen.set(l, n - 1); }
  }
  return Math.max(a.length, b.length) - same;
}

const MAX_CHANGED = 10;
const before = "line1\nline2\nline3";
console.log(changedLines(before, "line1\nline2 fixed\nline3"));
// → 1
const huge = Array.from({ length: 40 }, (_, i) => `rewritten ${i}`).join("\n");
console.log(changedLines(before, huge), changedLines(before, huge) > MAX_CHANGED);
// → 40 true
بنعدّ السطور المشتركة بين النسختين، والباقي هو اللي اتغير. سطر واحد اتعدل بيطلع 1، وإعادة كتابة 40 سطر بتطلع 40 وتتخطى الحد.

Cheat sheet · الخلاصة

  • Autocomplete: you hold the loop, next few lines. Agent: it holds the loop over a whole task.
  • An agent is the tool-calling loop with file and shell tools, plus a sandbox and permissions.
  • CLAUDE.md for Claude Code, AGENTS.md as the open format (closest file wins), .cursor/rules/*.mdc in Cursor; .cursorrules is legacy.
  • Context file: commands, conventions, don'ts. Under 200 lines. Only what the agent can't infer.
  • It's context, not enforcement: real guards are permissions, hooks and CI.
  • Lint the file against the repo: commands, paths, named tools.
  • Delegate what you can verify and undo. Pair on money, auth and tenancy. Lead on architecture and code you don't understand.
  • Test for merging: could you explain and debug this at 3 a.m.?
  • Passing tests aren't proof: the generated refund passed its test and paid out 16,000 on a 10,000 order.
  • Every turn resends the conversation, so session cost grows with context. Caching helps a lot, and review time still costs more.
  • Check agents mechanically: unchanged tests, allowed files, no new deps, real imports, no secrets, a held-out test.
  • Track five real tasks. Your numbers, not your feeling, decide what to delegate.
بالعامية
  • الـ autocomplete: إنت ماسك الـ loop، والسطور الجاية بس. الـ agent: هو ماسك الـ loop على task كامل.
  • الـ agent هو loop الـ tool calling مع tools للملفات والـ shell، ومعاها sandbox وصلاحيات.
  • CLAUDE.md لـ Claude Code، وAGENTS.md الـ open format (أقرب ملف بيكسب)، و.cursor/rules/*.mdc في Cursor، و.cursorrules legacy.
  • الـ context file: أوامر، وconventions، وdon'ts. أقل من 200 سطر، وبس اللي الـ agent ميعرفش يستنتجه.
  • هو context مش إجبار: الحماية الحقيقية صلاحيات وhooks وCI.
  • اعمل lint للملف قصاد الـ repo: الأوامر، والمسارات، والأدوات المذكورة.
  • إدّي اللي تقدر تتأكد منه وترجع فيه. pair في الفلوس والـ auth والـ tenancy. قود إنت في الـ architecture والكود اللي مش فاهمه.
  • مقياس الـ merge: تقدر تشرحه وتعمله debug الساعة 3 الصبح؟
  • الـ tests الناجحة مش دليل: الـ refund المتولّد عدّى الـ test بتاعه ودفع 16,000 على order بـ 10,000.
  • كل turn بيبعت المحادثة كلها، فتكلفة الـ session بتكبر مع الـ context. الـ caching بيساعد كتير، ووقت المراجعة لسه أغلى.
  • افحص الـ agents بالكود: tests متغيرتش، وملفات مسموحة، ومفيش deps جديدة، وimports حقيقية، ومفيش secrets، وheld-out test.
  • سجّل 5 tasks حقيقية. أرقامك إنت، مش إحساسك، هي اللي بتقرر تدّي إيه.
