Why this matters · ليه ده مهم

English

Lesson 19 stopped the model from doing harm. This one is about what you send and what you let in. Every prompt you send is customer data leaving your system, so you need to know what's in it, where it goes and how long it stays. Every AI endpoint you open is also the most expensive endpoint you own, so a bot or a stolen key can turn it into a four-figure bill by morning.

These are the questions you get in a security review before launch: what personal data reaches the provider, what's your retention, what do you do with abusive input, and what stops someone from using your endpoint as free compute? This lesson gives you code, numbers and the failure modes for each answer.

بالعامية

درس 19 منع الـ model يعمل ضرر. الدرس ده عن اللي بتبعته واللي بتسمحله يدخل. كل prompt بتبعته هو data عملاء خارجة من السيستم بتاعك، فلازم تعرف فيها إيه، ورايحة فين، وهتفضل قد إيه. وكل AI endpoint بتفتحه هو أغلى endpoint عندك، فـ bot أو key مسروق ممكن يقلبه فاتورة بأربع أرقام الصبح.

Part 1 — Reversible PII redaction 🟡 Intermediateالجزء 1 — الـ PII redaction القابل للرجوع

English

Replace personal data with tokens before the provider sees it (<PERSON_1>, <PHONE_1>), keep the map on your server, and rehydrate the model's output before showing it to the user. Reversible matters because the model often needs to say the name back, and the same person must keep the same token so the model can track who did what.

For Egyptian data the detectors are regexes plus validators, and the validators are what give you precision: mobile numbers (010/011/012/015, with +20 or 0020, including Arabic-Indic digits), 14-digit national IDs (century digit, a real date, a real governorate code), cards with the Luhn check, and emails. Names are the weak spot, because no regex finds them reliably: use context cues ("اسمي", "Mr.") and the names you already hold in your CRM for this ticket. Note the Arabic detail: a name can arrive glued to a preposition, as in "لمنى".

On 40 labelled Arabic and English fixtures, validators give precision 0.97 and recall 0.92, against 0.79 precision without them, and 3 of the 38 labelled spans still reached the provider: a redactor lowers exposure, it doesn't remove it. For a heavier pipeline there's Presidio (Python, named here, not run), and whatever you use, measure it the same way.

Bad redaction is one that breaks the sentence the model needs. Replacing everything with [REDACTED] means the model can't tell who complained about whom, and Arabic gender agreement can get lost. And streaming needs care: a token can be split across chunks, so hold back anything that might be the start of one.

// الـ redaction القابل للرجوع: النص بيتغير قبل الـ provider، والـ map بيفضل عندنا
export type PiiType = "PERSON" | "PHONE" | "NATIONAL_ID" | "CARD" | "EMAIL";
export type Span = { type: PiiType; start: number; end: number; value: string };
export type RedactOptions = { knownNames?: string[]; validators?: boolean };

// الأرقام العربية بتتحول حرف بحرف، فالـ offsets بتفضل صح على النص الأصلي
export const normalizeDigits = (s: string) =>
  s.replace(/[٠-٩]/g, (d) => String(d.charCodeAt(0) - 0x0660)).replace(/[۰-۹]/g, (d) => String(d.charCodeAt(0) - 0x06f0));

const digitsOnly = (s: string) => normalizeDigits(s).replace(/\D/g, "");

export function luhn(digits: string): boolean {
  let sum = 0;
  let double = false;
  for (let i = digits.length - 1; i >= 0; i--) {
    let d = digits.charCodeAt(i) - 48;
    if (double) { d *= 2; if (d > 9) d -= 9; }
    sum += d;
    double = !double;
  }
  return digits.length >= 13 && digits.length <= 19 && sum % 10 === 0;
}

// أكواد المحافظات في الرقم القومي: 88 يعني مولود برّه مصر
const GOVERNORATES = new Set(["01", "02", "03", "04", "11", "12", "13", "14", "15", "16", "17", "18", "19", "21", "22", "23", "24", "25", "26", "27", "28", "29", "31", "32", "33", "34", "35", "88"]);

// الشكل: قرن + سنة + شهر + يوم + محافظة + مسلسل ⁦+ check digit⁩
export function isEgyptianNationalId(d: string): boolean {
  if (!/^[23]\d{13}$/.test(d)) return false;
  const century = d[0] === "2" ? 1900 : 2000;
  const year = century + Number(d.slice(1, 3));
  const month = Number(d.slice(3, 5));
  const day = Number(d.slice(5, 7));
  const date = new Date(Date.UTC(year, month - 1, day));
  if (date.getUTCFullYear() !== year || date.getUTCMonth() !== month - 1 || date.getUTCDate() !== day) return false;
  if (date.getTime() > Date.now()) return false;
  return GOVERNORATES.has(d.slice(7, 9));
}

export function isEgyptianMobile(d: string): boolean {
  const local = d.startsWith("0020") ? d.slice(4) : d.startsWith("20") ? d.slice(2) : d.replace(/^0/, "");
  return /^1[0125]\d{8}$/.test(local);
}

const NAME_STOP = new Set(["ورقمي", "ورقمه", "ورقمها", "والطلب", "و", "اللي", "مش", "طلبت", "طلب", "قال", "كان", "كانت", "وكان", "وكانت"]);

const ARABIC_CUE = /(?:اسمي|اسمه|اسمها|أنا|الأستاذ|الأستاذة|السيد|السيدة|المهندس|المهندسة|دكتور|دكتورة|د\.)\s+([ء-ي]+(?:\s+[ء-ي]+)?)/g;
const ENGLISH_CUE = /(?:\b[Mm]y name is|\b[Tt]his is|\bMr\.?|\bMrs\.?|\bMs\.?|\bDr\.?)\s+([A-Z][a-z]+(?:\s+[A-Z][a-z]+)?)/g;

export function detect(text: string, opts: RedactOptions = {}): Span[] {
  const validators = opts.validators ?? true;
  const norm = normalizeDigits(text);
  const found: Span[] = [];
  const push = (type: PiiType, start: number, end: number) => found.push({ type, start, end, value: text.slice(start, end) });

  for (const m of norm.matchAll(/[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}/g)) push("EMAIL", m.index, m.index + m[0].length);

  // الرقم القومي الأول، عشان 14 رقم ممكن يعدوا Luhn بالصدفة فيتحسبوا كارت
  for (const m of norm.matchAll(/(?<!\d)\d{14}(?!\d)/g)) {
    if (!validators || isEgyptianNationalId(m[0])) push("NATIONAL_ID", m.index, m.index + m[0].length);
  }
  for (const m of norm.matchAll(/(?<![\d+])(?:\d[ -]?){12,18}\d(?![\d])/g)) {
    const d = digitsOnly(m[0]);
    if (d.length < 13 || d.length > 19) continue;
    if (!validators || luhn(d)) push("CARD", m.index, m.index + m[0].length);
  }
  for (const m of norm.matchAll(/(?<!\d)(?:(?:\+|00)?20[\s-]?)?0?1\d(?:[\s-]?\d){8}(?!\d)/g)) {
    if (!validators || isEgyptianMobile(digitsOnly(m[0]))) push("PHONE", m.index, m.index + m[0].length);
  }

  for (const cue of [ARABIC_CUE, ENGLISH_CUE]) {
    for (const m of text.matchAll(cue)) {
      const words = m[1]!.split(/\s+/);
      if (words.length === 2 && (NAME_STOP.has(words[1]!) || words[1]!.startsWith("و"))) words.pop();
      const name = words.join(" ");
      const start = m.index + m[0].indexOf(m[1]!);
      push("PERSON", start, start + name.length);
    }
  }
  // الأسماء اللي عارفينها من الـ CRM: ممكن تيجي لازقة في حرف جر زي "لمنى"
  for (const name of opts.knownNames ?? []) {
    const re = new RegExp(`(?<![\\p{L}])(?:[وبلفك]?)(${name.replace(/[.*+?^${}()|[\]\\]/g, "\\$&")})(?![\\p{L}])`, "gu");
    for (const m of text.matchAll(re)) {
      const start = m.index + m[0].indexOf(m[1]!);
      push("PERSON", start, start + m[1]!.length);
    }
  }

  // لو spans اتداخلوا، الأطول يكسب، والأولوية للنوع الأدق
  const rank: Record<PiiType, number> = { EMAIL: 0, NATIONAL_ID: 1, CARD: 2, PHONE: 3, PERSON: 4 };
  found.sort((a, b) => a.start - b.start || b.end - a.end || rank[a.type] - rank[b.type]);
  const out: Span[] = [];
  for (const s of found) {
    const prev = out.at(-1);
    if (prev && s.start < prev.end) continue;
    out.push(s);
  }
  return out;
}

export type RedactResult = { text: string; map: Map<string, string>; spans: Span[] };

// نفس القيمة بتاخد نفس الـ token، عشان الـ model يعرف إنهم نفس الشخص
export function redact(input: string, opts: RedactOptions = {}, existing = new Map<string, string>()): RedactResult {
  const spans = detect(input, opts);
  const map = existing;
  const reverse = new Map([...map].map(([k, v]) => [v, k]));
  const counters: Record<string, number> = {};
  for (const token of map.keys()) {
    const m = /^<([A-Z_]+)_(\d+)>$/.exec(token)!;
    counters[m[1]!] = Math.max(counters[m[1]!] ?? 0, Number(m[2]));
  }
  let out = "";
  let cursor = 0;
  for (const s of spans) {
    out += input.slice(cursor, s.start);
    let token = reverse.get(s.value);
    if (!token) {
      counters[s.type] = (counters[s.type] ?? 0) + 1;
      token = `<${s.type}_${counters[s.type]}>`;
      map.set(token, s.value);
      reverse.set(s.value, token);
    }
    out += token;
    cursor = s.end;
  }
  out += input.slice(cursor);
  return { text: out, map, spans };
}

// الرجوع: بنقبل اختلافات الـ model البسيطة، و token مش معروف بيتساب ويتبلغ عنه
export function rehydrate(text: string, map: Map<string, string>): { text: string; unknown: string[] } {
  const unknown: string[] = [];
  const replaced = text.replace(/<\s*(PERSON|PHONE|NATIONAL_ID|CARD|EMAIL)_(\d+)\s*>/gi, (whole, type: string, n: string) => {
    const token = `<${type.toUpperCase()}_${n}>`;
    const value = map.get(token);
    if (value === undefined) { unknown.push(whole); return whole; }
    return value;
  });
  return { text: replaced, unknown };
}

// في الـ stream: الـ token ممكن يتقطع بين chunks، فبنحجز أي بداية محتملة لـ token
export function streamRehydrator(map: Map<string, string>) {
  let buffer = "";
  return {
    push(chunk: string): string {
      buffer += chunk;
      const lastOpen = buffer.lastIndexOf("<");
      const held = lastOpen !== -1 && !buffer.slice(lastOpen).includes(">") && buffer.length - lastOpen <= 24;
      const ready = held ? buffer.slice(0, lastOpen) : buffer;
      buffer = held ? buffer.slice(lastOpen) : "";
      return rehydrate(ready, map).text;
    },
    flush(): string {
      const rest = rehydrate(buffer, map).text;
      buffer = "";
      return rest;
    },
  };
}

Part 2 — Residency and retention 🟡 Intermediateالجزء 2 — مكان الـ data ومدة الاحتفاظ بيها

English

Two questions: where does inference run, and how long is the data kept. For the Claude API, inference_geo takes "us" or "global" (default), and it's set per request or as a workspace default. The pricing page puts US-only inference at 1.1x on Claude 4.6 and later models, across all token categories. Workspace geo (where data is stored at rest) is currently "us" only. So there is no EU inference geo on the first-party API; on Amazon Bedrock and Google-managed Vertex the region follows your endpoint.

Retention, in Anthropic's words: for commercial and API customers "we automatically delete inputs and outputs on our backend within 30 days of receipt or generation", with exceptions such as the Files API, Usage Policy violations, and legal holds. The API docs describe the same area from the feature side, and say conversation content is "not retained by default" apart from Covered Models. Read the current pages and your contract, and don't paraphrase them from memory.

Zero data retention is an arrangement you request from sales, per organization: "Anthropic does not store customer prompts or responses at rest after the API response is returned." It doesn't cover everything: the Batch API (29-day retention), Files API and code execution (up to 30 days) are excluded, and even under ZDR flagged content can be kept for up to 2 years. Claude Fable 5, Fable 5.1, Mythos 5 and Mythos 5.1 are Covered Models: they require 30-day retention and are not available under ZDR unless expressly authorized by Anthropic, and non-conforming organizations get a 400.

For an Egyptian company with EU customers, GDPR can apply directly when you offer goods or services to people in the EU (Article 3(2)). You need a processing contract with the provider (Article 28) and a transfer mechanism for moving data outside the EU (Chapter V), and the US-only or global geo above is exactly such a transfer. Egypt's Personal Data Protection Law (No. 151 of 2020) has executive regulations (Decision 816 of 2025, issued 1 November 2025) with a one-year grace period and a licensing regime for transfers abroad. Part 3 — Moderation and guardrails 🟡 Intermediateالجزء 3 — الـ moderation والـ guardrails

English

Moderation is a classifier before and after the model: on the input to refuse abusive or off-limits requests, and on the output to catch what shouldn't reach the user. Layer it: cheap rules first, then a small model (Haiku 5.5, max_tokens around 256, JSON out). Rules are instant and blind to context; the model catches context and costs a call.

The provider has its own layer. Current Claude models can decline with a normal HTTP 200 and stop_reason: "refusal", where stop_details names a category such as cyber or general_harms, or null when none applies. Check stop_reason before reading content. A refusal can also arrive mid-stream, so discard partial text. fallbacks: "default" with the beta header server-side-fallback-2026-07-01 re-runs a declined request on another model; it applies to Opus 5.5 and Sonnet 5.5 (not to Haiku 5.5, which has no server-side fallback). The billed categories for pre-output refusals are listed on the refusals page and may change, so don't hardcode them.

To avoid slowing the stream, run the input guard in parallel with the main call, hold the first tokens back until the guard answers, and abort the main call if it flags. In this run the first visible token came at about 232 ms in parallel against 358 ms in series. A flagged request produced 15 of 113 tokens before the abort with a slow guard, and none reached the user.

False positives have a price. A keyword rule on 200 seeded tickets flagged 30 benign ones ("my account was hacked", "this delay is killing me"), a 15.7% false-block rate. At an assumed $1.20 per ticket that a human then has to pick up, that's $18,000 a month at 100,000 tickets, which is far more than the classifier costs ($1.20/month on Haiku 5.5 at 60 input and 12 output tokens). How accurate a real classifier is on your tickets isn't measured here: run your own eval.

async function classify(text: string, client: Anthropic = guardClient): Promise<Verdict> {

    model: "claude-haiku-5-5",
    max_tokens: 256,
    system: 'Classify a customer message. Reply with JSON only: {"flag": boolean, "category": "threat" | "fraud" | "abuse" | null}.',
    messages: [{ role: "user", content: `<message>${text}</message>` }],
  });

    return JSON.parse(raw) as Verdict;

    // لو الـ guard نفسه رجع حاجة بايظة، الأأمن إننا نعامله كـ flagged

}

Part 4 — Jailbreaks 🟡 Intermediateالجزء 4 — الـ jailbreaks

English

A jailbreak gets a model past its safety training: role-play framing, encoding the request, or multi-turn pressure until it gives in. It differs from prompt injection in the target: injection hijacks your app's instructions, a jailbreak goes after the model's own refusals. This page doesn't carry working recipes, on purpose: the fixtures below are descriptions, and that's all your test set needs.

The model's safety isn't your product's safety. Scope the product so that a jailbreak gains little: the model has no tools worth abusing, no secrets in the prompt, no data the user couldn't already see, and its output must fit a narrow schema or the user gets a canned reply. Then a fully jailbroken model is annoying instead of dangerous.

The eval assumes the worst: the stand-in complies with everything, every time. It's real code checking your scope, not the model. Then monitor for the pattern: an account that keeps hitting the canned reply in a short window is probing you, and the run below flags it after 5 blocked replies in 10 minutes.

English

An AI endpoint is free compute to anyone who can reach it. OWASP calls this LLM10:2025 Unbounded Consumption: a bot, a scraper or a stolen key can run up the bill. The layers are auth, rate limits (lesson 18 has the per-tenant token budgets), cost caps, and per-account anomaly detection, with a kill switch behind them.

A cost cap has to be atomic. Check-then-call fails under concurrency: 40 requests all read "under the cap" and all go through. In this run the check-then-call version spent $1.0950 against a $1.00 cap. The fix is to reserve the worst-case cost in a Lua script (input estimate plus max_tokens at output price), then settle the difference with the actual usage. The reservation version stopped at $0.9855, and without any cap the same bot spent $4.11 on 300 requests.

Anomaly detection is a daily job over usage: a z-score of today's tokens against that account's own history. The run flags the bot at z = 518.6 and also flags a growing startup at z = 5.7, so the action has to differ: auto-kill only the extreme case, send the rest to a human. Small accounts need a floor on the standard deviation and a minimum token count, otherwise an account going from 40 to 300 tokens scores 97.7 and pages someone for nothing.

Stolen API key: the kill switch is a Redis flag read on every request, so it works in the next request, not the next deploy. export type AnomalyOptions = { z: number; stdFloor: number; minTokens: number };
export const DEFAULTS: AnomalyOptions = { z: 4, stdFloor: 5_000, minTokens: 50_000 };

export function zScore(history: number[], today: number, stdFloor = 0): number {
  const mean = history.reduce((a, b) => a + b, 0) / history.length;
  const variance = history.reduce((a, b) => a + (b - mean) ** 2, 0) / history.length;
  const std = Math.max(Math.sqrt(variance), stdFloor);
  return std === 0 ? (today === mean ? 0 : Infinity) : (today - mean) / std;
}

export function isAnomalous(history: number[], today: number, opts: AnomalyOptions = DEFAULTS): boolean {

  if (today < opts.minTokens) return false;
  return zScore(history, today, opts.stdFloor) >= opts.z;

English

The eval that belongs in CI: redaction on the 40 fixtures with hard floors (precision ≥ 0.9, recall ≥ 0.85, and recall of 1.0 for cards and national IDs). The gate has to be able to fail, so the run also removes the validators and shows precision fall to 0.79 and the gate fail.

Two failure modes get a real run. PII in tool results bypasses the redactor: redacting only the user's message leaves the phone number in the tool result on the wire. The fix is one pipeline for every piece of text that reaches the provider, with the same map so tokens stay stable. Anomaly thresholds on small accounts: a tiny account scores z = 317 without a floor and isn't flagged with one. import { isEgyptianMobile, normalizeDigits } from "./redact.ts";

// الصيغة الجديدة: الـ 20 بين قوسين، والأرقام ممكن تكون عربي
const PHONE = /(?<!\d)\(?(?:\+|00)?20\)?[\s-]?0?1\d(?:[\s-]?\d){8}(?!\d)/g;

export function findPhones(text: string): string[] {
  const norm = normalizeDigits(text);
  return [...norm.matchAll(PHONE)].map((m) => m[0]).filter((v) => isEgyptianMobile(v.replace(/\D/g, "")));
}

assert.deepEqual(findPhones("call (+20) 122 333 4444 please"), ["(+20) 122 333 4444"]);
assert.deepEqual(findPhones("رقمي (٢٠) ١٠١٢٣٤٥٦٧٨ شكرا"), ["(20) 1012345678"]);
assert.deepEqual(findPhones("call (+20) 182 333 4444 please"), []);

3. Don't auto-kill new accounts 🟡 medium Write decide(history, today, minHistoryDays = 7) returning none, review or kill. Accounts with fewer than 7 days of history can reach review at most, whatever the z-score.

import assert from "node:assert/strict";
import { DEFAULTS, isAnomalous, zScore } from "./anomaly.ts";

// الحساب الجديد: تاريخه قصير، فأقصى حاجة نبعته لمراجعة بشرية، عمره ما يتقفل تلقائي
export type Action = "none" | "review" | "kill";
export function decide(history: number[], today: number, minHistoryDays = 7): Action {
  if (!isAnomalous(history, today)) return "none";
  if (history.length < minHistoryDays) return "review";
  return zScore(history, today, DEFAULTS.stdFloor) >= 20 ? "kill" : "review";
}

const steady = Array.from({ length: 30 }, () => 60_000);
assert.equal(decide(steady, 65_000), "none");
assert.equal(decide(steady, 2_400_000), "kill");
assert.equal(decide([900, 1_200, 800], 400_000), "review");
assert.equal(decide([40, 41, 42], 300), "none");

Cheat sheet · الخلاصة

  • Redact with reversible, numbered tokens before the provider, keep the map server-side, rehydrate the output, and handle tokens split across stream chunks.
  • Validators beat bare regex: Luhn, date plus governorate for national IDs, mobile prefixes. 40 fixtures: precision 0.97 / recall 0.92 with them, 0.79 precision without. Names stay the weak spot.
  • Redaction lowers exposure, it doesn't remove it: 3 of 38 labelled spans still reached the provider. Presidio (Python) is the heavier option.
  • inference_geo is us or global only (1.1x for US-only on 4.6+ models); there's no EU geo on the first-party API.
  • ZDR is by arrangement per organization and excludes Batch, Files and code execution; Fable 5/5.1 and Mythos 5/5.1 require 30-day retention. Flagged content can be kept up to 2 years. Read the current pages and your contract.
  • EU customers: a DPA (GDPR Art. 28) and a transfer basis (Chapter V). Egypt: Law 151 of 2020 and Decision 816 of 2025. Not legal advice.
  • Moderate in layers: rules, then a small model, on input and output. Run the input guard in parallel and hold tokens until it answers. Handle stop_reason: "refusal" before content.
  • False positives cost money: a keyword rule false-blocked 15.7% of 200 seeded tickets.
  • Jailbreaks target the model's refusals; your product's safety is scope: no valuable tools or data, narrow output schema, monitor for probing.
  • AI endpoints are free compute to attackers (OWASP LLM10:2025): auth, rate limits, an atomic cost cap, a Redis kill switch, a daily z-score job.
  • Atomic reservation held $0.9855 against a $1.00 cap; check-then-call hit $1.0950 at concurrency 40; no cap spent $4.11.
  • Run one redaction pipeline over every text the provider sees, tool results included; floor the z-score for small accounts; auto-kill only the extreme cases.
