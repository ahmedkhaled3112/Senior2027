Part 1 — VPC design and the NAT bill 🟡 Intermediateالجزء 1 — تصميم الـ VPC وفاتورة الـ NAT

English

The standard layout is three tiers across at least two Availability Zones. Public subnets hold only the ALB and the NAT gateways, and their route table sends 0.0.0.0/0 to an internet gateway. App subnets are private: their default route points at a NAT gateway, so tasks can call out but nothing can call in. Data subnets have no default route at all. The basic split is in lesson 35, and the "who can reach whom" model is in section 12, lesson 37, part 5. What's new here is sizing and cost.

Don't give every tier the same size. With awsvpc networking each Fargate task takes one IP from its subnet, and a rolling deploy can briefly double the count, so the app tier gets a /20 (4,091 usable; AWS reserves 5 addresses per subnet). The public and data tiers hold a handful of ENIs, so /24 is plenty. Check for overlap with every network you may ever peer with: the VPC's primary CIDR can't be changed later (you can only add secondary ranges), and overlapping ranges can't be routed across a peering or VPN.

NAT is where the bill surprises people. AWS's Ohio example, read on 2026-11-09: $0.045 per hour per gateway plus $0.045 per GB processed, with partial hours billed as full hours. The per-GB charge applies to traffic going to S3 in the same region too, unless you add an endpoint. A gateway endpoint (S3 and DynamoDB) has no hourly or data charge: it adds a route for the service's prefix list, and the longest prefix wins. An interface endpoint (ECR, Secrets Manager, CloudWatch Logs) is a paid ENI, at $0.01 per hour per AZ plus $0.01 per GB in AWS's US-East-1 example, so it only pays for itself above a break-even volume. The same page also lists a Regional NAT Gateway at $0.045 per hour per AZ, one resource spanning AZs.

One NAT per AZ versus one shared NAT is a real trade-off: three gateways cost more at rest, but with a single NAT, losing its AZ cuts egress for all of them, and traffic from the other AZs pays cross-AZ data transfer on top.

// الفكرة: كل tier ليها حجم حسب اللي هيعيش فيها، مش كل الـ subnets زي بعض
type Tier = { name: string; prefix: number; why: string };

const toInt = (ip: string) => ip.split(".").reduce((n, p) => n * 256 + Number(p), 0);
const toIp = (n: number) => [24, 16, 8, 0].map((s) => Math.floor(n / 2 ** s) % 256).join(".");
const range = (cidr: string) => {
  const [ip, p] = cidr.split("/");
  const size = 2 ** (32 - Number(p));
  const start = toInt(ip!);
  if (start % size !== 0) throw new Error(`${cidr}: host bits are set`);
  return { start, end: start + size - 1, size };
};
const overlaps = (a: string, b: string) => {
  const x = range(a), y = range(b);
  return x.start <= y.end && y.start <= x.end;
};

// التخصيص: من الأكبر للأصغر، وكل subnet لازم يبدأ على حدود حجمه (alignment)
export function plan(vpc: string, azs: string[], tiers: Tier[]) {
  const { start, end } = range(vpc);
  const wanted = tiers.flatMap((t) => azs.map((az) => ({ tier: t.name, az, prefix: t.prefix })));
  wanted.sort((a, b) => a.prefix - b.prefix);
  let cursor = start;
  const out = wanted.map((w) => {
    const size = 2 ** (32 - w.prefix);
    cursor = Math.ceil(cursor / size) * size;
    const cidr = `${toIp(cursor)}/${w.prefix}`;
    if (cursor + size - 1 > end) throw new Error(`${vpc} is too small for ${w.tier}-${w.az}`);
    cursor += size;
    // الـ 5 عناوين: AWS بتحجز أول 4 وآخر عنوان في كل subnet
    return { name: `${w.tier}-${w.az}`, cidr, usable: size - 5 };
  });
  return { subnets: out, freeAddresses: end - cursor + 1 };
}

التصميم المعتاد 3 طبقات على AZ اتنين على الأقل. الـ public فيها الـ ALB والـ NAT gateways بس، والـ route table بتاعتها بتبعت 0.0.0.0/0 للـ internet gateway. الـ app private: الـ default route بيروح NAT، فالـ tasks تقدر تكلّم بره بس محدش يقدر يكلمها. والـ data مالهاش default route أصلًا. التقسيم الأساسي في الدرس 35، ونموذج "مين يوصل لمين" في القسم 12، الدرس 37، الجزء 5. الجديد هنا الأحجام والتكلفة.

متديش كل tier نفس الحجم. مع awsvpc كل Fargate task بياخد IP من الـ subnet، والـ rolling deploy ممكن يضاعف العدد مؤقتًا، فالـ app ياخد /20 (4,091 عنوان، AWS بتحجز 5 في كل subnet). الـ public والـ data فيهم ENIs قليلة فـ /24 كفاية. وافحص التقاطع مع أي شبكة ممكن تربطها في يوم: الـ primary CIDR بتاع الـ VPC مبيتغيرش بعدين (تقدر تضيف secondary بس)، والـ ranges المتقاطعة مبتتعملش routing عبر peering أو VPN.

الـ NAT هو اللي بيفاجئ الناس. مثال AWS لـ Ohio يوم 2026-11-09: $0.045 في الساعة لكل gateway + $0.045 لكل GB، والساعة الناقصة بتتحسب ساعة كاملة. والـ GB بتتحسب حتى لو رايح S3 في نفس الـ region، إلا لو ضفت endpoint. الـ gateway endpoint (S3 و DynamoDB) ببلاش خالص: بيضيف route للـ prefix list بتاعت الخدمة، والـ prefix الأطول بيكسب. الـ interface endpoint (ECR، Secrets Manager، CloudWatch Logs) هو ENI بفلوس، $0.01 في الساعة لكل AZ + $0.01 لكل GB في مثال US-East-1، فمبيوفرش غير بعد حجم معيّن. ونفس الصفحة فيها Regional NAT Gateway بـ $0.045 في الساعة لكل AZ، resource واحد على كل الـ AZs.

NAT لكل AZ ضد NAT واحد مشترك trade-off حقيقي: التلاتة أغلى وهما واقفين، لكن مع NAT واحد لو الـ AZ بتاعته وقع كله بيفقد الـ egress، وكمان الـ traffic من باقي الـ AZs بيدفع cross-AZ data transfer.

فين هستخدمه في شغلي؟ الفاتورة طلعت فيها NAT بـ $600 والـ service مش كبير. بتشغّل VPC Flow Logs وتلاقي worker بيعمل resize للصور بيقرا ويكتب من S3 عن طريق الـ NAT. الحل مش تغيير كود: aws_vpc_endpoint واحد من نوع Gateway (الـ Terraform بتاعه في الجزء 6). والغلطة الشائعة العكسية: تضيف interface endpoints لكل خدمة من غير ما تحسب، فتزوّد الفاتورة زي ما شفت في الـ output.

Part 2 — Security groups, NACLs, load balancers, DNS 🟡 Intermediateالجزء 2 — الـ security groups والـ NACLs والـ load balancers والـ DNS

English

A security group is stateful and attached to an ENI: allow the request in and the reply is allowed out automatically, because the connection is tracked. It has allow rules only, and a rule can name another security group as its source, which survives autoscaling and IP changes. A network ACL is stateless and attached to a subnet: each direction is evaluated separately, rules run in number order, and there is an implicit deny at the end. So a NACL that allows 5432 in must also allow the reply out to the client's ephemeral port range, which is the classic "the rule is right and it still hangs" bug. Use security groups for the real policy, and keep NACLs at their default unless you need a subnet-wide explicit deny.

ALB vs NLB: an ALB works at L7, so it can route on host and path, terminate TLS, and do HTTP health checks. An NLB works at L4: TCP/UDP, static IPs, very high connection counts, and it can preserve the source IP. Choose an ALB for HTTP APIs and an NLB for non-HTTP protocols or when clients need fixed IPs. AWS's examples show both at $0.0225 per hour, with ALB LCUs at $0.008 per LCU-hour and NLB NLCUs at $0.006.

CloudFront in front: it caches at the edge, terminates viewer TLS and absorbs some DDoS, but an origin still reachable directly bypasses all of that. Three ways to close the gap, from AWS's docs: VPC origins (the ALB stays in private subnets), the AWS-managed CloudFront prefix list in the ALB's security group, or a secret custom header checked by an ALB rule and rotated regularly.

Route 53: policies are simple, weighted (canary), latency, failover, geolocation, geoproximity, IP-based and multivalue answer. Health checks probe an endpoint and remove an unhealthy answer, but DNS TTLs and client caching mean failover is measured in tens of seconds at best, and it isn't instant.

Stand-in: this models stateful vs stateless behaviour on one return packet. It isn't AWS: there are no ENIs, no real rule ordering for security groups, and no connection timeouts.

ده بديل تعليمي: بيوضح الفرق بين stateful و stateless على return packet واحد. مش AWS الحقيقي: مفيش ENIs، ومفيش ترتيب rules حقيقي للـ SG، ومفيش connection timeouts.
// بديل تعليمي: بيبيّن الفرق stateful ضد stateless بس. مش AWS الحقيقي (مفيش ENI ولا ترتيب SG كامل)
type Packet = { src: string; srcPort: number; dst: string; dstPort: number };
type Rule = { cidrOrSg: string; from: number; to: number; action?: "allow" | "deny" };

const tuple = (p: Packet) => `${p.src}:${p.srcPort}>${p.dst}:${p.dstPort}`;
const reverse = (p: Packet) => `${p.dst}:${p.dstPort}>${p.src}:${p.srcPort}`;

class SecurityGroup {
  // الجدول: الـ connections المتتبّعة، وده اللي بيخلّيها stateful
  private tracked = new Set<string>();
  private inbound: Rule[];
  constructor(inbound: Rule[]) { this.inbound = inbound; }
  in(p: Packet) {
    const ok = this.inbound.some((r) => (r.cidrOrSg === p.src || r.cidrOrSg === "any") && p.dstPort >= r.from && p.dstPort <= r.to);
    if (ok) this.tracked.add(tuple(p));
    return ok ? "ALLOW" : "DROP";
  }
  // الرد: لو الـ tuple متتبّع يعدّي، من غير ما نبص على أي outbound rule
  out(p: Packet) {
    return this.tracked.has(reverse(p)) ? "ALLOW (tracked)" : "DROP";
  }
}

class Nacl {
  private inbound: Rule[];
  private outbound: Rule[];
  constructor(inbound: Rule[], outbound: Rule[]) { this.inbound = inbound; this.outbound = outbound; }
  // الترتيب: أول rule تطابق هي اللي بتتطبق، وفي الآخر deny ضمني
  private match(rules: Rule[], port: number) {
    const r = rules.find((x) => port >= x.from && port <= x.to);
    return r?.action === "allow" ? "ALLOW" : "DROP";
  }
  in(p: Packet) { return this.match(this.inbound, p.dstPort); }
  out(p: Packet) { return this.match(this.outbound, p.dstPort); }
}

Part 3 — Least privilege by hand 🟡 Intermediateالجزء 3 — الـ least privilege بإيدك

English

A policy has three levers: Action (the exact API calls), Resource (the exact ARNs), and Condition (the context: tags, region, prefix). Note that s3:ListBucket applies to the bucket ARN while s3:GetObject applies to the object ARN, so scoping a list needs a Condition on s3:prefix. For per-tenant isolation, a policy variable such as ${aws:PrincipalTag/tenant_id} ties the prefix to a session tag that your backend sets when it assumes the role, so the tenant never comes from client input. The evaluation rule from lesson 35 stays: explicit deny beats allow, and no match is an implicit deny.

On ECS there are two roles, and mixing them up is common. The task execution role is used by the ECS agent to pull the image, write logs and fetch injected secrets. The task role is what your application code gets through the SDK, for S3, SQS and so on. AWS recommends a separate task role per service with the minimum permissions. An SDK inside the task uses the task role's credentials exclusively.

Treat policies as code: a CI script rejects "Action": "*", service wildcards, NotAction with Allow, and escalation actions like iam:PassRole on any resource. IAM Access Analyzer does this properly in the cloud: it validates policies, finds external access, and can generate a policy from CloudTrail history.

Stand-in: the evaluator extends the one from lesson 35 with Conditions and policy variables. It isn't IAM: no SCPs, permission boundaries, session policies or resource policies.

type Ctx = Record<string, string>;
type Condition = Record<string, Record<string, string | string[]>>;
type Statement = { Sid: string; Effect: "Allow" | "Deny"; Action: string[]; Resource: string[]; Condition?: Condition };
export type Policy = { Statement: Statement[] };

const glob = (pattern: string, value: string) =>
  new RegExp("^" + pattern.split("*").map((p) => p.replace(/[.+?^${}()|[\]\\]/g, "\\$&")).join(".*") + "$").test(value);

// الاستبدال: المتغير زي aws:PrincipalTag بيتحل من الـ context، ولو ناقص الـ statement مش بيطابق
const subst = (s: string, ctx: Ctx): string | null => {
  let missing = false;
  const out = s.replace(/\$\{([^}]+)\}/g, (_, k: string) => {
    if (ctx[k] === undefined) { missing = true; return ""; }
    return ctx[k]!;
  });
  return missing ? null : out;
};

const condOk = (c: Condition | undefined, ctx: Ctx) =>
  Object.entries(c ?? {}).every(([op, keys]) =>
    Object.entries(keys).every(([key, want]) => {
      const actual = ctx[key];
      const wants = [want].flat().map((w) => subst(w, ctx)).filter((w): w is string => w !== null);
      // الـ negated operators: لو الـ key مش موجود الشرط بيتحقق، زي IAM الحقيقي
      if (op === "StringNotEquals") return actual === undefined || !wants.includes(actual);
      if (actual === undefined) return false;
      if (op === "StringEquals") return wants.includes(actual);
      if (op === "StringLike") return wants.some((w) => glob(w, actual));
      throw new Error(`stand-in does not implement ${op}`);
    }),
  );

const applies = (s: Statement, action: string, resource: string, ctx: Ctx) =>
  s.Action.some((a) => glob(a, action)) &&
  s.Resource.some((r) => { const v = subst(r, ctx); return v !== null && glob(v, resource); }) &&
  condOk(s.Condition, ctx);

export function evaluate(policies: Policy[], action: string, resource: string, ctx: Ctx) {
  const hits = policies.flatMap((p) => p.Statement).filter((s) => applies(s, action, resource, ctx));
  const deny = hits.find((s) => s.Effect === "Deny");
  if (deny) return `DENY (explicit: ${deny.Sid})`;
  const allow = hits.find((s) => s.Effect === "Allow");
  if (allow) return `ALLOW (${allow.Sid})`;
  return "DENY (implicit)";
}

type Statement = {
  Sid?: string; Effect: "Allow" | "Deny";
  Action?: string | string[]; NotAction?: string | string[];
  Resource?: string | string[]; NotResource?: string | string[];
  Condition?: unknown;
};
type Finding = { policy: string; sid: string; severity: "HIGH" | "MEDIUM"; why: string };

const list = (v?: string | string[]) => (v === undefined ? [] : [v].flat());

// القايمة دي actions معروفة إنها بتطلّع صلاحيات أعلى لو الـ Resource مفتوح
const ESCALATION = ["iam:PassRole", "iam:CreatePolicyVersion", "iam:AttachRolePolicy", "sts:AssumeRole"];

export function audit(name: string, doc: { Statement: Statement[] }): Finding[] {
  const out: Finding[] = [];
  for (const s of doc.Statement) {
    if (s.Effect !== "Allow") continue;
    const sid = s.Sid ?? "(no Sid)";
    const actions = list(s.Action);
    const resources = list(s.Resource);
    const add = (severity: Finding["severity"], why: string) => out.push({ policy: name, sid, severity, why });

    if (actions.includes("*")) add("HIGH", 'Action is "*"');
    for (const a of actions) if (a !== "*" && a.endsWith(":*")) add("HIGH", `service wildcard ${a}`);
    if (s.NotAction) add("HIGH", "Allow with NotAction grants everything else");
    if (resources.includes("*") && !s.Condition) add("MEDIUM", 'Resource is "*" with no Condition');
    for (const a of actions) {
      if (ESCALATION.includes(a) && resources.includes("*")) add("HIGH", `${a} on any resource: privilege escalation`);
    }
  }
  return out;
}

Part 4 — Secrets Manager, Parameter Store, KMS 🟡 Intermediateالجزء 4 — الـ Secrets Manager والـ Parameter Store والـ KMS

English

The general method for keys and rotation is in lesson 19, so this part is about which AWS service and what it costs. Secrets Manager stores secrets with built-in rotation hooks, at $0.40 per secret per month plus $0.05 per 10,000 API calls (from AWS's pricing examples, read 2026-11-09). Parameter Store standard parameters have no storage charge; advanced parameters are $0.05 each per month, and API calls cost $0.05 per 10,000 for higher throughput or advanced parameters. KMS isn't a secret store: it holds keys that never leave it and performs encrypt, decrypt and data-key operations, at $1 per key per month plus $0.03 per 10,000 symmetric requests, with 20,000 requests free each month.

Choose by need: rotating database credentials → Secrets Manager. Plain config and a few secrets with no rotation → Parameter Store. Encrypting your own data → KMS with envelope encryption, covered in section 12, lesson 38.

Delivery has two shapes. ECS injection puts the value in an environment variable at container start. AWS's docs are explicit: if the secret is later rotated, the container doesn't get the new value, and you must launch a new task or force a new deployment. Anything in the container, including debugging tools, can read that variable. SDK with a TTL cache picks up rotation within the TTL, at the price of a dependency at runtime and some code. On an authentication failure (28P01 from Postgres), invalidate the cache and retry once, so a rotation doesn't wait out the TTL.

// بديل تعليمي: store في الذاكرة بدل Secrets Manager، عشان نعدّ الـ API calls ونشوف الـ rotation
class FakeSecretsStore {
  calls = 0;
  private value = "db-password-v1-not-real";
  get() { this.calls++; return this.value; }
  rotate(next: string) { this.value = next; }
}

class SecretCache {
  private cached?: { value: string; at: number };
  private store: FakeSecretsStore;
  private ttlMs: number;
  private now: () => number;
  constructor(store: FakeSecretsStore, ttlMs: number, now: () => number) {
    this.store = store; this.ttlMs = ttlMs; this.now = now;
  }
  get() {
    if (!this.cached || this.now() - this.cached.at >= this.ttlMs) {
      this.cached = { value: this.store.get(), at: this.now() };
    }
    return this.cached.value;
  }
  // الرد على 28P01: امسح الـ cache فورًا عشان المحاولة الجاية تجيب القيمة الجديدة
  invalidate() { this.cached = undefined; }
}

English

CloudWatch has four pieces: logs (log groups and streams), metrics (a namespace, a name and dimensions), alarms (a threshold on a metric that triggers an action), and dashboards. Metrics can be sent cheaply with Embedded Metric Format: a JSON log line with an _aws block that CloudWatch turns into metrics, so you skip PutMetricData calls. Below is a real line from aws-embedded-metrics with AWS_EMF_ENVIRONMENT=Local. The library's README lists stdout as the path for Lambda and the CloudWatch agent for ECS and EC2, so check how your platform forwards these lines; that part wasn't run here.

Prices from AWS's N. Virginia examples, read 2026-11-09: custom metrics $0.30 per metric per month for the first 10,000, then $0.10 up to 250,000 and $0.05 beyond, prorated by the hour; log ingestion $0.50 per GB (Standard) or $0.25 (Infrequent Access); archived logs $0.03 per GB-month; standard alarms $0.10 per metric; the first 3 custom dashboards are free (the per-dashboard price didn't load through my fetch, so check the page).

Two traps. First, AWS's own words: "CloudWatch treats each unique combination of dimensions as a separate metric." Put userId in a dimension and you multiply your metric count by your user count; put it in a property instead, and it stays searchable in Logs Insights for no metric cost. Second, a log group's default retention is never expire, so storage grows forever unless you set it. Alarms should page on a sustained condition (for example 3 of 5 datapoints), with treat_missing_data chosen on purpose: no requests means no errors, not "unknown".

  const names = new Set(sgs.map((s) => s.name));
  for (const sg of sgs) {
    for (const r of sg.ingress) {
      const edge = `${r.from}->${sg.name}:${r.port}`;
      if (r.from === "0.0.0.0/0") errors.push(`${edge}  open to the internet`);
      else if (!allowed.has(edge)) errors.push(`${edge}  not in the allowed edges`);
      if (r.from.endsWith("-sg") && !names.has(r.from)) errors.push(`${edge}  references unknown group`);
    }
  }
  // الاكتمال: لازم كل edge متوقع يكون موجود، وإلا الـ app مش هيوصل للـ DB
  for (const edge of allowed) {
    const [from, rest] = edge.split("->");
    const [to, port] = rest!.split(":");
    const sg = sgs.find((s) => s.name === to);
    if (!sg?.ingress.some((r) => r.from === from && r.port === Number(port))) errors.push(`${edge}  missing`);
  }
  return errors;
}

Solution · الحل 
type ResourceStatement = { Sid?: string; Effect: "Allow" | "Deny"; Principal: unknown; Condition?: unknown };

// الفحص: ⁦Principal "*"⁩ من غير Condition معناها أي حد على الإنترنت
export function publicStatements(doc: { Statement: ResourceStatement[] }) {
  return doc.Statement.filter((s) => {
    if (s.Effect !== "Allow" || s.Condition) return false;
    const p = s.Principal;
    if (p === "*") return true;
    return typeof p === "object" && p !== null && [(p as { AWS?: unknown }).AWS].flat().includes("*");
  }).map((s) => s.Sid ?? "(no Sid)");
}

  Statement: [

  ],
};

Cheat sheet · الخلاصة

  • Three tiers across AZs: public (ALB, NAT), app (default route to NAT), data (no default route). Size the app tier for doubled tasks.
  • NAT is $0.045/hour plus $0.045/GB in AWS's Ohio example. S3 and DynamoDB gateway endpoints are free; interface endpoints have a break-even.
  • Security groups are stateful; NACLs are stateless and need outbound ephemeral ports. Use SG-to-SG rules, not CIDRs.
  • ALB for L7 HTTP, NLB for L4 and fixed IPs. Lock the ALB to CloudFront. DNS failover is bounded by TTLs.
  • Policies: exact actions, exact ARNs, conditions. ListBucket needs the bucket ARN and an s3:prefix condition.
  • Execution role is for ECS; task role is for your code. One task role per service, and audit for * in CI.
  • Secrets Manager $0.40 per secret, Parameter Store standard free, KMS $1 per key. Cache reads; API calls are the trap.
  • Injected secrets don't update until a new task. SDK with TTL does, and invalidate on 28P01.
  • Each unique dimension combination is a billed metric at $0.30. Identifiers go in properties.
  • Log ingestion is $0.50/GB and retention defaults to never expire: set it on day one.
  • Keep allowed security-group edges as data and test both directions: nothing extra, nothing missing.
