Why this matters · ليه ده مهم

English

Backend systems are full of graphs that nobody calls graphs: packages that depend on packages, roles that inherit from roles, users who referred users, orders that move between states, products bought together, shelves a picker walks around. Running BFS on them is the easy part, and section 03 and section 05 · 2.5 already cover it.

The senior decision is the representation. In this lesson it decides whether a 10⁶-node graph takes 44 MB, 192 MB or 125 GB, whether an edge lookup costs 13 ns or 5 ms, whether a worker thread gets the graph in 0.2 ms or 18 ms, and whether the graph belongs in process memory at all or in a Postgres table. Every one of those numbers was measured on this machine.

بالعامية

الـ backend مليان graphs محدش بيسميها graphs: packages بتعتمد على packages، roles بتورث من roles، users جابوا users، orders بتتنقل بين states، منتجات بتتشري مع بعض، ورفوف الـ picker بيلف حواليها في المخزن. إنك تشغّل BFS عليهم ده الجزء السهل، والقسم 03 والقسم 05 · 2.5 شرحوه خلاص.

قرار السنيور هو الـ representation، يعني إزاي تخزّن الـ graph. في الدرس ده القرار ده هو اللي بيحدد إن graph فيه مليون node ياخد 44 MB ولا 192 MB ولا 125 GB، وإن السؤال "فيه edge بين دول؟" ياخد 13 ns ولا 5 ms، وإن الـ worker thread يستلم الـ graph في 0.2 ms ولا 18 ms، وهل الـ graph أصلًا مكانه في الـ memory بتاعة الـ process ولا في جدول Postgres. وكل رقم من دول اتقاس على الجهاز ده.

Part 1 — Three representations, one interface 🟡 Intermediateالجزء 1 — تلات تمثيلات ورا interface واحد

English

The vocabulary (directed, weighted, sparse, dense) is in section 03 · Graphs, part 1. Here we build the representations as code you can test and measure, behind one contract:

  • Graph<N> has addEdge(u, v), hasEdge(u, v), neighbors(u), degree(u) and edgeCount.
  • It is a simple directed graph: adding an edge that already exists is a no-op and returns false. Self-loops are allowed. Index-based implementations throw RangeError for a vertex outside [0, n).

The contract is not decoration. A matrix collapses duplicate edges by itself, while a list happily stores the same neighbour twice. Without a written rule, the same input gives two different degrees, and BFS does extra work on one of them. One shared test suite runs against every implementation and makes the difference impossible to miss.

The five implementations:

  • MapGraph<N>: Map<N, N[]>. Any key type (SKU strings, UUIDs). It grows on demand, but every node pays for a Map entry plus an array object.
  • ListGraph: number[][] over vertices 0..n-1. This is what you get after you map IDs to dense integers once.
  • BitMatrixGraph: n² bits in a Uint32Array, each row padded to whole 32-bit words. hasEdge is one AND. neighbors scans n / 32 words and pulls out set bits with w & -w and Math.clz32.
  • WeightedMatrixGraph: a Float32Array of n × n weights, where Infinity means "no edge". That is 4 bytes per pair, for dense tables such as distances.
  • EdgeListGraph: two parallel Int32Arrays, src and dst. It is the shape of a CSV export or an edges table: great for storage, for loading and as input to Kruskal or to CSR (part 3). It is terrible for queries: hasEdge and neighbors scan all E edges.

// تمثيلات الـ graph كلها ورا interface واحد، عشان الـ tests والـ benchmark يبقوا واحد
// العقد: directed graph بسيط، يعني إضافة edge موجودة قبل كده مبتعملش حاجة وبترجع false
export interface Graph<N = number> {
  addEdge(u: N, v: N): boolean;
  hasEdge(u: N, v: N): boolean;
  neighbors(u: N): Iterable<N>;
  degree(u: N): number;
  readonly edgeCount: number;
}

// (1) الـ adjacency list بـ Map: الـ nodes أي نوع (SKU، userId)، وبتكبر لوحدها
export class MapGraph<N> implements Graph<N> {
  #adj = new Map<N, N[]>();
  #edges = 0;
  get edgeCount(): number { return this.#edges; }
  addEdge(u: N, v: N): boolean {
    let out = this.#adj.get(u);
    if (out === undefined) { out = []; this.#adj.set(u, out); }
    // الـ sink لازم يتسجل كـ node برضه، وإلا مش هيظهر في أي loop على الـ nodes
    if (!this.#adj.has(v)) this.#adj.set(v, []);
    // التكلفة هنا ⁦O(degree)⁩ عشان نمنع الـ edge المكررة
    if (out.includes(v)) return false;
    out.push(v);
    this.#edges++;
    return true;
  }
  hasEdge(u: N, v: N): boolean { return this.#adj.get(u)?.includes(v) ?? false; }
  neighbors(u: N): readonly N[] { return this.#adj.get(u) ?? []; }
  degree(u: N): number { return this.#adj.get(u)?.length ?? 0; }
  nodes(): IterableIterator<N> { return this.#adj.keys(); }
}

function checkVertex(u: number, n: number): void {
  if (!Number.isInteger(u) || u < 0 || u >= n) throw new RangeError(`vertex ${u} out of range [0, ${n})`);
}

// (2) الـ adjacency list بالـ index: الـ nodes أرقام من 0 لـ n - 1، وده اللي بتعمله بعد ما تعمل map للـ IDs
export class ListGraph implements Graph<number> {
  readonly n: number;
  #adj: number[][];
  #edges = 0;
  constructor(n: number) {
    this.n = n;
    this.#adj = Array.from({ length: n }, (): number[] => []);
  }
  get edgeCount(): number { return this.#edges; }
  addEdge(u: number, v: number): boolean {
    checkVertex(u, this.n); checkVertex(v, this.n);
    const out = this.#adj[u]!;
    if (out.includes(v)) return false;
    out.push(v);
    this.#edges++;
    return true;
  }
  hasEdge(u: number, v: number): boolean { checkVertex(u, this.n); return this.#adj[u]!.includes(v); }
  neighbors(u: number): readonly number[] { checkVertex(u, this.n); return this.#adj[u]!; }
  degree(u: number): number { checkVertex(u, this.n); return this.#adj[u]!.length; }
}
// (3) الـ adjacency matrix كـ bitset: كل خانة bit واحدة، وكل صف متقرّب لمضاعفات الـ 32 bit
export class BitMatrixGraph implements Graph<number> {
  readonly n: number;
  readonly wordsPerRow: number;
  #bits: Uint32Array;
  #edges = 0;
  constructor(n: number) {
    const words = Math.ceil(n / 32) * n;
    // الحماية: n² bits لازم تتحسب قبل ما تعمل allocate، مش بعد ما الـ process يقع
    if (words > 2 ** 28) throw new RangeError(`a ${n}×${n} bit matrix needs ${(words * 4 / 1e9).toFixed(1)} GB`);
    this.n = n;
    this.wordsPerRow = Math.ceil(n / 32);
    this.#bits = new Uint32Array(words);
  }
  get edgeCount(): number { return this.#edges; }
  get byteLength(): number { return this.#bits.byteLength; }
  addEdge(u: number, v: number): boolean {
    checkVertex(u, this.n); checkVertex(v, this.n);
    const i = u * this.wordsPerRow + (v >>> 5), mask = 1 << (v & 31);
    if ((this.#bits[i]! & mask) !== 0) return false;
    this.#bits[i]! |= mask;
    this.#edges++;
    return true;
  }
  hasEdge(u: number, v: number): boolean {
    checkVertex(u, this.n); checkVertex(v, this.n);
    return (this.#bits[u * this.wordsPerRow + (v >>> 5)]! & (1 << (v & 31))) !== 0;
  }
  // الجيران: بنلف على الـ words بتاعة الصف، ونطلّع الـ bits اللي قيمتها 1 بس، فالتكلفة ⁦O(V / 32)⁩
  *neighbors(u: number): Generator<number> {
    checkVertex(u, this.n);
    const start = u * this.wordsPerRow;
    for (let w = 0; w < this.wordsPerRow; w++) {
      let word = this.#bits[start + w]!;
      while (word !== 0) {
        const low = word & -word;
        yield (w << 5) + (31 - Math.clz32(low));
        word ^= low;
      }
    }
  }
  degree(u: number): number {
    let d = 0;
    for (const _ of this.neighbors(u)) d++;
    return d;
  }
}

// (4) الـ weighted matrix: جدول مسافات كامل (dense)، والـ Infinity معناها مفيش طريق
export class WeightedMatrixGraph implements Graph<number> {
  readonly n: number;
  #w: Float32Array;
  #edges = 0;
  constructor(n: number) {
    this.n = n;
    this.#w = new Float32Array(n * n).fill(Infinity);
  }
  get edgeCount(): number { return this.#edges; }
  get byteLength(): number { return this.#w.byteLength; }
  setWeight(u: number, v: number, w: number): void {
    checkVertex(u, this.n); checkVertex(v, this.n);
    if (this.#w[u * this.n + v] === Infinity && w !== Infinity) this.#edges++;
    this.#w[u * this.n + v] = w;
  }
  weight(u: number, v: number): number { checkVertex(u, this.n); checkVertex(v, this.n); return this.#w[u * this.n + v]!; }
  addEdge(u: number, v: number): boolean {
    if (this.hasEdge(u, v)) return false;
    this.setWeight(u, v, 1);
    return true;
  }
  hasEdge(u: number, v: number): boolean { return this.weight(u, v) !== Infinity; }
  *neighbors(u: number): Generator<number> {
    checkVertex(u, this.n);
    for (let v = 0, row = u * this.n; v < this.n; v++) if (this.#w[row + v] !== Infinity) yield v;
  }
  degree(u: number): number { let d = 0; for (const _ of this.neighbors(u)) d++; return d; }
}
// (5) الـ edge list: مصفوفتين متوازيتين، الـ edge رقم i رايحة من ⁦src[i]⁩ لـ ⁦dst[i]⁩، زي جدول edges في الـ DB أو ملف CSV
export class EdgeListGraph implements Graph<number> {
  readonly n: number;
  #src: Int32Array;
  #dst: Int32Array;
  #len = 0;
  constructor(n: number, capacity = 16) {
    this.n = n;
    this.#src = new Int32Array(capacity);
    this.#dst = new Int32Array(capacity);
  }
  // البناء السريع من arrays جاهزة ومن غير تكرار: ده الاستخدام الطبيعي للـ edge list
  static fromArrays(n: number, src: Int32Array, dst: Int32Array): EdgeListGraph {
    const g = new EdgeListGraph(n, Math.max(src.length, 1));
    g.#src.set(src); g.#dst.set(dst); g.#len = src.length;
    return g;
  }
  get edgeCount(): number { return this.#len; }
  get sources(): Int32Array { return this.#src.subarray(0, this.#len); }
  get targets(): Int32Array { return this.#dst.subarray(0, this.#len); }
  addEdge(u: number, v: number): boolean {
    checkVertex(u, this.n); checkVertex(v, this.n);
    // التكلفة: منع التكرار هنا ⁦O(E)⁩، عشان كده الـ edge list مش معمولة للـ queries
    if (this.hasEdge(u, v)) return false;
    if (this.#len === this.#src.length) {
      const grow = (a: Int32Array) => { const b = new Int32Array(a.length * 2); b.set(a); return b; };
      this.#src = grow(this.#src); this.#dst = grow(this.#dst);
    }
    this.#src[this.#len] = u; this.#dst[this.#len] = v; this.#len++;
    return true;
  }
  hasEdge(u: number, v: number): boolean {
    for (let i = 0; i < this.#len; i++) if (this.#src[i] === u && this.#dst[i] === v) return true;
    return false;
  }
  *neighbors(u: number): Generator<number> {
    checkVertex(u, this.n);
    for (let i = 0; i < this.#len; i++) if (this.#src[i] === u) yield this.#dst[i]!;
  }
  degree(u: number): number { let d = 0; for (let i = 0; i < this.#len; i++) if (this.#src[i] === u) d++; return d; }
}
بالعامية

المصطلحات (directed، weighted، sparse، dense) موجودة في القسم 03 · Graphs، الجزء 1. هنا بنبني التمثيلات ككود تقدر تختبره وتقيسه، وكلهم ورا عقد واحد:

  • الـ Graph<N> فيه addEdge(u, v) وhasEdge(u, v) وneighbors(u) وdegree(u) وedgeCount.
  • هو directed graph بسيط: لو ضفت edge موجودة قبل كده مفيش حاجة بتحصل وبترجع false. الـ self-loop مسموح. والتمثيلات اللي بالـ index بترمي RangeError لأي vertex برّه [0, n).

العقد ده مش رفاهية. الـ matrix بتلم الـ edges المكررة لوحدها، لكن الـ list بتخزن نفس الجار مرتين عادي. من غير قاعدة مكتوبة، نفس الـ input هيدّيك degree مختلف في كل تمثيل، والـ BFS هيشتغل شغل زيادة في واحد فيهم. عشان كده عندنا test suite واحدة بتتشغّل على كل التمثيلات، وأي اختلاف بيبان على طول.

التمثيلات الخمسة:

  • MapGraph<N>: Map<N, N[]>. أي نوع key (SKU strings، UUIDs) وبتكبر لوحدها، بس كل node بتدفع تمن Map entry و array object.
  • ListGraph: number[][] على vertices من 0 لـ n-1. ده اللي بتوصله بعد ما تعمل map للـ IDs لأرقام متتالية مرة واحدة.
  • BitMatrixGraph: n² bit في Uint32Array، وكل صف متقرّب لـ words كاملة من 32 bit. الـ hasEdge عملية AND واحدة. والـ neighbors بتلف على n / 32 word وبتطلّع الـ bits اللي قيمتها 1 بـ w & -w وMath.clz32.
  • WeightedMatrixGraph: Float32Array فيها n × n وزن، والـ Infinity معناها مفيش edge. يعني 4 bytes لكل زوج، وده للجداول الـ dense زي المسافات.
  • EdgeListGraph: اتنين Int32Array جنب بعض، src وdst. ده شكل الـ CSV export أو جدول edges: ممتاز للتخزين وللتحميل وكـ input لـ Kruskal أو للـ CSR (الجزء 3). بس وحش جدًا للأسئلة: hasEdge وneighbors بيلفوا على الـ E edges كلهم.
فين هستخدمه في شغلي؟ service بيعمل "اتشرى معاه" من جدول order_items: بتسحب الأزواج (product_id، product_id) كـ edge list من Postgres، بتعمل map للـ UUIDs لأرقام 0..n-1 بـ Map<string, number> مرة واحدة، وبعدين تبني number[][] أو CSR. وفي الـ code review: لو لقيت Map<string, Set<string>> لمليون منتج جوه الـ API process، اسأل "إنتوا محتاجين string keys في الـ hot path ولا الـ mapping مرة واحدة كفاية؟" والجزء 2 فيه الأرقام اللي تسند السؤال.

The shared suite: every implementation runs the same tests, including a model-based test against a plain Set of "u>v" strings with a seeded generator.

الـ suite المشتركة: كل تمثيل بيعدّي على نفس الـ tests، ومنهم model-based test بيقارن بـ Set عادي فيه strings بالشكل "u>v"، والأرقام العشوائية جاية من generator بـ seed ثابت.
import { describe, test } from 'node:test';
import assert from 'node:assert/strict';
import { BitMatrixGraph, EdgeListGraph, ListGraph, MapGraph, WeightedMatrixGraph, type Graph } from './graph.ts';
import { mulberry32 } from './rng.ts';

// الفكرة: suite واحدة بتتشغّل على كل التمثيلات، فأي اختلاف في السلوك يبان على طول
const impls: Record<string, (n: number) => Graph<number>> = {
  'MapGraph': () => new MapGraph<number>(),
  'ListGraph': (n) => new ListGraph(n),
  'BitMatrixGraph': (n) => new BitMatrixGraph(n),
  'WeightedMatrixGraph': (n) => new WeightedMatrixGraph(n),
  'EdgeListGraph': (n) => new EdgeListGraph(n),
};
const sorted = (it: Iterable<number>) => [...it].sort((a, b) => a - b);

for (const [name, make] of Object.entries(impls)) {
  describe(name, () => {
    test('edges are directed', () => {
      const g = make(4);
      g.addEdge(0, 1);
      assert.equal(g.hasEdge(0, 1), true);
      assert.equal(g.hasEdge(1, 0), false);
    });
    test('a duplicate edge is a no-op', () => {
      const g = make(4);
      assert.equal(g.addEdge(2, 3), true);
      assert.equal(g.addEdge(2, 3), false);
      assert.equal(g.degree(2), 1);
      assert.equal(g.edgeCount, 1);
    });
    test('self-loops are allowed', () => {
      const g = make(3);
      g.addEdge(1, 1);
      assert.deepEqual(sorted(g.neighbors(1)), [1]);
    });
    test('a vertex with no edges has no neighbours', () => {
      const g = make(3);
      assert.deepEqual([...g.neighbors(2)], []);
      assert.equal(g.degree(2), 0);
    });
    test('works across the 32-bit word boundary', () => {
      const g = make(70);
      for (const v of [0, 31, 32, 63, 64, 69]) g.addEdge(5, v);
      assert.deepEqual(sorted(g.neighbors(5)), [0, 31, 32, 63, 64, 69]);
    });
    // الـ model-based test: عمليات عشوائية بـ seed ثابت، ونقارن بـ Set من الـ "u>v" كمرجع بسيط
    test('matches a Set-of-pairs model on 2,000 random edges', () => {
      const n = 60, rand = mulberry32(11), g = make(n), model = new Set<string>();
      for (let i = 0; i < 2_000; i++) {
        const u = Math.floor(rand() * n), v = Math.floor(rand() * n);
        assert.equal(g.addEdge(u, v), !model.has(`${u}>${v}`));
        model.add(`${u}>${v}`);
      }
      assert.equal(g.edgeCount, model.size);
      for (let u = 0; u < n; u++) {
        const expected = [...model].filter((k) => k.startsWith(`${u}>`)).map((k) => Number(k.split('>')[1]));
        assert.deepEqual(sorted(g.neighbors(u)), expected.sort((a, b) => a - b));
        for (let v = 0; v < n; v++) assert.equal(g.hasEdge(u, v), model.has(`${u}>${v}`));
      }
    });
  });
}

Trade-off: an idempotent addEdge has a price Checking for a duplicate costs O(degree) in a list and O(E) in an edge list, so building a 10⁷-edge edge list through addEdge would be O(E²). Bulk loaders skip the check when the input is already deduplicated (EdgeListGraph.fromArrays, CSR.fromEdges): dedupe once at the source (SELECT DISTINCT, or sort and drop repeats), not on every insert.

The workload is a random sparse "also bought" graph: every product points at 10 other products, so E = 10V, built from the seeded generator so every run sees the same graph. For each representation and size we measure five things: retained memory per edge (heapOf, with --expose-gc), build time from the edge arrays, hasEdge on 100,000 queries where half are real edges, a walk over every neighbour of every node (ns per edge), and one full BFS from node 0 as the realistic workload. The BFS itself is section 03 · Graphs, part 2 and section 05 · 2.5. Here it is only the thing we time.

Two representations have hard limits. The bit matrix is capped at 10⁴ nodes: at 10⁵ it would need 1.25 GB and at 10⁶ it would need 10¹² bits = 125 GB, a number the constructor computes and refuses instead of letting the process die. The library row, graphology 0.26 (a widely used JS graph library), stops at 10⁵ because it stores every node and edge as an object. // الـ BFS نفسه متشرح في القسم 03 والقسم 05، هنا هو بس الـ workload اللي بنقيس بيه
function bfsReached(g: Ops, v: number, start: number): number {
  const seen = new Uint8Array(v), queue = new Int32Array(v);
  let head = 0, tail = 0;
  seen[start] = 1; queue[tail++] = start;
  while (head < tail) {
    g.forEachNeighbor(queue[head++]!, (w) => { if (!seen[w]) { seen[w] = 1; queue[tail++] = w; } });
  }
  return tail;
}
const ms = (f: () => unknown): [number, unknown] => { const t = performance.now(); const r = f(); return [performance.now() - t, r]; };
const median = (xs: number[]) => xs.sort((a, b) => a - b)[xs.length >> 1]!;
// التوقيت: warm-up الأول، وبعدين نكرر لحد 30ms على الأقل، والنتيجة median لـ 3 قياسات
function perRun(f: () => unknown): number {
  f();
  const one = () => { let runs = 0; const t = performance.now(); do { f(); runs++; } while (performance.now() - t < 30); return (performance.now() - t) / runs; };
  return median([one(), one(), one()]);
}

  • hasEdge. The matrix is O(1): 5 ns at 10³ and 13 ns at 10⁴.   • Neighbours. Lists walk exactly the real neighbours: 3–15 ns per edge for number[][] from 10³ to 10⁶, against 3–42 ns for Map up to 10⁵ and 60 ns at 10⁶. The matrix scans a whole row whatever the degree: at 10⁴ that is 313 words to find 10 neighbours, so 135 ns per edge.

  • Build. At 10⁶, Map takes 2.5 s against 226 ms for number[][]: a million hashed inserts plus rehashing as the table grows.

Part 3 — CSR in typed arrays 🔴 Advancedالجزء 3 — الـ CSR في typed arrays

English

Compressed Sparse Row stores a whole graph in two or three flat typed arrays. targets (Int32Array, length E) holds every edge's destination, grouped by source. offsets (Int32Array, length V + 1) says where each source's group starts, so the neighbours of u are targets[offsets[u] .. offsets[u + 1]). An optional weights (Float32Array, length E) is parallel to targets. There is no array object per node, no pointer per edge and no hash table, which comes to 4(V + 1) + 4E bytes: 4.4 bytes per edge when E = 10V.

It is built from an edge list in two passes, which is a counting sort by source: (1) count the out-degree of each node, (2) turn the counts into start positions with an exclusive prefix sum (prefix sums are section 05 · 1.6), (3) walk the edges again and drop each target into its row with a moving cursor. All three passes are O(V + E) and allocate nothing per edge.

neighbors(u) returns targets.subarray(...), a zero-copy view on the same memory. That view is still a small object, so a hot loop should iterate the index range directly. The benchmark below shows the difference.

// الـ CSR: الجيران بتوع كل node ورا بعض في array واحدة، والـ offsets بتقولك كل node بتبدأ فين
// الجيران بتوع u هما targets من ⁦offsets[u]⁩ لحد ⁦offsets[u + 1] (⁩من غير الأخير)
export class CSR {
  readonly n: number;
  readonly offsets: Int32Array;
  readonly targets: Int32Array;
  readonly weights: Float32Array | undefined;
  private constructor(n: number, offsets: Int32Array, targets: Int32Array, weights?: Float32Array) {
    this.n = n; this.offsets = offsets; this.targets = targets; this.weights = weights;
  }

  // البناء على مرحلتين من ⁦edge list: (1)⁩ عدّ الـ degrees، ⁦(2) prefix sum⁩، (3) املا الأماكن
  // الـ alloc اختياري: تقدر تدّيله SharedArrayBuffer عشان الـ workers يقروا من غير نسخ
  static fromEdges(
    n: number, src: Int32Array, dst: Int32Array, w?: Float32Array,
    alloc: (bytes: number) => ArrayBufferLike = (b) => new ArrayBuffer(b),
  ): CSR {
    const e = src.length;
    if (dst.length !== e || (w && w.length !== e)) throw new RangeError('src, dst and weights must have the same length');
    const offsets = new Int32Array(alloc(4 * (n + 1)));
    for (let i = 0; i < e; i++) {
      const u = src[i]!;
      if (u < 0 || u >= n || dst[i]! < 0 || dst[i]! >= n) throw new RangeError(`edge ${i} leaves [0, ${n})`);
      offsets[u + 1]!++;
    }
    // الـ ⁦prefix sum: offsets[u + 1]⁩ بقت = مجموع الـ degrees لحد u
    for (let u = 0; u < n; u++) offsets[u + 1]! += offsets[u]!;
    const targets = new Int32Array(alloc(4 * e));
    const weights = w ? new Float32Array(alloc(4 * e)) : undefined;
    const cursor = offsets.slice(0, n);
    for (let i = 0; i < e; i++) {
      const slot = cursor[src[i]!]!++;
      targets[slot] = dst[i]!;
      if (weights) weights[slot] = w![i]!;
    }
    return new CSR(n, offsets, targets, weights);
  }

  // لو عندك الـ arrays جاهزة (مثلًا جاية من worker أو من ملف)، بنلفّها من غير نسخ
  static wrap(n: number, offsets: Int32Array, targets: Int32Array, weights?: Float32Array): CSR {
    if (offsets.length !== n + 1 || offsets[n] !== targets.length) throw new RangeError('offsets do not match targets');
    return new CSR(n, offsets, targets, weights);
  }

  get edgeCount(): number { return this.targets.length; }
  degree(u: number): number { return this.offsets[u + 1]! - this.offsets[u]!; }
  // الجيران كـ view على نفس الذاكرة: zero-copy، بس كل نداء بيعمل object صغير جديد
  neighbors(u: number): Int32Array { return this.targets.subarray(this.offsets[u]!, this.offsets[u + 1]!); }
  hasEdge(u: number, v: number): boolean {
    for (let i = this.offsets[u]!, end = this.offsets[u + 1]!; i < end; i++) if (this.targets[i] === v) return true;
    return false;
  }
  get byteLength(): number {
    return this.offsets.byteLength + this.targets.byteLength + (this.weights?.byteLength ?? 0);
  }
}

function bfsList(adj: number[][], start: number): number {
  const seen = new Uint8Array(adj.length), queue = new Int32Array(adj.length);
  let head = 0, tail = 0;
  seen[start] = 1; queue[tail++] = start;
  while (head < tail) {
    for (const w of adj[queue[head++]!]!) if (!seen[w]) { seen[w] = 1; queue[tail++] = w; }
  }
  return tail;
}
// الـ BFS على الـ CSR بالـ index مباشرة: مفيش ولا object بيتعمل جوه الـ loop
function bfsCSR(g: CSR, start: number): number {
  const { offsets, targets } = g, seen = new Uint8Array(g.n), queue = new Int32Array(g.n);
  let head = 0, tail = 0;
  seen[start] = 1; queue[tail++] = start;
  while (head < tail) {
    const u = queue[head++]!;
    for (let i = offsets[u]!, end = offsets[u + 1]!; i < end; i++) {
      const w = targets[i]!;
      if (!seen[w]) { seen[w] = 1; queue[tail++] = w; }
    }
  }
  return tail;
}
// نفس الـ BFS بس بـ ⁦neighbors()⁩ اللي بترجع subarray: view جديد لكل node
function bfsCSRViews(g: CSR, start: number): number {
  const seen = new Uint8Array(g.n), queue = new Int32Array(g.n);
  let head = 0, tail = 0;
  seen[start] = 1; queue[tail++] = start;
  while (head < tail) {
    for (const w of g.neighbors(queue[head++]!)) if (!seen[w]) { seen[w] = 1; queue[tail++] = w; }
  }
  return tail;
}

English

At 10⁶ nodes and 10⁷ edges: 44 MB instead of 192 MB (4.4× less), built ≈4× faster, and BFS ≈1.8× faster (≈137 against ≈246 ms) with the same O(V + E). The win is memory layout: one contiguous array instead of a million small arrays scattered over the heap, so fewer cache misses. Creating a subarray view per node gives back about a fifth of the gain (≈163 ms). Two limits apply. Int32 offsets overflow past 2³¹ − 1 ≈ 2.1 billion edges, where you switch the offsets to a Float64Array (exact up to 2⁵³; not run here at that size). And the structure is immutable.

Updates therefore go to a small overlay: new edges sit in a Map<number, number[]>, neighbors yields the base row and then the overlay, and once the overlay passes 5% of E the whole thing is rebuilt in O(V + E). Removals would need a tombstone set in the same overlay. This is the memtable + immutable runs + compaction idea of LSM trees, which is lesson 14.

// الـ CSR ثابت (immutable)، فالتعديلات بتتحط في overlay صغير، وكل فترة بنعمل rebuild
export class OverlayCSR {
  #base: CSR;
  #added = new Map<number, number[]>();
  #addedCount = 0;
  readonly rebuildRatio: number;
  constructor(base: CSR, rebuildRatio = 0.05) { this.#base = base; this.rebuildRatio = rebuildRatio; }
  get base(): CSR { return this.#base; }
  get pending(): number { return this.#addedCount; }
  addEdge(u: number, v: number): boolean {
    const n = this.#base.n;
    if (u < 0 || u >= n || v < 0 || v >= n) throw new RangeError(`edge ${u}→${v} leaves [0, ${n})`);
    if (this.hasEdge(u, v)) return false;
    let out = this.#added.get(u);
    if (!out) { out = []; this.#added.set(u, out); }
    out.push(v);
    // القاعدة: لما الـ overlay يعدّي 5% من الـ edges نعمل rebuild في ⁦O(V + E)⁩ مرة واحدة
    if (++this.#addedCount > this.rebuildRatio * this.#base.edgeCount) this.rebuild();
    return true;
  }
  hasEdge(u: number, v: number): boolean {
    return this.#base.hasEdge(u, v) || (this.#added.get(u)?.includes(v) ?? false);
  }
  *neighbors(u: number): Generator<number> {
    yield* this.#base.neighbors(u);
    const extra = this.#added.get(u);
    if (extra) yield* extra;
  }
  rebuild(): void {
    const b = this.#base, e = b.edgeCount + this.#addedCount;
    const src = new Int32Array(e), dst = new Int32Array(e);
    let k = 0;
    for (let u = 0; u < b.n; u++) {
      for (let i = b.offsets[u]!; i < b.offsets[u + 1]!; i++) { src[k] = u; dst[k++] = b.targets[i]!; }
      for (const v of this.#added.get(u) ?? []) { src[k] = u; dst[k++] = v; }
    }
    this.#base = CSR.fromEdges(b.n, src, dst);
    this.#added.clear();
    this.#addedCount = 0;
  }
}

Flat buffers also cross threads cheaply. An analytics job (top products by in-degree, reachability) can run in a worker_thread while the main thread keeps serving requests. There are three ways to hand it the 44 MB: postMessage copies it with structured clone; a transfer list moves ownership, so the main thread's buffers are detached and read as 0 bytes; a SharedArrayBuffer lets both threads read the same memory. Sharing is safe here because the CSR is immutable. Mutating shared memory needs Atomics and is a different lesson: section 06 · worker threads, part 2.

async function send(mode: 'copy' | 'transfer' | 'shared'): Promise<void> {
  // كل mode ليه CSR جديد: الـ transfer بيفضّي الـ buffer عند الـ main thread
  const alloc = mode === 'shared' ? (b: number) => new SharedArrayBuffer(b) : (b: number) => new ArrayBuffer(b);
  const g = CSR.fromEdges(n, src, dst, undefined, alloc);
  const msg = { mode, n, offsets: g.offsets, targets: g.targets };
  const t0 = performance.now();
  if (mode === 'transfer') worker.postMessage(msg, [g.offsets.buffer as ArrayBuffer, g.targets.buffer as ArrayBuffer]);
  else worker.postMessage(msg);
  const [got] = await once(worker, 'message');
  const delivered = performance.now() - t0;
  const [done] = await once(worker, 'message');
  const left = (g.offsets.byteLength + g.targets.byteLength) / 1e6;
  console.log(`${mode.padEnd(8)} ${(got.bytes / 1e6).toFixed(0)} MB delivered in ≈${delivered.toFixed(1)} ms,`,
    `main thread still has ${left.toFixed(0)} MB, top also-bought ${JSON.stringify(done.top)}`);
}

بالعامية

الـ Compressed Sparse Row بيخزن الـ graph كله في 2 أو 3 typed arrays مسطحة. الـ targets (Int32Array طولها E) فيها الوجهة بتاعة كل edge، ومترتبين بالـ source. الـ offsets (Int32Array طولها V + 1) بتقولك كل source بيبدأ فين، فجيران u هما targets من offsets[u] لحد offsets[u + 1] من غير الأخير. والـ weights اختيارية (Float32Array طولها E) وماشية جنب الـ targets. مفيش array object لكل node، ولا pointer لكل edge، ولا hash table، فالحسبة 4(V + 1) + 4E byte، يعني 4.4 byte لكل edge لما E = 10V.

بيتبني من edge list على مرحلتين، وهو في الحقيقة counting sort بالـ source: (1) عدّ الـ out-degree لكل node، (2) حوّل الأعداد لأماكن بداية بـ exclusive prefix sum (الـ prefix sums في القسم 05 · 1.6)، (3) لف على الـ edges تاني وحط كل target في الصف بتاعه بـ cursor بيتحرك. التلات مراحل O(V + E) ومفيش allocation لكل edge.

الـ neighbors(u) بترجع targets.subarray(...)، يعني view على نفس الذاكرة من غير نسخ. بس الـ view ده object صغير برضه، فالـ loop السخن يلف على الـ index range مباشرة، والـ benchmark فوق بيوريك الفرق.

على مليون node و 10 مليون edge: ‏44 MB بدل 192 MB (أقل 4.4 مرة)، والبناء أسرع ≈4 مرات، والـ BFS أسرع ≈1.8 مرة (≈137 قصاد ≈246 ms) بنفس الـ O(V + E). المكسب من شكل الذاكرة: array واحدة متصلة بدل مليون array صغيرة متفرقة في الـ heap، فالـ cache misses أقل. وعمل subarray view لكل node بياكل حوالي خُمس المكسب (≈163 ms). وفيه حدّين: الـ offsets اللي Int32 بتعمل overflow بعد 2³¹ − 1 يعني ≈2.1 مليار edge، وساعتها تحوّل الـ offsets لـ Float64Array (دقيقة لحد 2⁵³، ومتجربتش هنا على الحجم ده). والتاني إن الـ structure ثابتة (immutable).

عشان كده التعديلات بتروح على overlay صغير: الـ edges الجديدة في Map<number, number[]>، والـ neighbors بيطلّع صف الـ base وبعده الـ overlay، ولما الـ overlay يعدّي 5% من E بنعمل rebuild للكل في O(V + E). ولو عايز تشيل edges هتحتاج tombstone set في نفس الـ overlay. ودي نفس فكرة الـ memtable والـ immutable runs والـ compaction في الـ LSM trees، وهي الدرس 14.

والـ buffers المسطحة بتعدّي بين الـ threads بسهولة. job تحليلات (أكتر المنتجات اللي عليها edges داخلة، الـ reachability) ممكن يشتغل في worker_thread والـ main thread مكمّل يخدم requests. فيه 3 طرق تدّيله الـ 44 MB: الـ postMessage العادي بينسخها بالـ structured clone، والـ transfer list بتنقل الملكية فالـ buffers عند الـ main thread بتتفضّى وتبان 0 bytes، والـ SharedArrayBuffer بيخلّي الاتنين يقروا نفس الذاكرة. المشاركة هنا آمنة عشان الـ CSR ثابت. لو هتعدّل في ذاكرة مشتركة محتاج Atomics وده موضوع تاني: القسم 06 · worker threads، الجزء 2.

فين هستخدمه في شغلي؟ job بالليل بيبني "اتشرى معاه" من orders آخر 90 يوم: COPY ... TO STDOUT من Postgres ← edge list ← CSR.fromEdges على SharedArrayBuffer ← worker بيحسب الـ top-N لكل منتج والـ API thread شغال عادي. والـ edges اللي بتيجي خلال اليوم (orders جديدة) تروح في الـ overlay، والـ rebuild يحصل لما تعدّي الـ 5% أو مع job الليل. وفي الـ code review: لو حد بيعمل postMessage(graph) لـ Map كبيرة كل request، ده structured clone لكل الـ objects كل مرة.
What breaks: sharing memory you still mutate A SharedArrayBuffer is only safe to read without locks if nobody writes to it. If the main thread runs rebuild() into the same buffers while a worker is mid-BFS, the worker reads half-old, half-new rows and returns wrong answers with no error. Build the new CSR into new buffers, then post the new buffers and let the old ones be collected.

English

Many graphs are never stored at all. The edges come from a rule: a function moves(state) returns the [event, nextState] pairs you can take from a state. Search only touches what it visits, so memory is O(visited), not O(V + E). That matters because the full graph can be huge or infinite. Below is one generic BFS for that shape, shortestPath(start, isGoal, moves, key). The BFS itself is section 05 · 2.5; what is new here is that neighbours are computed on demand and that you choose the key used for the visited set.

  1. The order workflow. The states are pending → paid → packed → shipped → delivered, plus cancel and refund edges. The rules table is the graph, and next(state, event) is the edge function. A support tool can ask for the shortest event path ("how do I get this order to refunded?") or prove that something cannot happen (delivered is unreachable from refunded).
  2. A warehouse grid for picker routing. The neighbours of a cell come from its coordinates and the blocked cells (shelves). The visited key should be the number y * width + x, not the string "x,y".
  3. Cart states in a promo engine, as the warning. A state is the quantity of every product in the cart plus the coupons applied, so the state count multiplies with every product you add.

// الـ implicit graph: مفيش edges متخزنة، فيه function بتقولك "من هنا أروح فين"
// الـ BFS نفسه هو نفس اللي في القسم 05، اللي جديد هنا إن الجيران بتتحسب وقت الطلب
export function shortestPath<S, E, K>(
  start: S,
  isGoal: (s: S) => boolean,
  moves: (s: S) => Iterable<[E, S]>,
  key: (s: S) => K,
): E[] | null {
  // الـ visited هنا Map من الـ key للخطوة اللي جابتنا: الذاكرة ⁦O(⁩اللي اتزار) مش ⁦O(V + E)⁩
  const cameFrom = new Map<K, { prev: S; via: E } | null>([[key(start), null]]);
  let frontier: S[] = [start];
  while (frontier.length > 0) {
    const nextFrontier: S[] = [];
    for (const s of frontier) {
      if (isGoal(s)) {
        const path: E[] = [];
        for (let step = cameFrom.get(key(s)); step; step = cameFrom.get(key(step.prev))) path.push(step.via);
        return path.reverse();
      }
      for (const [via, t] of moves(s)) {
        const k = key(t);
        if (!cameFrom.has(k)) { cameFrom.set(k, { prev: s, via }); nextFrontier.push(t); }
      }
    }
    frontier = nextFrontier;
  }
  return null;
}

export type Grid = { width: number; height: number; blocked: Uint8Array };
export function* gridMoves(g: Grid, cell: number): Generator<[string, number]> {
  const x = cell % g.width, y = (cell - x) / g.width;
  if (x > 0 && !g.blocked[cell - 1]) yield ['W', cell - 1];
  if (x < g.width - 1 && !g.blocked[cell + 1]) yield ['E', cell + 1];
  if (y > 0 && !g.blocked[cell - g.width]) yield ['N', cell - g.width];
  if (y < g.height - 1 && !g.blocked[cell + g.width]) yield ['S', cell + g.width];
}

// ❌ الـ visited بـ ⁦string "x,y"⁩: كل خانة بتعمل string جديدة وبتتعمل لها hash
function bfsStringKeys(): Set<string> {
  const seen = new Set<string>(['0,0']);
  const queue: [number, number][] = [[0, 0]];
  for (let head = 0; head < queue.length; head++) {
    const [x, y] = queue[head]!;
    for (let d = 0; d < 4; d++) {
      const nx = x + DX[d]!, ny = y + DY[d]!;
      if (nx < 0 || ny < 0 || nx >= W || ny >= H || blocked[ny * W + nx]) continue;
      const k = `${nx},${ny}`;
      if (!seen.has(k)) { seen.add(k); queue.push([nx, ny]); }
    }
  }
  return seen;
}
// ✅ الـ visited بـ رقم y * W + x في ⁦Set<number>⁩: الذاكرة لسه ⁦O(⁩اللي اتزار)
function bfsNumberKeys(): Set<number> {
  const seen = new Set<number>([0]);
  const queue = new Int32Array(W * H);
  let head = 0, tail = 0;
  queue[tail++] = 0;
  while (head < tail) {
    const c = queue[head++]!, x = c % W, y = (c - x) / W;
    for (let d = 0; d < 4; d++) {
      const nx = x + DX[d]!, ny = y + DY[d]!;
      if (nx < 0 || ny < 0 || nx >= W || ny >= H) continue;
      const k = ny * W + nx;
      if (!blocked[k] && !seen.has(k)) { seen.add(k); queue[tail++] = k; }
    }
  }
  return seen;
}

// التشغيل: node --max-old-space-size=4000 src/cart-explosion.ts
// الـ promo engine: الـ ⁦state =⁩ كمية كل منتج في الـ ⁦cart (⁩من 0 لـ ⁦3) +⁩ الكوبونات المتطبقة
// الحركات: زوّد قطعة، شيل قطعة، طبّق أو شيل كوبون. السؤال: الـ graph ده حجمه كام؟
const COUPONS = 3, MAX_QTY = 3;

function reachableCartStates(items: number): { states: number; ms: number } {
  const t = performance.now();
  // الـ key: الكميات كأرقام في base 4، وبعدها bits الكوبونات
  const seen = new Set<number>([0]);
  let frontier = [0];
  while (frontier.length > 0) {
    const next: number[] = [];
    for (const s of frontier) {
      const coupons = s % (1 << COUPONS);
      const qtyCode = (s - coupons) / (1 << COUPONS);
      const moves: number[] = [];
      for (let i = 0, place = 1; i < items; i++, place *= MAX_QTY + 1) {
        const q = Math.floor(qtyCode / place) % (MAX_QTY + 1);
        if (q < MAX_QTY) moves.push((qtyCode + place) * (1 << COUPONS) + coupons);
        if (q > 0) moves.push((qtyCode - place) * (1 << COUPONS) + coupons);
      }
      for (let c = 0; c < COUPONS; c++) moves.push(qtyCode * (1 << COUPONS) + (coupons ^ (1 << c)));
      for (const m of moves) if (!seen.has(m)) { seen.add(m); next.push(m); }
    }
    frontier = next;
  }
  return { states: seen.size, ms: performance.now() - t };
}

export function workspaceGraph(dir: string): { deps: Map<string, string[]>; dependents: Map<string, string[]> } {
  const pkgs = readdirSync(dir).map((d) => JSON.parse(readFileSync(join(dir, d, 'package.json'), 'utf8')) as Pkg);
  const local = new Set(pkgs.map((p) => p.name));

    // بناخد الـ dependencies اللي جوه الـ workspace بس، الـ npm packages مش nodes هنا

      dependents.get(d)!.push(p.name);
    }
  }
  return { deps, dependents };
}

// الـ build order بـ ⁦Kahn (⁩متشرح في القسم 05): اللي فاضل في الآخر يا في cycle يا بيعتمد على cycle
export function buildOrder(deps: Map<string, string[]>): { order: string[]; stuck: string[] } {
  const pending = new Map([...deps].map(([p, ds]) => [p, ds.length]));
  const dependents = new Map<string, string[]>([...deps.keys()].map((p) => [p, []]));
  for (const [p, ds] of deps) for (const d of ds) dependents.get(d)!.push(p);
  const order = [...pending].filter(([, n]) => n === 0).map(([p]) => p);
  // الـ order نفسها هي الـ queue: بنمشي عليها بـ index بدل ⁦shift()⁩
  for (let i = 0; i < order.length; i++) {
    for (const q of dependents.get(order[i]!)!) {
      const left = pending.get(q)! - 1;
      pending.set(q, left);
      if (left === 0) order.push(q);
    }
  }
  return { order, stuck: [...pending].filter(([, n]) => n > 0).map(([p]) => p) };
}

// الأثر: كل اللي بيعتمد على package معيّن بشكل مباشر أو غير مباشر (BFS على الـ reverse edges)
export function affectedBy(dependents: Map<string, string[]>, changed: string): string[] {
  const seen = new Set([changed]), queue = [changed];
  for (let i = 0; i < queue.length; i++) {
    for (const p of dependents.get(queue[i]!) ?? []) if (!seen.has(p)) { seen.add(p); queue.push(p); }
  }
  return queue.slice(1);
}

(2) Permissions inheritance. Roles inherit from parent roles. A role can have two parents (support-lead inherits from support and from accountant), so it is a DAG, not a tree. The check can(roles, 'invoice:refund') is on the hot path of every request. Without a memo it is a DFS over all ancestors. With a memo, each role's effective permission set (its own plus everything inherited) is computed once, and a check becomes one Set lookup. The price is invalidation: granting a permission to a role must drop the memo of that role and of every descendant, which is a BFS over the child edges. So again you store both directions. addRole refuses unknown parents, which makes a cycle impossible to build.

// الـ roles بتورث من parent roles: ده DAG (role ممكن يورث من اتنين، ومفيش cycles)
export class RoleGraph {
  #parents = new Map<string, string[]>();
  // الـ reverse edges: لازمين عشان لما role يتغير نعرف مين ورث منه ونمسح الـ memo بتاعه
  #children = new Map<string, string[]>();
  #grants = new Map<string, Set<string>>();
  #memo = new Map<string, ReadonlySet<string>>();
  readonly useMemo: boolean;
  constructor({ memo = true } = {}) { this.useMemo = memo; }

  addRole(role: string, parents: string[] = [], grants: string[] = []): void {
    if (this.#parents.has(role)) throw new Error(`role ${role} exists`);
    for (const p of parents) if (!this.#parents.has(p)) throw new Error(`unknown parent ${p}`);
    // الأب لازم يكون موجود قبل الابن، فمستحيل نعمل cycle بـ addRole
    this.#parents.set(role, parents);
    this.#children.set(role, []);
    for (const p of parents) this.#children.get(p)!.push(role);
    this.#grants.set(role, new Set(grants));
  }

  grant(role: string, permission: string): number {
    this.#grants.get(role)!.add(permission);
    return this.#invalidate(role);
  }

  // من غير memo: DFS على كل الأجداد لحد ما نلاقي الـ permission، التكلفة ⁦O(⁩عدد الأجداد)
  #search(role: string, permission: string): boolean {
    const seen = new Set([role]), stack = [role];
    while (stack.length) {
      const r = stack.pop()!;
      if (this.#grants.get(r)!.has(permission)) return true;
      for (const p of this.#parents.get(r)!) if (!seen.has(p)) { seen.add(p); stack.push(p); }
    }
    return false;
  }

  // بالـ memo: الـ permissions الفعلية لكل role بتتحسب مرة واحدة (بتاعته + اللي ورثها)
  effective(role: string): ReadonlySet<string> {
    const hit = this.#memo.get(role);
    if (hit) return hit;
    const all = new Set(this.#grants.get(role)!);
    for (const p of this.#parents.get(role)!) for (const perm of this.effective(p)) all.add(perm);
    this.#memo.set(role, all);
    return all;
  }

  can(roles: readonly string[], permission: string): boolean {
    return roles.some((r) => (this.useMemo ? this.effective(r).has(permission) : this.#search(r, permission)));
  }

  // الـ invalidation: نمسح الـ memo بتاع الـ role وكل اللي ورثوا منه (BFS على الـ children)
  #invalidate(role: string): number {
    let dropped = 0;
    const seen = new Set([role]), queue = [role];
    for (let i = 0; i < queue.length; i++) {
      if (this.#memo.delete(queue[i]!)) dropped++;
      for (const c of this.#children.get(queue[i]!)!) if (!seen.has(c)) { seen.add(c); queue.push(c); }
    }
    return dropped;
  }
}

  IF NEW.referred_by IS NOT NULL AND EXISTS (

Both pass, both commit, and the cycle is in the table. The fix is to serialise referral edits with one transaction-scoped advisory lock, taken by a trigger that fires first (triggers of the same kind fire in alphabetical order of name). Locks are section 09 · locks.

CREATE FUNCTION lock_referral_tree() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  PERFORM pg_advisory_xact_lock(hashtext('referral-tree'));
  RETURN NEW;
END $$;

بالعامية

تلات graphs من backends حقيقية، وكل واحد معاه الـ representation اللي اخترناه وليه.

(1) الـ dependency graph بتاع الـ packages في الـ monorepo: بيتقري من ملفات الـ package.json في الـ workspace: عشرات الـ nodes، directed، وبيتقري مرة واحدة كل build. الـ Map<string, string[]> كفاية جدًا وأي حاجة أذكى تضييع مجهود. خزّن الـ edges العكسية كمان، لأن السؤال اللي بتسأله أكتر حاجة هو "هعمل rebuild لإيه لو @shop/users اتغيرت؟"، ودي فكرة nx affected والـ filters بتاعة Turborepo. من غير الـ reverse edges كل سؤال من دول بيبقى scan كامل. الـ Kahn (القسم 05 · 2.5) بيديك ترتيب الـ build، واللي ميعرفش يرتّبه يا إما جوه cycle يا بيعتمد على cycle. هنا @shop/api واقف بس عشان فوق الـ cycle بتاع orders وnotifications. ولو عايز تسمّي الـ cycle بالظبط استخدم الـ DFS بالتلات ألوان من القسم 03، الجزء 3.

(2) وراثة الـ permissions: الـ roles بتورث من parent roles، والـ role ممكن يبقى ليه أبين (الـ support-lead بيورث من support ومن accountant)، فده DAG مش tree. الـ check ‏can(roles, 'invoice:refund') بيتنفذ في كل request. من غير memo هو DFS على كل الأجداد. بالـ memo، الـ permissions الفعلية لكل role (بتاعته واللي ورثه) بتتحسب مرة، والـ check بقى lookup واحد في Set. التمن هو الـ invalidation: لما تدّي permission لـ role لازم تمسح الـ memo بتاعه وبتاع كل اللي ورثوا منه، وده BFS على الـ edges بتاعة الأبناء، فتاني بتخزن الاتجاهين. والـ addRole بيرفض أب مش موجود، فمستحيل تبني cycle.

القياس على 10⁴ role (‏100 tenant × 100 custom role، كل واحد بيورث من 1 أو 2 من آخر 10 في نفس الـ tenant): ≈3.8 µs للـ check من غير memo، و ≈0.25 µs بالـ memo بعد ما يتملي، يعني أسرع ≈15 مرة. والـ grant على الـ root role بتاع tenant مسح الـ 100 entry بتوعه بالظبط في ≈0.31 ms. الـ memo بياخد O(عدد الـ roles × الـ permissions الفعلية)، هنا ≈10⁴ × 19.7 entry في Sets. واللي بيكسر على scale: الـ memo عايش في كل API instance، فالـ grant في pod لازم يعمل invalidation في الباقيين (Redis pub/sub، أو version number لكل tenant بيتشيك وقت القراية). وتصميم الـ authorization نفسه في القسم 06 · الـ authorization.

(3) شجرة الـ referrals في Postgres: كل user بيشاور على اللي جابه: parent pointer اسمه referred_by وعليه index، لأن كل خطوة في الـ recursion بتعمل join على العمود ده. العمولة بتمشي لفوق عدد مستويات ثابت، والتقارير بتمشي لتحت بحد للعمق. الاتنين WITH RECURSIVE، والقسم 03، الجزء 7 عرّفه؛ هنا بنضيف حاجات الـ production: حد العمق، الـ cycles، والكتابة في نفس الوقت.

الـ cycles: الـ INSERT مستحيل يعمل cycle: الـ user الجديد ملوش أولاد لسه، والـ foreign key بيجبر اللي جابه يكون موجود، والـ CHECK بيمنع إنه يجيب نفسه. لكن UPDATE من admin بيـ"صلّح" referral ممكن يعمل cycle، وساعتها الـ upline من غير depth limit مبتخلصش لحد ما statement_timeout يقتلها. الـ CYCLE clause (من Postgres 14) بيحمي ناحية القراية: بيعلّم الصف اللي رجع لـ id اتزار ويقف. وناحية الكتابة محتاجة حارس: trigger على UPDATE OF referred_by بيمشي لفوق من الـ referrer الجديد ويرفض لو قابل نفس الـ user.

والـ trigger ده لسه فيه race. في READ COMMITTED، لو transaction بتحط 300 تحت 400 وفي نفس اللحظة transaction تانية بتحط 400 تحت 300، كل واحدة بتشيك على snapshot مفيهوش تعديل التانية، فالاتنين بيعدّوا ويعملوا commit والـ cycle بيبقى في الجدول. الحل إنك تخلّي تعديلات الـ referrals تمشي واحد ورا التاني بـ advisory lock واحد على مستوى الـ transaction، وياخده trigger بيشتغل الأول (الـ triggers من نفس النوع بتشتغل بالترتيب الأبجدي لأسمائها). الـ locks في القسم 09 · الـ locks.

فين هستخدمه في شغلي؟ برنامج referrals بعمولة على 3 مستويات: الـ upline بـ depth limit جوه الـ recursive term، والـ index على referred_by (من غيره كل لفة seq scan على الجدول كله)، والـ trigger مع الـ advisory lock عشان أداة الـ admin متعملش cycle، والـ CYCLE في أي query تقارير كحزام أمان. ونفس الـ pattern لـ categories.parent_id وemployees.manager_id. وفي الـ RBAC: الـ memo للـ permissions بيوفّر µs في كل request، بس اكتب الـ invalidation عبر الـ pods قبل ما تعمل deploy مش بعد أول incident "إديته الصلاحية ومازال بياخد 403".
Interview question "How would you store a referral tree or an org chart in Postgres, query it, and keep it free of cycles?" → A parent_id column with an index. Read with WITH RECURSIVE and a depth limit in the recursive term, and add CYCLE as a safety net. Guard writes with a trigger on UPDATE OF parent_id that walks up from the new parent, plus an advisory lock (or SERIALIZABLE) so two concurrent moves can't create a cycle between them; inserts can't create one. If subtree reads dominate, consider a closure table or the ltree extension, which trade write cost for read cost.
السؤال: "هتخزّن شجرة referrals أو org chart في Postgres إزاي، وهتعمل عليها queries إزاي، وهتمنع الـ cycles إزاي؟" الإجابة: عمود parent_id عليه index. القراية بـ WITH RECURSIVE وحد للعمق جوه الـ recursive term، وCYCLE كحزام أمان. الكتابة يحرسها trigger على UPDATE OF parent_id بيمشي لفوق من الأب الجديد، ومعاه advisory lock (أو SERIALIZABLE) عشان نقلتين في نفس الوقت ميعملوش cycle بينهم؛ والـ insert مستحيل يعمل cycle. ولو قراية الـ subtrees هي الغالبة، فكّر في closure table أو extension الـ ltree، ودول بيبدّلوا تكلفة الكتابة بتكلفة القراية.

❌ A matrix for a sparse graph

بالعامية

❌ الـ matrix بتحجز n² خانة مهما كان عدد الـ edges، فـ 10⁵ user بـ 10 follows لكل واحد بيبقوا 10¹⁰ خانة (≈80 GB، رقم محسوب) عشان 10⁶ edge بس، والـ process هتقع. ✅ الـ list بتاخد على قد الـ edges الحقيقية: ≈19 byte لكل edge في number[][] و ≈4.4 في الـ CSR. الـ matrix بس للـ graphs الصغيرة الـ dense زي جدول المسافات بين المخازن.

❌ في شبكة عرضها 3 وطولها 5، الـ x * width + y بيدّي 11 key بس لـ 15 خانة: الخانة (1,0) والخانة (0,3) الاتنين key بتاعهم 3، فالـ BFS هيفتكر إنه زار خانة هو مزارهاش ويقول "مفيش طريق" لـ bin موجود. على شبكة مربعة الغلطة مش بتبان، فالـ tests بتعدّي. ✅ اضرب في مدى الإحداثية التانية: y * width + x (والـ x دايمًا أقل من width) بيدّي 15 key مختلف. الأرقام دي من src/key-collision.ts.

import { CSR } from '../src/csr.ts';

// الـ transpose: نفس الـ edges بالعكس، فالجيران بقوا "مين بيشاور عليّا⁦" (in-neighbours)⁩
export function transpose(g: CSR): CSR {
  const src = new Int32Array(g.edgeCount), dst = new Int32Array(g.edgeCount);
  for (let u = 0, k = 0; u < g.n; u++) {
    for (let i = g.offsets[u]!; i < g.offsets[u + 1]!; i++, k++) { src[k] = g.targets[i]!; dst[k] = u; }
  }
  // نفس البناء على مرحلتين: count ثم prefix sum ثم fill، يعني ⁦O(V + E)⁩
  return CSR.fromEdges(g.n, src, dst);
}

// الـ lint للـ workflow: أي state مش قادرة توصل لـ state نهائية ⁦= order⁩ هيفضل عالق للأبد
export function deadEnds<S extends string, E extends string>(rules: Record<S, Partial<Record<E, S>>>): S[] {
  const states = Object.keys(rules) as S[];
  const terminal = states.filter((s) => Object.keys(rules[s]).length === 0);
  // الـ reverse graph: لكل state مين بيوصلها، وبعدين BFS من الـ terminals
  const into = new Map<S, S[]>(states.map((s) => [s, []]));
  for (const s of states) for (const t of Object.values(rules[s]) as S[]) into.get(t)?.push(s);
  const ok = new Set<S>(terminal), queue = [...terminal];
  for (let i = 0; i < queue.length; i++) for (const p of into.get(queue[i]!) ?? []) if (!ok.has(p)) { ok.add(p); queue.push(p); }
  return states.filter((s) => !ok.has(s));
}

Cheat sheet · الخلاصة

  • One Graph interface, one shared test suite. Write the contract down: duplicates are no-ops, self-loops are allowed, out-of-range vertices throw.
  • Adjacency list: O(V + E) space, O(degree) hasEdge; ≈19 bytes per edge as number[][], ≈21–23 as Map<number, number[]>.
  • Matrix: O(1) hasEdge but O(V²) space and O(V) per neighbour scan. Use it only for small dense graphs (200 warehouses: 160 KB, ≈11 ns, against 2.8 MB and ≈118 ns for a string-keyed Map).
  • Edge list: 8 bytes per edge, O(E) per query. Use it for storage, loading, Kruskal and building CSR.
  • CSR = offsets (V + 1) + targets (E) + optional weights, built by count → prefix sum → fill. At 10⁶ nodes: 44 MB against 192 MB and BFS ≈137 against ≈246 ms.
  • CSR is immutable: add edges to an overlay and rebuild at ≈5%. Share it with workers through SharedArrayBuffer (≈0.2 ms) or a transfer list (≈1 ms) instead of a copy (≈17 ms for 44 MB).
  • Big-O hides memory: list hasEdge went from 23 ns to 203 ns between 10³ and 10⁶ with the same O(degree).
  • Implicit graph = moves(state); memory is O(visited). Key cells as y * width + x, never "x,y" (≈3× slower) and never x * width + y (collides).
  • State spaces explode: 4k × 8 cart states means 8.4M at 10 products. Don't enumerate; use rules, DP or limits.
  • Small graphs at work: Map<string, string[]> plus reverse edges (affected builds, RBAC invalidation). A memo on role inheritance gives ≈15× faster checks but needs cross-instance invalidation.
  • Trees in Postgres: parent pointer + index, WITH RECURSIVE with a depth limit, CYCLE on reads, and a trigger plus an advisory lock on writes.
