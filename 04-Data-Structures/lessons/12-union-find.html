Why this matters · ليه ده مهم

English

Union-Find answers two questions as links arrive one by one: "are these two in the same group?" and "merge these two groups". Both take near-constant time. That covers duplicate customer accounts, fraud rings that share devices and cards, network partitions, Kruskal's minimum spanning tree and regions in a grid. It cannot split a group and it cannot tell you how two items are connected. Knowing those limits, and the offline trick that works around the first one, is part of using it well.

In production the 50-line structure is the easy part. On 10⁶ accounts in this lesson, the Union-Find took ≈5–8% of the job. The rest was normalising emails and phone numbers and hashing identifiers, and the result was wrong until a junk placeholder phone shared by 1,504 accounts was blocklisted.

Part 1 — UnionFind<K> 🟡 Intermediateالجزء 1 — UnionFind<K> من الصفر

English

The idea (each group is a tree of parent pointers, the root is the representative, and Kruskal uses it to reject edges that would close a cycle) is in section 03 · Graphs, part 6, and Kruskal itself is section 05 · 2.7. Here we build the production version:

  • Generic keys. A Map<K, number> turns account IDs, emails or any other key into dense indices once. Everything after that is integer work on two Int32Arrays, parent and size, which double when full, as in lesson 02.
  • find is iterative, with full path compression: one loop finds the root, a second loop points every node on the path straight at it. No recursion, so no stack limit (part 2 shows the recursive version crashing).
  • Union by size hangs the smaller tree under the larger, which keeps height ≤ log₂ n. The README says rank. Rank (an upper bound on height) gives the same O(log n) guarantee and the same α(n) bound with compression. Size is more useful in practice: sizeOf becomes free, and part 5 alerts on it. mnemonist uses rank.
  • count is the number of components, decremented only when a union really merges two roots.

The edge cases are design decisions, so decide them once, write them down and test them:

// الـ Union-Find generic: الـ keys أي نوع (accountId، "e:sara@mail.com")، وجوّه كله أرقام في typed arrays
export class UnionFind<K> {
  #index = new Map<K, number>();
  #keys: K[] = [];
  #parent: Int32Array;
  #size: Int32Array;
  #components = 0;

  constructor(capacity = 16) {
    this.#parent = new Int32Array(Math.max(1, capacity));
    this.#size = new Int32Array(Math.max(1, capacity));
  }

  // عدد الـ ⁦components (⁩المجموعات) دلوقتي
  get count(): number { return this.#components; }
  // عدد العناصر كلها
  get length(): number { return this.#keys.length; }
  has(key: K): boolean { return this.#index.has(key); }

  // القرار: add و union بيضيفوا الـ key لو جديد، لأن الـ entities بتظهر مع الـ edges نفسها
  add(key: K): number {
    const known = this.#index.get(key);
    if (known !== undefined) return known;
    const i = this.#keys.length;
    if (i === this.#parent.length) this.#grow();
    this.#index.set(key, i);
    this.#keys.push(key);
    this.#parent[i] = i;
    this.#size[i] = 1;
    this.#components++;
    return i;
  }

  // القرار: find و sizeOf على key مش موجود بيرموا error، لأن ده غالبًا bug في الـ caller
  find(key: K): K { return this.#keys[this.#root(this.#need(key))]!; }
  sizeOf(key: K): number { return this.#size[this.#root(this.#need(key))]!; }

  // القرار: connected على key مش موجود بترجع ⁦false (⁩مش مربوط بحاجة)، ومبتضيفوش
  connected(a: K, b: K): boolean {
    const ia = this.#index.get(a), ib = this.#index.get(b);
    if (ia === undefined || ib === undefined) return false;
    return this.#root(ia) === this.#root(ib);
  }

  // بترجع true لو دمجت مجموعتين، و false لو كانوا أصلًا مع بعض (أو a هو b)
  union(a: K, b: K): boolean {
    let ra = this.#root(this.add(a)), rb = this.#root(this.add(b));
    if (ra === rb) return false;
    // الـ union by size: الشجرة الصغيرة تتعلق تحت الكبيرة، فالارتفاع عمره ما يعدّي ⁦log2(n)⁩
    if (this.#size[ra]! < this.#size[rb]!) [ra, rb] = [rb, ra];
    this.#parent[rb] = ra;
    this.#size[ra]! += this.#size[rb]!;
    this.#components--;
    return true;
  }

  // المجموعات كلها: الـ ⁦representative →⁩ كل الـ keys اللي معاه
  groups(): Map<K, K[]> {
    const out = new Map<K, K[]>();
    for (let i = 0; i < this.#keys.length; i++) {
      const rep = this.#keys[this.#root(i)]!;
      let g = out.get(rep);
      if (!g) { g = []; out.set(rep, g); }
      g.push(this.#keys[i]!);
    }
    return out;
  }

  // الـ find iterative: لفة توصل للـ root، ولفة تانية تخلّي كل اللي في الطريق يشاور عليه (full path compression)
  #root(i: number): number {
    const parent = this.#parent;
    let root = i;
    while (parent[root] !== root) root = parent[root]!;
    while (parent[i] !== root) { const next = parent[i]!; parent[i] = root; i = next; }
    return root;
  }
  #need(key: K): number {
    const i = this.#index.get(key);
    if (i === undefined) throw new RangeError(`unknown key: ${String(key)}`);
    return i;
  }
  #grow(): void {
    const grow = (a: Int32Array) => { const b = new Int32Array(a.length * 2); b.set(a); return b; };
    this.#parent = grow(this.#parent);
    this.#size = grow(this.#size);
  }
}

الفكرة نفسها (كل مجموعة شجرة parent pointers، والـ root هو الممثل بتاعها، و Kruskal بيستخدمها عشان يرفض الـ edge اللي هتقفل cycle) موجودة في القسم 03، الجزء 6، و Kruskal نفسه في القسم 05 · 2.7. هنا بنبني نسخة الـ production:

  • الـ keys generic: ‏Map<K, number> بتحوّل الـ account IDs أو الإيميلات أو أي key لـ indices متتالية مرة واحدة. وكل اللي بعد كده شغل أرقام على Int32Array اتنين، parent وsize، وبيتضاعفوا لما يتملوا زي الدرس 02.
  • الـ find iterative بـ full path compression: لفة بتوصل للـ root، ولفة تانية بتخلّي كل node في الطريق تشاور عليه على طول. مفيش recursion، فمفيش حد للـ stack (الجزء 2 بيوري النسخة الـ recursive وهي بتقع).
  • الـ union by size: بيعلّق الشجرة الصغيرة تحت الكبيرة، فالارتفاع بيفضل ≤ log₂ n. الـ README بيقول rank. الـ rank (حد أعلى للارتفاع) بيدّي نفس ضمان الـ O(log n) ونفس حد الـ α(n) مع الـ compression. بس الـ size أفيد عمليًا: الـ sizeOf بيبقى ببلاش، والجزء 5 بيعمل alert عليه. والـ mnemonist بيستخدم rank.
  • الـ count هو عدد الـ components، وبيقل بس لما الـ union يدمج rootين مختلفين فعلًا.

الـ edge cases دي قرارات design، فاخدها مرة واكتبها واختبرها (الجدول فوق).

فين هستخدمه في شغلي؟ job الـ dedupe بالليل (الجزء 4) بيعمل UnionFind<number> على الـ account IDs. والـ API بتاع الـ checkout بيسأل connected(newAccount, flaggedAccount) قبل ما يدّي promo "أول طلب": الحساب الجديد خالص مش موجود في الـ structure، فـ false هي الإجابة الصح، مش exception توقّع الـ checkout. ولو حد في الـ review كتب find على حساب جديد من غير has، الـ RangeError هنا بتكشف الـ bug في الـ staging مش بعدين.

If a hot loop does millions of unions, map IDs to indices once and keep the indices.

Part 2 — Four variants, measured 🟡 Intermediateالجزء 2 — أربع variants بالقياس

English

Four ways to write the same structure, each counting the hops (parent pointers followed) in every find, so we can see path length and not only time: naive (always hang a's root under b's root, no compression), union by size only, path compression only in two flavours (full: two passes; halving: one pass, parent[x] = parent[parent[x]], every node jumps to its grandparent), and both. Path halving is popular because it needs one loop and no second walk, and it keeps the same α(n) bound when combined with union by size or rank.

// أربع variants على الأرقام من 0 لحد n - 1، وكل واحدة بتعدّ الـ ⁦hops (⁩خطوات الـ parent) عشان نقيس طول الطريق
export abstract class CountingUF {
  readonly parent: Int32Array;
  hops = 0;
  maxHops = 0;
  constructor(n: number) {
    this.parent = new Int32Array(n);
    for (let i = 0; i < n; i++) this.parent[i] = i;
  }
  abstract find(x: number): number;
  abstract union(a: number, b: number): boolean;
  protected count(h: number): void { this.hops += h; if (h > this.maxHops) this.maxHops = h; }
}

// (1) الساذج: من غير size ومن غير compression، الـ root بتاع a بيتعلق تحت الـ root بتاع b على طول
export class NaiveUF extends CountingUF {
  find(x: number): number {
    let h = 0;
    while (this.parent[x] !== x) { x = this.parent[x]!; h++; }
    this.count(h);
    return x;
  }
  union(a: number, b: number): boolean {
    const ra = this.find(a), rb = this.find(b);
    if (ra === rb) return false;
    this.parent[ra] = rb;
    return true;
  }
  // ❌ نفس الـ find بس recursive: كل hop بـ stack frame
  findRecursive(x: number): number {
    const p = this.parent[x]!;
    return p === x ? x : this.findRecursive(p);
  }
}

// (2) الـ union by size بس: الارتفاع ⁦≤ log2(n)⁩، والـ find من غير compression
export class SizeUF extends NaiveUF {
  readonly size: Int32Array;
  constructor(n: number) { super(n); this.size = new Int32Array(n).fill(1); }
  override union(a: number, b: number): boolean {
    let ra = this.find(a), rb = this.find(b);
    if (ra === rb) return false;
    if (this.size[ra]! < this.size[rb]!) [ra, rb] = [rb, ra];
    this.parent[rb] = ra;
    this.size[ra]! += this.size[rb]!;
    return true;
  }
}

// (3) الـ full path compression بس: لفتين، التانية بتخلّي كل اللي في الطريق يشاور على الـ root
export class CompressUF extends NaiveUF {
  override find(x: number): number {
    let root = x, h = 0;
    while (this.parent[root] !== root) { root = this.parent[root]!; h++; }
    while (this.parent[x] !== root) { const next = this.parent[x]!; this.parent[x] = root; x = next; }
    this.count(h);
    return root;
  }
}

// (3ب) الـ path halving بس: لفة واحدة، وكل node بتشاور على جدّها
export class HalvingUF extends NaiveUF {
  override find(x: number): number {
    let h = 0;
    while (this.parent[x] !== x) {
      this.parent[x] = this.parent[this.parent[x]!]!;
      x = this.parent[x]!;
      h++;
    }
    this.count(h);
    return x;
  }
}

// (4) الاتنين: union by size + path halving
export class SizeHalvingUF extends SizeUF {
  override find(x: number): number {
    let h = 0;
    while (this.parent[x] !== x) {
      this.parent[x] = this.parent[this.parent[x]!]!;
      x = this.parent[x]!;
      h++;
    }
    this.count(h);
    return x;
  }
}

// (4ب) الاتنين بالـ full compression، زي الـ ⁦UnionFind<K>⁩ بالظبط
export class SizeCompressUF extends SizeUF {
  override find(x: number): number {
    let root = x, h = 0;
    while (this.parent[root] !== root) { root = this.parent[root]!; h++; }
    while (this.parent[x] !== root) { const next = this.parent[x]!; this.parent[x] = root; x = next; }
    this.count(h);
    return root;
  }
}

function workload(kind: string, n: number): Int32Array {

    if (kind === 'chain') {

      ops[2 * k + 1] = k + 1;
    } else {
      const isUnion = k % 2 === 0;
      ops[2 * k] = isUnion ? Math.floor(rand() * n) : -1 - Math.floor(rand() * n);
      ops[2 * k + 1] = Math.floor(rand() * n);

  }

English

Tarjan's result: with union by rank (or size) and path compression, any sequence of m operations on n elements costs O(m · α(n)). That is amortized: one find can still be long, but the total is bounded, so the average per operation is O(α(n)). α is the inverse of the Ackermann function, which grows so fast that α barely moves. With the definition used in CLRS (A0(j) = j + 1, and Ak(j) applies Ak−1 to j a total of j + 1 times), α(n) is the smallest k with Ak(1) ≥ n. The values are small enough to compute:

The job: one person, many accounts. Group accounts that share an email, a phone or a card fingerprint, directly or through a chain, so promo abuse, refund fraud and "unique customers" reports work on people. The data is 10⁶ synthetic accounts from a seeded generator. 8% are planted duplicates of an older account, each sharing exactly one identifier in a messy form: the same email in different case, the same Egyptian mobile written +20…, 0020…, 0… or with spaces and dashes, the same card fingerprint, or a Gmail address without its dot.   1. Normalise with tested functions. Emails are trimmed and lowercased. Phones go to E.164 (+20 plus 10 digits starting 10, 11, 12 or 15), and anything that isn't a mobile becomes null. Removing dots in Gmail addresses is a business decision, so it is an option and off by default.

  5. Inspect: the cluster-size histogram and the biggest cluster. A giant cluster is almost always a data bug, so list the identifiers shared by suspiciously many accounts and blocklist them.

// الإيميل: trim + lowercase. شيل النقط في Gmail قرار business مش default، فبيبقى option
export function normalizeEmail(raw: string, opts: { gmailDots?: boolean } = {}): string | null {
  const email = raw.trim().toLowerCase();
  const at = email.lastIndexOf('@');
  if (at < 1 || at === email.length - 1) return null;
  let local = email.slice(0, at);
  const domain = email.slice(at + 1);
  // الـ Gmail بيتجاهل النقط في الاسم، بس ده صح لـ gmail.com و googlemail.com بس، مش لأي domain
  if (opts.gmailDots && (domain === 'gmail.com' || domain === 'googlemail.com')) local = local.replaceAll('.', '');
  return `${local}@${domain}`;
}

export function normalizePhoneEG(raw: string): string | null {
  const digits = raw.replace(/[^\d]/g, '');
  const m = /^(?:0020|20)?0?(1[0125]\d{8})$/.exec(digits);
  return m ? `+20${m[1]}` : null;
}

// المفتاح فيه نوع الـ ⁦identifier (e: / p: / c:)⁩ عشان قيمة من نوع متتلخبطش مع نوع تاني
export function identifiers(a: Account, gmailDots = false): string[] {
  const out: string[] = [];
  const email = normalizeEmail(a.email, { gmailDots });
  if (email) out.push(`e:${email}`);
  const phone = normalizePhoneEG(a.phone);
  if (phone) out.push(`p:${phone}`);
  if (a.cardFp) out.push(`c:${a.cardFp}`);
  return out;
}

export function clusterAccounts(accounts: readonly Account[], opts: { blocklist?: ReadonlySet<string>; gmailDots?: boolean } = {}) {
  const uf = new UnionFind<number>(accounts.length);
  // الـ index: لكل identifier أول حساب استخدمه، وعدد الحسابات اللي بتشاركه
  const owner = new Map<string, number>(), sharedBy = new Map<string, number>();
  for (const a of accounts) {
    uf.add(a.id);
    for (const key of identifiers(a, opts.gmailDots)) {
      if (opts.blocklist?.has(key)) continue;
      sharedBy.set(key, (sharedBy.get(key) ?? 0) + 1);
      const first = owner.get(key);
      // الـ union مع أول owner بس (star) مش مع كل اللي شاركوه ⁦(clique): k - 1 union⁩ بدل k² / 2
      if (first === undefined) owner.set(key, a.id); else uf.union(first, a.id);
    }
  }
  return { uf, sharedBy };
}

English

Union-Find keeps connected components up to date as edges arrive, at O(α) per edge, without re-running a traversal. BFS/DFS components over a stored graph are section 05 · 2.5; the difference here is incremental. count is the number of components after every link, and sizeOf is the size of any component. Read the size before and after a union and you can fire an alert exactly once, when a cluster crosses a threshold. Here the alert fires when a suspected fraud ring reaches 20 accounts, while the link stream also carries ordinary links.

// التشغيل: node src/ring-alert.ts
import { UnionFind } from './union-find.ts';

// الـ link بيوصل (حسابين شاركوا device أو كارت)، ولو المجموعة عدّت الحد لأول مرة نبعت alert
export function linkAccounts(uf: UnionFind<string>, a: string, b: string, threshold: number, alert: (rep: string, size: number) => void): void {
  const before = Math.max(uf.has(a) ? uf.sizeOf(a) : 1, uf.has(b) ? uf.sizeOf(b) : 1);
  if (!uf.union(a, b)) return;
  const after = uf.sizeOf(a);
  // التنبيه مرة واحدة بس: لما الحجم يعدّي الحد دلوقتي، مش كل ما مجموعة كبيرة تكبر
  if (before < threshold && after >= threshold) alert(uf.find(a), after);
}

Offline queries. Risk wants to know "were accounts A and B linked at time t?" for 10⁴ disputed orders, over a month of 10⁵ timestamped link events. Online, each question is a BFS over the edges with timestamp ≤ t: O(V + E) per query. Offline, when all links and all questions are known up front, sort both by time and sweep once. Apply every link up to the question's time, then answer with connected. The cost is O((E + Q) log(E + Q)) for the sorts plus O((E + Q) α) for the sweep.

import { UnionFind } from './union-find.ts';

export type Link = { t: number; a: number; b: number };
export type Query = { t: number; a: number; b: number };

// الـ offline: عارفين كل الـ links وكل الأسئلة مقدمًا، فبنرتب الاتنين بالوقت ونمشي مرة واحدة
// التكلفة: ⁦O((E + Q) log)⁩ للترتيب ⁦+ O((E + Q)⁩ α) للـ Union-Find
export function linkedAtOffline(links: readonly Link[], queries: readonly Query[]): boolean[] {
  const ls = [...links].sort((x, y) => x.t - y.t);
  const order = queries.map((_, i) => i).sort((i, j) => queries[i]!.t - queries[j]!.t);
  const uf = new UnionFind<number>(), answers = new Array<boolean>(queries.length);
  let next = 0;
  for (const qi of order) {
    const q = queries[qi]!;
    // كل link حصل لحد وقت السؤال (شاملًا نفس اللحظة) يدخل الأول
    while (next < ls.length && ls[next]!.t <= q.t) { uf.union(ls[next]!.a, ls[next]!.b); next++; }
    answers[qi] = q.a === q.b || uf.connected(q.a, q.b);
  }
  return answers;
}

// المرجع البطيء: BFS لكل سؤال على الـ edges اللي وقتها ≤ وقت السؤال، ⁦O(Q · (V + E))⁩
export function linkedAtBFS(n: number, links: readonly Link[], queries: readonly Query[]): boolean[] {
  const adj = Array.from({ length: n }, (): Link[] => []);
  for (const l of links) { adj[l.a]!.push(l); adj[l.b]!.push(l); }
  const seen = new Int32Array(n).fill(-1), queue = new Int32Array(n);
  return queries.map((q, qi) => {
    if (q.a === q.b) return true;
    let head = 0, tail = 0;
    queue[tail++] = q.a; seen[q.a] = qi;
    while (head < tail) {
      const u = queue[head++]!;
      for (const l of adj[u]!) {
        if (l.t > q.t) continue;
        const w = l.a === u ? l.b : l.a;
        if (w === q.b) return true;
        if (seen[w] !== qi) { seen[w] = qi; queue[tail++] = w; }
      }
    }
    return false;
  });
}

export type DayEvent = { kind: 'remove'; a: number; b: number } | { kind: 'ask'; a: number; b: number };
export function answerWithRemovals(startLinks: readonly [number, number][], events: readonly DayEvent[]): boolean[] {
  const key = (a: number, b: number) => (a < b ? `${a}-${b}` : `${b}-${a}`);
  const removed = new Set(events.filter((e) => e.kind === 'remove').map((e) => key(e.a, e.b)));
  const uf = new UnionFind<number>();
  for (const [a, b] of startLinks) { uf.add(a); uf.add(b); if (!removed.has(key(a, b))) uf.union(a, b); }
  const answers: boolean[] = [];
  for (let i = events.length - 1; i >= 0; i--) {
    const e = events[i]!;
    if (e.kind === 'remove') uf.union(e.a, e.b);
    else answers.push(e.a === e.b || uf.connected(e.a, e.b));
  }
  return answers.reverse();
}

الـ offline queries: فريق الـ risk عايز يعرف "الحسابين A و B كانوا مربوطين وقت t؟" لـ 10⁴ order عليهم نزاع، على شهر فيه 10⁵ link event بـ timestamp. لو online، كل سؤال BFS على الـ edges اللي وقتها ≤ t، يعني O(V + E) للسؤال. لو offline، يعني كل الـ links وكل الأسئلة معروفة من الأول، رتّب الاتنين بالوقت وامشي مرة واحدة: طبّق كل link لحد وقت السؤال، وجاوب بـ connected. التكلفة O((E + Q) log(E + Q)) للترتيب و O((E + Q) α) للـ sweep. والقياس: ≈233 ms قصاد ≈62 s، يعني ≈265 مرة، بنفس الإجابات بالظبط (ومتشيكة كمان بـ model-based test على data عشوائية).

Common mistakes · غلطات شائعة

❌ A recursive find 
// ❌ كل hop بـ stack frame
find(x: number): number {
  const p = this.parent[x]!;
  return p === x ? x : this.find(p);
}
// على chain طوله ⁦10⁵⁩:
// → RangeError: Maximum call stack size exceeded
✅ Two loops, no stack 
// ✅ لفة للـ root، ولفة تانية للـ compression
find(x: number): number {
  let root = x;
  while (this.parent[root] !== root) root = this.parent[root]!;
  while (this.parent[x] !== root) { const next = this.parent[x]!; this.parent[x] = root; x = next; }
  return root;
}
بالعامية

❌ الـ find الـ recursive شكله أنضف، بس على chain طوله 10⁵ في Node 22 وقع بـ RangeError (اتقاس في الجزء 2)، والـ chain ده بالظبط اللي بيطلع لما الـ links تيجي مترتبة بالـ id وانت من غير union by size. ✅ نفس الشغل بـ loopين، ومعاه path compression كمان، ومفيش أي حد غير الذاكرة.

import { UnionFind } from '../src/union-find.ts';

// عدد المناطق الفاضية المتصلة في شبكة المخزن: كل خانة فاضية تتوصل باللي يمينها واللي تحتها
export function freeZones(width: number, height: number, blocked: Uint8Array): number {
  const uf = new UnionFind<number>(width * height);
  for (let y = 0; y < height; y++) {
    for (let x = 0; x < width; x++) {
      const c = y * width + x;
      if (blocked[c]) continue;
      uf.add(c);
      if (x + 1 < width && !blocked[c + 1]) uf.union(c, c + 1);
      if (y + 1 < height && !blocked[c + width]) uf.union(c, c + width);
    }
  }
  return uf.count;
}

function zonesByBFS(w: number, h: number, blocked: Uint8Array): number {
  const seen = new Uint8Array(w * h), queue = new Int32Array(w * h);
  let zones = 0;
  for (let s = 0; s < w * h; s++) {
    if (blocked[s] || seen[s]) continue;
    zones++;
    let head = 0, tail = 0;
    queue[tail++] = s; seen[s] = 1;
    while (head < tail) {
      const c = queue[head++]!, x = c % w;
      for (const n of [x > 0 ? c - 1 : -1, x < w - 1 ? c + 1 : -1, c - w, c + w]) {
        if (n >= 0 && n < w * h && !blocked[n] && !seen[n]) { seen[n] = 1; queue[tail++] = n; }
      }
    }
  }
  return zones;
}

Cheat sheet · الخلاصة

  • Union-Find = Map<K, index> + parent and size Int32Arrays. Operations: find, union, connected, count, sizeOf. It cannot split groups or explain a path.
  • Decide the edge cases: a repeated or self union returns false; union auto-adds; find on an unknown key throws; connected on an unknown key returns false and adds nothing.
  • Iterative find always: the recursive one overflowed the stack at 10⁵ on Node 22.
  • Union by size (or rank) + path compression or halving: ≈0.5–0.64 average hops and max ≤ 6 from 10³ to 10⁷. Naive degrades to O(n) per find even on random input (14 → 1,112 hops).
  • O(m α(n)) amortized; α(n) ≤ 4 for any real n. Time per op still grows (≈43 → ≈221 ns) because of cache misses, not hops.
  • Generic keys cost ≈2.6× (Map lookups). Map IDs to indices once for hot loops.
  • Dedupe pipeline: normalise (lowercase email, phone to E.164; Gmail dots only by business decision) → prefixed keys (e: p: c:) → union with the first owner (star, not clique) → histogram → blocklist identifiers shared by too many accounts.
  • The structure is ≈5–8% of the dedupe time; normalising and hashing strings are the rest.
  • Postgres can do it with a recursive CTE, but the reachability rows grow with cluster size² (one junk cluster turned ≈0.4 s into ≈6.5 s). Keep it in Node unless the data must stay in the database.
  • Threshold alerts: compare size before and after a union to fire once per crossing. Size alone gives false positives.
  • Offline queries: sort links and questions by time and sweep once (≈233 ms against ≈62 s for a BFS per question). Removals only: reverse time so they become unions.
