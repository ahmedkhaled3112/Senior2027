Why this matters · ليه ده مهم

English

Every growable buffer you touch (a JS array, a Node Buffer you concatenate into, a Postgres result set, a Kafka batch) is a dynamic array with a growth policy, and every bounded buffer (the last N log lines, the last 60 seconds of latency, process.nextTick's queue) is a ring. The policy decides real numbers: how many elements get copied (1.05 per push at ×2, 499.5 per push with "+1000" at 10⁶), how big the memory spike is during a resize (3× the data at ×2), and whether a queue that drains ever gives memory back.

In this lesson you build both structures generically, prove amortized O(1) with a test instead of a whiteboard, catch the shrink thrash with a test, read Node's own FixedQueue, and ship a 60-second latency window into a Fastify app whose memory stays at ≈20 KB whether it served a thousand requests or a million.

بالعامية

كل buffer بيكبر بتلمسه (الـ JS array، والـ Buffer اللي بتلزق فيه في Node، والـ result set اللي راجع من Postgres، والـ batch بتاع Kafka) هو dynamic array ليه growth policy، وكل buffer بحجم ثابت (آخر N سطر log، آخر 60 ثانية latency، الـ queue بتاعة process.nextTick) هو ring. والـ policy دي بتحدد أرقام حقيقية: كام عنصر بيتنسخ (1.05 لكل push مع ×2، و499.5 لكل push مع "+1000" عند مليون)، والـ memory بتقفز قد إيه وقت الـ resize (3 أضعاف الـ data مع ×2)، والـ queue لما تفضى هترجّع الـ memory ولا لأ.

في الدرس ده هتبني الاتنين generic، وتثبت الـ amortized O(1) بـ test مش على السبورة، وتمسك الـ thrashing بتاع الـ shrink بـ test، وتقرا الـ FixedQueue بتاع Node نفسه، وتركّب window لآخر 60 ثانية latency في app بـ Fastify والـ memory بتاعته ≈20 KB سواء خدم ألف request أو مليون.

Part 1 — DynamicArray<T> from scratch 🟢 Basicالجزء 1 — الـ DynamicArray<T> من الصفر

English

The idea (a fixed block plus a size counter; when full, allocate a bigger block and copy) is in 03-CS lesson 03, part 2, which measured ≈1.05 copies per push at ×2 vs ≈2.43 at ×1.5. JS arrays already grow on their own, so to build an honest dynamic array the backing store must be something you never grow past its length: a Float64Array for DynamicFloat64Array (order amounts), and a fixed-length JS array for the generic DynamicArray<T>. The API is push, pop, get, set and at, with RangeError for out-of-bounds indexes, an iterator, and a copies counter so the cost is counted, not assumed. Growth and shrink policies are plain functions (shrinking is Part 4).

Two findings from measuring it. First, my first version allocated each block with Array.from({ length: n }, () => undefined) to keep it PACKED (lesson 01's rule), and DynamicArray<Job> pushes cost ≈117–149 ns versus ≈11–14 ns for Job[]. The probe below shows why: Array.from with a callback costs ≈53 ns per slot, and a resize allocates a whole block. new Array(n) costs ≈5.7 ns per slot; switching to it brought pushes to ≈17–26 ns, at the price of reads through get() going from ≈4–5 to ≈6–8 ns (the hole check). Node's own FixedCircularBuffer makes the same choice (Part 6). Lesson 01's rule is about data you fill once and scan; a container's unused capacity really is empty and is reallocated often.

Second, the bench: ns per push stays flat from 10⁵ to 10⁶ (amortized O(1)), but the worst single push grows with n, because it is the resize: copying 524,288 doubles (4 MB) into a new 8 MB block took ≈1.3 ms. Amortized O(1) is a statement about the average, not about each call.

// الـ dynamic array من الصفر: block ثابت ⁦+ size⁩، ولما يتملى نحجز block أكبر وننسخ
// الـ growth policy بتاخد الـ capacity الحالية وترجّع الجديدة
export type GrowthPolicy = (capacity: number) => number;
export const doubling: GrowthPolicy = (c) => Math.max(4, c * 2);

// الـ shrink policy بتتنادى بعد كل pop: ترجّع capacity جديدة أو undefined يعني "متصغّرش"
export type ShrinkPolicy = (size: number, capacity: number) => number | undefined;
export const neverShrink: ShrinkPolicy = () => undefined;
// ❌ الساذجة: أول ما تبقى نص مليانة صغّرها للنص، فبتبقى مليانة على الآخر وأي push بيكبّرها تاني
export const shrinkAtHalf: ShrinkPolicy = (size, cap) => (cap > 4 && size <= cap / 2 ? Math.floor(cap / 2) : undefined);
// ✅ الـ hysteresis: صغّر للنص بس لما تبقى ربع مليانة، فبعد الـ shrink هي نص مليانة: بعيدة عن الحدّين
export const shrinkAtQuarter: ShrinkPolicy = (size, cap) => (cap > 4 && size <= cap / 4 ? Math.floor(cap / 2) : undefined);

export interface Policies {
  grow?: GrowthPolicy;
  shrink?: ShrinkPolicy;
}

// النسخة الـ generic: الـ backing store هو JS array طولها ثابت، وإحنا عمرنا ما بنكتب بعد آخرها
export class DynamicArray<T> implements Iterable<T> {
  #slots: (T | undefined)[];
  #size = 0;
  #grow: GrowthPolicy;
  #shrink: ShrinkPolicy;
  copies = 0; // عدد العناصر اللي اتنسخت في كل الـ resizes، عشان نقيس مش نفترض

  constructor(capacity = 4, { grow = doubling, shrink = neverShrink }: Policies = {}) {
    if (!Number.isInteger(capacity) || capacity < 0) throw new RangeError(`capacity must be a non-negative integer, got ${capacity}`);
    this.#slots = DynamicArray.#block<T>(capacity);
    this.#grow = grow;
    this.#shrink = shrink;
  }

  // ملحوظة: هنا ⁦new Array(n)⁩ مقصودة: الـ capacity الفاضية holes فعلًا، والـ block بيتحجز مع كل resize
  // الـ ⁦Array.from({ length: n }, fn)⁩ كان أبطأ ⁦≈10⁩ مرات في الحجز (القياس تحت)، والـ HOLEY تمنه hole check في القراية
  static #block<T>(n: number): (T | undefined)[] {
    return new Array<T | undefined>(n);
  }

  get size(): number { return this.#size; }
  get capacity(): number { return this.#slots.length; }

  push(item: T): void {
    if (this.#size === this.#slots.length) {
      const capacity = this.#grow(this.#slots.length);
      // الحماية دي هي اللي بتمسك policy زي c => c * 2 لما الـ capacity تبدأ بصفر
      if (capacity <= this.#size) throw new RangeError(`growth policy returned ${capacity} for size ${this.#size}`);
      this.#resize(capacity);
    }
    this.#slots[this.#size++] = item;
  }

  pop(): T | undefined {
    if (this.#size === 0) return undefined;
    const item = this.#slots[--this.#size];
    this.#slots[this.#size] = undefined; // مهم: نسيب الـ reference عشان الـ GC يقدر يلم الـ object
    const smaller = this.#shrink(this.#size, this.#slots.length);
    if (smaller !== undefined && smaller >= this.#size && smaller < this.#slots.length) this.#resize(smaller);
    return item;
  }

  get(i: number): T {
    this.#check(i);
    return this.#slots[i] as T;
  }

  set(i: number, item: T): void {
    this.#check(i);
    this.#slots[i] = item;
  }

  // زي Array.prototype.at: الـ index السالب بيعد من الآخر، وبرّه الحدود بيرجع undefined
  at(i: number): T | undefined {
    const k = i < 0 ? this.#size + i : i;
    return k >= 0 && k < this.#size ? (this.#slots[k] as T) : undefined;
  }

  #check(i: number): void {
    if (!Number.isInteger(i) || i < 0 || i >= this.#size) throw new RangeError(`index ${i} out of bounds [0, ${this.#size})`);
  }

  #resize(capacity: number): void {
    const next = DynamicArray.#block<T>(capacity);
    for (let i = 0; i < this.#size; i++) next[i] = this.#slots[i];
    this.copies += this.#size;
    this.#slots = next;
  }

  *[Symbol.iterator](): IterableIterator<T> {
    for (let i = 0; i < this.#size; i++) yield this.#slots[i] as T;
  }
}

// النسخة الرقمية: Float64Array كـ backing store، والـ resize نسخة واحدة بـ ⁦set (memcpy)⁩
export class DynamicFloat64Array implements Iterable<number> {
  #data: Float64Array;
  #size = 0;
  #grow: GrowthPolicy;
  copies = 0;

  constructor(capacity = 4, grow: GrowthPolicy = doubling) {
    if (!Number.isInteger(capacity) || capacity < 0) throw new RangeError(`capacity must be a non-negative integer, got ${capacity}`);
    this.#data = new Float64Array(capacity);
    this.#grow = grow;
  }

  get size(): number { return this.#size; }
  get capacity(): number { return this.#data.length; }

  push(value: number): void {
    if (this.#size === this.#data.length) {
      const capacity = this.#grow(this.#data.length);
      if (capacity <= this.#size) throw new RangeError(`growth policy returned ${capacity} for size ${this.#size}`);
      const next = new Float64Array(capacity);
      next.set(this.#data.subarray(0, this.#size));
      this.copies += this.#size;
      this.#data = next;
    }
    this.#data[this.#size++] = value;
  }

  pop(): number | undefined {
    return this.#size === 0 ? undefined : this.#data[--this.#size];
  }

  get(i: number): number {
    if (!Number.isInteger(i) || i < 0 || i >= this.#size) throw new RangeError(`index ${i} out of bounds [0, ${this.#size})`);
    return this.#data[i]!;
  }

  // بيرجّع view على الجزء المستخدم بس، من غير نسخ (خلي بالك: بيتغير لو الـ array اتعملها resize)
  view(): Float64Array {
    return this.#data.subarray(0, this.#size);
  }

  *[Symbol.iterator](): IterableIterator<number> {
    for (let i = 0; i < this.#size; i++) yield this.#data[i]!;
  }
}

// الـ policy الساذجة c => c * 2 مع capacity صفر بترجع صفر: الـ resize لازم يرمي بدل ما يكتب برّه الـ block
test('capacity 0 then push: a naive ×2 policy is caught, the default policy works', () => {
  const naive: GrowthPolicy = (c) => c * 2;
  assert.throws(() => new DynamicArray<number>(0, { grow: naive }).push(1), RangeError);
  const ids = new DynamicArray<number>(0);
  ids.push(42);
  assert.deepEqual([...ids], [42]);
  assert.equal(ids.capacity, 4);
});

test('growth across several resizes keeps order and counts every copy', () => {
  const a = new DynamicArray<number>(4);
  for (let i = 0; i < 100; i++) a.push(i);
  // الـ capacities: 4 → 8 → 16 → 32 → 64 → 128، والنسخ ⁦4 + 8 + 16 + 32 + 64 = 124⁩
  assert.equal(a.capacity, 128);
  assert.equal(a.copies, 124);
  assert.deepEqual([...a], Array.from({ length: 100 }, (_, i) => i));
  const f = new DynamicFloat64Array(4);
  for (let i = 0; i < 100; i++) f.push(i + 0.5);
  assert.equal(f.copies, 124);
  assert.equal(f.get(99), 99.5);
});

test('matches a plain array under 50,000 random operations', () => {
  const rand = mulberry32(31);
  const sut = new DynamicArray<number>(0, { grow: (c) => Math.max(1, Math.ceil(c * 1.5)), shrink: shrinkAtQuarter });
  const model: number[] = [];
  for (let step = 0; step < 50_000; step++) {
    const r = rand();
    if (r < 0.55) { const v = Math.floor(rand() * 1e6); sut.push(v); model.push(v); }
    else if (r < 0.9) assert.equal(sut.pop(), model.pop(), `pop at step ${step}`);
    else if (model.length > 0) { const i = Math.floor(rand() * model.length); sut.set(i, step); model[i] = step; }
    assert.equal(sut.size, model.length);
  }
  assert.deepEqual([...sut], model);
});

Part 2 — Growth factor ×2 vs ×1.5 vs ×1.25 vs +k 🟡 Intermediateالجزء 2 — الـ growth factor: ×2 مقابل ×1.5 مقابل ×1.25 مقابل +k

English

The same DynamicFloat64Array with four policies, counting instead of guessing: total element copies, copies per push, the peak during the last resize (old and new blocks are alive together while copying: old + new divided by the data), the slack left unused at the end, and the time. With a multiplicative factor g, copies per push land between 1/(g − 1) and g/(g − 1), depending on where n falls between two resizes: 1–2 for ×2, 2–3 for ×1.5, 4–5 for ×1.25 (the table agrees: 1.02–1.31, 2.13–2.45, 4.40–4.82). An additive policy (+1000) copies 1000 + 2000 + 3000 + … ≈ n²/2000 elements: at 10⁶ that's 499,500,000 copies and ≈1.3 s versus ≈21–26 ms. The trade-off is memory: ×2 peaks at 3× the data and can leave up to 50% slack; ×1.5 peaks at 2.5×; ×1.25 at 2.25× with more resizes.

Why do some libraries prefer ≤ 1.5? With ×2 each new block is bigger than all previously freed blocks combined (16 + 32 + … + 2ᵏ⁻¹ < 2ᵏ⁺¹), so even an allocator that could merge adjacent freed blocks can never reuse them for the array. With a factor below the golden ratio (≈1.618) the freed blocks eventually add up to more than the next request. The small simulation below shows it happening at the 5th growth for ×1.5. Real allocators are more complicated, so treat this as the argument, not a measurement.

What does V8 do? Measured with %DebugPrint on Node 22.19: when a push needs length n, the new capacity is exactly n + ⌊n/2⌋ + 16 (17, 43, 82, 140, 227, … for an array built from []), so roughly ×1.5 plus a constant. And on Node 22 there is an alternative to copying: a resizable ArrayBuffer grows up to its maxByteLength and a length-tracking view follows it. The resize push at 4 MB → 8 MB took ≈28 µs versus ≈1.3 ms for copy-on-grow, consistent with no copy (the spec keeps the same buffer object; the address-space reservation is an engine detail I didn't measure directly).

// بديل على Node 22: resizable ArrayBuffer بيكبر لحد maxByteLength، والـ view اللي من غير length بيتابعه لوحده
export class ResizableFloat64Array {
  readonly maxLength: number;
  #buf: ArrayBuffer;
  #view: Float64Array;
  #size = 0;

  constructor(maxLength: number) {
    if (!Number.isInteger(maxLength) || maxLength < 1) throw new RangeError(`maxLength must be a positive integer, got ${maxLength}`);
    this.maxLength = maxLength;
    // الحد الأقصى بيتحدد هنا مرة واحدة: ده سقف حقيقي مش اقتراح
    this.#buf = new ArrayBuffer(0, { maxByteLength: maxLength * 8 });
    this.#view = new Float64Array(this.#buf);
  }

  get size(): number { return this.#size; }
  get capacity(): number { return this.#view.length; }

  push(value: number): void {
    if (this.#size === this.#view.length) {
      const next = Math.min(this.maxLength, Math.max(4, this.#view.length * 2));
      if (next === this.#view.length) throw new RangeError(`full: maxLength ${this.maxLength} reached`);
      this.#buf.resize(next * 8); // مفيش block جديد ولا نسخ من ناحيتنا: نفس الـ buffer بقى أطول
    }
    this.#view[this.#size++] = value;
  }

  get(i: number): number {
    if (!Number.isInteger(i) || i < 0 || i >= this.#size) throw new RangeError(`index ${i} out of bounds [0, ${this.#size})`);
    return this.#view[i]!;
  }
}

Part 3 — The accounting proof, as a test 🟡 Intermediateالجزء 3 — إثبات الـ accounting، كـ test

English

The accounting method charges every operation a fixed price and keeps a bank balance; if the balance never goes negative, the fixed price is an upper bound on the average cost. For a ×2 dynamic array, charge 3 credits per push: 1 pays for writing the element, and 2 are saved. Between a resize to capacity c and the next one, c/2 new elements are pushed, saving c credits, exactly enough to copy all c elements at the next resize (each new element pays for copying itself and one older element). So every push is O(1) amortized.

Instead of trusting the algebra, instrument the class: a credits counter that adds the charge on every push, subtracts the copies on resize and 1 for the write, and asserts it never drops below zero. Then let node:test push 10⁶ elements. The same test teaches two more facts: the price depends on the factor (with ×1.5 only c/3 pushes happen between resizes into capacity c, so each must save 3: 4 credits, and the test shows 3 run out), and with "+1000" no constant price survives: with 3 credits the balance goes negative at push #4,001. The aggregate and potential methods are in section 05 · 1.1; this part only does the accounting proof.

// نفس منطق DynamicFloat64Array، ومعاه حساب بنك: كل push بتدفع charge، والكتابة والنسخ بيسحبوا
import assert from 'node:assert/strict';
import type { GrowthPolicy } from './dynamic-array.ts';

export class AccountedArray {
  credits = 0;
  #data: Float64Array;
  #size = 0;
  #grow: GrowthPolicy;
  #charge: number;

  constructor(grow: GrowthPolicy, charge: number) {
    this.#data = new Float64Array(0);
    this.#grow = grow;
    this.#charge = charge;
  }

  push(value: number): void {
    this.credits += this.#charge; // الإيداع: كل push بتدفع نفس المبلغ الثابت
    if (this.#size === this.#data.length) {
      const next = new Float64Array(this.#grow(this.#data.length));
      next.set(this.#data);
      this.credits -= this.#size; // السحب: credit لكل عنصر اتنسخ
      this.#data = next;
    }
    this.#data[this.#size++] = value;
    this.credits -= 1; // السحب: credit للكتابة نفسها
    // الإثبات كله في السطر ده: لو الرصيد عمره ما نزل تحت الصفر، يبقى charge لكل push بيغطي كل الشغل
    assert.ok(this.credits >= 0, `credits went negative at push #${this.#size}: ${this.credits}`);
  }
}

Part 4 — Shrinking without thrashing 🟡 Intermediateالجزء 4 — التصغير من غير thrashing

English

Shrinking gives memory back after a spike, but the naive rule ("halve the capacity as soon as the array is half full") puts the shrink point exactly on the grow point. Fill to 2¹² = 4,096 (capacity 4,096, full), then alternate push and pop at that boundary: the push grows to 8,192 and copies 4,096; the pop leaves 4,096 in 8,192, which is half full, so it shrinks and copies 4,096; the next push grows again. Every operation copies the whole array: 100,000 operations, 409,600,000 copies, ≈0.6–2.6 s across runs on this loaded machine.

The fix is hysteresis: grow when full, but shrink to half only when the array is a quarter full. Right after a shrink it is half full, so it needs n/4 more pushes before the next grow and n/4 more pops before the next shrink, which restores amortized O(1). The same sequence copies 4,096 elements once (the first grow) and never again, and a real drain still returns memory (100k → 10 elements left capacity ≤ 64).

When not to shrink at all: a worker queue that spikes every night to 500k jobs and drains to zero by morning will regrow the same capacity tomorrow. Keeping the capacity trades memory you'll use again for not paying the regrowth copies (and their latency spikes) every night. Real JS arrays answer this for you: arr.length = 0 and arr.splice(0) both released the 10.4 MB backing store of a 1M-element array here (V8 does not keep the capacity), while q.items = [] released nothing because another module still held the old array, and that alias kept seeing all 1,000,000 stale jobs.

import { test } from 'node:test';
import assert from 'node:assert/strict';
import { DynamicArray, shrinkAtHalf, shrinkAtQuarter, type ShrinkPolicy } from './dynamic-array.ts';

// السيناريو العدائي: نملى لحد ⁦2^12⁩ بالظبط (الـ capacity مليانة على الآخر)، وبعدين push/pop بالتبادل ⁦10^5⁩ مرة
function thrash(shrink: ShrinkPolicy): { copies: number; ms: number; capacity: number } {
  const jobs = new DynamicArray<number>(4, { shrink });
  for (let i = 0; i < 4096; i++) jobs.push(i);
  const before = jobs.copies;
  const t0 = performance.now();
  for (let k = 0; k < 100_000; k++) {
    if (k % 2 === 0) jobs.push(k);
    else jobs.pop();
  }
  return { copies: jobs.copies - before, ms: performance.now() - t0, capacity: jobs.capacity };
}

test('shrink at half: every push and every pop at the boundary copies the whole array', () => {
  const r = thrash(shrinkAtHalf);
  console.log('shrinkAtHalf   ', r);
  assert.equal(r.copies, 100_000 * 4096);
});

test('shrink at a quarter (hysteresis): the same sequence copies once', () => {
  const r = thrash(shrinkAtQuarter);
  console.log('shrinkAtQuarter', r);

  assert.equal(r.copies, 4096);
});

  assert.ok(jobs.capacity <= 64, `capacity after draining: ${jobs.capacity}`);

بالعامية

التصغير بيرجّع memory بعد الـ spike، بس القاعدة الساذجة ("صغّر للنص أول ما الـ array تبقى نص مليانة") بتحط نقطة التصغير على نقطة التكبير بالظبط. املاها لحد 2¹² = 4,096 (الـ capacity 4,096 ومليانة)، وبعدين push و pop بالتبادل على الحد ده: الـ push بتكبّر لـ 8,192 وتنسخ 4,096؛ والـ pop بتسيب 4,096 في 8,192، يعني نص مليانة، فبتصغر وتنسخ 4,096؛ والـ push اللي بعدها بتكبّر تاني. كل عملية بتنسخ الـ array كلها: 100,000 عملية = 409,600,000 نسخة، و ≈0.6–2.6 ثانية بين التشغيلات على الجهاز المحمّل ده.

الحل اسمه hysteresis: كبّر لما تتملى، بس صغّر للنص لما تبقى ربع مليانة بس. بعد التصغير على طول هي نص مليانة، فمحتاجة n/4 push كمان قبل التكبير الجاي و n/4 pop قبل التصغير الجاي، وده بيرجّع الـ amortized O(1). نفس السيناريو نسخ 4,096 عنصر مرة واحدة (أول تكبير) ومش تاني، والتفضية الحقيقية لسه بترجّع memory (من 100 ألف لـ 10 عناصر الـ capacity بقت 64 أو أقل).

إمتى متصغّرش خالص: worker queue كل ليلة بتطلع لـ 500 ألف job وبتفضى الصبح، هتكبر لنفس الـ capacity بكرة. إنك تسيب الـ capacity زي ما هي معناه إنك بتدفع memory هتستخدمها تاني مقابل إنك متدفعش نسخ التكبير (والوقفات بتاعته) كل ليلة. والـ JS arrays الحقيقية بتجاوبك على السؤال ده لوحدها: arr.length = 0 و arr.splice(0) الاتنين رجّعوا الـ 10.4 MB بتوع array فيها مليون عنصر هنا (V8 مبيحتفظش بالـ capacity)، أما q.items = [] فمرجّعش حاجة لأن module تاني كان ماسك الـ array القديمة، والـ alias ده فضل شايف المليون job القديمين.

فين هستخدمه في شغلي؟ in-memory buffer للـ webhooks اللي فشلت، بيتملى ويفضى طول اليوم حوالين نفس الرقم تقريبًا. لو بتصغّر عند النص هتلاقي flame graph فيه copy في كل request؛ عند الربع (أو متصغّرش خالص وحط سقف) المشكلة بتختفي. ولو بتفضّي queue مشتركة: queue.length = 0 مش queue = []، وإلا الـ health check أو الـ metrics اللي ماسكين نفس الـ array هيفضلوا يشوفوا jobs اتعالجت، وهيحجزوا الـ memory.

Part 5 — RingBuffer<T> from scratch 🟢 Basicالجزء 5 — الـ RingBuffer<T> من الصفر

English

A ring buffer is a fixed block used as a circle: head points at the oldest item, writes go to tail = (head + size) % capacity, and both indexes wrap around to 0 at the end, so push and shift are O(1) with no copying and no growth. When head === tail the ring is either empty or full, so you need a way to tell them apart. There are three:

  • Keep a size counter (this lesson's RingBuffer): full is size === capacity. Simple and uses every slot.
  • Waste one slot: full when (tail + 1) % cap === head. No counter, one slot never used. Node does exactly this: its isFull() is ((this.top + 1) & kMask) === this.bottom (Part 6).
  • Ever-growing counters with a mask (CounterRing): head and tail only increase, size = tail − head, index = counter & (cap − 1). Needs a power-of-two capacity; wrapping the counters with | 0 keeps them Smis and stays correct across 2³¹ (tested).

When the ring is full you must pick a policy: overwrite the oldest and return it (metrics, logs: newest data matters), reject the new item (job intake: the caller decides to retry, return 429 or drop), or throw (a full ring is a bug). RingBuffer implements the first two as push and tryPush. Power-of-two capacities let you replace % with & (cap − 1); measured here, the difference was within noise (≈7–15 ns/op either way), so pick power-of-two for the counter trick, not for speed. Against array.shift() the ring wins by orders of magnitude: ≈19 ns/op vs ≈314,738 ns/op at 10⁵ jobs (shift is O(n) per call; 10⁶ was skipped).

// الـ ring buffer: block ثابت ⁦+ head + size⁩. الـ tail مش متخزن: بيتحسب ⁦(head + size) % capacity⁩
// لما يتملى عندك قرارين: ⁦overwrite (⁩ارمي الأقدم ورجّعه) أو ⁦reject (⁩ارفض الجديد)
export class RingBuffer<T> implements Iterable<T> {
  readonly capacity: number;
  #buf: (T | undefined)[];
  #head = 0;
  #size = 0;

  constructor(capacity: number) {
    if (!Number.isInteger(capacity) || capacity < 1) throw new RangeError(`capacity must be a positive integer, got ${capacity}`);
    this.capacity = capacity;
    this.#buf = new Array<T | undefined>(capacity).fill(undefined);
  }

  get size(): number { return this.#size; }
  get isEmpty(): boolean { return this.#size === 0; }
  get isFull(): boolean { return this.#size === this.capacity; }

  // الـ overwrite: لو مليان، العنصر الأقدم بيطلع ويرجع للي نادى (عشان يعمله log أو metric)
  push(item: T): T | undefined {
    const tail = (this.#head + this.#size) % this.capacity;
    if (this.#size === this.capacity) {
      const evicted = this.#buf[tail]; // لما يبقى مليان، الـ ⁦tail =⁩ الـ ⁦head =⁩ مكان الأقدم
      this.#buf[tail] = item;
      this.#head = (this.#head + 1) % this.capacity;
      return evicted;
    }
    this.#buf[tail] = item;
    this.#size++;
    return undefined;
  }

  // الـ reject: لو مليان، false والـ buffer زي ما هو (الـ caller يقرر: يرجّع 429، يستنى، يعمل drop)
  tryPush(item: T): boolean {
    if (this.#size === this.capacity) return false;
    this.#buf[(this.#head + this.#size) % this.capacity] = item;
    this.#size++;
    return true;
  }

  shift(): T | undefined {
    if (this.#size === 0) return undefined;
    const item = this.#buf[this.#head];
    this.#buf[this.#head] = undefined; // نسيب الـ reference للـ GC
    this.#head = (this.#head + 1) % this.capacity;
    this.#size--;
    return item;
  }

  peek(): T | undefined {
    return this.#size === 0 ? undefined : this.#buf[this.#head];
  }

  // الترتيب من الأقدم للأحدث، حتى بعد ما الـ head لفّ
  *[Symbol.iterator](): IterableIterator<T> {
    for (let i = 0; i < this.#size; i++) yield this.#buf[(this.#head + i) % this.capacity] as T;
  }
}

// نفس الفكرة بـ capacity أس 2: الـ % بقت ⁦& (capacity - 1)⁩
export class MaskRing<T> {
  readonly capacity: number;
  #mask: number;
  #buf: (T | undefined)[];
  #head = 0;
  #size = 0;

  constructor(capacity: number) {
    if (!Number.isInteger(capacity) || capacity < 1 || (capacity & (capacity - 1)) !== 0) {
      throw new RangeError(`capacity must be a power of two, got ${capacity}`);
    }
    this.capacity = capacity;
    this.#mask = capacity - 1;
    this.#buf = new Array<T | undefined>(capacity).fill(undefined);
  }

  get size(): number { return this.#size; }

  tryPush(item: T): boolean {
    if (this.#size === this.capacity) return false;
    this.#buf[(this.#head + this.#size) & this.#mask] = item;
    this.#size++;
    return true;
  }

  shift(): T | undefined {
    if (this.#size === 0) return undefined;
    const item = this.#buf[this.#head];
    this.#buf[this.#head] = undefined;
    this.#head = (this.#head + 1) & this.#mask;
    this.#size--;
    return item;
  }
}

// الطريقة التالتة: counters بتزيد على طول (من غير wrap يدوي) والـ index = counter & mask
// الـ size = tail - head، فمش محتاج size ولا خانة ضايعة. الـ ⁦| 0⁩ بيلف الـ counter عند ⁦2^31⁩ بأمان
export class CounterRing<T> {
  readonly capacity: number;
  #mask: number;
  #buf: (T | undefined)[];
  #head: number;
  #tail: number;

  constructor(capacity: number, start = 0) {
    if (!Number.isInteger(capacity) || capacity < 1 || (capacity & (capacity - 1)) !== 0) {
      throw new RangeError(`capacity must be a power of two, got ${capacity}`);
    }
    this.capacity = capacity;
    this.#mask = capacity - 1;
    this.#buf = new Array<T | undefined>(capacity).fill(undefined);
    this.#head = this.#tail = start | 0; // الـ start موجود عشان التيست يبدأ قريب من ⁦2^31⁩
  }

  get size(): number { return (this.#tail - this.#head) | 0; }

  tryPush(item: T): boolean {
    if (this.size === this.capacity) return false;
    this.#buf[this.#tail & this.#mask] = item;
    this.#tail = (this.#tail + 1) | 0;
    return true;
  }

  shift(): T | undefined {
    if (this.size === 0) return undefined;
    const i = this.#head & this.#mask;
    const item = this.#buf[i];
    this.#buf[i] = undefined;
    this.#head = (this.#head + 1) | 0;
    return item;
  }
}

بالعامية

الـ ring buffer هو block ثابت بتستخدمه كأنه دايرة: الـ head بيشاور على الأقدم، والكتابة بتروح لـ tail = (head + size) % capacity، والاتنين بيلفّوا للصفر لما يوصلوا للآخر، فالـ push والـ shift الاتنين O(1) من غير نسخ ولا growth. ولما head === tail الـ ring يا فاضية يا مليانة، فلازم طريقة تفرّق بينهم. وفيه تلاتة:

  • عدّاد size (الـ RingBuffer بتاع الدرس): مليانة لما size === capacity. بسيطة وبتستخدم كل الخانات.
  • تضيّع خانة: مليانة لما (tail + 1) % cap === head. مفيش عدّاد، وخانة واحدة عمرها ما بتتستخدم. وده بالظبط اللي Node بيعمله: الـ isFull() عنده ((this.top + 1) & kMask) === this.bottom (الجزء 6).
  • counters بتزيد على طول مع mask (CounterRing): الـ head والـ tail بيزيدوا بس، وsize = tail − head، والـ index = counter & (cap − 1). محتاجة capacity أس 2؛ والـ | 0 بيلف الـ counters فيفضلوا Smis ويفضل الحساب صح بعد 2³¹ (متجرّب).

ولما الـ ring تتملى لازم تختار policy: overwrite ترمي الأقدم وترجّعه (metrics و logs: الأحدث هو المهم)، أو reject ترفض الجديد (استقبال jobs: الـ caller يقرر يعيد المحاولة أو يرد 429 أو يرمي)، أو throw (الـ ring المليانة bug). الـ RingBuffer بيعمل الأولى والتانية كـ push وtryPush. والـ capacity الأس 2 بتخليك تبدّل % بـ & (cap − 1)؛ بس القياس هنا قال الفرق جوه الضوضاء (≈7–15 ns/op في الحالتين)، فاختار الأس 2 عشان حيلة الـ counters مش عشان السرعة. وقدام array.shift() الـ ring بتكسب بفرق ضخم: ≈19 ns/op مقابل ≈314,738 ns/op عند 100 ألف job (الـ shift بـ O(n) في كل call؛ والمليون اتعمله skip).

فين هستخدمه في شغلي؟ in-process queue قدام provider الـ SMS اللي عليه rate limit: الـ requests بتدخل بـ tryPush في ring سعتها 10,000، ولو رجعت false الـ endpoint بيرد 429 مع Retry-After بدل ما الـ memory تكبر لحد OOM. ولو كنت ماشي بـ array.push + shift وجالك burst بـ 100 ألف رسالة، كل shift بتنقل كل اللي وراها وبتقف ≈0.3 ms، فالـ worker بيقضي دقايق CPU في الـ queue نفسها مش في الإرسال.

Part 6 — Node's FixedQueue: a list of rings 🟡 Intermediateالجزء 6 — الـ FixedQueue بتاع Node: list من الـ rings

English

A ring has a fixed capacity, but process.nextTick must accept any number of callbacks. Node's answer, readable on your machine with node --expose-internals and process.binding('natives') (a lab trick, not app code), is internal/fixed_queue: a singly linked list of FixedCircularBuffers of kSize = 2048 slots. Push goes into the newest ring and links a fresh ring when it is full; shift reads from the oldest ring and unlinks it once it is empty. internal/process/task_queues creates one FixedQueue for the nextTick queue.

Why this design: it is unbounded, push and shift are O(1), and growing never copies existing items, because a new 2,048-slot chunk is linked instead. Build the same thing as ChunkedQueue<T> and compare it with a single ring that doubles by copying (GrowableRing<T>) and with the denque package, under a bursty producer: bursts of 10,000 pushes, of which the consumer only drains 90%, up to 10⁶ pushes.

Measured: throughput is a wash (≈121–148 ns/op including a timer around every push), and p99.9 push latency is ≈0.2–0.3 µs for all three. The growable ring copied 131,056 elements across 13 resizes at 10⁶; the chunked queue copied none. The largest single push, though, was in the same range for both (≈0.26–1.3 ms) because in JS every allocation can trigger a GC pause, and new chunks are allocations too: on this machine "no copy" did not mean "no pause". The structural win that did show clearly is memory: after a spike of 10⁶ jobs drained to zero, the chunked queue kept ≈0.02 MB, while the growable ring and denque both kept ≈8.4 MB, because a single array never shrinks unless you code it to.

const kSize = 2048;
const kMask = kSize - 1;
// When `top === bottom` the current queue is empty and when
// `top + 1 === bottom` it's full. This wastes a single space of storage
// but allows much quicker checks.

class FixedCircularBuffer {
  constructor() {
    this.bottom = 0;
    this.top = 0;
    this.list = ArrayPrototypeFill(new Array(kSize), undefined);
    this.next = null;
  }

  isEmpty() {
    return this.top === this.bottom;
  }

  isFull() {
    return ((this.top + 1) & kMask) === this.bottom;
  }

  push(data) {
    this.list[this.top] = data;
    this.top = (this.top + 1) & kMask;
  }

  shift() {
    const nextItem = this.list[this.bottom];
    if (nextItem === undefined)
      return null;
    this.list[this.bottom] = undefined;
    this.bottom = (this.bottom + 1) & kMask;
    return nextItem;
  }
}

module.exports = class FixedQueue {
  constructor() {
    this.head = this.tail = new FixedCircularBuffer();
  }

  isEmpty() {
    return this.head.isEmpty();
  }

  push(data) {
    if (this.head.isFull()) {
      // Head is full: Creates a new queue, sets the old queue's `.next` to it,
      // and sets it as the new main queue.
      this.head = this.head.next = new FixedCircularBuffer();
    }
    this.head.push(data);
  }

  shift() {
    const tail = this.tail;
    const next = tail.shift();
    if (tail.isEmpty() && tail.next !== null) {
      // If there is another queue, it forms the new tail.
      this.tail = tail.next;
      tail.next = null;
    }
    return next;
  }
};

const CHUNK = 2048; // أس 2، عشان الـ ⁦& (CHUNK - 1)⁩
const MASK = CHUNK - 1;

class Chunk<T> {
  bottom = 0; // مكان القراية
  top = 0; // مكان الكتابة
  slots: (T | undefined)[] = new Array<T | undefined>(CHUNK).fill(undefined);
  next: Chunk<T> | null = null;
  // زي Node بالظبط: top === bottom يعني فاضي، و ⁦top + 1 === bottom⁩ يعني مليان (خانة واحدة ضايعة)
  isEmpty(): boolean { return this.top === this.bottom; }
  isFull(): boolean { return ((this.top + 1) & MASK) === this.bottom; }
}

export class ChunkedQueue<T> {
  #head: Chunk<T>; // بنكتب هنا (الأحدث)
  #tail: Chunk<T>; // بنقرا من هنا (الأقدم)
  #size = 0;
  readonly copies = 0; // عمره ما بينسخ: موجود بس عشان الـ bench يقارن
  chunksAllocated = 1;

  constructor() {
    this.#head = this.#tail = new Chunk<T>();
  }

  get size(): number { return this.#size; }

  push(item: T): void {
    // لما الـ chunk يتملى بنعلّق واحد جديد: ⁦O(1)⁩، ومفيش أي نسخ للقديم
    if (this.#head.isFull()) {
      this.#head = this.#head.next = new Chunk<T>();
      this.chunksAllocated++;
    }
    const h = this.#head;
    h.slots[h.top] = item;
    h.top = (h.top + 1) & MASK;
    this.#size++;
  }

  shift(): T | undefined {
    const t = this.#tail;
    if (t.isEmpty()) return undefined;
    const item = t.slots[t.bottom];
    t.slots[t.bottom] = undefined;
    t.bottom = (t.bottom + 1) & MASK;
    this.#size--;
    // الـ chunk الأقدم خلص وفيه واحد بعده: نسيبه للـ GC
    if (t.isEmpty() && t.next !== null) {
      this.#tail = t.next;
      t.next = null;
    }
    return item;
  }
}

// للمقارنة: ring واحدة بتكبر ⁦×2⁩ بالنسخ لما تتملى (اللي هتكتبه أول ما تفكر في ⁦"ring⁩ مش محدودة")
export class GrowableRing<T> {
  copies = 0; // كام عنصر اتنقل في الـ resizes
  #buf: (T | undefined)[] = new Array<T | undefined>(16).fill(undefined);
  #head = 0;
  #size = 0;

  get size(): number { return this.#size; }

  push(item: T): void {
    if (this.#size === this.#buf.length) {
      const next = new Array<T | undefined>(this.#buf.length * 2).fill(undefined);
      // بنفك اللفّة واحنا بننسخ: الأقدم يبقى في الخانة 0
      for (let i = 0; i < this.#size; i++) next[i] = this.#buf[(this.#head + i) % this.#buf.length];
      this.copies += this.#size;
      this.#buf = next;
      this.#head = 0;
    }
    this.#buf[(this.#head + this.#size) % this.#buf.length] = item;
    this.#size++;
  }

  shift(): T | undefined {
    if (this.#size === 0) return undefined;
    const item = this.#buf[this.#head];
    this.#buf[this.#head] = undefined;
    this.#head = (this.#head + 1) % this.#buf.length;
    this.#size--;
    return item;
  }
}

Trade-off: one growable ring vs a list of fixed rings A single growable ring is contiguous (best for iteration and random at(i)), simple, but copies on growth, peaks at 3× during a resize and never returns memory unless you add shrinking. A list of fixed chunks never copies, returns memory chunk by chunk and keeps per-push work bounded, but random access needs a chunk walk, each chunk costs a little header memory, and in JS each new chunk is still an allocation that can land on a GC pause.
الـ ring الواحدة اللي بتكبر متصلة في الـ memory (أحسن حاجة للـ iteration وللـ at(i) العشوائي) وبسيطة، بس بتنسخ وهي بتكبر، وذروتها 3 أضعاف وقت الـ resize، ومبترجّعش memory إلا لو ضفت shrinking. أما الـ list من الـ chunks الثابتة فعمرها ما بتنسخ، وبترجّع الـ memory chunk ورا chunk، وشغل كل push محدود، بس الـ random access محتاج تمشي على الـ chunks، وكل chunk ليه header صغير، وفي JS كل chunk جديد لسه allocation ممكن تيجي معاه GC pause.

English

(1) A sliding window of the last 60 s of request latency. Keep a ring of 60 one-second buckets; each bucket holds a count, a sum, a max and a fixed histogram (11 bounds: 5, 10, 25, 50, 100, 250, 500, 1000, 2500, 5000 ms, +∞). The bucket for a sample is Math.floor(now / 1000) % 60. The bug everyone writes first: when the second changes, move to the next bucket and clear only that one. After 5 idle minutes, the next request clears one bucket and the other 59 still hold data from 5 minutes ago, so /metrics reports 60 requests at 200 ms max instead of 1 at 15 ms. The fix: remember the newest second seen and clear every bucket you skipped (at most 60), in record and also in snapshot, or the window freezes when traffic stops. Pass now in, so tests drive a fake clock instead of timers.

Quantiles come from the merged histogram: find the bucket holding rank q × count and interpolate linearly inside it, the same estimate as Prometheus's histogram_quantile. It's exact only to the bucket, so the test checks that the estimated p50/p99 fall in the same bucket as the exact percentiles of the raw samples. Memory is fixed at 60 × (4 + 8 + 8 + 4 × 11) bytes plus object headers: measured ≈16–20 KB after 10³, 10⁵ and 10⁶ requests, against ≈80 MB for an array that keeps every sample. Wire it into Fastify with an onResponse hook using reply.elapsedTime and serve GET /metrics/latency. For real Prometheus histograms, see 06-NodeJS lesson 31; a circuit breaker's rolling failure window is the same structure, see 10-Design-Patterns lesson 23.

(2) A flight recorder. Keep the last 1,000 log lines per tenant in an overwrite-on-full ring and dump only that tenant's lines when one of its requests fails. Bound the number of tenants too (here: evict the oldest-inserted tenant at 10,000), or the Map of rings becomes the leak.   readonly seconds: number;
  #count: Uint32Array;
  #max: Float64Array;
  #head = 0;
  #current = -1;

  constructor(seconds = 60) {
    this.seconds = seconds;
    this.#count = new Uint32Array(seconds);
    this.#max = new Float64Array(seconds);
  }

  record(ms: number, nowMs: number): void {
    const sec = Math.floor(nowMs / 1000);
    if (sec !== this.#current) {
      // الغلطة: 300 ثانية عدّت، واحنا اتحركنا خانة واحدة وصفّرناها، والـ 59 التانيين لسه فيهم بيانات قديمة

      this.#count[this.#head] = 0;
      this.#max[this.#head] = 0;

      count += this.#count[s]!;
      if (this.#max[s]! > max) max = this.#max[s]!;
    }
    return { count, maxMs: max };
  }

export const BOUNDS_MS = [5, 10, 25, 50, 100, 250, 500, 1000, 2500, 5000, Infinity];
const B = BOUNDS_MS.length;

export interface LatencySnapshot {
  count: number;
  avgMs: number;
  maxMs: number;
  p50Ms: number;
  p99Ms: number;
}

export class LatencyWindow {
  readonly seconds: number;
  #count: Uint32Array;
  #sum: Float64Array;
  #max: Float64Array;
  #hist: Uint32Array; // الـ bucket رقم s بياخد الخانات من s*B لحد s*B + B - 1
  #newest = -Infinity; // أحدث ثانية (absolute) شفناها

  constructor(seconds = 60) {
    if (!Number.isInteger(seconds) || seconds < 1) throw new RangeError(`seconds must be a positive integer, got ${seconds}`);
    this.seconds = seconds;
    this.#count = new Uint32Array(seconds);
    this.#sum = new Float64Array(seconds);
    this.#max = new Float64Array(seconds);
    this.#hist = new Uint32Array(seconds * B);
  }

  record(ms: number, nowMs: number): void {
    const sec = Math.floor(nowMs / 1000);
    this.#advance(sec);
    // سطر قديم أوي (clock skew أو request طوّل⁦):⁩ برّه الـ window، فبنرميه
    if (sec <= this.#newest - this.seconds) return;
    const s = sec % this.seconds;
    this.#count[s]!++;
    this.#sum[s]! += ms;
    if (ms > this.#max[s]!) this.#max[s] = ms;
    let b = 0;
    while (ms > BOUNDS_MS[b]!) b++;
    this.#hist[s * B + b]!++;
  }

  // الإصلاح كله هنا: صفّر كل bucket اتعدّى عليه الوقت، مش bucket واحد بس
  #advance(sec: number): void {
    if (sec <= this.#newest) return;
    const gap = this.#newest === -Infinity ? this.seconds : Math.min(sec - this.#newest, this.seconds);
    for (let k = 0; k < gap; k++) {
      const s = (sec - k) % this.seconds;
      this.#count[s] = 0;
      this.#sum[s] = 0;
      this.#max[s] = 0;
      this.#hist.fill(0, s * B, s * B + B);
    }
    this.#newest = sec;
  }

  snapshot(nowMs: number): LatencySnapshot {
    this.#advance(Math.floor(nowMs / 1000)); // من غيره: لو الـ traffic وقف، الـ ⁦/metrics⁩ هيفضل يعرض آخر دقيقة للأبد
    let count = 0, sum = 0, max = 0;
    const merged = new Float64Array(B);
    for (let s = 0; s < this.seconds; s++) {
      count += this.#count[s]!;
      sum += this.#sum[s]!;
      if (this.#max[s]! > max) max = this.#max[s]!;
      for (let b = 0; b < B; b++) merged[b]! += this.#hist[s * B + b]!;
    }
    return { count, avgMs: count ? sum / count : 0, maxMs: max, p50Ms: quantile(merged, count, 0.5, max), p99Ms: quantile(merged, count, 0.99, max) };
  }
}

// تقدير الـ quantile من الـ histogram بـ linear interpolation جوه الـ ⁦bucket (⁩نفس فكرة histogram_quantile في Prometheus)
function quantile(counts: Float64Array, total: number, q: number, max: number): number {
  if (total === 0) return 0;
  const rank = q * total;
  let seen = 0;
  for (let b = 0; b < counts.length; b++) {
    const c = counts[b]!;
    if (seen + c >= rank && c > 0) {
      const upper = BOUNDS_MS[b]!;
      if (upper === Infinity) return max; // الـ bucket الأخير ملوش حد أعلى، فبنرجّع أكبر قيمة شفناها
      const lower = b === 0 ? 0 : BOUNDS_MS[b - 1]!;
      return Math.min(max, lower + ((upper - lower) * (rank - seen)) / c);
    }
    seen += c;
  }
  return max;
}

import { RingBuffer } from './ring-buffer.ts';

export class FlightRecorder {
  readonly linesPerTenant: number;
  readonly maxTenants: number;
  #rings = new Map<string, RingBuffer<string>>();

  constructor(linesPerTenant = 1000, maxTenants = 10_000) {
    this.linesPerTenant = linesPerTenant;
    this.maxTenants = maxTenants;
  }

  log(tenantId: string, line: string): void {
    let ring = this.#rings.get(tenantId);
    if (!ring) {
      // حد على عدد الـ tenants كمان، وإلا الـ Map نفسها تبقى memory leak: نشيل أقدم tenant اتضاف
      if (this.#rings.size === this.maxTenants) this.#rings.delete(this.#rings.keys().next().value!);
      ring = new RingBuffer<string>(this.linesPerTenant);
      this.#rings.set(tenantId, ring);
    }
    ring.push(line); // الـ overwrite: لما يتملى، أقدم سطر بيطلع
  }

  dump(tenantId: string): string[] {
    return [...(this.#rings.get(tenantId) ?? [])];
  }
}

Interview question "Design GET /metrics/latency returning count, avg, max, p50 and p99 over the last 60 seconds, in bounded memory, for a service doing 20k requests per second." → A ring of 60 per-second buckets, each with count, sum, max and a fixed-bound histogram; slot = floor(now/1000) mod 60. On every record and every read, clear all buckets skipped since the newest second (at most 60), so idle periods don't leave stale data. Percentiles come from the merged histogram with linear interpolation, accurate to a bucket; choose bounds around your SLO. Memory is O(buckets × histogram size), independent of traffic (≈20 KB here vs ≈80 MB for raw samples). Per-process only: across instances, export the histogram buckets (Prometheus) and aggregate there, since you can't average p99s.

  pop(): number | undefined {
    if (this.#size === 0) return undefined;
    const value = this.#data[--this.#size]!;
    // الـ hysteresis: صغّر للنص بس لما تبقى ربع مليانة، ومتنزلش تحت 16 خانة
    const cap = this.#data.length;

      next.set(this.#data.subarray(0, this.#size));
      this.copies += this.#size;
      this.#data = next;

    return value;

});

# ADR-0001: Use a 60-bucket ring (LatencyWindow) for in-process latency metrics

- Date: YYYY-MM-DD   - Status: Accepted

## Context
We need p50/p99/max of API latency over the last 60 s for /metrics and the readiness probe.
Traffic peaks at N req/s; memory per pod must stay flat.

## Options
1. Keep every sample in an array, sort on read  - exact, memory grows with traffic (~80 MB per 1M samples measured)
2. LatencyWindow: 60 buckets x fixed histogram   - flat memory (~20 KB measured), p99 accurate to a bucket
3. Only export a Prometheus histogram            - no in-process p99 for the readiness probe

## Decision
Option 2, bucket bounds chosen around our SLO (e.g. 250 ms).

## Consequences
+ O(1) record, flat memory, testable with a fake clock
- percentiles are bucket estimates; per-process only (aggregate histograms, not p99s)
Revisit if: we need exact percentiles, or cross-instance p99 in-process

Cheat sheet · الخلاصة

  • Dynamic array = fixed block + size; full → allocate bigger, copy, drop old. Count copies; amortized O(1) is about the average, the resize push itself grows with n (≈1.3 ms for 4 MB here).
  • Backing block for a generic container: new Array(n) (≈5.7 ns/slot) beats Array.from({length}, fn) (≈53 ns/slot); Node's FixedQueue does the same.
  • Growth ×g: between 1/(g−1) and g/(g−1) copies per push (1–2 at ×2); ×2 peaks at 3× data with up to 50% slack, ×1.5 at 2.5×. +k is quadratic: 499,500,000 copies and ≈1.3 s at 10⁶.
  • V8 grows arrays to n + ⌊n/2⌋ + 16 (measured). Factors below ≈1.618 let freed blocks be reused. Node 22 resizable ArrayBuffer: resize push ≈28 µs vs ≈1.3 ms copying, up to a fixed maxByteLength.
  • Accounting proof: charge 3 per push at ×2 (1 + g/(g−1) in general: 4 at ×1.5); assert the credit balance never goes negative in a test. +1000 fails at push #4,001.
  • Shrink with hysteresis: grow when full, shrink to half at ¼ full. Shrinking at ½ copied 409,600,000 elements in 100k ops; ¼ copied 4,096 once. Don't shrink a queue that refills nightly.
  • Clearing JS arrays: length = 0 / splice(0) free the store and every alias sees it; arr = [] leaves aliases holding stale data.
  • Ring: head + size, tail = (head + size) % cap; full vs empty by size counter, a wasted slot (Node), or masked monotonic counters. Full policy: overwrite / reject / throw.
  • % vs &: within noise in JS here; ring vs shift(): ≈19 vs ≈314,738 ns/op at 10⁵.
  • Unbounded queue: list of fixed rings (FixedQueue, 2048 slots): no copies, memory returned as it drains (0.02 MB vs 8.4 MB), but allocations can still hit GC pauses.
  • Latency window: 60 buckets with count/sum/max/histogram, clear every skipped bucket on record and read, pass now in; ≈20 KB flat vs ≈80 MB for raw samples. Flight recorder: ring per tenant + a cap on tenants.
بالعامية
  • الـ dynamic array = block ثابت + size؛ لما يتملى احجز أكبر وانسخ وارمي القديم. عدّ النسخ؛ والـ amortized O(1) كلام عن المتوسط، أما الـ push اللي بتعمل resize فبتكبر مع n (≈1.3 ms لـ 4 MB هنا).
  • الـ block بتاع container generic: new Array(n) (≈5.7 ns للخانة) أحسن من Array.from({length}, fn) (≈53 ns للخانة)؛ والـ FixedQueue بتاع Node بيعمل نفس الحكاية.
  • الـ growth ×g: النسخ لكل push بين 1/(g−1) و g/(g−1) (من 1 لـ 2 مع ×2)؛ الـ ×2 ذروتها 3 أضعاف الـ data وفاضي لحد 50%، والـ ×1.5 ذروتها 2.5. والـ +k quadratic: 499,500,000 نسخة و ≈1.3 ثانية عند مليون.
  • الـ V8 بيكبّر الـ arrays لـ n + ⌊n/2⌋ + 16 (متقاس). والـ factors اللي أقل من ≈1.618 بتسمح بإعادة استخدام الـ blocks المتحررة. والـ ArrayBuffer الـ resizable في Node 22: push الـ resize ≈28 µs بدل ≈1.3 ms بالنسخ، لحد maxByteLength ثابت.
  • إثبات الـ accounting: حاسب كل push بـ 3 مع ×2 (وعمومًا 1 + g/(g − 1): يعني 4 مع ×1.5)؛ واعمل assert في test إن الرصيد عمره ما بقى سالب. والـ +1000 فشل عند الـ push رقم 4,001.
  • صغّر بـ hysteresis: كبّر لما تتملى، وصغّر للنص لما تبقى ربع مليانة. التصغير عند النص نسخ 409,600,000 عنصر في 100 ألف عملية؛ وعند الربع نسخ 4,096 مرة واحدة. ومتصغّرش queue بتتملى تاني كل ليلة.
  • تفضية الـ JS arrays: length = 0 أو splice(0) بيرجّعوا الـ store وكل alias بيشوف التفضية؛ أما arr = [] فبيسيب الـ aliases ماسكين data قديمة.
  • الـ ring: head + size، وtail = (head + size) % cap؛ والمليان من الفاضي بعدّاد size، أو خانة ضايعة (زي Node)، أو counters بتزيد مع mask. ولما تتملى: overwrite أو reject أو throw.
  • الـ % مقابل الـ &: جوه الضوضاء في JS هنا؛ والـ ring مقابل shift(): ≈19 مقابل ≈314,738 ns لكل عملية عند 100 ألف.
  • الـ queue اللي مالهاش حد: list من rings ثابتة (الـ FixedQueue، 2048 خانة): مفيش نسخ، والـ memory بترجع وهي بتفضى (0.02 MB مقابل 8.4 MB)، بس الـ allocations لسه ممكن تجيب GC pauses.
  • الـ latency window: 60 bucket فيهم count و sum و max و histogram، وصفّر كل bucket اتعدّى في الـ record وفي القراية، ومرّر now من برّه؛ ≈20 KB ثابتين مقابل ≈80 MB للـ samples الخام. والـ flight recorder: ring لكل tenant + حد على عدد الـ tenants.
