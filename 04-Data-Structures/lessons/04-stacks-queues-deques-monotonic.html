Why this matters · ليه ده مهم

English

Queues sit in front of every worker you write: webhook deliveries, emails, imports, the BFS frontier of a permission check. The most common queue in JavaScript, push + shift, is fast in every test and quadratic in production once it holds more than ≈16,000 items, and this lesson finds the exact byte where that happens on V8. The monotonic stack and deque turn "next higher revenue day" and "worst latency in the last hour" from O(n·k) into O(n), which is the difference between a metrics endpoint that answers in microseconds and one that pins a core. And the stack is behind undo, parsers and every recursion you convert to survive deep input.

بالعامية

الـ queues قاعدة قدام أي worker بتكتبه: إرسال الـ webhooks، الإيميلات، الـ imports، والـ BFS frontier في فحص صلاحيات. أشهر queue في JavaScript، push + shift، سريعة في كل test وبتبقى O(n²) في الـ production أول ما يبقى فيها أكتر من ≈16,000 عنصر، والدرس ده بيلاقي الـ byte بالظبط اللي ده بيحصل عنده في V8. الـ monotonic stack والـ deque بيحوّلوا "أول يوم إيراده أعلى" و "أسوأ latency في آخر ساعة" من O(n·k) لـ O(n)، وده الفرق بين metrics endpoint بيرد في microseconds وواحد بيمسك core كامل. والـ stack ورا الـ undo والـ parsers وأي recursion بتحوّلها عشان تستحمل input عميق.

Part 1 — Three ADTs, two backings each 🟢 Basicالجزء 1 — تلات ADTs، وكل واحد بطريقتين تخزين

English

An ADT says what the operations mean; a backing says how they are stored. The concepts (LIFO, FIFO, why an array suits a stack) are in CS Fundamentals lesson 03, parts 4–5. Here we write three interfaces, Stack<T>, Queue<T> and Deque<T>, and two backings for each:

  • Array-backed. A stack is push/pop: both touch only the end, O(1) amortized. A queue is an array plus a head index: dequeue reads items[head++] and never shifts; when the dead prefix is at least 16 slots and at least half the array, one slice compacts it. Each compaction copies fewer live items than were dequeued since the previous one, so it stays O(1) amortized. A deque on a plain array needs unshift/shift at the front: O(n) per operation, measured below at ≈14 µs per pushFront with 10⁵ items.
  • Ring-backed. Lesson 02's ring buffer (part 5), made to grow: the capacity is a power of two so wrap-around is & mask, pushFront moves head backwards ((head - 1) & mask wraps 0 to the last slot), and a full ring doubles, copying the items in order to the start of the new buffer. All four ends are amortized O(1), and at(i) is O(1) too.

One table-driven node:test suite runs the same tests, including 50,000-operation model-based tests against a plain array, on every implementation. Two tiny adapters, stackOf and queueOf, let one deque serve as either. A side finding while measuring the ring: Array.from({ length: n }, fn) took ≈31 ms for 2²⁰ slots against ≈3.7 ms for new Array(n).fill(undefined); the second one is HOLEY_ELEMENTS by kind (lesson 01, part 3) but holds no real holes, so the ring uses it.

// تلات ADTs: الـ interface بيقول "بيعمل إيه"، والـ class بيقول "متخزن إزاي"
export interface Stack<T> {
  push(item: T): void;
  pop(): T | undefined;
  peek(): T | undefined;
  readonly size: number;
}
export interface Queue<T> {
  enqueue(item: T): void;
  dequeue(): T | undefined;
  peek(): T | undefined;
  readonly size: number;
}
export interface Deque<T> {
  pushBack(item: T): void;
  pushFront(item: T): void;
  popBack(): T | undefined;
  popFront(): T | undefined;
  peekBack(): T | undefined;
  peekFront(): T | undefined;
  readonly size: number;
}

// الـ stack على array: push و pop بيلمسوا الآخر بس، يعني O(1) amortized
export class ArrayStack<T> implements Stack<T> {
  readonly #items: T[] = [];
  push(item: T): void { this.#items.push(item); }
  pop(): T | undefined { return this.#items.pop(); }
  peek(): T | undefined { return this.#items[this.#items.length - 1]; }
  get size(): number { return this.#items.length; }
}

// الـ queue على array + head index: مفيش shift، والـ compaction لما الجزء الميت يعدّي النص
export class ArrayQueue<T> implements Queue<T> {
  #items: (T | undefined)[] = [];
  #head = 0;
  enqueue(item: T): void { this.#items.push(item); }
  dequeue(): T | undefined {
    if (this.#head === this.#items.length) return undefined;
    const item = this.#items[this.#head];
    this.#items[this.#head++] = undefined;
    // كل compaction بتنسخ عناصر حية عددها أقل من اللي اتشالوا من آخر compaction: O(1) amortized
    if (this.#head >= 16 && this.#head * 2 >= this.#items.length) {
      this.#items = this.#items.slice(this.#head);
      this.#head = 0;
    }
    return item;
  }
  peek(): T | undefined { return this.#items[this.#head]; }
  get size(): number { return this.#items.length - this.#head; }
}

// الـ deque على array عادية: الطرف الورّاني ⁦O(1)⁩، بس الطرف القدّامي unshift/shift يعني ⁦O(n)⁩
export class ArrayDeque<T> implements Deque<T> {
  readonly #items: T[] = [];
  pushBack(item: T): void { this.#items.push(item); }
  pushFront(item: T): void { this.#items.unshift(item); }
  popBack(): T | undefined { return this.#items.pop(); }
  popFront(): T | undefined { return this.#items.shift(); }
  peekBack(): T | undefined { return this.#items[this.#items.length - 1]; }
  peekFront(): T | undefined { return this.#items[0]; }
  get size(): number { return this.#items.length; }
}

// الـ deque على ring بيكبر بالنسخ: الأربع أطراف O(1) amortized
export class RingDeque<T> implements Deque<T> {
  #buf: (T | undefined)[];
  #head = 0;
  #size = 0;
  // الـ capacity دايمًا power of two، فالـ wrap-around بـ ⁦& mask⁩ بدل %
  #mask: number;

  constructor(initialCapacity = 16) {
    let cap = 1;
    while (cap < initialCapacity) cap *= 2;
    this.#buf = new Array<T | undefined>(cap).fill(undefined);
    this.#mask = cap - 1;
  }

  get size(): number { return this.#size; }
  get capacity(): number { return this.#buf.length; }

  pushBack(item: T): void {
    if (this.#size === this.#buf.length) this.#grow();
    this.#buf[(this.#head + this.#size) & this.#mask] = item;
    this.#size++;
  }
  pushFront(item: T): void {
    if (this.#size === this.#buf.length) this.#grow();
    this.#head = (this.#head - 1) & this.#mask;
    this.#buf[this.#head] = item;
    this.#size++;
  }
  popFront(): T | undefined {
    if (this.#size === 0) return undefined;
    const item = this.#buf[this.#head];
    this.#buf[this.#head] = undefined;
    this.#head = (this.#head + 1) & this.#mask;
    this.#size--;
    return item;
  }
  popBack(): T | undefined {
    if (this.#size === 0) return undefined;
    const i = (this.#head + this.#size - 1) & this.#mask;
    const item = this.#buf[i];
    this.#buf[i] = undefined;
    this.#size--;
    return item;
  }
  peekFront(): T | undefined { return this.#size === 0 ? undefined : this.#buf[this.#head]; }
  peekBack(): T | undefined { return this.#size === 0 ? undefined : this.#buf[(this.#head + this.#size - 1) & this.#mask]; }
  // الوصول بالـ index من القدام: ⁦O(1)⁩ برضه، ودي ميزة على الـ linked list
  at(i: number): T | undefined { return i < 0 || i >= this.#size ? undefined : this.#buf[(this.#head + i) & this.#mask]; }

  *[Symbol.iterator](): Iterator<T> {
    for (let i = 0; i < this.#size; i++) yield this.#buf[(this.#head + i) & this.#mask] as T;
  }

  // بنضاعف ونفرد العناصر من head لأول الـ buffer الجديد: ⁦O(n)⁩ مرة كل ما الحجم يتضاعف
  #grow(): void {
    const old = this.#buf, cap = old.length * 2;
    // ملحوظة: ⁦Array.from({ length }, fn)⁩ أبطأ بكتير هنا (اتقاس في alloc.ts)؛ fill بيطلّع HOLEY_ELEMENTS بس من غير holes فعلًا
    const next = new Array<T | undefined>(cap).fill(undefined);
    for (let i = 0; i < this.#size; i++) next[i] = old[(this.#head + i) & this.#mask];
    this.#buf = next;
    this.#head = 0;
    this.#mask = cap - 1;
  }
}

// الـ deque الواحدة تنفع stack أو queue: adapters صغيرة
export const stackOf = <T>(d: Deque<T>): Stack<T> => ({
  push: (x) => d.pushBack(x), pop: () => d.popBack(), peek: () => d.peekBack(), get size() { return d.size; },
});
export const queueOf = <T>(d: Deque<T>): Queue<T> => ({
  enqueue: (x) => d.pushBack(x), dequeue: () => d.popFront(), peek: () => d.peekFront(), get size() { return d.size; },
});

بالعامية

الـ ADT بيقول العمليات معناها إيه، والـ backing بيقول متخزنة إزاي. المفاهيم (LIFO و FIFO وليه الـ array مناسبة للـ stack) في درس 03 في CS Fundamentals، الأجزاء 4 لـ 5. هنا بنكتب 3 interfaces: Stack<T> و Queue<T> و Deque<T>، ولكل واحد طريقتين تخزين:

  • على array. الـ stack هو push/pop: الاتنين بيلمسوا الآخر بس، O(1) amortized. الـ queue عبارة عن array + head index: الـ dequeue بتقرا items[head++] ومش بتعمل shift أبدًا؛ ولما الجزء الميت في الأول يبقى 16 خانة على الأقل ونص الـ array على الأقل، slice واحدة بتنضّفه. كل compaction بتنسخ عناصر حية أقل من اللي اتشالوا من آخر compaction، فالتكلفة فاضلة O(1) amortized. الـ deque على array عادية محتاجة unshift/shift من قدام: O(n) لكل عملية، واتقاست تحت ≈14 µs لكل pushFront و فيه 10⁵ عنصر.
  • على ring. الـ ring buffer بتاع درس 02 (الجزء 5) بس بيكبر: الـ capacity power of two فالـ wrap-around بـ & mask، والـ pushFront بترجّع الـ head لورا ((head - 1) & mask بتلف الـ 0 لآخر خانة)، ولما الـ ring يتملي بيضاعف وينسخ العناصر بالترتيب لأول الـ buffer الجديد. الأربع أطراف O(1) amortized، و at(i) كمان O(1).

Part 2 — The shift() trap, located 🟡 Intermediateالجزء 2 — فخ الـ shift، ومكانه بالظبط

English

Array.prototype.shift() removes index 0, so every remaining element must move one slot left: O(n). V8 usually hides this with left-trimming: instead of moving the elements, it moves the start of the backing store one slot forward and leaves a small filler object in the freed slot, which is O(1). But it does not always do that. In V8 12.4 (the V8 inside Node 22.19), Heap::CanMoveObjectStart returns false when the object is in large-object space, and also while the sampling heap profiler is on, while optimizing-compile jobs are pending, during incremental marking, and while the page is still being swept. Then shift() really moves everything.

Large-object space holds every object above kMaxRegularHeapObjectSize, which is half a 256 KiB V8 page: 128 KiB. A backing store is a 16-byte header plus 8 bytes per slot (64-bit Node, no pointer compression), so it crosses 128 KiB at 16,383 slots. Measured with arrays of exact capacity: 16,382 slots ≈128 ns per shift, 16,383 slots ≈73 µs (≈570× slower). Arrays built with push have spare capacity, so their cliff falls between 15,000 (≈159 ns) and 16,000 elements (≈53 µs). Turning left-trimming off with --no-move-object-start exposes the O(n) at 8,000 already (≈3.7 µs per shift). That is the "≈16k" section 03 observed, now explained.

The same quadratic hides in four shapes of real code, all draining (or filling) a queue of n jobs: while (q.length) q.shift() in a worker or a BFS frontier; q.splice(0, 1); jobs = jobs.slice(1) in an "immutable" reducer, which copies on every step even below the cliff; and q.unshift(urgent) to put a job first. At 50,000 jobs they took ≈2.3 s, ≈5.2 s, ≈3.6 s and ≈0.17 s; a head index took ≈1 ms. Fixes: a head index (ArrayQueue), a ring deque, a library (denque 2.1 is a power-of-two ring; yocto-queue 1.2 is a singly linked list, lesson 03's shape), or take the queue out of the process into Redis.

Part 3 — Queue with two stacks 🟡 Intermediateالجزء 3 — الـ queue من two stacks

English

Two stacks make a queue: enqueue pushes onto an inbox; dequeue pops from an outbox, and only when the outbox is empty does it pour the whole inbox into it, which reverses the order so the oldest item ends up on top. Each item is pushed at most twice (inbox, then outbox) and popped at most twice, so any sequence of m operations does O(m) work: amortized O(1). The formal proof (aggregate, accounting and potential methods) is section 05 · 1.1; here we count.

Over 10⁶ mixed operations, with a burst of 50,000 jobs every 100,000 operations (a nightly import), 1,000,351 items were enqueued and 1,751,117 pushes happened in total: 1.75 per item, under the bound of 2. But the amortized bound hides the distribution: the worst single dequeue took ≈10 ms because it poured 400,626 items at once. One request pays for the previous 400k. The ring deque also has a worst case, a grow that copies the ring (≈3 ms here, and the test confirms the worst op was the grow), but it happens only at each doubling, about log₂ n times in the queue's life. In steady throughput the ring is ≈2× faster at 10⁶ (≈16 vs ≈34 ns per operation).

So why learn it? Because it is the queue you can build from immutable lists: two cons lists, prepend-only, with the same pour. That is the persistent queue of functional languages and of lesson 17, part 2, where a ring buffer isn't an option. And it is a classic interview question that tests whether you understand amortized cost versus worst case.

// طابور (queue) من two stacks: الـ inbox بياخد الجديد، والـ outbox بيطلّع القديم
import type { Queue } from './adts.ts';

export class TwoStackQueue<T> implements Queue<T> {
  readonly #inbox: T[] = [];
  readonly #outbox: T[] = [];
  // عدّاد لكل مرة عنصر بيتحط على stack: مرة في الـ inbox ومرة في الـ outbox، يعني بحد أقصى مرتين
  moves = 0;
  // أكبر pour حصلت في dequeue واحدة: ده الـ latency spike
  worstPour = 0;

  enqueue(item: T): void {
    this.#inbox.push(item);
    this.moves++;
  }

  dequeue(): T | undefined {
    if (this.#outbox.length === 0) this.#pour();
    return this.#outbox.pop();
  }

  peek(): T | undefined {
    if (this.#outbox.length === 0) this.#pour();
    return this.#outbox[this.#outbox.length - 1];
  }

  get size(): number { return this.#inbox.length + this.#outbox.length; }

  // بنصبّ الـ inbox كله في الـ outbox بس لما الـ outbox يفضى: الترتيب بيتعكس فيبقى الأقدم فوق
  #pour(): void {
    const n = this.#inbox.length;
    if (n > this.worstPour) this.worstPour = n;
    while (this.#inbox.length > 0) {
      this.#outbox.push(this.#inbox.pop()!);
      this.moves++;
    }
  }
}

Part 4 — Monotonic stack 🟡 Intermediateالجزء 4 — الـ monotonic stack

English

"For each day, how many days until revenue is higher?" and "for each point in a product's price history, when does the price next drop?" are both next greater element problems. Brute force scans forward from every index. The monotonic stack does it in one pass: the stack holds indexes still waiting for a better value, and their values never get better from bottom to top. Each new element pops every waiting index it beats (it is their answer), then waits itself. Every index is pushed once and popped at most once, so the whole pass is ≤ 2n stack operations: O(n), whatever the data.

The comparator makes it generic: nextBetter(items, better) with (a, b) => a - b finds the next higher revenue, with (a, b) => b - a the next lower price. Equal values are not "better", which the tests pin down, and a model-based test compares it with brute force on 300 random series full of ties.

The benchmark has a lesson of its own. On random revenue, brute force looks fine (≈18–29 ns per element), because the next higher day is usually a few steps away. On a declining trend (a bad quarter: revenue drifting down with noise) almost no day has a higher day after it, every scan runs to the end, and brute force becomes ≈67 µs per element at 10⁵: 6.7 s in total, quadratic. The stack stays ≈10–30 ns per element on both shapes and at 10⁶. Production data has trends; test your algorithm on them, not just on uniform random input.

// الـ monotonic stack: لكل عنصر، أول عنصر بعده "أحسن" منه حسب الـ comparator

    const cur = items[i] as T;
    // العنصر الجديد بيحل مشكلة كل اللي فوق الـ stack وأوحش منه، وكل index بيتعمله pop مرة واحدة بس
    while (stack.length > 0 && better(cur, items[stack[stack.length - 1]!] as T) > 0) {
      answer[stack.pop()!] = i;
    }
    stack.push(i);
  }
  return answer;
}

// لكل يوم: كام يوم لحد أول يوم إيراده أعلى (⁦0 =⁩ مفيش)
export function daysUntilHigherRevenue(revenue: readonly number[]): Int32Array {
  const next = nextBetter(revenue, (a, b) => a - b);
  return next.map((j, i) => (j === -1 ? 0 : j - i));
}

// الـ brute force للمقارنة: لكل i بندوّر لقدام لحد ما نلاقي: ⁦O(n²)⁩ في أسوأ حالة
export function nextBetterBrute<T>(items: readonly T[], better: (a: T, b: T) => number): Int32Array {
  const answer = new Int32Array(items.length).fill(-1);
  for (let i = 0; i < items.length; i++) {
    for (let j = i + 1; j < items.length; j++) {
      if (better(items[j] as T, items[i] as T) > 0) { answer[i] = j; break; }
    }
  }
  return answer;
}

Part 5 — Monotonic deque: sliding-window max 🔴 Advancedالجزء 5 — الـ monotonic deque: أعلى قيمة في window متحركة

English

"The highest price in the last k minutes" or "the worst latency in the last hour" over a stream needs a window that slides by time, not by count: samples arrive irregularly, and after five idle minutes the window must be empty, not full of stale values. SlidingWindowMax keeps a deque of (timestamp, value) pairs whose values decrease from front to back. push(ts, value) first drops from the back every value ≤ the new one (they can never be the max again: the new sample is at least as large and leaves the window later), then appends. max(now) expires from the front every sample with ts ≤ now − windowMs, then returns the front. Every sample enters and leaves once: O(1) amortized per sample, and the deque lives in two Float64Array rings, so nothing is allocated per sample.

Measured on 10⁶ samples (one per second) with k = 60 and k = 3,600, asking for the max after every sample:

  • Naive scan (keep the window, loop over it): ≈0.4–0.5 µs per sample for k = 60, ≈17 µs for k = 3,600 (measured on 10⁵ samples; 10⁶ would take ≈17 s). O(n·k).
  • Heap with lazy deletion (push every sample, discard expired ones only when they reach the top): ≈94–149 ns per sample, O(n log n) here. The catch is memory: an old small value is removed only when it surfaces, so the heap peaked at 831,926 to 1,000,000 entries for a window of 60 or 3,600. It holds almost the whole stream.
  • Monotonic deque: ≈47–55 ns per sample for both windows and both data shapes, O(n), and its size never exceeds the window.

The general sliding-window technique (fixed and variable windows, sums and counts) is section 05 · 1.6; the deque is the piece that makes min/max windows O(1).

// أعلى قيمة في آخر windowMs: deque من (وقت، قيمة) والقيم نازلة من القدام للورا
export class SlidingWindowMax {
  readonly windowMs: number;
  // الـ deque على ring من Float64Array: مفيش allocation لكل sample
  #ts: Float64Array;
  #val: Float64Array;
  #head = 0;
  #size = 0;
  #mask: number;

  constructor(windowMs: number, initialCapacity = 64) {
    if (!(windowMs > 0)) throw new RangeError(`windowMs must be > 0, got ${windowMs}`);
    this.windowMs = windowMs;
    let cap = 1;
    while (cap < initialCapacity) cap *= 2;
    this.#ts = new Float64Array(cap);
    this.#val = new Float64Array(cap);
    this.#mask = cap - 1;
  }

  get size(): number { return this.#size; }

  push(ts: number, value: number): void {
    // (1) أي قيمة في الآخر أصغر من أو تساوي الجديدة عمرها ما هتبقى الـ max تاني: نشيلها
    while (this.#size > 0 && this.#val[(this.#head + this.#size - 1) & this.#mask]! <= value) this.#size--;
    if (this.#size === this.#ts.length) this.#grow();
    const i = (this.#head + this.#size) & this.#mask;
    this.#ts[i] = ts;
    this.#val[i] = value;
    this.#size++;
    this.#expire(ts);
  }

  // الـ ⁦max =⁩ أول عنصر في الـ deque، بعد ما نشيل اللي وقته خرج من الـ window
  max(now: number): number | undefined {
    this.#expire(now);
    return this.#size === 0 ? undefined : this.#val[this.#head];
  }

  // (2) من القدام: اللي أقدم من now - windowMs خرج من الـ window
  #expire(now: number): void {
    const cutoff = now - this.windowMs;
    while (this.#size > 0 && this.#ts[this.#head]! <= cutoff) {
      this.#head = (this.#head + 1) & this.#mask;
      this.#size--;
    }
  }

  #grow(): void {
    const cap = this.#ts.length * 2;
    const ts = new Float64Array(cap), val = new Float64Array(cap);
    for (let k = 0; k < this.#size; k++) {
      const j = (this.#head + k) & this.#mask;
      ts[k] = this.#ts[j]!;
      val[k] = this.#val[j]!;
    }
    this.#ts = ts; this.#val = val; this.#head = 0; this.#mask = cap - 1;
  }
}

export class HeapWindowMax implements WindowMax {

  peakSize = 0;
  constructor(windowMs: number) { this.windowMs = windowMs; }

    if (this.#heap.length > this.peakSize) this.peakSize = this.#heap.length;

Part 6 — Stacks at work 🟢 Basicالجزء 6 — الـ stacks في الشغل

English

Three uses you will write. The basic two-stack undo and a template bracket checker are in CS lesson 03, part 4; these versions add what production needs.

(1) Undo/redo for an invoice editor. Two stacks of commands: run applies a command and pushes it on undo; undo reverts it and moves it to redo; redo re-applies; a new edit clears redo, because those commands were built on a state that no longer exists. New here: the undo history is capped by putting it on the ring deque from Part 1. When it holds limit commands, popFront() drops the oldest in O(1) before the push; an array with shift() would be Part 2's trap again. How commands are designed (inverse operations vs snapshots, serializable commands) is the Command pattern in Design Patterns lesson 13, part 2.

(2) Bracket matching in a pricing-rule language such as (subtotal > 100) && (country in ['EG', 'SA']). Push each opener with its position; each closer must match the top. Two production details: brackets inside string literals are not brackets (coupon == 'SUMMER(25)'), and the error must say where, so the admin UI can put a caret under the problem.

(3) Recursion → iteration. Walking a category tree (or a comment thread) recursively uses one call-stack frame per level. Real data can be deep: a reply chain, a bad import that nests categories 100,000 levels, a cycle bug. On this machine the recursive walk failed at ≈5,500 levels with the real RangeError: Maximum call stack size exceeded. With an explicit stack on the heap, depth is limited by memory, and the 100,000-level chain sums fine. Post-order needs one more idea: the parent's total needs its children's totals first, so each node is visited twice, once to push its children (expanded = true) and once, after they are done, to compute its subtree total. Raising V8's limit (--stack-size) is not a fix: V8 doesn't know how big the OS thread's real stack is. Here, the default threw a catchable RangeError on a 10⁷-deep recursion, while --stack-size=65500 killed the process with Windows' stack-overflow status 0xC00000FD and no JavaScript error at all. The general conversion technique is section 05 · 1.2.

export interface Command {

  revert(inv: Invoice): Invoice;

export class InvoiceHistory {

    this.#state = initial;
    this.limit = limit;
    this.#undo = new RingDeque<Command>(limit);

  get canUndo(): boolean { return this.#undo.size > 0; }

    this.#redo.length = 0;
  }

  undo(): string | undefined {
    const cmd = this.#undo.popBack();
    if (!cmd) return undefined;
    this.#state = cmd.revert(this.#state);
    this.#redo.push(cmd);
    return cmd.label;
  }

  redo(): string | undefined {
    const cmd = this.#redo.pop();
    if (!cmd) return undefined;
    this.#state = cmd.apply(this.#state);
    this.#undo.pushBack(cmd);
    return cmd.label;
  }
}

export type BracketError = { message: string; index: number };

const OPEN: Record<string, string> = { ')': '(', ']': '[' };

export function checkBrackets(rule: string): BracketError | null {
  // الـ stack فيه كل قوس مفتوح ومكانه، عشان رسالة الغلط تقول فين بالظبط
  const open: { ch: string; index: number }[] = [];
  for (let i = 0; i < rule.length; i++) {
    const ch = rule[i]!;
    // الأقواس جوه string literal مش أقواس: نعدّي لحد آخر الـ string
    if (ch === "'" || ch === '"') {
      const end = rule.indexOf(ch, i + 1);
      if (end === -1) return { message: `unterminated string starting at ${i}`, index: i };
      i = end;
    } else if (ch === '(' || ch === '[') open.push({ ch, index: i });
    else if (ch === ')' || ch === ']') {
      const top = open.pop();
      if (top === undefined) return { message: `unexpected '${ch}' at ${i}`, index: i };
      if (top.ch !== OPEN[ch]) return { message: `'${top.ch}' at ${top.index} closed by '${ch}' at ${i}`, index: i };
    }
  }
  const unclosed = open.at(-1);
  return unclosed ? { message: `'${unclosed.ch}' at ${unclosed.index} is never closed`, index: unclosed.index } : null;
}

// الرسالة اللي بتظهر للأدمن في الـ UI: القاعدة وتحتها ^ عند مكان الغلط
export function explain(rule: string): string {
  const err = checkBrackets(rule);
  return err ? `${rule}\n${' '.repeat(err.index)}^ ${err.message}` : 'ok';
}

// شجرة تصنيفات (أو thread تعليقات⁦):⁩ كل node ليها عدد منتجات خاص بيها وأولاد
export type Category = { id: number; ownProducts: number; children: Category[] };

// النسخة الـ recursive: كل مستوى ⁦= frame⁩ على الـ call stack
export function totalRecursive(c: Category): number {
  let sum = c.ownProducts;
  for (const child of c.children) sum += totalRecursive(child);
  return sum;
}

// نفس الشغل بـ explicit stack على الـ heap: العمق بقى محدود بالـ memory مش بالـ call stack
export function totalIterative(root: Category): number {
  let sum = 0;
  const stack: Category[] = [root];
  while (stack.length > 0) {
    const c = stack.pop()!;
    sum += c.ownProducts;
    for (const child of c.children) stack.push(child);
  }
  return sum;
}

// الـ post-order بـ explicit stack: الأب محتاج مجموع أولاده الأول، فكل node بتتزار مرتين
// المرة الأولى بنحط أولادها، والمرة التانية (بعد ما يخلصوا) بنحسب الـ subtree total بتاعها
export function subtreeTotals(root: Category): Map<number, number> {
  const totals = new Map<number, number>();
  const stack: { c: Category; expanded: boolean }[] = [{ c: root, expanded: false }];
  while (stack.length > 0) {
    const top = stack[stack.length - 1]!;
    if (!top.expanded) {
      top.expanded = true;
      for (const child of top.c.children) stack.push({ c: child, expanded: false });
    } else {
      stack.pop();
      let sum = top.c.ownProducts;
      for (const child of top.c.children) sum += totals.get(child.id)!;
      totals.set(top.c.id, sum);
    }
  }
  return totals;
}

// شجرة عميقة جدًا: كل تصنيف جواه تصنيف واحد (زي thread ردود على ردود، أو بيانات import بايظة)
export function deepChain(depth: number): Category {
  const root: Category = { id: 0, ownProducts: 1, children: [] };
  let cur = root;
  for (let i = 1; i < depth; i++) {
    const next: Category = { id: i, ownProducts: 1, children: [] };
    cur.children.push(next);
    cur = next;
  }
  return root;
}

3 استخدامات هتكتبها. الـ undo الأساسي بـ two stacks وفاحص الأقواس للـ templates في درس 03 في CS، الجزء 4؛ النسخ دي بتزود اللي الـ production محتاجه.

(1) الـ undo/redo لمحرر الفواتير. اتنين stacks من الـ commands: الـ run بتطبّق الـ command وتحطه على الـ undo؛ والـ undo بتلغيه وتنقله للـ redo؛ والـ redo بتطبقه تاني؛ وأي تعديل جديد بيمسح الـ redo، لأن الـ commands دي اتبنت على حالة مبقتش موجودة. الجديد هنا: تاريخ الـ undo محدود لأنه على الـ ring deque من الجزء 1. لما يبقى فيه limit command، popFront() بتشيل الأقدم في O(1) قبل الـ push؛ لو array بـ shift() هنرجع لفخ الجزء 2. تصميم الـ commands نفسها (عمليات عكسية ولا snapshots، و commands ينفع تتخزن) هو الـ Command pattern في درس 13 في Design Patterns، الجزء 2.

(2) مطابقة الأقواس في لغة قواعد التسعير زي (subtotal > 100) && (country in ['EG', 'SA']). كل قوس مفتوح بيتعمله push ومعاه مكانه؛ وكل قوس قافل لازم يطابق اللي فوق. تفصيلتين للـ production: الأقواس جوه الـ string literals مش أقواس (coupon == 'SUMMER(25)')، ورسالة الغلط لازم تقول فين، عشان الـ admin UI يحط علامة تحت المشكلة.

(3) تحويل الـ recursion لـ iteration. المشي على شجرة تصنيفات (أو thread تعليقات) بالـ recursion بياخد frame في الـ call stack لكل مستوى. البيانات الحقيقية ممكن تبقى عميقة: سلسلة ردود، import بايظ عمل تصنيفات جوه بعض 100,000 مستوى، أو bug عمل cycle. على الجهاز ده الـ recursive وقعت عند ≈5,500 مستوى بالـ RangeError: Maximum call stack size exceeded الحقيقية. بـ explicit stack على الـ heap، العمق محدود بالـ memory، والسلسلة اللي فيها 100,000 مستوى اتجمعت عادي. الـ post-order محتاجة فكرة زيادة: مجموع الأب محتاج مجاميع أولاده الأول، فكل node بتتزار مرتين، مرة عشان نحط أولادها (expanded = true)، ومرة بعد ما يخلصوا عشان نحسب مجموع الـ subtree بتاعها. ورفع حد الـ V8 (--stack-size) مش حل: الـ V8 مش عارف حجم الـ stack الحقيقي بتاع الـ thread في الـ OS. هنا الـ default رمى RangeError تقدر تمسكها على recursion عمقها 10⁷، بينما --stack-size=65500 قتل الـ process بحالة الـ stack overflow بتاعة Windows (0xC00000FD) من غير أي JavaScript error خالص. تقنية التحويل عمومًا في القسم 05 · 1.2.

فين هستخدمه في شغلي؟ الـ undo بالـ ring: أي editor في الـ admin (فواتير، عروض أسعار، page builder) عايز يحتفظ بآخر 100 خطوة من غير ما الـ memory تكبر مع جلسة شغل طويلة. فاحص الأقواس: validation لقواعد الخصم أو الـ feature flags اللي الـ ops بيكتبوها في الـ dashboard، قبل ما تتحفظ وتكسر الـ checkout. والـ explicit stack: أي endpoint بيلف على بيانات شجرية جاية من users (تعليقات، تصنيفات، org chart، menu builder)، لأن العمق في إيد اللي بيدخّل البيانات مش في إيدك.

// الـ stack ده بيرجّع أقل قيمة فيه في ⁦O(1)⁩: كل خانة شايلة القيمة وأقل قيمة لحد عندها
export class MinStack {
  readonly #values: number[] = [];
  readonly #mins: number[] = [];
  push(v: number): void {
    const below = this.#mins[this.#mins.length - 1];
    this.#values.push(v);
    this.#mins.push(below === undefined || v < below ? v : below);
  }
  pop(): number | undefined { this.#mins.pop(); return this.#values.pop(); }
  min(): number | undefined { return this.#mins[this.#mins.length - 1]; }
  get size(): number { return this.#values.length; }
}

// لكل يوم: كام يوم ورا بعض لحد النهارده إيراده أقل من أو يساوي النهارده (النهارده محسوب)
export function revenueSpan(revenue: readonly number[]): number[] {
  const span: number[] = [];
  // الـ stack فيه أيام قيمتها نازلة: أي يوم أصغر من أو يساوي النهارده اتغطى خلاص
  const stack: number[] = [];
  for (let i = 0; i < revenue.length; i++) {
    while (stack.length > 0 && revenue[stack[stack.length - 1]!]! <= revenue[i]!) stack.pop();
    span.push(stack.length === 0 ? i + 1 : i - stack[stack.length - 1]!);
    stack.push(i);
  }
  return span;
}

3. Sliding-log rate limiter 🔴 hard Allow at most N requests per user in any window of W ms. Keep one deque of accepted timestamps per user; expire from the front, reject when full. Test: 3 per 10 s, the fourth request at t = 3 s is rejected, a request at t = 10 s is allowed again.
اسمح بـ N request بالكتير لكل user في أي window مدتها W ms. احتفظ بـ deque لكل user فيها أوقات الـ requests المقبولة؛ شيل القديم من قدام، وارفض لو مليانة. الـ test: 3 كل 10 ثواني، الـ request الرابع عند 3 ثواني يترفض، و request عند 10 ثواني يتقبل تاني.

Solution · الحل 
// الـ rate limiter بالـ sliding log: لكل user deque فيها أوقات آخر الـ requests المقبولة
import { RingDeque } from '../l04/adts.ts';

export class SlidingLogLimiter {
  readonly limit: number;
  readonly windowMs: number;
  readonly #logs = new Map<string, RingDeque<number>>();
  constructor(limit: number, windowMs: number) { this.limit = limit; this.windowMs = windowMs; }

  allow(userId: string, now: number): boolean {
    let log = this.#logs.get(userId);
    if (log === undefined) { log = new RingDeque<number>(this.limit); this.#logs.set(userId, log); }
    // نشيل من القدام كل وقت خرج من الـ window: كل timestamp بيدخل ويطلع مرة واحدة
    while (log.size > 0 && log.peekFront()! <= now - this.windowMs) log.popFront();
    if (log.size >= this.limit) return false;
    log.pushBack(now);
    return true;
  }
}
test('sliding log limiter: 3 requests per 10 s per user', () => {
  const rl = new SlidingLogLimiter(3, 10_000);
  assert.deepEqual([0, 1_000, 2_000, 3_000].map((t) => rl.allow('u-1', t)), [true, true, true, false]);
  assert.equal(rl.allow('u-2', 3_000), true);
  // عند 10,000 أول ⁦request (⁩وقت 0) خرج من الـ window
  assert.equal(rl.allow('u-1', 10_000), true);
  assert.equal(rl.allow('u-1', 10_500), false);
});

Cheat sheet · الخلاصة

  • Stack on an array: push/pop, O(1) amortized. Queue on an array: head index + compaction when the dead prefix passes half, never shift.
  • Deque: a plain array pays O(n) at the front (unshift ≈14 µs at 10⁵); a growable power-of-two ring makes all four ends amortized O(1).
  • shift() is O(1) only while V8 can left-trim: never in large-object space, i.e. backing stores > 128 KiB = more than 16,382 slots. Push-built arrays hit it between 15k and 16k items.
  • Hidden O(n²): while (q.length) q.shift(), splice(0, 1), jobs = jobs.slice(1), unshift for urgent jobs.
  • 200k jobs with shift() = minutes of blocked event loop; any O(1) queue (head index, ring, denque, yocto-queue) does it in ≈40–50 ms. Shared or durable queue → Redis RPUSH + BLMOVE.
  • Two-stack queue: ≤ 2 moves per item, amortized O(1), but one dequeue can pour everything (≈10 ms for 400k). Use it for immutable/persistent queues.
  • Monotonic stack = next/previous greater or smaller element in O(n); each index is pushed and popped once. Brute force looks fine on random data and goes quadratic on trends.
  • Monotonic deque = sliding-window max/min in O(1) amortized; window by timestamp for metrics; a lazy-deletion heap can hold the whole stream.
  • Undo/redo = two stacks, a new edit clears redo, cap history with a ring (popFront the oldest).
  • Brackets: stack of (char, index), skip string literals, report the position.
  • Recursion over user-controlled depth → explicit stack (≈5.5k levels was the recursive limit here); post-order with an expanded flag.
بالعامية
  • الـ stack على array: push/pop، O(1) amortized. الـ queue على array: head index + compaction لما الجزء الميت يعدّي النص، ومفيش shift أبدًا.
  • الـ deque: الـ array العادية بتدفع O(n) من قدام (unshift ≈14 µs عند 10⁵)؛ والـ ring اللي بيكبر بـ power of two بيخلّي الأربع أطراف O(1) amortized.
  • الـ shift() بتبقى O(1) بس طول ما الـ V8 يقدر يعمل left-trim: وده مستحيل في الـ large-object space، يعني backing store أكبر من 128 KiB = أكتر من 16,382 خانة. الـ arrays المبنية بـ push بتوصله بين 15 و 16 ألف عنصر.
  • الـ O(n²) المستخبية: while (q.length) q.shift()، و splice(0, 1)، و jobs = jobs.slice(1)، و unshift للـ jobs المستعجلة.
  • 200 ألف job بـ shift() = دقايق والـ event loop واقف؛ أي queue بـ O(1) (head index، ring، denque، yocto-queue) بتخلّصها في ≈40 لـ 50 ms. ولو الطابور مشترك أو لازم يعيش → Redis بـ RPUSH + BLMOVE.
  • الـ queue بـ two stacks: نقلتين بالكتير لكل عنصر، amortized O(1)، بس dequeue واحدة ممكن تصبّ كل حاجة (≈10 ms لـ 400 ألف). استخدمها للـ queues الـ immutable/persistent.
  • الـ monotonic stack = أول عنصر أكبر أو أصغر (قدام أو ورا) في O(n)؛ كل index بيتعمله push و pop مرة. الـ brute force باين كويس على بيانات عشوائية وبيبقى O(n²) مع الـ trends.
  • الـ monotonic deque = أعلى أو أقل قيمة في sliding window في O(1) amortized؛ الـ window بالـ timestamp للـ metrics؛ والـ heap بالحذف الكسلان ممكن يشيل الـ stream كله.
  • الـ undo/redo = اتنين stacks، والتعديل الجديد بيمسح الـ redo، وحدّد التاريخ بـ ring (popFront للأقدم).
  • الأقواس: stack من (حرف، مكان)، وعدّي على الـ string literals، وقول مكان الغلط.
  • الـ recursion على عمق في إيد الـ user → explicit stack (الحد هنا كان ≈5.5 ألف مستوى)؛ والـ post-order بعلامة expanded.
