Why this matters · ليه ده مهم

English

A Node round tests whether you understand what your runtime does: which queue runs next, what stops a fast producer, where an error goes once it leaves your stack. Senior candidates get the same questions as everyone else plus "and what breaks?". This lesson drills them as timed exercises: six output predictions run for real, the classic stream and async bugs, then four primitives from scratch with tests. You've read the theory in section 04. Part 1 — Output prediction 🟡 Intermediateالجزء 1 — توقّع الـ output

English
⏱ Timed prompt · 18 minutes (3 per snippet) Six snippets below. For each, on paper: name the queues involved, write the order, and state whether your answer depends on CommonJS or ESM. Don't run them until you've written all six.
⏱ التمرين بالتوقيت: 18 دقيقة (3 لكل snippet). فيه 6 snippets تحت. لكل واحد، على ورقة: سمّي الـ queues اللي داخلين في الموضوع، واكتب الترتيب، وقول إجابتك معتمدة على CommonJS ولا ESM. متشغلهمش غير لما تكتب الستة.

Brute force, for this one, is guessing: memorizing the order of a snippet you saw once, which is what breaks the moment a callback is nested. There's no complexity to measure here; the model answer is a method.

The answer format. Name the queues first, then walk through them, and ask "is this CommonJS or ESM?". The queues: synchronous code, the process.nextTick queue, the promise microtask queue, then the loop's phases. Since libuv 1.45 (Node 20) timers run once before the loop starts and then at the end of each iteration, after poll and check. See the event loop lesson and event loop and promises for the full model. After every macrotask callback, Node drains nextTick and then microtasks.

Why the module format changes the answer. A CommonJS file finishes, then Node processes the nextTick queue, then microtasks: tick comes before promise. An ES module body is already running inside a promise job, so when it ends V8 keeps draining microtasks first: promise comes before tick. Snippets 1 and 2 show it. Inside a timer or I/O callback we're back to the Node rule: tick, then promises, in both formats.

The two timing questions. Inside an I/O callback, setImmediate wins every time: poll is followed by check, and timers come after. From the main module, setTimeout(0) against setImmediate isn't defined: setTimeout(fn, 0) really means 1 ms, and it depends on whether that 1 ms has passed when the timers pass runs. So the honest answer to that pair is "either", and I show a 20-run count instead of one run.

Part 2 — Streams 🟡 Intermediateالجزء 2 — الـ streams

English
⏱ Timed prompt · 15 minutes Copy a large invoice archive to a destination slower than your disk. Memory must stay flat however big the file is. Then answer: what happens if you ignore the return value of write(), and what happens to the destination if the source fails halfway?
⏱ التمرين بالتوقيت: 15 دقيقة. انسخ أرشيف فواتير كبير لوجهة أبطأ من الـ disk بتاعك. الذاكرة لازم تفضل ثابتة مهما كبر الملف. وبعدها جاوب: إيه اللي بيحصل لو تجاهلت قيمة write()، وإيه اللي بيحصل للوجهة لو المصدر وقع في النص؟

Brute force first. readFile: memory is O(file size), buffered in full before the first byte moves. Claim before measuring: peak memory doubles with the file. A stream with a data handler looks better and isn't, if it ignores backpressure: the source reads as fast as the disk allows, and bytes pile up inside the destination's buffer, so memory is still O(file).

Final: pipeline. write() returns false when the buffer passes highWaterMark. pipeline pauses the source until drain, so at most about one highWaterMark sits in memory: O(1) in file size. Theory is in streams and backpressure. The measured doubling below: ignored buffers 30.69, then 61.50, then 124.31 MiB while pipeline stays at 0.06 MiB, and RSS climbs to about 191 MB against 82 MB.

Errors. .pipe forwards data, not errors: when the source fails, the destination is left open, its file descriptor leaking until the process exits. pipeline destroys every stream in the chain and rejects with the error. The run below shows both.

import { createReadStream } from "node:fs";
import { readFile } from "node:fs/promises";
import { Writable } from "node:stream";
import { pipeline } from "node:stream/promises";

const [, , mode, archivePath] = process.argv;

const rssMb = () => Math.round(process.memoryUsage().rss / 1024 / 1024);
let peakBufferedBytes = 0;
let peakRssMb = rssMb();
const sampler = setInterval(() => {
  peakRssMb = Math.max(peakRssMb, rssMb());
}, 20);

// الوجهة بطيئة عن قصد: chunk كل 2 ms، زي upload على شبكة
const destination: Writable = new Writable({
  highWaterMark: 64 * 1024,
  write(_chunk, _encoding, done) {
    peakBufferedBytes = Math.max(peakBufferedBytes, destination.writableLength);
    setTimeout(done, 2);
  },
});

if (mode === "readFile") {
  // أبسط حل: الملف كله في الذاكرة مرة واحدة
  const whole = await readFile(archivePath);
  peakBufferedBytes = whole.length;
  peakRssMb = Math.max(peakRssMb, rssMb());
  destination.destroy();
} else if (mode === "ignored") {
  // الغلطة: قيمة write متجاهلة، فالمصدر بيفضل يكتب أسرع من الوجهة
  await new Promise<void>((resolve, reject) => {
    const source = createReadStream(archivePath);
    source.on("data", (chunk) => {
      destination.write(chunk);
    });
    source.on("end", () => destination.end());
    source.on("error", reject);
    destination.on("error", reject);
    destination.on("finish", resolve);
  });
} else {
  // الحل: الـ pipeline بيوقف المصدر لما write ترجع false ويكمّله عند drain
  await pipeline(createReadStream(archivePath), destination);
}

clearInterval(sampler);
console.log(`${mode.padEnd(9)} peak buffered=${(peakBufferedBytes / 1024 / 1024).toFixed(2).padStart(7)} MiB   peak RSS≈${String(peakRssMb).padStart(4)} MB`);

بالعامية

Brute force first. Polling: while the count is full, wait a turn of the loop and check again. With n waiters each poll is O(n) work, and the queue drains over n turns: O(n²), x4. It also isn't FIFO: whoever polls at the right moment gets in.

Final. A count of permits and a queue of waiters. acquire takes a permit if one is free, otherwise it enqueues a resolver and returns a pending promise. release hands the permit straight to the first waiter and doesn't increment the count, so a newcomer can't barge in: FIFO is a guarantee, not a hope. Each operation is O(1): x2. The pattern is in locks, batching and actors. What's new here is the 20-minute version and its tests.

Two details. release belongs in finally: that's the whole point of withPermit, because otherwise one throw leaks a permit forever. And the queue isn't an array with shift(): draining with shift() measured ≈344 ms, ≈1.4 s and ≈4.5 s at 20k, 40k and 80k here, roughly x4 per doubling, against under a millisecond with a head index. The Fifo class is 15 lines.

Follow-up: cancel a waiter. On abort, mark the waiter cancelled and reject its promise. release skips cancelled waiters. That's O(1) for the abort, and each one is skipped once. Removing the listener on grant matters too: otherwise every grant leaves a listener on a long-lived signal.

// طابور بـ head index: الـ shift على array كبيرة ⁦O(n)⁩، وده هيأذيك مع آلاف الـ waiters
export class Fifo<T> {
  private items: (T | undefined)[] = [];
  private head = 0;

  get length(): number {
    return this.items.length - this.head;
  }

  push(item: T): void {
    this.items.push(item);
  }

  peek(): T | undefined {
    return this.items[this.head];
  }

  shift(): T | undefined {
    if (this.head === this.items.length) return undefined;
    const item = this.items[this.head];
    this.items[this.head++] = undefined;
    // الضغط لما النص يبقى فاضي: كل عنصر بيتنقل مرات قليلة، فالتكلفة ⁦amortized O(1)⁩
    if (this.head > 1024 && this.head * 2 > this.items.length) {
      this.items = this.items.slice(this.head);
      this.head = 0;
    }
    return item;
  }
}

export class PollingSemaphore {
  private used = 0;
  private readonly limit: number;
  private readonly tick: () => void;

  constructor(limit: number, tick: () => void = () => {}) {
    this.limit = limit;
    this.tick = tick;
  }

  async withPermit<T>(task: () => Promise<T>): Promise<T> {
    for (;;) {
      this.tick();
      if (this.used < this.limit) break;
      await nextTurn();
    }
    this.used++;
    try {
      return await task();
    } finally {
      this.used--;
    }
  }
}
import { Fifo } from "./fifo.ts";

type Waiter = { grant: () => void; cancelled: boolean };

export class Semaphore {
  private permits: number;
  private readonly maxPermits: number;
  private readonly waiters = new Fifo<Waiter>();
  private readonly tick: () => void;

  constructor(permits: number, tick: () => void = () => {}) {
    if (!Number.isInteger(permits) || permits < 1) throw new RangeError(`permits must be a positive integer, got ${permits}`);
    this.permits = permits;
    this.maxPermits = permits;
    this.tick = tick;
  }

  get available(): number {
    return this.permits;
  }

  acquire(signal?: AbortSignal): Promise<void> {
    this.tick();
    if (signal?.aborted) return Promise.reject(signal.reason);
    if (this.permits > 0) {
      this.permits--;
      return Promise.resolve();
    }
    return new Promise<void>((resolve, reject) => {
      const onAbort = () => {
        // مسح كسول: الـ waiter بيفضل في الطابور، و release هتعدّيه
        waiter.cancelled = true;
        reject(signal?.reason);
      };
      const waiter: Waiter = {
        cancelled: false,
        grant: () => {
          signal?.removeEventListener("abort", onAbort);
          resolve();
        },
      };
      signal?.addEventListener("abort", onAbort, { once: true });
      this.waiters.push(waiter);
    });
  }

  release(): void {
    this.tick();
    // التسليم مباشر للي عليه الدور: الـ permits مش بتزيد، فمفيش حد يخطف الدور
    for (let waiter = this.waiters.shift(); waiter; waiter = this.waiters.shift()) {
      if (waiter.cancelled) continue;
      waiter.grant();
      return;
    }
    if (this.permits === this.maxPermits) throw new Error("release without a matching acquire");
    this.permits++;
  }

  async withPermit<T>(task: () => Promise<T>, signal?: AbortSignal): Promise<T> {
    await this.acquire(signal);
    try {
      return await task();
    } finally {
      // الـ finally هو الضمان الوحيد إن الـ permit يرجع لو الـ task وقعت
      this.release();
    }
  }
}

Brute force first. An unbounded array and a polling consumer. Peak depth grows with n, so a fast producer can eat all memory: x2 per doubling in peak depth, with no upper limit. The final's depth is O(capacity): it should print x1.

Final. Three queues: buffer, waiting senders, waiting receivers. send hands off to a waiting receiver if there is one, otherwise it fills the buffer if there's room, otherwise it waits. receive takes from the buffer and immediately moves the first waiting sender's item in, so order stays FIFO and depth never exceeds capacity. The patterns are in producers, pipelines and worker pools.

Close, stated. Items already in the buffer are delivered. Senders still waiting get a ChannelClosedError, so nothing is dropped silently, and waiting receivers are woken with done: true. That's why the signature is IteratorResult: undefined can't double as "closed", because T might be undefined.

Follow-up: capacity 0 is a rendezvous, a direct hand-off, and the same code handles it.

// الـ brute force: array من غير حد، والـ consumer بيعمل polling
export class UnboundedQueue<T> {
  private readonly items: T[] = [];
  private finished = false;

  get depth(): number {
    return this.items.length;
  }

  push(item: T): void {
    this.items.push(item);
  }

  finish(): void {
    this.finished = true;
  }

  async pull(): Promise<T | undefined> {
    for (;;) {
      if (this.items.length > 0) return this.items.shift();
      if (this.finished) return undefined;
      await nextTurn();
    }
  }
}

export class ChannelClosedError extends Error {
  override readonly name = "ChannelClosedError";
}

type PendingSend<T> = { value: T; resolve: () => void; reject: (error: unknown) => void };
type PendingReceive<T> = (result: IteratorResult<T, undefined>) => void;

const DONE = { value: undefined, done: true } as const;

// الـ policy عند الـ close: اللي في الـ buffer بيتسلّم، واللي مستني يبعت بياخد error
export class Channel<T> implements AsyncIterable<T> {
  private readonly buffer = new Fifo<T>();
  private readonly senders = new Fifo<PendingSend<T>>();
  private readonly receivers = new Fifo<PendingReceive<T>>();
  private readonly capacity: number;
  private closed = false;

  constructor(capacity: number) {
    if (!Number.isInteger(capacity) || capacity < 0) throw new RangeError(`capacity must be >= 0, got ${capacity}`);
    this.capacity = capacity;
  }

  get depth(): number {
    return this.buffer.length;
  }

  send(value: T): Promise<void> {
    if (this.closed) return Promise.reject(new ChannelClosedError("send on a closed channel"));
    // لو فيه receiver مستني، التسليم مباشر ومفيش حاجة تدخل الـ buffer
    const receiver = this.receivers.shift();
    if (receiver) {
      receiver({ value, done: false });
      return Promise.resolve();
    }
    if (this.buffer.length < this.capacity) {
      this.buffer.push(value);
      return Promise.resolve();
    }
    // ده الـ backpressure: الـ await عند الـ producer مش بيرجع لحد ما يبقى فيه مكان
    return new Promise<void>((resolve, reject) => this.senders.push({ value, resolve, reject }));
  }

  receive(): Promise<IteratorResult<T, undefined>> {
    if (this.buffer.length > 0) {
      const value = this.buffer.shift() as T;
      // مكان فضي في الـ buffer: أول sender مستني يدخل، والترتيب يفضل FIFO
      const sender = this.senders.shift();
      if (sender) {
        this.buffer.push(sender.value);
        sender.resolve();
      }
      return Promise.resolve({ value, done: false });
    }
    // هنا الحالة بتاعة capacity صفر: التسليم يد بيد من الـ sender
    const sender = this.senders.shift();
    if (sender) {
      sender.resolve();
      return Promise.resolve({ value: sender.value, done: false });
    }
    if (this.closed) return Promise.resolve(DONE);
    return new Promise((resolve) => this.receivers.push(resolve));
  }

  close(): void {
    if (this.closed) return;
    this.closed = true;
    for (let receiver = this.receivers.shift(); receiver; receiver = this.receivers.shift()) receiver(DONE);
    for (let sender = this.senders.shift(); sender; sender = this.senders.shift()) {
      sender.reject(new ChannelClosedError("channel closed while waiting to send"));
    }
  }

  [Symbol.asyncIterator](): AsyncIterator<T, undefined> {
    return { next: () => this.receive() };
  }
}

Brute force first. Filter the whole log on every request: O(window size) per call, so n requests in one window are O(n²): x4.

Final: a sliding log. Timestamps are appended in order, so the expired ones are always at the front. Pop them until the first live one: each timestamp is pushed once and popped once, so it's amortized O(1) per request, x2. Note the boundary: a hit at time 0 with a 1,000 ms window still counts at 999 and has left the window at 1,000. See the rate limiter pattern lesson.

The race. Put any await between "how many so far?" and "record this one", and concurrent callers all pass the check before anyone records. The test below shows 20 callers against a limit of 5, and all 20 get through. The fix is to make check-and-record synchronous, with nothing to interleave. That holds for one process only. Across instances the same fix has to live in Redis, as one atomic operation, because a read followed by a write is the identical race on a network.

Trade-off: log against counter. A sliding log stores up to limit timestamps per key. A sliding counter (a current and a previous fixed window, weighted by overlap) stores three numbers, but it's approximate. In the run: 100 requests at t=59s, then at t=78s the log allows 0 of 40 and the counter allows 30.

export class FilterAllLimiter {

  private readonly limit: number;
  private readonly windowMs: number;
  private readonly now: () => number;
  private readonly tick: () => void;

    this.windowMs = windowMs;
    this.now = now;
    this.tick = tick;

export type AcquireResult = { allowed: boolean; retryAfterMs: number };

export class SlidingLogLimiter {
  private readonly logs = new Map<string, Fifo<number>>();
  private readonly limit: number;
  private readonly windowMs: number;
  private readonly now: () => number;
  private readonly tick: () => void;

  constructor(limit: number, windowMs: number, now: () => number = Date.now, tick: () => void = () => {}) {
    this.limit = limit;
    this.windowMs = windowMs;
    this.now = now;
    this.tick = tick;
  }

  // الدالة متزامنة عن قصد: مفيش await بين الفحص والتسجيل، فمفيش interleaving
  tryAcquire(apiKey: string): AcquireResult {
    const now = this.now();
    let log = this.logs.get(apiKey);
    if (!log) {
      log = new Fifo<number>();
      this.logs.set(apiKey, log);
    }
    // الـ log مترتب بالوقت، فبنشيل من الأول لحد أول timestamp لسه جوه الـ window
    for (let oldest = log.peek(); oldest !== undefined && oldest <= now - this.windowMs; oldest = log.peek()) {
      this.tick();
      log.shift();
    }
    this.tick();
    if (log.length >= this.limit) {
      return { allowed: false, retryAfterMs: (log.peek() as number) + this.windowMs - now };
    }
    log.push(now);
    return { allowed: true, retryAfterMs: 0 };
  }
}

export class SlidingCounterLimiter {
  private readonly counters = new Map<string, { windowStart: number; current: number; previous: number }>();
  private readonly limit: number;
  private readonly windowMs: number;
  private readonly now: () => number;

  constructor(limit: number, windowMs: number, now: () => number) {
    this.limit = limit;
    this.windowMs = windowMs;
    this.now = now;
  }

  tryAcquire(apiKey: string): boolean {
    const now = this.now();
    const windowStart = Math.floor(now / this.windowMs) * this.windowMs;
    const state = this.counters.get(apiKey) ?? { windowStart, current: 0, previous: 0 };
    if (state.windowStart !== windowStart) {
      state.previous = state.windowStart === windowStart - this.windowMs ? state.current : 0;
      state.current = 0;
      state.windowStart = windowStart;
    }
    this.counters.set(apiKey, state);
    const previousWeight = 1 - (now - windowStart) / this.windowMs;
    if (state.previous * previousWeight + state.current >= this.limit) return false;
    state.current++;
    return true;
  }
}

Brute force first. The same fixed delay for everyone, and every error retried, including a 400 that will fail forever. The damage isn't in the complexity, which is O(attempts) in both versions: it's that clients retry at the same instant. Claim: peak retries per tick equal the number of clients.

Final. Exponential backoff with full jitter: wait a random time between 0 and min(cap, base · 2^(attempt-1)). With rand fixed at 0.5 and base 100, the waits are 50, then 100. The caller supplies isRetryable, because only the caller knows whether a retry is safe: a POST without an idempotency key isn't. Abort: check the signal before each attempt and pass it to the sleep. Retry-After is a floor, and I add jitter on top so a thousand clients told "come back in 2 seconds" don't all return at the same moment.

Background in retry, timeout and fallback and timeouts and retry storms. Here, the point is the injected sleep and random: the whole test runs instantly, and every wait is exact.

The simulation. 1,000 clients fail at t=0 and retry three times. Fixed delay and plain exponential both put all 1,000 retries in the same 10 ms tick. Full jitter's worst tick has about 155. Total retries are identical: what changes is the peak the failing service has to survive, and that's what decides whether it recovers.

import { setTimeout as delay } from "node:timers/promises";

// الـ brute force: نفس الـ delay لكل الناس، وكل error بيتعاد حتى لو 400
export async function retryFixed<T>(operation: () => Promise<T>, attempts: number, delayMs: number): Promise<T> {
  for (let attempt = 1; ; attempt++) {
    try {
      return await operation();
    } catch (error) {
      if (attempt === attempts) throw error;
      await delay(delayMs);
    }
  }
}
import { setTimeout as delay } from "node:timers/promises";

export type RetryOptions = {
  maxAttempts: number;
  baseMs: number;
  capMs: number;
  // الـ caller هو اللي يقرر: الـ POST من غير idempotency key مش آمن يتعاد
  isRetryable: (error: unknown) => boolean;
  // الوقت اللي السيرفر طلبه، لو طلب
  retryAfterMs?: (error: unknown) => number | undefined;
  signal?: AbortSignal;
  // دول متحقنين عشان الـ test يبقى لحظي ومحدد
  sleep?: (ms: number, signal?: AbortSignal) => Promise<unknown>;
  random?: () => number;
};

const defaultSleep = (ms: number, signal?: AbortSignal) => delay(ms, undefined, { signal });

export async function retry<T>(operation: (attempt: number) => Promise<T>, options: RetryOptions): Promise<T> {
  const { maxAttempts, baseMs, capMs, isRetryable, retryAfterMs, signal, sleep = defaultSleep, random = Math.random } = options;

  for (let attempt = 1; ; attempt++) {
    signal?.throwIfAborted();
    try {
      return await operation(attempt);
    } catch (error) {
      if (attempt >= maxAttempts || !isRetryable(error) || signal?.aborted) throw error;
      // الـ full jitter: أي رقم بين صفر والسقف، وده اللي بيفرّق الـ clients عن بعض
      const ceiling = Math.min(capMs, baseMs * 2 ** (attempt - 1));
      const jitter = Math.floor(random() * ceiling);
      // الـ Retry-After حد أدنى، والـ jitter فوقه عشان متجيش كل الـ clients في نفس اللحظة
      const hinted = retryAfterMs?.(error);
      await sleep(hinted === undefined ? jitter : hinted + jitter, signal);
    }
  }
}

// الـ header بييجي إما عدد ثواني أو تاريخ HTTP
export function parseRetryAfter(header: string | null, nowMs: number): number | undefined {
  if (header === null) return undefined;
  if (/^\d+$/.test(header.trim())) return Number(header.trim()) * 1000;
  const at = Date.parse(header);
  return Number.isNaN(at) ? undefined : Math.max(0, at - nowMs);
}

const makeRandom = (seed: number) => () => {
  seed = (seed + 0x6d2b79f5) | 0;
  let t = Math.imul(seed ^ (seed >>> 15), 1 | seed);
  t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
  return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
};

const BASE_MS = 100;
const CAP_MS = 2_000;
const ATTEMPTS = 4;
const TICK_MS = 10;

type Delay = (attempt: number) => number;

function simulate(clients: number, nextDelay: Delay): { total: number; peak: number; busyTicks: number } {
  const perTick = new Map<number, number>();
  let total = 0;
  for (let client = 0; client < clients; client++) {
    let at = 0;
    for (let attempt = 1; attempt < ATTEMPTS; attempt++) {
      at += nextDelay(attempt);
      const tick = Math.floor(at / TICK_MS);
      perTick.set(tick, (perTick.get(tick) ?? 0) + 1);
      total++;
    }
  }
  return { total, peak: Math.max(...perTick.values()), busyTicks: perTick.size };
}

const ceiling = (attempt: number) => Math.min(CAP_MS, BASE_MS * 2 ** (attempt - 1));
const random = makeRandom(14);

  ["exponential", (attempt) => ceiling(attempt)],
  ["full jitter", (attempt) => Math.floor(random() * ceiling(attempt))],
];

Interview question "When should you not retry?" → When it isn't safe: a non-idempotent write with no idempotency key. When it won't help: a 4xx that isn't 429. When you're out of budget: the total deadline has passed or the caller aborted. And when the whole system is overloaded, retries from many callers need a budget or they turn an outage into a storm.

  // نفس فكرة الـ semaphore: المسح كسول، والـ sender الملغي بيتعدّى وقت الدور
  private nextSender(): PendingSend<T> | undefined {
    for (let sender = this.senders.shift(); sender; sender = this.senders.shift()) {
      if (!sender.cancelled) return sender;
    }
    return undefined;
  }

  send(value: T, signal?: AbortSignal): Promise<void> {
    if (signal?.aborted) return Promise.reject(signal.reason);
    if (this.closed) return Promise.reject(new ChannelClosedError("send on a closed channel"));
    const receiver = this.receivers.shift();
    if (receiver) {
      receiver({ value, done: false });
      return Promise.resolve();
    }
    if (this.buffer.length < this.capacity) {
      this.buffer.push(value);
      return Promise.resolve();
    }
    return new Promise<void>((resolve, reject) => {
      const onAbort = () => {
        pending.cancelled = true;
        reject(signal?.reason);
      };
      const pending: PendingSend<T> = {
        value,
        cancelled: false,
        reject,
        resolve: () => {
          signal?.removeEventListener("abort", onAbort);
          resolve();
        },
      };
      signal?.addEventListener("abort", onAbort, { once: true });
      this.senders.push(pending);
    });
  }

Cheat sheet · الخلاصة

  • Output prediction: name the queues, walk them, ask CJS or ESM. CJS: tick before promise. ESM body: promise before tick.
  • Inside an I/O callback, setImmediate beats setTimeout(0) every time. From the main module, it isn't defined.
  • Streams: ignoring write() makes memory O(file). pipeline stays near highWaterMark and destroys all streams on error.
  • Async: never forEach(async). Unhandled rejections exit with code 1. return await inside try. Promise.all doesn't cancel the rest.
  • Semaphore: count plus FIFO queue, hand off directly, release in finally, abort marks and skips.
  • Channel: buffer plus waiting senders and receivers. Close: buffer drains, senders error, receivers done.
  • Sliding log: pop expired from the front, amortized O(1). No await between check and record; across servers, one atomic operation.
  • Log against counter: exact and O(limit) per key, or 3 numbers and approximate.
  • Retry: full jitter, cap, retry only what's safe, abort, Retry-After as a floor plus jitter. Inject sleep and random.
بالعامية
  • توقّع الـ output: سمّي الـ queues، وامشي عليها، واسأل CJS ولا ESM. الـ CJS: tick قبل promise. جسم الـ ESM: promise قبل tick.
  • جوه I/O callback، setImmediate بيكسب setTimeout(0) كل مرة. من الـ main module، مش متحدد.
  • الـ streams: تجاهل write() بيخلي الذاكرة O(الملف). الـ pipeline بيفضل قريب من highWaterMark وبيدمّر كل الـ streams عند الـ error.
  • الـ async: عمرك ما تعمل forEach(async). الـ unhandled rejection بيخرج بـ code 1. return await جوه try. Promise.all مش بيلغي الباقي.
  • الـ semaphore: عداد وطابور FIFO، وتسليم مباشر، و release في finally، والـ abort بيعلّم وبيعدّي.
  • الـ channel: buffer و senders و receivers مستنيين. الـ close: الـ buffer بيخلص، والـ senders error، والـ receivers done.
  • الـ sliding log: شيل المنتهيين من الأول، amortized O(1). مفيش await بين الفحص والتسجيل؛ وعلى سيرفرات كتير عملية ذرية واحدة.
  • الـ log ضد الـ counter: دقيق و O(limit) لكل key، أو 3 أرقام وتقريبي.
  • الـ retry: full jitter، وسقف، وأعد بس على الآمن، و abort، و Retry-After حد أدنى وفوقه jitter. احقن الـ sleep والـ random.
