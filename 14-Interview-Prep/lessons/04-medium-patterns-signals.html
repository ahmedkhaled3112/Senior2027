Why this matters · ليه ده مهم

English

A Medium is rarely hard to code once you know which idea applies. The hard part is the first five minutes: reading a prompt that is dressed up as orders or invoices and working out what it really is. Candidates who grind problems without naming why each one belongs to its pattern can solve what they've seen and freeze on what they haven't. This lesson builds the signal table for all 14 README categories, drills the linear ones on the clock, and sets up a schedule that brings your mistakes back until they stop being mistakes. At work the skill is the same: recognizing that a slow report is really an interval merge or that a retry storm is a queue problem.

English

A signal is a feature of the prompt that makes one idea likely. The table covers all 14 README categories. This lesson drills the linear ones (hashing, two pointers, windows, stack, binary search, intervals, greedy), and the next lesson does the rest. Together they are the README's Medium set, which you still do on the site itself.

To test how far words alone go, classify.ts turns the table into regular expressions and guesses a pattern for 12 fictional prompts whose answers were assigned by hand first. The keyword lists were written once and not tuned against these prompts. The most hits wins, ties go to the first row, and zero hits means unknown.

It agrees on 9 of 12, and the three misses are the useful part. The org-chart prompt has no tree word in it, because "manager" and "employee" are domain vocabulary and you only see a tree when you notice each employee has one manager. The voucher prompt says "least number" where the list has "fewest": a synonym, and that is a DP prompt. The streak prompt is confidently wrong: "consecutive" fires the sliding-window rule, but it means consecutive values in unsorted input, not neighbouring positions, so the right tool is a hash set. Keywords tell you where to look first. The decision comes from the shape of the data: is it ordered, is it contiguous, does each item have one parent, does a shorter answer imply a longer one?

// أعلى عدد matches بيكسب، والتعادل للأول في الجدول، وصفر يبقى unknown
export function classify(prompt: string): Guess {
  const text = prompt.toLowerCase();
  let best: Guess = "unknown";
  let bestHits = 0;
  for (const [pattern, signals] of Object.entries(SIGNALS)) {
    const hits = signals.filter((signal) => signal.test(text)).length;
    if (hits > bestHits) {
      best = pattern;
      bestHits = hits;
    }
  }
  return best;
}

Part 2 — Hashing 🟡 Intermediateالجزء 2 — الـ Hashing

⏱ Timed prompts · 25 minutes each
  1. Group orders by basket. Each order is a list of SKUs. Two orders belong together if they hold the same SKUs with the same quantities, in any order. Return the groups of order indices.
  2. Longest order streak. You get the days a customer ordered, as integers, unsorted and possibly repeated. Return the length of the longest run of consecutive days.
  1. جمّع الـ orders بالسلة: كل order عبارة عن list من الـ SKUs. الـ orderين يبقوا مع بعض لو فيهم نفس الـ SKUs بنفس الكميات، بأي ترتيب. رجّع المجموعات كـ indices.
  2. أطول سلسلة أيام: عندك الأيام اللي عميل طلب فيها كأرقام صحيحة، مش مترتبة وممكن تتكرر. رجّع طول أطول سلسلة أيام ورا بعض.
English

Drill 1. Signal: "group things that are the same under some view". The brute force compares each order with every existing group: O(n²) comparisons when all baskets differ, plus the key cost. The fix is a Map from a canonical key to the group, so the design question becomes which key. Sorting the SKUs costs O(m log m) per basket. A count vector costs O(m + K), where K is the catalog size. Which is better depends on those numbers: the run below shows 16,512 operations against 2,026 for a long basket in a small catalog, and 2 against 5,003 for a short basket in a large one. Real catalogs are large and baskets short, so the sorted key usually wins. Either key needs a separator, or two different baskets can produce the same string.

Drill 2. Signal: "consecutive values, input unsorted". The brute force starts counting from every day: O(n²) when the days form one long run. Sorting first gives O(n log n), simple and easy to get right. The hash version gets O(n) by counting only from the start of a run, which is a day whose predecessor is absent; every other day is skipped in O(1), so each day is walked at most once. The op counts prove the difference, but on a million days the wall-clock gap is only about 1.5×, not the 20× that log n suggests, because hashing has a bigger constant. Offer the sort first and then the Set.

import { noTick, type Tick } from "./doubling.ts";

export type Basket = readonly string[];
export type Catalog = ReadonlyMap<string, number>;

// الـ key الأول: رتّب الأصناف، ⁦O(m log m)⁩ لكل basket
export function sortedKey(basket: Basket, tick: Tick = noTick): string {
  return basket.toSorted((a, b) => {
    tick();
    return a < b ? -1 : a > b ? 1 : 0;
  }).join("|");
}

// الـ key التاني: عدّ كل صنف في الكتالوج، ⁦O(m + K)⁩ لكل basket
export function countKey(basket: Basket, catalog: Catalog, tick: Tick = noTick): string {
  const counts = new Array<number>(catalog.size).fill(0);
  for (const sku of basket) {
    tick();
    counts[catalog.get(sku)!]++;
  }
  for (let slot = 0; slot < catalog.size; slot++) tick();
  return counts.join(",");
}

// الـ brute force: كل order بيتقارن بكل group موجودة، ⁦O(n²)⁩
export function groupBrute(baskets: readonly Basket[], tick: Tick = noTick): number[][] {
  const groups: { key: string; orders: number[] }[] = [];
  for (const [order, basket] of baskets.entries()) {
    const key = sortedKey(basket);
    let home = groups.find((group) => {
      tick();
      return group.key === key;
    });
    if (home === undefined) {
      home = { key, orders: [] };
      groups.push(home);
    }
    home.orders.push(order);
  }
  return groups.map((group) => group.orders);
}

// الحل: الـ Map بدل المرور على الـ groups، O(n) lookups
export function groupOrders(baskets: readonly Basket[], keyOf: (basket: Basket) => string, tick: Tick = noTick): number[][] {
  const groups = new Map<string, number[]>();
  for (const [order, basket] of baskets.entries()) {
    tick();
    const key = keyOf(basket);
    const orders = groups.get(key);
    if (orders === undefined) groups.set(key, [order]);
    else orders.push(order);
  }
  return [...groups.values()];
}

      tick();
      length++;
    }

// الحل بالترتيب: ⁦O(n log n)⁩ وسهل تثبته
export function longestRunSorted(days: readonly number[], tick: Tick = noTick): number {
  const sorted = days.toSorted((a, b) => {
    tick();
    return a - b;
  });
  let best = sorted.length > 0 ? 1 : 0;
  let length = 1;
  for (let at = 1; at < sorted.length; at++) {
    tick();
    if (sorted[at] === sorted[at - 1]) continue;
    length = sorted[at] === sorted[at - 1] + 1 ? length + 1 : 1;
    best = Math.max(best, length);
  }
  return best;
}

    tick();

      tick();

    }

English

Drill 1. Signal: "three values that sum to a target": fix one, and the rest is a sorted pair problem. The brute force tries every triple, O(n³). Sort first, fix an anchor, and walk two pointers over the rest: O(n²) time, and O(n) extra space for the sorted copy. The trap is duplicates. Without skipping equal anchors and equal pointer values, the same triple comes out again. The test below fails with the real output 2 !== 1. A Set of results would hide that, at the price of doing the duplicate work.

Drill 2. Signal: "longest contiguous" plus "at most k". The brute force tries every start, O(n²). The window grows on the right on each step and shrinks on the left only while the limit is exceeded. Each index enters once and leaves once, so at most 2n steps. The trap is the shrink condition: used > limit shrinks only when the window is invalid, while used >= limit throws away a valid window, gives 4 instead of 6 on the example below, and never terminates when limit is 0, because the condition stays true while left runs off the end. The test uses a step guard to report that instead of hanging.

export function zeroTriplesBrute(entries: readonly number[], tick: Tick = noTick): number[][] {
  const sorted = entries.toSorted((a, b) => a - b);
  const unique = new Map<string, number[]>();
  for (let a = 0; a < sorted.length; a++) {
    for (let b = a + 1; b < sorted.length; b++) {
      for (let c = b + 1; c < sorted.length; c++) {

    }

// الـ brute force: كل نقطة بداية، ⁦O(n²)⁩
export function longestSessionBrute(discounted: readonly boolean[], limit: number, tick: Tick = noTick): number {
  let best = 0;
  for (let start = 0; start < discounted.length; start++) {
    let used = 0;
    for (let cursor = start; cursor < discounted.length; cursor++) {
      tick();
      if (discounted[cursor]) used++;
      if (used > limit) break;
      best = Math.max(best, cursor - start + 1);
    }
  }
  return best;
}

// الحل: window متغيرة، كل عنصر بيدخل مرة ويخرج مرة، ⁦O(n)⁩
export function longestSession(discounted: readonly boolean[], limit: number, tick: Tick = noTick): number {
  let best = 0;
  let left = 0;
  let used = 0;
  for (let right = 0; right < discounted.length; right++) {
    tick();
    if (discounted[right]) used++;
    // الشرط أكبر من، مش أكبر من أو يساوي: الحد نفسه مسموح
    while (used > limit) {
      tick();
      if (discounted[left]) used--;
      left++;
    }
    best = Math.max(best, right - left + 1);
  }
  return best;
}

// النسخة الغلط: الشرط بيشيل عنصر مسموح بيه
export function longestSessionOffByOne(discounted: readonly boolean[], limit: number, tick: Tick = noTick): number {
  let best = 0;
  let left = 0;
  let used = 0;
  for (let right = 0; right < discounted.length; right++) {
    tick();
    if (discounted[right]) used++;
    while (used >= limit) {
      tick();
      if (discounted[left]) used--;
      left++;
    }
    best = Math.max(best, right - left + 1);
  }
  return best;
}

English

Signal: "next greater" or "nesting": the item you have to settle next is the most recent one still unsettled. That is exactly what a stack gives you. See stacks if the structure itself is new.

Drill 1. The brute force scans forward from each day, O(n²) on falling totals. The monotonic version keeps a stack of days still waiting for something bigger. When a bigger total arrives, it settles every smaller waiter on top. Each index is pushed once and popped at most once, so the total work is at most 2n, whatever the shape of the input. The counters below show 8,000 pushes and 7,999 pops on the worst case, and 100,000 pushes and 99,975 pops on random data. "Strictly bigger" matters: < in the pop condition keeps equal totals waiting.

Drill 2. The brute force repeatedly removes an adjacent open/close pair until nothing changes, O(n²) on deep nesting. A stack of open kinds is O(n), and it can say where the error is and why, which is what a real validator must do. Three failure modes need separate handling: a close with nothing open, a close of the wrong kind, and something left open at the end.

import { noTick, type Tick } from "./doubling.ts";

// الـ brute force: كل يوم بيدوّر قدامه، ⁦O(n²)⁩ لو الأرقام نازلة
export function daysUntilBiggerBrute(orders: readonly number[], tick: Tick = noTick): number[] {
  return orders.map((today, day) => {
    for (let later = day + 1; later < orders.length; later++) {
      tick();
      if (orders[later] > today) return later - day;
    }
    return 0;
  });
}

export type StackCounts = { pushes: number; pops: number };

// الحل: stack بيحفظ الأيام اللي لسه مستنية يوم أكبر
export function daysUntilBigger(orders: readonly number[], counts: StackCounts = { pushes: 0, pops: 0 }): number[] {
  const waits = new Array<number>(orders.length).fill(0);
  const waiting: number[] = [];
  for (const [day, today] of orders.entries()) {
    while (waiting.length > 0 && orders[waiting.at(-1)!] < today) {
      const earlier = waiting.pop()!;
      counts.pops++;
      waits[earlier] = day - earlier;
    }
    waiting.push(day);
    counts.pushes++;
  }
  return waits;
}
import { noTick, type Tick } from "./doubling.ts";

export type NestingResult = { ok: true } | { ok: false; at: number; reason: string };

// الـ brute force: شيل أي زوج open/close جنب بعض لحد ما مفيش
export function isNestedBrute(events: readonly string[], tick: Tick = noTick): boolean {
  const remaining = [...events];
  let removed = true;
  while (removed) {
    removed = false;
    for (let at = 0; at + 1 < remaining.length; at++) {
      tick();
      const [action, kind] = remaining[at].split(":");
      if (action === "open" && remaining[at + 1] === `close:${kind}`) {
        remaining.splice(at, 2);
        removed = true;
        break;
      }
    }
  }
  return remaining.length === 0;
}

// الحل: stack بيحفظ المفتوح حاليًا، ⁦O(n)⁩، وبيقول فين الغلطة
export function validateNesting(events: readonly string[], tick: Tick = noTick): NestingResult {
  const open: string[] = [];
  for (const [at, event] of events.entries()) {
    tick();
    const [action, kind] = event.split(":");
    if (action === "open") {
      open.push(kind);
      continue;
    }
    const top = open.pop();
    if (top === undefined) return { ok: false, at, reason: `close:${kind} with nothing open` };
    if (top !== kind) return { ok: false, at, reason: `expected close:${top}` };
  }
  if (open.length > 0) return { ok: false, at: events.length, reason: `unclosed ${open.at(-1)}` };
  return { ok: true };
}

English

The moment you notice. Nothing in the first prompt is sorted, but the answers are: if rate r is enough, every higher rate is enough too. That monotonic yes/no condition is what makes the answer space searchable. Whenever a prompt says "minimum X such that…" or "maximum X that still…", ask whether feasibility flips exactly once.

Drill 1. The brute force tries rates 1, 2, 3 and up, checking feasibility each time: O(N · max). Binary search over the rate range needs O(log max) feasibility checks, each O(N), so O(N log max). Keep the half-open invariant from lesson 03: everything below low is too slow, and everything from high upward is enough. The upper bound is the largest queue, because at that rate every queue takes one hour. Check the boundaries: H equal to N forces the largest queue; fewer hours than queues is impossible, so return null; one huge queue of 10⁹ takes about 30 checks. Find the maximum with reduce: Math.max(...queues) threw RangeError here between 120,000 and 130,000 arguments.

Drill 2. The brute force scans, O(n). In a rotated table, at least one half around the middle is still sorted, so you check whether the target falls inside that sorted half and discard the other: O(log n). This relies on distinct prices. With duplicates, the two ends can look the same and the worst case falls back to O(n), so ask.

import { noTick, type Tick } from "./doubling.ts";

export function hoursNeeded(queues: readonly number[], rate: number): number {
  let hours = 0;
  for (const backlog of queues) hours += Math.ceil(backlog / rate);
  return hours;
}

// الـ brute force: جرّب 1 و2 و3 لحد ما يكفي، ⁦O(N · max)⁩
export function minRateBrute(queues: readonly number[], hours: number, tick: Tick = noTick): number | null {
  if (hours < queues.length) return null;
  for (let rate = 1; ; rate++) {
    tick();
    if (hoursNeeded(queues, rate) <= hours) return rate;
  }
}

// الحل: كل rate أكبر بيخلّص أسرع، فالشرط monotonic ونقدر نعمل binary search
export function minRate(queues: readonly number[], hours: number, tick: Tick = noTick): number | null {
  if (hours < queues.length) return null;
  // اللي تحت low مش بيكفي، واللي من high وطالع بيكفي
  let low = 1;
  // استخدم reduce: الـ spread بيرمي RangeError مع مئات الآلاف من الـ queues
  let high = queues.reduce((largest, backlog) => Math.max(largest, backlog), 1);
  while (low < high) {
    tick();
    const middle = low + Math.floor((high - low) / 2);
    if (hoursNeeded(queues, middle) <= hours) high = middle;
    else low = middle + 1;
  }
  return low;
}

// الـ brute force: مرور خطي، ⁦O(n)⁩
export function findPriceScan(prices: readonly number[], target: number, tick: Tick = noTick): number {
  for (const [index, price] of prices.entries()) {
    tick();
    if (price === target) return index;
  }
  return -1;
}

// الحل: نص من النصين لازم يكون مترتب، ⁦O(log n)⁩، بشرط مفيش تكرار
export function findPrice(prices: readonly number[], target: number, tick: Tick = noTick): number {
  let low = 0;
  let high = prices.length;
  while (low < high) {
    tick();
    const middle = low + Math.floor((high - low) / 2);
    if (prices[middle] === target) return middle;
    if (prices[low] <= prices[middle]) {
      // الشمال مترتب: هل الهدف جوه الشمال؟
      if (prices[low] <= target && target < prices[middle]) high = middle;
      else low = middle + 1;
    } else {
      // اليمين مترتب: هل الهدف جوه اليمين؟
      if (prices[middle] < target && target <= prices[high - 1]) low = middle + 1;
      else high = middle;
    }
  }
  return -1;
}

English

Drill 1. Signal: "overlap", "at the same time", start and end. The brute force counts active jobs at every start, O(n²). Two O(n log n) solutions follow. The sweep sorts starts and ends separately and walks both: every start adds one, every end at or before that start removes one, and the answer is the peak. The heap keeps the earliest time a worker becomes free; if it is free by this job's start, reuse that worker. Both are tested and agree. The sweep is shorter and needs no extra structure. The heap also tells you which worker is free, so it fits a follow-up that assigns jobs. JavaScript has no built-in heap, so learn the short version below and check whether the platform provides one: LeetCode's article lists @datastructures-js/priority-queue 6.3.5 (seen through a search index on 2026-11-09), and this page tests against 6.4.0.

Drill 2. Signal: "can you reach". The brute force marks every hub reachable from every reachable hub, O(n²) when hops are long. Greedy tracks only the farthest hub reachable so far, O(n). Why greedy holds here: the reachable hubs always form an unbroken prefix, because a hop of up to k lets you stop anywhere along the way. So one number describes the whole reachable set and no choice is ever lost. That argument, not the intuition, is what you say out loud. The same "largest first" reasoning fails on vouchers of 10, 7 and 1 for a bill of 14: greedy uses 5, the optimum is 2 (7 + 7). The difference is that taking 10 there does lose options. See the patterns lesson for where greedy fails in general.

// الـ heap اللي هتكتبه بإيدك لما المنصة مفيهاش مكتبة: min-heap على أرقام
export class MinHeap {
  private items: number[] = [];
  private tick: () => void;

  constructor(tick: () => void = () => {}) {
    this.tick = tick;
  }

  get size(): number {
    return this.items.length;
  }

  peek(): number | undefined {
    return this.items[0];
  }

  push(value: number): void {
    this.items.push(value);
    let child = this.items.length - 1;
    while (child > 0) {
      this.tick();
      const parent = (child - 1) >> 1;
      if (this.items[parent] <= this.items[child]) break;
      [this.items[parent], this.items[child]] = [this.items[child], this.items[parent]];
      child = parent;
    }
  }

  pop(): number | undefined {
    const top = this.items[0];
    const last = this.items.pop();
    if (this.items.length > 0 && last !== undefined) {
      this.items[0] = last;
      this.siftDown();
    }
    return top;
  }

  private siftDown(): void {
    let parent = 0;
    for (;;) {
      this.tick();
      const left = 2 * parent + 1;
      const right = left + 1;
      let smallest = parent;
      if (left < this.items.length && this.items[left] < this.items[smallest]) smallest = left;
      if (right < this.items.length && this.items[right] < this.items[smallest]) smallest = right;
      if (smallest === parent) return;
      [this.items[parent], this.items[smallest]] = [this.items[smallest], this.items[parent]];
      parent = smallest;
    }
  }
}

// الوقت half-open: job بتخلص الساعة 10 و job بتبدأ الساعة 10 ينفعوا لنفس العامل
export type Job = { start: number; end: number };

// الـ brute force: عند بداية كل job عدّ الشغالين، ⁦O(n²)⁩
export function minWorkersBrute(jobs: readonly Job[], tick: Tick = noTick): number {
  let peak = 0;
  for (const { start } of jobs) {
    let active = 0;
    for (const job of jobs) {
      tick();
      if (job.start <= start && start < job.end) active++;
    }
    peak = Math.max(peak, active);
  }
  return peak;
}

function sortedNumbers(values: number[], tick: Tick): number[] {
  return values.sort((a, b) => {
    tick();
    return a - b;
  });
}

// الحل الأول: رتّب البدايات والنهايات لوحدهم وامشي عليهم، ⁦O(n log n)⁩
export function minWorkersSweep(jobs: readonly Job[], tick: Tick = noTick): number {
  const starts = sortedNumbers(jobs.map((job) => job.start), tick);
  const ends = sortedNumbers(jobs.map((job) => job.end), tick);
  let active = 0;
  let peak = 0;
  let nextEnd = 0;
  for (const start of starts) {
    tick();
    while (ends[nextEnd] <= start) {
      tick();
      active--;
      nextEnd++;
    }
    active++;
    peak = Math.max(peak, active);
  }
  return peak;
}

// الحل التاني: heap فيها أقرب وقت عامل هيفضى، ⁦O(n log n)⁩
export function minWorkersHeap(jobs: readonly Job[], tick: Tick = noTick): number {
  const byStart = jobs.toSorted((a, b) => {
    tick();
    return a.start - b.start;
  });
  const freeAt = new MinHeap(tick);
  for (const job of byStart) {
    const earliest = freeAt.peek();
    if (earliest !== undefined && earliest <= job.start) freeAt.pop();
    freeAt.push(job.end);
  }
  return freeAt.size;
}

// الـ brute force: علّم كل hub ممكن توصله من كل hub، ⁦O(n²)⁩
export function canReachLastBrute(maxHop: readonly number[], tick: Tick = noTick): boolean {
  if (maxHop.length === 0) return false;
  const reachable = new Array<boolean>(maxHop.length).fill(false);
  reachable[0] = true;
  for (let hub = 0; hub < maxHop.length; hub++) {
    if (!reachable[hub]) continue;
    for (let target = hub + 1; target <= hub + maxHop[hub] && target < maxHop.length; target++) {
      tick();
      reachable[target] = true;
    }
  }
  return reachable[maxHop.length - 1];
}

// الحل greedy: الـ hubs الممكنة دايمًا بادئة متصلة، فرقم واحد بيوصفها
export function canReachLast(maxHop: readonly number[], tick: Tick = noTick): boolean {
  if (maxHop.length === 0) return false;
  let furthest = 0;
  for (const [hub, hop] of maxHop.entries()) {
    tick();
    if (hub > furthest) return false;
    furthest = Math.max(furthest, hub + hop);
  }
  return true;
}

The README's schedule: redo what you got wrong after 3 days, a week and a month. spaced.ts builds on the CSV from lesson 03, whose tracker reads columns by name, so the two new columns don't break it (the run below proves that). The step is the number of solved attempts since the last wrong one, and the next redo is due that many intervals after the most recent attempt. A problem never marked wrong is never scheduled, and after three solved redos it graduates.

Log why you got it wrong, not only that you did. A short tag such as missed-signal, off-by-one or edge-case turns the file into a diagnosis: two off-by-one tags tell you to drill boundaries, not to solve more problems. Today's date is injected, so the tests never depend on the clock, and all arithmetic is in UTC so a daylight-saving change can't shift a day.

Trade-off: a fixed schedule or SM-2. SM-2 grades each review from 0 to 5 and keeps an ease factor per item, starting at 2.5, so intervals adapt: 1 day, 6 days, then the previous interval times the factor. It earns that complexity on thousands of cards. For about 150 problems over a few months, three fixed steps are enough, and the time goes into solving.

export type LogEntry = { id: string; status: "solved" | "revisit"; minutes: number; date: string; why: string };

// جدول الـ README: 3 أيام، وبعدها أسبوع، وبعدها شهر
export const INTERVAL_DAYS = [3, 7, 30];
const DAY_MS = 86_400_000;

export function parseLog(csv: string): LogEntry[] {
  const [headerLine, ...rows] = csv.trim().split(/\r?\n/);
  const header = headerLine.split(",").map((name) => name.trim());
  const column = (name: string) => {
    const at = header.indexOf(name);
    if (at === -1) throw new Error(`missing column: ${name}`);
    return at;
  };
  const at = { id: column("id"), status: column("status"), minutes: column("minutes"), date: column("date"), why: column("why") };

  return rows.map((row, offset) => {
    const lineNumber = offset + 2;
    const cells = row.split(",").map((cell) => cell.trim());
    const status = cells[at.status];
    const date = cells[at.date];
    if (status !== "solved" && status !== "revisit") throw new Error(`line ${lineNumber}: bad status "${status}"`);
    if (!/^\d{4}-\d{2}-\d{2}$/.test(date) || Number.isNaN(Date.parse(date))) throw new Error(`line ${lineNumber}: bad date "${date}"`);
    return { id: cells[at.id], status, minutes: Number(cells[at.minutes]), date, why: cells[at.why] ?? "" };
  });
}

// كل الحساب بالـ UTC عشان فرق التوقيت الصيفي ميغيّرش اليوم
export function addDays(date: string, days: number): string {
  return new Date(Date.parse(date) + days * DAY_MS).toISOString().slice(0, 10);
}

export function daysBetween(from: string, to: string): number {
  return Math.round((Date.parse(to) - Date.parse(from)) / DAY_MS);
}

export type Scheduled = { id: string; step: number; dueOn: string; why: string };

// الخطوة = عدد المرات اللي اتحلت صح بعد آخر غلطة
export function schedule(log: readonly LogEntry[]): { active: Scheduled[]; graduated: string[] } {
  const byProblem = new Map<string, LogEntry[]>();
  for (const entry of log.toSorted((a, b) => a.date.localeCompare(b.date))) {
    const attempts = byProblem.get(entry.id) ?? [];
    attempts.push(entry);
    byProblem.set(entry.id, attempts);
  }

  const active: Scheduled[] = [];
  const graduated: string[] = [];
  for (const [id, attempts] of byProblem) {
    const lastWrong = attempts.findLastIndex((attempt) => attempt.status === "revisit");
    if (lastWrong === -1) continue;
    const step = attempts.length - 1 - lastWrong;
    if (step >= INTERVAL_DAYS.length) {
      graduated.push(id);
      continue;
    }
    const lastAttempt = attempts.at(-1)!;
    active.push({ id, step, dueOn: addDays(lastAttempt.date, INTERVAL_DAYS[step]), why: attempts[lastWrong].why });
  }
  return { active: active.toSorted((a, b) => a.dueOn.localeCompare(b.dueOn)), graduated };
}

// الـ due لو ميعاده جه أو عدّى، والتاريخ لازم يتبعت من بره
export function dueOn(log: readonly LogEntry[], today: string): Scheduled[] {
  return schedule(log).active.filter((item) => item.dueOn <= today);
}

export function reasonCounts(log: readonly LogEntry[]): [string, number][] {
  const counts = new Map<string, number>();
  for (const entry of log) {
    if (entry.status === "revisit") counts.set(entry.why, (counts.get(entry.why) ?? 0) + 1);
  }
  return [...counts].toSorted((a, b) => b[1] - a[1] || a[0].localeCompare(b[0]));
}

// تمرين 2: أطول session بعدد SKUs مختلفة مش أكتر من الحد
export function longestWithDistinctLimit(skus: readonly string[], limit: number): number {
  const inWindow = new Map<string, number>();
  let best = 0;
  let left = 0;
  for (let right = 0; right < skus.length; right++) {
    inWindow.set(skus[right], (inWindow.get(skus[right]) ?? 0) + 1);
    while (inWindow.size > limit) {
      const count = inWindow.get(skus[left])! - 1;
      if (count === 0) inWindow.delete(skus[left]);
      else inWindow.set(skus[left], count);
      left++;
    }
    best = Math.max(best, right - left + 1);
  }
  return best;
}

function daysNeeded(parcels: readonly number[], capacity: number): number {
  let days = 1;
  let loaded = 0;
  for (const parcel of parcels) {
    if (loaded + parcel > capacity) {
      days++;
      loaded = 0;
    }
    loaded += parcel;
  }
  return days;
}

// تمرين 3: أقل سعة شاحنة تكفي نوزّع الطرود بالترتيب على عدد الأيام
export function minCapacity(parcels: readonly number[], days: number): number {
  // اللي تحت low مش بيكفي، و high دايمًا بيكفي
  let low = parcels.reduce((largest, parcel) => Math.max(largest, parcel), 0);
  let high = parcels.reduce((sum, parcel) => sum + parcel, 0);
  while (low < high) {
    const middle = low + Math.floor((high - low) / 2);
    if (daysNeeded(parcels, middle) <= days) high = middle;
    else low = middle + 1;
  }
  return low;
}

Cheat sheet · الخلاصة

  • Signals tell you where to look first. Restate the prompt without domain words, then look at the data's shape.
  • A keyword matcher scored 9/12 here. It missed a tree phrased as an org chart, a synonym, and "consecutive" values.
  • Hash key: sorted O(m log m) or count vector O(m + K). Always use a separator.
  • Runs: count only from a run's start, or you've written O(n²) without noticing.
  • Three-sum: sort, fix an anchor, two pointers, skip duplicates at both levels.
  • Window: shrink only when invalid (>, not >=). Test k = 0.
  • Monotonic stack: pushed once, popped once, so at most 2n. Ask about ties.
  • "Minimum X such that" means searching the answer if feasibility is monotonic. Use ceil for partial units.
  • Intervals: sweep for the count, heap for the assignment. An end at t frees a worker at t.
  • Greedy needs an argument that no choice is lost. Otherwise compare with DP on small inputs.
  • Redo wrong problems after 3 days, a week, a month. Tag why. Inject today's date.
  • Medium set: 101 by third-party count. Check the site, then plan with your own minutes and include redos.
