Why this matters · ليه ده مهم

English

Most interview prep goes wrong before the first problem: people train for a generic interview and then meet a specific one. A loop is a set of rounds, and each round produces one kind of evidence about you. Once you know which round measures what, your hours go where they move the decision and the format stops surprising you. This lesson is the map for the whole section. It pays off at work too: asking before you build, stating assumptions and owning what ships are what Senior means in a design review as well.

Model answer. A typical Senior loop looks like the flow below. "Typical" is a starting shape, not a fact about your company: the loop you get is the one the recruiter describes. The durations are common ranges.

  1. Recruiter call, 20–30 minutes: motivation, logistics, expectations.
  2. Phone screen, 45–60 minutes: usually one coding problem, sometimes a past-work conversation.
  3. Coding, 1–2 rounds of 45–60 minutes.
  4. System design, 1–2 rounds of 45–60 minutes.
  5. Behavioral or leadership, 45–60 minutes.
  6. Sometimes: a take-home, pair programming, or an architecture deep-dive on a system you built.

Two things the README's list predates, with dates in the table below: AI-assisted coding rounds and a return to in-person rounds. Neither is universal, and the reports vary in quality. The practical rule is one line: ask which rounds allow AI, and use none that isn't explicitly allowed. A round whose rule you don't know counts as banned.

loop.ts models a loop as typed data, then turns weeks and weekly hours into a prep budget per round type. The weights are a judgement call to edit, and the unknown AI state exists on purpose: it forces the question to the recruiter instead of defaulting to yes.

// الملف ده بيوزّع عدد ساعات صحيح على أوزان، من غير ما المجموع يضيع بسبب التقريب.
export function splitHours(total: number, weights: number[]): number[] {
  // ممنوع input غلط، وإلا هنقسم على صفر ونطلع NaN في الجدول
  if (!Number.isInteger(total) || total < 0) {
    throw new RangeError(`total must be a non-negative integer, got ${total}`);
  }
  const sum = weights.reduce((a, b) => a + b, 0);
  if (sum <= 0 || weights.some((w) => w < 0)) {
    throw new RangeError("weights must be non-negative with a positive sum");
  }

  const exact = weights.map((w) => (w / sum) * total);
  const hours = exact.map((x) => Math.floor(x));
  let left = total - hours.reduce((a, b) => a + b, 0);

  // الساعات الفاضلة بتروح للي الكسر بتاعه أكبر (largest remainder)
  const byFraction = exact
    .map((x, i) => ({ i, fraction: x - Math.floor(x) }))
    .sort((a, b) => b.fraction - a.fraction);
  for (const { i } of byFraction) {
    if (left === 0) break;
    hours[i] += 1;
    left -= 1;
  }
  return hours;
}

import { splitHours } from "./split.ts";

type RoundKind =
  | "recruiter" | "phone-screen" | "coding" | "ai-coding" | "system-design"
  | "behavioral" | "take-home" | "pair-programming" | "deep-dive";

// الـ unknown معناها لسه مسألتش، وبنعاملها زي الممنوع بالظبط
type AiRule = "allowed" | "banned" | "unknown";
export type Round = { kind: RoundKind; minutes: number; ai: AiRule };

// الأوزان دي رأي تقديري تعدّله لنفسك، مش إحصائية
const prepWeight: Record<RoundKind, number> = {
  recruiter: 0.25, "phone-screen": 3, coding: 6, "ai-coding": 4, "system-design": 6,
  behavioral: 3, "take-home": 4, "pair-programming": 3, "deep-dive": 3,
};

// الجملة دي هي الإشارة اللي الـ round بيطلّعها عنك
const signal: Record<RoundKind, string> = {
  recruiter: "motivation, logistics, fit",
  "phone-screen": "can code and talk in the tool",
  coding: "problem solving, code quality",
  "ai-coding": "verifies and directs an assistant",
  "system-design": "ambiguity, trade-offs, depth",
  behavioral: "ownership, conflict, scope",
  "take-home": "production habits, decisions",
  "pair-programming": "collaboration, working style",
  "deep-dive": "real systems, what broke",
};

export const round = (kind: RoundKind, minutes: number, ai: AiRule = "unknown"): Round => ({ kind, minutes, ai });

// المسموح بس هو اللي اتقالك عليه صراحة، أي حاجة تانية ممنوعة
export const mayUseAi = (r: Round): boolean => r.ai === "allowed";

export function budget(rounds: Round[], weeks: number, hoursPerWeek: number) {
  const kinds = [...new Set(rounds.map((r) => r.kind))];
  // الوزن بيتضرب في عدد المرات: 2 coding rounds وزنهم ضعف واحد
  const weights = kinds.map((k) => prepWeight[k] * rounds.filter((r) => r.kind === k).length);
  const hours = splitHours(weeks * hoursPerWeek, weights);
  return kinds.map((kind, i) => {
    const same = rounds.filter((r) => r.kind === kind);
    return { kind, count: same.length, minutes: same.reduce((a, r) => a + r.minutes, 0), hours: hours[i] };
  });
}

export function report(name: string, rounds: Round[], weeks: number, hoursPerWeek: number): void {
  console.log(`${name}: ${weeks} weeks x ${hoursPerWeek} h = ${weeks * hoursPerWeek} h`);
  for (const l of budget(rounds, weeks, hoursPerWeek)) {
    const kind = l.kind.padEnd(17);
    console.log(`  ${kind} x${l.count} ${String(l.minutes).padStart(4)} min ${String(l.hours).padStart(3)} h  ${signal[l.kind]}`);
  }
  const unknown = rounds.filter((r) => r.ai === "unknown").length;
  const allowed = rounds.filter(mayUseAi).length;
  console.log(`  AI: allowed in ${allowed}, unknown in ${unknown} -> ask the recruiter\n`);
}

  1. مكالمة الـ recruiter، 20 لـ 30 دقيقة: الدافع، والترتيبات، والتوقعات.
  2. الـ phone screen، 45 لـ 60 دقيقة: غالبًا مسألة coding واحدة، وأحيانًا كلام عن شغلك اللي فات.
  3. الـ coding، round أو اتنين، كل واحد 45 لـ 60 دقيقة.
  4. الـ system design، round أو اتنين، كل واحد 45 لـ 60 دقيقة.
  5. الـ behavioral أو leadership، 45 لـ 60 دقيقة.
  6. أحيانًا: take-home، أو pair programming، أو architecture deep-dive على نظام إنت بنيته.

فيه حاجتين الـ README مش مذكورين فيه، وتواريخهم في الجدول: rounds الـ coding بمساعدة AI، ورجوع rounds in-person. الاتنين مش موجودين في كل مكان، وجودة التقارير عنهم مختلفة. القاعدة العملية سطر واحد: اسأل أنهي rounds مسموح فيها الـ AI، وماتستخدمش غير اللي اتقال عليه صراحة. والـ round اللي مش عارف قاعدته يتحسب ممنوع.

loop.ts بيعبّر عن الـ loop كـ data بـ types، وبعدين يحوّل الأسابيع والساعات الأسبوعية لميزانية تحضير لكل نوع round. الأوزان اللي فيه رأي تقديري تعدّله إنت، وحالة unknown للـ AI موجودة عمدًا: بتجبرك تسأل الـ recruiter بدل ما تفترض إن الإجابة "آه". وsplit.ts بيضمن إن مجموع الساعات يفضل زي ما هو بعد التقريب، بطريقة الـ largest remainder.

فين هستخدمه في شغلي؟ لو جالك invite لـ loop في شركة payments بعد 4 أسابيع، متبدأش بمسائل عشوائية: ارسم الـ loop على ورقة، حط علامات استفهام على اللي مش عارفه، ودخّل 4 أسابيع وعدد ساعاتك في loop.ts. هتعرف الوقت هيتقسم إزاي بين الـ design والـ coding. ولو عندك round مش عارف قواعد الـ AI فيه، ابعت للـ recruiter قبل ما تفتح أي أداة، زي ما بتسأل على الـ contract قبل ما تكتب integration مع service تاني.

import { readFileSync } from "node:fs";

type Signals = {
  turns: number; clarifying: number; tradeOffs: number;
  numbers: number; ownership: number; vague: number;
};

export function review(transcript: string, speaker = "Candidate:"): Signals {
  // السطر اللي مش بادئ باسم متكلم بيكمّل كلام اللي قبله
  const turns: string[] = [];
  for (const line of transcript.split(/\r?\n/)) {
    if (/^(Interviewer|Candidate):/.test(line)) turns.push(line);
    else if (turns.length > 0 && line.trim()) turns[turns.length - 1] += " " + line.trim();
  }
  // كلام المرشح بس هو اللي بيتعد، مش أسئلة الـ interviewer
  const said = turns.filter((t) => t.startsWith(speaker)).map((t) => t.slice(speaker.length));
  const text = said.join("\n");
  const count = (re: RegExp) => (text.match(re) ?? []).length;

  return {
    turns: said.length,
    // أي علامة استفهام في كلام المرشح بتتحسب سؤال توضيحي
    clarifying: count(/\?/g),
    tradeOffs: count(/\b(trade-?off|instead of|at the cost of|that means|but it)\b/gi),
    numbers: count(/\d[\d,.]*/g),
    // جمل "أنا مسؤول" والحاجات اللي بتيجي بعد الـ deploy
    ownership: count(/\b(I will own|I own|shadow mode|on-call|runbook|alert|dashboard|roll ?back)\b/gi),
    vague: count(/\b(scal(e|able)|fast|simple|robust|best practice)\b/gi),
  };
}

function notes(s: Signals): string[] {
  const out: string[] = [];
  if (s.clarifying < 2) out.push("almost no clarifying questions");
  if (s.tradeOffs < 2) out.push("no trade-off stated out loud");
  if (s.numbers < 4) out.push("few numbers");
  if (s.ownership < 2) out.push("nothing about running it after the deploy");
  if (s.vague > s.numbers) out.push("more vague words than numbers");
  return out.length ? out : ["counts look healthy (this does NOT judge the content)"];
}

Model answer. Three shapes, and they are tendencies rather than rules. Big Tech leans on heavy DSA plus system design. Product companies lean on practical coding (build something real in 60 minutes), design and behavioral. Startups lean on a take-home plus culture and founder conversations. Plenty of companies mix these, so the loop you actually get is whatever the recruiter tells you. The table in allocate.ts is a starting point of mine for comparing the three, not market data.

The output shows why the type matters: DSA goes from 38 hours to 5 between Big Tech and a startup, and the take-home goes from 0 to 29. What you drill first changes completely. In the tool, the first drill is simply the largest share; the product type has a tie between practical coding and design, broken by track order.

If you are aiming at remote roles at companies abroad, ask early which loop applies to remote candidates and whether any round is in person. This is advice: don't take anyone's general claims about pay or market share for your plan.

Model reading. A job description has four layers. Must-haves are what the role can't work without. Domain signals are the words that predict the hard questions: for payments, "idempotent", "webhook retries", "double-entry ledger", "reconciliation", "PCI". Seniority signals are "own", "on-call", "lead incidents", "mentor". Everything else, such as the About us section, is often boilerplate.

Payments JD: must-haves are Node, TypeScript and Postgres down to isolation levels. Five likely questions: design a refund API that a webhook retry can't charge twice (idempotency); model a double-entry ledger and a daily reconcile (payment case study); which isolation level for moving money and why (isolation); an incident you led; how you mentor someone through a design review.

Logistics JD: must-haves are shipping end to end and deploying what you build. Five likely questions: the take-home itself; how you would do live driver tracking and at what update rate; how you cut a messy customer request down to shippable scope; how you deploy and roll back with no ops team; why a startup of this size. Note that the words "ownership, mentoring" in its About us section are culture copy, not a requirement.

jd.ts maps keyword groups to predicted topics. Domain matches are weighted above stack matches on purpose, since the hard questions come from the domain. The evidence line it prints exists so you can check each match yourself: a keyword match can't tell a real requirement from boilerplate, so the human read is the point. The sample skills file is invented; yours starts blank, in skills.template.json.

export function analyze(jd: string) {
  const lines = jd.split(/\r?\n/);
  return groups
    .map((g) => {
      // كل pattern بيتحسب مرة واحدة، عشان تكرار الكلمة مايرفعش الموضوع لوحده
      const hits = g.patterns.filter((p) => p.test(jd));
      // الدليل هو السطر اللي فيه أكتر كلمات من المجموعة دي
      const score = (l: string) => g.patterns.filter((p) => p.test(l)).length;
      const evidence = [...lines].sort((a, b) => score(b) - score(a))[0] ?? "";
      return { ...g, score: hits.length * weight[g.kind], evidence };
    })
    .filter((g) => g.score > 0)
    .sort((a, b) => b.score - a.score || weight[b.kind] - weight[a.kind]);
}

Model answer. calendar.ts turns weeks, hours and target type into a weekly schedule. Two rules are hard-coded because people skip them. First, coding practice stays light from early on: a floor of 2 hours every week, the README's number, so the skill doesn't lapse while you do other tracks. Second, mocks start before you feel ready: week 2 here, every two weeks at first and weekly in the last third.

The product run gives 8 mocks across 12 weeks, 16 hours of the 120. The README's full target is 15 recorded mocks, which needs a longer run; lesson 15 handles that. Weeks map to this section's lessons in the table below. Skip what your target doesn't use: a Big Tech target can drop the take-home lesson, and a startup target can drop the Hard set.

// للتشغيل: node calendar.ts product 12 10
import { splitHours } from "./split.ts";
import { type CompanyType, type Track, companyTypes, splits, tracks } from "./allocate.ts";

type Phase = { name: string; until: number; lessons: string; focus: Partial<Record<Track, number>> };

// الـ until نسبة من مدة الخطة، والأرقام في lessons هي دروس القسم ده
const phases: Phase[] = [
  { name: "map, CV, method", until: 1 / 6, lessons: "01 02 03 10 15", focus: { dsa: 3, practical: 2, behavioral: 4 } },
  { name: "coding, stories", until: 1 / 2, lessons: "04 05 07 11 12", focus: { dsa: 4, practical: 4, behavioral: 2, design: 3 } },
  { name: "depth, design", until: 5 / 6, lessons: "06 08 09 13 14 16 17", focus: { dsa: 2, practical: 3, design: 5, behavioral: 1, "take-home": 2 } },
  { name: "polish, offers", until: 1, lessons: "18 19 20", focus: { practical: 1, design: 2, behavioral: 2 } },
];

const CODING_FLOOR = 2;
const MOCK_HOURS = 2;

export type Week = { week: number; phase: string; lessons: string; hours: Record<Track, number> };

export function plan(type: CompanyType, weeks: number, perWeek: number): Week[] {
  if (!Number.isInteger(weeks) || weeks < 4) throw new RangeError(`need at least 4 weeks, got ${weeks}`);
  if (perWeek < CODING_FLOOR + MOCK_HOURS) throw new RangeError(`need at least ${CODING_FLOOR + MOCK_HOURS} h/week`);

  const codingTrack: Track = splits[type].dsa >= splits[type].practical ? "dsa" : "practical";
  const firstMock = Math.max(2, Math.ceil(weeks / 6));

  return Array.from({ length: weeks }, (_, i) => {
    const week = i + 1;
    const phase = phases.find((p) => week <= Math.round(p.until * weeks)) ?? phases[phases.length - 1];
    // أول mock قبل ما تحس إنك جاهز: كل أسبوعين، وبعدها كل أسبوع في آخر تلت
    const mock = week >= firstMock && ((week - firstMock) % 2 === 0 || week > (weeks * 2) / 3);
    const mockHours = mock ? MOCK_HOURS : 0;
    const rest = perWeek - CODING_FLOOR - mockHours;
    const weights = tracks.map((t) => (phase.focus[t] ?? 0) * splits[type][t]);
    const split = splitHours(rest, weights);
    const hours = Object.fromEntries(tracks.map((t, j) => [t, split[j]])) as Record<Track, number>;
    // الساعتين بتوع الـ coding ثابتين كل أسبوع من أول يوم، زي ما الـ README قال
    hours[codingTrack] += CODING_FLOOR;
    hours.mocks += mockHours;
    return { week, phase: phase.name, lessons: phase.lessons, hours };
  });
}

// الـ lint ده بيمسك أشهر خطة فاشلة: تلات شهور مسائل ومفيش ولا mock
export function lintPlan(weeks: Week[]): string[] {
  const out: string[] = [];
  const third = Math.ceil(weeks.length / 3);
  const earlyMocks = weeks.slice(0, third).filter((w) => w.hours.mocks > 0).length;
  if (earlyMocks === 0) out.push(`no mock in the first ${third} weeks`);
  if (weeks.some((w) => w.hours.dsa + w.hours.practical === 0)) out.push("a week with no coding at all");
  if (weeks.every((w) => w.hours.behavioral === 0)) out.push("no behavioral practice at all");
  return out;
}

}

import { readFileSync } from "node:fs";
import { analyze } from "./jd.ts";

export function withoutBoilerplate(jd: string): string {
  const kept: string[] = [];
  let skipping = false;
  for (const line of jd.split(/\r?\n/)) {
    const text = line.trim();
    if (/^(about us|our values|benefits|perks)$/i.test(text)) {
      skipping = true;
      continue;
    }
    // السطر القصير من غير ترقيم عنوان جديد، فبنرجع نقرا
    if (/^[A-Z][A-Za-z ]{2,28}$/.test(text)) skipping = false;
    if (!skipping) kept.push(line);
  }
  return kept.join("\n");
}

// الحل: بنخلط نسب نوعين شركات بوزن، والمجموع لازم يفضل هو هو.
// للتشغيل: node blend.ts
import assert from "node:assert/strict";
import { type CompanyType, type Track, splits, tracks } from "./allocate.ts";
import { splitHours } from "./split.ts";

export function blend(a: CompanyType, b: CompanyType, shareOfA: number, total: number): Record<Track, number> {
  if (shareOfA < 0 || shareOfA > 1) throw new RangeError(`shareOfA must be 0..1, got ${shareOfA}`);
  const weights = tracks.map((t) => shareOfA * splits[a][t] + (1 - shareOfA) * splits[b][t]);
  const hours = splitHours(total, weights);
  return Object.fromEntries(tracks.map((t, i) => [t, hours[i]])) as Record<Track, number>;
}

Cheat sheet · الخلاصة

  • A loop is a set of rounds; each one produces one kind of evidence. The loop that counts is the one the recruiter tells you.
  • Typical shape: recruiter → phone screen → coding ×1–2 → design ×1–2 → behavioral → sometimes a take-home, pair session or architecture deep-dive.
  • AI-assisted and in-person rounds exist since 2025. Ask per round, and use no AI that isn't explicitly allowed. Unknown means banned.
  • Senior isn't more knowledge: it is communication, trade-offs, handling ambiguity and ownership, said out loud.
  • Say "I", state a number, name the cost of a choice, and say who watches it after deploy.
  • Big Tech: heavy DSA + design. Product: practical coding + design + behavioral. Startups: take-home + culture. Tendencies, not rules.
  • Preparing for every type at once leaves all of them shallow.
  • Read a JD for must-haves, domain words and seniority words. Domain words predict the hard questions.
  • Keyword tools can't tell a requirement from boilerplate. Read it yourself.
  • Ask the recruiter: rounds, length, tool, language, Senior expectations, AI rules, take-home, panel, timeline.
  • 2 hours of coding a week from the start, and the first mock before you feel ready.
بالعامية
  • الـ loop مجموعة rounds، وكل واحد بيطلّع نوع واحد من الأدلة. والـ loop اللي بيتحسب هو اللي الـ recruiter بيقوله.
  • الشكل المعتاد: recruiter ← phone screen ← coding مرة أو اتنين ← design مرة أو اتنين ← behavioral ← وأحيانًا take-home أو pair session أو architecture deep-dive.
  • الـ rounds اللي بـ AI والـ in-person موجودين من 2025. اسأل عن كل round، وماتستخدمش AI غير لو اتقالك صراحة. والـ unknown يعني ممنوع.
  • الـ Senior مش معلومات أكتر: هو التواصل والـ trade-offs والتعامل مع الغموض والـ ownership، بصوت عالي.
  • قول "أنا"، وقول رقم، وسمّي تكلفة الاختيار، وقول مين هيراقبه بعد الـ deploy.
  • الـ Big Tech: DSA تقيلة و design. الـ product: practical coding و design و behavioral. الـ startups: take-home و culture. ده ميل عام مش قواعد.
  • لو اتجهزت لكل الأنواع مرة واحدة هتطلع سطحي في الكل.
